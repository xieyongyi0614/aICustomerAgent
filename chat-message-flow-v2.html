三、流式输出协议（NDJSON）

事件帧序列application/x-ndjson
客户端依次收到：turn_meta（回合元信息）→ delta（增量 token，多次）→ reply_replace（grounding 修正时，可选）→ done（session_id / turn_id / request_id）；工具步骤帧随时插入。

四、后台后处理（post_process · 13 步，异步独立容错）

回答已产出后异步执行（失败不影响已产出回答；per-user 写锁内串行）

  1. scene_update —— 场景状态更新并持久化
  2. state_update —— 角色状态（情绪/能量/强度）应用与保存
  3. goal_review —— 目标评审（创建/完成/过期/取消）
  4. summary —— 会话摘要更新（达阈值时）
  5. memory_extract —— 记忆提取（显式命令优先，四源幂等入 candidates）
  6. ledger_extraction —— 账本抽取候选（零写库）
  7. ledger_confirmation —— 账本确认挂接（待确认登记/超时清理）
  8. budget_observer —— 行为预算观测（违规告警）
  9. evaluation —— 回合评估（规则 + LLM Judge 采样）
  10. world_update —— 世界状态迁移 + 用户处境检出 + 物品录入
  11. character_action_sync —— 角色动作提取→校验→执行→写世界 notes
  12. action_planning —— 行动六闸门→计划→执行→四通道整合
  13. memory_evaluate —— 收尾记忆评估（本轮候选同轮转正）

五、旁路：后台自治周期（life_loop）

autonomous_tick Profile（与前台并列的第二条 Run 链路，非用户消息驱动）

perception → state_update → state_snapshot → goal_check → goal_stack → goal_supply → goal_advance → memory_retrieval → reflection_check → decision → world_experience
decision 是唯一 LLM capable 且 critical 段；event_driven Profile 仅白名单世界事件升级为完整 Run，其余 0 消耗。
