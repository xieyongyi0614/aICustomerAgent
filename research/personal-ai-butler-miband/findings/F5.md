# F5: 开源社区实践与失败案例

## Findings

### [1] Gadgetbridge 是小米手环社区最成熟的开源替代方案：AGPLv3、无云、F-Droid 分发，明确替代厂商闭源 App
- quote: "Gadgetbridge is a free and open source Android application that allows you to pair and manage various gadgets such as smart watches, bands, headphones, and more without the need for the vendor application."
- url: https://gadgetbridge.org/
- source_type: primary
- published: unknown (docs continuously updated; repo active as of 2026-09-23)
- confidence: high

### [2] 小米手环 9 Pro 在 Gadgetbridge 中被标记为 "Unknown support + Experimental"，支持由 PR #4363 基于 Matrix 反馈加入，需 Xiaomi token 配对，走 Xiaomi protobuf 协议
- quote: "Support added on pull request #4363, based on feedback from matrix. ... Requires Xiaomi token to pair ... Experimental ... Unknown support"
- url: https://gadgetbridge.org/gadgets/wearables/xiaomi/
- source_type: primary
- published: unknown
- confidence: high

### [3] Xiaomi protobuf 设备（含 Mi Band 8/9/9 Pro）可同步的健康字段已明确列出：心率、步数、卡路里、SpO2、压力、Vitality/PAI、睡眠阶段、皮肤温度（部分机型）
- quote: "Implemented: Heart rate, steps; Calories; SpO2; Stress; Vitality Score (equivalent to PAI); Sleep times and sleep stages; Skin temperature (Watch S1 Pro)"
- url: https://gadgetbridge.org/basics/topics/xiaomi-protobuf/
- source_type: primary
- published: unknown
- confidence: high

### [4] Xiaomi protobuf 同步缺失字段构成产品能力边界：Moving time、VO2 Max、血压、体温 UI、训练负荷、睡眠呼吸率等要么缺失要么仅有底层抓取无 UI
- quote: "Missing: Moving time; Standing time (fetched, but no UI); VO2 Max; Blood pressure; Body temperature (Watch S1 Pro) (fetched, but no UI); Training load (fetched, but no UI); Sleep respiratory rate"
- url: https://gadgetbridge.org/basics/topics/xiaomi-protobuf/
- source_type: primary
- published: unknown
- confidence: high

### [5] 失败案例：Mi Band 7 Pro 被官方标注 "Device not recommended"，因为只能同步当天活动数据，当天未同步则永久丢失
- quote: "Device not recommended: can ONLY sync current day's activities. If data is not synced for the current day, it cannot be synced later."
- url: https://gadgetbridge.org/gadgets/wearables/xiaomi/
- source_type: primary
- published: unknown
- confidence: high

### [6] 合规/封禁风险案例：Gadgetbridge 于 2017-06 在 GitHub 遭竞品 MiBandTools 开发者 DMCA 下架，仓库（含 wiki/issues）被整个关停约五周，靠 Counter Notice 于 2017-07-11 恢复
- quote: "This is because the developer of another app filed a DMCA request and github shut down the entire repository. ... Today, Github finally reopened our repository including wiki, issues and all other content, since the 14 days waiting period"
- url: https://gadgetbridge.org/blog/category/dmca/
- source_type: primary
- published: 2017-06-25 / 2017-07-11 / 2017-07-12
- confidence: high

### [7] 配对是逆向路径的硬门槛：Mi Band 4 及以后需厂商 App（Zepp Life / Zepp / Mi Fitness）先配对并把 auth_key 推到云端，Gadgetbridge 无法本地生成密钥；解绑或硬重置会使密钥失效
- quote: "As the authentication keys are stored on vendor servers, there is no way to generate these keys locally at the moment. ... Anytime you unpair your gadget from Mi Fit / Amazfit / Zepp the pairing key will be invalidated ... Hard resetting the gadget invalidates the key"
- url: https://gadgetbridge.org/basics/pairing/huami-xiaomi-server/
- source_type: primary
- published: unknown
- confidence: high

### [8] 社区可行的 auth_key 获取路径有四条：浏览器 Watchface Maker cookie 脚本调 Zepp API、root 后读厂商 App SQLite、非 root 读 Mi Fitness 日志（encryptKey/token/authKey/huamiAuthKey）、以及 Xiaomi Cloud Tokens Extractor / huami-token / huafetcher 等云提取工具
- quote: "As the authentication keys are stored on vendor servers ... The authentication key is stored on Huami servers or in the original Mi Fit / Mi Fitness / Xiaomi Wear / Zepp app's database. There are several ways to obtain the key."
- url: https://gadgetbridge.org/basics/pairing/huami-xiaomi-server/
- source_type: primary
- published: unknown
- confidence: high

### [9] 可借鉴数据管道：Gadgetbridge 以本地 SQLite 为真相源（MI_BAND_ACTIVITY_SAMPLE / BASE_ACTIVITY_SUMMARY），支持周期性 DB/zip 自动导出、GPX 自动导出、以及设备无关的 FIT 自动导出（含 Xiaomi）
- quote: "Auto FIT export allows you to automatically export a FIT file when a new activity is synced from your devices. Unlike GPX export, this should allow for any activity to be exported, even without a GPS track. FIT export is device-agnostic: it works for any device whose parser fills Gadgetbridge's generic activity and track objects, including Xiaomi, Garmin, Huami/Amazfit..."
- url: https://gadgetbridge.org/internals/automations/auto-export/
- source_type: primary
- published: unknown
- confidence: high

### [10] 合规导出旁路：Mi Fit/Zepp Life 数据可通过 Huami GDPR 隐私页（user.huami.com/privacy2）申请导出，得到 ACTIVITY_MINUTE.csv / HEARTRATE.csv / HEARTRATE_AUTO.csv / SLEEP.csv 等 CSV，Gadgetbridge 官方提供 Python 导入脚本
- quote: "Get your Mi Fit data via GDPR data request, either from Mi Fit or via this Huami privacy settings page. ... activity_file_name = \"ACTIVITY_MINUTE.csv\"; hr_file_name1 = \"HEARTRATE.csv\"; hr_file_name2 = \"HEARTRATE_AUTO.csv\"; sleep_file_name = \"SLEEP.csv\""
- url: https://gadgetbridge.org/internals/development/data-management/
- source_type: primary
- published: unknown
- confidence: high

### [11] UX/集成范式：Gadgetbridge 0.92.0 起经 Internet Helper 上传活动到自托管健身服务 Endurain（FIT）与 Wanderer（GPX），并原生写 Android Health Connect（步数/距离/心率/SpO2/血糖/HRV/体温/呼吸率/静息心率/睡眠/体重/VO2Max/运动），数据留在本机
- quote: "Since 0.92.0 Gadgetbridge supports uploading activities directly to self-hostable fitness tracking projects, via the Internet Helper add-on. ... all data stored in Health Connect stays inside the device, no data is sent to external servers (even to Google) through this integration."
- url: https://gadgetbridge.org/basics/integrations/online-fitness-trackers/ ; https://gadgetbridge.org/basics/integrations/health-connect/
- source_type: primary
- published: unknown
- confidence: high

### [12] 与官方 App 互斥是稳定失败模式：Mi Fit（现 Zepp Life）会自启并抢连设备，导致 Gadgetbridge 无法工作；官方 App 的同步会清空设备上未拉取的活动数据
- quote: "It looks like it is not feasible to have both Mi Fit (now Zepp Life) and Gadgetbridge installed at the same time. ... In order to receive data, make sure that no other app is syncing and removing the data from your gadget."
- url: https://gadgetbridge.org/gadgets/wearables/xiaomi/ ; https://gadgetbridge.org/basics/features/sync/
- source_type: primary
- published: unknown
- confidence: high

### [13] 深睡分期是社区长期未解的失败点：旧 Huami/小米设备只给 flags/hints，真实分期疑似在 Mi Fit 端后处理，Gadgetbridge 至今忽略这些标记；部分 xiaomi-protobuf 机型（如 Mi Band 8）可同步睡眠阶段
- quote: "There is no good Deep Sleep detection on old Huami (e.g. Xiaomi and Amazfit) gadgets. ... the gadgets no longer properly distinguish between light and deep sleep but set some flags or hints for later analysis which is probably done in the Mi Fit app."
- url: https://gadgetbridge.org/basics/features/activities/
- source_type: primary
- published: unknown
- confidence: high

### [14] 云提取工具 huafetcher（huami-token 的 Kivy GUI）已于 2026-02-15 归档，最后提交 2023-08-02，说明 auth_key 提取工具链存在维护断裂风险
- quote: "This repository has been archived on 2026-02-15. You can view files and clone it, but you cannot make any changes to its state... Last commit: 2023-08-02"
- url: https://codeberg.org/vanous/huafetcher
- source_type: primary
- published: archived 2026-02-15
- confidence: high

### [15] Xiaomi protobuf 机型明确不支持第三方实时心率通道，即使官方 App 也不行，意味着 OpenTracks 等外部 App 无法拿它当 HR 源
- quote: "3rd party realtime heart rate access is not support, even with the vendor app. This means that other apps such as OpenTracks will not be able to use these devices for heart rate measurement"
- url: https://gadgetbridge.org/basics/topics/xiaomi-protobuf/
- source_type: primary
- published: unknown
- confidence: high
