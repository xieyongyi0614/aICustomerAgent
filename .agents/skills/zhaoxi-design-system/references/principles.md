# 设计原则 · 反范围 · 文案语气

---

## 1. 五条设计原则（含可判定验收规则）

设计稿 §02 的 5 条原则是**理念**。下表把它们转成**可判定**的规则 —— 用于 golden 测试与人工走查。

| # | 原则 | 含义 | 可判定验收规则 |
|---|---|---|---|
| 1 | **AI 叙事优先** | 每个页面先讲「AI 帮你理解了什么」，再展示原始数据。数据是证据，不是主角 | 每页首屏**必须**存在一个 AI 结论块（`ai-card` / `insight-hero` / 结论文案），且其**渲染顺序先于**原始数据区。走查：遮住页面下半部分，仍能看懂「AI 帮了我什么」 |
| 2 | **卡片即结论** | 拒绝 Dashboard 式表格堆叠。一张卡 = 一个 AI 结论 + 最少的支撑数据 | 全站**不得出现纯数据表格**。每个数据卡必须含一句结论文案。走查：任意卡片若只有数字没有话，判不合格 |
| 3 | **记忆可见** | AI 记住了什么、为什么记住，对用户永远透明 —— 这是与普通助手的核心差异，也是信任来源 | 每条记忆**必须**同时有「来源追溯」与（可用的）「用途回执」。走查：点开任意记忆能看到来源；被 AI 用过的记忆能看到用途 |
| 4 | **主动但克制** | 主动出现永远有固定节奏与关闭开关，绝不打扰 | 三个主动开关（早间 / 晚间 / 异常）**默认可见且可关**；关闭后不再触发。走查：关掉开关 → 到点无通知 |
| 5 | **温暖而非企业** | 圆角 18–24、暖纸白底、柔和投影；禁止后台系统式的冷灰蓝与密集边框 | 全站无冷灰蓝主色；无密集边框（1px 实线框滥用）；圆角只取 24/18/12/999。走查：与设计稿截图比对无 M3 默认特征 |

## 2. 视觉关键词（判断「像不像」的形容词标尺）

**高级 · 安静 · 陪伴感 · 长期舒适 · 温暖纸感 · 克制的科技光**

反义词（出现即为跑偏）：热闹、廉价、密集、企业感、冷、炫技。

| 来源 | 占比 | 提供什么 |

## 4. 反范围（明确不做）

**设计稿 §07「不要开发」**：

| 不做 | 理由 |
|---|---|
| 传统数据 Dashboard / 报表页 | 与「卡片即结论」正面冲突 |
| 社交、社区、排行榜 | 不是本产品形态 |
| 手动分类编辑器等重表单记账 | 记账成本必须趋近于零 |
| 运动课程 / 健康计划等重健康功能 | 不做运动健康 App，只做 AI Insight |
| 多 AI 角色市场 | 会分散人格心智 |
| 3D 虚拟形象 | V3 再说；且本产品不支持 3D 生成能力 |

**补充反范围（工程侧）**：

- 不做把跨域合成逻辑放到客户端的实现（必须服务端合成）。
- 不做医疗级健康宣称（血压 / 血糖 / 血氧诊断）。
- 不做两套设计真相（跳过 Figma 重建，以本 skill + 原型为唯一依据）。

## 5. 文案语气

### 5.1 人格设定

- AI 名 **亚丝娜**，性格「**温柔可靠 · 会主动关心你的生活**」。
- 用户示例名「阿远」（原型用例，实际取用户资料）。
- 三种模式：`Professional 高效工作` / `Default 日常陪伴` / `Immersive 沉浸角色`。

### 5.2 七条语气规则

1. **AI 用第一人称「我」或自称「亚丝娜」**，主动承担责任，不说「系统检测到」。
2. **结论前置，理由跟上**。先说「今天状态不错」，再说为什么。
3. **用「建议 / 可以 / 别忘了」，不用「必须 / 请立即」**。不命令用户。
4. **给数字，也给含义**。「7h12m」之后必须跟一句「比前几天都好」。
5. **不催促**。未完成的任务由 AI **重新排期**，而不是反复提醒。
6. **出现具体的人与关系**。「给妈妈回电话」「回复导师邮件」—— 温度来自具体性。
7. **承诺要具体**。「我会在 23:00 提醒你」优于「记得早点休息」。

### 5.3 范例文案（真源，改文案时对齐这些）

| 场景 | 文案 |
|---|---|
| 首页 Hero | 「今天也交给我吧」／「亚丝娜已为你整理好今天的一切」 |
| 模式 chip | 「Default 模式 · 长期记忆运行中」 |
| 首页 AI 总结 | 「昨晚睡了 7 小时 12 分，状态不错。今天有 3 项任务，下午 3 点记得和产品组对齐方案。本月消费节奏正常，餐饮支出比上月同期少了 8%。」 |
| 任务副文案 | 「亚丝娜已拟好草稿，确认即可发送」／「上次通话是 9 天前，别拖太久」 |
| 消费结论 | 「近 7 天日均 ¥18，比上周少 12% —— 亚丝娜」（只用结构化字段：日均 + 环比） |
| 账本观察 | 「你的餐饮支出在下降，但周末消费占了一周的 52%。如果周末想出去玩，建议把旅行基金目标从 ¥500/月调到 ¥650/月，我帮你自动划转。」 |
| 记账结果 | 「已记下。本月餐饮一共花了 ¥1,240，比上月同期少 8%，继续保持。晚餐预算还剩 ¥45。」 |
| 健康副标 | 「不是数据，是亚丝娜对你的理解」 |
| 健康叙事 | 「睡眠时长回到 7 小时以上，静息心率平稳。不过最近 7 天你的入睡时间平均推迟了 40 分钟——如果继续这个趋势，下周精力会明显下降。建议今晚 23:30 前放下工作，我会在 23:00 提醒你。」 |
| 简报状态解读 | 「昨晚你睡了 7 小时 12 分，比前几天都好。今天可以安排点硬仗。」 |
| 简报任务卡 | 「3 项待办，1 项已由我起草」／「「给妈妈回电话」排在晚间 —— 那是你效率以外的时间」 |
| 生活副标 | 「说一句话，亚丝娜帮你归位」 |
| 记忆页标题 | 「亚丝娜记住的你」／「所有记忆对你完全可见，随时可改、可忘」 |
| 隐私承诺 | 「记忆是你的资产……亚丝娜只会用记忆来帮你，不会对你隐瞒。」 |
| 版本行 | 「朝夕 v0.1.0 (MVP) · Personal AI OS 的第一步」 |
| 更新面板 · 标题（推荐） | 「新版本准备好了」／强制态：「这个版本需要更新」 |
| 更新面板 · 版本行 | 「v0.10.0 → v0.20.0」（等宽数字） |
| 更新面板 · 按钮 | 主按钮「立即更新」／「去安装」／「重试」；次按钮「稍后再说」；文字链「忽略这个版本」 |
| 更新面板 · 下载中 | 「正在下载 · 62%」＋「14.2 MB / 23.1 MB」（两行均等宽） |
| 更新面板 · 拒权 | 「还需要允许安装应用：设置 → 应用 → 允许安装未知应用」 |
| 更新面板 · 失败 | 「网络不太稳，等下再试一次」／「安装包校验没通过，我重新下载一次」／「这个安装包不是同一个签名，需要先卸载旧版本」 |
| 检查更新行 · 副标 | 「当前 v0.10.0」／「v0.20.0 可用」／「已是最新」／「正在检查…」／「检查没成功，可以再试一次」 |
| 我的页 · 版本行（真值） | 「朝夕 v<versionName> (MVP) · Personal AI OS 的第一步」（`v0.1.0` 为 `package_info` 真值，不再是硬编码串） |

### 5.4 占位文案（输入类组件统一口径）

| 位置 | 占位文案 |
|---|---|
| 首页输入丸 | 「问问亚丝娜，或直接说「午饭 35 元」…」 |
| 对话页输入栏 | 「继续说点什么…」 |
| 记账页输入栏 | 「再说一笔，例如「打车 22」…」 |
| 生活快速捕获条 | 「「记一下，下个月准备去旅行」…」 |

> 占位文案**必须带一个示例**（用「例如」或直接引号举例），这是「记账成本趋近于零」的引导手段，不是装饰。

## 6. 走查清单（交付前逐条过）

- [ ] 首屏第一眼看到的是 AI 结论，不是数据
- [ ] 没有任何纯数字卡片（每张卡都有话）
- [ ] 渐变只出现在 AI 相关元素上
- [ ] 圆角只取 24 / 18 / 12 / 999（图标方块按边长÷3）
- [ ] 只有一档常规投影
- [ ] 除 Orb 与循环指示器外，动效 ≤ 400ms
- [ ] 图标是 Lucide 2px 线性，AI 用 ✦
- [ ] 数字等宽
- [ ] 健康相关界面有免责表述
- [ ] 文案语气对照 §5.3 范例，无「系统检测到」「请立即」这类措辞
- [ ] 与设计稿截图比对无 M3 默认视觉特征
