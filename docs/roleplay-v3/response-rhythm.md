# Response Rhythm

## 1. 背景

V2 仅有 token 上限 + "简短口语化"约束，AI 仍会一次性推进大量剧情、替用户行动。

## 2. 目标

不是写得更长，而是**一次只推进合理的一小步剧情**。

## 3. 基础规则（写入 rhythm Prompt 分节）

一次回复：
- 0~2 个角色动作（含 *动作描写*）
- 0~2 句角色台词
- 尽量不主动改变场景
- 不替用户决定动作
- 不替用户决定情绪与心理
- 不主动结束剧情

## 4. 角色扮演硬约束（V3 核心）

1. **不替用户行动**：禁止"你接过西瓜""你点点头"等第二人称用户动作描写，除非用户已明确表达。正确写法："我把西瓜递到你面前。"然后等待。
2. **不凭空创造用户心理**：禁止"你一定很开心""你看起来害羞"，除非上下文有明确依据。
3. **优先延续当前行为**：存在 pending_action 时，回复必须围绕"完成 / 继续 / 取消 / 响应"它，而不是发明新剧情。
4. **用户纠正优先级最高**：SceneIntent=correct_scene 时，本轮回复唯一任务就是执行/修正 pending_action。

## 5. 实现方式

- 以 Prompt 分节注入（PromptBuilder 新增 `rhythm` 段，见 prompt-design.md），伴随 `scene` 段一起出现。
- 约束是硬规则短句列表，不是长篇说明，控制 token 开销（目标 ≤ 300 字）。
- 不做输出侧自动重写/过滤（P2 若测试发现违规率高再考虑输出校验器）。

## 6. 边界情况

- immersive 模式下 AI 需要描写环境：允许描写**自己的**动作与环境，仍禁止替用户行动。
- mode 切换（default ↔ immersive）只影响语言风格，不影响 rhythm 规则 —— 解决 V2 问题 7（模式切换过于影响剧情表现）。

## 7. 验收标准

- Case 6：回复中不出现对用户动作/心理的虚构（测试用正则 + 人工抽检）。
- Case 7：单回复动作数 ≤ 2，剧情步进 ≤ 1。
