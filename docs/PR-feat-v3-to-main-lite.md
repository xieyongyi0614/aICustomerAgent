## 概述

本 PR 将 `feat/v3` 合并回 `main`，交付 **V3 ~ V9 七个版本的能力建设** 与 **一轮后端架构重构**。

一句话概括：把「亚丝娜」从一个**只会接话的聊天机器人**，变成一个有**连续行为、长期记忆、情绪与目标、能主动开口、且行为可观测可评估**的角色 Agent。

七个版本的关系是递进的：V3~V7 构建角色的**内在**（场景 → 记忆 → 情绪 → 目标 → 行为 → 自主），V7.5 / V7.8 叠加**只读旁路**（评估与观测，不干预对话主链路），V8~V9 补齐角色的**外在世界与行动闭环**。

**所有新增能力均可开关，关闭后行为与上一版本完全一致**（有提示词字节级不变测试保障）。

## V3 · 场景状态与行为连续性

**解决什么**：让角色知道「正在做什么、做到哪一步」。

- 维护单一待办动作（如「切西瓜」）跨轮持续推进，不跑题
- 用户纠正或取消时，由代码**确定性**处理，不依赖模型猜测
- 7 类场景意图识别，识别不准时降级为普通聊天
- 回复节奏有硬约束（单步 ≤1、动作 ≤2），禁止替用户行动

## V4 · 长期记忆系统

**解决什么**：跨会话记住用户，但不乱记、不膨胀。

- 跨会话记住用户偏好与事实（如「不喝咖啡」）并自然引用
- **模型的推测永不入库**——只存用户明说或可推导的内容
- 冲突记忆自动作废旧条目，不出现自相矛盾的两条
- 用户说「别记了 / 忘了」可彻底删除
- 结构化加权召回，后台异步执行，不阻塞流式响应

## V5 · 情绪与关系动态

**解决什么**：情绪与关系可解释、不跳变。

- 情绪改为「强度 + 成因」双字段，单轮变化有上限，强情绪受保护
- 关系引入**紧张度**，过高时自动冻结升级
- 三层限速机制，防止关系数值跳变
- 每轮关系变化写入事件账本，可追溯

## V6 · 目标与意图

**解决什么**：角色从「被动接话」转向「主动有目的」。

- 长期目标模型，覆盖创建、推进、完成、放弃的完整生命周期
- 多目标冲突时按优先级**确定性**裁决
- 12 类当轮意图，模型输出非法时自动降级
- 目标与意图注入提示词，使回复带有目的性

## V6.5 · 行为精化

**解决什么**：V6 解决「想做什么」，V6.5 解决「怎么做、怎么表现」。

- 意图映射为 12 种行为策略，单轮动作数量受预算约束
- 对话模式稳定化，避免每轮跳变
- 习惯/口头禅由关系事件沉淀为候选，**需人工确认才生效**，绝不自动生效
- 回复附带「表现方式」与「活动延续」信息

## V7 · 自主行为

**解决什么**：用户不说话时，角色能**合理地主动开口**。

- 支持不活跃、时间到期等触发条件
- 八步裁决决定是否开口，配**冷却 + 静音 + 退避**三重防护
- 主动消息走独立发件箱，支持已送达确认与重试
- 记忆中的约定到期可触发主动跟进

## V7.5 · 角色一致性评估（只读旁路）

**解决什么**：回答「这个角色演得像不像」。

- 五个维度评估：人设、情绪、记忆、行为、自主
- 规则引擎 + 模型评审双层，评审失败自动降级
- 每轮对话后旁路评估，不阻塞主链路
- 支持离线回看历史对话并聚合统计

## V7.8 · 运行时智能（只读旁路）

**解决什么**：回答「它为什么会这样回复」。

- 全链路执行轨迹持久化
- 记录每次模型调用的延迟、token 与成本
- 提示词快照，保障提示词**字节级不变**
- 决策历史与评估关联，可通过请求 ID 反查现场
- 热路径性能护栏：观测开销每轮不超过 50ms

## V8 · 世界状态系统

**解决什么**：给角色一个**独立、持久的外部世界**，消除跨轮事实不一致。

- 时间、地点、物品、环境、事件独立建模，与角色状态**严格分离**
- 物品有状态机与保质期，跨会话持久化
- 拿/切/吃/买/移动/天气等由**确定性规则**解释，模型辅助默认关闭
- 事件支持定时触发与自动过期
- 世界信息进入提示词；**空世界时提示词字节不变**

## V8.5 · 关系演化系统

**解决什么**：让关系「活」起来，而不只是几个数值。

- 关系维度扩充，新增**尊重**与**亲密度**
- 交互信号识别（词表启发式，**不新增模型调用**）
- 演化引擎为纯函数，可重放
- 里程碑 + 冲突六态状态机，含疏远检测与和解流程
- 关系事件可沉淀为记忆

## V9 · 行动能力系统

**解决什么**：让角色的「承诺」真正落地为**可审计的执行**——行动 ≠ 回复。

- 确定性检出 + 六道闸门，**不引入工具调用、不新增模型调用**
- 四个可用能力：提醒、记忆、世界操作、环境查询（搜索/通知为占位）
- 执行器支持超时、重试退避与幂等
- 行动记录六态生命周期，执行结果回流世界 / 记忆 / 关系
- 提供审计端点，并新增「言过其实」评估规则

## 后端架构重构（REF-001 ~ 013）

与功能版本并行完成的一轮架构治理，全程保持「功能不变、API 不变、schema 不变、提示词行为不变」：

- **止血**：修复提示词模板注入崩溃（用户输入含 `{}` 导致 500）、日志脱敏、隐私删除失败不静默
- **编排分层**：把上帝对象拆为编排层，后台任务改为注册表挂载，新能力可**零侵入**接入
- **边界收口**：API 不再直连数据层，提示词总量有硬上界
- **一致性**：账本与状态同事务、同用户并发写串行化，消除数据漂移与丢失更新
- **可观测性增强 + 遗留清理 + 测试分层**

> 其中「后台任务注册表挂载」是关键：后续 V7.5（第 7 步）、V8（第 8 步）、V9（第 9 步）都靠它以**纯加法**接入，这是本 PR 能保持增量、可回滚的结构性原因。

## 质量现状

```
自动化测试：1499 passed, 8 skipped, 6 failed
静态检查：pylint 8.57 / 10
```

**当前有 6 个 e2e 用例失败，合并前建议修复。** 排查中定位到两个缺陷，均为 V8.5 引入：

**缺陷一：关系状态落库失败（主因，未修复）**

调用 `session.refresh(row)` 时抛 `InvalidRequestError: Could not refresh instance '<RelationshipStateRow>'`，导致**每轮关系状态与事件账本都没能写入数据库**，系统退回上一轮状态。该异常被 `try/except` 吞掉只打了 ERROR 日志，因此测试表现为「等不到结果」而非直接断言失败，单个用例要耗到超时（约 150 秒）——这是测试套件显得很慢的直接原因。

**缺陷二：关系快照 trigger 解包崩溃（已修复）**

快照写入时把「冲突迁移类型」（字符串）当作二元组解包，且判空用了 `is not None`——空字符串不是 `None`，导致每轮只要关系阶段未跃迁就抛异常。已修正类型契约与判空逻辑，并补充防回归单测（`tests/unit/test_state_service_snapshot.py`）。

> 说明：缺陷二修复后 6 个用例仍失败，因为主因是缺陷一。缺陷二的修复本身是必要且正确的，它让 V8.5 的「快照回滚」能力真正可用，但也因此暴露了被它掩盖的下层问题。
