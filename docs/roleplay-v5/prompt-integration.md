# Prompt Integration

## 1. 背景

V2 PromptBuilder 已有 mood/energy/relationship 分节。V5 加入 intensity/cause/tension，并解决核心矛盾：**情绪不能覆盖人格**。

## 2. 注入顺序（固定）

```text
1. 人格块（IDENTITY/PERSONALITY/RELATIONSHIP/BEHAVIOR——V2 角色资产，不动）
2. 【角色当前情绪】（V5 新格式）
3. 【与用户的关系】（V5 扩展 tension 档）
4. 【当前场景】（V3 scene 段）
5. 【用户记忆】（V4 memory 段）
6. 对话摘要 / 窗口消息 / 模式指令 / 行为指令
```

## 3. 情绪段新格式

```text
【角色当前情绪】
心情：happy（强度 0.7，比较明显）
原因：用户刚才主动关心了你
表达要求：情绪通过语气、用词和节奏自然流露，不要直接报出情绪名称或数值。
```

强度分档文案（代码映射，非 LLM）：≤0.3 淡淡的 / 0.3~0.6 明显的 / >0.6 非常强烈的。

## 4. 人格优先约束（关键新增）

在情绪段尾部固定追加：

> 情绪叠加在你的人格之上：无论此刻情绪如何，你说话的方式、价值观和性格底色不变。温柔的角色生气时是"温柔地生气"，不是变成另一个人。

理由：人格块在 system prompt 更前置 + 情绪段显式声明从属关系，双保险防"一生气人设就没了"。

## 5. 关系段扩展

- 沿用 STAGE_LABELS/DESCRIPTIONS，追加 tension 档描述（自然/略有尴尬/气氛紧张）。
- tension > 0.5 时追加指令："最近气氛有些紧张，对话中保持一点距离感，直到氛围缓和。"

## 6. Token 预算

- 情绪段 ≤ 120 字、关系段 ≤ 150 字（新增内容后实测校验）。
- cause 只在 Debug 与 Prompt 出现，不进 API 响应。

## 7. 验收标准

- 兼容性：无 analysis 时（V1 路径）输出不变；各段可独立省略。
- 表现验收（真实模型回归）：温柔人格 + angry 情绪的回复仍是亚丝娜口吻但明显带刺/克制，而非暴躁失格。
- 各段超预算时截断策略生效。
