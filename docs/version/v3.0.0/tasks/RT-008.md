## 2. Background

### 2.1 为什么需要这个 Task

决策代码路径**已经统一**（`decision_pipeline.run_pipeline` 是唯一入口，前台 `chat_response` 与后台自主共用），但**入口有三处**、输入装配各不相同：

| 入口 | 事实 |
|---|---|
| `chat_pipeline._run_foreground_decision` | 前台：装配 stack / capabilities / chat_response 参数 |
| `life_loop._step_decision` → `autonomy_engine._process_user` | 后台：装配 `_pipeline_intention` / snapshot / tool_facts / plan_facts |
| `autonomy_engine._snapshot_for` / `_collect_*_facts` | 输入装配散落，无统一契约 |

循环缺少 Reason 段，导致「输入装配」与「决策管线」之间的边界模糊：任何想接入新触发源的人都要重写一遍装配。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 决策输入装配无契约 | 前台 / 后台各自装配，新触发源要复制装配逻辑 |
| 2 | `Intention` 无统一值对象 | 决策产物以 `DecisionResult` + `intention: str` 散落传递 |
| 3 | LLM 参与度不可见 | 「这次决策有没有 LLM 参与、走了哪档」无统一标记 |

### 2.3 在 V3.0 Runtime 中的位置

Reason 是六段第二段：消费 `Observation`（RT-007）+ `RuntimeState`（RT-003）+ 上下文（RT-004），产出 `Intention` 交给 Plan（RT-009，可选）与 Act（RT-010）。它是**唯一**允许产出「本轮做什么」的段，也是前台 / 后台唯一分叉点（候选构成差异）。

## 3. Scope

### 3.1 In Scope

1. **`reason(...) -> Intention`**（`stages/reason.py`）。
2. **输入装配**（本任务唯一新增的装配逻辑，全部为既有读面的编排）：目标栈读面（`services.goal_stack`）、状态快照（RT-003）、工具 / 行动 / 计划事实（`autonomy_engine.collect_tool_facts` / `_collect_action_facts` / `_collect_plan_facts`）、世界影响与日程（`world_engine` 既有只读面）、世界 / 关系闸输入（`decision_pipeline` 内部使用）。
3. **候选构成分叉**：前台 Run 传 `chat_response=True` + `chat_response_intention`；后台 Run 传 `trigger_intention` / `trigger_goal_id` / `capabilities`（后台经 `autonomy_engine.resolve_autonomy_surface` 解析能力面）。
4. **LLM 参与标记**：`Intention.llm_used` 由 LLM Gateway 记账结果（`llm_gateway.acquire` 是否授予）与既有决策链路径共同决定；全部 LLM 调用经 Gateway。
5. **意图确定性校验**：产出后经 `services.intention_policy.enforce`（前台既有语义）保持策略降级行为不变。
6. **审计落点**：`DecisionResult.audit` 仍经 `observability.on_decision` 落 `decision_records`（既有链路，零改动）。

### 3.2 Out of Scope（明确禁止扩张）

- **零决策数学改动**：不改 `collect_candidates` / `assign_priorities` / `score_candidates` / `run_risk_gates` / `select` / `_intention_for` 的系数、阈值、tiebreak。
- 不新增候选来源、不新增能力、不新增人格闸 / 关系闸规则。
- 不写 `decision_records` / `goals` / `memories`（只读 + 按既有链路落审计）。
- 不实现 mode / scene / behavior 裁决本体（属既有 `mode_service` / `scene_service` / `behavior_engine`，前台收编归 RT-015）。
- 不做 Plan（RT-009）、不做 Act（RT-010）、不做回写（RT-012）。
- 不直调 `chain` / `ChatOpenAI`（LLM 必经 `llm_gateway`）。
- 不新增设置字段。

## 4. Technical Design Requirements

### 4.1 接口契约（`stages/reason.py`）

```python
@dataclass(frozen=True, slots=True)
class Intention:
    intention: str | None        # 决策产出意图（None = 不行动 / 纯回复）
    goal_id: str | None          # 胜出候选绑定目标
    source: str                  # 候选来源（decision_pipeline.Candidate.source）
    priority: str | None         # 候选 P 级
    confidence: float | None     # 候选综合分
    llm_used: bool               # 本轮是否有 LLM 参与（Gateway 记账结果）
    audit: Mapping[str, Any]     # 候选审计只读快照（落 decision_records 用）
    decided_at: datetime

def build_stack(user_id: str, character_id: str = DEFAULT_CHARACTER_ID): ...
def capabilities_for(spec: ProfileSpec) -> list[str]: ...

async def reason(runtime_input: RuntimeInput | None,
                 session_context: SessionContext | None,
                 observation: Observation, *,
                 spec: ProfileSpec, runtime_state=None,
                 llm=None, run=None, now: datetime | None = None,
                 trace=None) -> Intention: ...
```

### 4.2 输入装配（全部既有读面，本段只编排）

| 输入 | 来源 |
|---|---|
| 目标栈 | `services.goal_stack`（`GoalStack` / `evaluate_stack` 读面；**不调** `retire_overdue`） |
| 状态快照 | `runtime_state.snapshot`（RT-003）或 `state.snapshot()` |
| 能力 / 工具面 | `autonomy_engine.resolve_autonomy_surface` + `collect_tool_facts` |
| 行动 / 计划事实 | `autonomy_engine._collect_action_facts` / `_collect_plan_facts` |
| 世界影响 / 日程 | `world_engine.collect_facts` / `_plan_schedule_context`（只读） |
| 工具洞察 | `autonomy_engine.collect_tool_insights` |
| LLM | `llm_gateway.acquire(user_id, "decision"|"proactive", run, now=now)`；未获批 → 规则兜底且 `llm_used=False` |

**唯一决策调用**：`decision_pipeline.run_pipeline(stack=…, snapshot=…, trigger_intention=…, trigger_goal_id=…, capabilities=…, chat_response=…, chat_response_intention=…, chat_response_goal_id=…, run=…, now=…, world_impacts=…, world_schedule=…, tool_insights=…)`。

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 决策**唯一入口**是 `run_pipeline`；本段零第二套候选 / 打分逻辑 | V2.1 红线 + ADR 11「前台 / 后台同一决策代码路径」 |
| D2 | 前后台分叉**只在候选构成与预算档**（`chat_response*` vs `trigger_*` + `capabilities`） | architecture §2.2 |
| D3 | 决策数学零改动（系数 / 闸门 / tiebreak 全不动） | RT-008 Out of Scope |
| D4 | LLM 必经 `llm_gateway`；拒绝 → 规则路径 + `llm_used=False` + Run degraded | architecture 附：边界不变量 4 |
| D5 | `Intention` 是运行期值对象：审计仍经 `observability.on_decision` 落 `decision_records`，本段零写表 | 单一写面纪律 |
| D6 | 意图校验复用 `intention_policy.enforce`（前台策略降级语义不变） | 行为零回归 |

### 4.4 依赖

- 允许：`decision_pipeline`、`goal_stack`、`intention_policy`、`autonomy_engine`（**只读投影函数**）、`world_engine`（只读）、`state`（RT-003）、`contracts`、`llm_gateway`。
- 禁止：`app.chains` / `app.prompts` 直调、写仓储、具体渠道实现、`chat_pipeline`（收编属 RT-015）。
