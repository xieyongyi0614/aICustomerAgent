## 2. Background

### 2.1 为什么需要这个 Task

V3.0 是本系统第一次做「运行时内核」级别的重构：涉及契约冻结、前后台收编、Schema 变更（`0052`）与真实流量路径。任何一项的回归都会直接作用于生产链路（Web + 飞书）。因此版本需要一个**独立、可判定、可留痕**的验收任务，而不是把验收散落在各 Task 的提交信息里。

### 2.2 当前风险面（验收必须覆盖）

| 面 | 风险 | 验收动作 |
|---|---|---|
| 契约 | 字段被后续任务私改 | 契约冻结测试（RT-001）+ 评审记录核对 |
| 前台 | 流式契约 / golden 漂移 | e2e + golden 全绿 + 基线对照（RT-015） |
| Schema | 多余迁移 / 表 / 列 | `SCHEMA_TABLE_COUNT == 45`、`MIGRATION_HEAD == "0052"` |
| Preserve | 域语义被顺手改动 | §4.2 清单逐模块 `git diff` 为空 |
| 开关 | 默认值漂移 / 版本前缀回归 | 影子矩阵核对（全部默认 off、零 `v30_` 前缀） |
| 边界 | 分层反向依赖、渠道 import 泄漏 | 静态扫描用例汇总执行 |

### 2.3 在 V3.0 Runtime 中的位置

RT-020 是版本收口：它不产出任何业务代码，只产出**证据**（测试结果、diff 证据、基线对照）与**人工回归清单**。它是 tasks.md §6（版本级 Acceptance Criteria）的唯一执行点。

## 3. Scope

### 3.1 In Scope

1. **Gate 执行**：逐一执行并记录 tasks.md §6.1 的 G1 ~ G12（每个 Gate 记录：判据 / 验证方式 / 结果 / 证据链接）。
2. **全量回归**：Fast Test、Integration、E2E、golden、`tests/v30` 全绿；既有版本目录（v2 / v21 ~ v26 / v7.8 等）零回归。
3. **影子矩阵核对**：全部 `runtime_*` 开关默认值核对（`runtime_session_tracking_enabled=False` … `runtime_orphan_run_sweep_enabled=True` 例外按 RT-018 定义）；Flag 全 off 时全量回归与 V2.6.1 逐字节一致。
4. **边界复检**：architecture 附「边界不变量清单」9 条逐条断言；Preserve 清单（tasks.md §0.5）模块 diff 为空。
5. **性能基线**：记录段级耗时、Run 开销、0 LLM 段零调用（只记录，不优化）。
6. **文档产出**：`acceptance-report.md`（Gate 结果 + 证据）与 `regression-checklist.md`（真实模型人工回归用例）。

### 3.2 Out of Scope（明确禁止扩张）

- **零代码改动**：本任务不新增 / 修改任何生产代码；发现缺陷 → 回到对应 Task 修复后重跑 Gate。
- 不做性能优化（只记录基线）。
- 不改 Preserve 模块、不改前端、不改提示词。
- 不实现 Backlog 项（V3.1 记忆演化 / V3.2 反思 / V3.3 Self Improvement / 多角色 / Discord / MCP）。
- 不提交 / 推送（除非用户明确要求）。

## 4. Technical Design Requirements

### 4.1 Gate 验证矩阵（G1 ~ G12 的执行方式）

| Gate | 验证方式（命令 / 动作） |
|---|---|
| G1 契约冻结 | `pytest tests/v30/test_runtime_contracts.py -v` + 契约冻结表评审记录 |
| G2 单一循环 | `test_stage_order_only_from_profiles` + `test_single_loop_path` |
| G3 边界不变量 | 各 Task 静态扫描用例汇总 + 分层依赖审查 |
| G4 Preserve 零改动 | `git diff <基线>..HEAD -- <preserve 清单>` 为空 + 对照测试 |
| G5 零新表 | `SCHEMA_TABLE_COUNT == 45` 钉测 + 列摘要核对 |
| G6 迁移可逆 | `uv run alembic upgrade head` / `downgrade -1`（需 `TEST_DATABASE_URL`） |
| G7 零回归 | Fast + Integration + E2E + golden + 各版本目录全绿 |
| G8 降级语义 | `test_terminal_status_for_recoverable_matrix` + 循环降级用例 |
| G9 预算纪律 | LLM Gateway 记账断言 + 0 LLM 段零调用用例 |
| G10 全链可观测 | `test_full_observability_chain_foreground/background` |
| G11 恢复语义 | `test_sweep_converges_timed_out_running_run` + `test_no_replay_on_restart` |
| G12 多渠道可扩展 | RT-013 / RT-014 静态断言 + 等价性用例 |

## 5. Implementation Plan

1. **影子核对**：检查 `core/settings/agent_runtime.py` 全部 `runtime_*` 字段默认值与 tasks.md §0.4 一致；确认无 `v30_` 版本前缀。
2. **全量测试**：按 §7 顺序执行（Fast → v30 → Integration → E2E → golden → 各版本目录），失败项回到对应 Task 修复后重跑。
3. **边界复检**：执行 Preserve 清单 `git diff`；执行分层 / 渠道 import 静态扫描。
4. **性能基线**：记录前台 Run 段耗时分布、后台 tick 周期耗时、0 LLM 段调用数（只记录，不优化）。
5. **产出 `acceptance-report.md`**：G1~G12 结果表 + 证据 + 影子矩阵 + 性能基线 + 遗留问题登记。
6. **产出 `regression-checklist.md`**：真实模型人工回归用例（前台多轮对话 / 后台 tick 观察 / 主动行为投递 / 渠道切换 / 孤儿 Run 恢复 / 回放取材抽查 / 开关灰度顺序）。
7. **收尾**：`git status` 干净、无临时产物；提交（§9）。

## 7. Testing Requirements

### 7.1 全量测试命令（按序执行，失败即停）

```powershell

uv run pytest tests/v30 -q                              # 2) V3.0 新增
uv run pytest -m integration -q                         # 3) Integration（无 PG 实例自动 skip）
uv run pytest -m e2e -q                                 # 4) E2E 全链路
```
