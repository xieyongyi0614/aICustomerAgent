## 2. Background

### 2.1 为什么需要这个 Task

观测三层已建两层：`loop_runs`（行为台账）与 `runtime_traces`（turn 级足迹，`kind ∈ ('turn','proactive','autonomy_tick')`，`steps` / `events` JSON）。RT-005 ~ RT-017 在循环内发出了段级事件并调用了 `TurnTraceSession.record`，但：

- **段级足迹没有统一消费面**：`trace_collector` 是内存缓存（`trace_capacity=20`），落库仍由 turn 链路驱动；后台 Run 的段级信息只存在 `loop_runs.steps`。
- **`correlation_id` 列已建未消费**（RT-002 迁移 `0052` 建，无写入方）。
- **无法按 `run_id` / `session_id` 回溯**一次循环的完整序列。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 查询按 turn 维度 | 无 `run_id` / `session_id` / `correlation_id` 维度的回溯 |
| 2 | Debug 视图不成体系 | 段顺序 / 耗时 / 降级原因需要人肉拼 JSON |
| 3 | Replay 无取材入口 | architecture §7.2 的「按 snapshot_version 对齐重放」无查询面 |

### 2.3 在 V3.0 Runtime 中的位置

RT-019 是可观测的**消费半边**：RT-005（事件）/ RT-006（段）/ RT-017（主动链）产生素材，RT-018（执行历史投影）提供跨表读取，本任务把它们组织为「Debug / Replay / Evaluation」三种消费场景的统一查询面。

## 3. Scope

### 3.1 In Scope

1. **`correlation_id` 消费**：trace 落库时填充 `runtime_traces.correlation_id`（来源：Run / 段事件的 `correlation_id`，含 RT-017 主动链）。
2. **Trace 查询面**（新增 `services/observability/trace_query.py`）：`by_run_id(run_id)` / `by_session(session_id, limit)` / `by_correlation(correlation_id)`——只读，走 `trace_repository` / `loop_run_repository` 既有读方法。
3. **Run 级调试视图**：`run_debug_view(run_id)` —— 六段顺序、每段 `duration_ms` / `status` / 降级原因、`ErrorKind` / `stage`、token usage、事件序列（来自 `loop_runs.steps` + `runtime_traces`）。
4. **Replay 取材**：`replay_bundle(run_id)` —— 以 `agent_state_snapshots` 为时点锚点的只读包（快照 + 决策 + 行动 + 状态变更 + trace），**不执行副作用**。
5. **脱敏与保留**：沿用 `observability_prompt_redact` / 各 `*_retention_days`；新增查询不改清理行为。
6. **零写入**：查询面零 DB 写（Evaluation 仍为只读旁路，V7.5 铁律）。

### 3.2 Out of Scope（明确禁止扩张）

- 不新增观测表 / 列 / 迁移（只消费 `0052` 的 `correlation_id`）。
- 不改前端控制台、不做 Trace 可视化 UI。
- 不新增 Evaluation 规则 / 指标（V2.1 AGENT-006 既有）。
- 不改采样 / 脱敏 / 保留期数值与 `observability_persist_enabled` 门控。
- 不改 `trace_collector` 的内存容量与缓存策略（`trace_capacity` 既有）。
- 不做事件回放执行（RT-018 已明确只读取材）。

## 4. Technical Design Requirements

### 4.1 接口契约（`services/observability/trace_query.py` + `observability.py` 扩展）

```python
# trace_query.py（全部只读）
@dataclass(frozen=True, slots=True)
class RunDebugView:
    run_id: str
    session_id: str | None
    run_kind: str
    trigger_type: str | None
    status: str
    started_at: datetime
    finished_at: datetime | None
    stages: tuple[Mapping[str, Any], ...]     # loop_runs.steps（duration_ms / status / 降级原因）
    llm_call_count: int
    budget_state: Mapping[str, Any]

@dataclass(frozen=True, slots=True)
class ReplayBundle:
    run_id: str
    snapshot_anchor: Mapping[str, Any] | None
    decisions: tuple[Mapping[str, Any], ...]
    actions: tuple[Mapping[str, Any], ...]
    traces: tuple[Mapping[str, Any], ...]

def by_run_id(run_id: str) -> RunDebugView | None: ...
def by_session(session_id: str, *, limit: int = 50) -> list[RunDebugView]: ...
def by_correlation(correlation_id: str) -> list[Mapping[str, Any]]: ...
def replay_bundle(run_id: str) -> ReplayBundle | None: ...

# observability.py 扩展
def bind_correlation_id(correlation_id: str | None) -> None: ...   # 落库时填充 correlation_id
```

### 4.2 三种消费场景（architecture §7.2 落地）

| 场景 | 查询 | 数据层 |
|---|---|---|
| **Debug** | `by_run_id` / `by_correlation` | `loop_runs.steps` + `runtime_traces`（段顺序 / 耗时 / 降级 / 错误） |
| **Replay** | `replay_bundle` | `agent_state_snapshots` 锚点 + `decision_records` + `action_records` + trace |
| **Evaluation** | `history_for_run`（RT-018 投影）+ 既有指标 | 全三层，只读旁路 |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 查询面**零写入**；`correlation_id` 只在 trace **落库时**填充 | V7.5 Evaluation 铁律 + 边界不变量 3 |
| D2 | Debug 视图以 `loop_runs.steps` 为权威段序，`runtime_traces` 为补充 | Run 台账是行为权威 |
| D3 | `correlation_id` 只来自既有链路（RT-017 主动链 / Run / 段事件），本任务**不新造键** | 键语义归产生方 |
| D4 | Replay bundle 不执行任何副作用（不调域服务、不写表） | RT-018 D5 一致 |
| D5 | 脱敏 / 采样 / 保留期沿用既有设置；新增字段不改清理行为 | 观测成本可控 |
| D6 | 不新增观测表 / 列 / 迁移；不改 `trace_collector` 缓存策略 | RT-019 Out of Scope |

### 4.4 依赖

- 允许：`trace_repository` / `loop_run_repository` / `decision_repository` / `action_repository` / `agent_state_snapshot_repository`（只读）、`execution_history`（RT-018）、`trace_collector`（读内存态）、`app.core.settings`。
- 禁止：任何写仓储、`app.chains` / `app.prompts`、Evaluation 规则改动、具体渠道实现。

## 10. 实现回写（偏差登记，2026-09-22）

实现与本文冻结规格的偏差如下；**未新增表 / 列 / 迁移**（AC6 成立）。

| # | 偏差 | 理由 |
|---|---|---|
| D-1 | `repositories/trace_repository.py` 的 `_to_model` / `_from_model` 补 `correlation_id` 直通（§6.2 未列该文件） | `RuntimeTrace` 落库必经此映射，不直通则列恒为 NULL、`by_correlation` 与 RT-018 `history_for_run` 均取不到数据。仅字段直通，`save` 写语义零变化。 |
| D-2 | `models/observability.py` 的 `RuntimeTrace` 增 `correlation_id: str \| None = None` | 值对象字段（非 Schema 变更）。`api_dict()` **刻意不加**该键 → `/api/v1/debug` 响应逐字段不变（前端零改动）。 |
| D-3 | `correlation_id` 在 `on_turn_finished` / `on_turn_error` **同步捕获后显式下传**，不在 `_assemble_trace` 内读 ContextVar | `spawn_background` 在跨线程分支走 `run_coroutine_threadsafe`，**不复制 contextvars** → 在读点取值会丢。 |
| D-4 | `services/observability/__init__.py` 用 PEP 562 `__getattr__` **惰性导出**查询面符号（非模块级 import） | `app.chains` → `llm_capture` 会触发本包 `__init__`，而 `trace_query` 依赖 `agent_runtime` 聚合包（其 `__init__` 反向导入本包）→ 模块级导入成环并把整个运行时拉进 LLM 热路径。 |
| D-5 | `ReplayBundle` 增 `state_changes` 字段（§4.1 契约未列） | §3.1 第 4 项明确要求回放包含「状态变更」；取材委托 RT-018 `execution_history.history_for_run`（§4.4 允许），不重复实现跨表关联。 |
| D-6 | `RunDebugView` 增 `degraded` / `failed_stages` / `correlation_id` 只读派生属性；`stages` 条目补 `phase` / `error_kind` | `error_kind` 由 `loop.STAGE_TO_PHASE` / `ERROR_KIND_BY_PHASE` **唯一映射表**派生（不复制映射）；未知阶段（`abort` / `orphan_sweep`）标记 `None` 而非抛错。`promote_degraded=False` 的后台 Run 终态仍为 `done`，故降级判定需兼看段落账。 |
| D-7 | `by_session` 返回**升序**（旧 → 新）时间线 | §4.1 未定序；与 `trace_repository.list_by_correlation_id` 升序一致，符合 Debug/Replay 阅读方向。 |
| D-8 | `by_correlation` 关联策略 | trace 按 `correlation_id`；decision 按 `request_id` + trace 携带的 `action_id`；action 按 `run_id` + 上述 `action_id` —— 覆盖 RT-017 主动链 `proactive:{dedupe_key}`（其 action 无 `run_id` 匹配）。 |
