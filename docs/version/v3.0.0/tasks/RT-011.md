## 2. Background

### 2.1 为什么需要这个 Task

Reflection 已在 V2.6.1 建齐（证据窗聚合 → LLM 结构化推理 → confidence 校准 → 三闸复检 → Insight 落库），并有两条触发路径：

| 路径 | 位置 |
|---|---|
| 周期触发 | `services/reflection/triggers.run_reflection_trigger_tick`（经 job worker 注册：`register_with_job_worker`） |
| 执行 | `services/reflection/reflector.run_queued_reflections` / `execute_run`（queued run 消费） |

但循环里没有 Reflect 段，`life_loop._step_reflection_check` 只是「检查是否该反思」的一步。结果：慢时钟与快时钟的**边界只在文档里**，循环内无法表达「这一段是慢时钟」。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 慢时钟无显式段 | 快慢分离只在调度层体现，循环内不可观测 |
| 2 | 循环与周期可能重复反思 | 若在循环内直接触发，可能与周期 tick 重复产出 Insight |
| 3 | 证据源未显式 | 行动 / 工具 / 指标证据的选取散落在 reflector 内部 |

### 2.3 在 V3.0 Runtime 中的位置

Reflect 是六段第五段、**可选 / 慢时钟段**：由 `OPTIONAL_PHASES` 与 `runtime_loop_optional_stages` 裁决是否进入；证据源包含 Act 段产生的行动结果（`ActionCompleted` 事件窗）与既有指标快照；产物（`Insight`）交给 Update 段（RT-012）调制后续轮次。它**不改变循环形状**，只是把既有能力挂到显式位置（为 V3.2「持续反思」预留）。

## 3. Scope

### 3.1 In Scope

1. **`reflect(...) -> list[InsightRef]`**（`stages/reflect.py`）。
2. **触发接线**：复用 `services.reflection.triggers.trigger_for_user(...)`（入队）与 `reflector.run_queued_reflections(...)` / `execute_run(...)`（执行），不经新任务系统。
3. **幂等共存（Q4）**：与周期路径共用既有去重判据（`_scheduled_already_handled` / `_quota_used` / 证据窗 bucket key），同窗不重复产出。
4. **证据源显式化**：`ActionCompleted` 事件窗（RT-005）+ `agent_metric_snapshots`（既有）+ 既有 reflection evidence 选择面（只读）。
5. **预算**：慢时钟 LLM 调用走后台档；预算不足 → 跳过该段并记 degraded（不抛错）。
6. **开关**：`runtime_reflect_in_loop_enabled`（默认 `False`）+ 注册进 `tests/v30/runtime_support.py`。

### 3.2 Out of Scope（明确禁止扩张）

- 不改三闸（confidence 校准 / 复检）、`Insight` 生命周期、证据窗聚合数学（`services/reflection/**` 全 Preserve）。
- **不做循环内持续反思 / 目标导向反思**（V3.2 范围）。
- 不新增 job worker / 常驻循环 / 表 / 列 / 迁移。
- 不直写 `insights` / `reflection_runs` / `evidence_links`（落库仍经既有 `reflector._persist`）。
- 不改 `life_loop._step_reflection_check` 与 job worker 注册（收编归 RT-016）。
- 不新增 `Insight` 类型。

## 4. Technical Design Requirements

### 4.1 接口契约（`stages/reflect.py`）

```python
@dataclass(frozen=True, slots=True)
class InsightRef:
    insight_id: str
    insight_type: str                # 既有 Insight 类型（不新增）
    confidence: float
    summary: str

@dataclass(frozen=True, slots=True)
class ReflectOutcome:
    triggered: bool                  # 是否入队 / 执行了反思
    skipped_reason: str | None       # budget | quota | duplicate_window | disabled
    insights: tuple[InsightRef, ...]
    llm_used: bool

async def reflect(*, action_outcome: ActOutcome | None = None,
                  session_context: SessionContext | None = None,
                  run=None, llm=None, now: datetime | None = None,
                  trace=None) -> ReflectOutcome: ...

def evidence_window_key(user_id: str, now: datetime) -> str: ...
```

### 4.2 接线面（全部既有）

| 动作 | 既有接口 | 说明 |
|---|---|---|
| 入队触发 | `services.reflection.triggers.trigger_for_user(...)` | 内部含 bucket / quota / 日程判定（`_scheduled_already_handled` / `_quota_used`） |
| 执行 | `services.reflection.reflector.run_queued_reflections(now, trace)` / `execute_run(run_id, trace)` | 含三闸（confidence 校准 / 复检 / 落库） |
| 证据源 | `ActionCompleted` 事件窗（RT-005）+ `agent_metric_repository`（既有）+ reflection evidence 选择面 | 全部只读 |
| 落库 | `reflector._persist`（内部） | 本段零直接表写 |

### 4.3 关键裁决（Q4 落地）

| # | 裁决 | 理由 |
|---|---|---|
| D1 | Reflect 段是**可选慢时钟段**：`runtime_loop_optional_stages` 含 `reflect` 且 `runtime_reflect_in_loop_enabled=True` 才进入 | Q4：Profile 显式段 + 预算裁决 |
| D2 | **幂等共存**：与周期路径共用 triggers 的 bucket / quota 去重键；同窗命中即跳过（`duplicate_window`） | 避免重复 Insight 污染认知 |
| D3 | 三闸与 Insight 生命周期**零改动**：本段只调 `run_queued_reflections` / `execute_run` | `services/reflection/**` 全 Preserve |
| D4 | 预算：慢时钟 LLM 走后台档；不足 → `budget` 跳过 + 段 degraded，不抛错 | 慢时钟不应拖垮快时钟 |
| D5 | 默认**关闭**，开启后叠加在既有周期反思之上（不替换） | 灰度安全，关闭即回 V2.6.1 |
| D6 | 不新增 job worker / 常驻循环（反思执行仍由既有 job worker 消费） | 避免第二套调度 |

### 4.4 依赖

- 允许：`app.services.reflection.triggers`、`app.services.reflection.reflector`、`events`（RT-005，读证据窗）、`agent_metric_repository`（只读）、`ActOutcome`（RT-010）、`app.core.settings`。
- 禁止：`insights` / `reflection_runs` / `evidence_links` 直写、`app.chains` / `app.prompts` 直调、改动既有 job worker 注册逻辑。

## 5. Implementation Plan

1. 实现值对象 `InsightRef` / `ReflectOutcome` 与 `evidence_window_key`（复用 triggers 的 bucket key 构造，不新造算法）。
2. 实现 `reflect(...)`：
   - 门控：开关关（`disabled`）或可选段未启用 → 直接返回；
   - 预算检查（后台档）→ 不足即 `budget` 跳过 + degraded；
   - 触发：`trigger_for_user(...)`（入队）→ 命中去重 → `duplicate_window`；
   - 执行：`run_queued_reflections(now, trace)` → 归集 Insight 投影为 `InsightRef`。
3. `loop.py` 的 `reflect` 段委派指向 `stages.reflect.reflect`（`OPTIONAL_PHASES` 已含 `reflect`）。
4. 设置：`core/settings/agent_runtime.py` 加 `runtime_reflect_in_loop_enabled: bool = False`；`tests/v30/runtime_support.py` 登记。
5. 测试 `tests/v30/test_runtime_reflect_stage.py`（§7）。
6. Focused → Module → Fast 后提交（§9）。
