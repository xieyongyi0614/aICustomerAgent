## 2. Background

### 2.1 为什么需要这个 Task

出站目前**半直连**：`channels/feishu/delivery.py` 内既定义 `FeishuChannelAdapter.send`（通道无关契约的实现），又直接提供业务化投递函数 `deliver_reply(outcome)` / `send_proactive(...)`，并且这两个函数**自己构造并发送**消息。调用方（回复回传、主动投递）只能经飞书专用函数出站，其它渠道要复制这套逻辑（C3）。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| C3 | 出站半直连 | 主动投递与 Feishu delivery 内含通道专属逻辑，未统一走 `ChannelAdapter.send` |
| — | 适配器无统一解析点 | `FeishuChannelAdapter()` 在 delivery 内部各处直接实例化 |
| — | 幂等键生成分散 | 回复键与主动键的组装逻辑在渠道内 |

### 2.3 在 V3.0 Runtime 中的位置

Outbound Gateway 是 Runtime 的**唯一出站面**（architecture §8.1）：`Agent Runtime → Outbound Gateway → 各 Channel Adapter`。RT-017（自主行为触发与投递）依赖它把主动行为投递统一出站；RT-015（前台收编）不改变出站语义（回复仍经同一出口）。

**分层要点**：`outbound.py` 在 application 层，**只依赖 `channels.base` 的 Protocol**；具体适配器由**组合根**（`app/main.py` 或渠道 API 层）注册——这两处允许 import `app.channels.feishu`。

## 3. Scope

### 3.1 In Scope

1. **适配器注册表（代码静态注册）**：`register_adapter(channel, adapter)` / `resolve_adapter(channel)` / `registered_channels()` / `clear_adapters()`（测试助手）。
2. **统一投递**：`deliver(message: OutboundMessage, *, trace=None) -> SendResult`——解析 channel → 命中适配器 → `await adapter.send(message)` → 归一 `SendResult`；失败**不抛异常**。
3. **幂等键契约**：回复 = `(reply_ref, index)`；主动 = `(channel, external_id, idempotency_key, index)`（沿用既有语义，键生成保持由调用方提供）。
4. **逐渠道切换**：`runtime_outbound_gateway_channels`（csv）控制已纳管渠道；未纳管渠道走既有 `delivery.deliver_reply` / `send_proactive`。
5. **调用点收敛**：把主动投递调用点改为经 Gateway（实现前先枚举调用点，见 §5 步骤 1），回复投递保持既有调用链但出口统一。
6. **可观测**：投递结果落 Trace（`SendResult.ok` / `error` / `external_message_id`），失败不冒泡。

### 3.2 Out of Scope（明确禁止扩张）

- 不做文案生成 / 消息模板 / 分片策略（`outbound.split_text` 等既有能力保持原样，由适配器或调用方使用）。
- 不新增渠道实现（Discord 不实现）；不改 `channels/base.py` 契约。
- 不改 `feishu_deliveries` 幂等台账语义、不改 `delivery._claim_delivery` 钩子机制。
- 不做重试 / 退避 / 队列（投递失败即返回，重试策略如需属于渠道侧或后续版本）。
- 不新增表 / 列 / 迁移；不新增常驻循环。
- 不接管回复生成与 SSE 流（属 RT-015 与既有链路）。

## 4. Technical Design Requirements

### 4.1 接口契约（`outbound.py`）

```python
def register_adapter(channel: str, adapter: ChannelAdapter) -> None: ...   # 组合根注册
def resolve_adapter(channel: str) -> ChannelAdapter | None: ...
def registered_channels() -> frozenset[str]: ...
def clear_adapters() -> None: ...                      # 测试助手
def is_enabled(channel: str) -> bool: ...              # runtime_outbound_gateway_channels

async def deliver(message: OutboundMessage, *, trace=None) -> SendResult: ...
async def deliver_reply(outcome, *, trace=None) -> SendResult: ...   # 兼容入口：内部走 deliver
```

**投递语义**：`deliver` 解析 `message.channel` → 未纳管 / 未注册 → 返回 `SendResult(ok=False, error=DISABLED)`；命中 → `await adapter.send(message)`；任何异常归一为 `SendResult(ok=False, error=UNKNOWN)`（**不抛异常**）。

### 4.2 调用点与切换

| 场景 | 现状 | 收编后 |
|---|---|---|
| 回复投递 | `channels/feishu/adapter.py:180` → `delivery.deliver_reply(outcome)` | `outbound.deliver(...)`（飞书适配器已实现 `send`，注册后即走统一出口） |
| 主动投递 | `services/proactive_executor.py` → `delivery.send_proactive(...)`（AUTO-005 两阶段投递） | `outbound.deliver(...)`；`proactive_executor` 的「生成可重试、投递失败不出错」语义保留 |
| 未纳管渠道 | 既有路径 | 行为逐字节不变 |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 具体适配器由**组合根注册**（`app/main.py` 或渠道 API 层，允许 import `app.channels.feishu`）；application 层只依赖 `ChannelAdapter` Protocol | 遵守「核心层不得 import `app.channels.<impl>`」边界 |
| D2 | `idempotency_key` 仍由调用方提供（回复 / 主动两套既有键形），Gateway **不新造键** | 幂等语义零改动（`feishu_deliveries` 台账不变） |
| D3 | 失败以 `SendResult` 表达，**不冒泡**；调用方按既有语义决定是否标记状态 | 「投递永不冒泡」是既有纪律（SendResult 而非异常） |
| D4 | 逐渠道切换（csv 默认空 → 行为不变）；飞书可先切 | Q5 同批策略，风险可控 |
| D5 | Gateway 不做重试 / 退避 / 队列 / 分片 | 避免把渠道策略搬到 Runtime；分片仍由渠道 `outbound.split_text` 处理 |
| D6 | 不新增 `SendResult` 语义与错误类型：直接复用 `channels.base.SendResult` / `ChannelErrorKind` | 契约零改动 |

### 4.4 依赖

- 允许：`app.channels.base`（`OutboundMessage` / `SendResult` / `ChannelAdapter` Protocol）、`inbound`（渠道清单）、`contracts`、`app.core.settings`。
- 禁止：`app.channels.feishu`（核心层禁止；注册在组合根完成）、写仓储、`app.chains` / `app.prompts`。

## 5. Implementation Plan

1. **枚举调用点**（实现前必做）：检索 `send_proactive` / `deliver_reply` / `FeishuChannelAdapter` 全部调用点并登记（已知：`channels/feishu/adapter.py:180`、`services/proactive_executor.py`）。
2. 实现 `outbound.py`：注册表 + `deliver` + `deliver_reply` 兼容入口 + Trace 记录。

6. 测试 `tests/v30/test_runtime_outbound_gateway.py` + 飞书投递回归（§7）；Focused → Module → e2e 后提交（§9）。
