## 2. Background

### 2.1 为什么需要这个 Task

`Run`（`loop_runs`）是**行为单位**，但「会话」不是一等概念：`conversations` / `messages` 表里有 `session_id` 语义（对话内容按会话组织），而 `loop_runs` **没有** `session_id`。后果是台账无法回答「这个会话发生过哪些 Run」，也无法把前台对话 Run 与后台 tick Run 归到同一会话下。

飞书侧已把派生规则写死在 `services/channel_identity_service.build_session_id(channel, external_id)`（`session_id = f"feishu:{open_id}"`），Web 侧 `api/v1/chat.py` 用请求携带或新生成的 uuid 作为 `session_id`。两条路径各有一套语义，但没有任何 Runtime 层契约把二者统一描述。

### 2.2 当前架构问题

| # | 问题 | 证据 |
|---|---|---|
| L1 | 无 Session 生命周期 | `loop_runs` 无会话列；会话开始/结束无落点 |
| C2 | Session / Thread 未对齐 | `InboundMessage.external_thread_id` 是通道局部概念，与 Run 无挂接 |
| — | 会话台账不可查 | `loop_run_repository.list_recent(session_id=...)` 不存在 |

### 2.3 在 V3.0 Runtime 中的位置

Session 是 Runtime 生命周期的宿主层（architecture §2.2）：**Session 包裹 Run**，一个 Session 内可有多个 Run（一轮对话 = 一个前台 Run；周期 tick = 一个后台 Run）。本任务是 RT-013（Inbound Gateway 归一 + `external_thread_id → session_id` 映射）、RT-018（恢复与执行历史）、RT-019（按 Session 回溯 Trace）的前置。

### 3.2 Out of Scope（明确禁止扩张）

- **不建 `sessions` 表**（tasks.md §0.3 Q1 裁决：扩列起步）；不建会话元数据 / 会话状态存储。
- 不做上下文内容装配（RT-004）、不做入站网关与 `external_thread_id` 映射实现（RT-013）、不做 Trace 消费（RT-019）。
- 不改 `conversations` / `messages` 表与其仓储；不改 `channel_identity_service.build_session_id` 派生结果。
- 不做会话级写锁 / 串行化（飞书 `inbox.SessionInbox` per-session FIFO 既有机制保留，不得改动）。
- 不写会话级业务语义（不产生「会话状态机」新语义：Session 无 SoT，见 §4.2 裁决 D1）。
- 不新增常驻循环 / worker。

## 4. Technical Design Requirements

### 4.1 接口契约（`session.py`）

```python
def build_session_context(
    session_id: str,
    *,
    character_id: str = DEFAULT_CHARACTER_ID,   # from contracts.py
    channel: str | None = None,
    external_user_id: str | None = None,
    thread_id: str | None = None,
    trigger_type: str = TRIGGER_CHANNEL_MESSAGE,
    run_id: str | None = None,
    now: datetime | None = None,
) -> SessionContext: ...

def open_session(
    channel: str,
    external_user_id: str,
    *,
    character_id: str = DEFAULT_CHARACTER_ID,
    thread_id: str | None = None,
    trigger_type: str = TRIGGER_CHANNEL_MESSAGE,
    now: datetime | None = None,
) -> SessionContext:
    """渠道身份 → session_id → SessionContext（派生复用 channel_identity_service）。"""

def resume_session(session_id: str, *, now: datetime | None = None) -> SessionContext | None:
    """从 loop_runs 台账重建 SessionContext；无任何 Run 记录时返回 None。"""

def close_session(
    context: SessionContext, *, now: datetime | None = None
) -> SessionCloseSummary:
    """会话收口：只做台账聚合，不落会话表（裁决 D1）。"""

@dataclass(frozen=True, slots=True)
class SessionCloseSummary:
    session_id: str
    run_count: int
    status_counts: Mapping[str, int]     # done / aborted / degraded / running
    first_started_at: datetime | None
    last_finished_at: datetime | None
    closed_at: datetime
```

**仓储扩展**（`loop_run_repository.py`）：

```python
def create_run(..., session_id: str | None = None) -> LoopRunRow: ...
def list_recent(..., session_id: str | None = None) -> list[LoopRunRow]: ...
```

**Run 挂接**（`controller.py`，向后兼容的默认参数）：

```python
def open_run(user_id, run_kind, trigger_type, reason,
             now=None, *, session_id: str | None = None) -> RunContext: ...
def open_foreground_run(user_id: str, now=None, *,
                        session_id: str | None = None) -> RunContext: ...
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **Session 无独立 SoT**：`SessionContext` 是运行期值对象，`open/resume/close` 不写任何会话表；`close_session` 只聚合 `loop_runs` | Q1 裁决（扩列起步）；避免「第二套 Session」（飞书接入期已明确禁止新增会话表） |
| D2 | `session_id` 派生**复用** `channel_identity_service.build_session_id(channel, external_id)`，不重复实现、不改其返回值 | 既有派生结果被 `conversations` / `memories` / `worlds` 隔离语义依赖 |
| D3 | `runtime_traces.correlation_id` 列由本任务随 `0052` **同批建**，消费在 RT-005 / RT-019 | 避免两次迁移（tasks.md §0.2：迁移链头钉测一次升级成本已高） |
| D4 | 开关只控制**写入**：`runtime_session_tracking_enabled=False` 时 `create_run` 不传 `session_id`（列留 `NULL`）；**读路径始终兼容 NULL** | 灰度期可随时回退，且历史行可读 |
| D5 | `resume_session` 只能重建「台账可证」的部分（`session_id` / 触发类型 / Run 序列）；`character_id` 取默认值，渠道身份为 `None`，由 RT-013 在入站网关补全 | 不引入新表就无法持久化会话元数据，明确登记此限制 |

### 4.3 数据流与生命周期

```text
渠道入站（Web session_id 请求携带 / 飞书 build_session_id 派生）
   → open_session(channel, external_user_id, ...) → SessionContext(session_id, ...)
   → controller.open_run(..., session_id=context.session_id)   ← 开关门控写入
   → loop_runs 行（session_id 列）
   ↓（同一个 Session 内可重复 N 次：前台 chat Run + 后台 tick Run）
close_session(context) → 聚合该 session_id 下全部 Run → SessionCloseSummary
```

**生命周期状态**：Session 本身不持有可变状态（无状态机落库）；「Open / Close」是**调用语义**（可开 Run / 不再开 Run），由调用方控制，Runtime 只在 `close_session` 时给出台账收口视图。

- 允许依赖：`app.channels.base`（契约）、`channel_identity_service`、`loop_run_repository`、`contracts`（RT-001）、`core.settings`。
