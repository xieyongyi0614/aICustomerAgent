## 2. Background

### 2.1 为什么需要这个 Task

状态真相源分散在各域（`character_state` / `relationship_state` / `development_state` / `goals` / `memories` / `world_*` / `personality_state`）。V2.1 已引入 `agent_state_assembler.assemble()`（规则投影、0 LLM、`snapshot_version`）解决「角色此刻是什么状态」，但：

- **读时点散落**：Run 内各阶段各自读状态，`chat_pipeline` 在步骤 2 装配快照、步骤 5 读场景、步骤 12 读行为上下文——「Run 内快照不变」只靠约定，没有强制。
- **无版本视角**：各域审计行（`relationship_events` / `development_changes` / `decision_records` / `action_records` / `agent_state_snapshots`）天然构成版本证据，但没有统一入口回答「这个 Run 读的是哪一版、现在到哪一版」。
- **同步语义缺位**：快变量（情绪/能量，秒~分钟）与慢变量（人格轴/目标，天~月）在 Run 内的冲突裁决没有统一规则。

### 2.2 当前架构问题

| # | 问题 | 证据 |
|---|---|---|
| S1 | 无状态版本 | `agent_state_snapshots.version` 只在存档时递增，各域写入无统一时点对齐 |
| S2 | 读时点靠约定 | `agent_state_assembler.activate_run_state` 只把 `state_snapshot_version` 塞进 `run.data`，无强制 |
| S3 | 冲突无裁决 | 快/慢变量优先级未成文 |

### 2.3 在 V3.0 Runtime 中的位置

State Manager 是四个运行时组件之一（architecture §3.3）：Context Manager（RT-004）经它取角色段；Agent Loop（RT-006）用它在 Run 开始时钉住时点；Update 段（RT-012）的回写经它做冲突裁决报告（**执行写仍走各域合法通道**）；RT-019 的 Replay 用它做时点对齐锚点。

## 3. Scope

### 3.1 In Scope

1. **状态门面**（`state.py`）：`snapshot()` / `version(domain, ...)` / `observe(domain, event)` / `observed_version(domain, ...)` / `reconcile(snapshot, writes)` / `activate(run, ...)` / `current(run)` / `reset(run)`。
2. **值对象**：`StateVersion` / `RuntimeState` / `ReconcileReport` / `ReconcileConflict`（全部 frozen dataclass）。
3. **域 → 版本来源注册表** `DOMAIN_SOURCES`（免写死 if-else，便于测试与扩展）。
4. **新增只读仓储** `development_change_repository.py`：`count_changes(user_id)` / `latest_change(user_id)`（补齐 `development_changes` 缺失的读面，遵守「DB 访问只走 repositories」）。
5. **Run 内时点一致性**：`activate(run)` 把冻结的 `RuntimeState` 放进 `run.data["runtime_state"]`（与既有 `run.data["state_snapshot_version"]` 并存、不冲突）。
6. **开关**：`runtime_state_versioning_enabled`（默认 `False`）+ 注册进 `tests/v30/runtime_support.py` + 新仓储注册进 `tests/conftest.py::_REPO_MODULES`。

### 3.2 Out of Scope（明确禁止扩张）

- **零写入**：门面不写任何业务表（`reconcile` 只出报告，不执行写；写回归 RT-012 的合法通道）。
- **零新表 / 零新列 / 零迁移**（Q3 裁决：版本 = 既有审计行投影聚合）。
- 不改 State 域数值数学与情绪衰减；不改 V8.5 关系引擎；不改 `agent_state_assembler` 的投影规则与存档频率。
- 不实现 Memory / World / Relationship 的读取逻辑（只调既有仓储 / 既有组装函数）。
- 不做跨域分布式事务；不做版本表；不做状态回滚执行。
- 不调用 LLM、不产生网络 IO。

## 4. Technical Design Requirements

### 4.1 接口契约（`state.py`）

```python
@dataclass(frozen=True, slots=True)
class StateVersion:
    domain: str
    version: int | None            # 审计行计数；None = 该域无版本证据
    basis: str                     # "ledger" | "snapshot" | "unavailable"
    latest_at: datetime | None
    observed_at: datetime
    detail: Mapping[str, Any] = field(default_factory=dict)

@dataclass(frozen=True, slots=True)
class RuntimeState:                # Run 内冻结态（Run 内不变）
    snapshot: AgentStateSnapshot
    snapshot_version: int
    time_point: datetime           # = run.started_at（时点对齐）
    versions: Mapping[str, StateVersion]

@dataclass(frozen=True, slots=True)
class ReconcileConflict:
    domain: str
    kind: str                      # "stale_snapshot" | "value_conflict" | "noop"
    snapshot_value: Any
    write_value: Any
    resolution: str                # "write_wins" | "snapshot_retained" | "no_change"

@dataclass(frozen=True, slots=True)
class ReconcileReport:
    time_point: datetime
    snapshot_version: int
    conflicts: tuple[ReconcileConflict, ...]
    resolved: Mapping[str, Any]    # 裁决后的读视图（不落库）

def snapshot(user_id: str, character_id: str = DEFAULT_CHARACTER_ID,
             now: datetime | None = None) -> AgentStateSnapshot: ...

def version(domain: str, user_id: str,
            character_id: str = DEFAULT_CHARACTER_ID,
            now: datetime | None = None) -> StateVersion: ...

def observe(domain: str, event: RuntimeEvent) -> None: ...      # 只更新进程内观察缓存
def observed_version(domain: str, user_id: str) -> StateVersion | None: ...
def reset_observed_cache() -> None: ...                          # 测试助手

def reconcile(snapshot: AgentStateSnapshot,
              writes: Mapping[str, Any]) -> ReconcileReport: ... # 纯函数，零写

def activate(run, user_id: str, character_id: str = DEFAULT_CHARACTER_ID,
             now: datetime | None = None) -> RuntimeState: ...   # 开关关时不落 run.data
def current(run) -> RuntimeState | None: ...
def reset(run) -> None: ...
```

### 4.2 域 → 版本来源注册表（`DOMAIN_SOURCES`）

| domain | basis | 读取面（全部只读） |
|---|---|---|
| `relationship` | ledger | `relationship_event_repository.count_events(user_id)` + `list_events(user_id, limit=1)` |
| `development` | ledger | `development_change_repository.count_changes(user_id)` + `latest_change(user_id)`（本任务新增） |
| `decision` | ledger | `decision_repository.search(user_id=user_id, limit=1)` |
| `action` | ledger | `action_repository.recent_records(user_id, limit=1)` + `count_active(user_id)` |
| `character` / `goal` / `memory` / `world` / `personality` | snapshot | `agent_state_snapshot_repository.latest(user_id, character_id)` → `version` 列 |
| 其他（未注册域） | unavailable | `version=None`、`basis="unavailable"`（**不造假版本**，不抛错） |

**关键裁决**：

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **不新增真相源、不写业务值**：门面仅聚合只读审计行与既有快照 | architecture §3.3「State Manager 不新增真相源」；Q3 投影裁决 |
| D2 | `reconcile` 返回 `ReconcileReport`（architecture 原签名 `-> None`） | 纯函数可测；**语义不变**（只裁决不写），返回值化属接口增强 |
| D3 | **版本单调性限定**：`version` = 审计行计数，保留期清理（如 `decision_records` 14 天）可能使计数下降，故只承诺「**Run 内一致** + **无清理时跨 Run 单调不减**」，并以 `basis="ledger"` / `latest_at` 提供可解释性 | 不引入版本表就无法得到绝对单调序列；诚实登记边界优于造假单调 |
| D4 | 冲突裁决规则：快变量（`mood` / `energy` / `intensity` / `relationship.*`）→ `write_wins`；慢变量（`personality` / `goal`）→ `snapshot_retained`（写来源标注 `evolution` 时例外） | 快慢分离沿用 architecture §2.1；Evolution 合法通道优先级来自 V2.1 铁律 |
| D5 | `observe` 只写**进程内缓存**（`(domain, user_id) → StateVersion`），不落库 | 事件总线（RT-005）是进程内同步层，缓存属观察视图而非 SoT |

### 4.3 数据流与生命周期

```text
Run 开始（RT-006）
   → activate(run, user_id)             # 时点 = run.started_at；开关关 → 不落 run.data
       ├── snapshot()  ← agent_state_assembler.assemble（既有，0 LLM）
       └── version(domain) × DOMAIN_SOURCES（只读审计聚合）
   → RuntimeState 冻结（Run 内 current(run) 恒返回同一份）
段执行中的读（RT-004 / RT-007 / RT-008）→ current(run) 或 snapshot()（同一时点）
Update 段（RT-012）→ reconcile(snapshot, writes) → ReconcileReport（报告交调用方）
Run 结束 → reset(run)
```
