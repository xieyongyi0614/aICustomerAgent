## 2. Background

### 2.1 为什么需要这个 Task

主动行为链路已经存在但**隐式**：

```
autonomy_engine.tick → _process_user → _produce_autonomy_action
    → proactive_repository.enqueue（dedupe_key 占位）
    → services/proactive_executor.py（AUTO-005 两阶段：生成可重试 → 投递）
    → channels/feishu/delivery.send_proactive → FeishuChannelAdapter.send → delivered
```

触发判据分散在 `autonomy_policy.evaluate` / `trigger_evaluator.poll_due_followup` / `poll_due_actions` / `in_quiet_hours` / `_should_skip_user_facing`；投递出口是渠道专用函数（C3，RT-014 已归一）。**从 Run 到投递**之间没有任何统一关联标识。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 触发 → Run 无显式关联 | 无法回答「这次主动行为是哪个 Run 决定的」 |
| 2 | 投递不可追溯 | 投递结果与 Run / 决策 / 行动无 `correlation_id` 串联 |
| 3 | 事件缺失 | 无 `ProactiveTriggered` / `ProactiveDelivered` 事件供观测 |

### 2.3 在 V3.0 Runtime 中的位置

本任务落实 architecture §6.2 的示例链在**主动路径**上的对应物：`ProactiveTriggered`（触发判定通过）→ Run → `Decision` → `Action` → `ProactiveDelivered`（投递返回），并让 RT-019 能用 `run_id` / `correlation_id` 追溯全链。它是 RT-012（Update）/ RT-014（出站）在自主路径上的补充，不改任何判定数学。

## 3. Scope

### 3.1 In Scope

1. **触发源显式化**：`trigger_router` 增 `classify_proactive_trigger(reason)` 归一（`due_trigger` / `goal_work` / `goal_catchup` → `schedule`；`inactivity_eligible` → `threshold`；`followup:*` / 行动到期 → 既有映射）——**复用既有 `_BACKGROUND_REASON_TO_TRIGGER` 语义**，不新增触发类型。
2. **关联标识**：主动行为经 `correlation_id = proactive:{dedupe_key}` 串联触发 → Run（`loop_runs`）→ 决策（`decision_records`）→ 行动（`action_records.run_id`）→ 投递（`runtime_traces.correlation_id`）。
3. **投递协调**：主动投递经 RT-014 `outbound.deliver(...)`（纳管渠道）；未纳管走既有 `delivery.send_proactive`（等价）。
4. **事件**：`ProactiveTriggered` / `ProactiveDelivered` 经 RT-005 发出（开关关闭时空操作）。
5. **语义保留**：`autonomy_policy` 免打扰窗口（`in_quiet_hours`）、`life_loop_storm_daily_limit`、`_should_skip_user_facing`、`dedupe_key` 占位与 `proactive_executor` 两阶段状态机**零改动**。

### 3.2 Out of Scope（明确禁止扩张）

- 不改触发评估数学、阈值、cooldown、storm 限流、免打扰窗口判定。
- 不改 `dedupe_key` 生成规则（`proactive_actions` 唯一性与幂等不变）。
- 不改 `proactive_executor` 的两阶段语义（生成可重试 / 投递失败不出错）。
- 不做多角色 / 多用户广播；不新增通知渠道；不做文案排版（归 `prompts/` 与各域）。
- 不新增表 / 列 / 迁移；不新增 worker / 定时任务。
- 不改 `decision_pipeline` / `action_engine` 内部（只消费）。

## 4. Technical Design Requirements

### 4.1 接口契约

```python
# trigger_router.py 扩展（复用既有映射语义）
def classify_proactive_trigger(reason: str) -> str: ...   # reason → trigger_type（schedule/threshold）

# 主动链路协调（新；建议落 app/application/autonomy_bridge.py）
def proactive_correlation_id(dedupe_key: str) -> str: ...    # "proactive:{dedupe_key}"

async def coordinate_delivery(action_id: str, *, dedupe_key: str,
                              trace=None) -> SendResult | None: ...
```

### 4.2 全链时序（现状 + 本任务新增点）

```text
1. 触发判定（零改动）：autonomy_policy.evaluate / trigger_evaluator.poll_due_*
   / in_quiet_hours / _should_skip_user_facing / life_loop_storm_daily_limit
        ↓ 通过
2. [新增] classify_proactive_trigger(reason) → trigger_type；发 ProactiveTriggered
3. Run（RT-016）：run_autonomous_cycle(trigger_type=…, reason=…)
        ↓ decision（三道闸）→ act
4. 主动意图 → proactive_repository.enqueue（dedupe_key 占位，零改动）
5. proactive_executor（AUTO-005 两阶段，状态机零改动）
        ↓ 投递
6. [改造] coordinate_delivery → outbound.deliver（RT-014；未纳管走 send_proactive）
        ↓
7. [新增] 发 ProactiveDelivered；trace 记录 SendResult
```

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 触发分类**复用** `_BACKGROUND_REASON_TO_TRIGGER` 既有语义（仅暴露为函数），零新触发类型 | 分类数学 Preserve |
| D2 | `correlation_id = "proactive:{dedupe_key}"` 贯穿 Run / decision / action / delivery | 一次触发全链可追溯（architecture §6.2） |
| D3 | 投递统一经 RT-014 网关；未纳管回落既有 `send_proactive`（等价） | 出站归一不改变渠道语义 |
| D4 | 免打扰 / storm / 幂等判定**零改动**：`coordinate_delivery` 不做任何触发判定 | 只协调出口，不重复裁决 |
| D5 | 事件经 RT-005 发出（事件开关关闭时空操作）；`runtime_traces.correlation_id` 由 RT-019 消费 | 观测锚点不承载业务写 |
| D6 | 不做任何新的主动行为类型 / 通知渠道 | RT-017 Out of Scope |

### 4.4 依赖

- 允许：`trigger_router`、`autonomy_engine`（只读投影）、`proactive_repository`（既有读写，语义不变）、`proactive_executor`、`outbound`（RT-014）、`events`（RT-005）、`app.core.settings`。
- 禁止：`autonomy_policy` / `trigger_evaluator` 内部改动、`proactive_actions` 状态机改动、`app.channels.feishu` 直调（经网关）、写 `feishu_deliveries`。

## 5. Implementation Plan

1. `trigger_router.py` 增加 `classify_proactive_trigger`（复用既有映射字典，暴露为公共函数）。
2. 新增 `application/autonomy_bridge.py`：`proactive_correlation_id` + `coordinate_delivery`（经 RT-014 网关，未纳管回落既有投递）。
