## 2. Background

### 2.1 为什么需要这个 Task

Planning System 已经建齐（`PlanningEngine.plan` / `revise` / `enqueue` / `run_jobs`、`PlanScheduler`、`PlanObserver`、`PlanRevisionPolicy`、`goal_repository` 计划面），但**接入点是后台专属**：`life_loop._route_planning_jobs` 与 `_execute_active_plans` 直接从 tick 里调用，前台链路完全没有 Plan 段，认知循环的第三段在代码里不存在。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | Plan 不属于循环形状 | 「目标 → 计划 → 步骤 → 行动」的链路只在后台可见 |
| 2 | Plan 无运行期值对象 | 计划以 `GoalPlanRecord` + `SubGoalSpec`（落库态）直接参与执行编排，运行期无只读投影 |
| 3 | 可选性不可控 | 无法按 Profile / 预算决定「这一轮要不要规划」 |

### 2.3 在 V3.0 Runtime 中的位置

Plan 是六段第三段、**可选段**（`OPTIONAL_PHASES`）：由 `Intention` 与目标栈驱动，产出 `PlanValue`（计划 + 当前可执行步骤）供 Act 段消费；未启用时 Act 直接消费 `Intention`（前台最小快路径）。

---

## 3. Scope

### 3.1 In Scope

1. **`plan(...) -> PlanValue | None`**（`stages/plan.py`）。
2. **规划接线**：复用 `services.planning.engine.get_planning_engine()`（`plan` / `revise`）与 `goal_repository` 计划面；`PlanScheduler` 只读消费（推进在既有维护步 / `_execute_active_plans`）。
3. **运行期只读投影**：`PlanValue`（计划标识 / 状态 / 当前步骤 / 步骤列表）+ `PlanStepRef`（步骤索引 / 描述 / 绑定工具 / 状态）。
4. **可选段裁决**：由 RT-006 的 `resolve_stages` 决定是否进入；段内再受 `plan_*` 既有预算闸（`PlanContext` 预算跳过逻辑）保护。
5. **降级语义**：规划失败 / 预算跳过 → 段 `degraded`，`PlanValue = None`，循环继续；不留半成品计划（不产生新的 `GoalPlanRecord` 中间态）。
6. **前台约束**：**前台 Run 默认不启用 Plan 段**（`optional_stages` 前台为空）；如需启用，Plan 段对前台只读（不落计划）。

### 3.2 Out of Scope（明确禁止扩张）

- 不重写拆解（`decompose`）/ 观察（`observer`）/ 修订（`revision`）算法与 `SubGoalSpec` 校验规则。
- 不新增计划表 / 列（落库仍只经 `goal_repository` 计划面）；不新增迁移。
- 不做执行（执行归 Act / RT-010）；不在 Plan 段调用 `PlanScheduler` 推进步骤。
- 不在前台做长期化计划写入（architecture「前台只读，长期化写入只在后台」）。
- 不新增设置字段、不改 `PlanContext` 预算数学。
- 不引入 LLM 直调（规划引擎内部如需 LLM，仍走既有链路与 Gateway）。

## 4. Technical Design Requirements

### 4.1 接口契约（`stages/plan.py`）

```python
@dataclass(frozen=True, slots=True)
class PlanStepRef:
    index: int
    intent: str                  # 步骤意图 / 描述（只读投影）
    tool_id: str | None          # 绑定工具（可空）
    status: str                  # pending | done | failed | blocked（既有语义）

@dataclass(frozen=True, slots=True)
class PlanValue:                 # 运行期只读投影（零新表）
    plan_id: str
    goal_id: str
    status: str
    version: int
    steps: tuple[PlanStepRef, ...]
    current_step: PlanStepRef | None
    budget_skipped: bool
    created_at: datetime

async def plan(intention: Intention, *, spec: ProfileSpec,
               session_context: SessionContext | None = None,
               run=None, llm=None, now: datetime | None = None,
               trace=None) -> PlanValue | None: ...

def current_plan_value(user_id: str, goal_id: str | None = None) -> PlanValue | None: ...
def to_plan_value(plan_record, goal_id: str) -> PlanValue: ...
```

### 4.2 接线面（全部既有）

| 动作 | 既有接口 | 说明 |
|---|---|---|
| 生成计划 | `get_planning_engine().plan(...)` | 仅后台启用；预算 / 校验 / 落库仍由引擎负责 |
| 修订结论 | `PlanningEngine.revise(...)` | 修订触发仍在 `PlanRevisionPolicy` / 监听器；本段**不主动修订** |
| 读计划 | `goal_repository.get_latest_plan` / `list_active_plans` / `get_plan` | 运行期投影来源 |
| 推进步骤 | **不在本段**：`PlanScheduler` 推进仍由 `_execute_active_plans` / 维护步负责 | 保证「规划只编排不执行」 |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **前台默认不启用 Plan 段**（`foreground_chat.optional_stages` 为空）；后台 `autonomous_tick` 可启用 | architecture：前台只读、长期化写入只在后台 |
| D2 | 计划落库仍只经 `goal_repository` 计划面；本段零直接仓储写入 | 单一写面纪律（V2.5 红线） |
| D3 | 规划失败 / 预算跳过 → `degraded` + `PlanValue=None`，**不留半成品计划** | 事务边界清晰，避免脏计划污染执行 |
| D4 | `PlanValue` 是只读投影：不新建表、不改 `GoalPlanRecord` 模型 | RT-009 Out of Scope |
| D5 | Act 消费契约：`PlanValue.current_step` 为空 → Act 回落为「消费 `Intention`」 | 保证可选段关闭 / 计划未就绪时循环仍可推进 |

### 4.4 依赖

- 允许：`app.services.planning.engine`（`get_planning_engine`）、`app.repositories.goal_repository`（只读 + 引擎内部写）、`contracts`（RT-001）、`Intention`（RT-008）、`app.core.settings`。
- 禁止：`PlanScheduler` 执行推进路径、`app.chains` / `app.prompts` 直调、具体渠道实现、`GoalPlanRow` 之外的任何表写入。

## 5. Implementation Plan

1. 实现 `PlanValue` / `PlanStepRef` 与投影函数 `to_plan_value` / `current_plan_value`。
2. 实现 `plan(...)`：启用条件判定（可选段 + Profile）→ 目标存在性检查 → 调 `PlanningEngine.plan`（后台）→ 投影为 `PlanValue`；失败 / 跳过 → `None` + degraded。
3. `loop.py` 的 `plan` 段委派指向 `stages.plan.plan`（`OPTIONAL_PHASES` 已含 `plan`）。
4. 登记「前台不启用 Plan 段」默认（Profile 注释 + 测试双证）。
5. 测试 `tests/v30/test_runtime_plan_stage.py`（§7）。
6. Focused → Module → Fast 后提交（§9）。
