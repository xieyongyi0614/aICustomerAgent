## 2. Background

### 2.1 为什么需要这个 Task

入站目前是**两条独立路径、各自触达编排层**：

| 渠道 | 入站路径 | 事实 |
|---|---|---|
| Web | `api/v1/chat.py` → `agent_service.stream_chat(session_id, user_id, content, llm, trace)` | HTTP + SSE 语义；`session_id` 由请求携带或新生成 |
| 飞书 | `api/v1/feishu.py`（验签 / 解密 / 去重 / 立即 200）→ `channels/feishu/adapter.py` → 同一条 `agent_service.stream_chat` | webhook 语义；`session_id = build_session_id("feishu", open_id)` |

两条路径都**绕过** Runtime 契约直接调管线（`Run` 在 `chat_pipeline` 内部才被打开），并且 `InboundMessage.external_thread_id` 与 `session_id` 没有任何统一挂接（C2）。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| C1 | 无入站归一 | 新增渠道要各自适配编排层，无法「注册即接入」 |
| C2 | Thread / Session 未对齐 | 渠道线程语义泄漏到核心层 |
| — | Runtime 契约未被渠道使用 | `RuntimeInput`（RT-001）无生产调用方 |

### 2.3 在 V3.0 Runtime 中的位置

Inbound Gateway 是 Runtime 的**唯一入站面**（architecture §8.1）：`Web / Feishu / Discord → Inbound Gateway → Agent Runtime`。它只做两件事——**归一为 `RuntimeInput`** 与**解析 `SessionContext`**；执行入口的接管（把 `stream_chat` 换成 `AgentLoop.run`）属于 RT-015。

---

## 3. Scope

### 3.1 In Scope

1. **归一**：`normalize(inbound) -> RuntimeInput`（源为 `channels.base.InboundMessage` 或 Web 请求字段）。
2. **会话解析**：`resolve_session(channel, external_user_id, thread_id) -> SessionContext`，内部复用 `channel_identity_service.build_session_id`（派生结果不变）。
3. **渠道注册表**：`CHANNEL_SOURCES = {"web": …, "feishu": …}`（代码静态注册；Discord 仅留注册位，不实现）。
4. **逐渠道切换**：`runtime_inbound_gateway_channels`（csv）控制已纳管渠道；**未纳管渠道走既有路径，行为逐字节不变**（Q5：飞书先切、Web 后切）。
5. **飞书侧薄适配**：`channels/feishu/adapter.py` 在纳管时经 Gateway 生成 `RuntimeInput` / `SessionContext` 并挂到既有 `TurnOutcome` / `Run` 上下文（**仍调既有 `stream_chat`**，不改执行入口）。
6. **线程挂接**：`external_thread_id → thread_id` 映射在入口完成一次，Runtime 不感知渠道线程语义。

### 3.2 Out of Scope（明确禁止扩张）

- 不改 `channels/base.py` 契约（`InboundMessage` / `ChannelAdapter.send` 零改动）；不新增渠道实现（Discord 仅留注册位）。
- 不改 `api/v1/schemas.py`、不改流式响应结构（Web 仍走 HTTP + SSE）。
- **不接管执行入口**（改调 `AgentLoop.run` 属 RT-015）。
- 不做鉴权 / 验签 / 去重 / 串行（飞书 `feishu/inbox.py`、`feishu_dedupe_ledger`、立即 200 语义全保留）。
- 不做出站（RT-014）；不新增表 / 列 / 迁移；不新增常驻循环。
- 核心层不得 import `app.channels.feishu`（仅可 import `app.channels.base`）。

## 4. Technical Design Requirements

### 4.1 接口契约（`inbound.py`）

```python
CHANNEL_WEB = "web"
CHANNEL_FEISHU = "feishu"
CHANNEL_SOURCES: dict[str, str] = {CHANNEL_WEB: "rest", CHANNEL_FEISHU: "webhook"}

def enabled_channels() -> frozenset[str]: ...        # 读 runtime_inbound_gateway_channels
def is_enabled(channel: str) -> bool: ...

def normalize(channel: str, *, text: str, received_at: datetime,
              external_user_id: str | None = None,
              thread_id: str | None = None,
              payload: Mapping[str, Any] | None = None) -> RuntimeInput: ...

def normalize_inbound(message: InboundMessage) -> RuntimeInput: ...   # channels.base 契约入参

def resolve_session(channel: str, external_user_id: str, *,
                    thread_id: str | None = None,
                    character_id: str = DEFAULT_CHARACTER_ID,
                    now: datetime | None = None) -> SessionContext: ...
```

### 4.2 映射规则

| 来源 | `RuntimeInput.kind` | `source` | `thread_id` |
|---|---|---|---|
| Web（`api/v1/chat.py`） | `channel_message` | `web` | 请求可携带（缺省无） |
| 飞书（`channels/feishu`） | `channel_message` | `feishu` | `InboundMessage.external_thread_id` |
| 未来 Discord | `channel_message` | `discord` | 适配器提供 |

`session_id` 一律经 `channel_identity_service.build_session_id(channel, external_user_id)` 派生（**结果不变**）；`external_thread_id` 只作为 `thread_id` 透传，不参与 `session_id` 计算。

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 本任务只**归一与挂接**，不接管执行入口（执行切换属 RT-015） | 分步收敛，避免「归一 + 收编」同批导致回归不可定位 |
| D2 | 未纳管渠道走既有路径、行为逐字节不变；纳管渠道也仍调既有 `agent_service.stream_chat` | Q5 逐渠道切（飞书先行） |
| D3 | `ChannelAdapter` / `InboundMessage` 契约零改动；核心层只 import `app.channels.base` | architecture §8.2 铁律 + 通道层边界 |
| D4 | 鉴权 / 验签 / 去重 / 串行 / 立即 200 全保留在渠道侧，Gateway 不接管 | C1 只要求「归一」，不要求把渠道治理上移 |
| D5 | `normalize` 纯函数（零 IO、零 DB）；`resolve_session` 只读（派生 + 组装），两者都不写表 | 契约层最小职责 |
| D6 | 未知 channel → `ValueError`（fail-closed），避免静默归一成错来源 | 与 RT-005 订阅 fail-closed 风格一致 |

### 4.4 依赖

- 允许：`app.channels.base`（契约）、`app.services.channel_identity_service`、`session`（RT-002）、`contracts`（RT-001）、`app.core.settings`。
- 禁止：`app.channels.feishu`（核心层禁止）、`app.repositories`、`app.chains` / `app.prompts`、`agent_service`（本任务不接管执行）。

## 5. Implementation Plan

1. 实现 `enabled_channels` / `is_enabled`（csv 解析 + 去空白，容错空值）。
2. 实现 `normalize(...)` / `normalize_inbound(message)`（构造 `RuntimeInput`；校验 `kind` / tz-aware `received_at` / JSON-safe payload）。
3. 实现 `resolve_session(...)`（调 `build_session_id` → RT-002 的 `build_session_context`）。
4. 在 `channels/feishu/adapter.py` 加**纳管分支**：`is_enabled("feishu")` 为真时用 `normalize_inbound` + `resolve_session` 生成 `RuntimeInput` / `SessionContext` 并挂到既有 `TurnOutcome`（**仍调既有 `stream_chat`**）。
5. 设置：`core/settings/agent_runtime.py` 加 `runtime_inbound_gateway_channels: str = ""`；`tests/v30/runtime_support.py` 登记。
6. 测试 `tests/v30/test_runtime_inbound_gateway.py` + 飞书链路回归（§7）；Focused → Module → e2e 后提交（§9）。
