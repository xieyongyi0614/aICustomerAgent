## 2. Background

### 2.1 为什么需要这个 Task

Action Execution 已建齐（统一 Action 抽象、六态状态机、`ActionEngine` 五段编排、`CapabilityExecutor` / `ToolExecutor` 分派、`action_schedules` 调度、`ActionResult` 统一结果契约），但**接入点有两处、且都在「后处理」语境里**：

| 接入点 | 位置 | 事实 |
|---|---|---|
| 前台 / 后台行动创建 | `post_process.run_action_planning` | 在 post_process 步骤里被调用（受 per-user 写锁） |
| 计划步骤执行 | `life_loop._execute_plan_step` | 后台 tick 内直接调用 |

认知循环的 Act 段在代码里不存在：行动是「后处理的一个副作用」，不是循环的一段。这导致「意图 → 行动 → 结果 → 反馈」链路不可在循环内观测。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 行动无循环位置 | 行动结果无法与 `Intention` / `RunResult` 对齐 |
| 2 | 结果回流无契约 | `ActionResult` 的消费散落在 `integrate_result` / `mark_decision_outcome` |
| 3 | 重试 / 调度归属易混淆 | 循环内若自行重试会与 `action_retry` 维护步冲突 |

### 2.3 在 V3.0 Runtime 中的位置

Act 是六段第四段：消费 `Intention`（RT-008）与可选 `PlanValue`（RT-009），产出 `ActOutcome`（含 `ActionResult`）供 Reflect（RT-011）与 Update（RT-012）消费，并向决策面回灌 `action_facts` / `tool_facts`（供下一轮 Reason）。

**边界**：Runtime 不直接调工具（architecture §9.3）；工具意图经 Act → Action Execution → Tool Registry。

## 3. Scope

### 3.1 In Scope

1. **`act(...) -> ActOutcome`**（`stages/act.py`）。
2. **行动创建**：把 `Intention` 转为 `ActionIntent`（动作类型 + 参数），经 `action_engine.run_action_planning(...)`（**唯一编排器**）创建并执行记录。
3. **计划步骤执行**：当 `PlanValue.current_step` 存在且绑定工具时，经既有计划步骤执行路径（`_execute_plan_step` 的本体调用，非重写）执行。
4. **结果回流**：`ActOutcome`（`record_id` / `action_type` / `result: ActionResult` / `gates` / `llm_used`）。
5. **结果集成**：经既有 `action_engine.integrate_result(record, result)`（写世界 / 记忆 / 关系信号 / outbox 均归其内部既有路径）。
6. **不决策约束**：Act 不做「要不要做」判断（已由 Reason 决定），不做重试（由 `action_retry` 维护步），不做调度（由 `action_schedules`）。

### 3.2 Out of Scope（明确禁止扩张）

- 不改 Action 六态状态机、`GateReason` / `FailureKind`、五段闸门（权限 / 确认 / 校验 / 归一 / 健康）、`ACTION_EXECUTION_MAP`。
- 不新建 Action 抽象 / 执行器 / 结果类型；不新增动作类型与能力。
- **不重试 / 不定时 / 不排期**：`next_retry_at`、`scheduled_at` 的写入只发生在既有调度 / 重试路径。
- 不绕过 Tool 治理（零直调 `Capability.execute`）；不直写 `action_records` 状态列（只经 `ActionManager` / `ActionEngine`）。
- 不改 `post_process.run_action_planning` / `life_loop._execute_plan_step`（收编归 RT-015 / RT-016）。
- 不实现具体外部能力（外部 API 经既有 Tool 路径）。

## 4. Technical Design Requirements

### 4.1 接口契约（`stages/act.py`）

```python
@dataclass(frozen=True, slots=True)
class ActOutcome:
    action_id: str | None            # action_records.id（未创建则为 None）
    action_type: str | None
    result: ActionResult | None      # 每次执行必产（成功 / 失败 / 超时 / 异常）
    gates: Mapping[str, Any]         # 六闸门裁决摘要（既有 GateSnapshot 投影）
    source: str                      # conversation | autonomy | plan | event_driven
    executed: bool                   # 是否真正进入执行（被闸门拦下则为 False）
    decided_at: datetime

async def act(intention: Intention, *,
              plan: PlanValue | None = None,
              session_context: SessionContext | None = None,
              run=None, llm=None, now: datetime | None = None,
              trace=None) -> ActOutcome: ...

def intent_to_action_intent(intention: Intention, *, session_id: str | None,
                            goal_id: str | None) -> ActionIntent | None: ...
```

### 4.2 接线面（全部既有）

| 动作 | 既有接口 | 说明 |
|---|---|---|
| 创建 + 执行（唯一编排器） | `action_engine.run_action_planning(user_id, intent, …, session_id=…, goal_id=…)` | 内部五段：`new_record` → 闸门 → `assemble_plan` → `execute_plan` → `integrate_result` |
| 结果集成 | `action_engine.integrate_result(record, result)` | 写世界 / 记忆候选 / 关系信号 / outbox 全在其既有路径内 |
| 生命周期操作 | `services.action.manager.create` / `execute(action_id, session_id=…)` / `query` / `cancel` / `get_status` | 结果对象由 `services.action.result.from_*` 统一归一 |
| 计划步骤 | `life_loop._execute_plan_step`（调用其本体行为） | 仅当 `plan.current_step` 存在且绑定工具 |
| 决策面回灌 | `autonomy_engine.collect_tool_facts` / `_collect_action_facts`（下一轮只读读取） | 本段不写决策面 |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 行动创建**唯一入口**是 `run_action_planning`（或 `ActionManager.create` + `execute`）；本段零直写 `action_records` | V2.6 单一编排器纪律 |
| D2 | **每次执行必产 `ActionResult`**：闸门拦截 / 未绑定工具 / 超时 / 异常四类均归一为结果对象 | G5「结果必产」（V2.6） |
| D3 | 本段**不做重试、不写 `next_retry_at`、不定时** | 重试 / 调度归既有 `action_retry` / `action_schedules` 维护步 |
| D4 | 工具路径必经 `ToolExecutor` 五段短路（零直调 `Capability.execute`） | V2.4 / V2.6 治理不绕过 |
| D5 | 行动失败 / 超时 → Run `degraded`，循环继续（行动失败 ≠ Run 失败） | architecture 附不变量 + V2.1 语义 |
| D6 | `intent_to_action_intent` 只做**映射**（意图 → 动作类型 + 参数），不做「做不做 / 做哪个」判断 | Reason 段已决策（G3 不决策） |

### 4.4 依赖

- 允许：`app.application.action_engine`、`app.services.action.manager` / `result`、`contracts`（RT-001）、`Intention`（RT-008）、`PlanValue`（RT-009，可选）、`post_process.get_user_write_lock`。
- 禁止：直接 `action_repository.save_record` 改状态、`Capability.execute` 直调、`world_engine` 直写、`app.chains` / `app.prompts` 直调。

## 5. Implementation Plan

1. 实现值对象 `ActOutcome` 与映射函数 `intent_to_action_intent`（意图 → `ActionIntent`；参数校验失败返回 `None`）。
2. 实现 `act(...)`：
   - No-op 分支：`intention.intention is None` 且非 `chat_response` → `executed=False`，零引擎调用；
   - 主分支：映射 → `run_action_planning(...)` → 归一 `ActionResult`（`result.from_*`）→ 包装 `ActOutcome`；
   - 事件：发 `ActionExecuted` / `ActionCompleted`（RT-005，开关关闭时空操作）。
3. 计划步骤分支：`plan.current_step` 存在时经 `asyncio.to_thread` 调 `life_loop._execute_plan_step` 的本体行为（阻塞 IO 离开事件循环）。
4. 结果集成：确认写世界 / 记忆候选 / 关系信号仍由 `action_engine.integrate_result` 内部既有路径完成（本段零直写）。
5. `loop.py` 的 `act` 段委派指向 `stages.act.act`；测试 `tests/v30/test_runtime_act_stage.py`（§7）。
6. Focused → Module → Fast 后提交（§9）。
