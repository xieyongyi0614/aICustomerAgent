## 2. Background

### 2.1 为什么需要这个 Task

回写路由（Feedback）在代码里是**分散的后处理步骤**：`post_process` 注册了 `run_scene_update` / `run_state_update` / `run_goal_review` / `run_summary` / `run_memory_extract` / `run_world_update` / `run_character_action_sync` / `run_action_planning` / `run_evaluation` / `run_budget_observer`，由 `schedule_post_process` 在回答产出后异步编排。桥接能力也已存在：`services/action/memory_bridge.py`、`relationship_bridge.deliver_action_signal`、`memory2.ingest.ingest_from_*`。

但没有「Feedback」这个一等概念：谁因 `ActionCompleted` 被触发、写去哪、是同步还是后台，只能读 `post_process` 的步骤列表才能回答（architecture §1.2 M2 / §6.3 订阅规则）。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | 回写路由不可枚举 | 订阅关系隐含在步骤列表里 |
| 2 | 前后台回写边界模糊 | 「前台只读、长期化写入后台」靠约定 |
| 3 | 跨域投递语义分散 | outbox 与函数直调混用，无统一裁决 |

### 2.3 在 V3.0 Runtime 中的位置

Update 是六段第六段、循环收口段：消费 `ActOutcome`（RT-010）与 Reflect 产物（RT-011），产出 `Feedback`（回写事件流 + 目标域 + 后台标记），并发出 `MemoryUpdated` / `RelationshipUpdated` / `StateVersionBumped` 等事件（RT-005）供 RT-019 观测与后续 `State Manager.observe`（RT-003）。

**写面纪律**：Runtime 只**路由**，写永远由各域自己的合法通道完成（architecture 附：边界不变量 1/2）。

## 3. Scope

### 3.1 In Scope

1. **`update(...) -> Feedback`**（`stages/update.py`）。
2. **路由表**（显式化的既有通道）：

| 触发 | 合法通道 | 同步 / 后台 |
|---|---|---|
| 对话轮次产物 | `memory2.ingest.ingest_from_conversation(...)`（候选摄取，R1~R8 裁决） | 后台 |
| 行动结果 | `memory2.ingest.ingest_from_action_record(...)` + `action/memory_bridge` | 后台 |
| 行动关系信号 | `services/action/relationship_bridge.deliver_action_signal(record, user_id)` | 后台 |
| 场景 / 状态 / 目标 | `post_process` 既有步骤（`run_scene_update` / `run_state_update` / `run_goal_review`） | 后台 |
| 世界变更 | `deferred_world_op → outbox → world_engine`（既有唯一写面） | 后台 |
| 跨域延迟投递 | `outbox_repository`（既有事务内投递） | 后台 |
| 前台 Run | `post_process.schedule_post_process(...)`（交接即返回） | 交接 |

3. **前后台边界**：前台 Update 段只做「交接后台任务」；后台 Run 内可直接调用同步通道（仍在既有 `get_user_write_lock` 内）。
4. **事件**：`MemoryUpdated` / `RelationshipUpdated` / `StateVersionBumped` 经 RT-005 发出（开关关闭时空操作）。
5. **失败隔离**：任一通道失败不影响已产出回复与 Run 终态（对齐 `post_process` 独立容错纪律）。

### 3.2 Out of Scope（明确禁止扩张）

- **零直写**：不写 `memories` / `relationship_state` / `personality_state` / `world_*` / `goals` / 计划。
- 不做 Development 编译（唯 Evolution Engine）；不做人格演化。
- 不改 `post_process` 步骤**内部实现**、不改 `outbox_consumer`、不改 `deferred_world_op` 路径。
- 不新增表 / 列 / 迁移 / 常驻 worker；不新增设置字段。
- 不做 Reflect（RT-011）；不做 Decide（Reason）。
- 不直调 `ToolExecutor` / `Capability`。

## 4. Technical Design Requirements

### 4.1 接口契约（`stages/update.py`）

```python
@dataclass(frozen=True, slots=True)
class FeedbackItem:
    target: str                      # memory | relationship | state | scene | goal | world
    channel: str                     # 合法通道名（如 "memory2.ingest_from_conversation"）
    applied: bool
    background: bool
    detail: Mapping[str, Any] = field(default_factory=dict)

@dataclass(frozen=True, slots=True)
class Feedback:
    run_id: str
    items: tuple[FeedbackItem, ...]
    handed_off: bool                 # 前台是否已交接后台任务
    emitted_events: tuple[str, ...]
    finished_at: datetime

async def update(*, action_outcome: ActOutcome | None = None,
                 reflect_outcome: ReflectOutcome | None = None,
                 context=None,                          # RuntimeContext（RT-004）
                 session_context: SessionContext | None = None,
                 spec: ProfileSpec | None = None,
                 run=None, now: datetime | None = None,
                 trace=None) -> Feedback: ...

def routes_for(spec: ProfileSpec, action_outcome=None) -> tuple[str, ...]: ...
```

### 4.2 前后台分派

| Run 类型 | Update 段行为 |
|---|---|
| 前台 `foreground_chat` | 调 `post_process.schedule_post_process(...)` **交接即返回**（`handed_off=True`）；段内不执行重活 |
| 后台 `autonomous_tick` / `event_driven` | 在既有 `get_user_write_lock` 保护下直接调用同步通道（记忆候选 / 关系信号 / 状态）；跨域部分仍走 outbox |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | Runtime 只路由：一切写经各域**合法通道**（`memory2.ingest` / `relationship_bridge` / `state_service` / `post_process` 步骤 / `deferred_world_op → outbox`） | architecture 附：边界不变量 1/2 |
| D2 | 前台**不阻塞**：段内只做交接，不得 `await` 后台任务完成 | 对齐「后处理失败不得影响已产出回答」 |
| D3 | 跨域延迟投递仍走 `outbox_events`；世界写仍走 `deferred_world_op` 唯一写面 | 一致性模型零改动 |
| D4 | 事件（`MemoryUpdated` / `RelationshipUpdated` / `StateVersionBumped`）经 RT-005 发出；RT-003 的 `observe` 只更新进程内版本视图 | 事件只读投影，不承载写语义 |
| D5 | 失败隔离：任一通道异常 → 该 `FeedbackItem.applied=False`，Run degraded；其余通道继续 | 单点失败不污染整体回写 |
| D6 | Development / 人格演化**不在本段**（唯 Evolution Engine 编译） | V2.1 铁律 |

### 4.4 依赖

- 允许：`app.application.post_process`（`schedule_post_process` / `get_user_write_lock` / 既有步骤函数）、`app.services.memory2.ingest`、`app.services.action.memory_bridge` / `relationship_bridge`、`app.repositories.outbox_repository`、`state`（RT-003）、`events`（RT-005）、`contracts`。
- 禁止：域表直写、`app.chains` / `app.prompts` 直调、`outbox_consumer` 改动、具体渠道实现。

## 5. Implementation Plan

1. 实现 `FeedbackItem` / `Feedback` 与 `routes_for`（Profile + 行动结果 → 目标通道清单）。
2. 实现同步通道私有函数：`_apply_memory` / `_apply_relationship` / `_apply_state` / `_apply_goal`（各自 try/except → `FeedbackItem`）。
3. 实现异步通道：`_handoff_post_process`（前台）与 `_enqueue_world_write`（经既有 `deferred_world_op → outbox`）。
4. 实现 `update(...)`：按 `routes_for` 依序执行 → 汇总 `Feedback` → 发事件 → 返回。
5. `loop.py` 的 `update` 段委派指向 `stages.update.update`。
6. 测试 `tests/v30/test_runtime_update_stage.py`（§7）；Focused → Module → Fast 后提交（§9）。
