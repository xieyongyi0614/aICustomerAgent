## 2. Background

### 2.1 为什么需要这个 Task

循环的第一段必须回答「这一轮到底感知到了什么」。当前没有这个对象：前台把「用户说了什么」直接塞进 `chat_pipeline` 的参数，后台把「为什么跑」（`_cycle_reason` 的 `due_trigger` / `goal_work` / `inactivity_eligible`）塞进 Run 的 `reason` 字段，世界事件经 `outbox` 预闸升级——**三种感知形态三种载体**，且都不可枚举、不可断言。

### 2.2 当前架构问题

| # | 问题 | 证据 |
|---|---|---|
| 1 | 无 Observation 载体 | 触发增量散落在 `RunContext.data` / `reason` / 函数参数 |
| 2 | 感知面不可枚举 | 「世界事实 / 关系状态 / 记忆信号」分别读于 `world_engine.collect_facts`、`agent_state_assembler`、`context_builder`，无统一入口 |
| 3 | 去重语义缺失 | 同 `dedupe_key` / 同事件重复进入循环时无统一判定处 |

### 2.3 在 V3.0 Runtime 中的位置

Observe 是六段之首（architecture §2.1）：它消费 `RuntimeInput`（RT-001）+ `SessionContext`（RT-002）+ `RuntimeContext`（RT-004），产出 `Observation` 供 Reason（RT-008）消费，并把 `ObservationRecorded` 事件（RT-005）用于后续 Context 刷新订阅。

**边界**：Observe **只读投影**，不实现 Memory / World / Relationship 的任何逻辑（architecture §4 边界裁决表：这些域全部 Preserve）。

## 3. Scope

### 3.1 In Scope

1. **`observe(...) -> Observation`**（`stages/observe.py`）。
2. **四类感知事实**：
   - 用户输入感知：`RuntimeInput.payload["text"]`、渠道身份（`channel_identity`）、`thread_id`；
   - 世界状态感知：`world_engine.collect_facts(user_id)`（只读，时间 / 场景 / 活跃事件）；
   - 记忆信号感知：`RuntimeContext.memory` 投影（最近记忆 / 高显著度信号，**不二次检索**）；
   - 关系与状态感知：`RuntimeState.snapshot.relationship` / `mood` / `energy` / `interest_focus`（RT-003 只读投影）。
3. **归一规则**：`dedupe_key`（`kind:source:基准`）、时点对齐 `run_started_at`、`source` 标记（channel 名或域标识）。
4. **降级**：任一事实集读取失败 → 该集为空 + `ObservationDegradation`，**不抛异常**。
5. **事件**：产出后经 `events.emit(...)` 发 `ObservationRecorded`（开关关闭时空操作）。

### 3.2 Out of Scope（明确禁止扩张）

- **零写入**：不写 `memories` / `world_*` / `relationship_*` / `character_state` / `scene_state`。
- **零 LLM**：不触碰 `llm_gateway` / `chains` / `prompts`。
- 不实现记忆打分、冲突消解、世界推演、关系数值计算（全属各域）。
- 不建表、不加列、不改迁移。
- 不做决策（RT-008）、不做上下文装配（RT-004，本段只消费）。
- 不改 `world_engine.collect_facts` / `agent_state_assembler` 的内部实现。

## 4. Technical Design Requirements

### 4.1 接口契约（`stages/observe.py`）

```python
@dataclass(frozen=True, slots=True)
class UserInputFact:
    text: str
    channel: str | None
    external_user_id: str | None
    thread_id: str | None

@dataclass(frozen=True, slots=True)
class WorldFact:
    payload: Mapping[str, Any] | None      # world_engine.collect_facts 结果（只读）

@dataclass(frozen=True, slots=True)
class MemorySignalFact:
    count: int
    topics: tuple[str, ...]                # 高显著度记忆主题（来自 RuntimeContext.memory）

@dataclass(frozen=True, slots=True)
class CharacterStateFact:                  # 关系与状态感知（RT-003 快照投影）
    mood: str | None
    energy: float | None
    relationship: Mapping[str, Any]
    snapshot_version: int

@dataclass(frozen=True, slots=True)
class ObservationDegradation:
    fact_set: str                          # user_input | world | memory | character
    error: str

@dataclass(frozen=True, slots=True)
class Observation:
    kind: str                              # RuntimeInput.kind（四类触发源）
    source: str
    dedupe_key: str
    observed_at: datetime                  # 对齐 run_started_at
    user_input: UserInputFact | None
    world: WorldFact | None
    memory: MemorySignalFact | None
    character: CharacterStateFact | None
    degradations: tuple[ObservationDegradation, ...]

def observe(runtime_input: RuntimeInput | None,
            session_context: SessionContext | None = None,
            *,
            runtime_context=None,          # RT-004 产物（可选）
            runtime_state=None,            # RT-003 冻结态（可选）
            now: datetime | None = None,
            trace=None) -> Observation: ...

def observation_dedupe_key(kind: str, source: str, runtime_input) -> str: ...
```

### 4.2 事实集来源（全部只读）

| 事实集 | 来源 | 缺失 / 失败处理 |
|---|---|---|
| 用户输入 | `RuntimeInput.payload["text"]` + `channel_identity` + `thread_id` | 无文本（后台触发）→ 该集 `None`（**不是降级**） |
| 世界 | `runtime_context.world` 优先；缺上下文时 `world_engine.collect_facts(user_id)` | 异常 → `degradations += world`，`world=None` |
| 记忆 | `runtime_context.memory` 投影（`memories` 计数 + 主题） | 异常 → 降级记录；**禁止**调 `memory2_retriever.retrieve` |
| 关系与状态 | `runtime_state.snapshot`（`mood` / `energy` / `relationship`）；缺冻结态时 `state.snapshot(user_id)` | 异常 → 降级记录 |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | `Observation` 是**纯值对象**，只落 Trace，不落业务表 | architecture 附：边界不变量 2 |
| D2 | 记忆信号**复用 RT-004 召回结果**，不二次检索 | 避免重复检索与成本翻倍（与 RT-004 D2 一致） |
| D3 | `observed_at` 对齐 `run.started_at` | RT-003 时点一致性的延伸 |
| D4 | 四类触发源产出**同 schema** `Observation`（仅 `kind` / `source` 不同） | Reason 段对来源无感，前台后台同形 |
| D5 | 任何事实集失败都不抛异常；只有 `recoverable=False` 才由循环裁决 | 感知失败不应中断 Run（旁路纪律） |
| D6 | `ObservationRecorded` 经 RT-005 发出（开关关闭时空操作） | 为后续 Context 刷新订阅留锚点 |

### 4.4 依赖

- 允许依赖：`contracts`（RT-001）、`session`（RT-002）、`state`（RT-003）、`context`（RT-004）、`events`（RT-005）、`app.application.world_engine.collect_facts`。
- **禁止**依赖：任何写仓储 / 写服务、`app.chains`、`app.prompts`、`llm_gateway`、`app.channels.feishu`、`memory2.retriever`。

### 10.2 实测发现（后续段须注意）

**`state.snapshot` 会间接读世界事实**：`state_manager.snapshot` → `agent_state_assembler.assemble` 内部会调 `world_engine.collect_facts`。

因此 `test_world_fact_prefers_runtime_context` 的「传 `runtime_context` → **零调用** `world_engine.collect_facts`」断言**必须同时传 `runtime_state`** 隔离角色段；否则角色段的快照会替你调用一次 `collect_facts`，断言假红。后续任何「某段零调用某域读面」的断言都要先确认**其它事实集不会传递性触发同一读面**。
