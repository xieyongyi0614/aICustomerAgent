## 2. Goal

让世界有"季节与节气感"和"自行变化的天气"：日历资产提供季节判定与节假日；天气演化器每日 day_start 按季节转移概率推进天气（种子可重放），落 `worlds.environment` 并发 `weather_change` 事件；day_cycle 补齐 `season_change` 标记。

## 3. Background

P3 指出事件来源贫乏：没有天气变化、节日等自然事件流。天气是最典型的"无人输入也发生"的世界事件，也是 G1（世界持续运行）最可感知的证据。V8 的 `worlds.environment` 已有 weather 字段但只能 manual 更新；context_selector 已渲染天气。本 Task 让它"活"起来，且日期/季节为决策与话题提供素材（节日 → calendar_event 事件）。

## 4. Scope

- 新增 `app/character/asuna/calendar.py`：季节映射、节假日表、`season_of(date)` / `holiday_of(date)` 纯函数。
- 新增 `app/services/world/weather.py`：`WEATHER_ENUM`（对齐既有词表）、季节转移概率表、`evolve(prev_weather, season, date, rng)` 纯函数。
- 扩展 `app/application/world_engine.py`：day_start 时执行天气演化（幂等键 `weather:{date}`），更新 `environment`（复用既有 `set_environment`）并发 `weather_change` 事件。
- 扩展 `day_cycle.py`：day_start 时判定 `season_change` 标记；节假日发 `calendar_event` 事件。

## 5. Non Scope

- 天气对情绪/风格的消费（WS-016）。
- 用户所在地真实天气接入（本系统是叙事世界，天气是模拟值）。
- 天气历史表（变化轨迹由 weather_change 事件天然留痕，架构 §6.4）。
- 节假日配置文件化/年度更新机制（遗留 Q6）。

## 6. Technical Design

### 6.1 CalendarAsset（角色资产）

- `SEASONS`：气象季节 3-5 春 / 6-8 夏 / 9-11 秋 / 12-2 冬；`season_of(date) -> "spring"|"summer"|"autumn"|"winter"`。
- `HOLIDAYS`：`(month, day) -> {name, kind}`，kind ∈ festival / memorial；覆盖主要公历节日（元旦/情人节/清明/劳动节/儿童节/中秋按公历近似/国庆/圣诞等，具体清单实现时定稿并入提交）。`holiday_of(date) -> dict|None`。

### 6.2 WeatherEvolver（纯函数）

- `WEATHER_ENUM`：实现前先读 `context_selector._weather_word` 与测试固件，确认既有 weather 取值集合；若为自由文本则在本 Task 收敛为枚举（如 sunny/cloudy/overcast/rainy/snowy/windy）并回归 `_weather_word` 全覆盖、`interpreter`/渲染不破。
- `TRANSITIONS[season][weather] -> list[(next_weather, weight)]`：如冬天 snowy 自持概率高、夏天 rainy→cloudy 概率高；每季节含 1~2 种"稀有天气"低权重。
- `evolve(prev_weather, season, date)`：`rng = random.Random(f"{world_id}|{date.isoformat()}")` → 加权抽样。确定性可重放（同日同世界必得同天气）。
- 温度带：`TEMPERATURE_BAND[season]`，随天气微调，落 `environment.temperature`（若既有渲染无此键则只存不渲染，Preserve）。

### 6.3 编排（world_engine 内，time_advance 子闸）

```text
day_start 标记存在（当日键已发）且 weather:{date} 未发：
  prev = environment.weather（缺省按季节基线）
  next = evolve(prev, season_of(date), date)
  set_environment(user_id, weather=next, temperature=band, updated_by="weather_sim")
  发 weather_change 事件（幂等键 weather:{date}）
    importance：rainy/snowy/windy 或天气类别变化大 → high/medium；微变 → low
    payload：{prev, next, season, date}
season_change：season_of(today) != season_of(yesterday) → time_marker 子类标记（幂等键 time:season:{date}）
calendar_event：holiday_of(date) 命中 → type=calendar_event, source=calendar,
  importance=medium, payload={name, kind}, 幂等键 calendar:{date}
```

### 6.4 数据流

```text
day_start 标记 → WeatherEvolver.evolve → worlds.environment.weather
                → weather_change 事件 → （WS-011 影响裁决 → WS-013/016 消费）
```

## 12. Acceptance Criteria

**功能验收**

1. 连续多日模拟：每日 day_start 后 environment.weather 更新，转移符合季节概率表的方向性（如冬天不出"晴热"）。
2. 同一 (world_id, date) 多次重放演化结果完全一致（种子确定性）。
3. 跨季节日期触发 season_change 标记恰一次；节假日触发 calendar_event 恰一次。
4. weather_change 事件 importance 分级符合 §6.3 规则。

**数据验收**

5. `worlds.environment` 只新增/更新 weather/temperature 相关键，其它键零变化；`updated_by="weather_sim"`。
6. 幂等：weather:{date} / calendar:{date} / time:season:{date} 各当日至多一条。

**接口验收**

无新增接口；`/debug/world` 可见新天气。

**异常情况**

- prev_weather 为空/非法值 → 按季节基线天气冷启动，不抛错。
- 转移表缺某组合 → 回落"维持原天气"，留 trace。

## 13. Testing Requirement
