## 2. Goal

落地 V2.3.0 的全部持久化增量：两张新表（`daily_plans`、`user_situations`）与两处扩列（`worlds.sim_last_advanced_at`、`world_events.idempotency_key`），供后续所有模拟/消费 Task 使用，并保证可逆放。

## 3. Background

Daily Life 需要按日具象化的日程行存储；用户处境需要独立于记忆的生命周期存储；TimeAdvancer 需要幂等推进锚点；日循环/天气标记需要防重发键。架构 §6 已冻结字段与索引设计，本 Task 忠实落地。模型放独立文件 `models/world_simulation.py` 而非改 `models/world.py` 主体，以保持 V8 模型（Preserve 对象）最小 diff。

## 4. Scope

- 新增 `app/models/world_simulation.py`：`DailyPlan`、`UserSituation` 两个 ORM 模型。
- 扩展 `app/models/world.py`：`World.sim_last_advanced_at`、`WorldEvent.idempotency_key`（仅加列）。
- 迁移 `0044_daily_plans_user_situations.py`（revision "0044"，down_revision "0043"）。
- 迁移 `0045_world_simulation_extensions.py`（revision "0045"，down_revision "0044"）。
- 逆放测试（0045→0043）。

## 5. Non Scope

- 表的业务读写函数（后续 Task 的 service/world 模块）。
- 历史清理 job（`daily_plan_retention_days` 的消费在 WS-017）。
- world_events 既有状态机/类型域的任何变更。

## 6. Technical Design

**模块设计**：纯模型 + 迁移，无逻辑。主键、时间列、JSON 列的类型与命名全部沿用 `models/world.py` 既有惯例。

**数据流**：无运行时数据流；仅需保证 `ensure_world`/`create_event` 等既有函数在扩列后行为不变（新列可空、不参与既有逻辑）。

## 7. Data Model

### Entity: DailyPlan（`daily_plans`，新建）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | String | PK | 沿用既有 uuid 惯例 |
| `user_id` | String | NOT NULL | 归属用户世界（同 worlds 口径） |
| `plan_date` | Date | NOT NULL | 计划日 |
| `seq` | Integer | NOT NULL | 块序号 |
| `part_of_day` | String | ck: morning/noon/afternoon/evening/night | |
| `start_minutes` / `end_minutes` | Integer | NOT NULL | 日内分钟（0~1439） |
| `activity` | String(50) | NOT NULL | ≤50 字纪律同 V3 |
| `location_id` | String(50) | NOT NULL | LocationRegistry id（WS-006） |
| `variability_source` | String | ck: fixed/variant/user_influenced | |
| `status` | String | ck: planned/active/completed/skipped/superseded | 状态机在 WS-008 应用层执行 |
| `routine_version` | Integer | NOT NULL | 生成所用模板版本 |
| `note` | String(200) | nullable | 用户影响来源备注 |
| `created_at` / `updated_at` | DateTime(tz) | NOT NULL | |

约束/索引：`uq_daily_plans_user_date_seq (user_id, plan_date, seq)` 唯一；`idx_daily_plans_lookup (user_id, plan_date, status)`；check 命名 `ck_daily_plans_part_of_day` / `ck_daily_plans_variability` / `ck_daily_plans_status`。

### Entity: UserSituation（`user_situations`，新建）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | String | PK | |
| `user_id` | String | NOT NULL | |
| `dimension` | String(30) | NOT NULL | health/work_pressure/schedule_change/travel/emotional_context |
| `summary` | String(100) | NOT NULL | ≤100 字 |
| `intensity` | Integer | ck: 1~5 | |
| `status` | String | ck: active/expired/dismissed | supersede 旧行置 expired |
| `source` | String | ck: conversation_pattern/user_directive/llm_assist | |
| `evidence_json` | JSON | nullable | {message_id, quote, matched_pattern} |
| `detected_at` / `valid_until` / `updated_at` | DateTime(tz) | detected_at/updated_at NOT NULL | |

索引：`idx_user_situations_active (user_id, status, valid_until)`；check 命名 `ck_user_situations_status` / `ck_user_situations_source` / `ck_user_situations_intensity`。

### 扩展列

| 表 | 列 | 类型 | 说明 |
|---|---|---|---|
| `worlds` | `sim_last_advanced_at` | DateTime(tz), nullable | TimeAdvancer 幂等锚点（real_sync 不用） |
| `world_events` | `idempotency_key` | String(100), nullable | 时间/天气标记防重发键 |

部分唯一索引：`uq_world_events_idempotency ON world_events(idempotency_key) WHERE idempotency_key IS NOT NULL`（Alembic 同时传 `sqlite_where` 与 `postgresql_where`）。

### Relation

- `daily_plans.user_id` / `user_situations.user_id` 与 worlds（`home:{user_id}`）为逻辑关联，是否加物理 FK 以 `models/world.py` 既有口径为准（保持同构）。
- 0044 只建新表；0045 只做扩列 + 部分唯一索引；两者均可独立逆放。

## 11. Implementation Steps

- **Step 1**：写 `models/world_simulation.py`（含 §7 全部 check 约束与命名）。

- **Step 3**：写迁移 0044（create_table × 2，含索引/约束）与 0045（add_column × 2 + 部分唯一索引；SQLite 兼容性核对，必要时 batch_alter_table）。

## 12. Acceptance Criteria

**功能验收**

1. 两张新表可建行、可查询；check 约束拦截非法枚举值（如 `status="done"` 被拒）。
2. `worlds.sim_last_advanced_at` / `world_events.idempotency_key` 为可空列，既有读写路径零影响。
3. 同一非空 `idempotency_key` 第二次插入被唯一索引拒绝；NULL 键不受约束（可多条）。

**数据验收**

4. `upgrade head` 后两新表结构与 §7 完全一致；存量表行数与内容不变。
5. `downgrade 0043` 后两表、扩列、部分唯一索引消失；再 `upgrade` 幂等。

**接口验收**

无新增接口；既有 `/debug/world` 系列端点回归通过。

**异常情况**

- 部分唯一索引在 SQLite/PostgreSQL 双方言下行为一致。
- 约束命名与既有 ck_/uq_/idx_ 冲突时迁移失败并给出可定位报错。

## 13. Testing Requirement

- **Integration Test**：迁移正向 + 逆放（0043↔0045）；部分唯一索引行为。
- **Scenario Test**：既有全套件在 `upgrade head` 后全绿（零回归基线）。
