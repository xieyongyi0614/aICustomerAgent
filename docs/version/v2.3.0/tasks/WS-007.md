## 2. Goal

让角色"有生活"：RoutineAsset 定义角色一天的模板（按日型 × part），DailyPlanBuilder 在每日 day_start 将模板具象化为当日 `daily_plans` 行——固定块保持、变体块按种子加权随机、用户影响（处境/承诺）替换或插入块，产出可被决策/简报/风格消费的"她今天要做什么"。

## 3. Background

P2：角色没有作息，凌晨与白昼状态等同。架构 §5.3 要求支持固定习惯、随机变化、用户影响三要素，且随机可复现（G6，测试与"世界一致性"的前提）。触发时机是 day_start 标记（WS-004 产出），计划落 WS-002 的 daily_plans 表。

## 4. Scope

- 新增 `app/character/asuna/routine.py`：`ROUTINE_TEMPLATES`（weekday/weekend/holiday × 块列表）与 `ROUTINE_VERSION` 常量。

## 6. Technical Design

### 6.1 RoutineAsset

```text
RoutineBlock = {
  seq, part, start_min, end_min,      # 模板时间（变体块允许 ±30 分钟种子抖动）
  activity, location_id,
  variability: {"mode":"fixed"}
             | {"mode":"variant","alternatives":[{"activity","location_id","weight"},...]},
  user_influencable: bool,            # 该块是否允许被用户影响覆盖
  energy_bias: int,                   # -2..+2（WS-016 消费）
  topics: [str],                      # 话题池（决策/主动素材）
}
ROUTINE_TEMPLATES: {"weekday": [...], "weekend": [...], "holiday": [...]}
ROUTINE_VERSION = 1（资产内容变更时递增；种子含此版本）
```

示例（weekday，实现时定稿）：早晨 早餐 dining_area(fixed) → 上午 工作/学习 company(fixed) → 午后 咖啡店休息 cafe(variant：咖啡店/公园/在家) → 傍晚 运动/购物(variant) → 晚间 阅读/追剧(variant) → 深夜 休息 bedroom(fixed)。

`day_type_of(date)`：holiday_of(date) 命中 → "holiday"；周六日 → "weekend"；否则 "weekday"。

### 6.2 DailyPlanBuilder 核心逻辑

```text
build_daily_plan(user_id, plan_date):
  1. 幂等：查询该日 status∈(planned,active) 的行 → 全部置 superseded（重建安全）
  2. seed = f"{user_id}|{plan_date.isoformat()}|{ROUTINE_VERSION}"；rng = random.Random(seed)
  3. template = ROUTINE_TEMPLATES[day_type_of(plan_date)]
  4. 逐块展开：
     - fixed → 原样；variant → rng 加权抽样 alternative
     - 时间抖动：variant 块 start/end ±30min 内 rng 偏移（fixed 不抖动）
  5. 用户影响绑定（优先级：显式请求 > 处境 > 模板）：
     - active user_situations：
         health 且 user_influencable 晚间块 → 活动替换为"探望/照顾"类块，note="用户健康处境"
         travel → 午后块替换为外出块
         work_pressure → 晚间块替换为轻松陪伴向变体
     - commitment 记忆（memory2 既有 commitment 类型、到期日=plan_date）→ 插入对应用户块
     - 命中的块 variability_source="user_influenced"，note 记录来源 id
  6. 落库 daily_plans（status=planned）；返回计划摘要
```

**变体抽样与影响绑定的确定性**：影响绑定在抽样之后按确定性规则执行（不引入额外随机），保证同输入同输出。

### 6.3 触发与自愈

- day_start 标记在当 tick 的事件列表中 → 构建；
- 自愈：tick 时发现当日（按世界时间）无 planned/active 计划 → 构建（进程重启/漏标记兜底，与 WS-004 幂等键互补）。

## 12. Acceptance Criteria

**功能验收**

1. 同一 (user_id, plan_date) 两次构建产出**逐字节相同**的计划（种子重放）。
2. fixed 块无抖动；variant 块在同种子下选择一致、跨日期分布合理（统计抽测）。
3. 节假日走 holiday 模板；周末走 weekend 模板。
4. 用户影响：注入 health 处境后晚间块被替换且 `variability_source=user_influenced`、note 可溯源；commitment 到期日在计划中出现对应用户块。
5. 重复构建：旧 planned/active 行全部 superseded，新行 seq 连续无空洞。

**数据验收**

6. daily_plans 行字段完整符合 WS-002 约束；当日恰一套非 superseded 计划。
7. user_situations / memories 只读零写。

**接口验收**

无新增接口。

**异常情况**

- user_situations 表空 / memory 查询失败 → 退回纯模板计划（降级不抛错）。
- location_id 非法（资产漂移）→ 构建失败留 trace 并跳过该块（不自愈出坏行）。

## 13. Testing Requirement

- **Unit Test**：day_type 判定矩阵；种子重放一致性；抖动边界；影响绑定优先级与幂等；supersede 语义。
- **Integration Test**：day_start → 落库 → 查询函数；自愈路径（删计划后 tick 重建）。
- **Scenario Test**：工作日/周末/节假日 + 处境注入的四象限场景计划对比；Flag off 时 daily_plans 零写入。
