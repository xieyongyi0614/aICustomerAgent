## 2. Goal

补齐时间模拟的两种极端：**长离线**（用户 N 天后回来，世界连续但不重放噪声——逐日折叠 day_summary 或长间隔单事件 + 天气落终态 + 只生成今天计划）与**事件风暴**（单 tick 模拟事件超上限时折叠为 world_digest 摘要事件）。

## 3. Background

架构 §7.4：N≤7 逐日 day_summary；N>7 折叠为单条"长时间过去"事件 + 当前快照重建。§5.4：单 tick 每用户事件 ≤ `world_event_tick_cap`。没有这两条，用户休假一周回来会被几十条 part 标记与事件淹没，记忆与主动行为都会被噪声污染。

## 4. Scope

- 新增 `app/services/world/catch_up.py`：`compute_catch_up_plan(last_day_key, current_date) -> CatchUpPlan`（纯函数）与执行编排。
- 扩展 `world_engine._emit_simulation_events`：本 tick 计数 + 上限折叠（world_digest）。
- 追赶后的状态重建：天气直接演化落终态（逐日循环 evolve 但只发最后一条 weather_change）、过期处境批量 expire、当日计划构建（WS-007 自愈路径复用）。
- day_summary 事件规范与 world_digest 事件规范。

## 5. Non Scope

- 正常单日推进（WS-003/004/008）。
- 追赶期间的记忆逐日沉淀（记忆只收 day_summary/终态，见 §6.2）。
- sim_time 补帧（WS-003 截断语义已覆盖；本 Task 处理日级跨越）。

## 6. Technical Design

### 6.1 CatchUpPlan（纯函数）

```text
输入：最后一个 day_start 幂等键日期 last_date、世界当前日期 today
输出：
  days_behind = (today - last_date).days
  days_behind == 0 → 无追赶
  1 ≤ days_behind ≤ catch_up_max_days(7)：
     逐日 day_summary 事件（缺过去的 day_start/part 标记，不补发）+
     今日正常 day_start
  days_behind > 7：
     单条 long_gap 事件（payload={from, to, days}）+ 今日 day_start
```

### 6.2 day_summary / long_gap 事件规范

| 事件 | idempotency_key | importance | payload |
|---|---|---|---|
| day_summary | `time:day_summary:{date}` | low | {date, weekday}（内容摘要不入记忆——WS-015 低权重分流） |
| long_gap | `time:long_gap:{from}:{to}` | medium | {days, from, to}（可入记忆："她独自过了十二天"） |

追赶日不补发 part_transition / day_close / 逐日 weather_change；天气按日期序列循环 `evolve`，仅落终态并发最后一条 weather_change（payload 带 skipped_days）。

### 6.3 风暴防护（漏斗增强）

```text
_emit_simulation_events(user_id, drafts):
  cap = settings.world_event_tick_cap
  if len(drafts) <= cap: 全部落库
  else: 前 cap-1 条按（importance 降序, 生成序）保留，
        其余折叠为一条 world_digest（type=world_digest, source=simulation,
        importance=low, payload={kinds:[...], count}, 幂等键 world_digest:{tick_ts}）
  被折叠事件不落库（其下游影响由 digest 承载；importance 语义：被折叠者皆 low）
```

### 6.4 数据流

```text
tick → run_simulation_maintenance
  → catch_up 检查（对照最近 day_start 键）→ CatchUpPlan 执行（含天气终态/处境批量过期/今日计划）
  → 正常推进（WS-004/005/008）
  → _emit_simulation_events（计数 + 风暴折叠）
```

## 12. Acceptance Criteria

**功能验收**

1. 离线 3 天回来：恰 3 条 day_summary + 今日 day_start，无 part/逐日天气噪声；天气为今日终态且事件 payload 带 skipped_days。
2. 离线 12 天：恰 1 条 long_gap（medium，可入记忆）+ 今日 day_start + 今日计划。
3. 追赶当日无重复（幂等键防重；二次 tick 零新增）。
4. 单 tick 构造 20 条模拟事件 → cap=8 时落库 7 条常规 + 1 条 world_digest（payload.count=12），importance 分级保留正确。

**数据验收**

5. 追赶不产生 memory_candidates 噪声（day_summary 不入桥；long_gap 经 WS-015 可入）。
6. worlds.sim_time / environment 终态与"逐日模拟"结果一致（种子重放对照）。

**接口验收**

无新增接口。

**异常情况**

- 最近 day_start 键查询失败 → 保守按"无追赶"处理（宁可少补不可误补）。
- 追赶与 WS-008 对账同 tick 竞争 → 维护步内顺序执行（catch_up 先于 plan advance），无并发写。

## 13. Testing Requirement

- **Unit Test**：Plan 边界矩阵；折叠选择算法（importance/序）；幂等键。
- **Integration Test**：冻结时钟快进 3/12 天全链（事件集、环境终态、计划、处境过期）。
- **Scenario Test**：周模拟中断重启恢复连续性；风暴注入（批量事件）后 world_events 增量 ≤ cap；Flag off 时漏斗直通行为与 V2.2.0 一致。
