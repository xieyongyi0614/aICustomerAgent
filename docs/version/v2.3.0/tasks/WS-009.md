## 2. Goal

让世界感知"用户正在经历什么"：从对话中确定性检出用户处境（生病/压力/出差/考试/情绪低落），落 `user_situations`（含证据与有效期）并发 `user_condition` 事件；支持到期过期、显式解除（"我好了"）与同维度 supersede；LLM 辅助检出作为独立灰度增强。

## 3. Background

架构示例世界状态中的"用户今天工作压力较大"、天气变冷式关怀与 WS-007 的用户影响绑定，都依赖结构化的用户处境。V8 解释器只解释世界操作（物体/位置），不追踪用户处境；架构将其定位为"角色视角下用户是世界的一部分"（不破 V8 铁律）。

## 4. Scope

- 新增 `app/services/world/user_situation.py`：模式表（dimension → 关键词/正则/解除模式）、`detect_user_situations(user_id, text, evidence)`、`dismiss_situations(...)`、`expire_stale_situations(user_id, now)`。
- 扩展 `app/application/post_process.py::run_world_update`（第 8 步）：解释器之后追加处境检出段（v23_event_detection_enabled 门控）。
- LLM 辅助链 `app/chains/situation_detect.py`（build_structured_chain + llm_factory light profile），`v23_world_llm_assist_enabled` 且确定性无命中时按采样率触发；失败返回 None。
- `user_condition` 事件产出（source=user_evidence）。

## 5. Non Scope

- 处境的消费（WS-007 计划影响 / WS-011 影响裁决 / WS-012 简报）。
- 敏感维度的产品口径扩张（遗留 Q2：本 Task 只实现 §6.1 清单内维度）。
- 用户画像/长期偏好推断（属反思域）。

## 6. Technical Design

### 6.1 确定性模式表（初版清单，实现时定稿并入提交）

| dimension | 命中模式（示例） | intensity_hint | 解除模式 |
|---|---|---|---|
| health | 生病/感冒/发烧/不舒服/去医院 | 4 | 好了/没事了/痊愈/恢复 |
| work_pressure | 加班/deadline/项目上线/压力大/加班到 | 3 | 项目结束了/忙完了 |
| schedule_change | 考试/答辩/面试/出差准备 | 3 | 考完了/面完了 |
| travel | 出差/去外地/旅行中/在路上 | 2 | 回来了/到家了 |
| emotional_context | 心情不好/难过/烦躁/委屈 | 3 | （无自动解除，随有效期过期） |

每命中产出：summary（≤100 字，模板 + 命中原文截断）、intensity（hint ± 关键词强化，clamp 1~5）、`valid_until = now + user_situation_valid_hours`、`evidence_json={message_id, quote, matched_pattern}`、source=conversation_pattern。

### 6.2 生命周期规则

- **supersede**：同 dimension 已有 active 行 → 旧行置 expired（updated_at 刷新）→ 插入新行（单一主处境纪律）。
- **dismiss**：解除模式命中且存在 active 同维度行 → 置 dismissed，并发 `user_condition`（payload.kind="ended"）事件（WS-015 记忆分流消费）。
- **expire**：模拟维护步内 `expire_stale_situations`：valid_until < now 的 active 行 → expired（同样发 ended 事件，importance=low）。

### 6.3 LLM 辅助链

```text
条件：v23_world_llm_assist_enabled 且 v23_event_detection_enabled
      且确定性无命中 且 rng < v23_llm_assist_sample_rate
输入：用户本轮消息文本
输出（structured）：{dimension?, summary?, intensity?, valid_hours?} 或 {none}
失败/超时/解析失败 → None（静默，走无检出）
source 落 "llm_assist"；evidence_json.record="llm"
```

### 6.4 数据流

```text
用户消息 → post_process 第 8 步 run_world_update
  → V8 解释器（Preserve）→ UserSituationTracker.detect（Flag 内）
      → user_situations 落库 + user_condition 事件（漏斗）
  → 消费：WS-007 计划影响 / WS-011 care_relevance / WS-012 WorldBrief / WS-013 escalation
```

## 12. Acceptance Criteria

**功能验收**

1. "我感冒了，头好疼" → health active 行（intensity≥4 → 事件 importance=high，evidence 含 message_id 与引文）。
2. 同维度重复检出 → 旧行 expired、仅一行 active；"我好了" → dismissed + ended 事件；到期 → expired + ended 事件（low）。
3. 确定性无命中且辅助闸开启时按采样率触发 LLM；辅助命中落 source=llm_assist。
4. 非处境文本零检出零写入。

**数据验收**

5. user_situations 行符合 §7 约束；evidence_json 可溯源（message_id 存在）。
6. user_condition 事件 type/source/importance 正确，经漏斗落库。

**接口验收**

无新增接口。

**异常情况**

- LLM 辅助失败/超时 → 静默返回，不影响主链路（post_process 其余步骤照常）。
- 消息文本超长 → 截断后匹配；evidence.quote 截断至 100 字。

## 13. Testing Requirement

- **Unit Test**：模式命中矩阵（五维度 × 命中/解除/干扰文本）、intensity clamp、supersede/dismiss/expire 状态机、采样开关。
- **Integration Test**：post_process 端到端（消息 → 行 + 事件）；过期在模拟维护步生效。
- **Scenario Test**：连续对话"感冒 → 恢复"全生命周期；Flag off（总闸/子闸/辅助闸三态）时第 8 步行为与 V2.2.0 一致。
