## 2. Goal

让世界时间自主流动：在 Life Loop 维护步序列中新增 `world_simulation` 步骤，内含 TimeAdvancer 按 `worlds.time_mode` 三模式推进时间（real_sync 核对 / simulated 增量×rate 带上限 / story 跳过），并落幂等推进锚点。该步骤在用户离线（idle tick）时也必须执行。

## 3. Background

P1 的根因：V8 TimeProvider 三模式齐备，但 `sim_time` 只能被显式 `advance_time` 推进，世界静止。Life Loop 是项目唯一调度器（架构铁律），时间推进必须作为维护步骤挂载而非新循环。关键事实：`life_loop._run_maintenance` 的执行不依赖 work_users，但 tick 入口有 `if not work_users and not maintenance_pending: return` 的短路——因此 `_maintenance_pending` 必须扩展，否则离线时世界停止运转（违背 G1）。

## 4. Scope

- 新增 `app/services/world/time_advancer.py`：`advance_world_time(user_id, now) -> TimeAdvanceResult`。
- 扩展 `app/application/world_engine.py`：新增 `run_simulation_maintenance(user_id, now)` 编排入口（本 Task 只含时间推进段，为 WS-004/005/007/008/009/017 预留顺序钩子）。
- 扩展 `app/application/life_loop.py`：`_run_maintenance` 注册 `world_simulation` 步骤；`_maintenance_pending` 同步纳入；复用 `_maintenance_due/_mark_maintenance/_safe_sync_call/_record_maintenance_run`。
- WS-002 的 `worlds.sim_last_advanced_at` 锚点写入。

## 5. Non Scope

- 日循环标记/天气/日程/处境的产生与消费（WS-004~009）。
- catch-up 折叠（WS-017；本 Task 对 simulated 大跨度只做上限截断，不折叠补发）。
- `world_engine.advance_time`（V8 显式推进 API）语义的任何变更；story 模式的显式推进路径不动。

## 6. Technical Design

### 6.1 模块设计

```text
life_loop._run_maintenance(now)
  └─ world_simulation 步（v23_world_simulation_enabled 且 v23_time_advance_enabled，interval=world_sim_interval_seconds）
       └─ world_engine.run_simulation_maintenance(user_id, now)   [application 编排]
            ├─ ensure_world(user_id)
            ├─ time_advancer.advance_world_time(user_id, now)      [service，本 Task]
            │    └─ 更新 worlds.sim_time / sim_last_advanced_at
            └─ （预留顺序钩子，后续 Task 填充）
                 WS-004 emit_time_markers → WS-005 weather → WS-007 plan build
                 → WS-008 plan advance → WS-009 situation expiry → WS-017 catch-up
```

### 6.2 TimeAdvancer 核心逻辑（`advance_world_time`）

按 `worlds.time_mode` 分派：

- **real_sync**：TimeProvider 直接读真实钟，无需推进；仅确保 `sim_last_advanced_at = now`（锚点核对）。返回 `advanced_minutes=0`。
- **simulated**：
  1. `anchor = world.sim_last_advanced_at`；为 None 时（首次）仅落锚点 `anchor = now`，不推进（防止部署瞬间大跳）。
  2. 否则 `real_delta = now - anchor`；`sim_delta = real_delta × settings.world_sim_rate`；按 `sim_advance_max_minutes` 截断（截断时下一 tick 继续追赶或由 WS-017 折叠）。
  3. `world.sim_time += sim_delta`；`sim_last_advanced_at = now`。返回 `advanced_minutes` 与是否截断。
- **story**：不自动推进；仅落锚点。返回 `advanced_minutes=0, mode="story"`。

**TimeAdvanceResult 值对象**：`{mode, advanced_minutes, truncated, anchor}`（纯数据，供 trace 与后续 Task 消费）。

### 6.3 调用关系与事务

- 与 `world_maintenance` 步同构：`_safe_sync_call("world_simulation", world_engine.run_simulation_maintenance)`，异常被捕获记录、不中断其它维护步（World 旁路纪律）。
- 锚点与 sim_time 更新在单事务内提交；失败时两者都不落（防"时间推进了锚点没动"的重复推进）。

### 6.4 数据流

```text
tick(60s) → _maintenance_due("world_simulation") → run_simulation_maintenance
  → worlds.sim_time / sim_last_advanced_at 持久化 → TimeAdvanceResult 进 loop_runs 步骤记录
```

## 12. Acceptance Criteria

**功能验收**

1. simulated 模式：给定锚点 10:00、rate=1.0、now=10:05，tick 后 `sim_time` 前进 5 分钟；rate=2.0 前进 10 分钟。
2. 单 tick 跨度超过 `sim_advance_max_minutes` 时按上限截断且 `truncated=True`，锚点仍推进到 now。
3. 首次运行（锚点为 NULL）只落锚点不推进；story 模式任何情况下不改 `sim_time`；real_sync 不改 `sim_time`。
4. `world_simulation` 步骤在无 work_users 的 idle tick 中照常执行（`_maintenance_pending` 命中），`loop_runs.steps` 出现该步记录。

**数据验收**

5. `sim_time` 与 `sim_last_advanced_at` 同事务落库；异常注入时两者保持旧值。
6. `worlds` 其它列与既有事件/实体零变化。

**接口验收**

无新增接口；既有 `/debug/world` 返回的 sim_time 与推进结果一致。

**异常情况**

- DB 失败时该步被 `_safe_sync_call` 捕获，Life Loop 其它维护步照常执行，下个 interval 重试。
- 系统时钟回拨（now < anchor）时按 0 推进处理并留 trace，不产生负增量。

## 13. Testing Requirement
