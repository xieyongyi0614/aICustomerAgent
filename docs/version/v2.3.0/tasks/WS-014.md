## 2. Goal

让决策"知道此刻是几点、她在忙什么、世界给了什么机会"：timing 维度引入日程信号（打断成本），goal_compile 候选源消费 EventImpact 的 goal_opportunity（origin=world_event，layer=short_term），完成 §8.3 链路的 Goal 层闭环。

## 3. Background

P5：timing 只有 current_focus 在途判断。架构 §8.3 要求 Goal 层接收世界机会（如降温 → user_care 目标"提醒添衣"）。既有基础比预期更好：goal_planning 已支持 World 事件来源、`character_goals.origin` 值域已含 `world_event`（AGENT-003 交付）——本 Task 是接线而非新机制。

## 4. Scope

- `app/services/decision_pipeline.py` timing 评分扩展：新增日程信号输入（当前块 activity/part → interrupt cost），flag 参数化，缺省路径数值逐字节不变。
- `app/services/goal_planning.py`：goal_opportunity → 候选（domain/type/hint 来自 GoalHint，origin=world_event，layer=short_term，经既有 supply 审核通道）。
- 目标候选落库走 goal_service 既有创建路径（character_goals origin=world_event）。
- `v23_event_detection_enabled` + 总闸门控。

## 5. Non Scope

- P0~P4 优先级、六维权重、四风险闸的任何调整。
- goal 状态机/仲裁语义（Preserve）。
- 世界侧直接写 character_goals（违反边界不变量 2）。

## 6. Technical Design

### 6.1 timing 日程信号

```text
timing 评分既有公式（六维之一，中性 0.5 兜底）扩展输入：
schedule_signal = f(current_block, part, candidate_urgency)
  - 无日程数据（Flag off / 无计划）→ 既有路径（不引入新项，数值逐字节一致）
  - 当前块 ∈ {工作/学习类} 且候选 urgency ∈ {none, low} → timing -= interrupt_cost（常量 0.15）
  - 块 ∈ {休息/阅读类} 或非块时段 → 中性
  - candidate 携带 high care impact → 中性偏正（打断合理性）
审计：timing 分项在 decision_records 既有分项结构中可见（原因字段含 schedule 信号来源）
```

实现形态：timing 评分函数加可选 `world_schedule` 参数（None 时行为不变），decision 插槽在 Flag 内传入（与 WS-013 素材包同源）。

### 6.2 goal_opportunity → 候选

```text
goal_planning.materialize 既有 World 事件来源扩展：
  输入素材 = world_facts.impacts（WS-013）
  对每个 impact.goal_opportunity 非空项产候选：
    layer="short_term", domain=hint.domain, type=hint.type,
    description=hint.hint（≤50 字）, origin="world_event",
    优先级按 care_relevance 映射 GOAL_TIER（user_care=1 / scene=0，既有语义）
  去重：同 goal_id/同 hint 同日已存在候选则跳过（幂等，读 character_goals origin=world_event 当日行）
  走既有 supply 审核通道（审核规则零改动）
```

### 6.3 数据流

```text
EventImpact（WS-011）
  ├→ timing 信号（前台/后台 decision 共用路径）
  └→ goal_planning 候选（origin=world_event）→ 审核 → character_goals
       → Goal Stack L1 → 决策对齐度/行动候选（V2.1 既有通道）
```

## 12. Acceptance Criteria

**功能验收**

1. 工作块内低 urgency 候选 timing 下降且审计可见原因；高 care 候选不受抑制。
2. 降温 impact 的 GoalHint → character_goals 出现 origin=world_event 的 short_term user_care 行（经审核通道）。
3. 同一机会重复评估不产生重复目标（幂等去重）。
4. Flag off：timing 分项与候选集合与 V2.2.0 逐字节一致。

**数据验收**

5. character_goals 新行字段（layer/domain/origin）符合本 Task 规范；goals 域其余表零写。

**接口验收**

无新增接口；decision_records 既有结构兼容（分项字段追加不破坏消费方）。

**异常情况**

- world_schedule 传 None / 素材包为空 → 既有路径。
- GoalHint 非法（hint 超长/域未知）→ 丢弃该候选并 trace。

## 13. Testing Requirement

- **Unit Test**：timing 信号矩阵（块类型 × urgency × care）；候选映射与去重；契约冻结断言。
- **Integration Test**：impact → 候选 → goal_service 落库 → Goal Stack L1 可见；decision_records 审计完整性。
- **Scenario Test**：架构 §8.3 全链复刻（世界事件 → 目标 → 决策胜出 → proactive）；Flag off 对照逐字节一致。
