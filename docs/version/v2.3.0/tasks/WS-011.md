## 2. Goal

为世界事件建立统一的"对角色意味着什么"换算口径：输入事件（type/importance/payload）与轻量上下文（part/当前块/活跃处境），输出影响裁决包（urgency / care_relevance / topic_value / goal_opportunity）。这是世界事件进入自治候选、时机评分与目标机会的**唯一换算函数**。

## 3. Background

V8 时代世界事实进自治靠 W1/W2/W3 三条硬编码修饰规则，事件类型扩展后不可持续。架构 §5.4 将 EventImpactRules 定为纯函数裁决层：可单测、可解释、可扩展。消费方是 WS-013（自治素材与 escalation）与 WS-014（timing 与 goal opportunity）。

## 4. Scope

- 新增 `app/services/world/event_impact.py`：`EventImpact` 值对象 + `evaluate(event, context) -> EventImpact` 纯函数 + 规则矩阵。
- 规则矩阵覆盖 §5.4 全部 V2.3 事件类型 + 既有类型（reminder/appointment 等）的兼容映射。
- 单元测试冻结接口契约（输入/输出/分值区间），供 WS-013/014 消费。

## 5. Non Scope

- 任何消费接线（WS-013/014）。
- decision_pipeline / autonomy_policy 文件改动（只冻结接口）。
- 事件的产生与落库（上游 Task）。

## 6. Technical Design

### 6.1 输出契约（冻结，WS-013/014 按此消费）

```text
EventImpact = {
  urgency: "none"|"low"|"medium"|"high",
  care_relevance: float,      # 0.0~1.0，关切用户程度
  topic_value: float,         # 0.0~1.0，可聊性
  goal_opportunity: GoalHint | None,
}
GoalHint = {domain: "user_care"|"scene", type: str, hint: str≤50, layer: "short_term"}
```

### 6.2 规则矩阵（初版，常量集中便于调参）

| 事件 | urgency | care_relevance | topic_value | goal_opportunity |
|---|---|---|---|---|
| weather_change（rainy/snowy/windy 或降温） | low | 0.7 | 0.4 | user_care / remind_clothing（降温）/ remind_umbrella（雨） |
| weather_change（微变） | none | 0.1 | 0.2 | None |
| user_condition（新检出） | intensity≥4 → high，否则 medium | 0.9 | 0.6 | user_care / care_{dimension} |
| user_condition（ended） | none | 0.3 | 0.5 | None |
| calendar_event（festival） | low | 0.5 | 0.8 | scene / celebrate_{name} |
| time_marker（day_start） | none | 0.1 | 0.3 | None |
| time_marker（part_transition） | none | 0.1 | 0.2 | None |
| life_event（activity_done，user_influenced） | none | 0.3 | 0.6 | None |
| life_event（location_change） | none | 0.1 | 0.4 | None |
| goal_completed（outcome=success） | none | 0.2 | 0.7 | None |
| goal_completed（outcome=failed） | none | 0.2 | 0.3 | None |
| interest_emerged | none | 0.2 | 0.6 | None |
| reminder/appointment 到期（既有） | high | 0.5 | 0.3 | None |

上下文修正项（context 非空时叠加，clamp 后输出）：

- 深夜（part=night）→ urgency 降一档（care 类除外）。
- 当前块为 工作/学习（读 plan_block.activity）→ 低 urgency 事件 topic_value -0.2。
- 同 dimension 处境已 active 的 user_condition → urgency 降档（避免重复打扰）。

### 6.3 数据流

```text
world_events（新事件）→ evaluate（纯函数）→ EventImpact
  → WS-013：autonomy 素材包 + escalation 白名单匹配
  → WS-014：timing 信号 + goal_planning 候选（origin=world_event）
```

## 12. Acceptance Criteria

**功能验收**

1. 矩阵中每类事件产出符合 §6.2 的裁决包（urgency/care/topic 数值断言）。
2. 上下文修正生效：深夜降档、工作块降 topic、重复处境降档；clamp 后不越界。
3. 未知类型事件返回全中性值（urgency=none、0.5、0.5、None）且可解释。
4. 既有 reminder/appointment 到期映射为 urgency=high（兼容 V8 语义）。

**数据验收**

不涉及数据库（纯函数）。核对：输入事件对象不 Zipper 修改（无副作用断言）。

**接口验收**

无新增接口；`evaluate` 签名与 `EventImpact` 字段冻结为 WS-013/014 契约（联调测试锁定）。

**异常情况**

- payload 缺字段 / 类型不符 → 按缺省中性值处理并留可读 trace，不抛错。
- context 传 None → 等价于无修正项的基准裁决。

## 13. Testing Requirement

- **Unit Test**：矩阵全类型覆盖；修正项；clamp 边界；纯函数性（无 IO/无副作用）；契约形状。
- **Integration Test**：以真实落库事件行（测试夹具）驱动 evaluate。
- **Scenario Test**：天气变冷 + 用户健康处境两场景的组合裁决（修正项叠加路径）；Flag 无关（纯函数不读 Flag，门控在消费方）。
