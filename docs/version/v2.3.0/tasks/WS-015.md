## 2. Goal

按架构 §8.3 分流规则接通世界与记忆：V2.3 新事件类型经 memory_bridge 单向投递（重要事件 → 记忆候选；"第一次"事件重要性提升）；处境结束事件可沉淀；反思证据窗天然获得世界来源记忆；短期世界信息（天气/当前块）**不落记忆**。

## 3. Background

V8 memory_bridge 已实现"完结且重要事件 → 记忆候选"（materialized 幂等），memory2 五源已含 world_events。V2.3 的新事件类型（life_event/user_condition/goal_completed/interest_emerged/calendar_event）不在桥的映射内；"第一次旅行"类事件需要显著性提升机制（架构 §8.3 中期示例）。

## 4. Scope

- 扩展 `app/services/world/memory_bridge.py::to_memory_candidates`：新事件类型映射 + payload 提取 + "首次"显著性规则。
- 处境 ended 事件的分流：health/travel 类 ended 且 intensity≥3 → 记忆候选（"用户感冒已恢复"）。
- 反思侧验证：确认世界来源记忆进入证据窗（memory2 既有机制，跑通并留测试）；不做反思代码改动。
- 长离线 day_summary（WS-017 产出）的低权重分流（importance=low → 不入记忆，仅评估器可见）。

## 5. Non Scope

- memory_candidates 评估/转正/衰减机制（既有）。
- 反思触发、三闸、insights 生命周期（既有；只验证消费）。
- "用户喜欢冬天"类长期偏好（由反思从世界来源记忆归纳，属既有能力路径，本 Task 不写推导逻辑）。

## 6. Technical Design

### 6.1 分流规则（对齐 architecture §8.3 表）

| 世界信息 | 层级 | 去向 |
|---|---|---|
| 今日天气 / 当前日程块 / 活跃处境 | 短期 | WorldBrief（WS-012），**不落记忆** |
| 重要事件：goal_completed、interest_emerged、calendar_event(festival)、user_influenced 块完成、location_change(旅行地点) | 中期 | memory_bridge → memory_candidates |
| 处境 ended（health/travel，intensity≥3） | 中期 | 同上 |
| 模式归纳（多次同类事件） | 长期 | 反思证据（经记忆候选入评估后自然成为证据窗素材） |

### 6.2 桥映射扩展

```text
to_memory_candidates(event) 新增映射：
  life_event(activity_done, importance=medium) → 摘要"她{activity}（{location}）"
  life_event(location_change, to ∈ travel_*) → 摘要"她到了{location 中文名}"
  goal_completed(success) → 摘要"她完成了目标：{title}"
  interest_emerged → 摘要"她对新事物产生兴趣：{topic}"
  user_condition(ended) → 摘要"用户{summary}（已结束）"
  calendar_event → 摘要"今天是{name}"
首次显著性：候选生成时查 memories 是否已存在同 activity/topic 摘要
  → 不存在且事件类型属"经历类" → 事件 importance 提升一档（upsert 前判定，不改库中事件行）
幂等：沿用 materialized 标记机制（既有）
```

### 6.3 数据流

```text
world_events（V2.3 类型）→ to_memory_candidates（映射 + 首次判定）
  → memory_candidates(pending) → 既有评估 job → memories
  → 反思证据窗（既有聚合）→ insights（长期偏好，如"喜欢冬天"由多次天气-情绪记忆归纳）
```

## 12. Acceptance Criteria

**功能验收**

1. V2.3 各新类型事件的记忆候选摘要符合 §6.2 文案规则、溯源 payload（event_id 可查）。
2. "第一次"经历类事件 importance 提升一档且仅首次；第二次同活动不提升。
3. health ended（intensity≥3）→ 候选生成；intensity<3 或 dismiss 无感知类 → 不生成。
4. day_start/part_transition/普通 low 块完成 → 零候选（短期信息不落记忆）。

**数据验收**

5. memories/memory_candidates 结构零改动；类型仍属既有 7 类词表（不新增类型值）。
6. 同一事件重复桥接 → materialized 幂等，仅一候选。

**接口验收**

无新增接口。

**异常情况**

- 首次判定查询失败 → 保守按"非首次"处理（不提升），桥接照常。
- 摘要超 100 字 → 截断。

## 13. Testing Requirement

- **Unit Test**：映射矩阵（类型 × importance × 幂等）；首次判定边界（恰存在同摘要）。
- **Integration Test**：事件 → 候选 → 评估转正 → 证据窗可见全链（复用 memory2 job 测试设施）。
- **Scenario Test**：架构 §8.3 示例复刻——"第一次旅行"（travel 地点 location_change）入记忆；"今天天气"不入记忆；Flag off 时桥行为与 V8 现状一致。
