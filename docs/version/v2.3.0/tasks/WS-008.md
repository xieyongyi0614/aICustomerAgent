## 2. Goal

让"计划"变成"生活"：随 part_of_day 跃迁推进当日块状态（planned → active → completed / skipped），完成块发 life_event，块地点变化时经 MovementResolver 迁移 `worlds.current_location` 并发 location_change。世界因此拥有"她此刻在做什么、在哪里"的连续事实。

## 3. Background

WS-007 产出静态计划后，需要运行时把它推进成动态事实：决策 timing 要知道"她正忙"，主动话题要从"她今天做了什么"取材，WorldBrief 要报"她此刻在客厅阅读"。这些消费方都依赖块的实时状态与位置事实（P4 的 current_location 静止问题由此解决）。

## 4. Scope

- 扩展 `app/services/world/daily_plan.py`（或新增 `daily_plan_runner.py`，实现时按体量定）：`advance_daily_plan(user_id, now)`。
- world_engine 模拟维护步接入：part_transition 标记触发 + 每 tick 对账自愈。
- life_event / location_change 事件产出（type=life_event，payload.kind 区分 activity_done / location_change / block_skipped）。
- `v23_daily_life_enabled` 门控。

## 5. Non Scope

- 计划生成（WS-007）。
- 块事件的记忆沉淀与影响裁决（WS-015 / WS-011）。
- V9 自主移动动作（架构 Non-Goals）；用户叙事移动（V8 解释器既有路径）。

## 6. Technical Design

### 6.1 推进核心逻辑（`advance_daily_plan`）

```text
输入：当日计划（planned/active 行按 seq 排序）、世界当前时刻（minutes_of_day, part）
1. 过期闭合：status=active 且 end_minutes < now 的块 → completed
   （发 life_event kind=activity_done，importance 低；块为 user_influenced 或
     与用户相关话题 → importance=medium，使记忆桥可拾取）
2. 错过跳过：status=planned 且 end_minutes < now 且未激活 → skipped
   （发 life_event kind=block_skipped，importance=low）
3. 激活当前：now ∈ [start, end] 且 status=planned 的块 → active
4. 位置迁移：active 块 location_id != worlds.current_location
   → MovementResolver.apply(user_id, block.location_id, source="schedule",
                             reason=f"block:{activity}")
   （被叙事优先仲裁跳过时留 trace，不强推）
5. 返回推进摘要 {completed:[...], skipped:[...], activated, moved}
```

### 6.2 触发时机

- part_transition 标记存在的 tick：全量推进一次；
- 每 tick 对账：以时间窗（而非标记）重算一次，纠正漏触发（与 WS-004/007 的自愈哲学一致）。

### 6.3 数据流

```text
part_transition（WS-004）/ 每 tick 对账
  → advance_daily_plan → daily_plans 状态流转（单事务）
  → life_event / location_change（经 MovementResolver 与漏斗）
  → worlds.current_location 更新
  → 消费方：WorldBrief（WS-012）、决策 timing（WS-014）、state_engine（WS-016）、记忆（WS-015）
```

## 12. Acceptance Criteria

**功能验收**

1. 块到点激活、过点完成、跨过未激活即 skipped；状态流转不回退（completed 不可再变）。
2. 完成块发 life_event：普通块 importance=low，user_influenced 块 medium。
3. 块地点 != current_location 时触发移动；同 part 内用户叙事已移动 → 日程移动被仲裁跳过且 trace 可见。
4. part_transition 触发与每 tick 对账结果一致（双触发幂等）。

**数据验收**

5. 当日每个块终态恰一：planned（未来）/ active（当前）/ completed / skipped；无孤儿行。
6. location_change 事件与 worlds.current_location 一致；活动事件经 `_emit_simulation_events` 落库。

**接口验收**

无新增接口。

**异常情况**

- 当日计划缺失（WS-007 未跑）→ 推进步 no-op 并 trace，不报错。
- 移动校验失败（location 非法）→ 跳过移动、块照常 active，留 trace。

## 13. Testing Requirement

- **Unit Test**：状态机全转移矩阵（含非法回退拒绝）；时间窗边界（start/end 整点）；importance 分级。
- **Integration Test**：冻结时钟推进一日全流程；与 MovementResolver/事件漏斗联动。
- **Scenario Test**：一日六块日程模拟——激活/完成/跳过/移动序列正确；深夜（night 块）时 current_location=bedroom；Flag off 时零状态流转零事件。
