## 2. Goal

让角色在每轮对话中"知道世界此刻的状态"：WorldBriefAssembler 将时间/天气/当前日程块/活跃处境/显著事件合成 ≤400 字的 WorldBrief，合并进既有【当前世界】段（总闸开启时世界段预算 600→1000），前台链路只动 `world_engine.build_context` 与 `context_selector.render_world_section` 的内部。

## 3. Background

架构 §5.1：V8 WorldContext 回答"世界上有什么"，WorldBrief 补充"世界上正在发生什么"（含角色生活与用户处境）。这是 G2（角色有生活）在前台最直接的体感：她知道现在几点、自己在做什么、用户是否不舒服。

## 4. Scope

- 新增 `app/services/world/world_brief.py`：`build_world_brief(...) -> WorldBrief`（纯函数：text ≤ world_brief_char_budget + 结构化 parts）。
- 扩展 `app/services/world/context_selector.py`：`render_world_section` 增加可选 brief 参数（追加简报段；缺省 None 时输出与现状逐字节一致）。
- 扩展 `app/application/world_engine.py::build_context`：总闸开启时装配 brief 并传递（读取当日计划/活跃处境/显著事件）。
- 预算策略：`v23_world_simulation_enabled` 开 → 世界段预算用 `world_context_char_budget_v23`（1000），关闭 → 既有 600。

## 5. Non Scope

- brief 的消费扩展到决策/风格（WS-013/014/016 各自读结构化事实，不读 prompt 文本）。
- prompt 其它段（memory/goal/style）的任何改动。
- 世界段渲染格式的重排（既有行保持原顺序，brief 作为追加段）。

## 6. Technical Design

### 6.1 WorldBrief 结构

```text
WorldBrief = {
  text: str,                 # ≤400 字，渲染示例见 architecture §5.1
  parts: {
    time_line: "2026-09-14 周一 晚间（22:00）晴天",
    place_line: "她此刻在家·客厅，今天的晚间安排是阅读。",
    situations_line: "用户今天工作压力较大（下午检出）。" | None,
    events_line: "最近：…（≤2 条显著事件）" | None,
  }
}
```

**输入装配**（world_engine.build_context 内）：

- TimeContext（既有 build_time_context）+ worlds.environment.weather；
- 当日 active 块（WS-007 `get_current_block`；daily_life 关闭或缺计划 → place_line 退化为基础位置行）；
- active user_situations（event_detection 关闭 → situations_line=None）；
- 显著事件：active 且 importance≥medium 的 world_events 顶部 2 条（复用既有 salient 查询）。

### 6.2 渲染与预算

```text
render_world_section(ctx, budget, brief=None):
  既有渲染不变 → brief 存在时追加两行：time_line + place_line（+situations/events 有则追加）
  追加段计入世界段预算；超预算时先裁 events_line → situations_line（保留 time/place）
build_context：budget = world_context_char_budget_v23 if 总闸 else world_context_char_budget
```

### 6.3 数据流

```text
run_chat_pipeline 第 2 步 world_engine.build_context
  → [总闸] build_world_brief（读 plans/situations/events/weather）
  → render_world_section(ctx, budget, brief) → world_ctx 段
  → PromptBuilder（零改动，段文本即载体）→ answer_chain
```

## 12. Acceptance Criteria

**功能验收**

1. 全 Flag 开、组件齐备时：世界段出现时间行（日期/星期/part/天气）、位置+日程行、处境行、事件行，总长 ≤1000。
2. 优雅降级：无计划 → 无日程句；无处境 → 无处境句；无 weather_sim → 时间行天气位空缺；任一输入缺失不抛错。
3. 总闸关闭时：世界段输出与 V2.2.0 **逐字节一致**（含预算 600）。

**数据验收**

4. 装配只读：daily_plans/user_situations/worlds/world_events 零写。
5. brief.text ≤ world_brief_char_budget（400）。

**接口验收**

无新增接口。

**异常情况**

- daily_plan 查询异常 → brief 缺 place 日程部分，位置行仍输出。
- 预算超限裁剪顺序固定（events → situations），可复现。

## 13. Testing Requirement

- **Unit Test**：装配降级矩阵（各输入缺失组合）；裁剪顺序；text 预算断言。
- **Integration Test**：run_chat_pipeline 世界段快照——Flag off 对照 V2.2.0 逐字节一致；Flag on 对照 §6.1 形状。
- **Scenario Test**：晚间 + 在家阅读块 + 用户 work_pressure 处境 → 简报三行齐备且事实与库一致。
