## 2. Goal

把角色侧的重要节点转成世界事件：目标完成/失败 → `goal_completed`，高置信兴趣类 Insight → `interest_emerged`。世界事件流因此包含"角色自己身上发生的事"，供决策话题、记忆沉淀与未来叙事消费。

## 3. Background

架构 §5.4 三源事件中的角色事件目前缺失：目标完成只更新 goal 表，Insight 只进反思与 personality 编译——世界不知道"她刚完成了一个目标""她对摄影产生了兴趣"。桥接必须走既有 outbox（事务一致性惯例：域状态变更同事务登记事件），由 outbox_consumer 转译落 world_events。

## 4. Scope

- 新增 `app/services/world/event_bridge.py`：`register_goal_event(user_id, goal, outcome)` / `register_interest_event(user_id, insight)`（outbox 登记助手，同事务）。
- 扩展 goal 终态迁移点（goal_service/goal_observation 的 completed/abandoned 出口）：追加桥接调用（Flag 门控）。
- 扩展 insight_created 进程内 listener（main.py lifespan 注册处）：兴趣类 Insight 桥接（Flag 门控）。
- 扩展 `app/application/outbox_consumer.py`：新 outbox 事件类型 → world_events 转译（create_event 落库）。
- `v23_event_detection_enabled` 门控。

## 5. Non Scope

- 事件的影响裁决与候选生成（WS-011/013）。
- insight 内容判断的 LLM 化（用既有 confidence/scope/domain 字段做规则筛选）。
- goal 创建时机（goal_planning 的 origin=world_event 在 WS-014，方向相反）。

## 6. Technical Design

### 6.1 事件规范

| 桥接 | world_event | source | importance | payload | 幂等键 |
|---|---|---|---|---|---|
| goal completed | type=goal_completed | character | medium | {goal_id, domain, title≤50} | `char:goal_done:{goal_id}` |
| goal abandoned（失败） | type=goal_completed, payload.outcome="failed" | character | low | 同上+outcome | `char:goal_done:{goal_id}` |
| interest emerged | type=interest_emerged | character | medium | {insight_id, topic≤50, confidence} | `char:interest:{insight_id}` |

### 6.2 挂接点与转译

```text
goal_service/goal_observation 终态迁移（既有函数内，Flag 内追加）
  → event_bridge.register_goal_event → outbox_events 同事务登记
insight_created listener（main.py 既有注册处，追加一个 listener）
  → 规则筛选（scope 含 self/interest 且 confidence ≥ 阈值，常量定稿）
  → event_bridge.register_interest_event → outbox 登记
outbox_consumer.consume_pending
  → 新增类型映射：goal.completed / interest.emerged → world_engine.create_event 落库
```

**阈值常量**：兴趣筛选用 settings（`v23_interest_confidence_threshold: float = 0.7`，归入 WS-001 参数集——若 WS-001 已冻结则在本 Task 实施记录登记补参）。

### 6.3 数据流

```text
角色域状态变更 → outbox_events（同事务）→ outbox_consumer → world_events（唯一 SoT）
  → WS-011 影响裁决 → WS-013 escalation/候选 → WS-015 记忆沉淀
```

## 12. Acceptance Criteria

**功能验收**

1. 目标完成 → outbox 登记 → 消费后 world_events 出现 goal_completed（payload 溯源 goal_id）；abandoned 产出 outcome=failed 低重要度事件。
2. 高置信兴趣 Insight → interest_emerged 恰一条（幂等键防重）；低置信/非兴趣域 → 零事件。
3. 桥接失败（如 create_event 异常）不回滚角色域状态变更（outbox 重试语义）。

**数据验收**

4. outbox 行与 world_events 行一一对应（消费成功后既有已消费标记语义不变）。
5. goals/insights 表内容与 Flag off 时逐字段一致（桥接只读不写角色域）。

**接口验收**

无新增接口。

**异常情况**

- outbox 消费重复投递 → 幂等键查重兜底，world_events 不重复。
- listener 抛错 → 按既有 listener 异常隔离惯例处理，不影响 insight 主流程。

## 13. Testing Requirement

- **Unit Test**：登记助手字段/幂等键；兴趣筛选阈值边界（=0.7 命中）。
- **Integration Test**：goal 终态 → outbox → consumer → world_events 全链；insight listener 全链。
- **Scenario Test**：目标完成→事件→（联 WS-011 后）影响裁决可用；Flag off 时 goals/insights 行为零差异、outbox 零新增类型。
