## 2. Goal

为 V2.3.0 全部能力建立统一的开关与参数层：一个总闸、六个子闸、若干模拟参数，全部默认关闭/安全值，并接入既有 enablement 启用链校验。后续所有 Task 只从本 Task 定义的 settings 读取开关与阈值。

## 3. Background

架构规定 World Simulation 全程灰度（G7）：总闸 `v23_world_simulation_enabled` 关闭时系统与 V2.2.0 逐字节一致。项目既有惯例是每版本一组 `v2X_*` Flag + `enablement.py` 启用链校验（v22 四子闸要求总闸先开的模式已存在）。V2.3.0 组件多（时间/日程/事件/场景），必须先把开关与参数的"合同"定下来，避免各 Task 自行散落配置。

## 4. Scope

- 新增 `app/core/settings/world_simulation.py`：`WorldSimulationSettings(BaseSettings)`，含 7 个 Flag 与全部模拟参数（见 §6）。
- 按 settings 包既有组装方式并入全局 Settings（参照 `experience.py` 被引用的方式）。
- 扩展 `app/core/settings/enablement.py::enablement_violations`：新增 v23 子闸启用链校验（模式照抄 v22 段）。
- 单元测试：默认值、启用链、参数边界。

## 5. Non Scope

- 任何行为接线（维护步注册、组件实现——后续 Task）。
- 既有 `world_llm_assist_enabled`（V8 解释器辅助）的语义改动；V2.3 的 LLM 辅助闸是独立的 `v23_world_llm_assist_enabled`。
- `.env` 样例文档更新（可在 WS-019 收口时统一）。

## 6. Technical Design

**模块设计**：单文件 settings 模块 + enablement 校验扩展，无运行时逻辑。

**Flag 定义**（全部 `bool = False`）：

| Flag | 控制面 |
|---|---|
| `v23_world_simulation_enabled` | 总闸：维护步注册、WorldBrief、事件类型扩展 |
| `v23_time_advance_enabled` | TimeAdvancer / DayCycle / Weather / Calendar |
| `v23_daily_life_enabled` | Routine / DailyPlanBuilder / Runner |
| `v23_event_detection_enabled` | UserSituationTracker / CharacterEventBridge / EventImpact 接线 / escalation 白名单扩展 |
| `v23_scene_expansion_enabled` | SceneProfile 风格接入 / 地点扩展消费 |
| `v23_habit_time_enabled` | habit_triggers 时间条件维度 |
| `v23_world_llm_assist_enabled` | 处境提取 LLM 辅助 / 日程自然语言化 |

**参数定义**（默认值即安全值）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `world_sim_interval_seconds` | 60 | world_simulation 维护步节流间隔 |
| `sim_advance_max_minutes` | 120 | simulated 模式单 tick 推进上限（防补帧风暴） |
| `world_event_tick_cap` | 8 | 单 tick 单用户模拟事件上限（WS-017 消费） |
| `catch_up_max_days` | 7 | 长离线逐日折叠上限（WS-017 消费） |
| `world_brief_char_budget` | 400 | WorldBrief 字符预算（WS-012 消费） |
| `world_context_char_budget_v23` | 1000 | 总闸开启时世界段总预算（关闭时用既有 600） |
| `daily_plan_retention_days` | 30 | daily_plans 历史清理窗 |
| `user_situation_valid_hours` | 48 | 处境默认有效期（WS-009 消费） |
| `v23_part_boundaries_json` | `{"morning":360,"noon":690,"afternoon":840,"evening":1080,"night":1320}` | part_of_day 日内分钟边界（WS-004 消费） |
| `v23_llm_assist_sample_rate` | 0.2 | LLM 辅助采样率（WS-009 消费） |
| `v23_event_escalation_types` | `"user_condition,weather_change,calendar_event,goal_completed"` | 事件升级白名单扩展（WS-013 消费，csv） |

**启用链规则**（`enablement_violations` 新增，消息格式对齐 v22）：

1. 六个子闸任一开启而总闸关闭 → 违规（`{sub} 要求 v23_world_simulation_enabled（V2.3.0 总闸先开）`）。
2. `v23_daily_life_enabled` 开而 `v23_time_advance_enabled` 关 → 违规（日程依赖 day_start 标记）。
3. `v23_world_llm_assist_enabled` 开而 `v23_event_detection_enabled` 关 → 违规（辅助服务于处境检出）。

**数据流**：无运行时数据流；`validate_enablement_chain` 在既有调用点（启动校验）自动覆盖新规则。

## 11. Implementation Steps

- **Step 1**：新建 `world_simulation.py`，按 §6 定义全部 Flag 与参数（命名/默认值逐字对齐本表，禁止改名）。
- **Step 2**：并入全局 Settings；确认 `settings.v23_world_simulation_enabled` 等可访问。

- **Step 4**：编写 `tests/v23/test_ws001_settings.py`；跑通全套件确认零回归。

## 12. Acceptance Criteria

**功能验收**

1. `settings.v23_*` 七个 Flag 全部可访问且默认 `False`；全部参数可访问且等于 §6 默认值。
2. 启用链：单独开启任一子闸（无总闸）时 `enablement_violations` 返回对应违规项；`validate_enablement_chain` 抛错；总闸+子闸组合合法时零违规。

**数据验收**

不涉及数据库。

**接口验收**

无新增接口；`validate_enablement_chain` 既有调用点（启动）行为不变（默认配置零违规）。

**异常情况**

- 子闸依赖子闸（规则 2/3）的违规信息能明确指出缺失的前置闸。
- `.env` 传入未知 `v23_*` 变量不导致启动失败（BaseSettings 默认行为，不额外配置）。

## 13. Testing Requirement

- **Unit Test**：默认值断言；`enablement_violations` 对 7 个子闸 × 有/无总闸的矩阵；规则 2/3 组合；参数 JSON 字段可解析。
- **Integration Test**：应用启动路径下 `validate_enablement_chain(settings)` 默认零违规。
- **Scenario Test**：无（纯配置）。
