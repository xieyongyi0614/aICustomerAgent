## 2. Goal

在时间推进之上产生"时间边界事件"：day_start / part_of_day 跃迁 / day_close / week_boundary 四类标记，以 idempotency_key 幂等写入 world_events（source=time），成为天气演化（WS-005）、日程具象化（WS-007）、块推进（WS-008）、habit 时间条件（WS-016）等下游的统一触发源。

## 3. Background

时间要影响 Emotion/Habit/Autonomy，前提是"时间边界"本身成为可消费的世界事实。架构的解法是把 part_of_day 跃迁、日界、周界转成 world_events——下游不必各自比对时钟，只消费事件。V8 的 world_events 表已有 source/importance/payload 与状态机，本 Task 只扩展取值域并加防重发键写入路径。

## 4. Scope

- 新增 `app/services/world/day_cycle.py`（纯函数）：`compute_due_markers(...)` 标记计算。
- 扩展 `app/services/world/time_provider.py` 或 `day_cycle.py`：part_of_day 边界判定消费 `v23_part_boundaries_json`。
- 扩展 `app/application/world_engine.py`：`emit_time_markers`（幂等落库，查重 + `create_event` 扩展 `idempotency_key` 可选参数）与模拟事件统一落库漏斗 `_emit_simulation_events`（WS-017 的风暴上限挂点，本 Task 先实现漏斗本身，不设上限）。
- world_events 新类型取值 `time_marker`、source 取值 `time`（自由域扩展，无迁移）。

## 5. Non Scope

- season_change 标记与 calendar_event（WS-005）。
- 多日追赶折叠（WS-017；本 Task 只做单 tick 邻近区间的标记检测）。
- 任何标记的直接消费逻辑（下游 Task）。
- `world_llm_assist`（标记计算纯规则，永不 LLM）。

## 6. Technical Design

### 6.1 标记计算（纯函数）

```text
compute_due_markers(prev_ctx, curr_ctx, boundaries, fired_keys) -> list[TimeMarkerDraft]
```

- 输入：上一 tick TimeContext（由 world_simulation 步在进程内传递，重启丢失安全——幂等键兜底）、当前 TimeContext、part 边界（分钟）、已发标记键集合（查 world_events）。
- 规则：
  1. **日期变化**（prev.date != curr.date）→ 先发上一日 `day_close`，再发今日 `day_start`。
  2. **part 跃迁**（prev.part != curr.part 且同日）→ 发 `part_transition`（payload 含 from/to part）。
  3. **ISO 周变化** → 发 `week_boundary`。
  4. 首次观测（prev_ctx 为 None）→ 只发当日 `day_start`（避免冷启动标记风暴）。
- 跨多个 part 的跃迁（tick 滞后）只发"from → to"一条跃迁标记，中间 part 不补发（多日情况归 WS-017）。

### 6.2 标记规范

| 标记 | idempotency_key | importance | payload |
|---|---|---|---|
| day_start | `time:day_start:{YYYY-MM-DD}` | medium | {date, weekday, is_weekend} |
| part_transition | `time:part:{date}:{to_part}` | low | {from_part, to_part} |
| day_close | `time:day_close:{YYYY-MM-DD}` | low | {date} |
| week_boundary | `time:week:{ISO周键}` | low | {iso_week} |

全部：`type="time_marker"`、`source="time"`、status 直接 `completed`（瞬时事实，无需生命周期）。

### 6.3 幂等与漏斗

- `emit_time_markers`：对每个 draft 先查 `world_events.idempotency_key IN (...)`，已存在即跳过；再经 `_emit_simulation_events(user_id, drafts)` 统一落库（漏斗记录本 tick 已发模拟事件数，供 WS-017 实施上限）。
- `world_engine.create_event` 增加可选 `idempotency_key=None` 参数（默认 None 时行为与现状逐字节一致——Preserve 底线）。

### 6.4 数据流

```text
run_simulation_maintenance → advance_world_time（WS-003）
  → compute_due_markers（纯函数）
  → emit_time_markers（查重）→ _emit_simulation_events → world_events（type=time_marker）
  → 标记列表返回给维护步上下文，供 WS-005/007/008 在同一 tick 内消费
```

## 12. Acceptance Criteria

**功能验收**

1. 同日两次 tick：第二次不发任何重复标记（幂等键查重生效）。
2. 跨日 tick：先 day_close（昨日）后 day_start（今日），顺序与键正确。
3. part 跃迁标记 from/to 正确；跨两 part 的滞后 tick 只发一条跃迁。
4. 冷启动（无 prev_ctx）只发 day_start；week_boundary 按 ISO 周正确触发。

**数据验收**

5. world_events 新行：type=time_marker、source=time、status=completed、payload 符合 §6.2、idempotency_key 唯一。
6. 既有事件（提醒/角色动作）行零变化；`create_event` 不传幂等键时行为与现状一致。

**接口验收**

无新增接口；标记可经既有 `GET /debug/world/events` 查询。

**异常情况**

- 查重查询失败 → 本 tick 放弃发射（宁可漏发不可重发；下游以"当日存在 day_start 键"自愈，见 WS-007 Step 3）。
- 并发两个 tick 同时发射同键 → 部分唯一索引兜底，一胜一败且败方静默降级。

## 13. Testing Requirement

- **Unit Test**：跃迁矩阵（日界/part 界/周界/冷启动/跨多 part）、键格式、importance 映射。
- **Integration Test**：run_simulation_maintenance 端到端发射与幂等；与 WS-003 锚点联动。
- **Scenario Test**：模拟一天（冻结时钟快进）产生恰好的标记序列：day_start → 若干 part_transition → day_close；Flag off 时零标记产生。
