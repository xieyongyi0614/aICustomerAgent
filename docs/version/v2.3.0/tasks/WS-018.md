## 2. Goal

让验收与调参"看得见"：新增三个只读调试端点（模拟总览 / 当日计划 / 活跃处境），并在前端调试控制台新增"世界模拟"面板展示时间上下文、当前日程块、活跃处境与近期模拟事件。同时提供手动触发一次模拟维护步的调试入口（仅测试环境 Flag）。

## 3. Background

V2.3 的验收标准大量依赖"世界事实正确"（计划/处境/事件/简报），逐条查库效率低且不直观。既有 `api/v1/world.py` 已有 `/debug/world` 系列惯例，前端已有 `components/debug` 与 `src/api` 设施。本 Task 是 WS-019 人工回归的操作面板。

## 4. Scope

- `app/api/v1/world.py` 新增三个只读端点 + 一个调试触发端点（schemas 扩展）。
- 前端：`src/api` 新增 world-sim 请求函数（rest.ts 惯例）；`src/features/` 新增 world-sim 面板组件；挂入调试区（components/debug 既有挂载方式）。
- 端点全部受总闸门控（关闭时返回 enabled:false，不暴露内部错误）。

## 5. Non Scope

- 业务写接口（计划/处境的人工编辑——如需，未来版本以命令面形式设计）。
- 聊天主界面 / 普通用户可见 UI。
- 鉴权体系变更（沿用既有 debug 端点同等访问语义）。

## 6. Technical Design

### 6.1 端点设计

| Endpoint | Method | Request | Response |
|---|---|---|---|
| `/api/v1/debug/world/simulation` | GET | `?user_id=`（缺省默认用户，沿用 `_user` 惯例） | `{enabled, time_context, brief:{text,parts}, current_block, active_situations, recent_events:[≤10 条模拟事件], flags:{7 个 v23 开关值}}` |
| `/api/v1/debug/world/plan` | GET | `?user_id=&date=YYYY-MM-DD`（缺省今日） | `{enabled, date, blocks:[{seq,part,start_minutes,end_minutes,activity,location_id,variability_source,status,note}]}` |
| `/api/v1/debug/world/situations` | GET | `?user_id=&include_expired=false` | `{enabled, situations:[{dimension,summary,intensity,status,source,detected_at,valid_until,evidence}]}` |
| `/api/v1/debug/world/simulation/tick` | POST | `{user_id}` | `{enabled, result:{advanced_minutes, markers:[键], plan_summary, errors:[]}}`（手动执行一次 run_simulation_maintenance，受 `v23_debug_tick_enabled` 保护，默认 False，归入 WS-001 参数集补参） |

响应模型放 `app/api/v1/schemas.py`（追加，不改既有模型）。错误语义：user 无世界 → 404 语义体 `{detail}`；总闸关 → 200 + `enabled:false`。

### 6.2 前端面板

```text
src/api/world-sim.ts：getWorldSimulation / getWorldPlan / getWorldSituations / postWorldSimTick
  （rest.ts 惯例 + query-keys.ts 注册 query key）
src/features/world-sim/WorldSimPanel.tsx：
  ① 时间与天气行 + WorldBrief 全文
  ② 当日计划时间轴（块状态色标：planned/active/completed/skipped）
  ③ 活跃处境卡片（维度/强度/有效期/证据引文）
  ④ 近期模拟事件列表（type/importance/幂等键）
  ⑤ [手动 tick] 按钮（v23_debug_tick_enabled 时显示）
挂载：components/debug 既有调试区入口，路由/Tab 沿用 shell 现有模式
```

## 12. Acceptance Criteria

**功能验收**

1. 总闸开：三端点返回与库一致的数据（时间/part/块状态/处境/事件抽查一致）；brief.text 与 prompt 世界段同源。
2. 总闸关：三端点返回 `{"enabled": false}` 且不执行任何查询。
3. tick 端点：调试闸开时手动触发一次维护步并返回摘要；闸关时 403 语义返回。
4. 前端面板五块正确渲染；时间轴状态色标与 status 一一对应；无计划/无处境时空态文案。

**数据验收**

5. 端点全部只读（测试内断言相关表行数不变，tick 端点除外）。

**接口验收**

6. OpenAPI/响应模型与 §6.1 一致；既有 `/debug/world` 系列端点回归通过。

**异常情况**

- 非法 date / 未知 user → 4xx + detail，不暴露堆栈。
- 装配内部异常 → 端点 500 前降级为部分字段 null（观测面不因局部缺失整体失败）。

## 13. Testing Requirement

- **Unit Test**：schemas 序列化；门控三态（总闸/调试闸/日期参数）。
- **Integration Test**：端点 × 库数据一致性（夹具造数）；tick 端点执行摘要与 loop_runs 记录对应。
- **Scenario Test**：完整用户流程——造处境/计划/事件 → 面板可见 → 手动 tick 推进 → 面板状态更新；Flag off 面板空态与端点 enabled:false 一致。
