## 2. 阻断级问题（P0）详述

### P0-1 流式对话契约错配 —— 客户端永远收不到一个字

**现象**：`ChatEvent` union 建模正确、`switch` 穷尽检查正确、`tool_step` 字段对齐正确，**但事件判别子选错了**。

**证据（后端真实 wire，`apps/backend/app/api/v1/chat.py`）**：

| 行 | 实际产出 | 有 `type`？ |
|---|---|---|
| `:62` `:109` | `step.to_ndjson_dict()` → `{"type":"tool_step", ...}` | ✅ |
| `:65-90` | `{"type":"turn_meta", "role_mode": {**对象**}, "analysis": {**对象**}, ...}` | ✅ |
| `:92` | `{"delta": "..."}` | ❌ **无** |
| `:97` `:101` `:105` | `{"detail": ..., "error": ...}` | ❌ **无** |
| `:111-114` | `{"done": true, "session_id": ..., "turn_id": ...}` | ❌ **无** |

**证据（客户端解析，`apps/mobile/lib/core/network/events/chat_event_parser.dart:5,45-46`）**：

```dart
final type = json['type'] as String?;
switch (type) {
  ...
  default: throw FormatException('unregistered event type: $type');
```

**后果（三条全部致命）**：

1. `token` 行 → `type == null` → 抛 `FormatException` → `ndjson_parser.dart:23-24` 兜成 `ChatEvent.failure` → **正文永远不会渲染**；
2. `done` 行 → 同样失败 → `ChatStreamMonitor._done` 永不置位 → **每一轮都被标记为「断流」**；
3. `turn_meta` 行 → `json['role_mode'] as String?` 对 `Map` 转型 → `TypeError` → 同样兜成 `Failure` → **`memory_refs` 永远解析不到**，记忆提示条永久为空。

**旁证（测试把错的契约钉死了）**：`apps/mobile/test/core/ndjson_parser_test.dart:20-21` 断言的是 `{"type":"token", ...}` 与 `{"type":"done"}`——**这与后端实现相反**。测试全绿掩盖了真实链路全断。

> **任务书早就写明了真相**：`docs/version/v5.0.0/tasks/API-002.md:32` 明确记录「`token`（`{"delta": ...}`，**无 `type` 字段**）、`done`（`{"done": true, ...}`，**无 `type` 字段**）」。客户端实现者没有按这份契约写。

**修复方向**：客户端改为**按键存在性判别**（`delta` → token；`done` → done；`detail`/`error` → failure），或后端为三类事件补 `type`（后者会改既有 wire，需评估对 `apps/frontend` 调试台的影响）。**二者择一，必须冻结**。

### P0-2 鉴权：定义了但没有任何端点使用

**证据链（四环全断）**：

| 环 | 状态 | 证据 |
|---|---|---|
| ① 令牌签发 | 可用 | `auth.py:61-67` `/auth/pair` 返回 `issue_token(...)` |
| ② 令牌校验 | 可用 | `auth.py:44-58` `parse_token` + `current_user_id` |
| ③ **端点强制** | ❌ **零引用** | `grep -rn "current_user_id" app/api/v1/{home,insights,memory,tasks,brief,health}.py` → **空**；新端点全部用 `get_settings().default_user`（`home.py:69`、`memory.py:41`、`tasks.py:52`、`brief.py:41`） |
| ④ 客户端发送 | ❌ 用 Noop | `chat_stream_repository.dart:12-16` 默认 `NoopTokenReader()`；`chat_page.dart:205` `ChatStreamRepository()` **不传参** → 永远不发 `Authorization` |

**另外两个设计缺陷**：

- `/auth/pair` **本身无鉴权、无配对凭证**（不校验一次性配对码 / 不限制来源）→ 任何能访问该端点的客户端都能领到 30 天长期令牌（`auth.py:34-36`）。「设备绑定」只绑了名字，没绑信任。
- 令牌**无服务端记录、无法吊销**（纯 HMAC 自包含），30 天有效期到期前无法失效。

**影响**：`requirements-analysis.md` §3 冲突 7 描述的风险（「App 装到真机、连公网，等于把账本与记忆敞开」）**依然成立**。
