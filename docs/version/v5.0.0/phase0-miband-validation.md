## 2. P1 · 原生写入判定

### 2.1 判定口径

打开**系统健康应用** → 「数据来源 / 已连接的应用」列表 → **是否出现 Mi Fitness**。

| 结果 | 含义 | 对 M4 的影响 |
|---|---|---|
| ✅ **成立** | Mi Fitness 原生写入系统健康中枢 | 走主路径，M4 可启动 |
| ⚠️ **需用户手动开启** | Mi Fitness 内有「同步到健康平台」开关或引导，默认关 | **不等同未通过**——只需在 `APP-023` 加引导步骤 |
| ❌ **不成立** | 完全无写入、也无开关 | 触发 R1 降级（见 §7） |

### 2.2 结论

- **P1 结论**：`{{成立 / 需用户手动开启 / 不成立}}`
- **证据**：`phase0-evidence/P1-{{YYYY-MM-DD}}-datasource.png`（系统健康应用数据来源截图）
- **附加记录**：Mi Fitness 内是否存在「同步至健康平台 / 健康互联」显式开关 → `{{有 / 无}}`；开关默认值 → `{{开 / 关}}`

> ⚠️ **关键区分**：「开关默认关闭」与「完全不支持」对 M4 含义完全不同——前者只需引导，后者触发整段后置。此处判定错会直接导致排期误判。

### 2.3 已知干扰（测量期间必须规避）

- 官方 App 与 **Gadgetbridge 互斥**（抢连设备 / 清空未拉取数据，`F5[12]`）→ 测量期间**不得**同时安装或连接 Gadgetbridge。

## 8. 合规输入（若通过 · 交 `PLT-002` 承接）

> **[已由桌面调研锁定]** 以下为调研结论，本任务只记录为输入，不重复调研。

| 维度 | 硬约束 | 对策 |
|---|---|---|
| 敏感个人信息（PIPL） | 医疗健康信息 = 敏感 PI；须**单独同意**（独立勾选框，不可与其他条款合并）；PIPIA 留存 ≥ 3 年 | 首次开启健康同步时独立勾选同意（对位 `APP-021`) |
| 数据出境 | 敏感 PI 年累计 ≥ 1 万人 → CAC 安全评估；不足 1 万人 → 中国 SCC 备案 + PIPIA | 个人阶段默认境内 / 本机存储 |
| 长臂管辖 | 境外处理境内用户 PI **同样适用** PIPL | 服务器在海外也不能逃避 |
| 生成式 AI | 《暂行办法》：防沉迷、防「健康」歧视、内容标识、可能需行政许可 | 定位「生活方式教练」；显著免责；未成年人模式 |
| App Store | 禁「仅用设备传感器」测血压 / 血糖 / 血氧的宣称；须提示就医；精度方法论可披露 | 文案只用「趋势 / 参考」；固定「非医疗建议，请咨询医生」 |
| HealthKit | 禁广告 / 出售健康数据；**必须**提供隐私政策 | 不做健康数据广告变现 |
| 医疗边界 | Whoop 等同类产品自我限定为「安全网、非医疗建议」 | 复制该措辞模式 |

**未闭合（`PLT-002` 承接）**：中国 App 备案细则 / NMPA 是否把 LLM 健康解读打成 SaMD / Google Play 健康类政策 / 国内安卓商店健康类资质。
