# 朝夕 App · 免商店分发方案（个人主体 · 暂不上架国内商店）

> **上游**：`compliance/android-store-release-guide.md`（个人主体国内安卓商店上架指南：硬门槛 / 费用 / 素材 / 待补清单）、`compliance/plt002-notes.md`（PLT-002 未闭合调研结论）、`tasks.md` §7 `PLT-002` / `PLT-005`。
> **场景**：暂时不办软著、不上架国内应用商店，但要把 App（`朝夕`，包名 `com.zhaoxi.app`）交给他人下载使用。
> **口径**：各平台官方文档 + 2026-10 公开资料；外部结论标注来源，访问日期 **2026-10-08**；**平台规则以后台实时校验为准**。
> **不含代码与 DDL**；文中命令仅作操作说明，不新增脚本、不改 CI 配置。
> **费用与资质口径以上架指南为准**，本文只回答「不上架怎么给人用」。

---

## 1. 结论摘要

1. **自分发不需要软著，也不触发商店侧的备案核验** —— 软著是国内应用商店的准入件（上架指南 §1 / §2.2），不是分发本身的法律前提。
2. **但合规义务不因不上架而豁免**：生成式 AI 服务、AI 生成内容标识、隐私与个人信息保护的要求照旧适用（见 §6）。
3. **分发范围决定风险等级**：熟人 / 邀请制内测风险最低；**公开推广或收费会把风险等级抬高一个量级**（见 §8）。
4. 五类渠道各有取舍：**自有落地页 + APK 直链**最省事，**内测分发平台**最像成品，**IM / 网盘直传**最快，**海外商店**覆盖面最广，**Flutter Web** 免安装但工程当前仅有模板占位。
5. **不上架 = 失去商店自动更新**：版本告知、下载与安装引导必须自己承担（当前无「检查更新」实现，见 §7）。
6. **自分发的最佳定位是过渡**：软著（0 元自办）与 App 备案可并行先办，办成后随时切到上架路径（见 §9）。

## 2. 渠道对比矩阵（2026-10-08）

| 渠道 | 需软著 | 需 App 备案 | 现金成本 | 国内可访问性 | 更新体验 | 适用规模 |
|---|---|---|---|---|---|---|
| **A** 自有落地页 + APK 直链（海外免费托管：GitHub Releases / Cloudflare Pages） | 否 | 否 | 0 元（域名可选） | 良（GitHub 在国内偶发慢） | 手动：换链接 + 通知 | 任意 |
| **A'** 自有落地页 + APK 直链（国内云托管） | 否 | 否，但**下载页域名必须 ICP 备案**才能指向境内服务器 | 服务器 60–400 元/年起 + 域名 60–80 元/年 | 优 | 手动：换链接 + 通知 | 任意 |
| **B** 内测分发平台（Firebase App Distribution） | 否 | 否 | 0 元 | 需能访问 Google 服务 | 平台内邮件邀请 | 数十–数百人 |
| **B'** 国内内测分发平台（蒲公英 / fir.im 类） | 否 | ⬜ 以平台当期规则为准 | 0–数百元 | 优 | 平台内推送 + 二维码 | 数十–数千人 |
| **C** IM / 网盘直传（微信 / QQ / 飞书 / 网盘） | 否 | 否 | 0 元 | 优 | 差（靠群公告人工传达） | 数十人 |

| **D'** Google Play | 否 | 否 | 开发者账号一次性注册费约 25 美元 | 差（国内不可达） | 商店自动更新 | 公开（海外） |
| **E** Flutter Web（H5 免安装） | 否 | 否，但**境内托管域名需 ICP 备案** | 0–400 元/年起 | 优 | 刷新即最新 | 任意（体验受限） |
| **F** iOS（TestFlight / App Store） | 否 | 商店提审需 ICP 备案号（2023-09-30 起 Apple 中国大陆区规则） | TestFlight 需 Apple 开发者账号 99 美元/年 | 中 | 平台内 | TestFlight：邀请制 / App Store：公开 |

> **关于「需 App 备案」一列**：工信部 App 备案的核验义务主要落在**分发平台与网络接入服务提供者**两侧。自分发不经分发平台，但**后端仍跑在境内服务器 / 已备案域名上**，接入商侧是否要求为 App 单独备案，⬜ **需向所选接入商（阿里云 / 腾讯云等）确认**。为降低不确定性，小范围内测阶段可优先把后端与下载页放在**同一主体的境内部署**并按要求履行备案；若完全不希望触碰备案，则后端需落在境外（会引入数据出境与访问体验问题，见 §8 风险 5）。

## 3. 各渠道操作步骤

### 3.1 前置：先出一个可分发的包（所有渠道共用）

| # | 步骤 | 要点（含本项目现状） |
|---|---|---|
| 1 | 递增版本号 | `apps/mobile/pubspec.yaml:4` 的 `version: x.y.z+n` → `versionCode` 取 `n`，**每次分发必须递增**（`android/app/build.gradle.kts:31-32` 从 pubspec 读取） |
| 2 | 准备 `dart_defines/prod.json` | ⬜ **当前不存在**（`apps/mobile/dart_defines/` 只有 `dev.json`）。结构同 `dev.json`：`{"API_BASE_URL": "<正式后端地址含 /api/v1>", "APP_FLAVOR": "prod"}`；README §4 已约定「正式部署时新增 `prod.json`」 |
| 3 | 确认正式后端可达 | API 地址经 `--dart-define` 注入，**未注入时启动即崩**（`apps/mobile/lib/core/env/app_env.dart` fail-fast）；`API_BASE_URL` 必须带 `/api/v1` 前缀 |
| 4 | 出包（显式指定 ABI） | `flutter build apk --release --flavor prod --dart-define-from-file=dart_defines/prod.json --target-platform android-arm64`；或用 `--split-per-abi` 后只分发 `arm64-v8a`。**不可直接分发默认的 `flutter build apk` 产物**——若只含模拟器 ABI，真机启动即白屏闪退（`apps/mobile/README.md:117-119`） |
| 5 | 核对签名是正式签名 | `key.properties` 缺失时 release 会**静默回退 debug 签名**（`android/app/build.gradle.kts:60-67`）→ 用 `keytool -printcert -jarfile <apk>` 或 `apksigner verify --print-certs <apk>` 核对指纹；**签名不一致会导致用户之间无法覆盖升级** |
| 6 | 归档产物与元数据 | 命名 `zhaoxi-<versionName>+<versionCode>-prod.apk`；同批记录 `SHA256`、构建时间、提交号 |

### 3.2 渠道 A：自有落地页 + APK 直链（推荐首选）

1. **托管**：GitHub Releases（免费、自带版本记录与直链）或 Cloudflare Pages / Vercel / Netlify（免费静态页）。
2. **落地页必备要素**：应用名与图标、版本号与发布日期、安装包下载按钮、`SHA256` 校验值、安装步骤（见 §4）、隐私政策与用户协议链接、联系方式（邮箱）。
3. **分发**：把落地页短链生成二维码，配合群公告发放。
4. ⚠️ **微信 / QQ 内直接点 APK 链接会被拦截**：需按 §4 的话术引导「用浏览器打开」。
5. **不放在境内服务器时**：无需 ICP 备案；一旦改用境内云托管下载页，**域名必须 ICP 备案**。

### 3.3 渠道 B：内测分发平台

- **Firebase App Distribution**：免费，上传 APK 后按邮箱邀请测试者，可管理测试组；需要 Google 账号，国内网络可达性差。
- **国内内测平台（蒲公英 / fir.im 类）**：上传即得二维码与安装页，体验最接近成品商店；⬜ 平台的实名与内容审核规则随监管滚动，**上传前先确认当期规则**。
- **飞书内部分发**：本项目后端已有飞书通道（`apps/backend/app/api/v1/feishu*`），可在飞书群 / 云文档内直接发安装包与更新说明，适合已在使用飞书的群体。

### 3.4 渠道 C：IM / 网盘直传

- APK 可作为**文件**直接在微信 / QQ / 飞书里发送（不是链接），也可放网盘做定向分享。
- 优点：0 成本、即发即用；缺点：版本散落、无法追溯「谁装了哪版」。
- 缓解：统一产物命名 + 每次分发附一句版本号，群里保留「当前最新版本」置顶消息。

### 3.5 渠道 D：海外商店

- **Google Play**：需一次性注册开发者账号（约 25 美元）；需隐私政策 URL、数据安全表单，targetSdk 需满足当期要求；国内用户不可直接访问。
- **APKPure / Aptoide / Uptodown / Amazon Appstore / Samsung Galaxy Store**：免费上传，**均不要求中国软著**；国内用户需能访问站点。
- ⚠️ 一旦公开上架海外商店，等于**面向公众分发**，§6 / §8 的合规底线须按公开口径执行。

### 3.6 渠道 E：Flutter Web（H5 免安装）

- 工程已含 web 目标（`apps/mobile/.metadata:30-32`），但 `index.html` / `manifest.json` 仍是 Flutter 模板占位（`apps/mobile/web/index.html:32` 标题为 `mobile`、`apps/mobile/web/manifest.json:2-3` 名称为 `mobile`、主题色为模板蓝）→ **上线前必须补齐**（标题 / 描述 / 图标 / 主题色）。
- 部署：Cloudflare Pages / Vercel / Netlify（免费）或境内服务器（域名需 ICP 备案）。
- ⚠️ 两点限制：① 后端需放开 Web 端 **CORS**；② Web 端拿不到系统级健康数据与本地相册等原生能力，**只适合体验式试用**，不是完整替代。

### 3.7 渠道 F：iOS（仅作说明）

- **TestFlight**：需 Apple 开发者账号（99 美元/年），适合邀请制内测；⬜ 是否卡备案以 Apple 当期规则为准。
- **App Store（中国大陆区）**：自 2023-09-30 起 Apple 要求填写有效 **ICP 备案号**才能提审（多家媒体报道，访问日期 2026-10-08）→ 走这条路等于回到「先备案」。
- ⚠️ **不建议**走企业签名 / 超级签名等灰产渠道：随时失效、用户设备被吊销、且属监管明确打击对象。

## 4. 分发话术与安装引导

| 场景 | 用户看到什么 | 建议话术 / 处理 |
|---|---|---|
| 微信 / QQ 内点下载链接 | 提示「已停止访问该网页」或直接拦截 | 「点右上角 ··· → 在浏览器打开，再下载」 |
| 应用市场搜不到 | 搜索无结果 | 「朝夕尚未上架应用商店，请用我发的安装包（或落地页链接）」 |
| 未知来源安装被拦 | 提示「禁止安装未知应用」 | 「设置 → 应用（应用管理 / 应用与权限）→ 找到你用来打开安装包的 App（浏览器 / 文件管理）→ 允许安装未知应用」；各厂商路径略有差异，按机型提示走 |
| 安全检测警告 | 提示「该应用未经安全检测 / 可能有风险」 | 「选择『继续安装』；这是我本人开发的应用，未上架商店所以没有商店的签名背书」 |
| 安装后无法联网 / 闪退 | 后端不可达 | 确认拿的是 `prod` flavor 包体且正式后端可达；`dev` 包默认指向 `http://127.0.0.1:8020/api/v1`（`dart_defines/dev.json`），装到别人手机上必然不可用 |
| 打开是白屏闪退 | ABI 不匹配 | 确认分发的是**显式指定 ABI** 的产物（§3.1 第 4 步），不是默认 `flutter build apk` 的结果 |
| 需要更新 | 无商店自动更新 | 每次发新版同步发「新版本说明 + 新安装包」，并说明**同签名可直接覆盖安装**（无需卸载，数据保留） |

## 5. 版本与签名纪律

- `versionCode`（`pubspec.yaml` 的 `version: x.y.z+n` 中的 `n`）**必须单调递增**；同一包名 + 同一签名才能覆盖升级（上架指南 §9）。
- 签名文件 = 应用身份：`apps/mobile/android/zhaoxi-release.jks` 与 `key.properties` **不入库**（`apps/mobile/android/.gitignore:12-14`），丢失后**已分发用户无法覆盖升级，只能换包名重来** → 密码管理器 + 离线介质各一份。
- 出包后**必须核对签名指纹**（§3.1 第 5 步）：release 在 `key.properties` 缺失时会静默回退 debug 签名（`android/app/build.gradle.kts:60-67`）。
- 产物命名与归档：`zhaoxi-<versionName>+<versionCode>-<flavor>.apk` + `SHA256` + 构建时间 + 提交号。
- ⬜ **仓库当前无打包脚本**（`apps/mobile/tool/` 仅有 `gen_app_icons.py`），出包为手工命令 → 易漏 `--flavor prod` 与注入文件（缺口见 §7）。
- ⚠️ **引用避坑**：`apps/mobile/README.md:115` 与 `apps/mobile/docs/mobile-code-audit-2026-10.md:81` 仍写旧包名 `com.example.mobile`，**以 `android/app/build.gradle.kts:17,28`（`com.zhaoxi.app`，dev flavor 为 `com.zhaoxi.app.dev`）为准**。

## 6. 不上架状态下的合规底线（不豁免）

| # | 底线 | 现状（2026-10-08 只读核实） |
|---|---|---|

| 2 | **隐私政策 / 用户协议可点击可访问**，内容含 SDK 清单、数据出境说明、注销渠道 | ⬜ 现为不可点击文本（`agreement_check.dart:42-64`），且登录页默认勾选（`login_page.dart:21`） |

| 4 | **AI 生成内容显式标识** | ⬜ 未实现（现有 ✦ 视觉标签不等于标识办法要求的显式标识） |
| 5 | 健康「非医疗建议」常驻、相册「仅本机 / 不上传服务器」 | ✅ 已实现（`privacy_page.dart:50`、`album_cards.dart:23` 等） |
| 6 | 权限与功能对应、不索要无场景权限 | ✅ Manifest 9 项均对应功能（上架指南 附录 A） |
| 7 | 数据出境（天气源 open-meteo 为境外服务、LLM 链路）在隐私政策中如实披露 | ⬜ 待核查（上架指南 §2.3） |

> 自分发虽然不经商店审核，但**用户投诉 / 举报的路径依然存在**；上述 7 条属于法律义务，与是否上架无关。底线 1 / 2 / 3 / 4 是「先做才分发」的建议顺序。

> **底线 1 与自动更新的关系（2026-10-09 补充）**：自动检查更新属于「业务网络请求」，**不得**放在 `bootstrap()` 内。`APP-044` 的实现把触发点放在**首帧之后**的 `lib/app/update/update_gate.dart`；这样 `PLT-002` 落地首启同意弹窗后，弹窗天然排在自动检查之前，**更新域无需再改**。此约束已写入 `tasks/APP-044.md` §4.1.3（裁决 D2）并有静态断言（`bootstrap.dart` 内不得出现更新逻辑）。

## 8. 风险提示

| # | 风险 | 等级 | 说明 / 应对 |
|---|---|---|---|
| 1 | 公开推广后被认定为「面向境内公众提供生成式 AI 服务」 | **高** | 未完成算法备案 / 大模型备案或登记前，**不要公开推广、不要投渠道、不要收费**；维持邀请制内测 |
| 2 | 收费 / 广告变现 | **高** | 个人主体备案不得用于经营性活动；一旦变现需迁移企业主体并重新备案（上架指南 §2.1） |
| 3 | 安装包被二次打包 / 篡改 | 中 | 提供 `SHA256` 校验值；优先使用固定直链（GitHub Releases）而非临时网盘链接 |
| 4 | 签名文件丢失导致无法覆盖升级 | 中 | 双备份（§5）；归档 `.jks` 与口令 |
| 5 | 后端 / 下载页在境内但未备案，被接入商处置 | 中 | 自分发阶段可优先海外托管 + 独立下载页；后端的境内落地与备案见上架指南 §2.3 |
| 6 | iOS 用户装不上 | 中 | 明确告知仅提供 Android 包；iOS 需 TestFlight / App Store（开发者账号 99 美元/年），且中国大陆区上架需 ICP 备案号 |
| 7 | 用户装到 `dev` 包或非 arm64 产物导致白屏 / 连不上 | 中 | 按 §3.1 出包并在分发时标注包体类型；话术见 §4 |
