## 1. 结论摘要

个人主体**可以**上架国内安卓商店，但有 **4 个硬门槛**，缺一不可：

| # | 门槛 | 归属 | 周期 | 现金成本（官方） | 状态 |
|---|---|---|---|---|---|
| 1 | 中国 App 备案（工信部） | 主体资质 | 约 2–4 周 | **0 元** | ⬜ 未启动 |
| 2 | 软著（三选一，见 §2.2） | 主体资质 | 普通程序 30–60 个工作日 | **0 元**（自办） | ⬜ 未启动 |
| 3 | 境内服务器 + ICP 备案域名（隐私政策页可公网访问） | 部署 | 约 2 周 | 域名 60–80 元/年 + 服务器 60–400 元/年起 | ⬜ 待核查 |
| 4 | **AI 类**：算法/大模型备案材料（第三方 API → 供应商备案号 + 合作协议） | 合规 | 取决于供应商，1–6 个月 | **0 元**（代办 1 万–5 万元+） | ⬜ 未启动（**最大不确定项**） |

> 门槛 1~3 是所有商店的准入前置；门槛 4 只卡 AI 类应用，但本产品是 AI 对话形态，**必然被核验**。
>
> **门槛 2 的费用口径需澄清**：软著**官方登记自 2017-04-01 起已免费**，付费项只有代办、加急与第三方电子版权证书（依据与「300 元」来源拆解见 §2.2）；逐项费用见 §1.1。
>
> **门槛 1 的归属需精确**：工信部《关于开展移动互联网应用程序备案工作的通知》列出的申报材料为主办者证件、App 负责人身份证件与核验照片、App 基础信息（名称 / 图标 / 包名 / 域名 / SDK / 接入服务单位）与网络接入信息，**未把软著列为必需项**；但**商店侧强制要软著**，且接入商初审实操中常要求 App 权属材料——因此软著仍是事实上的前置件，**它不花钱，只花时间**（⬜ 本项目需向所选接入商确认权属材料口径）。
>
> **门槛 4 无捷径**：未完成算法备案 / 大模型备案或登记的生成式 AI 应用，主流商店一律不予上架；行业通行口径下，**只调用已备案第三方大模型 API 且不改动底层模型**的，一般按「大模型登记」办理，自研或深度微调的才需完整备案（⬜ 以网信办最新口径为准）。

|---|---|---|---|
| 全部自办（软著自办、备案自提） | **约 200–500 元/年**（域名 + 服务器） | 3–6 个月 | AI 类备案 |

### 1.2 不上架的替代路径（速览）

若暂时不上任何国内商店，仍有 5 类方式可把 App 交给他人使用——**自分发不需要软著，也不经商店的备案核验**（但合规义务不豁免）：

| 路径 | 一句话 |
|---|---|
| 自有落地页 + APK 直链 | 最省事：产物 + 一个可访问页面 + 二维码 |
| 内测分发平台 | 最像成品：上传即得邀请 / 二维码（Firebase App Distribution、国内平台） |
| IM / 网盘直传 | 最快：微信群 / 飞书群 / 网盘发文件 |
| 海外商店 | 面向公开用户的最短路径（APKPure / Aptoide / Google Play 等，均不认中国软著） |
| Flutter Web（H5 免安装） | 免安装试玩；工程已有 `web/` 目标但仍是模板占位 |

> 渠道对比矩阵、逐渠道操作步骤、安装引导话术、版本与签名纪律、合规底线与客户端配套缺口，见 `compliance/self-distribution-guide.md`。

## 2. 硬门槛明细

### 2.1 中国 App 备案

- 依据：工信部《关于开展移动互联网应用程序备案工作的通知》（2023-08）；**应用商店必须在上架前核验备案号**。
- 个人可办：身份证 + 实名手机号 + **已实名域名** + **境内服务器**（走阿里云 / 腾讯云等接入商通道）。
- 周期：接入商初审 1–3 工作日 + 管局终审 5–10 工作日；首次无备案档案时整体约 2–4 周。
- 产出：App 备案号 → 填入各商店后台 + **必须在 App 内公示**（"我的 / 关于"页）。
- 纪律：**备案主体必须与商店开发者实名主体完全一致**，不支持跨主体备案；个人备案不得用于经营性活动——若后续出现会员付费 / 广告变现，需迁移企业主体重新备案。

### 2.2 软著（三选一）

| 选项 | 性质 | 官方费用 | 周期 |
|---|---|---|---|
| 计算机软件著作权登记证书（软著） | 中国版权保护中心登记，个人可申请 | **0 元**（见下方口径） | 普通程序 30–60 个工作日 |
| APP 电子版权证书 | 第三方商业认证服务，vivo 等商店认可，常作软著下证前的临时替代 | 300–1500 元 | 当天–15 工作日 |
| 软件著作权认证证书 | 部分服务商提供 | 以服务商报价为准 | 15–30 工作日 |

**「软著要 300 元」与「官方免费」为什么冲突（2026-10-08 核实）**：

- **官方口径（免费）**：财政部《关于清理规范一批行政事业性收费有关政策的通知》（**财税〔2017〕20 号**）取消「软件著作权登记费」；中国版权保护中心 **2017-03-29** 发布《关于停征软件著作权登记缴费有关事项的通告》，**自 2017-04-01 起停止执收**，且不再发放缴费通知书。停征范围覆盖「软件著作权登记申请费（含申请例外交存手续费）」「软件著作权登记证书费」「软件著作权合同登记费」「变更或补充登记费」「软件源程序封存保管费」「查询费」共 6 类项目。来源：新华社 / 中国新闻出版广电报 2017-04-01 报道、中国版权保护中心官网通告（访问日期 2026-10-08）。
- **「300 元」的三种真实来源**（均非官费）：① **代办服务费** 300–1200 元（代写说明书、整理 60 页源码、跟进补正）；② 版权中心**加急费** 500–5000 元（普通程序免费，加急才收费）；③ 第三方《**APP 电子版权证书**》300–1500 元。
- **误传来源**：网络上大量「官费 300 元/件」的文章沿用 **2017 年 4 月 1 日之前**的旧收费标准（含部分法律问答类站点），与财税〔2017〕20 号冲突。
- **自办要付的是时间与材料**：需实名认证 + 申请表 + 说明书 + 源代码（通常前后各 30 页、共 60 页）；材料被要求补正会顺延周期。

**商店侧硬约束（vivo / iQOO，2026-10-08 核实）**：

| 约束 | 内容 | 依据 |
|---|---|---|
| 三选一强制 | 上架必须提交《计算机软件著作权登记证书》《APP 电子版权证书》或《软件著作权认证证书》之一 | vivo 审核常见问题（doc/62） |
| 一证一应用 | 同一份软著证书**不得在不同应用中使用** | 同上 |
| 名称一致 | **软著证书上的应用名称必须与上传的应用名称一致**（本产品：`朝夕`），一字不符直接驳回 | 同上 |
| 主体一致 | 上传主体与软著主体不一致时，需提交真实有效的授权证明（软著类可授权，金融类证照不可授权） | vivo 审核常见问题（doc/62 / doc/147） |
| 著作权人 | 著作权人 = 上架实名主体（本项目为个人） | 同上 |
| 造假后果 | 使用虚假、伪造、盗用的软著 / 营业执照等资质 → **永久冻结开发者账号** | vivo 开发者账号冻结与解封流程（doc/352） |

### 2.3 境内服务器与域名

- 后端 API + 隐私政策 / 用户协议落地页必须**境内、可公网访问、域名已 ICP 备案**（主体与 App 备案一致）。
- **待核查项（本项目）**：后端当前部署位置；天气源 `api.open-meteo.com` 为**境外服务**，链路为「客户端位置 → 后端 → 境外 API」，属位置信息出境场景，需在隐私政策中如实披露并评估必要性（可换境内天气源，或降级为手动选城市）。

### 2.4 AI 类特有门槛（决定能否上架）

- 依据：《生成式人工智能服务管理暂行办法》+ 各商店 AIGC 审核口径（小米等**强制核验算法备案**）。
- 两条路径：
  1. **自研模型** → 自行完成算法备案 + 大模型备案（周期长，个人主体难度高）；
  2. **调用第三方 API** → 提供**第三方的算法/大模型备案号 + 双方合作协议**（本产品走这条）。
- **备案与登记的区分（⬜ 以网信办最新口径为准）**：行业通行口径为——**只调用已备案的第三方大模型 API、不改动底层模型**的，一般按「**大模型登记**」办理（周期与材料显著轻于完整备案）；自研模型或基于第三方基座做预训练 / 深度微调后对外提供服务的，才需完整**大模型备案**（省级网信办初审 + 国家网信办终审，1–6 个月）。**无论走哪条，未备案一律不予上架**。
- **商店侧核验方式**：商店会核验所使用生成式 AI 服务的备案信息与合作协议（小米等口径更严），并要求在商店后台 / 应用内公示已备案的生成式 AI 服务信息。
- **本项目现状**：后端 `LLM_PROFILES_JSON` 可配多 profile，默认 profile 为 `longcat`（OpenAI 兼容端点）→ 上架前需向供应商索取**备案号 + 合作协议**；并在商店后台 / 应用内公示所使用已备案的生成式 AI 服务信息（国家网信办定期公告已备案清单，2025-12 累计 748 款服务 / 435 款应用登记）。
- 《人工智能生成合成内容标识办法》（2025-09-01 施行）：AI 生成的文本/图片须有**显式标识**（用户可明显感知的"AI 生成"提示）+ **隐式标识**（文件元数据）→ 对话与 AI 结论区需要落地标识（客户端待补，见 §7）。

### 3.1 个人开发者通道新变化（2026-09-16，⬜ 待核实）

- **事件**：2026-09-16 vivo 开发者大会宣布**应用商店开放个人开发者通道**——个人**仅需实名认证**即可申请入驻，官方将「有序开放 AI 应用、蓝河应用、IoT 应用」类目（来源：IT之家对 2026 vivo 开发者大会的报道及多家转载，访问日期 2026-10-08）。
- **对本项目的意义**：本产品正是 AI 应用形态；若该通道已对个人开放 AI 类目，则「个人主体能否提交」这一历史上最大的疑虑直接消失。
- ⬜ **提交前必须核实的 3 件事**（以 vivo 开放平台后台实况 / 工单答复为准）：
  1. 个人通道的 **AI 应用类目**当前是否对本产品开放，是否需排队、申请或名额限制；
  2. 个人主体提交是否**接受《APP 电子版权证书》**（三选一中的第三方证书），是否额外要求补充材料；
  3. AI 类材料的提交形式：第三方 LLM 备案号 + 合作协议的具体要求（本产品默认 profile 为 `longcat`）。
- ⚠️ **口径正在滚动的证据**：vivo 平台的《蓝河应用审核规范》（doc/698，2026-09-08）当时仍写「本平台暂不接受个人开发者注册账号和上传蓝河应用」——说明个人通道是 2026-09 新增、规则滚动更新中。**不要用旧文档结论判断能否提交**，以工单答复为准。

## 8. 隐私合规红线（高分拒审原因，逐条自查）

1. 首启无隐私弹窗，或不同意就闪退之外还强制索取权限；
2. 用户未同意前 SDK 已初始化 / 已发网络请求；
3. 权限申请无场景说明，或一次索要全部权限；
4. 无账号注销通道（或只有"联系客服"）；
5. 定向推送 / 个性推荐无关闭开关；
6. 隐私政策缺 SDK 清单、缺数据出境说明、缺收集目的；
7. 权限与功能不符（如后台持续定位）；
8. 医疗 / 金融宣称（本项目红线：健康"非医疗建议"、记账不涉资金）；
9. AI 生成内容无显式标识；
10. 截图含示例假数据 / 其他品牌手机边框 / 状态栏通知图标。

> **本项目补充自查项（2026-10-08 核实）**：隐私政策 / 用户协议必须是**可点击、可访问**的页面（现状为不可点击文本），且登录页**不得默认勾选**同意（现状 `apps/mobile/lib/features/profile/presentation/login_page.dart:21` 默认为 `true`）。

## 9. 渠道与版本管理

- **渠道号**：各商店需要区分渠道包（用于数据归因）；本项目当前**无多渠道配置**（仅 `dev` / `prod` 两个 flavor）→ 上架前需补渠道方案（商店自动嵌入 或 新增 flavor）。
- **版本号**：`pubspec.yaml` 的 `version: x.y.z+n` → `versionName` / `versionCode`；**versionCode 必须单调递增**，同一包名 + 同一签名才能覆盖升级。
- **首发建议顺序**：vivo/iQOO（用户点名渠道）与小华为先发（审核口径明确），过审后再铺其余渠道——避免同一版被多家同时驳回时反复改包。
- **不上架（自分发）时的同一套纪律**：`versionCode` 单调递增 + 同一包名 + 同一签名才能覆盖升级；签名文件与口令双备份，丢失后**已分发用户无法覆盖升级，只能换包名重来**；出包须显式指定 ABI（`--target-platform android-arm64` 或 `--split-per-abi`），否则产物可能只含模拟器 ABI，真机启动即白屏闪退（`apps/mobile/README.md:117-119`）。详见 `compliance/self-distribution-guide.md` §5。
