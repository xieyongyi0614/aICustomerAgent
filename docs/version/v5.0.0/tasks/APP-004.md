## 2. Background

### 2.1 现状：无任何本地存储层，且三套介质的分工必须先定死

| 事实 | 证据 |
|---|---|
| `flutter_secure_storage` 是**安全硬缺口**的补齐项——Dio 不存凭据；**Drift 与 `shared_preferences` 都是明文，禁止存令牌** | `flutter-architecture.md:84` |
| 令牌方案已裁决：设备绑定 + 长期令牌，存 `flutter_secure_storage` | `requirements-analysis.md:373`（决策 D3） |
| 客户端缓存**只存服务端 DTO 投影，不做本地业务逻辑**，以降低与后端 Schema 演进的耦合 | `flutter-architecture.md:23`、`:414` |
| `shared_preferences` 的定位是**非敏感偏好**（主动关怀开关、上次会话）；用 Drift 存这类键值属过度设计 | `flutter-architecture.md:93` |
| 缓存与离线策略已按数据类分档 | `flutter-architecture.md:367-378` |
| **V1 明确不做 Offline-first 的写路径**；写失败进重试队列，UI 明示「待同步」 | `requirements-analysis.md:398`；`flutter-architecture.md:375`、`:378` |
| 非功能需求首次定义：可离线查看范围、令牌存储、日志脱敏 | `requirements-analysis.md:221-222`（缺口 13） |
| 金额展示**必须标注数据时间** | `flutter-architecture.md:373` |
| 记忆页口径：只展示 **active 且未 forgotten** 的条目 | `requirements-analysis.md:375`（决策 D5） |
| 反范围：不做把跨域合成逻辑放到客户端 | `requirements-analysis.md:394` |

**结论**：仓库中**不存在** Flutter 侧存储层。本任务要一次性把「什么数据进哪个介质」定死——这是安全与合规的前置，也是后续所有 `features/*/data` 的公共契约。

### 2.2 为什么必须做

1. **令牌落错介质 = 安全事故**：`shared_preferences` 与 drift 都是明文（`flutter-architecture.md:84`）。若令牌进了任一个，等于把账本与记忆的访问权明文落盘。
2. **缓存策略决定冷启动体验**：读缓存是为了冷启动体验（`flutter-architecture.md:378`），首页 / 会话 / 记忆 / 账本四类都要有；没有统一存储层，各域会各自实现、各自漂移。
3. **写路径的反范围必须被结构性地锁死**：V1 不做离线写（`requirements-analysis.md:398`）。若不在此任务把「重试队列只做持久化与状态，不做执行」写清楚，后续 `APP-016` 记账页很可能顺手把离线写做出来。
4. **它是 `APP-003` 的依赖**：令牌注入拦截器需要一个「令牌读取接口」，该接口的实现落在本任务。

### 2.3 在 V5.0.0 中的位置

关键路径旁路（非最长链，但为 M0 必交付）：`flutter-architecture.md:429` 的开工顺序第 ⑥ 步。它是 `APP-009`（会话历史）、`APP-017`（记忆缓存）、`APP-016`（账本缓存）、`APP-014`（首页骨架）、`APP-019`（通知偏好）、`APP-021`（清空同步）的共同依赖。

## 3. Scope

### 3.1 In Scope

1. **`flutter_secure_storage` 封装**：令牌写入 / 读取 / 删除；提供 `APP-003` 的令牌读取接口实现。
2. **drift schema 与迁移**：四类只读缓存表（会话历史 / 记忆列表 / 账本汇总与账单 / 首页聚合），`schemaVersion` 与迁移策略。
3. **只读缓存读写**：进页先渲染缓存再刷新；写入以服务端 DTO 投影为准。
4. **缓存时间戳**：每条 / 每张缓存带数据时间，供金额等场景标注数据时间。
5. **`shared_preferences` 偏好存储**：主动关怀设定时刻、上次会话等**非敏感**键。
6. **重试队列持久化**：写操作失败的记录持久化 + 状态枚举（**不实现执行**）。
7. **清空联动**：`一键清空`（`/life/data`）后同步清除本地缓存与令牌以外的本地残留。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不做 Offline-first 写路径**（不排队后自动重放、不本地先行写） | 反范围明确不做（`requirements-analysis.md:398`；`flutter-architecture.md:378`）。V1 只做「失败入队 + UI 明示待同步」 |
| 2 | **不在本地做业务逻辑**（不聚合、不排序、不计算环比、不做衰减） | 客户端缓存只存投影（`flutter-architecture.md:23`、`:414`）；跨域合成必须在服务端（`requirements-analysis.md:394`） |
| 3 | 不实现通知调度 | 属 `APP-019`（`tasks.md:183`）。本任务只提供偏好读写 |
| 4 | 不实现鉴权与令牌签发 | 属 `API-001`（`tasks.md:127`）。本任务只做**存储与读取** |
| 5 | 不做加载 / 空态 / 错误 / 骨架四态组件 | 属 `APP-008`（`tasks.md:113`） |
| 6 | 不做导出 / 清空的 UI 交互 | 属 `APP-021`（`tasks.md:185`）。本任务只提供**清空的本地联动能力** |

## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 三存储介质分工契约

| 介质 | 存什么 | **绝不存什么** | 依据 |
|---|---|---|---|
| `flutter_secure_storage`（Keychain / Keystore） | 长期令牌、设备标识等凭据 | 业务数据（体积大且无需硬件保护） | `flutter-architecture.md:84`、`:376` |
| **drift**（SQLite） | **服务端 DTO 投影**：会话历史 / 记忆列表 / 账本汇总与账单 / 首页聚合 | **令牌**（明文）；本地推导字段；跨域合成结果 | `flutter-architecture.md:23`、`:367-374` |
| `shared_preferences` | **非敏感偏好**：主动关怀设定时刻、上次会话、上次同步时间 | **令牌**；任何金额 / 健康数值 | `flutter-architecture.md:93` |

#### 4.1.2 令牌存储契约

| 项 | 契约 |
|---|---|
| 介质 | `flutter_secure_storage`（iOS Keychain / Android Keystore） |
| 键名 | 单一键（不在文档中写死具体字符串，实现时集中定义于 `core/storage`） |
| 写入时机 | `API-001` 设备配对成功后 |
| 读取方 | 仅 `APP-003` 的令牌注入拦截器（经本任务提供的读取接口） |
| 删除时机 | 重新配对、用户主动退出、`一键清空` 联动 |
| **禁止** | 令牌值不得进日志（`tasks.md:216`）、不得进 drift、不得进 prefs、不得进崩溃上报 |

#### 4.1.3 drift 缓存表契约（只存投影）

| 缓存域 | 表内容（服务端 DTO 投影字段） | 数据时间戳 | 策略 | 落点 |
|---|---|---|---|---|
| 会话历史 | 会话 id、消息 id、角色、正文、事件时间 | 是 | 只读缓存；进页先渲染缓存再刷新 | `features/chat/data` |
| 记忆列表 | 记忆 id、类型（`kind`）、标签、内容、来源摘要、`last_updated`、用途回执 | 是 | 只读缓存；**只含 active 且未 forgotten 的条目** | `features/memory/data` |
| 账本汇总 / 账单 | 汇总金额字段（**服务端已格式化文本 + 原值**）、环比、账单行（含 `source` 录入方式） | 是 | 只读缓存；**金额展示必须标注数据时间** | `features/ledger/data` |
| 首页聚合 | 服务端 `home/summary` 返回的整块区块投影 | 是 | 只读缓存（冷启动骨架 → 数据） | `features/home/data` |

**硬约束**：
1. 每个字段**必须**能追溯到服务端 DTO 的某个字段；**不得**新增本地推导字段（如「本地计算的环比」「本地排序权重」）。
2. 每张表**必须**带数据时间戳；UI 展示金额 / 健康类数据时以此标注「数据时间」。
3. 记忆缓存只含 **active 且未 forgotten** 条目（对齐决策 D5，`requirements-analysis.md:375`），避免「服务端已忘、本地还在」。
4. drift 的生成物后缀为 **`.drift.dart`**，且**表定义文件内不得同时出现 Freezed 模型或 Riverpod provider**（承接 `APP-001` 的三生成器隔离契约，`flutter-architecture.md:113-117`）。

#### 4.1.4 `shared_preferences` 偏好键契约

| 键用途 | 值形态 | 是否敏感 | 备注 |
|---|---|---|---|
| 主动关怀 · 早间设定时刻 | **参数类**：时刻值 | 否 | 存**设定时刻**，不存功能开关位（见 §4.2 D7） |
| 主动关怀 · 晚间设定时刻 | 参数类：时刻值 | 否 | 同上 |
| 上次会话 id | 标识 | 否 | 冷启动恢复上次会话 |
| 上次同步时间 | 时间戳 | 否 | 与缓存时间戳配合展示 |

**硬约束**：键名集中定义（不散落字符串字面量）；**不得**存 `*_enabled` 形态的功能位；**不得**存金额 / 健康数值 / 记忆正文。

#### 4.1.5 缓存读写与失效契约

| 场景 | 契约 |
|---|---|
| 进页读 | **先渲染缓存，再发起刷新**；缓存为空走空态（不阻塞刷新） |
| 写缓存 | 仅在收到服务端成功响应后写；**写失败不写缓存** |
| 失效 | 以服务端响应为准**整体覆盖**该域缓存（不做端上 diff / 合并，避免本地逻辑） |
| 时间戳 | 每次成功写入刷新数据时间；UI 可据此标注「数据时间」 |
| 清空 | `/life/data` 成功返回后，**同步清除**全部缓存表 + 偏好键（令牌按 §4.1.2 处理） |
| 版本升级 | 服务端 DTO 字段变更 → 客户端提升 drift `schemaVersion` 并走迁移；**不做字段猜测式兼容** |

#### 4.1.6 重试队列持久化契约（**V1 只持久化与展示，不执行**）

| 项 | 契约 |
|---|---|
| 入队时机 | 写操作（记账 / 勾选任务等）失败 |
| 队列内容 | 操作类型、目标端点、请求参数、失败时间、失败原因分类（复用 `APP-003` 错误模型） |
| 状态枚举 | `pending`（待同步）/ `failed`（需人工处理）/ `discarded` |
| UI 契约 | 相关页面必须**明示「待同步」**，不得静默丢失（`flutter-architecture.md:375`） |
| **V1 禁止** | **不自动重放**、不做本地先行写、不做冲突合并 |

来源：`flutter-architecture.md:375`；`requirements-analysis.md:398`。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| **D1** | **drift 缓存表只存服务端 DTO 投影，不存本地推导字段** | 后端 Schema 会演进；端上若做推导（环比、排序权重、聚合），每次后端变更都会让端上逻辑失配（`flutter-architecture.md:414`）。投影策略把耦合面压到最小 |
| **D2** | **V1 不做 Offline-first 写路径**：失败只入队 + UI 明示「待同步」，**不自动重放** | 反范围已明确（`requirements-analysis.md:398`）。离线写会引入冲突解决、幂等、顺序一致性三类复杂度，与「记账成本趋近于零」的 V1 目标不成比例 |
| **D3** | **令牌介质 = `flutter_secure_storage`（Keychain / Keystore）** | 决策 D3（`requirements-analysis.md:373`）。Dio 不存凭据；drift 与 `shared_preferences` 都是明文（`flutter-architecture.md:84`） |
| **D4** | **令牌、金额、健康数值**三者**一律不进** drift / prefs / 日志 | 令牌是凭据（D3）；金额与健康数值是**敏感个人信息**（`requirements-analysis.md:187` 敏感 PI 口径）+ 日志禁打（`tasks.md:216`）。三者都不该落在明文介质里 |
| **D5** | **不在本地做任何业务逻辑**（不聚合 / 不排序 / 不计算 / 不做衰减） | 跨域合成必须在服务端（`requirements-analysis.md:394`）；衰减与上限机制不向用户暴露（D5，`requirements-analysis.md:375`） |
| **D6** | **每张缓存表必带数据时间戳；金额展示必须标注数据时间** | `flutter-architecture.md:373` 明确要求。缓存数字若不带时间，用户会把旧数据当实时数据 |
| **D7** | **主动关怀偏好存「设定时刻」参数值，不存 `*_enabled` 功能位** | 全局约束 2 禁 `*_enabled` 形态（`README.md:92`）；`API-008` 也要求偏好落库为**非开关形态**（`tasks.md:181`）。「未设定时刻」即等价于关闭，语义更简单 |
| **D8** | **记忆缓存只含 active 且未 forgotten 的条目** | 对齐决策 D5 与 `APP-017` 口径（`requirements-analysis.md:375`）。否则会出现「已遗忘的记忆在离线缓存里复活」 |
| **D9** | **缓存失效采用「服务端响应整体覆盖」，不做端上 diff / 合并** | 端上合并就是本地业务逻辑（违反 D5），且会产生服务端无法复现的状态 |
| **D10** | **drift 迁移走 `schemaVersion` 单调递增 + 迁移用例**；不依赖「删库重建」 | 删库重建会让用户丢失离线可读的会话历史，且掩盖迁移缺陷 |
| **D11** | **清空（`/life/data`）必须联动清除本地缓存与偏好** | 否则「服务端已清空、本地仍可读」，是合规风险（`requirements-analysis.md:131` 的同类问题：误导性陈述） |
| **D12** | **不新增依赖、不引入第二套本地库** | `flutter-architecture.md:152` 已否决 `isar` / `hive`；依赖清单由 `APP-001` 冻结 |

### 4.3 数据流

```text
【读路径（冷启动优先缓存）】
  features/*/data（repository）
    → core/storage/cache（drift DAO）
         ├── 命中 → 立刻返回缓存（带数据时间戳）→ UI 渲染骨架/旧数据
         └── 未命中 → 返回空
    → core/network（APP-003）请求服务端
         → 成功 → 整体覆盖该域缓存（D9）→ 刷新数据时间戳 → UI 更新
         → 失败 → 保留缓存，按 APP-008 错误态处理

【令牌路径】
  API-001 配对成功
    → core/storage/secure（flutter_secure_storage）写入令牌
  core/network 令牌注入拦截器（APP-003）
    → core/storage/secure 读取令牌（本任务实现该读取接口）
    → 注入请求头（令牌值不落日志）

【写路径（V1 不做离线写）】
  用户操作（记账 / 勾选任务）
    → core/network 写请求
         ├── 成功 → 覆盖相关缓存 → 正常反馈
         └── 失败 → core/storage/retry_queue 入队（状态 pending）
                    → 相关页面明示「待同步」
                    → （V1 到此为止：不自动重放）

【清空路径】
  APP-021 触发 /life/data
    → 成功 → core/storage 清除全部缓存表 + 偏好键 + 令牌 → UI 回到初始态
```

### 4.4 依赖与边界

- **允许依赖**：`APP-001` 工程骨架；`drift` / `drift_dev` / `sqlite3_flutter_libs` / `flutter_secure_storage` / `shared_preferences`（均在 20 项清单内）。
- **禁止依赖**：
  - `lib/features/**`（`core/` 不得 import `features/`）；
  - `lib/design_system/**`（存储层零 UI）；
  - `apps/backend/**` 内部结构；
  - `isar` / `hive` 等第二套本地库。

```bash
cd apps/mobile

# 2) 生成物一致性（drift 后缀隔离）

git diff --stat -- apps/mobile/pubspec.yaml apps/mobile/pubspec.lock

git add apps/mobile/lib/core/storage \
```
