## 3. Scope

### 3.1 In Scope

1. `car_add_page.dart`：照 B13 的 7 段（返回 → 类型横滑 → 金额区 → 表单行 → AI 提示条 → 联动说明 → 保存）。
2. 路由 `/car/add`（`chromeImmersive`）。
3. **类型 → 表单字段映射**（§4.1），含 `mileage` 的**无金额**分支。
4. 联动口径用服务端 `hint`；加载失败时用**兜底文案**（仍强调不重复记账），不出现空白。
5. 幂等：一次保存固定 `idempotency_key`（≥8 位），重试复用。
6. 保存成功 `pop(true)`，返回 35 页。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | 里程之外的非费用项扩展（如"年检"作为类型） | 设计稿定型六类型（`pages/36:104-111`）；新增类型会牵动 `API-019` 映射表 |
| 2 | 保养项目的**细项拆分**（机油/机滤分项计价） | 设计稿为单行金额（`pages/39:175` ¥200）；细项属后续 |
| 3 | 充电站选择器（`pages/36:120` 的「可跳转选择」） | 无站点库数据源（后端零命中）；本期为**文本输入**，选择器列后续 |
| 4 | 单价自动换算的**推算逻辑**（`pages/36:119` 的「单价自动换算 ¥0.99/kWh」） | 需历史均价口径（`API-019` §3.2 #4）；本期只在服务端给出真实可得时展示，否则不展示 |
| 5 | 照片 / 票据上传 | 无设计要求；且会引入相机权限面 |
| 6 | 端上离线草稿 | 复用会引入已死 drift 通道（`progress-audit` §7.6） |

## 4. Technical Design Requirements

### 4.1 页面契约

| # | 段 | 组件 | 内容 |
|---|---|---|---|
| 1 | 返回 | `BackLink` | 「‹ 车辆」 |
| 2 | 类型横滑 | **`TypeScroll`（A35）** | 充电（默认选中）/ 加油 / 里程 / 停车 / 过路 / 保养 |
| 3 | 金额区 | `LedgerAmount`（A32） | 「本次金额」；**`mileage` 类型时整段不渲染** |
| 4 | 表单行 | `LedgerFormRows`（A32） | 随类型切换（下表） |
| 5 | AI 提示条 | `AiCard` 单行变体 | 服务端可得时下发（如谷电单价对比）；不可得时**只保留通用提示**，不编造数字 |
| 6 | 联动说明 | `PrivacyNote` 变体 | 服务端 `hint`；兜底文案固定强调「不用重复记」 |
| 7 | 保存 | `LedgerSaveButton`（A32） | 「保存记录」；`mileage` 时文案为「保存里程」 |

**类型 → 表单字段映射**：

| 类型 | 表单行 | 必填 |
|---|---|---|
| `charge` | 充电度数（kWh，含单价换算辅助值，仅在可得时）/ 充电站 / 当前里程 / 时间 / 备注 | 金额、度数 |
| `fuel` | 油量或单价（可选）/ 加油站 / 当前里程 / 时间 / 备注 | 金额 |
| `mileage` | 本次里程（必填）/ 总里程（= 档案 `odometer_km` + 本次，只读展示）/ 时间 / 备注 | 本次里程 |
| `parking` | 地点 / 时间 / 备注 | 金额 |
| `toll` | 路段（可选）/ 时间 / 备注 | 金额 |
| `service` | 保养项目（必填）/ 门店 / 当前里程 / 下次里程（可选）/ 时间 / 备注 | 金额、项目 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **`mileage` 类型不渲染金额区** | `API-019` §4.2 裁决 2：里程不是费用；渲染金额框会诱导用户填 0 并产生 0 元账目 |
| 2 | **联动口径文案以服务端 `hint` 为准**，端上只做兜底 | `API-020` §4.2 裁决 4；同一句话出现在 36 与 39 两处，端上各写一遍会分叉 |
| 3 | **AI 提示条不得编造单价 / 对比数字** | `APP-014` 红线；不可得时收缩为不含数字的通用提示 |
| 4 | **`service` 类型走双写**（账目 + 档案回链） | `API-019` §4.1；页面无需感知，但保存后返回 35 应能看到账目与记录同时出现 |
| 5 | 保存按钮在请求中禁用 + 固定幂等键 | 同 `APP-027` §4.2 裁决 4 |
| 6 | 充电站为文本输入（选择器列后续） | 无站点数据源（§3.2 #3）；做成假选择器即假交互 |

### 4.3 数据流

```text
进入 /car/add
  → （可选）fetchProfile()            GET /car/profile        # 总里程基线用于 mileage 的只读展示
切换类型
  → 表单字段集切换（纯本地）
保存
  → repository.createEntry(kind, amount_minor?, occurred_at, note?, odometer_km?, kwh?, place?, idempotency_key)
      POST /car/entries
      → {entry_id?, record_id?, category_name, odometer_delta_km?, hint}
  → pop(true)
返回 35 页
  → car_page 重新 fetchOverview() → 支出与最近记录更新
```
