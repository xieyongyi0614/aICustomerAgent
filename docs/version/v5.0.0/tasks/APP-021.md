### 2.2 为什么必须做

1. **它是上架合规的硬前置。** 健康信息属 PIPL 敏感个人信息，**必须单独同意**（`requirements-analysis.md:132`、`:187`）；「本地优先」若被理解为「数据不出设备」而实际上传服务端，属**误导性陈述**，App Store 与国内安卓商店审核均会关注（`requirements-analysis.md:132`；风险 R6，`tasks.md:271`）。
2. **它是「用户控制权」承诺的兑现面。** 决策 D2 把口径从「物理位置」改为「控制权」（`:372`）；本任务是该口径在客户端的唯一落地面——没有本页，承诺只停留在文案。
3. **它是两个治理端点的唯一消费方。** `/life/export` 与 `/life/data` 是**服务端**端点（`governance.py:40`、`:62`），客户端若「自行删本地就宣称已清空」，将与服务端实际状态脱节（决策 D5，`:375`）——本任务必须把「以服务端返回为准」写成契约与 AC。
4. **它承载「授权可回收 → 降级而非报错」这条可判定规则。** 与三宫格「空态 + 引导授权」同源（`tasks.md:166`）；不做降级，回收授权会让页面直接报错或空白。

### 2.3 在 V5.0.0 中的位置

M3 客户端第 5 个任务（`tasks.md:185`），**P0 合规硬项**。它只依赖 `APP-004`（存储与凭据），是 `APP-020`（我的页「数据授权 / 隐私设置」行）的跳转目标，与 `APP-017`（记忆页一键清空）共享「服务端删除 + 二次确认」口径，并把**健康专项同意流程**与**隐私政策 / 上架合规**分别让渡给 `APP-025` 与 `PLT-002`。

## 3. Scope

### 3.1 In Scope

1. **页面结构与文案契约**（§4.1.1）：授权范围组 → 单独同意组 → 治理操作组 → `A25` 隐私说明，逐段照组件规格。
2. **数据授权范围管理契约**（§4.1.2）：可读数据范围列表（记账 / 记忆 / 任务）+ 每项可回收。
3. **单独同意（健康数据）契约**（§4.1.3）：**独立成项**，状态独立于其他数据域。
4. **导出契约**（§4.1.4）：`GET /life/export`（json / csv）+ 端侧保存 / 分享；**不写日志**。
5. **一键清空契约**（§4.1.5）：`DELETE /life/data?confirm=true` + **二次确认** + **以服务端返回为准**。
6. **授权回收降级契约**（§4.1.6）：回收后对应模块**降级而非报错**。
7. **文案契约**（§4.1.7）：按 D2 改写 + 红线 8（医疗免责 / 禁医疗级宣称）。
8. **边界契约**（§4.1.8）：与 `APP-025`（健康专项同意流程）、`PLT-002`（隐私政策 / 上架合规）的职责切分。
9. **红线自检**（§7.3）：无硬编码色值 / 无「本地优先」/ 无医疗级措辞 / 无 `*_enabled`。

| 🚨 **以服务端为准** | **客户端不得自行删除本地数据后就宣称「已清空」**；成功判定 = 服务端返回 `total` / `per_domain`；`failed_domains` **非空**时须提示**部分失败**，**不得**宣称「已全部清空」 | 本任务裁决 ⑤；决策 D5（`requirements-analysis.md:375`） |
| 清空后 | 刷新各域，条目**不再出现**（与 `APP-017` 同款一致性要求） | `APP-017.md:175` |
| 与 `APP-017` 边界 | `APP-017` 的「一键清空」是**记忆页入口**；本任务是**隐私治理页入口**，两者**同一端点、同一二次确认口径**，不得各写一套 | `APP-017.md:173` |

#### 4.1.6 授权回收降级契约（★ 可判定）

| 项 | 契约 |
|---|---|
| 语义 | 用户回收某域授权（关闭 `scope_*`）→ 该域**停止读取**，对应模块走**降级态** |
| 降级表现 | **降级而非报错**：相关模块显示**空态 + 引导重新授权**（不留白、不用假数据），**不得**抛出错误页 / 500 提示 | 依据「降级而非报错」既有裁决模式（`tasks.md:166`；`requirements-analysis.md:119`） |
| 记忆域 | 回收记忆授权 → 记忆相关卡片降级（不展示具体记忆内容），入口保留 |
| 健康域 | 回收健康授权 → 三宫格 / 健康页走空态 + 引导（与 `APP-014` / `APP-023` 同款） |
| 恢复 | 重新开启授权 → 立即恢复读取（不必重启 App） |
| 判定 | 「回收 → 降级不报错」是**可判定**规则，须有可执行用例（§7.2） |

### 4.3 数据流

```text
我的页「数据授权 / 隐私设置」行（APP-020）
   → 路由 #profile/privacy → features/profile/privacy/presentation/privacy_page
        → features/profile/privacy/data/privacy_repository（L3：presentation 不得直调 dio）
             · 授权范围态 ← core/storage（shared_preferences：scope_ledger / scope_memory / scope_task）
             · 健康授权态 ← 平台权限（Health Connect / HealthKit，APP-023）
             · 导出 → GET /life/export?format=json|csv（governance.py:40）
             · 清空 → DELETE /life/data?confirm=true（governance.py:62）
        → Riverpod provider
        → 渲染：标题 → A26 授权范围组 → A26 单独同意组(健康) → A26 治理操作组
                → A25 隐私说明(D2 全文) → 健康轻量免责

用户回收授权（A27 关）
   → 写 scope_* = false → 对应域停止读取 → 模块降级（空态 + 引导，不报错）

用户导出
   → GET /life/export → 落盘 / 分享（标注 generated_at；内容禁写日志）

用户清空
   → 二次确认（明示不可逆）
   → DELETE /life/data?confirm=true
   → 以服务端 DeletionReportOut 为准：
        failed_domains 为空 → 提示已清空
        failed_domains 非空 → 提示部分失败（不得宣称「已全部清空」）

装配红线：
   ✗ 健康同意并入总同意（D1）        ✗ 清空无二次确认（D2）
   ✗ 出现「本地优先 / 本地可见」（D3）  ✗ 回收后报错 / 空白（D4）
   ✗ 本地删后宣称已清空（D5）         ✗ 实现 APP-025 同意页 / PLT-002 文本（D7/D8）
```
