**结论**：后端**已经能检索到本轮引用的记忆**（`retriever.py`），但**没有把「引用了哪几条」下发到产品级事件面**。客户端因此无法渲染记忆提示条——`APP-009` 的 `A11 mem-hint` 整条无数据来源（`tasks.md:137`）。

### 2.2 为什么必须做

1. **「记忆可见」是五条设计原则之一，且是核心护城河。** `principles.md:13` 把「记忆可见」列为可判定验收规则：「每条记忆**必须**同时有『来源追溯』与（可用的）『用途回执』」。对话页的记忆提示条是这条原则在**对话链路**上的唯一落点（`traceability.md:43`）。
2. **它是 `APP-009` 的硬依赖。** `tasks.md:137` 明确 `APP-009` 依赖 `API-003`；`tasks.md:129` 的验收口径第①条即「无记忆引用时字段缺省」。
3. **它是 M1「对话闭环」的组成件。** M1 目标是「跑通『说一句话 → 看到 AI 逐字回复 → 看到 AI 做事的过程』」（`tasks.md:121`），而「AI 记着你的什么」是对话页区别于普通聊天页的三个特征之一（`components.md:315`「不是普通聊天页」）。
4. **它必须做成「契约扩展」而不是「新接口」。** `turn_meta` 已经是每轮对话的元信息载体，记忆引用是**同一轮次的元信息**，塞进新接口会让端上多一次请求、且无法保证与回复同轮对齐。

### 2.3 在 V5.0.0 中的位置

`tasks.md` §3.1 的第三个后端任务，无依赖、可**立即并行开工**（与 API-001 / API-002 并列）。它位于 `API-003 → APP-009`（对话页装配）这条边上；`APP-009` 的 M1 交付面含「长期记忆调用提示条（数据来自 `API-003`）」（`tasks.md:137`）。

## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 `memory_refs` 字段契约

追加进 `turn_meta` 的 `payload`（装配点 `chat.py:55-77`，事件源 `chat_pipeline.py:691-702`）：

| 字段 | 类型 | 必填 | 语义 | 缺省 |
|---|---|---|---|---|
| `memory_refs` | `array<object>` | **否** | 本轮对话**实际引用**的长期记忆摘要列表 | **键缺省**（无引用时**不出现该键**，§4.1.2） |

`memory_refs` 元素（`MemoryRef`）字段：

| 字段 | 类型 | 必填 | 取值来源 | 语义 |
|---|---|---|---|---|
| `id` | `string` | 是 | `UserMemory.id`（`models/memory.py:30`） | 记忆标识；端上用于去重与后续跳转 |
| `kind` | `string` | 是 | `UserMemory.type`（`MemoryType` 九值，`models/memory.py:6-16`） | 记忆类型 token，**原值透传、不归一**；端上提示条不按它分组，仅备后续用途（如按类型上色） |
| `label` | `string` | 是 | 由 `UserMemory.content`（`models/memory.py:34`）生成的**短摘要** | 端上提示条拼接展示，如「旅行偏好 · 预算习惯 · 作息」（`components.md:114`） |

**数量契约**：`memory_refs` 的条数 = **本轮实际参与生成的记忆条目数**（即检索结果中被真正注入本轮上下文的那部分）。本任务**不引入新的条数上限设置**；端上若需截断展示，属 `APP-009` 的展示层职责（`tasks.md:137` 的文案示例为 3 条，端上按实际条数渲染）。

#### 4.1.2 缺省语义契约（**本任务的核心红线**）

| 场景 | 契约 | 理由 |
|---|---|---|
| 本轮**无**记忆引用 | `memory_refs` **键缺省**（`turn_meta` payload 中不存在该键） | 端上须能区分「没有记忆被调用」与「有记忆但列表为空」；空数组会让端上误判为后者，进而渲染出「0 条记忆」这类错误提示条（`tasks.md:129`） |
| 本轮**有**记忆引用 | `memory_refs` 为**非空数组** | 契约保证「键存在 ⇒ 至少一条」 |
| 端上判定口径 | `memory_refs` 键缺失 → **整条提示条不渲染**（`APP-009`） | 与 `APP-003.md:201`（D11）的解析层约定同源：解析层必须把「缺省」与「空数组」区分开 |

**推论（可判定）**：本任务的实现**禁止**出现 `memory_refs: []`。任何「无引用」分支都必须走**不写键**，而不是写空数组。

#### 4.1.3 `label` 摘要口径契约

| 项 | 契约 |
|---|---|
| 生成来源 | **仅**由 `UserMemory.content` 截取，**不得**由 LLM 另行生成（避免逐轮 LLM 开销与不确定性） |
| 长度上限 | **冻结为 12 个字符**（中文按字符计）——理由是 `A11 mem-hint` 一行内需容纳「本轮对话已调用 N 条长期记忆：」+ 最多 3 条 `label`（`components.md:114`），单条 `label` 超过 12 字即溢出；此值为**展示约束**，非产品承诺 |
| 截断规则 | 超出上限时**截断 + 省略号**（`…`），**不**做语义改写、**不**做摘要生成 |
| 空内容 | `content` 为空或纯空白 → 该条**不进** `memory_refs`（不得产出 `label: ""`） |
| 字符集 | 原样保留 `content` 的字符（不转义、不替换） |

> **说明**：`12 字` 是**契约参数**（展示约束），不是新增设置项——它写在契约里、由实现常量承载，**不得**做成 `*_enabled` 形态或可配置项（裁决 9）。

#### 4.1.4 键序契约同步

`turn_meta` 的键序被 parity 测试断言为**契约序的子序列**（允许按值缺席，**不允许乱序**）：

| 项 | 契约 |
|---|---|
| 契约位置 | `apps/backend/tests/e2e/test_foreground_cutover_parity.py:129-138`（`TURN_META_ORDER`） |
| 断言点 | `:220-221`（`_is_subsequence(tuple(_meta(on)), TURN_META_ORDER)`） |
| 本任务处置 | `memory_refs` **追加至键序末尾**（在 `mode` 之后），并**同批**更新 `TURN_META_ORDER`——属**契约追加**（同批登记），非私改 |
| 追加理由 | `memory_refs` 是**按值决定是否下发**的键（无引用时缺省），与 `current_goal` / `action_intent` 同款；子序列断言天然允许其缺席 |
| 其它受影响测试 | `tests/e2e/test_turn_meta_stream.py`（首事件形状）、`tests/e2e/test_six_stage_loop_parity.py`（流形状）；两者**不得**出现新增失败 |

#### 4.1.5 登记契约（`runtime_*` 与键集）

| 项 | 契约 |
|---|---|
| `runtime_*` 字段 | 本任务**预期零新增**（`memory_refs` 是事件字段，不是设置字段）。若实现中确需新增，须登记 `apps/backend/tests/v30/runtime_support.py::V30_RUNTIME_FIELDS`（`:10-24`） |
| `turn_meta` 键集 | 变更须同步 §4.1.4 的 `TURN_META_ORDER`；**不涉及** `EXPECTED_EVENT_TYPES`（本任务**不新增事件类型**，`turn_meta` 已登记） |
| `loop_runs.steps` | **零触碰**（`test_agent_loop_core.py` 键集钉测） |

#### 4.1.6 字段禁令

| 禁止出现在 `memory_refs` 中的内容 | 理由 |
|---|---|
| 记忆正文**全文**（`content` 原值） | 提示条只需短标签；下发全文等于把用户记忆原文灌进每轮流事件，扩大日志与抓包暴露面（`tasks.md:216` 日志禁打记忆正文） |
| 向量 / `embedding` | 内部实现细节；无端上用途 |
| 检索分数（`semantic` / `structured` / `affinity` / `score`）与 `penalty_reason` | 那是 `_item_digest` 的 debug 面（`retriever.py:376-384`）；产品级事件不得携带（同 `API-002` §4.1.1 的字段禁令纪律） |
| `salience` / `decay` / 上限相关字段 | 决策 D5：上限与衰减不向用户暴露（`requirements-analysis.md:375`） |
| `user_id` / `character_id` | 单用户模型下无意义；且属身份字段，不进事件面 |

### 4.2 关键裁决与铁律留痕

#### 4.2.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | `memory_refs` 挂在 **`turn_meta`**，**不新建端点** | 记忆引用是**同一轮次**的元信息，须与回复同轮对齐；新建端点会让端上多一次请求且无法保证轮次一致（§2.2 第 4 条） |

| D4 | `kind` **原值透传** `MemoryType`，**不做分组归一** | 归一属记忆页（`APP-017` / `API-007`）口径；本任务透传即可，端上提示条不按类型分组（`components.md:114`） |
| D5 | `memory_refs` 追加至**键序末尾**，同批登记 `TURN_META_ORDER` | 键序是契约（`test_foreground_cutover_parity.py:220-221`）；追加属**契约追加**（同批登记），非私改 |
| D6 | **不新增事件类型** | `turn_meta` 已在 `EXPECTED_EVENT_TYPES` 面内；本任务是字段扩展（`tasks.md:129` 标题即「契约扩展」） |
| D7 | **零 DB 写**、不改 `retriever.py` 检索语义 | 本任务只做**观测出口**；改检索会波及记忆域钉测（`tasks.md:98` 铁律） |
