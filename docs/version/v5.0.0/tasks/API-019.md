## 2. Background

| 账户解析 | `service.py:122`（`resolve_account_id(user_id, account_id=None)`）；`:130`（`ensure_user_bootstrap`，含 `ensure_default_account` 与 `ensure_seed_categories` `:134-139`） |

| 既有交通子项（须纳入口径） | `app/character/asuna/ledger_categories.py:12-13`：`交通/加油`（别名含「洗车」「充电桩」）、`交通/停车` |

| 治理留痕 | `service.py:61-70`：`created` 时才 `record_provenance`（`domain="ledger"`） |

**为什么必须做**：`pages/35-car.html:155-161` 的四条子类目支出与 `pages/36-car-add.html:131-134` / `pages/39-car-profile.html:188-191` 的「同时计入记账养车分类，不用重复记」是**同一件事的两面**：既要求"记一次"，又要求"两边都对"。如果 car 域自存金额，必然分叉。

**为什么不能端上聚合**：`traceability.md:312` 的评审纪律要求跨域合成在服务端；端上聚合会让车辆页与账本页各持一套口径（`requirements-analysis.md` §7 反范围 #2「不做把跨域合成逻辑放到客户端」）。

## 3. Scope

### 3.1 In Scope

1. `app/services/car/entries.py`：
   - `record_car_expense(user_id, *, kind, amount_minor, occurred_at, …)` → 经 `record_entry` 落账，分类解析为**养车子项**（未命中时走 `normalize` 兜底并返回归类结果）。
   - 保养类型额外写 `car_service_records` 并回填 `ledger_entry_id`（`API-018` 表）。
2. `app/services/car/aggregate.py`：
   - `car_expense_breakdown(user_id, period)` → 按子类目聚合（口径见 §4.2 裁决 1）。
   - `car_recent_records(user_id, limit)` → 最近记录（费用行来自记账域 + 里程行来自 car 域，**统一成一种视图**）。
3. 幂等：入账 `idempotency_key` 由调用方提供（≥8 位，`app/services/action/capabilities/ledger.py:50`）。
4. 单位纪律：金额一律**整数分**（`app/models/ledger.py:69`）。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | **在 car 域新增任何金额存储** | 决策 D12；会让账目分叉 |
| 2 | 改造记账域的 `normalize` / `list_categories` / `record_entry` 语义 | 属既有域行为，改动会波及既有回归面（`tasks.md` §0.2 前提二「后端只许新增」） |
| 3 | **把「交通/加油」「交通/停车」迁移到养车树** | 迁移会影响既有用户数据与既有归类用例；改由本任务在**读侧**做显式映射（§4.2 裁决 1） |
| 4 | 电耗 / 百公里电耗的**精确算法**（含充电度数换算） | 设计稿只给当前值（`pages/35:151`）；精确电耗需完整充电记录（度数 + 里程增量），本期以「充电费用 + 里程增量」近似并在响应中标注口径；精算列 V2 |
| 5 | 油车专属口径（油耗） | 设计稿为电车向（`components.md:608`「电车优先」）；油车的「加油」仅作为录入类型存在 |
| 6 | 养车预算 / 目标 | 无设计诉求 |
| 7 | 跨月趋势 / 图表数据 | 35 页无趋势图 |

## 4. Technical Design Requirements

### 4.1 契约（服务层函数）

| 函数 | 入参 | 出参 |
|---|---|---|
| `record_car_expense` | `user_id`, `kind ∈ {charge, fuel, mileage, parking, toll, service}`, `amount_minor`（`mileage` 允许 0 或缺省 → 只写里程不落账）, `occurred_at`, `note?`, `odometer_km?`, `place?`, `idempotency_key` | `{entry_id?, service_record_id?, category_id, category_name, normalized_from}` |
| `car_expense_breakdown` | `user_id`, `period` | `[{category_id, category_name, net_minor, count}]`（按 `net_minor` 降序；仅含**有值的项**，无值的子类目不返 0 行） |
| `car_recent_records` | `user_id`, `limit ≤ 50` | `[{kind, title, subtitle, net_minor \| null, odometer_delta_km \| null, occurred_at, source, ledger_entry_id?}]` |

**类型 → 分类映射（§4.2 裁决 1）**：

| kind | 落账分类 | 备注 |
|---|---|---|
| `charge` | `养车/充电` | 费用 |
| `fuel` | `养车/加油费` | 费用 |
| `parking` | `养车/停车费` | 费用 |
| `toll` | `养车/过路` | 费用 |
| `service` | `养车/保养` | **双写**：账目 + `car_service_records` |
| `mileage` | —（**不落账**） | 只写 `car_mileage_logs`；`amount_minor` 忽略 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **养车支出口径 = 养车子树 ∪ `交通/加油` ∪ `交通/停车`，映射表写在 `services/car/aggregate.py`，记账域零改动** | 决策 D15 已在 `tasks.md` §15.4 声明「聚合在服务端完成」；D15 同时禁止迁移既有节点（会影响既有用户数据）。映射表**必须在代码里显式列出并带用例**，避免"隐式包含" |
| 2 | **`mileage` 不落账** | 里程不是费用（`pages/35:186` 的里程行显示 `38 km` 而非金额）；落账会产生 0 元账目污染账本 |
| 3 | **保养双写但金额单源**：先 `record_entry` 拿到 `entry.id`，再写 `car_service_records.ledger_entry_id` 与金额 | 单向回链保证"改一处不分叉"；反向（先写档案再记账）会在记账失败时留下孤儿档案行 |
| 4 | **聚合在服务端** | `requirements-analysis.md` §7 反范围 #2；且端上聚合会让车辆页与账本页口径分叉 |
| 5 | **无值子类目不返 0 行** | 35 页是"支出构成"（`pages/35:155-161` 四条都有值）；返 0 行会渲染出空条 |
| 6 | **电耗口径显式标注** | 本期以「充电费用 + 里程增量」近似（`pages/35:150-152`），响应中带口径标记；不宣称精确电耗 |
| 7 | **入账失败不留半成品** | 保养双写的两步若第二步失败，需回滚或标记重试；**不得**留下"有账目无档案"的静默不一致（`API-018` §4.2 裁决 5 的配套） |

### 4.3 数据流

```text
36 页「保存记录」（kind=charge, 42.00）
  API-020 → car.entries.record_car_expense
    → ledger.category.normalize(user, "充电")     → 养车/充电
    → ledger.resolve_account_id(user)              # service.py:122
    → ledger.service.record_entry(LedgerEntryDraft(...), idempotency_key=...)   # service.py:40
         → record_provenance(domain="ledger")      # service.py:62
    → {entry_id, category_name: "充电"}

36 页「保存记录」（kind=service, 200.00）
  → record_entry(...)                              → entry_id
  → car_service_records.insert(..., ledger_entry_id=entry_id, amount_minor=20000)
  → {entry_id, service_record_id}

35 页「本月养车支出」
  API-020 → car.aggregate.car_expense_breakdown(user, month)
    → ledger.query 取本月 entries（by_category 单层）
    → 用映射表把 category_id 折叠到 养车子项口径      # 养车子树 ∪ 交通/加油 ∪ 交通/停车
    → 按 net_minor 降序，剔除 0 值
```
