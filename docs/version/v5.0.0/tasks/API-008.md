**实际后果**：设计原则第四条「**主动但克制**——主动出现永远有固定节奏与关闭开关，绝不打扰」目前**没有服务端内容源**：`#briefing` 只能渲染端上写死的假文案，而端上写死文案违反「文案不自创」纪律（`tasks/README.md:63`）。

### 2.2 为什么必须做

1. **它是「主动但克制」的唯一内容底座。** 决策 D4 已定「V1 用本地通知 + **服务端预生成简报内容**」（`requirements-analysis.md:377`）——端侧只投递不生成（`APP-019` §4.1.1），故内容**必须**由本任务产出。
2. **`APP-018` 的晚间形态**被本任务**硬阻塞**：三处逐字文案（晚间主标题 / Orb 回顾解读 / 第四张回顾卡）明确要求在此冻结（`APP-018` §4.1.2）。
3. **「未完成任务由 AI 重新排期而非催促」是语气规则 5 的落地**（`principles.md:74`；`design:323`）——它需要一个**服务端给出的 `rescheduled_to` + 文案**，端上不得自创。
4. **风险点是「持久化载体」**：简报是**结构化四卡**，而 `proactive_actions` 只有单列 `payload_text` 且 `type` 枚举闭合（`core/db.py:488` / `:501-503`）；维护步名亦闭合（`core/db.py:1218-1222`）。**服务端定时落库需要第 3 个迁移**，与 `tasks.md:37`「本版本只加 1 个迁移」冲突 → 见 §4.2.4（**阻塞项**）。

### 2.3 在 V5.0.0 中的位置

M3（主动与我的）后端第 1 个任务，是 `APP-018`（简报页）/ `APP-019`（本地通知）/ `APP-020`（我的页三开关）的共同后端依赖（`tasks.md:181-184`）。它消费 M2 的 `API-004` / `API-006`，并把「AI 今天已经帮我整理好了」从首页延伸到**固定节奏**。

## 3. Scope

### 3.1 In Scope

1. `GET /api/v1/briefing?type=morning|evening` —— **两种形态共用一套渲染契约**（§4.1.2）。
2. **★ 晚间逐字文案冻结**（§4.1.4）——解除 `APP-018` §4.1.2 的阻塞。
3. **晚间「重新排期而非催促」契约**（§4.1.7）：服务端给 `rescheduled_tasks[]`（`slot` + 逐字文案），端上只渲染。
4. `GET /api/v1/briefing/preferences` —— 时刻**读面**（两字符串参数 + 空串语义）。
5. 新增 `core/settings/briefing.py`：`briefing_morning_time` / `briefing_evening_time`（参数类，env 名 = 字段名大写）。
6. `period_key` 幂等 + **离线可读路径**（端侧设定时刻前预取 + drift 只读缓存，§4.1.6）。
7. 新模块 `app/services/briefing/compose.py`（**确定性模板合成，零 LLM**，数字只来自既有聚合）+ 端点注册与响应模型（`router.py` + `schemas.py` 追加）。

## 4. Technical Design Requirements

### 4.1 接口契约

> 前缀 `/api/v1`；身份经 `API-001` 的 `Depends(require_user)`（`user_id` **仅从 token 解析**）。越权 → **403**「不得读写他人数据」（沿用 `ledger.py:145`）。

#### 4.1.1 `GET /briefing`（两种形态共用一套渲染契约）

| 方向 | 字段 | 类型 | 必填 | 语义 / 缺省 |
|---|---|---|---|---|
| 请求 | `type` | `string` | **是** | `morning` \| `evening`；其他值 → **422** |
| 请求 | `date` | `string` | 否 | `YYYY-MM-DD`；缺省 = **本地今天**；未来日期 → **422** |
| 响应 | `type` | `string` | — | 回显（`morning` / `evening`）——**端上不得按当前时刻自行推断形态**（`APP-018` §4.1.2） |
| 响应 | `period_key` | `string` | — | `"{type}:{date}"`（**幂等键**，可复算，见 §4.1.6） |
| 响应 | `generated_at` | `string` | — | ISO 8601（本地时区） |
| 响应 | `eyebrow` | `string` | — | 眉标：「08:00 · 早间简报」/「21:30 · 晚间总结」 |
| 响应 | `title` / `orb_line` | `string` | — | 主标题（含换行，逐字）/ Orb 状态解读（逐字）——§4.1.3 / §4.1.4 |
| 响应 | `cards` | `object[]` | — | **四张卡**，顺序冻结（§4.1.2） |
| 响应 | `rescheduled_tasks` | `object[]` | — | 晚间专用：未完成任务**重新排期**清单（§4.1.7）；早间恒 `[]` |
| 响应 | `cta` | `string` | — | 收尾语：「开始今天」/「安顿明天」 |
| 响应 | `disclaimer` | `string` | — | 常驻免责：「趋势参考，非医疗建议」（**出现健康数值时必填**，`APP-018` §4.1.7） |
| 响应 | `degraded_blocks` | `string[]` | — | 降级区块名清单（缺省 `[]`；对齐 `API-004` 的区块级降级） |

#### 4.1.2 渲染契约（★ 两形态**同构**，仅按 `type` 换数据与文案）

| 字段 | 类型 | 语义 / 缺省 |
|---|---|---|
| `cards[].key` | `string` | 卡片稳定键（`weather` / `schedule` / `tasks` / `rhythm` / `done` / `spent` / `sleep` / `remembered`） |
| `cards[].label` | `string` | 小标题（逐字，§4.1.3 / §4.1.4） |
| `cards[].text` | `string` | 主文案（逐字模板 + 真实数字） |
| `cards[].note` | `string` | 补充说明（**每张卡必填**，体现 AI 判断；`APP-018` §4.1.3） |
| `cards[].available` | `bool` | `false` → 端上走**空态 + 引导**，**不得**用假数据填充（对齐 `API-004` §4.1 区块 4 降级纪律）；`degraded_reason` ∈ `no_data_source` / `not_authorized` / `health_domain_not_delivered` / `no_tasks` |

**同构纪律**：① 两形态 `cards[]` **元素结构完全一致**，端上**同一个 widget 树**按 `type` 取数据（`APP-018` §4.1.2「禁止复制出两个页面文件」）；② 卡片**数量恒为 4**（`available:false` 时仍占位）；③ 数字格式化（`¥` / `°C` / 时刻 / `7h12m`）由端上经 `intl` 做，**结论文案由服务端给**。

#### 4.1.5 `GET /briefing/preferences`（时刻读面）
