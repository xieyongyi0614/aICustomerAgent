## 4. Technical Design Requirements

### 4.1 页面契约（照 `components.md:701-714` B18）

| # | 段 | 组件 | 内容 |
|---|---|---|---|
| 1 | 返回 | `BackLink` | 「‹ 相册」 |
| 2 | 标题 | 页标题 + 副题 | 相簿名 + 「N 张 · 本机自动归类 · 只存在这台手机上」 |
| 3 | AI 整理卡 | `AiCard` | 本机分析结论（**只含已实现类别**）+ 入口 → `/album/manage?album=` |
| 4 | 日期分组标题 | `_DayHeader` | 「M 月 D 日 · 地点」14px/700 + hint「N 张 · M 段视频」11.5px `ink3` |
| 5 | 照片网格 | **`PhotoTile`（A36）** | 3 列 / 间隙 6 / 圆角 12；视频时长徽章；**✦ 渐变徽章**（22px）标 AI 保留原片；整格可点 → `/album/photo?id=` |
| 6 | 次级按钮 | 边框按钮 | 「批量管理这个相簿」→ `/album/manage?album=` |
| 7 | 隐私卡 | `PrivacyNote` | 本机归类 / 不上传 / 系统「最近删除」30 天 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **「12 组连拍，每组留了最清楚的一张」不得输出** | D16：连拍分组需感知哈希 + 清晰度评分，本期不做；照抄即假结论（`APP-014` 红线） |
| 2 | **✦ 徽章的语义收敛为「AI 保留了这张」**，可对**重复保存**场景生效（同一张图存了多次时留最早/最清晰的一张）；无判定依据时**不显示 ✦** | `components.md:714` 要求「AI 留下的原片要可见」；但标记必须来自真实判定 —— 重复保存可判（哈希），连拍清晰度不可判。**语义收紧、不越界** |
| 3 | AI 整理卡**只统计已实现类别** | 同 `APP-035` §4.2 裁决 2 |
| 4 | 地点缺失时**不显示地点段**（不写「未知地点」） | 无元数据时不编造；组标题降级为「M 月 D 日」 |
| 5 | 隐私口径与 `APP-035` **逐字一致** | 同一红线的两处落地必须同口径；不一致会被走查抓出 |
| 6 | 零网络 | D18 守卫 |

### 4.3 数据流

```text
进入 /album/detail?album=旅行
  → album_repository.loadAssets(album)         # 本机资产（分页）
  → album_analysis.groupByDay(assets)          # 按拍摄日期分组（本机）
       → 组标题：日期 + 地点（缺失则省略）+ 张数 + 视频段数
       → ✦ 标记：仅对「重复保存」判定命中的保留项（无判定则不标）
点击照片 → push /album/photo?id=…
点击「批量管理这个相簿」/ AI 卡入口 → push /album/manage?album=…
```
