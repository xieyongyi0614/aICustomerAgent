### 2.2 为什么必须做

1. **它是 M1 的入口页面。** M1 目标是「跑通『说一句话 → 看到 AI 逐字回复 → 看到 AI 做事的过程』」（`tasks.md:121`），而 `#chat` 是这条链路的**承载页**（`traceability.md:82`）。
2. **它是「记忆可见」在对话链路上的唯一落点。** 设计原则「记忆可见」的可判定规则要求每条记忆有来源追溯与用途回执（`principles.md:13`）；对话页的记忆提示条是用户**在对话中**感知「AI 记着我」的唯一位置（`traceability.md:43`，本轮补挂）。
3. **它是 `REQ-CHAT-03` 的落点任务，且是本轮核对补挂的缺口。** `traceability.md:278`（G3）明确：`REQ-CHAT-03` 此前**无任务落点**，已并入 `APP-009`。
4. **会话历史是「回看」的硬需求，且端点已就绪。** `REQ-CHAT-06` 就绪度 ✅（`requirements-analysis.md:257`），但**会话列表端点不存在**（§2.1），因此「列表」必须靠端上投影，这是一条必须显式裁决的边界（§4.2 D3）。
5. **滚动定位是易错点，必须显式契约化。** 「进入会话定位到末条」与「回看历史不被新消息打断」是一对**互斥**诉求：前者要求自动滚底，后者要求**抑制**自动滚底——不写清就会实现成「看历史时被新 token 拽回底部」这种经典缺陷。

### 2.3 在 V5.0.0 中的位置

M1 客户端第 1 个任务，位于 `APP-005 → APP-009` 与 `API-003 → APP-009` 两条边的汇合点；`APP-012` 依赖本任务（`tasks.md:140`），因为状态栏是**装配在对话页头部**的。

## 3. Scope

### 3.1 In Scope

1. **对话页装配（`B2 #chat` 八段）**：按 §4.1.1 的结构表装配，**本任务只做装配与页面级状态**，子组件的**内部实现**归各自任务。
2. **长期记忆调用提示条**：`A11 mem-hint` 的**接入与渲染条件**（§4.1.2）——组件由 APP-007 交付，本任务负责「何时渲染 / 何时整条不渲染」与文案拼接。
3. **会话列表**：端上会话投影列表（§4.1.3，含来源裁决）。
4. **历史回放**：`GET /conversations/{id}/messages` 的接入、分页游标（`before_id`）、与流式新消息的**合并顺序**（§4.1.4）。
5. **滚动定位契约**：进会话定位末条 / 回看历史不被新消息打断（§4.1.5）。
6. **会话历史只读缓存**（drift）：进页先渲染缓存再刷新（§4.1.6）。
7. **页面级四态**：加载 / 空 / 错误 / 骨架（消费 APP-008 组件）。
8. **页面级状态容器**：对话页的 Riverpod 状态（**不含**流式渲染状态机——那归 APP-010）。

#### 4.1.2 记忆提示条契约（**本任务的核心交付**）

| 项 | 契约 |
|---|---|
| 组件 | `A11 mem-hint`（由 APP-007 交付，`tasks/APP-007.md:68`）；本任务**只消费**，不得改组件 |
| 数据来源 | `ChatTurnState.memoryRefs`（`flutter-architecture.md:238`），源头为 `turn_meta.memory_refs`（`API-003`） |

| 分隔符 | `label` 之间用 ` · `（中间点，前后各一空格）——与真源文案一致 |
| **渲染条件（红线）** | `memoryRefs` **键缺省**（无引用）→ **整条不渲染**（不占位、不显示「0 条」、不显示空条） |

| 位置 | 第 2 段（头部之下、消息流之上），随页面滚动**不吸顶**（设计稿未定义吸顶，自行添加属发明需求） |

| 无障碍 | 需有语义标签，读出「本轮已调用 N 条长期记忆」；`label` 文本可被读屏逐条读出 |

> **端上截断**：`API-003` 下发**全部**引用条目（`API-003.md:114`），本任务按实际条数渲染；若 `label` 拼接超出单行，**换行而非省略**（提示条是信息而非装饰，不得截断掉信息）。此条为**展示层裁决**，写入 §4.2 D2。

#### 4.1.4 历史回放契约

| 项 | 契约 |
|---|---|
| 端点 | `GET /conversations/{conversation_id}/messages`（`history.py:20`） |
| 请求参数 | `limit`（默认 200 / 上限 500，`history.py:24`）、`before_id`（游标，`history.py:26`）——端上**首屏用默认 limit**，上滑加载更多时用 `before_id` 游标 |
| 响应字段 | `conversation_id` + `messages[{id, role, content, created_at}]`（`history.py:35-45`） |
| 消息方向 | `role` 决定气泡归属（`user` → 用户深色泡；其余 → AI 白卡泡），**渲染归 APP-011** |
| **与流式新消息的合并顺序** | 历史消息（按 `created_at` 升序）在前 → 本轮流式产生的 turn 追加在**末尾**；`id` 用于去重（同一消息 id 不重复插入） |
| 历史消息**不含** | `memory_refs` / `toolSteps` / `chips`（回放体只有 `id/role/content/created_at`）——**因此历史 turn 不渲染记忆提示条与过程卡**，这是**契约事实**而非缺陷；不得由端上凭空补 |
| 会话不存在 | 404「会话不存在」（`history.py:29`）→ 映射为用户可读文案（APP-008 口径），**不暴露状态码** |
| 分页边界 | `before_id` 到顶（无更多）→ 停止加载，**不重复请求** |

#### 4.1.5 滚动定位契约（**两个互斥诉求**）

| 场景 | 契约 | 理由 |
|---|---|---|
| **进入会话** | 定位到**末条**（滚到底），**先渲染缓存再定位**（避免缓存回填后跳动） | 用户期望「接着上次说」 |
| **流式期间且视口在底部** | 新 token 到达 → 保持贴底 | 连续阅读体验 |
| **流式期间但用户已上滑**（视口不在底部） | **抑制**自动贴底；不因新消息把用户拽回底部 | 「回看历史不被新消息打断」 |
| 用户手动回到底部 | 恢复自动贴底 | 显式意图 |
| 历史回放（上滑加载更多） | 加载更多后**保持当前视口位置**（不跳到底） | 同上 |
| 判定阈值 | 「是否在底部」的判定阈值冻结为 **48 logical px**（端上展示约束，非设置项） | 需要可判定的判据 |

#### 4.1.6 只读缓存契约

| 项 | 契约 |
|---|---|
| 载体 | drift（SQLite），落点 `features/chat/data/`（`flutter-architecture.md:371`） |
| 存什么 | **只存服务端 DTO 投影**（`history.py:38-45` 的字段投影 + `conversation_id`），**不做本地业务逻辑**（`flutter-architecture.md:23`） |
| 读路径 | 进页 → **先渲染缓存** → 再发 `GET /conversations/{id}/messages` 刷新 → 用响应**整体替换**该会话的缓存投影 |
| 写路径 | **只写缓存投影**；**不**做离线发消息、**不**做写排队（反范围，`requirements-analysis.md:398`） |
| 失效 | 会话删除 / 清空数据（`/life/data`）→ 本地缓存**必须**同步清空（合规：用户控制权口径，决策 D2） |
| 时间标注 | 缓存回填的数据需可判断「是否为缓存」（用于骨架 → 数据的过渡），但**不要求**在对话页展示数据时间（对话页非账本页，`flutter-architecture.md:373` 的「金额展示必须标注数据时间」只针对账本） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **本任务是「装配方」，不实现任何子组件** | `APP-009~013` 五条任务必须在 §3.2 划清边界，否则会重复交付（`tasks/README.md:51` 要求 Out of Scope 逐条给理由） |
| D2 | 记忆提示条 **`label` 超行换行、不截断**；`N` 与条数按实际渲染 | 提示条承载「记忆可见」原则（`principles.md:13`），截断会吃掉信息；`API-003` 已下发全部引用条目（`API-003.md:114`） |
| D3 | **会话列表走端上投影，不新增后端端点** | `tasks.md` 中**无**「会话列表」API 任务；新增即范围蔓延（`tasks/README.md:5`「不增不减」）。会话 id 已由 `X-Session-Id` 回传（`chat.py:101`），端上可维护投影 |
| D4 | **`memoryRefs` 键缺省 ⇒ 提示条整条不渲染** | `API-003` 的缺省语义红线（`API-003.md:129`）；端上若把缺省当空数组会渲染出「0 条记忆」 |
| D5 | **滚动定位：视口在底部才贴底，否则抑制** | 「进入定位末条」与「回看不被打断」是互斥诉求，必须用「是否在底部」分流；阈值冻结 48px 以便判定 |
| D6 | **历史回放不补 `memory_refs` / 过程卡** | 回放体只有 `id/role/content/created_at`（`history.py:38-45`）；端上凭空补属发明数据 |
| D7 | **进页先渲染缓存再刷新** | `flutter-architecture.md:371` 明确会话历史为只读缓存策略 |
| D8 | 缓存**只存 DTO 投影**，不做本地业务逻辑 | 降低与后端 Schema 演进的耦合（`flutter-architecture.md:414`） |
| D9 | 页面**不得直接调 `dio`**，一律经 `features/chat/data/` 的 repository | 分层纪律 L3（`flutter-architecture.md:197`） |
| D10 | 页面**不得 import 其它 `features/*`**（含 `memory` / `home`） | 分层纪律 L1（`flutter-architecture.md:195`）；记忆提示条是独立组件，不复用记忆页卡片 |
| D11 | 输入栏 `bottom 88` 由**页面布局**让出，不由输入栏组件自行定位 | 屏幕级间距属页面职责（`tokens.md:219`）；组件自行定位会导致多页不一致 |
| D12 | **不做未读 / 红点 / 会话删除 / 重命名** | 设计稿未定义（`components.md:315-327` 只有 8 段结构）；自行添加属发明需求 |
| D13 | 新增设置 = **无** | 裁决 9（`tasks.md:26`）；列表上限 20、滚动阈值 48px 均为**展示约束常量**，不做成设置项 |

### 4.3 数据流

```text
go_router（APP-005）→ features/chat/presentation（本任务）
   │
   ├── 进页
   │     → features/chat/data（repository，经 APP-003 的 dio 客户端）
   │           ├── 读 drift 缓存投影（会话历史）→ 先渲染（D7）
   │           └── GET /conversations/{id}/messages（history.py:20）
   │                 → 整体替换缓存投影 → 刷新 UI
   │
   ├── 发消息（经 APP-010 的流式引擎）
   │     → POST /chat/message（chat.py:35）
   │           ├── turn_meta  → role_mode → 头部槽位（APP-012）
   │           │                 memory_refs → 记忆提示条（本任务，缺省则不渲染 D4）
   │           ├── token       → 正文（APP-010）
   │           ├── tool_step   → 过程卡穿插位（APP-013）
   │           └── done        → 收口，落历史 + 写缓存投影
   │     → 响应头 X-Session-Id（chat.py:101）→ 会话列表投影新增 / 更新（D3）
   │
   └── 滚动定位（D5）
         ├── 进会话 → 滚到末条（缓存渲染完成后）
         ├── 视口在底部（≤48px）→ 新 token 保持贴底
         └── 视口已上滑 → 抑制贴底；用户回底后恢复

分层红线：
   ✗ presentation 不直接调 dio（D9，L3）
   ✗ features/chat 不 import 其它 features/*（D10，L1）
   ✗ 不新增后端端点（D3）
```
