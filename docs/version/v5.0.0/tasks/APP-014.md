## 2. Background

### 2.1 现状：首页所需的每一块都**没有聚合出口**

| 事实 | 证据 |
|---|---|
| `apps/mobile/` 工程尚未创建（`apps/` 下只有 `backend` / `frontend`） | `ls apps/` → `backend frontend` |
| **无 `GET /home/summary`**；`api_router` 聚合 13 个子路由，**无 home 路由** | `apps/backend/app/api/v1/router.py:18-31`（13 个 `include_router`，无 home） |
| 首页一屏需 5+ 请求拼装，其中 1 个还是 debug 接口 | `requirements-analysis.md:176-180`（缺口 11）；`/memories` 在 `history.py:48`、工具执行在 `debug.py:237` |
| **无产品级洞察接口**（AI 总结卡无来源） | `grep '"/insights"' apps/backend/app/api/v1/*.py` → 无输出；`requirements-analysis.md:170-174`（缺口 10） |
| **无「今日任务」实体**（任务行无落点） | `requirements-analysis.md:157-162`（冲突 6）；`API-005` 建 `life_tasks` |
| **健康域完全缺失**（三宫格无来源），且有一项未闭合实机验证 | `requirements-analysis.md:182-187`（缺口 9）；决策 D1（`tasks.md:78`） |

| 首页聚合须**区块级降级**，任一子域不可用时不整体 500 | `tasks.md:154`（API-004 验收 ④） |
| 首页聚合走 drift **只读缓存**（冷启动骨架 → 数据） | `flutter-architecture.md:374` |
| `B1 #home` 的 11 段结构与真实文案已冻结 | `components.md:293-311` |
| 首页 AI 总结 / Hero / 消费结论 / 输入丸占位文案 | `principles.md:81-85`、`:101` |
| 「AI 叙事优先」的可判定验收规则 | `principles.md:11`（红线 4，`SKILL.md:45`） |

### 2.2 为什么必须做

1. **首页是产品定位的兑现点。** 页面目的即「10 秒内感受『AI 今天已经帮我整理好了』」（`traceability.md:71`）；这句话若不成真，整个产品退化为「几个工具页的集合」。
2. **它是 M2 收口点 C3 的一半。** C3 判定标准 =「首页单请求成型 + 记账页与后端数字逐项一致」（`tasks.md:257`）。本任务负责前半，`APP-016` 负责后半。
3. **它是「跨域合成必须在服务端」这条反范围的落地检验。** `requirements-analysis.md:394` 明确「不做把跨域合成逻辑放到客户端」；若客户端自行拼装 `state + memories + ledger + plans`，就同时击穿该反范围与首屏性能基线（`PLT-006`）。
4. **三宫格双分支是决策 D1 的客户端承载。** D1 裁定「未通过 → 首页三宫格走**空态 + 引导授权**」（`tasks.md:78`），且该分支**属 M2 范围**（`tasks.md:196`）——本任务不得以「等 M4」为由留白或用假数据。

### 2.3 在 V5.0.0 中的位置

M2 客户端第 2 个任务，位于关键路径末端（`APP-007 → APP-013 → APP-014`，`tasks.md:246`）。它同时消费 APP-006（Orb 英雄区）与 APP-013（输入丸跳对话后的过程卡链路），是 M2 的收口页面。

## 3. Scope

### 3.1 In Scope

1. **`B1 #home` 11 段装配**（§4.1.1）：问候行 → Hero → AI 结论卡 → 区块标题 → 指标三宫格 → 区块标题 → 任务列表 → 区块标题 → 消费块 → 输入丸 → Tab 栏，逐段照 `components.md:293-311`，真实文案逐条照抄。
2. **信息流顺序契约**（§4.1.2）：「先结论 → 后数据 → 再行动」，落地 `REQ-HOME-08` 与红线 4。
3. **三宫格双分支**（§4.1.3）：通过 → 真实数据 + 来源标注；未通过 → **空态 + 引导授权卡**（零数值、零留白）。
4. **消费块**（§4.1.4）：`A7` 规格 + 结论文案。
5. **任务列表**（§4.1.5）：`A6` 规格 + 「3 项 · AI 已排序」hint；`order_reason` 由服务端给，客户端只渲染。
6. **单请求数据契约**（§4.1.6）：`GET /home/summary`；区块级降级。
7. **冷启动缓存**（§4.1.7）：drift 只读缓存 → 骨架 → 数据。
8. **非医疗建议纪律的适用性判断**（§4.2 D4）：三宫格健康文案的边界。

#### 4.1.2 信息流顺序契约（「先结论 → 后数据 → 再行动」）

| 层 | 承载段 | 语义 | 可判定规则（`principles.md:11`） |

| 先结论 | 段 2 Hero + 段 3 AI 结论卡 | AI 帮你理解了什么 | 首屏**必须**存在 AI 结论块，且**渲染顺序先于**原始数据区（段 4~9） |

### 4.3 数据流

```text
冷启动
   → features/home/data（drift 只读缓存）→ 先渲染骨架 / 旧数据
   → GET /home/summary（单请求，API-004）
        · 服务端跨域合成：state + memories + ledger + tasks(API-005) + insights(API-006) + 健康（若可用）
        · 任一子域不可用 → 该区块标记不可用（不整体 500）
   → features/home/data/home_repository（L3：presentation 不得直调 dio）
   → Riverpod provider → features/home/presentation
        · 段 2/3 渲染 AI 结论（服务端文案）
        · 段 5 按分支渲染：可用 → A5 ×3 真实数据；不可用 → 引导授权卡
        · 段 7 渲染任务 + order_reason（服务端给）
        · 段 9 渲染 A7 消费块
   → 渲染顺序固定「先结论（2/3）→ 后数据（4~9）→ 再行动（10）」

装配红线：
   ✗ 不发第二个请求补数据（D2）
   ✗ 不本地生成 AI 结论文案（D7）
   ✗ 空态不显示任何健康数值（D8）
```
