| 合规：健康信息 = 敏感 PI；须固定免责；**HealthKit 禁广告 / 出售健康数据** | `REPORT.md:95`、`:100`；`requirements-analysis.md:187`；红线 8（`SKILL.md:49`） |

**实际后果**：即便 `PLT-001` 验证通过、`API-009` 落库就绪，**端侧仍无任何通道把 Health Connect / HealthKit 的数据送上去**；`APP-014` 三宫格的「通过分支」与 `APP-024` 健康页全部悬空。

### 2.2 为什么必须做

1. **它是主路径的端侧一半。** 调研主路径的端侧环节是「细粒度 `READ_*` / HealthKit 类型授权 → App Health Ingest」（`REPORT.md:68-70`）；没有本任务，服务端 ingest 无数据可收。
2. **它的最大技术风险是 Android 14+ 新权限模型。** `health` 包对该模型支持**可能不完整**（`flutter-architecture.md:415`），因此裁决为**该部分走平台通道**——这是本任务最核心的工程内容。
3. **它是「权限被拒不是死路」这条可判定规则的落点。** 与三宫格「空态 + 引导授权」同源（`tasks.md:166`）；不做降级，用户拒绝权限后 App 会直接失效。
4. **它承载「同步范围最小化」的合规要求。** 只申请展示所需字段（`REPORT.md:9`、`:77`）；超范围申请既违反最小必要原则，也会提高商店审核风险（`REPORT.md:95`）。
5. **它是决策 D7「Android 优先」的执行面。** Health Connect 路径风险低于 HealthKit（`requirements-analysis.md:377`）。

### 2.3 在 V5.0.0 中的位置

M4 客户端第 1 个任务（`tasks.md:202`），位于 `PLT-001 → APP-023 → APP-024` 链首（`tasks.md:226-228`）。它依赖 `APP-021`（授权治理入口），是 `APP-024` 健康页与 `APP-014` 三宫格通过分支的数据前提；它与 `APP-025`（同意流程）**分工不重叠**（§4.4）。

## 3. Scope

### 3.1 In Scope

1. **平台能力探测**（§4.1.1）：Health Connect SDK 可用性 / HealthKit 可用性 → 三态（可用 / 不可用 / 需升级）。

5. **读取与幂等同步**（§4.1.4）：按窗口读取 → 经 `POST /health/ingest` 上行；重复同步零新增（对齐 `API-009` 幂等键）。

7. **来源声明数据**（§4.1.5）：为 `A23 src-note` 提供 `device_model` / 授权态（供 `APP-024` 渲染「数据来自 小米手环 9 Pro · 已授权同步」）。
8. **合规**：含健康表述处常驻轻量免责；**HealthKit 禁广告 / 出售健康数据**（本任务不引入任何广告 / 数据出售路径）。

## 4. Technical Design Requirements

### 4.1 组件 / 接口契约

#### 4.1.1 平台能力探测与权限模型契约（★ Android 14+ 核心）

> **依据**：`REPORT.md:77`（Android 14+ 需 `VIEW_PERMISSION_USAGE` + `HEALTH_PERMISSIONS`）；`flutter-architecture.md:415`（`health` 包支持可能不完整 → **该部分走平台通道**，包仅用于数据读取）。

| 平台 | 探测 | 权限声明 / 申请 | 走法 |
|---|---|---|---|
| **Android**（优先，D7） | `HealthConnectClient.getSdkStatus()` → `available` / `update_required` / `unavailable` | **Manifest 声明**：`android.permission.health.READ_<TYPE>` × 申请范围；**隐私政策 rationale Intent**（`ACTION_SHOW_PERMISSIONS_RATIONALE`） | 权限模型部分**走平台通道**（`MethodChannel`），**不用 `health` 包的权限 API** |
| **Android 14+** | 同上 + 版本判定 | **`VIEW_PERMISSION_USAGE` + `HEALTH_PERMISSIONS`**：`<activity-alias>` 指向宿主 Activity，带 `android.permission.START_VIEW_PERMISSION_USAGE`，intent-filter `ACTION_VIEW_PERMISSION_USAGE` + category `HEALTH_PERMISSIONS`；授权前后展示 rationale | **平台通道**（`flutter-architecture.md` §10 风险 3 的落地） |
| **iOS** | `HKHealthStore.isHealthDataAvailable()` | `NSHealthShareUsageDescription`（Info.plist）；`requestAuthorization(toShare: [], read: <types>)`（**只读**） | HealthKit 类型授权经平台通道；**读权限状态不可直接查询** → 以「能否取到数据」推断 |

**平台通道契约（`core/health/`，方法级）**

| 方法 | 入参 | 出参 | 语义 |
|---|---|---|---|
| `probe` | 无 | `{platform, status: available\|update_required\|unavailable, sdk_version}` | 能力探测 |
| `requestReadPermission` | `{metrics: string[]}` | `{granted: string[], denied: string[]}` | **只申请入参列出的细粒度读权限** |
| `readSamples` | `{metrics, window_start, window_end}` | `{samples: [{metric, value_num, unit, started_at, ended_at, granularity}]}` | 读取（**只读已授权 metric**） |
| `openRationale` | 无 | `{opened: bool}` | 打开隐私政策 rationale（Android） |
| `deviceModel` | 无 | `{model: string}` | 供 `A23 src-note` 文案 |

> **纪律**：权限模型与 rationale **必须走平台通道**（`flutter-architecture.md:415`）；`health` 包**只用于数据读取**（`readSamples` 的实现可复用它，但**不得**用它的权限 API 处理 Android 14+ 模型）。

#### 4.1.2 细粒度读权限申请范围（**最小化**）

| `metric`（对齐 `API-009` §4.1.2） | Android 权限 | iOS HealthKit 类型 | 是否申请 |
|---|---|---|---|
| `sleep_duration` | `READ_SLEEP` | `sleepAnalysis` | ✅ |
| `sleep_deep_ratio` | `READ_SLEEP` | `sleepAnalysis` | ✅（同源） |
| `resting_hr` | `READ_RESTING_HEART_RATE` | `restingHeartRate` | ✅ |
| `steps` | `READ_STEPS` | `stepCount` | ✅ |
| `active_minutes` | `READ_ACTIVE_CALORIES_BURNED` / `READ_EXERCISE` | `appleExerciseTime` | ✅ |
| `hrv` / `spo2` / `stress` | — | — | ⛔ **不申请**（展示不需要；§3.2 #5） |
| 任意 `WRITE_*` | — | — | ⛔ **不申请**（§3.2 #4） |

> **范围由 `PLT-001` 结论冻结**：`PLT-001` 输出的可同步字段清单决定上表**实际申请子集**；未证实可同步的 `metric` **不得申请**（`REPORT.md:87`）。

#### 4.1.3 权限被拒降级契约（★ 可判定）

| 项 | 契约 |
|---|---|
| 语义 | 权限被拒 / 部分拒绝 / 平台不可用 → **不是死路**，进入**降级态** |
| 降级表现 | 相关模块显示**空态 + 引导授权**（不留白、不用假数据），**不得**抛错误页 / 崩溃；`APP-014` 三宫格走**未通过分支**（`APP-014.md:124-142`） |
| 引导动作 | 提供「去授权」→ 跳 `APP-021` 的授权范围管理（健康独立项）或 `APP-025` 的同意流程 |
| 部分拒绝 | 部分 metric 被拒 → **只用已授权 metric** 同步；未授权 metric **不读取、不上传**（§4.1.4） |
| 恢复 | 用户在系统设置 / 授权页重新授权 → 回到可用态，**不必重启 App** |
| 判定 | 「拒绝 → 降级不报错」是**可判定**规则，须有可执行用例（§7.2） |

#### 4.1.4 读取与同步契约（**幂等 + 不上传未授权字段**）

| 项 | 契约 |
|---|---|
| 上行通道 | `POST /health/ingest`（`API-009` §4.1.5，**唯一**通道） |
| 请求体 | `{source_kind, platform, window_start, window_end, metrics[], device_model, samples[]}` |
| 窗口 | 默认 `health_sync_window_days`（端侧偏好，默认 `7`）；窗口由 `API-009` 上限约束 |
| **幂等** | 端侧重试 / 重复同步 → 服务端按 `API-009` 幂等键去重（`ingested=0`）；**端侧不自行去重作为唯一保证**（服务端唯一索引兜底） |
| **未授权字段** | 请求中的 `samples[].metric` **必须** ⊆ 已授权 `metrics`；越界样本端侧**先剔除**，服务端**再拒绝**（双保险） |
| 失败处置 | 上行失败 → 可读错误 + 重试；**不静默失败**（`APP-008` 错误规范）；V1 **不做离线写**（`flutter-architecture.md:375`），失败进重试队列并明示「待同步」 |
| 日志 / 埋点 | **禁打健康数值**（`requirements-analysis.md:222`；`tasks.md:216`） |
| 触发 | 用户主动同步 / 进健康页时增量同步；**不新建常驻后台循环**（对齐「不建第二套调度」纪律） |

### 4.3 数据流

```text
门控解除（PLT-001 通过 + API-009 / APP-021 落地）
   ↓
进健康页 / 用户点「同步」（APP-024 / APP-021 入口）
   → core/health（平台通道）
        · probe() → available / update_required / unavailable
        · requestReadPermission(metrics=§4.1.2 最小范围)
             Android 14+ → VIEW_PERMISSION_USAGE + HEALTH_PERMISSIONS（平台通道）
             iOS        → HKHealthStore.requestAuthorization(read-only)
             rationale → openRationale()（Android 隐私政策 Intent）
        · readSamples(metrics=已授权子集, window)
             · 未授权 metric → 不读取
   → features/health/permission（授权引导态）
        授权通过 → 进入同步
        被拒 / 部分拒 / 平台不可用 → 降级态（空态 + 引导授权，不报错）
   → 上行：POST /health/ingest（samples 已剔除未授权字段）
        → API-009 幂等落库（重复 → ingested=0）
   → 结果回执（last_synced_at / ingested / rejected）→ 展示「待同步」或「已同步」

降级路径（权限被拒）：
   三宫格 / 健康页 → 空态 + 引导授权（APP-014 §4.1.3 未通过分支）
   引导动作 → 跳 APP-021 授权范围管理（健康独立项）/ APP-025 同意流程

装配红线：
   ✗ 用 health 包的权限 API 处理 Android 14+ 模型（D1）
   ✗ 权限被拒后报错 / 崩溃 / 空白（D2）
   ✗ 申请 WRITE_* 或展示不需要的类型（D4）
   ✗ 上传未授权字段（D5）
   ✗ 健康数值进日志 / 埋点（D9）
```
