### 2.2 为什么必须做

1. **「综合 N 分」是健康页首屏的核心结论，且口径必须可被用户理解。** M4 验收口径要求「首屏是『今天状态不错』而非指标表」（`tasks.md:206`）；黑箱分数违背「AI 叙事优先 / 卡片即结论」原则（`requirements-analysis.md:39-40`）——用户必须看懂「86 分」由哪几项构成。
2. **它是「不建第二套 Agent」纪律的检验点。** 洞察**生成**已存在（reflection / development 三闸）；本任务**只做读面与口径**（`API-006.md:76` D4）。
3. **最大合规风险是「文案越界」，且异常检测产出必须与投递解耦。** 健康文案一旦出现「诊断 / 医疗级 / 血压 / 血糖 / 血氧」即触碰红线 8 与 App Store 1.4.1（`REPORT.md:99`、`:100`）；`REQ-PROA-04` 属 P2（`requirements-analysis.md:315`）——本任务只产**可被后续消费的结论**，**不投递**（`tasks.md:195`）。

### 2.3 在 V5.0.0 中的位置

M4 后端第 2 个任务，位于 `API-009 → API-010 → APP-024` 链中（`tasks.md:226-228`）。它同时消费 `API-009`（事实域）与 `API-006`（洞察读面），是 `APP-024` 健康页的数据前提。

## 3. Scope

### 3.1 In Scope

1. **评分口径（文档化 + 端点回传）**：`GET /health/overview` → `{score, score_breakdown[], headline, narrative, disclaimer, generated_at}`（§4.1.1、§4.1.2）。
2. **睡眠趋势批注**：`GET /health/trends?metric=sleep&window=7d` → `{points[], annotation, source_refs[]}`（§4.1.3）。
3. **异常趋势检测**：阈值化（非诊断）检测，产出**结论记录**（§4.1.4）；**不投递**（§3.2）。
4. **洞察只做读面**：叙事生成走 `API-006`（reflection / development 既有服务）；本任务**不新建生成链路**（§4.2.1 D3）。
5. **文案合规**：统一「趋势 / 参考」语义 + 固定免责声明；禁医疗级宣称（§4.2.3 禁用词清单）。
6. **评分 / 趋势 / 异常全部确定性可复算，零 LLM**（数字与分数由规则产生；叙事文案由 `API-006` 既有生成服务产出）。
7. **纯新增**：零新迁移、零 `*_enabled` 开关、零 `app/repositories` 反向依赖、零新事件类型。

## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 端点与响应

**① `GET /api/v1/health/overview`**

| 方向 | 字段 | 类型 | 必填 | 语义 / 缺省 |
|---|---|---|---|---|
| 请求 | `date` | `string` | 否 | 目标日期（缺省 = 今日，用户本地时区）；非法 → 422 |
| 响应 | `score` | `int` | — | **综合分**（0–100 整数，确定性可复算，§4.1.2） |
| 响应 | `score_breakdown` | `object[]` | — | **口径可解释**：`[{metric, raw_value, unit, sub_score, weight, target}]` |
| 响应 | `headline` | `string` | — | 一句话结论（由 `score` 分档的**确定性模板**给出，如「今天状态不错」） |
| 响应 | `narrative` | `string` | — | 叙事全文（**来自 `API-006` 的洞察读面**，本任务不生成） |
| 响应 | `disclaimer` | `string` | — | **固定免责声明**：「非医疗建议，请咨询医生」 |
| 响应 | `generated_at` | `string` | — | ISO 8601（本地时区） |

**② `GET /api/v1/health/trends`**

| 方向 | 字段 | 类型 | 必填 | 语义 / 缺省 |
|---|---|---|---|---|
| 请求 | `metric` | `string` | 是 | `sleep` / `resting_hr` / `steps` / `active_minutes`；非法 → 422 |
| 请求 | `window` | `string` | 否 | `7d`（默认）/ `14d` / `30d`；非法 → 422 |
| 响应 | `points` | `object[]` | — | `[{date, value, unit}]`（来自 `health_daily_rollups`） |
| 响应 | `annotation` | `string` | — | **趋势批注**（确定性模板 + 证据；§4.1.3） |
| 响应 | `source_refs` | `object[]` | — | `[{kind, ref, label}]`（来源追溯，对齐 `API-006`） |
| 响应 | `disclaimer` | `string` | — | 固定免责声明 |

**错误语义**：`422` 非法 `metric` / `window` / `date`；`403` 越权（他人 `user_id`）；**无数据 → 200 + 空结果**（`points: []`、`score: null`、`annotation` 为「还没有足够的数据」类空态文案，**不 500**）；**不透传堆栈**。

#### 4.1.2 🚨 评分口径（**必须文档化，不可黑箱**）

> **裁决 D1**：用户必须能理解「86 分」怎么来的。因此端点**必须**回传 `score_breakdown`，且口径**冻结、确定性、零 LLM、可复算**。

| 项 | 契约 |
|---|---|
| 输入 | `health_daily_rollups` 中目标日期的 `metric` 子集（`API-009` §4.1.2 冻结值域） |
| 分项 | 睡眠（`sleep_duration` + `sleep_deep_ratio`）/ 静息心率（`resting_hr` 相对自身基线）/ 步数（`steps` vs 目标）/ 运动（`active_minutes` vs 目标） |
| 权重（冻结，参数类） | `睡眠 40 / 静息心率 25 / 步数 20 / 运动 15`（合计 100；`vitals_score_weights` 可调，**参数类**） |
| 分项映射 | 每项按**分段线性**映射到 `0–100` 子分（目标值 / 阈值来自参数类设置，如 `vitals_sleep_target_min=420`、`vitals_steps_target=8000`）；映射曲线**文档化**（写在 `services/vitals/scoring.py` 模块 docstring + 本表） |
| 综合分 | `score = round(Σ(sub_score_i × weight_i) / 100)`，取整到 `0–100`；**缺项**（某 metric 无数据）→ 该权重**按剩余项归一化**（并在 `score_breakdown` 标注 `available=false`），**不默认 0 分**（避免「没数据 = 状态差」的误读） |
| 分档 headline | `≥80`「今天状态不错」/ `60–79`「状态平稳」/ `<60`「今天可以慢一点」（模板化，见 `principles.md:89` 叙事范例；**不含诊断语义**） |
| 可复算 | 同输入 → 同 `score` / 同 `score_breakdown`；`generated_at` 除外 |
| 零 LLM | 分数**只由规则产生**；LLM **永不生成 / 复述**分数与测量数字（`REPORT.md:38`、`:186`） |
| 无数据 | 全部项缺失 → `score: null` + 空态文案（**不返 0 分**） |

**`score_breakdown` 单项字段**

| 字段 | 类型 | 语义 |
|---|---|---|
| `metric` | `string` | 分项名（`sleep` / `resting_hr` / `steps` / `active_minutes`） |
| `raw_value` / `unit` | `float?` / `string` | 当日实际值（来自 rollups）/ 单位 |
| `sub_score` | `int?` | 子分（0–100） |
| `weight` | `int` | 权重（归一化后） |
| `target` | `string` | 目标 / 基线说明（如「目标 8,000 步」「相对你的静息基线」） |
| `available` | `bool` | 该项是否有数据（缺项归一化依据） |

#### 4.1.3 睡眠趋势批注契约（确定性）

| 项 | 契约 |
|---|---|
| 数据源 | `health_daily_rollups`（`metric in (sleep_duration, sleep_deep_ratio)`） |
| 批注结构 | **趋势 → 预判 → 行动建议**（照 `principles.md:89` 健康叙事范例结构） |
| 生成方式 | **确定性模板**（按窗口统计量选择模板分支，如「周中缺口已补上」）；**数字来自 rollups**，零 LLM |
| 文案真源 | 沿用 `principles.md:89` 范例的**语气与句式**（第一人称「我」/「亚丝娜」；用「建议 / 可以」，不用「必须 / 请立即」）；**不得自创风格** |
| 免责 | 批注**必须**伴随 `disclaimer`（红线 8） |
| 参考语义 | 一律用「趋势 / 参考」，**禁**「诊断 / 异常病理」类措辞（§4.2.3） |

#### 4.1.4 异常趋势检测契约（**产结论，不投递**）

| 项 | 契约 |
|---|---|
| 方法 | **阈值化统计**（如相对自身基线的 z-score > `vitals_anomaly_z_threshold`），**非诊断**（`REPORT.md:178`「阈值，非诊断」） |
| 产出 | **结论记录**（`{metric, window, direction, magnitude, generated_at}`），供**后续消费**（`REQ-PROA-04`，产品阶段 P2） |
| 🚨 不投递 | 本任务**不**触发通知 / 简报 / 飞书 / 端侧推送（§3.2 #1；`tasks.md:195`） |
| 消费方式 | 结论可经 `API-006` 的洞察读面暴露（作为 `domain=health` 的洞察证据）；**投递由 P2 任务实现** |
| 文案边界 | 结论措辞只描述**趋势**（「最近 7 天入睡时间平均推迟」），**禁**诊断 / 病理 / 医疗级表述 |
| 零 LLM | 检测**零 LLM**（阈值规则） |
