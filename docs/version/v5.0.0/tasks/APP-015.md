## 2. Background

### 2.1 现状：生活页的六个模块里，只有两个有真实数据落点

| 事实 | 证据 |
|---|---|
| `apps/mobile/` 工程尚未创建（`apps/` 下只有 `backend` / `frontend`） | `ls apps/` → `backend frontend` |
| **无产品级洞察接口**（模块摘要无来源） | `grep '"/insights"' apps/backend/app/api/v1/*.py` → 无输出；`requirements-analysis.md:170-174`（缺口 10） |
| **无面向用户的任务实体**（任务模块与备忘录计数无落点） | `requirements-analysis.md:157-162`（冲突 6）；`API-005` 建 `life_tasks` |
| **无备忘录域** | `requirements-analysis.md:106`（缺口表末行） |
| 日历 / 旅行模块设计稿列**产品阶段 P2**，本版本 🚫 | `traceability.md:51-52`；`requirements-analysis.md:270` |
| 健康模块依赖决策 D1（Phase 0 实机验证） | `tasks.md:78`、`tasks.md:196` |
| **V1 降级裁决**：不建独立备忘录域，备忘录类输入统一落任务域（`kind=memo`），模块卡显示任务域内 memo 计数 | `tasks.md:186`（APP-022） |
| `B4 #life` 结构与真实文案已冻结 | `components.md:343-353` |
| 「摘要必须是 AI 生成的动态结论，不是静态数字」 | `components.md:355` |
| `A17 capture` / `A18 mod` + `soon` 规格 | `components.md:171-176`、`:178-188` |

### 2.2 为什么必须做

1. **它是「生活模块化 Skill 容器」这一产品形态的可见证据。** 页面目的即「生活事务收纳处，设计重点是『可扩展』」（`traceability.md:91`）；「即将上线」占位与 Skill 商店位是**为扩展留的口**（`REQ-LIFE-03`）。**〔2026-10-03 IA 修订〕**该占位区已移除，页面现以「生活工具箱 + 长按模块卡设动态位」体现可扩展（新模块有真实页面才进宫格）。
2. **它是「AI 叙事优先」在二级页的落点。** 模块摘要若不是 AI 动态结论而是静态数字，页面就退化为「工具宫格」，与红线 3（卡片即结论）与红线 4（AI 叙事优先）冲突。
3. **它必须把本版本的三个降级裁决显式封口**（备忘录 / 日历 / 旅行 / 健康），否则实现时极易「顺手做全」——`tasks.md:186` 与决策 D1 是**反范围护栏**。
4. **它是 APP-022 的入口。** 快速捕获条的「一句话归位」由 `APP-022` 承接（`tasks.md:186`），本任务只做入口与回执落点。

### 2.3 在 V5.0.0 中的位置

M2 客户端第 3 个任务（`tasks.md:167`），依赖 `APP-007` 的组件与 `API-005` 的任务域；健康模块的深度由 M4 门控决定（决策 D1）。

   ✗ 不生成摘要（D1）
   ✗ 不实现日历 / 旅行内部（D3）
