## 2. Background

**三处都有"半个来源"，必须补读面而非新造数据源。**

| 需求 | 已有事实 | 证据 | 缺什么 |
|---|---|---|---|
| 本月自动记账笔数 | 账目带 `source` 字段，枚举含 `conversation` / `action` / `manual` / `import` | `app/services/tool/builtin.py:71`（`LEDGER_SOURCES`）；`app/models/ledger.py:75`（`LedgerEntry.source`） | 按 `source ∈ AI 来源` + 当月的**聚合读面** |
| 分类准确率 | 账目分类与人工修正链在服务层存在 | `app/services/ledger/correction.py`、`app/services/ledger/evidence.py` | **修正记录是否可枚举尚未证实** → 见 §4.2 裁决 2 |
| 待确认数 | `pending.list_pending(user_id).total`（`API-015`） | `app/services/ledger/pending.py:30/100` | 无 |
| 我学会的规则 | 分类行自带 `aliases` 与 `is_seed` | `app/models/ledger.py:52-61`（`LedgerCategory.aliases` / `is_seed`）；`category.py:106`（`add_alias`） | 「用户学到的规则」**读面**（`GET /ledger/categories` 只返全量分类，不区分是否学到） |
| 修正次数（「修正 3 次后学会」） | **无任何计数落点** | 全仓无「修正次数」字段 | ⚠️ **无来源**（缺口 20） |
| 备注 → 分类预览 | 归类能力完整 | `category.py:30-36`（`normalize(user_id, hint, *, kind, now) -> NormalizationResult`）、`category.py:14-20`（`NormalizationResult` 五字段） | 只缺 HTTP 出口 |

**为什么必须做**：33 页的 AI 提示条（`pages/33-ledger-add.html:136-139`）与 34 页的统计三卡（`pages/34-ledger-auto.html:126-130`）、规则区（`:170-175`）、31 页双入口副文案（`pages/31-ledger.html:151`）四处**都要求带数字的 AI 结论**。没有真实来源就只能造假，违反 `APP-014` 红线。

## 3. Scope

### 3.1 In Scope

1. `GET /ledger/auto-summary`：当月 `auto_count` / `accuracy`（有条件）/ `pending_count` / `by_category`（AI 记账的分类分布）。
2. `GET /ledger/rules`：用户已学会的规则（非 seed 分类的 `aliases`）+ 每条的目标分类。
3. `GET /ledger/classify-preview?note=&kind=`：调 `category.normalize` 返回预览结论（**不落账、不写库**）。
4. 三端点**零 `app/repositories` 依赖**（服务层封装）。
5. 端上可安全消费的**缺省语义**（无法真实取得的字段一律缺省）。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | **编造 `accuracy` 或 `learned_from`（修正次数）** | 决策 D14 / 缺口 20：无真实来源的字段必须缺省；`APP-014` 红线（`progress-audit-2026-09-29.md` §2.1） |
| 2 | 自动同步来源（微信 / 支付宝 / 银行卡短信）的任何数据面 | 平台不可行（缺口 19 / D14），本任务不为其建接口 |
| 3 | 「AI 学会了新规则」的**写路径** | 写面归 `API-015`（确认时 `add_alias`）；本任务只读 |
| 4 | 历史趋势 / 跨月对比 / 图表数据 | 设计稿本页无趋势图（`pages/34-ledger-auto.html` 只有三个 stat 卡）；加了属范围扩张 |
| 5 | 备注 → 分类的**自动写入**（不预览直接改分类） | 预览是"提示不喧宾夺主"（`components.md:568`），自动写入会夺走用户决定权 |
| 6 | 分类准确率的**口径调参**（阈值/窗口配置项） | 新增设置项违反 `tasks.md` §0.2；先由真实派生值决定是否可出该字段 |

## 4. Technical Design Requirements

### 4.1 接口契约（字段级）

#### 4.1.1 `GET /ledger/auto-summary`

| 参数 | 类型 | 缺省 | 说明 |
|---|---|---|---|
| `period` | `"month"` \| `"week"` | `"month"` | 复用 `/ledger/summary` 的期间口径（`ledger.py:44-56` 的 `PeriodResponse`） |

响应：

| 字段 | 类型 | 语义 | 缺省规则 |
|---|---|---|---|
| `period` | object | `{since, until, label}`（同 `ledger.py:25-28`） | 必出 |
| `auto_count` | int | 期间内 `source ∈ {conversation, action}` 的条数 | 必出（0 是合法值） |
| `accuracy` | float \| null | 分类准确率 | ⚠️ **`null` 或缺省**——见 §4.2 裁决 2；**禁止填 0 / 1 或估算值** |
| `pending_count` | int | `pending.list_pending(user_id).total` | 必出 |
| `by_category` | list[{`category_id`,`category_name`,`net_minor`,`count`}] | AI 记账的分类分布（供 34 页无图表时留白或后续复用） | 必出（可空数组） |
| `generated_at` | str(ISO8601) | 生成时刻 | 必出 |

#### 4.1.2 `GET /ledger/rules`

响应：

| 字段 | 类型 | 语义 |
|---|---|---|
| `generated_at` | str(ISO8601) | — |
| `total` | int | 规则条数 |
| `items` | list | 见下 |
| `items[].keyword` | str | 学会的关键词 / 别名（来自 `LedgerCategory.aliases`） |
| `items[].category_name` | str | 目标分类名 |
| `items[].category_id` | str | 目标分类 id |
| `items[].learned_from` | str \| null | 「修正 N 次后学会」的计数口径。⚠️ **无真实来源时缺省**（缺口 20）；端上缺省即不渲染该 hint |

**口径**：只返 `is_seed=False` 且 `aliases` 非空的分类行（`models/ledger.py:59`）；种子别名（如 `交通/加油` 的「洗车」「充电桩」，`ledger_categories.py:12`）**不算"学会的规则"**，必须排除，否则会把出厂规则说成用户习惯。

#### 4.1.3 `GET /ledger/classify-preview`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `note` | str | ✅ | 备注文本；空白 → 返回 `matched=false` 而非 422 |
| `kind` | `"expense"` \| `"income"` | ❌ 默认 `expense` | 透传 `category.normalize(kind=...)`（`category.py:34`） |

响应：

| 字段 | 类型 | 语义 |
|---|---|---|
| `matched` | bool | 是否命中（空白备注 / 未命中 → `false`） |
| `category_id` | str \| null | 命中分类 id（`NormalizationResult.category_id`） |
| `category_name` | str | 命中分类名或兜底名（`category.py:38-39` 的 `ledger_category_fallback`） |
| `confidence` | float | `NormalizationResult.confidence`（未命中为 0.1，`category.py:47`） |
| `reason` | str | `NormalizationResult.reason`（可解释来源，**须原样下发**） |
| `is_fallback` | bool | 是否落到兜底分类（`reason` / `confidence` 派生） |

**只读性硬约束**：本端点**不得写库**（不 `add_alias`、不落账、不改分类），必须由用例断言。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **「AI 自动记账」= `source ∈ {conversation, action}`** | `LEDGER_SOURCES`（`builtin.py:71`）四值中，`manual` 是手动（33 页路径）、`import` 是导入；AI 自动记账只可能来自对话链路或 action 执行 |
| 2 | **`accuracy` 无真实来源时不出现该字段，端上整卡省略** | 修正记录是否可枚举须在实现时以 `app/services/ledger/correction.py` / `evidence.py` 求证；**求证不通过就删掉这个 KPI**，而不是填一个好看的数字（缺口 20 / D14） |
| 3 | **`learned_from` 同理：无计数则缺省** | 设计稿 `.html:170` 的 `.hint`「来自你的 9 次修正」改为无数字措辞（如「来自你的分类修正」）；**不编造次数** |
| 4 | **规则区必须排除种子别名** | `ledger_categories.py:2-39` 的种子别名是出厂配置；把它们说成"我学会的"是误导性陈述，与 `SKILL.md:52` 的诚实口径同类问题 |
| 5 | **`classify-preview` 严格只读** | 预览若产生副作用，用户"想一想"就改变了数据；且会让 33 页的输入过程产生隐式写路径 |
| 6 | **`question` / 文案不由本任务下发** | 与 `API-015` 裁决 4 一致：澄清问句已由 `confirmation.py:44-56` 模板渲染；预览只返结构化结论 + `reason` |

### 4.3 数据流

```text
GET /ledger/auto-summary
  ledger.py → ledger_stats_service.auto_summary(user_id, period)
    ├─ query_service 聚合 entries（source ∈ AI 来源，期间内）      # 复用既有查询层
    ├─ pending.list_pending(user_id).total                        # 跨任务复用（API-015）
    └─ correction/evidence 求证 accuracy（可枚举则派生，否则 None）

GET /ledger/rules
  ledger.py → category.list_learned_rules(user_id)
    → ledger_repository.list_categories(user_id) 过滤 is_seed=False 且 aliases 非空

GET /ledger/classify-preview
  ledger.py → category.normalize(user_id, note, kind=kind)         # 纯读，零副作用
    → 映射为 {matched, category_id, category_name, confidence, reason, is_fallback}
```
