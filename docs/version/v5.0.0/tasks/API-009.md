### 2.2 为什么必须做

1. **它是健康模块的唯一数据底座，也是「数字永不由 LLM 生成」铁律的落点。** 主路径「手环 → Mi Fitness → Health Connect / HealthKit → ingest → `health_*` 三件套（**不进 memory**）→ Agent 解读」；LLM 只做解读，**永不生成 / 复述测量数字**（`REPORT.md:63-75`、`:71`、`:38`、`:186`）。
2. **它是第三个结构化事实域**（继用户实体、账本之后）：精确、append-only、可对账、可纠正（`REPORT.md:38`、`:171`）。
3. **最大工程风险是「命名撞车」与「迁移钉测」**（`requirements-analysis.md:99`；`tasks.md:40`，风险 R3）；**可行性前提尚未闭合**（Mi Fitness 国内版是否原生写入系统健康平台，`REPORT.md:87`），故**受 `PLT-001` 门控**（`tasks.md:194`）。

### 2.3 在 V5.0.0 中的位置

M4 后端第 1 个任务，位于 `PLT-001 → API-009 → API-010 → APP-024` 链首（`tasks.md:226-228`）；是 M4 验收口径「真机授权后首页三宫格显示真实数据且标注来源」的服务端前提（`tasks.md:206`）。

## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 `health_*` 三件套表结构（字段级）

> 同构账本三件套范式：**来源（当前态）+ 样本（append-only 时序）+ 日聚合（快照）**（`REPORT.md:171`）。三表**均含 `user_id`**（裸字符串，不加 FK，§4.2.1 D3）。

| 表 | 列 | 类型 | 约束 / 缺省 | 语义 |
|---|---|---|---|---|
| `health_sources` | `id` / `user_id` / `character_id` | `String` | PK / NOT NULL / NOT NULL（默认 `"asuna"`） | 来源 id / 分区键 / 角色归属 |
| | `source_kind` | `String` | NOT NULL，CHECK | `mi_fitness` / `health_connect` / `healthkit` / `manual` / `csv_import` |
| | `platform` | `String` | NOT NULL，CHECK | `android` / `ios` / `unknown` |
| | `device_model` / `authorized_scopes` | `String` / `JSON` | NULL | 如 `小米手环 9 Pro`（供 `A23 src-note`）/ 已授权字段清单（**只记展示所需字段**） |
| | `status` | `String` | NOT NULL，默认 `"active"`，CHECK | `active` / `revoked` |
| | `last_synced_at` / `created_at` / `updated_at` | `DateTime` | NULL / NOT NULL / NOT NULL | 时间戳 |
| `health_samples` | `id` / `user_id` / `source_id` | `String` | PK / NOT NULL / NOT NULL（**裸字符串，不加 FK**） | 样本 id / 分区键 / 指向 `health_sources.id` |
| | `metric` | `String` | NOT NULL，CHECK | §4.1.2 冻结值域 |
| | `value_num` / `unit` | `Float` / `String` | NOT NULL | 数值（**由端侧平台给出，LLM 不参与**）/ 单位（`min`/`bpm`/`count`/`percent`/`ms`） |
| | `started_at` / `ended_at` / `granularity` | `DateTime` / `DateTime` / `String` | NOT NULL / NULL / NOT NULL，CHECK | 窗口起止（样本型可空）/ 粒度 `sample` / `session` / `daily` |
| | `idempotency_key` | `String` | NOT NULL | **幂等键**（§4.1.3，唯一索引） |
| | `raw_ref` / `created_at` | `JSON` / `DateTime` | NULL / NOT NULL | 原始载荷引用（**不存原始明细进 Prompt**，`REPORT.md:178`）/ 落库时刻（**只增不改**） |
| `health_daily_rollups` | `id` / `user_id` / `rollup_date` | `String` / `String` / `Date` | PK / NOT NULL / NOT NULL | 聚合 id / 分区键 / 聚合日期（用户本地时区） |
| | `metric` / `value_num` / `unit` | `String` / `Float` / `String` | NOT NULL | 指标 / 当日聚合值 / 单位 |
| | `sample_count` | `Integer` | NOT NULL，默认 `0` | 参与聚合的样本数（可对账） |
| | `source_id` / `computed_at` | `String` / `DateTime` | NOT NULL | 主来源（裸字符串）/ 重算时刻（**可复算**） |
| | `created_at` / `updated_at` | `DateTime` | NOT NULL | 时间戳 |

**索引（4 个）**：`ux_health_samples_idempotency`（`idempotency_key`，**unique**，幂等核心）、`ix_health_samples_user_metric_time`（`user_id, metric, started_at`）、`ix_health_rollups_user_date`（`user_id, rollup_date`）、`ux_health_rollups_user_date_metric`（`user_id, rollup_date, metric`，**unique**，日聚合唯一）。

**CHECK 约束（6 条，全部为完整布尔式）**：`ck_health_sources_kind`（`source_kind IN (...)`）/ `ck_health_sources_status`（`status IN ('active','revoked')`）/ `ck_health_sources_platform`（`platform IN ('android','ios','unknown')`）/ `ck_health_samples_metric`（`metric IN (<§4.1.2 值域>)`）/ `ck_health_samples_granularity`（`granularity IN ('sample','session','daily')`）/ `ck_health_samples_window`（`ended_at IS NULL OR ended_at >= started_at`，沿 `ck_insights_invalidated_reason` 一致性写法）。

#### 4.1.2 `metric` 值域（**门控冻结**）

| `metric` | 单位 | 粒度 | 说明 |
|---|---|---|---|
| `sleep_duration` / `sleep_deep_ratio` | `min` / `percent` | `session` / `daily` | 睡眠时长 / 深睡占比（**只作参考，不作诊断**） |
| `resting_hr` | `bpm` | `daily` | 静息心率（`REQ-HLTH-04`） |
| `steps` / `active_minutes` | `count` / `min` | `daily` | 步数 / 运动分钟（`REQ-HLTH-04`） |
| `hrv` / `spo2` / `stress` | `ms` / `percent` / `count` | `daily` | 趋势参考（`spo2` **禁诊断语义**，`REPORT.md:99`） |

> 🚨 **值域由 `PLT-001` 结论冻结**：`PLT-001` 输出的「可同步字段清单」决定上表**实际子集**；未证实可同步的 `metric` **不得**进入值域（避免造数）。此表为**待门控冻结**的候选集。

#### 4.1.3 ingest 工具契约（`builtin.health.sync`）

| 项 | 契约 |
|---|---|
| 工具 id | `builtin.health.sync`（照 `REPORT.md:70`、`tasks.md:200` 原文；工具 id 命名空间 `builtin.*` 与模块路径无关，**不构成命名撞车**） |
| 接入方式 | 走**既有工具系统**（`services/tool/` 五段执行）+ **既有 Action 台账**（`action_records`）；**不建第二套 Agent**（`tasks.md:30`） |
| 输入 | `source_kind`（必填）、`platform`（必填）、`window_start` / `window_end`（必填，ISO 8601）、`metrics[]`（可空 = 全部已授权 metric）、`device_model`（可空） |
| 输出 | `{source_id, ingested, skipped_duplicates, rejected, last_synced_at}` |
| **幂等键** | `sha256(user_id \| source_kind \| metric \| started_at \| ended_at \| value_num)` 的**确定性摘要**；同键**只落一行**（唯一索引兜底并发） |
| 幂等语义 | 重复调用同一窗口 → `ingested=0`、`skipped_duplicates=N`，`health_samples` 行数**不变** |
| 日聚合 | ingest 后**重算受影响日期**的 `health_daily_rollups`（`upsert`，`computed_at` 更新，`value_num` 可复算）；**零 LLM** |
| 失败处置 | 单条样本非法（越界 / 缺单位）→ 计入 `rejected` 并**跳过**，**不整批失败**；来源登记失败 → 抛错（不静默） |
| 过程可见 | ingest 过程步骤走 `API-002` 的**独立通道**，**不进 `loop_runs.steps`**（`tasks.md:29`） |
| 身份 | `user_id` 由既有身份机制解析（`API-001` 落地后走 token）；请求中的 `user_id` **拒绝** |

#### 4.1.4 设置字段（参数类，非开关）

| 字段 | 默认 | 语义 | env 名 |
|---|---|---|---|
| `vitals_ingest_window_days` | `7` | ingest 默认回溯窗口（天） | `VITALS_INGEST_WINDOW_DAYS` |
| `vitals_ingest_max_samples` | `2000` | 单次 ingest 样本硬上限（超出 → 拒绝，不静默截断） | `VITALS_INGEST_MAX_SAMPLES` |

> **纪律**：`env 名 = 字段名大写`（`tasks.md:27`）；**禁** `*_enabled` 形态（裁决 9）。

#### 4.1.5 ingest 薄端点契约（`POST /api/v1/health/ingest`）

| 项 | 契约 |
|---|---|
| 端点 | `POST /api/v1/health/ingest`（`api/v1/health_ingest.py::health_ingest_router`） |
| 请求 | `{source_kind, platform, window_start, window_end, metrics[]?, device_model?, samples[]}`；`samples[]` 为端侧读出的样本（`metric` / `value_num` / `unit` / `started_at` / `ended_at` / `granularity`） |
| 响应 | 与工具输出同构：`{source_id, ingested, skipped_duplicates, rejected, last_synced_at}` |
| 处理 | 薄端点**只做**：身份解析（拒绝请求中的 `user_id`）+ 参数校验（`metric` 值域 / 窗口 / 样本数上限）→ **转发到 `builtin.health.sync`**；业务逻辑全在 `services/vitals` |
| 幂等 | 与工具同款幂等键（§4.1.3）；端侧重试同一批 → `ingested=0` |
| 未授权字段 | 请求中出现**未授权 scope** 的 `metric` → **拒绝该样本**（计入 `rejected`），**不上传**（`APP-023` 对侧约束） |
| 错误语义 | `422` 参数非法；`403` 越权；**不透传堆栈**；`health_ingest.py` **零 `app.repositories` / langchain / `app.core.db` 依赖** |

> **为什么需要这个薄端点**：`builtin.health.sync` 是**后端工具**，无法自行读取端侧 Health Connect / HealthKit；端侧样本必须经一条**受治理**的上行通道进入工具。该端点是**唯一**通道，且**不承担业务逻辑**（保持「零 `repositories` 反向依赖」与「不建第二套 Agent」两条铁律）。
