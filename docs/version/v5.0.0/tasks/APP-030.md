## 3. Scope

### 3.1 In Scope

1. 建 `features/car/{data,domain,presentation}`（三层齐备，否则 `layer_guards_test.dart:20` 红）。
2. `data/car_repository.dart`：**自建数据面直连后端**（禁 import `features/ledger`）；方法 `fetchOverview()` / `createEntry(...)` / `fetchProfile()` / `updateProfile(...)` / `fetchServices()`。
3. `car_page.dart`：照 B12 的 12 段。
4. 路由 `/car`（`chromeImmersive`）+ `_tabIndex` 归「生活」Tab。
5. `layer_guards_test.dart:32-41` 的 domain 清单追加 `car`。
6. 消费 `APP-042` 的 `LoanCard` 与既有 `MetricCard` / `CategoryBar` / `TxRow`。
7. 区块级降级：`degraded_blocks` 非空时对相应区块显示诚实缺省态。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | 档案编辑 UI（录入表单） | 归 `APP-032`（39 页）；本页只放档案**入口**（`pages/35:189-193`） |
| 2 | 养车记一笔的表单 | 归 `APP-031`（36 页） |
| 3 | **端上聚合 / 端上派生**（车贷剩余、电耗、提醒） | `API-020` 已在服务端派生（§4.2 裁决 2）；端上再算会产生两套口径 |
| 4 | 限行的城市数据 / 尾号推断 | 决策 D19（用户配置）；本页只展示服务端下发的提醒项，**未配置时不造数据** |
| 5 | 里程/充电的趋势图表 | 无设计要求 |
| 6 | 车辆档案的本地缓存（drift） | 复用会引入已死通道（`progress-audit` §7.6）；本页用内存态 |

## 4. Technical Design Requirements

### 4.1 页面契约（照 `components.md:589-606` B12）

| # | 段 | 组件 | 数据 |
|---|---|---|---|
| 1 | 返回 | `BackLink` | 「‹ 生活」 |
| 2 | 车贷卡 | **`LoanCard`（A34）** | `loan.*`；空态时**整段不渲染**（无车贷用户） |
| 3 | AI 观察卡 | `AiCard` | 服务端下发结论文案 |
| 4 | 区块标题 | `_SectionTitle` | 「电车状态」+ hint 期间 |
| 5 | 指标三卡 | `MetricCard` ×3 | `ev_metrics.charge_kwh_month` / `kwh_per_100km` / `odometer_km`（+ 本月增量） |
| 6 | 区块标题 | `_SectionTitle` | 「本月养车支出」+ hint 合计 |
| 7 | 分类条 | `CategoryBar` × N | `expense_breakdown`（**只渲染有值的项**，`API-019` §4.2 裁决 5） |
| 8 | 区块标题 | `_SectionTitle` | 「车辆提醒」+ hint「我会提前告诉你」 |
| 9 | 提醒行 | 既有 `SettingRow` / 行组件 | `reminders`；未配置限行时**不出现该项** |
| 10 | 区块标题 | `_SectionTitle` | 「最近记录」+ hint「AI 自动分类」 |
| 11 | 记录行 | `TxRow` | `recent_records`（费用行带负号金额；里程行显示 `km` 而非金额） |
| 12 | 两入口 | `BackLink` 样式入口 + `LedgerSaveButton` 变体 | 「车辆档案」→ `/car/profile`；「记一笔养车费用」→ `/car/add` |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **car 域自建数据面，禁 import `features/ledger`** | `layer_guards_test.dart:49`；先例 `life_repository.dart` / `chat_ledger_repository.dart` |
| 2 | **必须在 `layer_guards_test.dart:32-41` 登记 `car`** | 该清单是硬编码的，不登记即测试红（守卫的设计意图就是强制新域显式登记） |
| 3 | **车贷卡的进度填充只能来自 `APP-042` 的 `LoanCard`** | 组件内已锁定 warm 渐变（`APP-042` §4.2 裁决 1）；页面自绘会破坏该禁令 |
| 4 | **里程行与费用行分型渲染** | `pages/35:186` 的里程行显示 `38 km`（非金额）；统一按金额渲染会显示 `-0` |
| 5 | 无车贷 / 无档案时**整段缺省**而非占位 | 延续 `APP-014` 空态先例；占位会让人误以为"有车贷但没数据" |
| 6 | 限行项缺省时**不显示引导文案之外的任何内容** | D19；不得出现尾号数字 |

### 4.3 数据流

```text
进入 /car
  → repository.fetchOverview()        GET /car/overview      # 单请求拿全页
  → 渲染 12 段；degraded_blocks 非空的块走诚实缺省
点「记一笔养车费用」→ push /car/add
  → 36 页保存成功 pop(true)
  → 本页再次 fetchOverview()          # 支出与记录立即一致
点「车辆档案」→ push /car/profile
```
