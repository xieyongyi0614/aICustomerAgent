**实际后果**：设计原则第二条「**记忆可见**——AI 记住了什么、为什么记住，对用户永远透明」目前**没有产品出口**（`requirements-analysis.md:41`）。「记住 → 帮到 → 更信任」的飞轮（`traceability.md:125`）转不起来。

### 2.2 为什么必须做

1. **D5 是本版本已裁决的口径，但代码层面尚不成立。** D5 原文：「记忆页只展示 **active 且未 forgotten** 的条目；标题写『我记住了你 N 件事』；『遗忘』= 置 `forgotten`；『一键清空』= 走 `/life/data`。**200 上限与衰减机制不向用户暴露**」（`requirements-analysis.md:375`、`tasks.md:79`）。现有 `/memories` 三条都不满足。
2. **`APP-017` 的字段契约等本任务冻结**：`source_kind` / `source_count` / `last_updated` / `usage_receipts[]` / `kind`（`APP-017` §4.1.4、§4.1.7、§4.4）。`kind` 枚举未冻结前，端上只能「按内容关键词猜分组」——这正是 `APP-017` 明令禁止的。
3. **它是 `API-004` 的输入之一**：首页 `ai_summary` 的跨域合成要读记忆域（`tasks.md:154`、`tasks.md:240`）。**风险点是「写路径」**：记忆域是 V4.0.0 **Preserve** 面（`docs/version/v4.0.0/tasks.md:87-96` 裁决 5）——新接口若图省事直写 `memories`，就违反「**不直写 `memories`**」铁律（`tasks.md:286`）与「域唯一写面」纪律（`tasks.md:30`）。

### 2.3 在 V5.0.0 中的位置

M2 后端第 4 个任务；与 `API-005`（任务域）/ `API-006`（洞察读面）并列为 `API-004`（首页聚合）的三条输入线（`tasks.md:240`）。它把设计原则第二条从理念变成可验收的产品面。

## 3. Scope

### 3.1 In Scope

1. `GET /api/v1/memory/items` —— 分组列表 + 同口径计数（D5 口径，只含 `active`）。
2. **`kind` 四分组枚举冻结**（长期偏好 / 习惯 / 目标 / 当下）+ 9 个记忆类型 → `kind` 的**全量映射表**（§4.1.3），端上零猜测。
3. **`source_kind` / `source_label` / `source_count` / `last_updated`** 四个来源追溯字段（§4.1.4），全部由 `source_ref` / `merge_chain` / `updated_at` **确定性派生**，零 LLM。
4. **`usage_receipts[]` 用途回执**（§4.1.5）—— 从 `runtime_traces` 的 `memory_retrieve_v2` 步派生，按 `trace.kind` 区分用途，**零编造**。
5. `PATCH /api/v1/memory/items/{memory_id}` —— 逐条**编辑**（仅内容 / 重要度；不改 `type` / `status` / `source`）。
6. `POST /api/v1/memory/items/{memory_id}/forget` —— 逐条**遗忘**（置 `forgotten`，**不硬删**，可审计，幂等）。
7. 新模块 `app/services/memory2/product_view.py`：产品读面 + 用户写面，**委托**域内既有写面（`lifecycle.explicit_forget`）。
8. 端点注册与响应模型（`router.py` + `schemas.py` 追加）。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不做「一键清空」** | D5 明确「一键清空 = 走 `/life/data` 服务端删除」（`requirements-analysis.md:375`）；该端点**已存在**（`governance.py:62`，要求 `confirm=true`），本任务重复实现会造成两条删除路径 |
| 2 | **不做硬删 / 物理删** | 与「遗忘可审计」（`tasks.md:157` 验收 ③）直接冲突；物理清理由既有 `lifecycle.purge_expired_forgotten` 在保留期后执行（`services/memory2/lifecycle.py:232`），**不在本任务** |
| 4 | **不给 `memories` 加列 / 改 CHECK / 加索引** | `memories` 属 Preserve（`docs/version/v4.0.0/tasks.md:87`）；本版本只允许 1 个迁移（`tasks.md:37`）；加列会触发 `SCHEMA_COLUMNS_DIGEST` 与 `ck_memories_type` 钉测 |

| 6 | **不新建记忆生成路径** | 生成仍走 `memory2/ingest.py` / `commands.py`（摄取 + 命令通道）；本任务是**读面 + 用户写面**，不建第二套摄取（`tasks.md:30`「不建第二套 Agent」） |
| 8 | **不做记忆的「新增 / 手工创建」** | 记忆由摄取与对话产生（`memory2/ingest.py`）；产品页只允许**改**与**忘**（`REQ-MEM-05` 原文「逐条编辑 / 遗忘」，`requirements-analysis.md:292`） |
| 9 | **不引入新第三方依赖** | 读面只用既有 `SessionLocal` / `trace_repository`；`services` 层不得 import `app.application`（`tasks.md:287`） |

## 4. Technical Design Requirements

### 4.1 接口契约

> 前缀 `/api/v1`；身份经 `API-001` 的 `Depends(require_user)`（`user_id` **仅从 token 解析**）。请求体 / query 中若出现 `user_id` 且与令牌不符 → **403**「不得读写他人数据」（沿用 `ledger.py:145` 文案）。

#### 4.1.1 `GET /memory/items`

| 方向 | 字段 | 类型 | 必填 | 语义 / 缺省 |
|---|---|---|---|---|
| 请求 | `limit` | `int` | 否 | 缺省 **200**、`ge=1`、`le=200`（= 记忆域 active 软上限，见 §4.1.9） |
| 响应 | `generated_at` | `string` | — | ISO 8601（本地时区），本次合成时刻 |
| 响应 | `total` | `int` | — | **同口径全量条数**（= 各组 `items` 长度之和；D5 口径） |
| 响应 | `added_this_week` | `int` | — | 本周新增条数（`created_at ≥ 本周一 00:00 本地`），对应原型「本周 +6」 |
| 响应 | `groups` | `object[]` | — | **固定 4 组**，顺序冻结：`preference` → `habit` → `goal` → `now`（见 §4.1.3） |
| 响应 | `degraded` | `bool` | — | 回执派生失败时 `true`（**列表照常返回**，见 §4.1.5） |

> `groups[]` 元素：`{kind, label, items[]}`——`label` 为分组中文标题（服务端下发：长期偏好 / 习惯 / 目标 / 当下）；空组返回 `items: []`（**不省略组**，端上据此渲染空态，不留白）。

#### 4.1.2 记忆项字段（`groups[].items[]`）

| 字段 | 类型 | 语义 / 派生规则 |
|---|---|---|
| `id` | `string` | `memories.id` |
| `kind` | `string` | 分组枚举（§4.1.3，由 `memories.type` 派生） |
| `type` / `type_label` | `string` | 记忆类型（9 值之一，遗留类型**归一化**为 7 规范值，`memory2/types.py:31-37`）+ 类型中文标签（偏好 / 习惯 / 目标 / 关系 / 近况 …），**服务端下发**（`APP-017` §4.1.3 据此选配色） |
| `content` | `string` | 记忆正文（`memories.content`） |
| `source_kind` / `source_label` | `string` | 来源枚举（§4.1.4）+ 来源中文短语（如「对话提及」「任务完成时间统计」），**服务端下发** |
| `source_count` | `int` | 被观察次数，`≥1`（§4.1.4） |
| `last_updated` | `string` | ISO 8601 = `memories.updated_at`（端上经 `intl` 格式化为 `M/D`，`APP-017` §4.1.4） |
| `usage_receipts` | `object[]` | 用途回执（§4.1.5）；**可为空数组**（不伪造） |

> **不含**：`status` / `salience` / `confidence` / `importance` / `embedding` / `superseded_by` / `merge_chain` / `forgotten_at`。前四项暴露即违反 D5（上限与衰减不暴露）；后四项是机制细节（`APP-017` §4.1.6「不向用户暴露机制」）。

#### 4.1.3 `kind` 分组映射（★ 冻结；端上**不得**按关键词猜）

| `memories.type`（存储 9 值） | `kind` | `label` | `type_label` |
|---|---|---|---|
| `user_preference` | `preference` | 长期偏好 | 偏好 |
| `behavior_pattern` | `habit` | 习惯 | 习惯 |
| `commitment` / `milestone_event` | `goal` | 目标 | 目标 |
| `user_fact` / `experience` / `important_event`（遗留 → `experience`） | `now` | 当下 | 近况 |
| `relationship_fact` / `relationship_event`（遗留 → `relationship_fact`） | `now` | 当下 | 关系 |

**映射纪律**：① 覆盖 `ck_memories_type` 的**全部 9 值**，无兜底分支、无 `else` 默认组（漏映射须**显式失败**并记日志，而非静默塞进「当下」）；② 映射表为模块内**常量**，可被用例逐条枚举（§7.1）；③ 端上只读 `kind` / `label` / `type_label`，**零本地映射**。

#### 4.1.4 来源追溯三字段的派生规则（★ 确定性、零 LLM）

**`source_kind`**（枚举 11 值）= 优先取 `memories.source_ref["table"]`；`source_ref` 缺失时回退 `memories.source`：

| `source_kind`（来源表，`memory2/ingest.py:21-26` / `commands.py:26` / `ledger/memory_bridge.py:18`） | `source_label` |
|---|---|
| `conversation` / `action_records` / `world_events` / `relationship_events` / `relationship_milestones` / `character_goals` | 对话提及 / 任务完成 / 生活事件 / 相处经历 / 关系里程碑 / 目标达成 |
| `commands` / `ledger_insights` | 你直接交代 / 记账观察 |
| `user_stated` / `user_derived` / `ai_inferred`（`source_ref` 缺失时的回退，`core/db.py:115-117`） | 你亲口说过 / 从对话里整理 / 我自己留意到的 |

**`source_count`** = `1 + len(memories.merge_chain or [])`：`merge_chain` 是**同主题合并链**（`services/memory2/lifecycle.py:316-318`，每次合并 `append(target.id)`），即「同一件事被反复观察」的次数——首次观察 = 1，被合并 5 次 = 6 → 端上渲染「**6 次对话提及**」（对齐 `APP-017` §4.1.4 示例）；`None` → `1`（**不返 0**，`≥1` 是硬约束）。

**`last_updated`** = `memories.updated_at`（`update_memory_content` 与 `explicit_forget` 均会更新该列，`memory_repository.py:199`）。

#### 4.1.5 `usage_receipts[]` 用途回执（★ 有真实来源，零编造）

**唯一数据源**：`runtime_traces` 中 `steps[].name == "memory_retrieve_v2"`（`retriever.py:26`）且该步 `extra.returned[]` / `extra.memory_ids[]` / `extra.memory_id` / `extra.target_id` 命中本记忆 id（命中语义对齐既有 `attribution.py:184-194`）。

| 项 | 契约 |
|---|---|
| 回执条目 | `{kind, label, ts, ref}`；`ts` = `trace.started_at`（ISO 8601），`ref` = `trace.turn_id`（无则 `null`） |
| `kind` / `label` 映射 | `trace.kind == "turn"` → `recall_turn` /「已用于对话」；`== "autonomy_tick"` → `recall_autonomy` /「**已用于任务排序**」；`== "proactive"` → `recall_proactive` /「已用于主动关心」 |
| 依据 | `RuntimeTraceRow.kind` CHECK 恰为 `('turn','proactive','autonomy_tick')`（`core/db.py:890-893`）；规划上下文经同一检索器（`services/planning/context.py:609`），故 `autonomy_tick` 即「用于排序 / 规划」 |
| 窗口 / 去重 | 最近 **30 天**（常量 `RECEIPT_WINDOW_DAYS = 30`；沿用既有 `list_since(cutoff, limit=2000)` 读法，`attribution.py:151-154`）；每个 `kind` 只留**最新一条**（最多 3 条） |
| **无回执 / 降级** | 无命中 → `[]`，端上**不渲染**回执段（`APP-017` §4.1.4「不得伪造」）；派生异常 → **不整体 500**：`usage_receipts: []` + 顶层 `degraded: true`（列表必须照常可用） |
| **禁** | 不得把「记忆被摄取」当作「被使用」（摄取 ≠ 使用）；不得用 `evidence_links`（那是 Insight 的证据链，方向相反） |

#### 4.1.6 `PATCH /memory/items/{memory_id}`（逐条编辑）

**请求**：`content`（`string`，必填，`len(strip()) ∈ [1, 500]`）+ `importance`（`float | null`，可选，缺省 `null` = **不改**，给值须 ∈ `[0,1]`）；越界 → **422**。
**响应**：`item`（同 §4.1.2 结构的更新后记忆项，端上原地替换）+ `updated_at`（ISO 8601）。

**只改内容，不改机制**：`type` / `status` / `source` / `source_ref` / `confidence` / `salience` **一律不变**——否则用户可通过编辑篡改「来源」与「置信度」，使「来源可追溯」失效。**不走** `supersede` / `invalidate`（编辑不是取代）。

#### 4.1.7 `POST /memory/items/{memory_id}/forget`（逐条遗忘）

**响应**：`{id, status: "forgotten", forgotten_at}`——`forgotten_at` 为 ISO 8601，是**审计依据**。

| 场景 | 状态码 | 语义 |
|---|---|---|
| 成功（首次） | **200** | 置 `forgotten` + 清向量（同事务，`lifecycle.py:357-382` 既有语义） |
| **已 `forgotten`（重复调用）** | **200** | **幂等**（`TRANSITIONS` 含 `(forgotten, forget) → forgotten`，`lifecycle.py:71`）；`forgotten_at` 为**首次**时刻（不被覆盖） |
| id 不存在 | **404** | 对齐 `explicit_forget` 的 `False` 返回（`lifecycle.py:364-366`） |
| 越权（他人记忆） | **403** | **前置校验**：`row.user_id` 必须等于令牌 `user_id`（既有 `explicit_forget` **无 user 校验**，`lifecycle.py:362-363` 只 `session.get(Memory, memory_id)`） |
| 令牌缺失 / 无效 | **401** | `require_user` |

**不硬删**：**禁止**调用 `memory_repository.forget_memory` / `delete_memory`（`memory_repository.py:233-243`，二者等价于 `session.delete`）——硬删使「遗忘可审计」不成立，且绕过保留期与 `purge_expired_forgotten`（`lifecycle.py:232`）。

**可审计双证**：① `memories.forgotten_at` 非空；② `explicit_forget` 内 `_trace(..., event=EVENT_FORGET, memory_id=..., previous_status=...)` 落 `runtime_traces`（`lifecycle.py:371-380`）。

#### 4.1.8 统一错误语义（三个端点共用）

| 场景 | 状态码 | 语义 |
|---|---|---|
| 令牌缺失 / 无效 / 过期 | **401** | 由 `require_user` 统一处理（`API-001` §4.1.4） |
| `user_id` 与令牌不符 | **403** | 「不得读写他人数据」（沿用 `ledger.py:145` 文案） |
| id 不存在 **或** `status != "active"` | **404** | 两者**不区分**——403/404 之分会**确认 id 存在**，泄露 `forgotten` 条目（D5：遗忘后不可见于列表） |
| 参数越界（`content` 空 / 超长、`importance` 越界、`limit` 越界） | **422** | FastAPI 参数校验 |

#### 4.1.9 计数口径（★ 与列表同口径）

| 项 | 契约 | 依据 |
|---|---|---|
| `total` 口径 | `status == "active"`（即「active 且未 forgotten」——`forgotten` 是**状态值**而非独立标志位） | D5（`tasks.md:79`）；`TRANSITIONS` 六态（`lifecycle.py:41-72`） |
| `total` 与 `groups` 一致性 | `total == Σ len(groups[i].items)`；**同一份内存快照**内计算（单次查询后切片，不二次查库） | 冲突 4 的教训：口径不一致 → 「产品承诺与引擎行为打架」（`requirements-analysis.md:154`） |
| 为何无需额外 `COUNT` 查询 | active 软上限 **200**（`requirements-analysis.md:153`）；`limit=200` 时单次 `list_active(..., limit=200)` **即全量** → `total` 取长度即精确 | 避免新造仓储方法（`memory_repository` 无 count 方法） |
| `added_this_week` | `created_at ≥ 本周一 00:00（本地）` 的 active 条数；**同口径子集** | 原型「本周 +6」；D5 未禁止新增计数 |
| 空态 | `total == 0` → `groups` **仍返 4 组**（`items: []`） | 端上渲染空态、不留白（`APP-017` §4.1.2 空态纪律） |
