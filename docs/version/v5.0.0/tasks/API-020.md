## 3. Scope

### 3.1 In Scope

1. `app/api/v1/car.py`：5 端点（§4.1），内联 pydantic 模型（对齐 `ledger.py` 风格），`prefix="/car"`。
2. `app/services/car/reminders.py`：**纯函数**提醒派生（保养 / 车险 / 年检 / 限行），无 IO、可单测。
3. `app/core/settings/car.py`：3 个参数类设置（§1 交付面）。
4. `app/api/v1/router.py`：import + 注册一行（**纯追加**）。
5. 端点**零 `app/repositories` 依赖**；`user_id` 一律 `Depends(require_user)`。
6. 区块级降级：任一子块不可用时该块缺省，不整体 500。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | **推送投递** | 决策 D20：投递复用端侧本地通知（`APP-019`）；后端只给"什么时候该提醒" |
| 2 | **城市限行政策数据** | 决策 D19：限行由用户手动配置（`API-018` 的 `restriction_*` 列）；接入政策数据属反范围 #5 |
| 3 | 多车 / 车库选择 | `API-018` §3.2 #3（单车） |
| 4 | 车贷提前还款流程 | `API-018` §3.2 #7 |
| 5 | 电耗精确算法 | `API-019` §3.2 #4（本期为近似口径并显式标注） |
| 6 | 车辆费用进 car 域的独立端点 | 决策 D12：统一经 `API-019` 的 `record_car_expense` |
| 7 | 档案变更历史 / 审计视图 | 无设计诉求；档案是"当前状态"型数据 |
| 8 | 车辆导出 / 删除（隐私页联动） | 无设计要求；`/life/export` 与 `DELETE /life/data` 的域扩展属独立决策 |

## 4. Technical Design Requirements

### 4.1 接口契约（字段级）

#### 4.1.1 `GET /car/overview`（35 页，单请求）

| 字段 | 类型 | 语义 | 来源 |
|---|---|---|---|
| `profile` | object \| null | 档案摘要（`model` / `plate` / `odometer_km`） | `car_profiles` |
| `loan` | object \| null | `{remaining_minor, monthly_minor, paid_periods, total_periods, next_due_at, settled_at, paid_ratio}` | `car_loans` + **派生**（`API-018` §4.2 裁决 4） |
| `ev_metrics` | object | `{charge_kwh_month, kwh_per_100km, odometer_km, odometer_delta_month}` | 档案 + 记账（充电度数）+ 里程 |
| `expense_breakdown` | list | 养车子类目（`API-019` §4.1） | `car_expense_breakdown` |
| `expense_total_minor` | int | 合计 | 派生 |
| `reminders` | list | `[{kind: service\|insurance\|inspection\|restriction, title, detail, due_at?, due_km?, level: normal\|soon}]` | `reminders.py` |
| `recent_records` | list | `API-019` §4.1 的混排视图（≤ 10 条） | `car_recent_records` |
| `degraded_blocks` | list[str] | 不可用区块名（区块级降级留痕） | 编排层 |

#### 4.1.2 `GET /car/profile`（39 页）

| 字段 | 类型 | 语义 |
|---|---|---|
| `identity` | object \| null | `{model, plate, trim_note, battery_kwh, age_text, purchased_at, odometer_km}`（`age_text` 由 `purchased_at` **派生**） |
| `files` | list | 四档案行：保险 / 年检 / 充电桩 / 保养周期（`pages/39:146-168`），每项 `{key, label, detail, value_text, due_at?}` |
| `loan` | object \| null | 同 §4.1.1 |
| `services` | list | 保养记录时间线（`API-019` 的档案行 + 记账回链）；**末行必须是「下一次保养」未发生态**（`components.md:385`） |
| `reminders` | list | 同 §4.1.1 |

#### 4.1.3 `PUT /car/profile`（档案写入）

请求体：`identity` / `files` 的可写子集 + `loan` 可写子集 + `restriction`（`{city, digits, weekday}`）。**全字段可选**（部分更新）；一次性 upsert `car_profiles`（+ `car_loans` 若传）。

**错误语义**：`battery_kwh <= 0` / `odometer_km < 0` / `paid_periods > total_periods` → **422**。

#### 4.1.4 `POST /car/entries`（36 页，六类型记一笔）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `kind` | `"charge"\|"fuel"\|"mileage"\|"parking"\|"toll"\|"service"` | ✅ | 见 `API-019` §4.1 映射表 |
| `amount_minor` | int | 条件 | `mileage` 之外必填，`gt=0` |
| `occurred_at` | str(ISO8601) | ❌ | 缺省 = now |
| `note` | str \| null | ❌ | 「备注（选填）」`pages/36:123` |
| `odometer_km` | int \| null | ❌ | 「当前里程」`pages/36:121` |
| `kwh` | float \| null | ❌ | 「充电度数」`pages/36:119` |
| `place` | str \| null | ❌ | 「充电站」`pages/36:120` |
| `idempotency_key` | str（≥8 位） | ✅ | `app/services/action/capabilities/ledger.py:50` |

响应：`{entry_id?, record_id?, category_name, odometer_delta_km?, hint?}`（`hint` = 联动口径文案，由服务端下发，见 §4.2 裁决 4）。

#### 4.1.5 `GET /car/services`

查询：`limit ≤ 50`。响应：`{total, items: [...]}`（同 `API-019` 的档案行结构）。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **提醒 = 纯函数派生，不落表、不出写端点** | `API-018` §4.2 裁决 3；且"下次该做什么"随当前时间变化，落表必然不同步 |
| 2 | **`age_text` / `paid_ratio` / `expense_total_minor` 均在服务端派生** | 端上算会让 35 与 39 两页出现两套口径；且 `ages` 依赖当前时间 |
| 3 | **限行为用户配置（D19）**，未配置时 `reminders` 不返限行项并带引导标记 | 决策 D19；不得编造「尾号 4 和 9」 |
| 4 | **联动口径文案由服务端下发**（`hint`） | `pages/36:131-134` 与 `pages/39:188-191` 是同一句话的两个位置；端上各写一遍会产生两套文案真相（同 `API-015` 裁决 4 的教训） |
| 5 | **提前量为参数类设置**，不用功能位 | `tasks.md` §0.2「不加功能开关」；env 名 = 字段名大写 |
| 6 | **区块级降级** | 沿用 `API-004` 的先例（`tasks.md:156`「任一子域不可用时不整体 500」）：某块失败则该块缺省并记入 `degraded_blocks` |
| 7 | **不提供车辆导出/删除端点** | 无设计要求；跨域治理扩展须独立决策（§3.2 #8） |

### 4.3 数据流

```text
35 页进入
  GET /car/overview
    car.py → car_service.overview(user_id)
      ├─ car_repository.get_profile / get_loan
      ├─ aggregate.car_expense_breakdown（API-019）
      ├─ aggregate.car_recent_records（API-019）
      └─ reminders.derive(profile, loan, mileage, now, settings)   # 纯函数

36 页保存
  POST /car/entries → entries.record_car_expense（API-019）
    → 落账 + （service 时）双写档案 + 回填里程
    → {entry_id, category_name, hint}

39 页
  GET /car/profile  → 身份卡 + 四档案行 + 保养时间线（末行未发生态）
  PUT /car/profile  → 档案 / 车贷 / 限行 upsert
```
