## 2. Background

### 2.1 现状：token 层尚不存在，且上游有 4 处色值必须定稿

| 事实 | 证据 |
|---|---|
| `apps/mobile/lib/design_system/tokens/` 由 `APP-001` 建为**空目录**，无任何 token 定义 | `docs/version/v5.0.0/tasks.md:106`（APP-001 交付面为骨架，不含 token） |
| 设计稿自身 **4 处色值三方不一致**，已在 D9 定稿 | `requirements-analysis.md:198-211`；`flutter-architecture.md:258-271` |
| 定稿口径：以**设计稿 §06 色卡 + 原型**为准，`:root` 的 4 个值视为笔误 | `flutter-architecture.md:269`；`SKILL.md:35` |
| M3 自带整套视觉主张，会与设计稿正面冲突 | `flutter-architecture.md:63-78`；`flutter-mapping.md:9-23` |
| 原型大量使用 **550 / 650 / 750** 字重，Flutter 无对应常量 | `tokens.md:168-173`；`flutter-mapping.md:82-92` |
| 深色模式要求 **暖纸白 ↔ 深夜紫对调**，故 `AppColors` 必须是 `ThemeExtension` | `flutter-mapping.md:107-122`；`traceability.md:200`（G3 本轮补挂 REQ-VIS-08） |
| M0 收口点 **C1** 的两条一票否决都落在本任务 | `tasks.md:255`；`flutter-architecture.md:434-439` |

**结论**：本任务把「设计稿色卡 + 原型」翻译成 Flutter 的唯一取色入口。**在此之前，任何页面都不允许写颜色。**

### 2.2 为什么必须做

1. **色值是最底层 token，改一个值波及全部 golden 测试**——所以必须一次性定稿，不能边写页面边补（`requirements-analysis.md:210`）。
2. **M3 若不显式覆盖会「漏」出来**：风险登记第 6 条明确「一旦发现 M3 默认样式漏出，**先改主题层，禁止在业务组件里打补丁**」（`flutter-architecture.md:418`）。没有覆盖层，后续每个页面都会各自打补丁，最终视觉失控。
3. **深色模式的结构决策只能现在做**：若 `AppColors` 一开始写成 `static const`，后期改造会波及所有页面（`flutter-mapping.md:121`）。虽然深色模式是 V1.1 范围，**token 结构必须从一开始支持对调**。
4. **语义纪律靠命名约束而非自觉**：「AI 渐变只用于 AI 的存在与行动」（`SKILL.md:42`）只有在 token 命名层面（`aiPrimary` 而非 `purple`）才可被评审（`flutter-architecture.md:301`）。

### 2.3 在 V5.0.0 中的位置

本任务在关键路径上：`APP-001 → APP-002 → APP-007 → APP-013 → APP-014`（`tasks.md:246`）。同时它是 `APP-006`（Orb）与 `APP-007`（组件库）的唯一依赖，也是 M0 收口点 **C1**「设计系统冻结」的主体（`tasks.md:255`）。

## 3. Scope

### 3.1 In Scope

1. **7 个 `ThemeExtension`**：`AppColors` / `AppGradients` / `AppRadii` / `AppTypography` / `AppElevation` / `AppSpacing` / `AppMotion`，字段与值见 §4.1。
2. **`iconTile(size)` 规则**：图标底色方块圆角 = 边长 ÷ 3（取整），用函数表达而非散落写死。
3. **`AppTypography.numeric` 等宽变体**：所有数值型样式统一带 `FontFeature.tabularFigures()`。
4. **M3 覆盖层**：手工构造 `ColorScheme`、显式 `TextTheme` 覆盖、关闭 `surfaceTintColor` 与默认 elevation、图标改 Lucide、Tab 栏自绘（本任务只声明禁令与主题侧关闭项，Tab 实现属 `APP-005`）。
5. **浅 / 深两套 `ThemeData`**：深色按 `flutter-mapping.md` §5 对调表实现，**只建结构不做 UI 切换开关**。
6. **取用扩展**：`context.colors` / `context.gradients` / `context.radii` / `context.typography` / `context.elevation` / `context.spacing` / `context.motion`，避免页面写长串 `Theme.of(context).extension<...>()!`。
7. **token 单测 + golden 基线**：token 值与 `tokens.md` 逐项对齐的断言；覆盖层不得出现 M3 默认特征的 golden 基线。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| **D1** | **字重 550 / 650 / 750 选「方案 B：降级映射」**——`550→w500`、`650→w600`、`750→w700`，并在 `AppTypography` 内统一封装 | 方案 A（`FontVariation('wght', 550)`）需引入**可变字体资源**，而字体授权是 `PLT-002` 未闭合项、字体资源不进仓库（`flutter-mapping.md:73-74`）。若选 A，token 层会被合规阻塞，与既有裁决「字体只影响 token 层，不阻塞开发」（`flutter-mapping.md:74`）直接冲突。选 B 则零成本、可立即开工；封装为单一改动点，字体授权落地后可整体切到 A 而不动页面 |
| D2 | **`AppColors` 必须是 `ThemeExtension`，不得是 `static const`** | 深色模式要求暖纸白 ↔ 深夜紫对调；`static const` 无法随主题变化，后期改造会波及所有页面（`flutter-mapping.md:29`、`:121`） |
| D3 | **手工构造 `ColorScheme`，禁用 `fromSeed`** | `fromSeed` 从种子色推导整套 tonal palette，与 10 个固定 token 直接打架（禁令 1） |
| D4 | **图标族锁定 `lucide_icons`；AI 语义符号统一 ✦ 四芒星** | 设计稿明确要求 Lucide 2px 线性圆角；AI 相关一律 ✦（禁令 4；`tokens.md:243-248`） |
| D5 | **渐变描边卡的实现不在本任务**，本任务只交 `AppGradients.ai` | 描边需 `CustomPainter` 自绘（`Container.border` 不支持渐变），属组件层（`APP-007`，`flutter-architecture.md:312`）。此处只保证 token 就绪 |
| D6 | **深色模式只建 token 结构与两套 `ThemeData`，不做 UI 切换入口** | 深色模式是 V1.1 范围（`flutter-mapping.md:121`）；本任务交付的是「结构支持对调」，不是「深色功能上线」 |
| D7 | **token 一律经 `context.<x>` 扩展取用，禁止页面直接 import token 常量** | 直接 import 会绕过主题对调能力；扩展方法避免页面写长串 `extension<...>()!`（`flutter-mapping.md:42`） |
| D8 | **`iconTile(size)` 用函数表达，禁止在组件里写死圆角** | 圆角 = 边长 ÷ 3 是原型隐含规律，散落写死必然漂移（`flutter-mapping.md:44-49`） |
| D9 | **`Color(0x` 与 `Colors.` 的唯一合法出口是 token 文件** | 红线 2「禁止散落硬编码色值」（`SKILL.md:43`）；M0 一票否决自检 1（`flutter-architecture.md:437`） |
| D10 | **不做两套设计真相**：token 值只从 `tokens.md` 取，不参考 Figma | D11 已裁决跳过 Figma 重建（`traceability.md:265-268`）；`tokens.md` 是唯一真源 |
| D11 | **`ai` 渐变只允许出现在 AI 语义元素上**，靠命名与评审双重约束 | 红线 1（`SKILL.md:42`）；`flutter-architecture.md:301` |
