## 4. Technical Design Requirements

### 4.1 表契约

> 通用列：`id: str PK`、`user_id: str`（索引）、`created_at` / `updated_at: datetime`；命名随最终实现定，**字段级语义如下**。

#### 4.1.1 `car_profiles`（车辆档案，每用户至多 1 行）

| 列 | 类型 | 来源（设计稿） |
|---|---|---|
| `model` / `plate` | str | `pages/39:129-130` 车型 + 车牌 chip |
| `trim_note` | str \| null | `pages/39:132`「715km 尊享型 · 2024 年 6 月上牌」 |
| `battery_kwh` | float \| null | `pages/39:134` 电池容量 |
| `purchased_at` | datetime \| null | `pages/39:132` 上牌时间（**车龄由此派生**，不存冗余） |
| `odometer_km` | int | `pages/39:136` 总里程；也是保养周期与电耗的分母 |
| `insurance_due_at` / `insurance_note` / `insurance_annual_minor` | datetime \| str \| int \| null | `pages/39:149-152`（交强 + 商业险、年保费） |
| `inspection_due_at` / `inspection_note` | datetime \| str \| null | `pages/39:153-157` |
| `charger_power_kw` / `charger_note` | float \| str \| null | `pages/39:158-162`（7 kW 慢充 · 谷电） |
| `service_interval_km` / `service_interval_months` | int \| null | `pages/39:163-167`（10,000 km 或 12 个月，**以先到为准**） |
| `restriction_city` / `restriction_digits` / `restriction_weekday` | str \| null | `pages/35:175-179` 限行配置（**决策 D19：用户手动配置**） |

**约束**：`odometer_km >= 0`；`battery_kwh > 0`（若存在）；`service_interval_km > 0`（若存在）。`create_check_constraint` 必须传**完整布尔式**（`tasks.md` §0.3 陷阱 1）。

#### 4.1.2 `car_loans`（车贷）

| 列 | 类型 | 来源 |
|---|---|---|
| `principal_minor` | int \| null | 贷款总额（`pages/35:138` 月供 × 期数可派生，但留存原始值以免口径漂移） |
| `monthly_minor` | int | `pages/35:138` 月供 ¥3,850 → 385000 |
| `paid_periods` / `total_periods` | int | `pages/35:138` 已还 18 / 36 期 |
| `next_due_at` | datetime \| null | `pages/35:137`「下期 10 月 5 日」→ 徽章 |
| `settled_at` | datetime \| null | `pages/35:140`「2028 年 9 月结清」 |

**约束**：`0 <= paid_periods <= total_periods`；`monthly_minor > 0`；`total_periods > 0`。
**派生不落库**：剩余待还 = `monthly_minor × (total_periods − paid_periods)`；已还比例 = `paid_periods / total_periods`（`pages/35:139-140` 的进度条与双端说明）。

#### 4.1.3 `car_service_records`（保养记录）

| 列 | 类型 | 来源 |
|---|---|---|
| `title` | str | `pages/39:174`「小保养 · 机油机滤」 |
| `place` | str \| null | `pages/39:174`「华迪 4S 店」/ `:179`「厂家赠送」 |
| `odometer_km` | int \| null | `pages/39:174` 10,380 km |
| `occurred_at` | datetime | `pages/39:174` 2026-08-16 |
| `amount_minor` | int \| null | `pages/39:175` ¥200；`:180`「免费」→ **null** |
| `next_due_at` / `next_due_km` | datetime \| int \| null | `pages/39:184`「还剩 2,100 km 或 45 天」的落点 |
| `ledger_entry_id` | str \| null | **与记账域的回链**（`API-019` 写入）；`amount_minor` 与记账行同源 |

#### 4.1.4 `car_mileage_logs`（里程记录）

| 列 | 类型 | 来源 |
|---|---|---|
| `odometer_km` | int | 本次记录的里程表读数 |
| `delta_km` | int \| null | 本次增量（`pages/35:186`「38 km」） |
| `recorded_at` | datetime | `pages/35:186` 记录时刻 |
| `note` | str \| null | `pages/35:186`「通勤往返」 |

**约束**：`delta_km` 允许为 null（首次记录无前值）；`odometer_km >= 0`。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **表进 `app/core/db.py`，域模型进 `app/models/car.py`** | 实测约定（§2 表）；偏离会产生"两处表定义"的第二套真相 |
| 2 | **费用字段零进 car 表** | 决策 D12；同时避免绕过 `record_provenance`（`service.py:62-70`）造成治理面缺账 |
| 3 | **提醒不落表，由纯函数派生** | 提醒是「档案 + 车贷 + 里程 + 当前时间」的确定性函数；落表会产生与源数据不同步的冗余状态，且无法免测 |
| 4 | **车龄 / 剩余待还 / 已还比例均**派生不落库 | 落库会与 `purchased_at` / `paid_periods` 分叉 |
| 5 | **保养行与记账行用 `ledger_entry_id` 单向回链** | `pages/36:131-134` 与 `pages/39:188-191` 要求「保养费用同时计入记账养车分类，不用重复记」；回链使两处金额**同源**而不是各存一份 |
| 6 | **迁移编号固定 `0003`、`down_revision="0002"`** | `tasks.md` §0.3 已登记；健康域若届时进 V1 须顺延 `0004`（**同批迁移必须串行入链**） |
| 7 | **先测爆炸半径再动手** | `tasks.md` §0.3 陷阱 2：加一个迁移会打破约 22 条跨版本钉测（`MIGRATION_HEAD` 字面量、`test_migration_chain_head_is_still_00NN` 用例名、`SCHEMA_TABLE_COUNT`、`SCHEMA_COLUMNS_DIGEST`） |

