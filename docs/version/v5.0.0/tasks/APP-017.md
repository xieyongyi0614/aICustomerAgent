### 2.2 为什么必须做

1. **它是与普通助手的核心差异。** 页面目的即「回答『AI 到底记住了我什么』，透明 = 信任」（`traceability.md:121`）；红线 3「记忆可见」把「每条记忆有来源追溯 + 用途回执」列为**可判定验收**（`principles.md:13`）。
2. **它是本任务最容易出错的地方——口径。** 冲突 4（`requirements-analysis.md:150-155`）明确：若不定义清楚，「产品承诺会与引擎行为打架（例如用户看到『遗忘』后刷新又出现）」。决策 D5 已给出唯一口径，本任务必须逐条落地。
3. **它携带一处合规风险。** 原型写「全部本地可见」，而实际是服务端 PG 存储；`requirements-analysis.md:132` 明确「**这是合规风险，不只是文案问题**」。决策 D2 已裁定改文案，本任务必须落地。
4. **它依赖的产品级写接口尚不存在。** 编辑 / 遗忘归 `API-007`（`tasks.md:157`），**未落地前本任务不得开工写路径**（`traceability.md:56` 的 ⚠️）。

### 2.3 在 V5.0.0 中的位置

M2 客户端第 5 个任务（`tasks.md:169`）。它消费 `API-007` 与 `APP-007`，与 `APP-021`（隐私与授权页）共享隐私文案口径（决策 D2），与 `APP-014`（首页）共享「AI 叙事优先」纪律。

```text
        · 遗忘 → 置 forgotten（API-007）
        · 一键清空 → DELETE /life/data?confirm=true（governance.py:62）
   → drift 只读缓存（进页先渲染缓存再刷新，flutter-architecture.md:372）
   → Riverpod provider → 按 4 分组渲染 A24 列表 + A25 隐私承诺卡

装配红线：
   ✗ 不展示 forgotten / decayed 条目（D1）
   ✗ 不暴露 200 上限 / 衰减机制（D5）
   ✗ 不硬删记忆（D6）
   ✗ 不端上生成用途回执（D8）
```
