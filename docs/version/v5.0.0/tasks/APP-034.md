| 既有网络守卫只覆盖 presentation | `layer_guards_test.dart:87`（`test_features_presentation_does_not_import_dio`）——**只查 `/presentation/`**，`data/` 层不在其中，故 `album` 的"全程不联网"需要**新守卫**（D18） |

## 3. Scope

### 3.1 In Scope

1. `pubspec.yaml` 增 `photo_manager`（版本以 `PLT-007` 结论为准）与必要伴随依赖。
2. Android：`android/app/src/main/AndroidManifest.xml` 声明 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO`（Android 13+）与低版本兼容声明；iOS：`ios/Runner/Info.plist` 增 `NSPhotoLibraryUsageDescription`，文案**含「仅本机 / 不上传服务器」语义**（红线 9）。
3. 权限申请流（复用既有 `permission_handler`），拒权 → 明确引导态（不静默失败）。
4. `features/album/data/album_repository.dart`：读取资产 / 相簿、按目录与元数据分类、按需缩略图。
5. `features/album/domain/album_models.dart`：相簿 / 照片 / 建议 / 分类口径模型。
6. **本机分析**（`data/album_analysis.dart`）：过期截图 + 重复保存；**在后台 isolate 执行、可中断、中断不改变任何照片**。
7. **端侧元数据存储**：在 album 域内新建轻量存储（**不复用 `LocalStores`**，见 §4.2 裁决 3）。
8. `layer_guards_test.dart`：L32-41 追加 `'album'`；**新增守卫** `test_album_feature_has_no_network_access`（§4.1）。
9. 性能：照片列表分页 + 缩略图按需解码（`cacheWidth`），不一次载入原图。

| 2 | **任何网络请求 / 云同步 / 上传** | 红线 9（`SKILL.md:52`）+ D18；含"顺手加个备份"也属反范围 |

| 4 | 人脸识别 / 人物聚类 | 反范围 #3（生物特征敏感） |

## 4. Technical Design Requirements

### 4.1 新增守卫契约（D18）

| 守卫名 | 断言 | 落点 |
|---|---|---|
| `test_album_feature_has_no_network_access` | 扫描 `lib/features/album/**/*.dart`，**不得出现** `package:dio`、`core/network/`、`http://`、`https://` 字面量 | `test/scaffold/layer_guards_test.dart` |
| `test_layer_dirs_exist`（既有，需改） | 域清单 L32-41 追加 `album`，断言 `lib/features/album/{data,domain,presentation}` 三层存在 | 同上 |

> **注**：`presentation` 目录由 `APP-035` 填充，但 `layer_guards_test.dart:20` 断言的是**目录存在**，故三层目录须在本任务一并创建（可先放占位文件）。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **全程零网络，并以静态守卫固化** | D18；红线 9 若无可验证约束就只是文案；已有 `layer_guards_test.dart:87` 只覆盖 presentation，覆盖面不足，故新增整域守卫 |
| 2 | **分析在后台 isolate 且可中断** | 缺口 28：数千张的哈希 / 元数据扫描放在主 isolate 会卡 UI；"可中断"是 `pages/62:144`「清理随时可以停下，停下的部分不会有任何改变」的技术前提 |
| 3 | **不复用 `LocalStores` / drift 表** | `progress-audit` §7.6：`LocalStores` 零引用（死代码），drift 7 表是服务端 DTO 投影；复用等于把一个已死通道接进新产品面，且语义不符（相册元数据不是服务端 DTO） |
| 4 | **图片源由调用方提供为真实缩略图** | `APP-043` §4.2 裁决 3；本任务的数据面负责产出缩略图句柄 |
| 5 | **权限拒权呈引导态而非空页** | 与 `APP-014` 空态分支先例一致；`permission_handler` 已在依赖中（`pubspec.yaml:29`） |
| 6 | **不做相似连拍**，但**要为其留出诚实的"未支持"外观** | D16；页面（`APP-036`/`037`/`038`/`039`）需要能表达"这项分析本期不做"，数据面须提供明确的"未支持"信号而非空结果（否则会被误解为"扫了但没有"） |
| 7 | **删除走系统能力**（`PhotoManager` 的回收站 / 删除语义） | D17；不自建回收站 |
| 8 | 依赖版本由 `PLT-007` 结论锁定 | 避免与本机 SDK 约束冲突 |

### 4.3 数据流

```text
【权限】
  album 域进入 → permission_handler 申请相册读权限
    ├─ 授予 → 继续
    └─ 拒绝 → 引导态（含去设置的入口）

【读取】
  PhotoManager（本机）→ 相簿列表 + 资产列表（**分页**）
    → domain 模型（相簿 / 照片 / 分类）
    → 缩略图按需解码（cacheWidth）→ APP-043 的 AlbumTile / PhotoTile 消费

【本机分析（isolate）】
  assets → 过期截图判定（目录 / 尺寸 / 时间启发式）
         → 重复保存判定（文件哈希）
         → 建议集合 { kind, count, bytes, reason }
    ↑ 可中断：取消时丢弃中间结果，**不调用任何删除 / 移动**
  ✗ 相似连拍 → 返回"未支持"信号（D16）

【元数据存储】
  album 域自有轻量存储（预选推翻记录 / 收藏 / 上次扫描时间）
  ✗ 不用 LocalStores / AppCacheDb

【网络】
  ✗ 零请求（D18 静态守卫 + 运行期用例）
```

### 4.4 依赖与边界

| 允许依赖 | 禁止依赖 |
|---|---|
| `photo_manager`、`permission_handler`、Dart `Isolate` / `compute` | **`core/network/**`、`package:dio`**（D18） |
| album 域自有存储 | `core/storage/**` 的 `LocalStores` / `AppCacheDb`（§4.2 裁决 3） |
| `design_system/**`（类型引用） | `features/*` 其他域（`layer_guards_test.dart:49`） |
