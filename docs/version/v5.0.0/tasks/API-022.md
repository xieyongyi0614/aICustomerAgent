### 2.2 为什么必须做

1. **没有它，`APP-044` 无数据源。** `APP-044` 的全部逻辑建立在「查最新版本 → 比对 `version_code` → 取制品 `sha256`」之上；后端不存在这两个出口，客户端只能硬编码版本号或依赖外链，前者是第二真相源（与 `update-system-architecture.md` §3.2 冲突），后者违背「不引入第三方分发平台」的裁决。
2. **它是「制品即真相」的落库点。** `PLT-008` 从 APK 反读 `version_code` / `version_name` 并落 manifest，但 manifest 只是**文件**；客户端不会读文件系统，只有入库后 `version_code` 才成为「服务端下发的比对基准」。**不入库 = 版本真相链断在中段**。
3. **它是断点续传的服务端前提。** `update-system-architecture.md` §5.3 的续传依赖 `Range`。若服务端不支持，20–60 MB 的包在弱网下每次失败都要从 0 重来——这是本域最影响口碑的单点。
4. **它是「零死字段」与「补丁预留」的平衡执行点。** 数据面要同时满足「不留无实现的字段」（`rollout_percent` 一律不建）与「`artifact_type` 预置 `'patch'`」（避免将来接差分时必须改迁移）。这个平衡只能在迁移里表达。
5. **它必须同时关掉容器卷缺口，否则制品随容器消失。** `docker-compose.yml:33-49` 的 `console` 服务无任何挂载；若把制品放进容器内路径而不挂卷，任何一次 `docker compose up --build` 都会让已在库的 `storage_path` 全部 404。**这是本任务不可分拆的一部分**。

### 2.3 在 V5.0.0 中的位置

PLT 批次的后端补齐任务，与 `PLT-008` / `APP-044` 同批立项。它承接 `tasks.md:639` 台账 #7 中的「版本端点」一项，并作为 `APP-044` 的**唯一数据源**。

**不是 `PLT-005` 的一部分**：`PLT-005` 的交付面是 CI 与分发链路（`PLT-005.md:19`），而本任务交付的是运行时读面与数据面，验收方式（迁移钉测 / 端点契约 / Range 行为）与流水线完全不同。

**与 `API-021` 无冲突**：`API-021` 已于 2026-10-07 被「首页每日 AI 总结生成器」占用（`tasks.md:672-678`），本任务用**下一可用号 `API-022`**（`tasks.md:625` 登记「下一可用号 `API-022`」）。**两者无依赖关系**。

### 4.2 关键裁决与铁律留痕

#### 4.2.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **无更新返回 `200 + has_update:false`，不用 `204`** | 客户端需稳定结构驱动三态状态机（有更新 / 无更新 / 检查失败）；`204` 空体在 Dio 层与「服务端异常」难以区分（`core/network/dio_client.dart:37-42` 的 `ErrorMappingInterceptor` 只处理错误态）。对齐 `API-010.md` §4.1 既有裁决「无数据 → 200 + 空结果，不 500」 |
| D2 | **两表，非单表** | `artifacts[]` 是多值结构；塞进单表只能靠 JSON 列或重复行。两表让「一个版本挂多个制品（未来 full + patch 并存）」成为自然表达，且下载端点有稳定行主键可寻址 |
| D3 | **`artifact_type` 的 CHECK 预置 `'patch'`，本期无写入路径** | 这是「预留 patch 契约」在数据面的唯一落点：将来接差分时**不必改迁移**。除此之外**不留任何死字段**（`rollout_percent` 之类一律不建） |
| D4 | **`storage_path` 存相对路径；解析后强制校验在 `storage_dir` 之下** | 存绝对路径会在换部署环境（容器内外路径不同）时全部失效；而「接受路径」若不校验就是目录穿越入口。相对路径 + 双处校验同时解决两个问题 |
| D5 | **入库走脚本，不开管理写端点** | 内测期无可信管理鉴权体系（`tasks.md:713` 记 `IDENT-010` 调试面鉴权留白）。开放未鉴权的写接口 = 任何人可推假版本 → 分发链被接管。脚本入参是文件系统路径，攻击面 = 服务器本地权限，与网络隔离 |
| D6 | **两个端点均不鉴权；`channel` 精确匹配无兜底** | ① 版本查询在冷启动路径，不可依赖 token（未登录用户也须能收到安全更新）；② 本域无任何用户数据；③ 「内测包推给线上用户」是不可逆事故（`self-distribution-guide.md:101` 已有装机事故先例） |
| D7 | **`artifacts[].url` 下发相对路径** | ① 客户端已有 `AppEnv.apiBaseUrl`（`core/env/app_env.dart:9`），拼接待由客户端做；② 下发绝对 URL 会把「部署域名」写进数据面，改域名需回刷历史行；③ 换 CDN 时只需改 `url` 的**生成逻辑**，不改表 |
| D8 | **落盘文件缺失返回 `404`，不暴露路径** | 与「行不存在」对客户端是同一后果（无法下载），但对攻击者是两类信息：区分二者会泄露服务器目录结构。日志侧区分（ERROR + 路径），响应侧统一 |
| D9 | **manifest 的 `schema_version` 未知 → 拒绝入库** | 对齐仓库既有 fail-closed 纪律（同 `EXPECTED_EVENT_TYPES` 思路，`tests/v30/test_runtime_contracts.py:27-42`）：未知契约版本**不猜**，避免用旧解析器读新结构造成静默错值 |
| D10 | **入库时**重算** `sha256` / `size_bytes` 并与 manifest 比对** | manifest 是文件，可被篡改或传输损坏；重算是「制品即真相」的第二次收口。这也让「manifest 与包体不一致」在**入库前**暴露，而不是在用户安装失败时 |
| D11 | **不新增 `runtime_*` 字段、不新增事件类型** | 本域不触碰 Agent Runtime 契约（`runtime_support.py:10-24`、`test_runtime_contracts.py:27-42`）；登记义务为 **N/A**，须在 §4.2.2 留痕 |
| D12 | **只保留业务键的隐式唯一索引，不另建同列索引、不建 `published_at` 索引** | ① 主查询路径是 `(platform, channel, version_code)` 取最大值，`uq_app_releases_identity` 的隐式索引已覆盖；② 再建同列普通索引是**纯冗余**（写放大、无读取收益）；③ 按时间排序的运维查询量极小，不值得第二个索引。**这是一处对初稿的修正**（初稿曾列 `ix_app_releases_lookup` + 独立唯一约束） |
| D13 | **读面走 `app/services/app_release/`，端点不直连 ORM** | 对齐 `car.py:1` 的「只做表现，零仓储依赖」先例（`app/services/car/service.py:11` 才 import 仓储）。这既是铁律约束 1 的满足方式，也让「未来接灰度 / 多平台」的选取逻辑集中在服务层 |

### 4.3 数据流

```text
① 出包与制品（PLT-008）
   APK → {storage_dir}/{channel}/{version_code}/full/{apk, release-manifest.json}
        ↓
② 入库（本任务，脚本）
   scripts/import_release.py --manifest <path>
     ├─ 校验 schema_version / 路径在 storage_dir 之下（§4.1.7）
     ├─ 重算 sha256 + size_bytes 并与 manifest 比对（D10）
     └─ 单事务 upsert app_releases + app_release_artifacts（幂等，§4.1.5）
        ↓
③ 读面（本任务，端点）
   api/v1/app_release.py  →  services/app_release/service.py  →  repositories/app_release_repository.py  →  core/db
     ├─ GET /latest       → 取 (platform, channel) 下 version_code 最大行 + 其 artifacts
     └─ GET /{id}/download → 校验路径 → FileResponse（Range → 206）
        ↓
④ 消费（APP-044）
   比对 version_code → 策略裁决 → 下载（Range 续传）→ 双校验 → 安装
```

**装配红线**：

- ✗ `app/api/v1/app_release.py` **不得** import `app.repositories`、`app.core.db`、`sqlalchemy`（§4.2.2 检查项 1）。
- ✗ `app/services/app_release/**` **不得** import `app.application`、`app.channels`（分层倒置 / 通道反向依赖）。
- ✗ 端点**不得**在响应中拼绝对路径或 `storage_dir`。
- ✗ 入库脚本**不得**调用 HTTP 端点（脚本与端点共用服务层，不互相调用）。
- ✗ 全链路**不得**触碰 `world_*` / `memories` / `relationship_state` / `loop_runs`。
