## 3. Scope

### 3.1 In Scope

1. `_ModuleGrid` 扩展为 **3×3 九卡**：记账 / 备忘录 / 任务 / 日历 / 旅行 / 健康 / **车辆** / **相册占位**（相册卡由 `APP-040` 填实，本任务先留位或延后由 `APP-040` 添加——见 §4.2 裁决 4）。
2. **车辆卡**：摘要 = 「本月养车 ¥N」；无数据时「还没有养车记录」（诚实空态）；点击 → `/car`。
3. **日历 / 旅行卡（D21）**：不可点（无 `onTap`），摘要为明确的未接入文案（如「未接入」），**禁止**「15:00 方案对齐」「十一行程规划中」类伪造摘要。
4. `features/life/data/life_repository.dart` 追加 `monthCarExpenseText()`（读 `GET /car/overview` 的 `expense_total_minor`）——**仍不得 import `features/ledger`**。
5. 失败容忍：车辆摘要请求失败时降级为诚实文案，**不影响其他模块卡**。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | **解禁日历 / 旅行**（新建两个域） | 决策 D21：维持 🚫 后置；解禁等于范围扩张且两者均无后端实体 |
| 2 | 相册卡的**真实摘要**（张数） | 归 `APP-040`（三期）；本任务不引入相册依赖 |
| 3 | 改造记账 / 备忘录 / 任务 / 健康的既有摘要口径 | 已通过前一轮真实化整改（`progress-audit` §6.1），改动会退回假数据风险 |
| 4 | `_SoonGrid`（阅读 / 习惯打卡 / 更多 Skill）的改动 | 设计稿未动（`pages/30:167-171`）；保持现状 |
| 5 | 快速捕获条改造 | 归既有 `capture_route.dart`（`REQ-LIFE-01`，已实现） |
| 6 | 把车辆卡摘要做成"AI 生成的动态结论"（如「很省」） | 「很省」需同级油车基准值（`API-019` §3.2 #4 列 V2）；本期只给**可验证**的金额结论 |

## 4. Technical Design Requirements

### 4.1 宫格契约（九卡）

| 卡 | 摘要 | 交互 | 数据来源 |
|---|---|---|---|
| 记账 | 既有（`_ledgerSummary`，`life_page.dart:62-68`） | → `/ledger` | `life_repository.monthExpenseText()` |
| 备忘录 | 既有（`_memoSummary`，`:70-74`） | 既有 | 既有 |
| 任务 | 既有（`_taskSummary`，`:76-80`） | 既有 | 既有 |
| 日历 | **「未接入」**（D21） | **不可点** | — |
| 旅行 | **「未接入」**（D21） | **不可点** | — |
| 健康 | 既有「即将接入」 | 既有 | — |
| **车辆** | 「本月养车 ¥N」/ 空态「还没有养车记录」/ 失败「暂时取不到，点下方重试」 | → `/car` | **本次新增** `monthCarExpenseText()` |
| 相册 | 占位（`APP-040` 填实） | — | — |

**组件**：沿用既有 `ModuleCard`（`design_system/components/chips.dart`）；图标底色方块圆角 = 边长 ÷ 3（`SKILL.md:40` 已裁决歧义 4）。车辆卡语义色用 `aiBlue`（与 `pages/30:158` 一致）。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **日历 / 旅行维持 🚫 后置，渲染为不可点的未接入态** | 决策 D21；若解禁则需新建日历域与旅行域（工期不可控），且 `traceability.md:51-52` 的 🚫 需同步回改 |
| 2 | **禁止伪造摘要**「15:00 方案对齐」「十一行程规划中」 | `APP-014` 红线（`tasks.md:168`）；这两句在项目里没有任何数据源 |
| 3 | **车辆摘要只给可验证结论**（金额 / 空态 / 失败），不做"很省"这类需基准值的判断 | 基准值口径未定（`API-019` §3.2 #4）；编造基准即假数据 |
| 4 | **相册卡由 `APP-040` 添加，本任务不引入相册依赖** | 相册期需要新增原生依赖 + 工具链修复（`PLT-007`）；本任务提前引入会让二期被三期阻塞 |
| 5 | 车辆摘要读取**经 `life_repository`**，禁 import `features/ledger` | `layer_guards_test.dart:49`；且 `life_repository.dart` 已是"自建数据面"的既有先例 |
| 6 | 单个摘要失败**只降级该卡** | 沿用 `life_page.dart:49-54` 的既有分块失败标记（`_tasksFailed` / `_ledgerFailed`）；整体失败会让一个域的故障拖垮整页 |

### 4.3 数据流

```text
进入 /life
  → _load()（life_page.dart:29）
      ├─ listOpenTasks()            （既有）
      ├─ monthExpenseText()         （既有）
      └─ monthCarExpenseText()      GET /car/overview        # 本次新增
           → 取 expense_total_minor → 文本化 / 空态 / 失败三态
车辆卡点击 → push /car
```
