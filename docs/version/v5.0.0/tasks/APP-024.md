### 2.2 为什么必须做

1. **它是 M4 验收口径的直接承载，也是「AI 叙事优先」与「卡片即结论」两条原则在健康域的落地检验。** 「首屏是『今天状态不错』而非指标表」是**唯一判定线**（`tasks.md:206`；`principles.md:11-12`）；做反了就退化成运动健康 App 的 Dashboard（反范围，`requirements-analysis.md:389`）。
2. **它是红线 8（医疗免责常驻）的页面级落点。** 本页含**建议类**健康文案（如「建议 20 分钟快走」），因此**必须**携带常驻免责（`components.md:389`；`SKILL.md:49`）。
3. **它是「数字不跳动」的展示检验，并承载 `A21` / `A22` / `A23` 三个健康专属组件**（只在本页使用）。睡眠时长 / 心率 / 步数全部走 `AppTypography.numeric`（`flutter-architecture.md:326-329`），否则滚动时数字左右跳动。

### 2.3 在 V5.0.0 中的位置

M4 客户端第 2 个任务（`tasks.md:203`），位于 `PLT-001 → APP-023 → APP-024` 链末（`tasks.md:226-228`）。它消费 `APP-023`（数据 / 授权态）与 `API-010`（评分 / 批注），是 M4 验收口径的最终承载页；与 `APP-025`（免责常驻）**互补不重叠**（§4.4）。

```text

        · GET /health/overview → score / score_breakdown / headline / narrative / disclaimer
        · GET /health/trends?metric=sleep&window=7d → points / annotation / source_refs
        · 授权态 / device_model ← APP-023（core/health）
   → Riverpod provider → features/health/presentation
        · 段 1 标题行（固定文案）
        · 段 2 Hero 卡（insightHero 底 + Orb md + headline + score + narrative）
        · 段 3~4 区块标题 + A21 hbar 趋势卡（今日柱 ai 渐变）+ 批注
        · 段 5~6 区块标题 + A22 h-row ×3（副文案含 AI 建议）
        · 段 7 A23 src-note 来源声明
        · 免责常驻（APP-025 组件，任意滚动位置可见）
   → 渲染顺序固定「先结论（段 2）→ 后数据（段 3~6）→ 来源（段 7）」

降级路径（未授权 / 无数据 / 子请求失败）：
   对应区块 → 空态 + 引导授权（零数值、零留白、不报错）

装配红线：
   ✗ 把趋势图 / 指标行放在 Hero 卡之前（D1）
   ✗ 免责只在页底出现一次（D2）        ✗ 手写数字样式（D3）
   ✗ 端侧生成分数 / 叙事（D5）          ✗ 纯数据表格（D6）
   ✗ Hero 卡用 ai 渐变描边（D7）        ✗ 降级显示 -- / 0（D8）
```
