## 2. Background

| 事实 | 证据 |
|---|---|
| 工具链故障（精确根因） | `reviews/progress-audit-2026-09-29.md` §7.7：flutter_tools 在 `generateCommands` 阶段**急切定位 Android SDK**，执行 `where.EXE aapt` 时子进程创建失败（`CreateFile failed 231 所有的管道范例都在使用中`，`process_win.cc:744`） |
| 环境缺失项 | 同 §7.7：`ANDROID_HOME` / `ANDROID_SDK_ROOT` 未设；`android/local.properties` 只有 `flutter.sdk`；常见 SDK 路径不存在 |
| 已验证失败的绕过 | 同 §7.7：设 `ANDROID_HOME` 指向**空目录**仍走 `_which('aapt')`（`android_sdk.dart:127`） |
| 后果范围 | 同 §7.7：「本机既不能 `pub get` 也不能 `analyze`/`test`（Dart→子进程一律失败）」；**阻塞面**＝任何需新增/变更 Flutter 依赖的修复 |
| 已受到的约束 | `tasks.md` §0.4 / `reviews/progress-audit-2026-09-29.md` §6.2：**不得以静态检查替代**真实 `analyze` / `test` |
| 相册期的依赖刚需 | `requirements-analysis.md` §2.4：`pubspec.yaml` 现无 `photo_manager` / `image_picker` / `camera` / `path_provider`；相册期必须先 `pub get` |
| 既有探针报告体例 | `apps/mobile/docs/plt001-probe.md`（`PLT-001` 的产出体例，可照抄结构） |

**为什么必须先做**：三期全部 5 个相册页面 + album 域都依赖 `photo_manager`；`pub get` 不通则一行都写不了。且**缺口 25（"仅本机"可验收）的 D18 守卫测试也需要 `flutter test` 能跑**——工具链故障同时卡住"实现"与"验收"两条路。

## 3. Scope

### 3.1 In Scope

1. **修复** `flutter pub get` / `analyze` / `test` 的故障（根因两条候选路径：① 修复宿主机 `CreateNamedPipe` 路径，疑 EDR hook；② 在另一台可用机器上建立开发环境）。
2. 记录**修复步骤的可复现命令**（换机器时能照做）。
3. 验证 `photo_manager`（或等价库）在当前 `sdk: ^3.13.4` 约束下的兼容性：`pub get` + 最小 demo。
4. 验证相册权限链路：Android 13+ 的 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO`；iOS 的 `NSPhotoLibraryUsageDescription`（`api/` 与 `ios/Runner/Info.plist` 落点）。
5. 产出结论报告（含**否**情形下的替代方案与影响面）。

### 3.2 Out of Scope

| 2 | 修改 `pubspec.yaml` 落地正式依赖 | 依赖变更属 `APP-034`；本任务只做**可行性验证**（可临时验证后回滚） |

| 6 | 修复 `PLT-001` 遗留的探针问题 | 探针已就绪（`apps/mobile/docs/plt001-probe.md`），属独立范围 |

## 4. Technical Design Requirements

### 4.1 修复路径与验证口径

| 步骤 | 命令 | 判定 |
|---|---|---|
| 0 环境留痕 | `flutter --version` / `where aapt` / `echo $env:ANDROID_HOME` | 记录基线（含失败态） |
| 1 路径 A（本机修复） | 修复宿主机子进程创建（`CreateNamedPipe`）；确认 `aapt` 可解析 | `where.EXE aapt` 返回 0 且输出路径 |
| 2 路径 B（换机） | 在可用机器上克隆 + `flutter pub get` | 成功 |
| 3 依赖解析 | `flutter pub add photo_manager`（临时验证后回滚） | `pub get` 成功且无版本冲突 |
| 4 静态检查 | `flutter analyze` | **零 error**（warning 需逐条说明） |
| 5 测试可执行 | `flutter test` | 产出通过/失败计数（非"无法执行"） |
| 6 最小相册 demo | 临时页面：申请权限 → `PhotoManager.getAssetCount()` → 取 1 张缩略图 | 真机/模拟器可见张数与缩略图 |
| 7 Android 权限 | `android/app/src/main/AndroidManifest.xml` 声明 `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` | 授权弹窗出现并可授予 |
| 8 iOS 权限 | `ios/Runner/Info.plist` 加 `NSPhotoLibraryUsageDescription` | 文案符合红线 9（仅本机语义） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **本任务必须先于三期任何编码** | `requirements-analysis.md` §6.1 `D22` 与 §15.7 阻塞清单第 8 项 |
| 2 | **不得以静态检查替代 `analyze` / `test`** | `tasks.md` §0.4 明文；`reviews/progress-audit-2026-09-29.md` §6.2 已把"仅静态验证"列为不可接受 |
| 3 | **验证用的依赖变更须回滚** | 正式依赖变更归 `APP-034`；留在 `pubspec.yaml` 会让三期任务边界模糊 |
| 4 | **权限文案须守红线 9** | `SKILL.md:52`：涉及相册必须明示"仅本机存储、不上传服务器"；iOS 的 `NSPhotoLibraryUsageDescription` 也会被用户与审核看到 |
| 5 | 结论为"否"时**本任务仍是完成项**，但须给出替代方案与影响面 | 参照 `PLT-001` 的门控语义（`tasks.md:216`：结论直接决定排期） |

### 4.3 数据流

```text
修复工具链 → pub get / analyze / test 三命令可用

```
