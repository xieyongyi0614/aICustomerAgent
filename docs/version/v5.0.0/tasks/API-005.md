## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 表结构（`life_tasks`，字段级）

| 列 | 类型 | 约束 / 缺省 | 语义 |
|---|---|---|---|
| `id` | `String` | **PK** | 任务 id（服务端生成） |
| `user_id` | `String` | NOT NULL | 分区键（**裸字符串，不加 FK**，§3.2 第 7 条） |
| `character_id` | `String` | NOT NULL，默认 `"asuna"` | 角色归属（与既有表一致） |
| `kind` | `String` | NOT NULL，默认 `"task"`，CHECK | `task` / `memo`（备忘录降级标记，`tasks.md:186`） |
| `title` | `String` | NOT NULL | 任务标题 |
| `note` | `Text` | NULL | 备注 / AI 副文案原文 |
| `status` | `String` | NOT NULL，默认 `"open"`，CHECK | 生命周期 `open` / `done` / `cancelled` |
| `remind_at` | `DateTime` | NULL | 时间提醒时刻（`REQ-HOME-05`「14:30 提醒」） |
| `reminder_ref` | `String` | NULL | 已注册提醒的**行动台账 id**（`action_records.id`，§4.1.4） |
| `sort_rank` | `Integer` | NOT NULL，默认 `0` | 排序位次（越小越前） |
| `sort_reason` | `String` | NULL | **排序理由文案**（服务端给出，客户端只渲染） |
| `source` | `String` | NOT NULL，默认 `"manual"`，CHECK | `manual` / `capture` / `ai` |
| `source_ref` | `JSON` | NULL | 来源追溯（如 `{table, id}`，沿用 `memory_candidates.source_ref` 范式） |
| `completed_at` | `DateTime` | NULL | 完成时刻 |
| `created_at` | `DateTime` | NOT NULL | 创建时刻 |
| `updated_at` | `DateTime` | NOT NULL | 更新时刻 |

**索引（3 个，覆盖首页与提醒两条读路径）**：`ix_life_tasks_user_status`（`user_id, status`，首页只取 `open`）、`ix_life_tasks_user_remind`（`user_id, remind_at`，待触发扫描）、`ix_life_tasks_user_kind`（`user_id, kind`，备忘录计数，`tasks.md:186`）。

**CHECK 约束（4 条，全部为完整布尔式）**

| 约束名 | 布尔式语义 |
|---|---|
| `ck_life_tasks_kind` | `kind IN ('task', 'memo')` |
| `ck_life_tasks_status` | `status IN ('open', 'done', 'cancelled')` |
| `ck_life_tasks_source` | `source IN ('manual', 'capture', 'ai')` |
| `ck_life_tasks_done_consistency` | `status != 'done' OR completed_at IS NOT NULL`（沿用 `ck_insights_invalidated_reason` 同款一致性写法，`core/db.py:1058-1061`） |

#### 4.1.2 CRUD 端点（`api/v1/tasks.py`，prefix `/tasks`）

| 方法 | 路径 | 请求关键字段 | 响应关键字段 |
|---|---|---|---|
| `GET` | `/tasks` | `status`（默认 `open`）、`kind`、`limit`（默认 50，**硬上限 200**）、`offset` | `items[]`（含 `sort_rank` / `sort_reason`）、`total`、`limit`、`offset` |
| `POST` | `/tasks` | `title`（必填）、`kind`、`note`、`remind_at`、`source` | 任务对象（含 `id` / `sort_rank` / `sort_reason`） |
| `PATCH` | `/tasks/{id}` | `title` / `note` / `remind_at` / `kind`（**不含 `status`**） | 任务对象 |
| `POST` | `/tasks/{id}/complete` | 无 | 任务对象（`status="done"`、`completed_at` 非空） |
| `POST` | `/tasks/{id}/reopen` | 无 | 任务对象（`status="open"`、`completed_at=null`） |
| `DELETE` | `/tasks/{id}` | 无 | 任务对象（`status="cancelled"`，**软取消**，不物理删） |

**任务对象响应字段**：`id` / `user_id` / `kind` / `title` / `note` / `status` / `remind_at` / `sort_rank` / `sort_reason` / `source` / `completed_at` / `created_at` / `updated_at`。
**错误语义**：`404` 不存在；`403` 越权；`400` 参数非法（`limit` 超硬上限 / `title` 空）；`409` 终态冲突；**不透传堆栈**。身份只从既有机制解析（API-001 落地后走 token），请求中的 `user_id` **拒绝**。

#### 4.1.3 勾选完成语义（**幂等**）

| 场景 | 契约 |
|---|---|
| `complete` 一个 `open` 任务 | → `status="done"`、`completed_at=now`；200 |
| `complete` 一个**已 `done`** 任务 | → **不变**（`completed_at` 保持原值）；200（**幂等**） |
| `complete` / `reopen` 一个 `cancelled` 任务 | → `409`（终态不可变更；显式优于静默） |
| `reopen` 一个 `done` 任务 | → `status="open"`、`completed_at=null`；200 |
| `reopen` 一个**已 `open`** 任务 | → **不变**；200（**幂等**） |
| 并发两次 `complete` | → 结果与单次一致（`completed_at` 只写一次；靠 `status` 条件更新，**不做「先查后写」**） |

> **幂等判据**：对同一任务连续 `complete` N 次，`status` / `completed_at` / `updated_at`（除首次）**均不变**；重复调用**不重复注册提醒**。

#### 4.1.4 时间提醒注册字段与语义

| 项 | 契约 |
|---|---|
| 触发条件 | `remind_at` 非空且 `status="open"` |
| 注册路径 | 经**既有 reminder 能力**（`services/action/capabilities/reminder`，架构基线 §3.5）注册；**不新建调度器**（§3.2 第 3 条） |
| 落点 | `reminder_ref` 存注册产出的行动台账 id（`action_records.id`） |
| 幂等 | 同一 `(task_id, remind_at)` 只注册一次；`remind_at` 变更 → 旧注册取消、新注册建立 |
| 终态 / 投递 | 任务完成 / 取消 → 已注册提醒**取消**（`reminder_ref` 置空或标记失效）；投递归既有 `proactive_delivery` 与端侧本地通知（`APP-019`），本任务**不做投递** |

#### 4.1.5 `order_reason`（排序理由）契约

| 项 | 契约 |
|---|---|
| 存储 | `sort_rank`（位次）+ `sort_reason`（文案）**落在任务行上**（数据，不是读时生成） |
| 生成方 | **任务域服务**（`services/tasks/`），确定性规则；**不做 LLM**（§3.2 第 4 条） |
| 规则输入（冻结） | `remind_at` 临近度 → 是否「晚间」标签 → 创建先后 → `id` 兜底（保证全序、可复算） |
| 文案形态 | 模板化短语（如「14:30 有提醒，排在最前」「晚间事项，稍后处理」）；**不含金额 / 健康数值** |
| 读取方 / 刷新 | `API-004` 以 `order_reason` 读出（`requirements-analysis.md:162`）；写入时重算，跨天首读时重算（**同输入同输出**） |

### 4.3 数据流

```text
   → life_task_repository.list_by_user(user_id, status="open", limit=硬上限)
   → 逐项 order_reason = sort_reason（服务端已算好，客户端只渲染）
```
