**结论**：本任务是 `APP-003 → APP-010` 关键路径的落点（`tasks.md:230`），也是 R5（渲染性能）的**唯一对策承载者**。

### 2.2 为什么必须做，且必须逐条按 §3.2 落地

1. **逐 token 重绘会直接掉帧。** token 到达频率极高，每个 token 触发一次重绘会掉帧（`flutter-architecture.md:227`）。这不是优化项，是**正确性**问题——M1 验收要求「真机对着后端发一句话，能**逐字**看到回复」（`tasks.md:142`），抖动的逐字体验即验收失败。
2. **半截 Markdown 会闪烁。** 流式文本反复解析 Markdown 成本高，且半截语法（如刚出现 `**` 未闭合）会闪烁（`flutter-architecture.md:228`）。
3. **静默断流是不可接受的失败模式。** 网络中断时 `done` 未到，若当作正常结束，用户会看到一段「说完了但没说完」的文本且**无法重试**（`flutter-architecture.md:229`）。
4. **不取消就是泄漏。** 用户返回或切页后流仍在跑、回调仍在写状态，会造成「已卸载页面 setState」与资源泄漏（`flutter-architecture.md:230`）。
5. **它是 `APP-011` 的前置。** `tasks.md:139` 明确 `APP-011`（消息组件与输入栏）依赖 APP-010；气泡渲染消费本任务产出的正文与状态。

### 2.3 在 V5.0.0 中的位置

关键路径上：`APP-003 → APP-010 → APP-011`（`tasks.md:230`）。它同时是 `APP-009`（装配）的渲染数据源，与 `APP-013`（过程卡）并列消费同一 `ChatTurnState`。

## 4. Technical Design Requirements

### 4.1 接口与行为契约

#### 4.1.1 `ChatTurnState` 字段契约（唯一状态真相）

| 字段 | 类型 | 初值 | 语义 | 写入方 |
|---|---|---|---|---|
| `status` | 枚举 `idle \| streaming \| toolRunning \| done \| failed` | `idle` | 本轮生命周期状态 | 本任务（唯一） |
| `text` | `String` | `""` | 正文累积（由 `token` 的 `delta` 拼接） | 本任务（节流后） |
| `memoryRefs` | `List<MemoryRef>` | 空 | 来自 `turn_meta`（`API-003`）；**键缺省 ⇒ 空列表**（与「无引用」同义，端上不区分） | 本任务 |
| `toolSteps` | `List<ToolStep>` | 空 | 来自 `tool_step`（`API-002`） | 本任务（写入）/ APP-013（渲染） |
| `chips` | `List<QuickAction>` | 空 | 结果卡快捷操作（服务端下发） | 本任务（写入）/ APP-013（渲染） |
| `error` | `AppError?` | `null` | 统一错误模型（APP-003 交付） | 本任务 |
| `incomplete` | `bool` | `false` | **断流标记**：`done` 未到即流结束 | 本任务（§4.1.5） |
| `canceled` | `bool` | `false` | 用户主动取消 / 页面 dispose 取消 | 本任务（§4.1.6） |

**硬约束**：
1. **`status` 只有本任务能写**——它是流式生命周期的唯一权威（避免多处写状态导致竞态）。
2. `text` 的每次更新都**必须**经合帧节流（§4.1.3）；**禁止**在 `token` 回调里直接改状态。
3. `incomplete` 与 `canceled` **互斥**：取消不是失败，断流不是取消（§4.1.5 / §4.1.6）。

#### 4.1.2 状态迁移表

| 起始 | 事件 | 终态 | 备注 |
|---|---|---|---|
| `idle` | 发起请求 | `streaming` | 收到 `turn_meta` 前即为 `streaming`（首 token 预算从此刻起算） |
| `streaming` | 收到 `tool_step(status: running)` | `toolRunning` | 过程卡开始执行 |
| `toolRunning` | 收到 `token` | `streaming` | 工具完成后继续出正文 |
| `streaming` / `toolRunning` | 收到 `done` | `done` | 收口；`incomplete = false` |
| `streaming` / `toolRunning` | 流结束但**无** `done` | `failed` | `incomplete = true`；**可重试**（§4.1.5） |
| `streaming` / `toolRunning` | `failure` 事件 | `failed` | `error` = 统一错误模型；`incomplete = false` |
| `streaming` / `toolRunning` | 用户取消 / dispose | `failed` | `canceled = true`；**不显示重试**（用户主动） |
| `done` / `failed` | 新一轮开始 | `streaming` | 旧 turn 落历史后新建 turn |

**非法迁移（必须抛断言 / 拒绝）**：`done → streaming`（同一 turn 不得复活）、`failed → done`（不得把失败洗成成功）。

#### 4.1.3 合帧节流契约（**细节 1：逐 token 重绘**）

| 项 | 契约 |
|---|---|
| 问题 | token 到达频率极高，每个 token 触发一次重绘会掉帧（`flutter-architecture.md:227`） |
| 做法 | **合帧节流**：按 **16ms 窗口** flush 累积文本，**而非逐 token `setState`** |
| 累积方式 | token 回调只把 `delta` **追加到缓冲**（不触发重绘）；窗口到期时一次性把缓冲**并入** `text` 并通知 UI |
| 窗口 | **16ms**（≈60fps 的一帧）；该值为**契约常量**，不做成设置项 |
| 窗口到期时的行为 | flush 后**重置**缓冲与计时；若窗口内无新 token → 不 flush（不空转） |
| 流结束（`done` / 断流 / 取消） | **必须**先 flush 残余缓冲，再切换终态（否则会丢尾字） |
| 一致性 / 禁止 | `text` 最终值**必须**等于所有 `delta` 的顺序拼接（节流只影响**时机**，不影响**内容**）；**禁止**在 `token` 回调内直接写 `ChatTurnState.text`，**禁止**用 `Future.delayed` 递归模拟节流 |

#### 4.1.4 Markdown 增量渲染契约（**细节 2**）

| 项 | 契约 |
|---|---|
| 问题 | 流式文本反复解析 Markdown 成本高，且半截语法会闪烁（`flutter-architecture.md:228`） |
| 做法 | **只对「已闭合块」做完整解析**；**尾部未闭合块按纯文本渲染** |
| 「已闭合块」判定 | 以**块级边界**（空行 / 列表项结束 / 代码块闭合 ``` / 引用块结束）切分；最后一个**未闭合**的块为「尾部块」 |
| 尾部块渲染 | **纯文本**（不解析行内语法），避免半截 `**` / `` ` `` 闪烁 |
| 增量策略 | 已闭合块的解析结果**缓存复用**（只对新增的已闭合块做解析），不整篇重解析 |
| 降级路径 | 若选定的 Markdown 包不支持增量，则**流式期间**降级为轻量格式（纯文本 + 换行），`done` 后一次性完整渲染（§4.1.8） |
| 硬约束 | **不得**在每个 flush 周期对**整篇**文本做完整 Markdown 解析 |
| 可判定 | 单元用例：给定「含未闭合 `**` 的流式文本」→ 尾部块按纯文本渲染，**不**产生粗体闪烁 |

#### 4.1.5 断流契约（**细节 3**）

| 项 | 契约 |
|---|---|
| 触发 | `done` 未到即流结束（网络中断 / 连接被关） |
| 处置 | 标记 turn 为「**不完整**」：`status = failed` + `incomplete = true` |
| **禁止** | **静默当作正常结束**（不得置 `done`、不得吞掉标记） |
| UI 表达 | 由 APP-011 / APP-013 渲染「不完整」提示与**重试**入口；本任务提供 `incomplete` 标志与重试所需的上下文 |
| 重试语义 | 重试 = **新一轮**请求（不拼接旧文本），旧 turn 保留在历史中并标注不完整 |
| 与 `failure` 事件的区别 | `failure` 是**服务端明确下发**的失败（`chat.py:85/89/93`）；断流是**没有收口信号**——两者都进 `failed`，但 `incomplete` 只对断流为 `true` |
| 与取消的区别 | 取消是**用户/页面**主动（`canceled = true`，不提示重试）；断流是**被动**（提示重试） |
| 可判定 | 契约回放用例：`done` 缺失的 fixture → `incomplete == true` 且 `status == failed` |

#### 4.1.6 取消契约（**细节 4**）

| 项 | 契约 |
|---|---|
| 持有 | 每个 turn 持有独立 `CancelToken`（由 APP-003 提供，`APP-003.md:175-185`） |
| 页面 dispose | **必须**在 dispose 时 `cancel()`，避免泄漏 |
| 切页 / 返回 | 同 dispose |
| 新 turn 覆盖旧 turn | 旧 `CancelToken` **先取消再新建** |
| 取消后的行为 | 不得再向上游发出事件；**先 flush 残余缓冲**再置 `canceled = true`；已累积文本按「已取消」终态**保留** |
| 终态 | `status = failed` + `canceled = true`（**不提示重试**） |
| 可判定 | 单元用例：dispose 后上游零事件；`canceled == true` |

#### 4.1.7 长文本虚拟化契约

| 项 | 契约 |
|---|---|
| 层级一：消息流 | 消息列表走 **`ListView.builder` 型虚拟化**（只构建可见项）；**禁止**一次性构建全部历史消息 |
| 层级二：单条超长文本 | 单条消息正文若超过阈值（冻结为 **4000 字符**），按**块边界**切分为多个可虚拟化的子项，避免单条 Text 撑爆布局 |
| 阈值 | `4000 字符`为**契约常量**，非设置项 |
| 与滚动定位的关系 | 虚拟化**不得**破坏「进入会话定位末条」（由 APP-009 负责定位；本任务保证列表可被定位到末项） |
| 可判定 | widget 用例：100 条消息时构建的 widget 数远小于 100；超长单条被切分 |
| 性能基线（可复现） | **首 token ≤ 1.5s**（从 `streaming` 起算到首个 flush 后的首个可见字符，`requirements-analysis.md:219`）；**流式与滚动均 60fps**（帧时间线测量） |

#### 4.1.8 Markdown 包选型与降级契约

| 项 | 契约 |
|---|---|
| 选型约束 | 包清单第 16 项为「Markdown 渲染包（`flutter_markdown` 或 `markdown` + 自绘）」（`flutter-architecture.md:140`）；**版本与最终选型由 APP-001 冻结**，本任务不自行新增依赖 |
| 核心诉求 | **流式增量渲染**是选型核心诉求（`flutter-architecture.md:91`） |
| 若选定包支持增量 | 走 §4.1.4 的标准路径（已闭合块完整解析 + 尾部纯文本） |
| 若选定包不支持增量 | 走**降级路径**：流式期间纯文本 + 换行；`done` 后一次性完整渲染。**降级路径必须实现**，不得因选型未定而阻塞 |
| 降级触发条件 | 由本任务的渲染器**按能力开关**决定，不由页面判断 |
| 待定 + 阻塞条件 | 若 APP-001 冻结的包**既无增量能力、又无法在 `done` 后完整渲染**（如无任何 Markdown 支持），则**阻塞条件**为：回改 APP-001 的依赖清单（属 APP-001 缺陷，不在本任务扩依赖） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| **D1** | **逐 token 重绘 → 合帧节流（16ms 窗口）** | `flutter-architecture.md:227`；token 频率极高，逐 token `setState` 会掉帧。**这是细节 1 的直接落地** |
| **D2** | **Markdown 只对已闭合块完整解析，尾部未闭合块按纯文本** | `flutter-architecture.md:228`；避免半截语法闪烁与整篇重解析。**细节 2 的直接落地** |
| **D3** | **断流标记「不完整」+ 可重试，禁止静默当正常结束** | `flutter-architecture.md:229`；静默断流会让用户看到「说完了但没说完」且无法重试。**细节 3 的直接落地** |
| **D4** | **持有 `CancelToken`，dispose 时取消** | `flutter-architecture.md:230`；否则流与回调泄漏、已卸载页面被写状态。**细节 4 的直接落地** |
| D5 | **`ChatTurnState.status` 只有本任务能写** | 多处写状态会产生竞态（如 token 与 `done` 同时到）；状态机必须单一权威 |
| D6 | **`incomplete` 与 `canceled` 分离且互斥** | 断流（被动）与取消（主动）的 UI 表达不同（前者提示重试，后者不提示）；混为一谈会让用户取消后看到「重试」 |
| D7 | 节流窗口 **16ms 为契约常量**，不做设置项 | 裁决 9（`tasks.md:26`）；这是渲染参数不是产品配置 |
| D8 | **flush 必须覆盖终态切换**（`done` / 断流 / 取消前先 flush） | 否则会丢尾字——这是节流最典型的实现缺陷 |
| D9 | **已闭合块的解析结果缓存复用**，不整篇重解析 | `flutter-architecture.md:228` 的成本诉求 |
| D10 | **长文本双层虚拟化**（消息列表 + 超长单条切分） | `requirements-analysis.md:220`（长文本虚拟化）；R5 对策（`tasks.md:270`） |
| D11 | **降级路径必须实现**（流式期间纯文本 + `done` 后完整渲染） | Markdown 包选型未定（`flutter-architecture.md:91`）；不实现会阻塞整条链路 |
| D12 | 业务状态一律 **Riverpod**；`useState` / `useEffect` **禁用** | Hooks 边界（`flutter-architecture.md:56`）；hooks 只承载 widget 级临时资源（如动画 controller） |
| D13 | **不引入第二套状态管理** | 反范围（`flutter-architecture.md:146-154`） |
| D14 | 渲染层**不决定是否贴底**（那是 APP-009 的滚动策略） | 分工护栏（§3.2 第 6 条）；渲染层只暴露「文本增长」事实 |

### 4.3 数据流

```text
APP-003 core/network（NDJSON 解析）
   → ChatEvent union（sealed）
        ├── turn_meta  → memoryRefs / role_mode（→ APP-012）
        ├── token      → 【本任务】delta 追加到缓冲（不触发重绘）
        ├── tool_step  → toolSteps（写入）→ 状态置 toolRunning
        ├── done       → 【本任务】flush 残余 → status = done
        └── failure    → 【本任务】flush 残余 → status = failed + error
        ↓ 未知 type → fail-closed（APP-003 D4）
   → 【本任务】合帧节流器（16ms 窗口）
        · 缓冲累积（token 回调只追加）
        · 窗口到期 → 一次性并入 ChatTurnState.text → notify
        · 终态切换前强制 flush（D8）
   → ChatTurnState（唯一状态真相）
        ├── status: idle | streaming | toolRunning | done | failed
        ├── text / memoryRefs / toolSteps / chips / error
        └── incomplete / canceled
   → 【本任务】增量 Markdown 渲染器
        · 切分：已闭合块 / 尾部未闭合块
        · 已闭合块 → 完整解析（结果缓存复用）
        · 尾部块 → 纯文本
        · 降级：包无增量能力 → 流式纯文本，done 后完整渲染
   → 【本任务】长文本虚拟化（消息列表 + 超长单条切分）
   → UI（气泡与正文由 APP-011 渲染；过程卡由 APP-013）

生命周期：
   发起 → 建 CancelToken
   页面 dispose / 切页 / 新 turn → cancel()（先 flush 残余，再置 canceled）
   流结束无 done → incomplete = true（可重试，D3）
```
