### 2.2 为什么必须做

1. **它是「记账成本趋近于零」的兑现页。** 记账由对话完成（`APP-013` 的 4 步过程卡），账本页只负责**看与订正**；若金额展示各端各算，就会与「一次说一句就记好」的承诺脱节。
2. **它是 M2 收口点 C3 的另一半。** C3 判定标准 =「首页单请求成型 + **记账页与后端数字逐项一致**」（`tasks.md:257`）。本任务的 AC1 即 C3 的后半。
3. **它承载 `REQ-LEDG-05` 的不可逆语义。** 订正 = 冲正（生成冲正记录）+ 重录；`ledger.py:93` 的 `reason` 必填是服务端契约，客户端必须**先于**服务端拦住空原因并做二次确认（对齐 `PLA-016.md` D6 的同款裁决）。
4. **它的「观察卡」是「AI 叙事优先」在账本页的落点。** `requirements-analysis.md:101` 明确「观察卡依赖 API-006」——**这是本任务唯一的阻塞项**。

### 2.3 在 V5.0.0 中的位置

M2 客户端第 4 个任务（`tasks.md:168`）。后端能力最完整（`requirements-analysis.md:353`「记账域：可行性**高**，无阻塞项」），因此本任务是 M2 中最稳的一块；唯一外部依赖是「观察卡」的 `API-006`。

## 3. Scope

### 3.1 In Scope

1. **`B5 #ledger` 结构装配**（§4.1.1）：返回 → 总览卡 → AI 观察卡 → 分类支出条 → 最近账单，逐段照 `components.md:357-369`。
2. **`A3 sum-card` 契约**（§4.1.2）：深夜紫渐变 + 白字 + 环比趋势徽章。
3. **`A19 cat` 契约**（§4.1.3）：分类支出条与语义渐变。
4. **`A20 tx` 契约**（§4.1.4）：账单行 + **记录方式标签** + 记忆生效提示。
5. **端点消费契约**（§4.1.5）：7 个端点 + `POST /entries` 的字段级消费口径。
6. **订正交互契约**（§4.1.6）：冲正 + 重录；原因必填 + 二次确认。
7. **金额展示契约**（§4.1.7）：只用 `*_text`，客户端零换算；数值走 `AppTypography.numeric`。

#### 4.1.6 订正交互契约（`REQ-LEDG-05`）

> 原型「改成 40 元」来自 `#chatLedger` 的 chip（`components.md:339`，见 APP-013 §4.1.6）；账本页另提供账单行内「订正」入口。二者进入同一流程。

| 步 | 契约 |
|---|---|
| 1 | 用户触发订正（对话 chip「改成 40 元」/ 账单行「订正」） |
| 2 | 展示**原因输入**（必填，`1~80` 字符，对齐 `ledger.py:93-95`）；未填 → **提交被阻止** |
| 3 | **二次确认**：明示「订正是不可逆语义，将生成一条冲正记录」（对齐 `PLA-016.md` D6） |
| 4 | 确认 → `POST /ledger/entries/{id}/reverse`（带 `reason`）；**不硬删原记录** |
| 5 | 需重录 → 追加 `POST /ledger/entries`（`source="manual"`），由 `CorrectionResponse.new_entry_id` 关联 |
| 6 | 结果反馈：冲正成功 / 重录成功；相关查询**缓存失效并重取** |
| 7 | 取消二次确认 → **不提交**，无副作用 |

#### 4.1.7 金额展示契约（★ 客户端零换算）

| 项 | 契约 |
|---|---|
| 唯一来源 | **直接使用 API 返回的 `*_text` 字段**：`expense_text` / `income_text` / `net_text` / `amount_text` / `limit_text` / `consumed_text`（`ledger.py:44-51`、`:60-75`、`:124-135`） |

| 数据时间 | 账本类金额展示须**标注数据时间**（`flutter-architecture.md:373`） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 金额**只用 `*_text`**，客户端零换算 | 反范围纪律；`format_minor` 是唯一格式化出口，端上重复实现必然漂移（对齐 `PLA-016.md` D3） |
| D2 | 订正**必填原因**且**二次确认**；**不硬删** | `REQ-LEDG-05`；`reason` 是服务端必填（`ledger.py:93-95`）；冲正是不可逆语义，生成冲正记录（对齐 `PLA-016.md` D6） |
| D3 | 「亚丝娜的观察」**依赖 API-006**；未就绪时**降级** | `requirements-analysis.md:101`、`:174`；**阻塞项**（见 §7.3 阻塞标注） |
| D4 | 此页**无 Tab 栏** | `components.md:99` |
| D5 | 记录方式标签取自 `source`；未知值**不显示方式** | `REQ-LEDG-04`；`ledger.py:60-75` 的 `source` 是唯一来源；猜测会误导 |
| D6 | 记忆生效提示**仅在记忆域有来源时**渲染 | `components.md:368` 的「「咖啡不加糖」已记忆」是记忆回执；无来源不得伪造（对齐 `REQ-MEM-04`） |
| D7 | 环比徽章仅在 `compared_to_previous != null` 时渲染 | 无环比数据时不显示「—」/「0%」（避免被误读为零变化） |
| D8 | 观察卡的可执行动作（预算）走 `PUT /ledger/budgets` | `REQ-LEDG-06`；采纳建议是「AI 叙事 → 行动」的闭环 |

| D10 | 数值一律 `AppTypography.numeric` | 金额滚动不得左右跳动（`flutter-architecture.md:329`） |
| D11 | 零硬编码色值 / 圆角 / 投影 | 红线 2（`SKILL.md:43`） |
| D12 | 新增设置 = **无** | 裁决 9（`tasks.md:26`） |

### 4.3 数据流

```text
features/ledger/presentation/ledger_page
   → features/ledger/data/ledger_repository（L3：presentation 不得直调 dio）
        · GET /ledger/summary            → 段 2 总览卡 + 段 5 分类条
        · GET /ledger/entries?limit≤200  → 段 7 最近账单
        · GET /ledger/categories         → 分类名 / 别名
        · GET /ledger/budgets            → 观察卡的可执行动作（预算）
        · GET /insights?domain=ledger    → 段 3 观察卡（API-006；不可用则降级）
        · POST /ledger/entries/{id}/reverse（reason 必填）→ 订正
        · POST /ledger/entries（source=manual）→ 重录
        · PUT  /ledger/budgets            → 采纳预算建议
   → drift 只读缓存（账本汇总 / 账单；标注数据时间）
   → Riverpod provider → 渲染

装配红线：
   ✗ 客户端不做分的换算（D1）
   ✗ 不硬删账单（D2）
   ✗ 无环比数据不渲染徽章（D7）
```
