**结论**：本任务在**无 CI 的仓库**上从零建立流水线，且必须解决两个既存风险（风险 5 golden 一致性、风险 7 生成物覆盖）与一条全局合规约束（密钥不进仓库，`AGENTS.md:71`）。

### 2.2 为什么必须做

1. **它是「密钥不进仓库」从约定变成门禁的唯一手段。** `AGENTS.md:71` 是全局约定，但约定**需要审计手段**才能成立。本任务必须提供**可 grep / 可审计**的核验（§4.1.3），否则签名密钥与 API Key 会在某次赶工期被 `git add`。
2. **它是 flavor 隔离能否成立的可验证面。** `flutter-architecture.md:396-401` 定义了 flavor，但「隔离是否正确」必须由**产物证据**证明（applicationId / bundle id / 后端地址各不同）——这正是本任务的验收方式（§4.1.2）。
3. **它是 golden 门禁的落地处。** `PLT-004` 建了 golden 套件（`PLT-004.md:314`），但「golden 失败必须人工确认」（`flutter-architecture.md:405`）这一**流程规则**只能在 CI 中实现（自动跑 + 人工放行）。两者是「测试」与「门禁」的分工。
4. **它是决策 D7 的执行载体。** 「Android 优先、iOS 紧随」若只写在文档里，不会自动生效；必须落到**流水线的排期与验收顺序**（Android 链路先通、iOS 后通）——这正是 `tasks.md:218` 对 4.2 裁决的第 ⑤ 条要求。
5. **它是上架的前置链路的终点。** `PLT-002` 出上架资质结论（`tasks.md:215`），本任务把「可上架」变成「**已产出可安装产物**」（Android 内测渠道 + TestFlight 各一次）。

### 2.3 在 V5.0.0 中的位置

PLT 第 5 个任务，依赖 `APP-001`（`tasks.md:218`）。它是 `PLT-004`（测试门禁）与 `PLT-002`（上架资质）的**汇合点**：前者提供门禁命令，后者提供上架结论；本任务把二者串成**可执行流水线**。它不阻塞 M0~M4 的开发（P1），但**阻塞正式分发**——因此排期上应在 M2/M3 期间并行建设。

## 4. Technical Design Requirements

### 4.1 流水线契约

#### 4.1.1 CI 流水线契约（触发 + 步骤 + 门禁）

| 项 | 契约 | 依据 |
|---|---|---|
| 触发 | 每次提交 / 每次推送 / PR | `flutter-architecture.md:405`（每次提交跑） |
| 步骤 1 | `flutter pub get` | 依赖解析 |
| 步骤 2 | `flutter analyze` | 期望 **0 issue**（`APP-001.md:314`） |
| 步骤 3 | `dart run build_runner build --delete-conflicting-outputs` → `git diff --exit-code` | 生成物一致性（`flutter-architecture.md:116`；`PLT-004.md:337`） |
| 步骤 4 | 单元 + widget + 契约回放 | `flutter test test/`（`PLT-004.md:378`） |
| 步骤 5 | **golden** | `flutter test test/design_system`（失败须人工确认，§4.1.7） |
| 步骤 6（可选，发布前） | 集成 / 性能回归 | 阶段末（`PLT-006` 口径） |
| 门禁 | 步骤 2~5 任一失败 → **阻断**（golden 例外见 §4.1.7） | 本任务 D1 |
| 级别映射 | 对齐 `TESTING.md:99-104` 的 Fast → Integration → E2E → Full 思路 | `docs/TESTING.md` |

#### 4.1.2 flavor 隔离契约（★ 可验证）

| 项 | `dev` | `prod` | 验证方式 |
|---|---|---|---|
| applicationId / bundle id | 带 `.dev` 后缀 | 正式 id | 产物元数据（`aapt dump badging` / `Info.plist`）比对 |
| 后端地址 | `--dart-define=API_BASE_URL=<dev>` | `--dart-define=API_BASE_URL=<prod>` | 产物内**不含**硬编码地址；启动日志 / 配置读取验证 |
| 日志级别 | verbose（**仍禁打金额与健康数值**） | error | 配置比对（`APP-001.md:112`） |
| 密钥 | **绝不进仓库** | 同左 | §4.1.3 |
| 注入方式 | `--dart-define`（**不写进仓库**） | 同左 | `APP-001.md:192`（D5） |

> **纪律**：未传 `--dart-define` 时启动**必须失败并给出明确提示**，不得静默回退到硬编码地址（`APP-001.md:316`）。

#### 4.1.3 密钥管理契约（★ 硬约束）

| 项 | 契约 | 依据 |
|---|---|---|
| 存放 | CI 平台 **secret 机制**（如 GitHub Actions secrets / 环境变量）；本地开发用未入库的 `.env` | `AGENTS.md:71`（「只从环境变量或 `.env` 读取」） |
| **绝不进仓库** | 签名密钥（keystore / provisioning profile）、API Key、后端地址敏感值 | `flutter-architecture.md:402`；`AGENTS.md:71` |
| `.gitignore` | 显式忽略 `*.jks` / `*.keystore` / `*.mobileprovision` / `.env*` / `key.properties` | 本任务冻结 |
| 审计方式 | ① `git ls-files` 检索敏感扩展名；② `grep` 源码检索硬编码密钥模式；③ 提交前 hook 或 CI 步骤拦截 | 本任务 AC2 |
| 违规后果 | 密钥一旦入库 → 视为**安全事件**，须轮换密钥（不得只删文件） | 安全纪律 |

#### 4.1.4 签名与混淆契约

| 平台 | 契约 | 依据 |
|---|---|---|
| Android 签名 | keystore 从 CI secret 注入；`key.properties` **不入库** | `AGENTS.md:71` |
| Android 混淆 | **开 R8** | `flutter-architecture.md:403` |
| iOS 签名 | provisioning profile / certificate 从 CI secret 注入；不入库 | 同上 |
| iOS 混淆 | 按 iOS 构建配置（`flutter-architecture.md:403` 提及「iOS 开 bitcode 相关配置」） | `flutter-architecture.md:403` |
| 产物可复现 | 同 flavor + 同 commit + 同配置 → 可重复构建 | 工程纪律 |

#### 4.1.5 分发契约

| 渠道 | 契约 | 依据 |
|---|---|---|
| **Android 内测渠道** | 产出**可安装产物**（APK / AAB）并分发到内测渠道；**先通** | `flutter-architecture.md:404`；D7 |
| **iOS TestFlight** | 产出可安装产物并上传 TestFlight；**后通** | `flutter-architecture.md:404`；D7 |
| 分发前置 | 上架资质结论（`PLT-002`）不阻塞**内测**，但阻塞**正式上架** | `PLT-002.md:§4.1.3~4.1.6` |
| 产物归档 | 每次分发保留产物 + 构建元数据（commit / flavor / 版本号） | 可追溯 |

#### 4.1.6 平台顺序契约（★ 决策 D7）

| 顺序 | 平台 | 流水线要求 | 验收要求 |
|---|---|---|---|
| 1（优先） | **Android** | 构建 / 签名 / 内测分发链路**先建成并跑通** | Android 内测产物**先出**一次可安装产物 |
| 2（紧随） | **iOS** | 在 Android 链路跑通后接入 TestFlight | iOS 产物**后出**一次可安装产物 |
| 理由 | — | Health Connect 路径风险低于 HealthKit，且调研主路径在 Android | `requirements-analysis.md:377`（D7）；`tasks.md:78` |

> **纪律**：流水线的**排期与验收顺序**必须体现该顺序（`tasks.md:218` 4.2 裁决 ⑤）；不得先做 iOS 再补 Android。

#### 4.1.7 golden 门禁契约

| 项 | 契约 | 依据 |
|---|---|---|
| 自动跑 | 每次提交自动跑 golden | `flutter-architecture.md:405` |
| **失败必须人工确认** | golden 失败**不自动判为失败**——视觉变更**可能是有意的**；须人工复核 diff 后放行或修正 | `flutter-architecture.md:405`（原话） |
| CI 不一致处置 | 与 `PLT-004` 一致：**固定容器镜像**跑，或 CI 标记「**非阻塞告警**」；二者**只选一种**并固化 | 风险 5（`flutter-architecture.md:417`）；`PLT-004.md:§4.2 D6` |
| 与 `PLT-004` 边界 | 门禁**规则**归本任务（CI）；golden **用例与 fixture** 归 `PLT-004` | `tasks.md:217-218` |

#### 4.1.8 codegen 产物校验接入契约

| 项 | 契约 |
|---|---|
| 命令来源 | `PLT-004` 提供（`dart run build_runner build --delete-conflicting-outputs` → `git diff --exit-code`） |
| 接入点 | CI 步骤 3（§4.1.1） |
| 失败含义 | 生成物未提交或被互相覆盖（风险 7，`flutter-architecture.md:419`） |
| 归属 | 约定由 `APP-001` 冻结；命令由 `PLT-004` 提供；**执行**由本任务接入 CI |

### 4.3 数据流（谁产出、谁消费）

```text
【触发】每次提交 / 推送 / PR
   ↓
CI 流水线（本任务交付）
   ① flutter pub get
   ② flutter analyze                        → 0 issue（阻断）
   ③ build_runner build + git diff --exit-code → 生成物一致（阻断）★PLT-004 命令
   ④ flutter test test/（单元 + widget + 契约）→ 通过（阻断）★PLT-004 套件
   ⑤ flutter test test/design_system（golden） → 失败须人工确认（D5）
   ↓ 通过

   flutter build apk|aab --flavor prod --dart-define=API_BASE_URL=<secret>

      · 混淆：R8（D4）
   flutter build ipa --flavor prod --dart-define=...（iOS 紧随，D6）
   ↓
【分发】
   Android 内测渠道（先）  → 可安装产物
   iOS TestFlight（后）     → 可安装产物

【消费方 —— 本任务存在的理由】
  ① 全部 APP-* 任务   ← 每次提交被门禁拦住回归（analyze / 单元 / golden / codegen）
  ② PLT-004（测试）   ← 本任务为其 golden 与契约套件提供**执行与门禁**（分工：用例 vs 流水线）
  ③ PLT-002（合规）   ← 本任务消费其上架资质结论，决定正式上架节奏
  ④ PLT-006（性能）   ← 发布前性能回归可挂在流水线步骤 6
  ⑤ 内测用户 / 团队   ← 消费可安装产物

装配红线：
  ✗ 密钥 / API Key 入库（D3）
  ✗ 后端地址写进仓库（D2）
  ✗ golden 失败被自动判为通过或自动放行（D5）
  ✗ 先 iOS 后 Android（D6）
  ✗ 未传 dart-define 静默回退硬编码地址（D8）
```

## 7. Testing Requirements

> 本任务交付物是流水线，故此处为**对流水线自身的验证项**（等价于「CI 的 CI」）。

### 7.1 门禁有效性

| 用例 / 验证 | 断言 |
|---|---|
| `ci_blocks_on_analyze_failure` | 故意注入一个 lint 错误 → CI **阻断** |
| `ci_blocks_on_test_failure` | 故意注入一个失败用例 → CI **阻断** |
| `ci_blocks_on_codegen_drift` | 故意改模型不提交生成物 → CI **阻断**（步骤 3） |
| `ci_golden_failure_requires_manual_confirm` | golden 失败 → **不自动放行**，等待人工确认（D5） |
| `ci_runs_on_every_commit` | 每次提交均触发（触发条件验证） |

### 7.2 flavor 与密钥

| 用例 / 验证 | 断言 |
|---|---|
| `flavor_dev_prod_application_id_differs` | 两 flavor 产物的 applicationId / bundle id **不同** |
| `flavor_api_base_url_injected_not_hardcoded` | 产物内**不含**硬编码后端地址；地址来自 `--dart-define` |
| `missing_dart_define_fails_fast` | 未传 `--dart-define` → 启动失败并提示（D8） |
| `no_secret_in_repo_by_extension` | `git ls-files` 无 `*.jks` / `*.keystore` / `*.mobileprovision` / `key.properties` / `.env*` |
| `no_hardcoded_secret_in_source` | `grep` 源码无硬编码 API Key / 密钥模式（`AGENTS.md:71`） |

### 7.3 分发链路

| 用例 / 验证 | 断言 |
|---|---|
| `android_beta_artifact_installable` | Android 内测渠道产出**可安装产物**（**先**） |
| `ios_testflight_artifact_installable` | iOS TestFlight 产出**可安装产物**（**后**） |
| `android_before_ios_order` | 流水线与验收顺序体现 Android 先 / iOS 后（D6） |
| `r8_enabled_on_android_release` | Android release 构建开启 R8（D4） |
