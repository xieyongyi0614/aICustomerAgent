## 3. Scope

### 3.1 In Scope

1. `ledger_auto_page.dart`：照 B11 的 10 段（返回 → AI 结论卡 → 统计三卡 → 待确认 → 来源 → 规则 → 隐私说明）。
2. 路由 `/ledger/auto`（`chromeImmersive`）。
3. `ledger_repository.dart` 新增：`fetchPending()` / `confirmPending(pendingKey, …)` / `ignorePending(pendingKey)` / `fetchAutoSummary()` / `fetchRules()`。
4. **D14 降级实现**：来源区块为**静态能力声明**（三项「未接入」+ 不可用原因；语音记账「一直开着」），**不含任何动态计数**。
5. **缺省语义**：`accuracy` 缺省 → 统计三卡降为**两卡**（不占位、不显示 `--`）；`learned_from` 缺省 → 规则行**不渲染右侧来源**。
6. 待确认操作后的**乐观更新 + 失败回滚**（失败提示并恢复原列表）。
7. 隐私说明：文案照 `pages/34:177` 的语义，但**不得承诺"关闭同步后立刻停止读取"这类与未接入状态矛盾的话**（见 §4.2 裁决 3）。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | **渲染任何同步来的账单动态数据**（「今天同步 6 笔」「昨天同步 11 笔」） | 平台不可行（缺口 19）；渲染即造假（D14） |
| 2 | 实现微信 / 支付宝 / 银行卡短信的任何接入或模拟 | 同上；真实账单**文件导入列 V2** |
| 3 | 编造「修正 N 次后学会」 | 缺口 20；`API-016` 无来源时字段缺省 |
| 4 | 编造 / 估算分类准确率 | `API-016` §4.2 裁决 2；缺省即不渲染该卡 |
| 5 | 来源开关的**实际开关行为**（开启 / 关闭同步） | 无同步能力则开关无对象；做成可点会立刻变成假交互（`progress-audit` §2.1 #4 的同类缺陷） |
| 6 | 待确认的批量操作 / 历史已确认记录页 | 见 `API-015` §3.2 #5；设计稿为逐条操作 |

## 4. Technical Design Requirements

### 4.1 页面契约（照 `components.md:570-585` B11）

| # | 段 | 组件 | 内容来源 |
|---|---|---|---|
| 1 | 返回 | `BackLink` | 「‹ 记账」 |
| 2 | AI 结论卡 | `AiCard` | 文案含真实 `auto_count` / `pending_count`；**无 `accuracy` 时不提准确率** |
| 3 | 统计三卡 | `LedgerStatCard` × N | `auto-summary`：本月自动记账（`auto_count` 笔）/ 分类准确率（`accuracy`，可缺省）/ 待你确认（`pending_count` 笔） |

| 5 | 待确认行 | `LedgerConfirmRow` | `pending` 列表：标题 = 商户 / 金额；AI 判断 = 「我的判断：{category_name} · {direction}」；按钮组按 `reason` 变化（见 §4.2 裁决 2） |
| 6 | 区块标题 | `_SectionTitle` | 「自动同步来源」+ hint「随时可关」 |
| 7 | 来源组 | `SettingGroup` + `SettingRow` | **静态能力声明**（§4.2 裁决 3） |
| 8 | 区块标题 | `_SectionTitle` | 「我学会的规则」+ hint（`learned_from` 缺省时不带数字） |
| 9 | 规则行 | `LedgerRuleRow` | `rules` 列表 |
| 10 | 隐私说明 | `PrivacyNote` | 见 §4.2 裁决 3 |

**A33 页面纪律**（`components.md:328`）：AI 结论卡**必须在待确认列表之前**（段 2 早于段 5）。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **空态而非占位数字**：无待确认时「需要你的确认」整段显示诚实空态（「这个月没有拿不准的账单」），**不显示"0 笔待确认"卡片堆** | 延续 `APP-014` 的空态分支先例（`traceability.md` §13.4、`tasks.md:168`） |
| 2 | **待确认行的按钮组由 `reason` 决定文案** | `reason` 是服务端语义（`confirmation.py:15-19`）：`direction_ambiguous` → 「记为支出 / 记为收入」；`amount_over_threshold` / 其他 → 「确认 / 修改」；`category_ambiguous` → 候选分类 chip + 「忽略」。端上**按 reason 映射语义动作**，不猜测金额 |
| 3 | **来源区块 = 静态能力声明，零动态计数** | 三项「未接入」+ 原因（微信 / 支付宝无公开账单接口；银行卡短信受系统权限限制）；语音记账标「一直开着」。**不含开关、不含同步时间、不含条数**——因为无同步能力时开关无对象（§3.2 #5） |
| 4 | 隐私说明**去掉与状态矛盾的承诺** | `pages/34:177` 的「关闭同步后我会立刻停止读取」预设了同步已接入；改为「账单数据只用于帮你记账与生成消费观察；**目前我不会读取任何第三方账单**，语音记账只在你主动说话时发生」 |
| 5 | **`accuracy` 缺省即整卡不渲染**（统计区从三卡变两卡） | `API-016` §4.2 裁决 2；显示 `--` 或 `0%` 都是误导 |
| 6 | **`learned_from` 缺省即不渲染来源位** | 缺口 20；渲染「修正 0 次后学会」荒谬 |
| 7 | 待确认操作用**乐观更新 + 失败回滚** | 确认是高频轻操作；等待往返会让「确认」手感变差。回滚保证不产生"看起来成功了但没成功"的状态 |

### 4.3 数据流

```text
进入页面
  ├─ repository.fetchAutoSummary()   GET /ledger/auto-summary
  ├─ repository.fetchPending()       GET /ledger/pending
  └─ repository.fetchRules()         GET /ledger/rules
确认
  → repository.confirmPending(pendingKey, categoryName?)  POST /ledger/pending/{k}/confirm
  → 乐观移除该行 → 成功则重拉 summary（笔数变化）；失败回滚并提示
修改
  → 弹选择（候选 category_name 来自 item.candidates）→ 同上
忽略
  → repository.ignorePending(pendingKey)  POST /ledger/pending/{k}/ignore
  → 乐观移除；失败回滚
来源 / 规则 / 隐私
  → 只读渲染；来源为本地能力常量
```
