### 2.2 为什么必须做

1. **它是 G5 缺口的唯一处置落点。** `traceability.md:280` 明确：「§02 五条设计原则缺可判定验收口径」→「已并入 `PLT-004`」。若本任务只交付「四层测试框架」而不交付**五条原则的验收化规则**，G5 缺口仍未闭合，设计原则继续停留在口号层面。
2. **它是「像不像朝夕」的可自动化防线。** 产品定位的成败在视觉与信息流（`principles.md:19-24` 视觉关键词），而 golden 是唯一能自动拦住「跑偏」的手段。Orb 是**全站唯一 AI 语义承载者**（`SKILL.md:43`），其四态视觉回归成本最高（`flutter-architecture.md:363`）。
3. **它是 M3 污染的唯一系统性防线。** 风险 6 明确「一旦发现漏出，先改主题层，禁止在业务组件里打补丁」（`flutter-architecture.md:418`）；但**发现**依赖本任务的 M3 特征回归 golden。没有它，M3 的色渗 / pill indicator 只能靠人眼偶然发现。
4. **它是「最难复现路径」的唯一可控复现手段。** `flutter-architecture.md:392` 指出 `tool_step` 序列与断流**最容易在真实环境出问题、又最难手工复现**；契约回放 fixture 是唯一能稳定复现的手段。不建 fixture，M1 的过程卡与断流恢复（`APP-013` / `APP-010`）将缺乏回归保护。
5. **它保护「生成物」这一已登记风险。** 风险 7「三生成器 `.g.dart` 互相覆盖」（`flutter-architecture.md:419`）；本任务的 codegen 产物校验是其在 CI 侧的落地（`APP-001.md:159-169`）。

### 2.3 在 V5.0.0 中的位置

PLT 第 4 个任务，依赖 `APP-001`（`tasks.md:217`），且 `tasks.md:217` 明确「**M0 起就要有**」——因为它为 M0 收口点 **C1**（设计系统冻结，`tasks.md:255`）提供验证手段。它是 `PLT-005`（CI 门禁）与 `PLT-006`（性能复测）的上游；其 golden 基线一旦建立，后续所有 `APP-*` 页面任务都必须通过它才能收口。

## 4. Technical Design Requirements

### 4.1 测试契约

#### 4.1.1 四层测试映射契约

> 逐层对齐 `flutter-architecture.md:382-390`（§8）。

| 层 | 覆盖对象 | 工具 | 执行级别（对齐 `TESTING.md` 思路） |
|---|---|---|---|
| 单元 | token 计算、NDJSON 行解析、状态机转移（tool step 推进）、金额格式化、**脱敏层** | `flutter_test`（纯 Dart，无需设备） | Focused → Module（默认日常） |
| **Golden** | **Orb 四态 × 尺寸**、渐变描边卡、指标卡、任务行、账单行、记忆卡、**M3 特征回归** | `matchesGoldenFile` | Module（CI 必跑，见 §4.2 D6） |
| Widget | 页面装配（mock repository 注入假数据）、四态（加载 / 空 / 错 / 骨架） | `flutter_test` + `mocktail` | Module |
| **契约** | NDJSON 事件序列回放（真实后端录制的流做 fixture），**含 `tool_step` 与断流** | 自定义 fixture runner | Module（回归必跑） |
| 集成 | 真机走通：对话流式 → 过程卡 → 记账落库 | `integration_test` | 阶段末 / 发布前（**不默认**） |

> **纪律（借 `TESTING.md:4` / `:52-59`）**：**测试可靠性 > 覆盖数量 > 执行数量**；AI 改码后**不默认全量**，按变更影响范围选层执行（`TESTING.md:61-71` 的 Flutter 对侧）。

#### 4.1.2 五条设计原则验收化契约（★ G5 处置）

> **直接引用 `principles.md` §1**（`principles.md:9-15`）的「可判定验收规则」列，落成 golden / 人工走查项。**不得另起一套**（`tasks.md:217`）。

| # | 原则 | 可判定规则（引用 `principles.md` §1） | 落地形式 |
|---|---|---|---|
| 1 | **AI 叙事优先** | 每页首屏**必须**存在 AI 结论块（`ai-card` / `insight-hero` / 结论文案），且**渲染顺序先于**原始数据区 | golden + 渲染树顺序断言（`test_info_flow_conclusion_before_data` 类）+ 人工走查「遮住下半屏仍能看懂 AI 帮了什么」 |
| 2 | **卡片即结论** | 全站**不得出现纯数据表格**；每个数据卡必须含一句结论文案 | golden + 人工走查「只有数字没有话 → 不合格」 |
| 3 | **记忆可见** | 每条记忆**必须**同时有「来源追溯」与（可用的）「用途回执」 | golden（记忆卡）+ 人工走查「点开任意记忆能看到来源；被用过的能看到用途」 |
| 4 | **主动但克制** | 三个主动开关（早间 / 晚间 / 异常）**默认可见且可关**；关闭后不再触发 | golden（开关组）+ 行为断言「关掉 → 到点无通知」+ 人工走查 |
| 5 | **温暖而非企业** | 全站无冷灰蓝主色；无密集边框（1px 实线框滥用）；圆角只取 24/18/12/999 | golden（含 M3 特征回归，§4.1.4）+ 人工走查「与设计稿截图比对无 M3 默认特征」 |

#### 4.1.4 M3 特征回归契约（★ 负向断言）

> 依据：`flutter-architecture.md:418`（风险 6 明确「PLT-004 加 M3 特征回归 golden」）与 `:78`（APP-002 验收）。

| # | 负向断言 | 判定 |
|---|---|---|
| 1 | **无色渗** | 页面内**不得**出现 M3 `surfaceTint` 导致的色偏（`Card` / `ElevatedButton` 无 tonal 叠色） |

#### 4.1.6 契约回放 fixture 契约（★ 最难复现路径）

| fixture | 必须包含 | 依据 |
|---|---|---|
| **`tool_step` 序列** | 完整工具步骤事件序列（`running → done` / `failed`；含 `step_id` / `tool_id` / `label` / `detail` / `target`），且能驱动过程卡四态渲染（`APP-013`） | `flutter-architecture.md:392`（§8 原话） |
| **断流场景** | `done` 未到就结束的流（网络中断）；回放后 turn **必须**被标记「不完整」，**不得**静默当正常结束 | `flutter-architecture.md:392`；`:229`（§3.2 断流） |
