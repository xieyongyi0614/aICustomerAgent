## 2. Background

### 2.1 现状：首页一屏需要 5+ 请求，且其中 1 个是 debug 接口

| 事实 | 证据 |
|---|---|
| 首页一屏需要 `state` / `memories` / `ledger/summary` / `ledger/budgets` / `debug/plans` / `proactive/pending` 拼装 | `requirements-analysis.md:176-180`（缺口 11） |
| 「今日任务 · AI 已排序」**无产品级来源**，只有 `GET /debug/plans` / `/debug/plans/pending` / `/debug/plans/{id}/steps` | `apps/backend/app/api/v1/debug.py:1181` / `:1222` / `:1248`；`requirements-analysis.md:92` |
| 健康三宫格无来源（健康域整体缺失，`services/tool/health.py` 是**工具熔断健康度**，命名撞车） | `requirements-analysis.md:99`；`tasks/README.md:113`（命名避歧） |
| 产品级洞察读面不存在 → 「今日 AI 总结」无来源 | `apps/backend/app/api/v1/debug.py:454`（仅 debug attribution）；`requirements-analysis.md:170-174` |
| 路由静态聚合 13 个子路由，**无 `home`** | `apps/backend/app/api/v1/router.py:19-31` |
| 既有读面可复用：`GET /state`（`state.py:53`）、`GET /ledger/summary`（`ledger.py:176`）、`GET /ledger/budgets`（`ledger.py:349`）、`GET /proactive/pending`（`proactive.py:17`） | 见括号内路径 |
| `app/api/**` 已有 **26 处**反向依赖 `app/repositories`（V4.0.0 记为 **L3 债**） | `tasks.md:25`；`apps/backend/app/api/v1/debug.py:47-57`（实证） |

**实际后果**：冷启动首屏必然慢，且**跨域合成逻辑泄漏到端上**——「AI 叙事优先」这条设计原则的架构保障被绕过。客户端一旦自己拼装总结，同一份数据在不同端会产生不同结论。

### 2.2 为什么必须做

1. **首页是 M2 的收口点 C3 的前提。** `tasks.md:257` 的 C3 判据是「首页单请求成型」；`APP-014`（首页装配）直接依赖本任务（`tasks.md:166`）。
2. **它承担「AI 叙事优先」的架构保障。** 设计原则第一条要求「每页首屏必须存在一个 AI 结论块，且位于原始数据之前」（`requirements-analysis.md:39`）。结论块要跨域合成，而**跨域合成只能在服务端**——放端上等于把原则交给每个客户端各自实现。
3. **它是对 L3 债的「不扩大」承诺。** 与 `PLA-015`（`docs/version/v4.0.0/tasks/PLA-015.md:18`）同源纪律：新增 API 文件必须完全合规，不把 26 处变成 27 处。
4. **它的风险点是「一个子域挂掉拖垮整屏」。** 健康域未落地、洞察可能为空、账本可能无数据——首页必须**区块级降级**而非整体 500。

### 2.3 在 V5.0.0 中的位置

M2 后端第 1 个任务，是 `API-005 / API-006 / API-007` 的**消费方**（`tasks.md:240` 依赖图 `API-005 → API-004 ← API-006 / API-007`）。它是 `APP-014`（首页）的唯一数据来源，也是 `API-008`（简报预生成）的上游（`tasks.md:181`）。

## 3. Scope

### 3.1 In Scope

1. **端点**：`GET /api/v1/home/summary`——一次返回全部区块（契约见 §4.1）。
2. **跨域合成服务**：`app/services/home/summary.py::build_home_summary(user_id, now)`——**唯一合成点**，聚合下列既有/新增读面：
   - 角色状态与模式：`services/state_service.load_snapshot` + `services/history_service.find_latest_conversation`（`state.py:60` / `state.py:20`）；
   - 账本：`services/ledger/query.summary` + `services/ledger/budget.check_all_budgets`（`ledger.py:188` / `ledger.py:349`）；
   - 任务：API-005 的任务域读面；
   - 洞察：API-006 的 `GET /insights?domain=home`（读面）；
   - 记忆口径：API-007 的 `GET /memory/items`（读面，供总结的来源追溯）；
   - 主动待办：`services/proactive_delivery` / `proactive_repository.list_pending`（`proactive.py:17`）。
3. **区块级降级**：每个区块自带 `available` 与 `degraded_reason`；任一子域异常 → 该区块返缺省/不可用标记，**其余区块照常**，HTTP 仍为 200。
4. **每个区块的 AI 结论文案字段**：`narrative`（见 §4.1 逐区块表）；无洞察/无数据时 `narrative` 为 `null`（**不编造**）。
5. **身份**：`user_id` 从既有身份机制解析（API-001 落地后走 token）；**不接受客户端传入的 `user_id`**。
6. **纯新增**：零新迁移、零 `*_enabled` 开关、零 `app/repositories` 反向依赖。

**区块 6 · `spend`（近 7 天消费速览）**

> 2026-10-07 起口径为**近 7 天**（含今天，产品时区本地日边界）；旧的「今日消费 + 预算进度」已退役
> ——日预算没有数据源（`ledger/budget.py` 的 `BudgetSpec.period` 只有 month/week），

### 4.2 关键裁决与铁律留痕

#### 4.2.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **跨域合成必须在服务端**（`services/home/summary.py` 是唯一合成点） | 「AI 叙事优先」的架构保障（`requirements-analysis.md:180`）；反范围项明令禁止端上合成（`requirements-analysis.md:394`） |
| D2 | **区块级降级**：任一子域异常 → 该区块 `available=false`，**不整体 500** | 首页任一子域（健康未落地 / 洞察为空 / 账本无数据）都常见；整体 500 会让首屏全黑，违背「10 秒内感受 AI 已整理好」 |
| D3 | `app/api/v1/home.py` **零 `app/repositories` 依赖**，合成下沉 `services/home/summary.py` | 铁律 1（`tasks/README.md:92`）；V4.0.0 已记 26 处 L3 债，新增 API 不得扩大（`tasks.md:25`） |
| D4 | **不加功能开关**（无 `home_summary_enabled`） | V4.0.0 裁决 9（`tasks.md:26`）；交付即生效 |
| D5 | 健康区块未落地时 `available=false` + `metrics=[]`，**不用假数据** | 决策 D1 门控（`requirements-analysis.md:371`）；`traceability.md:72` 已把三宫格标为「⚠️ 依赖 D1」 |
| D6 | 每区块**恰一个** `narrative` 结论文案字段；无数据返 `null` | 设计原则「卡片即结论」（`requirements-analysis.md:40`）；无数据编造 = 毒化信任 |
| D7 | `ai_summary` **只消费** API-006，不在本任务生成洞察 | 生成走既有 reflection / development（`tasks.md:157`）；避免第二套生成链路 |
| D8 | `tasks.items[].order_reason` 由**服务端**给出文案，客户端只渲染 | `requirements-analysis.md:162`（决策 D6 的排序理由口径） |
| D9 | 身份来自既有机制；请求中的 `user_id` **拒绝** | 越权红线（沿用 `ledger.py:141-149` 语义与 `PLA-015` D2） |
| D10 | 各区块有**硬上限**（任务 ≤ 5、待办 ≤ 3、周柱固定 7 点），超限截断 | 首屏是摘要不是列表；防超大查询 |
| D11 | 零新迁移、零新表 | 本版本只加 `0055`（`tasks.md:37`）；首页是投影 |
| D12 | **不建第二套 Agent**：本任务不注册 Profile 阶段、不产 LLM 决策 | V4.0.0 裁决 8 R1（`docs/version/v4.0.0/tasks.md:130`）；纯读面聚合 |
