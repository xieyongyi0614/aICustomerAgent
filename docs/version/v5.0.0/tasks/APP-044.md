### 2.2 为什么必须做

1. **没有它，「不上架 = 用户永远用不到新版本」。** `self-distribution-guide.md:17` 已定性「不上架 = 失去商店自动更新：版本告知、下载与安装引导必须自己承担（当前无『检查更新』实现）」；`self-distribution-guide.md:103` 的兜底话术是「每次发新版同步发『新版本说明 + 新安装包』」——这是**人工广播**，随用户量增长不可持续。
2. **它是 `API-022` 的唯一消费方。** 后端表与端点建好后若无客户端消费，等于零收益；本任务是整条发布链的收口端。
3. **它必须解决「装不上」这一最高频失败面。** 现状 `AndroidManifest.xml:4-18` 缺 `REQUEST_INSTALL_PACKAGES`、`:19-55` 缺 FileProvider —— 这两项任一缺失都会让安装在新机型上**必然失败**，且失败信息对用户不可理解（`FileUriExposedException` / 无反应）。这是本域最高优先级的技术债。
4. **它必须处理「未同意不得发网络请求」的合规底线。** `self-distribution-guide.md:122` 的底线 1 是法律义务（与是否上架无关，`:130`），而更新检查天然是「业务网络请求」。若沿用「在 `bootstrap()` 里检查」的直觉做法，本任务会**制造一个新的合规违规**。
5. **它是「不引入模板包」这一裁决的兑现处。** `update-system-architecture.md` §1.2 否决了 `upgrader` / `in_app_update` / `flutter_ota`；那么 `A41` 面板、`A32` 按钮、进度条、关于页的每一处视觉都必须落到设计系统的**真实编号与规格**上，而不是自创。

### 2.3 在 V5.0.0 中的位置

APP 线第 44 个任务（`tasks.md:624` 登记「下一可用号 `APP-044`」），与 `API-022` / `PLT-008` 同批立项。它是发布链的**终点**，不影响 M0~M4 开发（P1），但**阻塞第一次可自我更新的分发**。

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 更新状态机与策略契约

```text
UpdateState（sealed 家族，仅本域内部使用）
  Idle
  Checking
  UpToDate(checkedAt)
  Available(strategy, latest, artifacts)
  Downloading(receivedBytes, totalBytes)         // 进度按 received/total 计算，不按百分比整数存
  Verifying
  ReadyToInstall(apkPath)
  PermissionRequired                             // 「安装未知应用」未授权
  Failed(reason, recoverable)
```

| 策略 | 判定条件（客户端按服务端下发值计算，**不自行推断**） | 交互 |
|---|---|---|
| `force` | `localVersionCode < latest.min_supported_version_code` **或** `latest.force_update == true` | 面板**不可关闭**（无把手关闭、无返回键关闭、无遮罩点击关闭）；仅「立即更新」；下载失败可重试，但不可跳过 |
| `recommend` | `localVersionCode < latest.version_code` 且非 `force` | 可「稍后再说」（**本次会话不再提示**，不写忽略态） |
| `ignore`（用户动作） | 用户点「忽略此版本」 → 写 `update.ignored_version_code` | 同一 `versionCode` 不再提示；**下次版本更高时重新提示** |
| 无更新 | `latest.version_code <= localVersionCode` 或 `has_update == false` | 无面板；手动检查时给一句确认文案 |

**§4.1.1.1 ★ 未知制品类型（fail-closed）**

| 输入 | 处理 |
|---|---|
| `artifacts[].type == "full"` | 正常流程；多个 `full` 取**第一个**并记 WARN |
| `artifacts[].type` 为其它值（含未来 `patch`） | **忽略该条 + 记 WARN**，不回退、不猜测 |
| `sha256` / `signature_fingerprint` / `size_bytes` 任一缺失或非法 | 该制品视为**不可用**（不跳过校验） |
| 过滤后无可用制品 | `Failed(reason: noApplicableArtifact)`，面板改为「到发布页手动下载」文案（`A12 chip-btn`） |

> 对齐后端既有 fail-closed 纪律（`tests/v30/test_runtime_contracts.py:27-42`）。

#### 4.1.3 ★ 检查触发与节流契约

| 触发 | 时机 | 节流 | 依据 |
|---|---|---|---|
| 自动检查 | `lib/app/update/update_gate.dart` 在 `MobileApp` 首帧后（`WidgetsBinding.instance.addPostFrameCallback`）触发 | 距 `update.last_check_at` ≥ **24h**；`dev` flavor 同规则 | D2 + `update-system-architecture.md` §5.2 |
| 手动检查 | 我的页「检查更新」行 / 关于页「检查更新」按钮 | **不受节流** | 用户显式动作 |
| 启动清理 | `update_gate` 初始化时清空私有目录下 `updates/` 的**残留**（非当前进行中） | 无条件 | §4.1.4 |
| 结果回收 | 首帧后读一次 `installedVersionCode()`，与 `update.last_check_at` 无关 | 无条件（轻量，本地调用） | D7 |

**裁决 D2：自动检查**不**在 `bootstrap()` 内发起，挂首帧后的 `app/` 层。** 理由：`self-distribution-guide.md:122` 的合规底线 1 要求「未点同意前不得发起业务网络请求」，而 `bootstrap.dart:19-50` **当前无同意门控**。把触发点放在首帧之后：① 现在即可工作；② `PLT-002` 落地同意弹窗后，弹窗必然在首帧之前拦截，**本任务无需改动**；③ 不在 `bootstrap()` 的 fail-closed 链（`app_env.dart:12-18`）上叠加网络副作用，保持启动路径的可预测性。

**裁决 D3：首帧后延迟触发，不立即触发。** 理由：冷启动首帧是性能预算竞争区（`PLT-006` 的「冷启动首屏 ≤ 2.5s」）；把网络请求推到首帧之后，避免与首屏渲染争带宽与主线程。落法：`addPostFrameCallback` + `Future.delayed` 一个小延迟（具体值由 `APP-044` 实现期与 `PLT-006` 基线共同确定，**不写死在本 Detail**）。

#### 4.1.4 下载契约

| 项 | 契约 |
|---|---|
| 落盘位置 | 应用私有目录：`getApplicationSupportDirectory()/updates/`（**不落外部存储**，免权限、免残留泄漏） |
| 文件命名 | `{artifactId}.apk`（临时态不加 `.part` 后缀——「不完整」由状态机而非文件名表达；避免两次运行间文件名不一致导致续传失效） |
| 续传 | 请求头 `Range: bytes=<已有字节数>-`；收到 `206` 视为续传成功，收到 `200` 视为从头开始（**必须截断本地文件**，否则拼接出错误内容——这是最容易踩的坑） |
| 进度 | 按 `receivedBytes / totalBytes` 累积；**合帧 16ms 窗口** flush（对齐 `flutter-architecture.md:228` 的节流思路）；`totalBytes` 取自 `artifacts[].size_bytes` |
| 取消 | 页面 dispose / 用户点取消 → `CancelToken.cancel()`；**保留已下载分片**以便续传 |
| 失败 | **不自动重试**（D4）；状态置 `Failed(recoverable: true)`，由用户点「重试」 |
| 清理 | 安装成功 / 指纹或 `sha256` 校验失败 / 用户点「忽略此版本」 → 删除文件；冷启动时删除 `updates/` 下所有**非当前进行中**的文件 |
| 仅 Wi-Fi | `update.wifi_only` 默认 `true`；非 Wi-Fi 时先弹 `A41 choice-sheet` 二次确认（「继续下载」/「等 Wi-Fi」），确认后才开始 |
| 网络类型判定 | 经原生通道 `isOnWifi()`（§4.1.6），**不引入 `connectivity_plus`**（D6） |
| 请求侧 | 复用 `createDio()` 共享实例（`dio_client.dart:11-26`）；注意其 `receiveTimeout = 15s`（`:33`）对**长下载**不适用——下载请求必须**显式覆盖** `receiveTimeout`（或设为 `null`）并关闭 `responseType: json` 改为 `ResponseType.stream` |

**裁决 D4：下载失败不自动重试。** 理由：APK 在 20–60 MB 量级，弱网下自动重试会形成流量黑洞；改为「保留分片 + 用户显式重试走续传」，成本与体验兼顾（`update-system-architecture.md` §5.2 D9）。

**裁决 D5：`sha256` 在 Dart 侧算，签名指纹在原生侧算。** 理由：① Dart 侧用 `crypto` 包（**已是 `pubspec.lock` 的传递依赖**，实现期须核实是否需提升为直接依赖——若需提升，则**本任务的 Dart 依赖数从 1 变为 2**，必须在该批 §6.2 显式登记）；② 签名指纹必须读 **APK 归档内的签名块**，只能经 `PackageManager.getPackageArchiveInfo(..., GET_SIGNING_CERTIFICATES)` 完成，无 Dart 侧替代。

#### 4.1.5 ★ 双校验契约

| 步 | 校验 | 数据来源 | 失败处置 |
|---|---|---|---|
| ① | 体积 | 本地文件字节数 vs `artifacts[].size_bytes` | `Failed(incomplete)`，**可续传**（体积不符通常意味着下载未完成） |
| ② | `sha256` | 本地计算（小写十六进制、无分隔） vs `artifacts[].sha256` | `Failed(hashMismatch)`，**删除文件**，重试从头开始 |
| ③ | **签名指纹** | 原生读 APK 指纹 vs **`getPackageInfo(packageName)` 读到的运行中 App 自身指纹** | `Failed(signatureMismatch)`，删除文件；文案指向「旧包需卸载重装」 |

**裁决 D7：指纹比对目标 = 运行中 App 自身签名，不是清单里的 `signature_fingerprint`。** 理由：清单与 `sha256` **同源**（都由服务端下发），若托管被替换，攻击者会用同一份被篡改的清单同步替换两者——只比清单等于没校验。与自身签名比对锚定的是**应用身份**（`self-distribution-guide.md:110`「签名文件 = 应用身份」）。`artifacts[].signature_fingerprint` 仅用于**诊断日志**（不一致时能区分「服务端清单写错」与「包被替换」）。

**debug 回退场景**：`android/app/build.gradle.kts:59-67` 允许 release 缺 `key.properties` 时回退 debug 签名 → 「debug 包更新 debug 包」比对仍成立；**跨签名更新会失败，这是正确行为**（不是缺陷）。文案必须给出可行动指引（「当前安装的是旧签名版本，需要先卸载再安装」）。

#### 4.1.6 ★ 原生安装通道契约

```text
channel: "com.zhaoxi.app/updater"       // 与 applicationId 同源；dev flavor 下仍用同一 channel 名
  installApk(apkPath: String)               -> bool      // 是否成功调起系统安装器
  canInstallPackages()                      -> bool      // Settings.canDrawOverlays 类比：canRequestPackageInstalls()
  openInstallPermissionSettings()           -> void      // ACTION_MANAGE_UNKNOWN_APP_SOURCES
  installedVersionCode()                    -> int       // PackageInfo.versionCode
  signatureFingerprint(apkPath: String)     -> String?   // GET_SIGNING_CERTIFICATES → SHA-256，大写冒号分隔
  isOnWifi()                                -> bool      // 需 ACCESS_NETWORK_STATE（普通权限）
```

| 项 | 契约 | 理由 |
|---|---|---|
| FileProvider authority | **`${applicationId}.fileprovider`**（经 manifest placeholder 展开） | dev flavor 有 `.dev` 后缀（`build.gradle.kts:46-57`）；写死常量会让 dev/prod 同机安装时 authority 冲突或解析到错误 App |
| FileProvider 路径暴露 | `res/xml/file_paths.xml` 只暴露 `<files-path name="updates" path="updates/" />`（或 `<cache-path>` 对应子目录），**不得暴露整个内部存储** | 最小暴露面 |
| 安装 Intent | `ACTION_VIEW` + `setDataAndType(uri, "application/vnd.android.package-archive")` + `FLAG_GRANT_READ_URI_PERMISSION` | Android 7.0+ `content://` 标准姿势 |
| 权限预检 | `installApk` 内部先判 `canRequestPackageInstalls()`；false → 返回 false，Dart 侧转 `PermissionRequired` 态 | 不给用户「点了没反应」的体验 |
| 拒权引导 | `openInstallPermissionSettings()` → `ACTION_MANAGE_UNKNOWN_APP_SOURCES` + `package:<applicationId>` | 现状无任何引导路径 |
| **前台要求** | 安装只在 Activity 前台发起；Dart 侧在调用前判 `AppLifecycleState.resumed`，非前台则先提升到前台并提示 | Android 10+ 后台启动 Activity 受限、Android 14（API 34）后台无法拉起安装器 |
| 结果回收 | 主路径 = **冷启动读 `installedVersionCode()`**（D7）；辅路径 = `installApk` 返回 true 后在 `onResume` 再读一次 | `ACTION_PACKAGE_REPLACED` 广播在部分 ROM 上不可靠，不作为唯一依据 |
| 通道注册点 | `MainActivity.configureFlutterEngine`（现仅 1 个 class 声明，`MainActivity.kt`） | 已继承 `FlutterFragmentActivity`，可承载 Channel |
| 异常归一 | 原生侧任何异常 → `result.error(code, message, null)`，Dart 侧统一成 `Failed(reason: platformError)`，**不吞异常、不返回成功** | 静默成功会让状态机与真实世界脱节 |

**裁决 D8：`dev` flavor 只检测不安装。** 理由：① 开发机常需与本地后端联调，真实安装会打断调试；② 防止线上包覆盖开发机；③ `self-distribution-guide.md:101` 已记录 dev 包指向 `127.0.0.1` 的装机事故先例。落法：`AppEnv.flavor != 'prod'` 时，「立即更新」按钮替换为 `A12 chip-btn`（`ghost` 变体）「前往发布页下载」，**不调用下载与安装**。

### 4.2 关键裁决与铁律留痕

#### 4.2.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 模型不用 Freezed | `flutter-architecture.md:46` 反向建议；无 union 需求；避开一文件一生成器约束 |
| D2 | **自动检查不在 `bootstrap()` 内**，挂首帧后 `app/` 层 | 合规底线 1（`self-distribution-guide.md:122`）：`bootstrap.dart:19-50` 无同意门控，在其中发请求 = 制造新违规；挂首帧后则 `PLT-002` 落地后无需改动 |
| D3 | 首帧后**延迟**触发，不立即触发 | 不与首屏渲染争资源（`PLT-006` 冷启动预算）；具体延迟与基线共同确定，不写死在 Detail |
| D4 | 下载失败**不自动重试** | 20–60 MB 包在弱网下自动重试 = 流量黑洞；保留分片 + 显式重试走续传 |
| D5 | `sha256` 在 Dart 侧算，指纹在原生侧算 | 指纹只能读 APK 归档签名块（`PackageManager.getPackageArchiveInfo`）；体积/哈希在 Dart 侧避免无谓的通道往返 |
| D6 | **不引入 `connectivity_plus`**；网络类型走本已要写的原生通道 `isOnWifi()` | 依赖数量已被审计点名（`mobile-code-audit-2026-10.md:218-232`）；本任务已有原生通道，加一个方法成本远低于加一个包；`ACCESS_NETWORK_STATE` 是普通权限（无用户可见弹窗） |
| D7 | 指纹比对 = **运行中 App 自身签名**（清单里的指纹只用于诊断） | 清单与 `sha256` 同源，只比清单等于没校验；自身签名锚定应用身份（`self-distribution-guide.md:110`） |
| D8 | `dev` flavor 只检测不安装 | 防开发机被线上包覆盖、防打断联调；`self-distribution-guide.md:101` 已有先例 |
| D9 | 用 **`A41` 底部面板**，不用系统 `AlertDialog` | `A41` 规格显式覆写尺寸/圆角/按钮位/键盘避让，能可靠承载「滚动说明 + 进度条」；系统 `AlertDialog` 无设计系统登记，且其默认样式正是 M3 禁令要避免的 |
| D10 | 不用 `showModalBottomSheet` 的**默认样式**，按 `A41` 规格显式覆写（含键盘避让 `viewInsets`） | `components.md:510-511`（「`showModalBottomSheet` 不处理 `viewInsets`」）；另需显式关闭 `surfaceTint` 等 M3 特征 |
| D11 | **`force` 态无任何关闭路径**，含系统返回手势 | 强制更新一旦可绕过即失去意义；落法：`PopScope(canPop: false)` + 面板无把手交互 + 遮罩不可点 |
| D12 | `responseType` 与超时**必须**在下载请求上显式覆盖 | `dio_client.dart:33-34` 的 `receiveTimeout = 15s` + `responseType: json` 对 20–60 MB 流式下载是致命的（15s 空闲即断）；共享实例的默认值不能直接用于下载 |
| D13 | 续传收到 `200` 时**必须截断**本地文件 | 服务端在 `Range` 不可满足或忽略时会回 `200` 全量；直接追加会拼出损坏文件，且体积校验可能恰好通过（若差值巧合）——这是最难排查的一类缺陷 |
| D14 | 失败态一律**可重试**，但**不可跳过** `sha256` 与指纹校验 | 校验是安全边界，不能因「用户着急」而降级；反范围里已排除任何降级猜测行为 |
| D15 | 复用 `createDio()` 共享实例，**不新建 Dio** | `dio_client.dart:11-26` 的共享实例已带 4 个拦截器（含 `LogRedactionInterceptor` 脱敏）；新建实例会漏掉脱敏与错误映射 |

### 4.3 数据流

```text
── 检查 ────────────────────────────────────────────────
MobileApp 首帧后（app/update/update_gate.dart）
  ├─ 读 update.last_check_at → 距上次 < 24h ? 跳过 : 继续
  ├─ 读 installedVersionCode()（原生）→ 与上次记录比对（安装结果回收，D7）
  ├─ 清空 updates/ 下非进行中残留
  └─ 调 updateServiceProvider.check(manual: false)
        → release_api.fetchLatest(android, AppEnv.flavor, localVersionCode)   [API-022 §4.1.3]
        → update_checker.decide(...)  → force | recommend | none
        → 写 update.last_check_at
        → 展示 update_sheet（若 force/recommend 且未被 ignore）

── 下载 ────────────────────────────────────────────────
用户点「立即更新」
  ├─ 读 update.wifi_only + 原生 isOnWifi() → 非 Wi-Fi 则先 choice-sheet 确认
  ├─ 已有分片 ? Range: bytes=<n>- : 无 Range
  ├─ dio（ResponseType.stream，覆盖 receiveTimeout）→ 流式写 updates/{artifactId}.apk
  ├─ 合帧 16ms flush 进度
  └─ 收到 200 且本地有分片 → 截断后重写（D13）

── 校验 ────────────────────────────────────────────────
  ├─ 体积 vs size_bytes
  ├─ sha256 vs artifacts[].sha256
  └─ 原生 signatureFingerprint(apkPath) vs 自身签名指纹（D7）

── 安装 ────────────────────────────────────────────────
  ├─ canInstallPackages() == false → PermissionRequired 态 → openInstallPermissionSettings()
  └─ resumed 态下调 installApk(path)   [原生: FileProvider content:// + ACTION_VIEW]
        → 系统安装器 → 用户确认安装 → App 被杀

── 回收 ────────────────────────────────────────────────
下次冷启动 → update_gate 读 installedVersionCode() → > 上次记录 ? 清 updates/ 与 ignore 态 : 保持
```

**装配红线**：

- ✗ 不得在 `bootstrap.dart:19-50` 内发起任何更新网络请求（D2）。
- ✗ `core/updater/` 不得出现 `features/` 字样（L1）；不得 import `design_system/`（L2）。
- ✗ `release_notes` 不得按 Markdown / HTML 渲染（服务端下发纯文本；渲染会引入注入面并误判格式）。
- ✗ 不得为更新流程修改 `design_system/tokens/` 或既有 `A*` 组件规格。
- ✗ 不得在 `dev` flavor 下真实下载与安装（D8）。
