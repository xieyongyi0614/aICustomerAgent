### 2.2 为什么必须做

1. **消息气泡是「对话」的视觉本体。** 原型 `#chat` 第 3 段即「AI 白卡泡 / 用户深色泡交替」（`components.md:321`）；没有它，`APP-009` 的装配与 `APP-010` 的流式正文都无处落地。
2. **typing 是「AI 正在想」的唯一信号。** `REQ-CHAT-09` 为 P0（`requirements-analysis.md:260`）；它是 M1 验收「逐字看到回复」的**前置等待态**。
3. **输入栏是对话的唯一入口。** `REQ-CHAT-08` 就绪度 ✅（本地，`requirements-analysis.md:259`）；它是 M1 闭环的起点。
4. **三组组件都有「易错细节」必须显式契约化**：
   - 气泡的**贴底角**是 `6` 而非 `20`（`tokens.md:137`）——最容易漏的一条；
   - typing 的 `1.1s` 循环是**动效纪律的显式例外**（`tokens.md:235`）——不写清会被当成违规而改短；
   - 输入栏的**占位文案**在 skill 内存在「表格条目 vs 末注纪律」的张力（§4.2 D5）——必须显式裁决。
5. **语音是 P2，必须写成护栏。** 若在本任务实现语音，会同时越界 `REQ-CHAT-08` 的 P2 标注（`requirements-analysis.md:259`）与端侧权限范围。

### 2.3 在 V5.0.0 中的位置

M1 客户端第 3 个任务，依赖 `APP-007`（组件风格与 token 约定）与 `APP-010`（正文与状态）；`APP-009`（装配）消费本任务的三组组件。

#### 4.1.4 占位文案契约（**含 skill 内张力的显式裁决**）

| 项 | 契约 |
|---|---|
| 文案 | **「继续说点什么…」** |
| 真源 | `principles.md:102`（§5.4 占位文案表「对话页输入栏」）、`components.md:326`（`B2` 第 8 段）——**两处一致** |
| 张力 | `principles.md:106`（§5.4 末注）要求「占位文案**必须带一个示例**（用「例如」或直接引号举例）」；而对话页表格条目「继续说点什么…」**不含示例** |
| 裁决 | **以表格条目为准**取「继续说点什么…」（skill 内 2:1：`principles.md` 表格 + `components.md` 均不含示例）；末注纪律的**示例型占位**在其它输入位已满足（首页输入丸「问问亚丝娜，或直接说「午饭 35 元」…」、记账页「再说一笔，例如「打车 22」…」、生活捕获条，`principles.md:101-104`） |
| **待定 + 阻塞条件** | 若设计系统 skill 裁定对话页占位**必须**带示例，则**阻塞条件**为：需 skill 给出**对话页专用**的示例文案（**不得**跨场景挪用记账页文案）；在此之前按真源「继续说点什么…」实现 |
| 空会话特例 | **不做**（不得为「首次进入」另起一套占位，属发明需求） |

| `A15 typing` | 使用 `useAnimationController`（Hooks 允许用法，`flutter-architecture.md:54`）；**不得**用 `useState` 存业务状态 | `visible`（布尔） | 无 | 无（图形指示器 + 语义标签） |
| `A16 inputbar` | 使用 `useTextEditingController`（Hooks 允许用法，`flutter-architecture.md:55`）；**不得**用 `useEffect` 拉数据 | `placeholder`、`enabled`、`onSend(text)` | `onSend` 回调、`onPlusTap?`（本任务不绑定）、`onVoiceTap?`（禁用） | 占位文案由调用方传入，默认取 §4.1.4 真源 |

**统一约束**：三组组件**不得 import `core/` 或 `features/`**（`design_system/` 可独立 golden，`flutter-architecture.md:196` L2）；`A16` 的发送回调由 `features/chat` 注入。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 气泡**贴底角为 `6`**（用户右下 / AI 左下），其余三角 `20` | `tokens.md:137` 明确「气泡：`20`，且贴底角改为 `6`」；这是最易漏的一条规格 |
| D2 | AI 头像必须是 **Orb `sm` 22px**，**不是**悬浮球 | 两个「球」的辨析（`tasks/APP-005.md:164-179`）：Orb 表达 AI 状态，悬浮球是按钮 |
| D3 | **加号按钮渲染但不绑定功能**（待定 + 阻塞条件） | 设计稿未定义加号行为；实现附件上传属发明需求且与「不做重表单」反范围冲突（`principles.md:45`） |
| D4 | **语音按钮渲染但禁用，零实现** | `REQ-CHAT-08` 明确语音为 P2（`requirements-analysis.md:259`） |
| D5 | 占位文案取真源「**继续说点什么…**」，并按 §4.1.4 记录张力与阻塞条件 | skill 内 2:1 多数（`principles.md:102` 表格 + `components.md:326`）；跨场景挪用记账页示例文案不可接受 |
| D6 | typing 的 `1.1s` 循环**是合规的**（循环指示器例外） | `tokens.md:235`：除 Orb 与循环指示器外所有动效 ≤ 400ms。**不得**为「合规」而改短 |
| D7 | 气泡**无投影** | `components.md:125-131` 未给气泡投影；`tokens.md:196` 常规 UI 只有一档投影且用于卡片 |
| D8 | 输入栏**不自行定位**，`bottom 88` 由页面让出 | 屏幕级间距属页面职责（`tokens.md:216-219`）；组件自行定位会导致多页不一致（`APP-009.md` D11） |
| D9 | 三组组件**不得 import `core/` / `features/`** | 分层纪律 L2（`flutter-architecture.md:196`）；否则 golden 需要网络 / 仓储桩 |
| D10 | 动效 controller 走 hooks（`useAnimationController`），**禁用** `useState` 存业务状态 | Hooks 边界（`flutter-architecture.md:54-56`） |
| D11 | 发送条件：trim 后非空 | 空消息发送无意义；与后端 `content 不能为空` 的 422 校验对齐（`chat.py:41-42`） |
| D12 | **不做**消息时间戳 / 已读 / 发送状态 / 长按菜单 | 设计稿未定义；后端消息体无对应字段（`history.py:38-45`） |
| D13 | 新增设置 = **无** | 裁决 9（`tasks.md:26`） |

### 4.3 数据流

```text
APP-010 流式渲染引擎（ChatTurnState：status / text）
   ↓
features/chat/presentation（APP-009 装配）
   ├── 消息流 ──→ A13 msg（role=user / ai，content=已就绪文本或渲染子树）
   │                 └── AI 泡头像 = Orb sm 22px（APP-006 的 Orb）
   ├── typing 位 ──→ A15 typing（visible = status ∈ {streaming, toolRunning}）
   └── 输入栏位 ──→ A16 inputbar（placeholder 真源、onSend(text) → 触发新一轮流式请求）
                          ├── 加号（+）：渲染，不绑定（D3）
                          ├── 语音（mic）：渲染，禁用，零实现（D4）
                          └── 发送（→）：文本非空 → onSend(text)（D11）

组件依赖方向（L2）：
   design_system/components/{message_bubble, typing_indicator, chat_input_bar}
       → 只依赖 design_system/tokens + design_system/orb（仅 A13 用 Orb sm）
       ✗ 不 import core/**、features/**

定位：
   输入栏 bottom 88（页面让出）；页面底部让开 118（APP-009）
   键盘弹起 → 随键盘上移（Scaffold / SafeArea）
```
