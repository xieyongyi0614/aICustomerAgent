### 2.2 为什么必须做

1. **「AI 叙事优先」这条设计原则能否成立，取决于这个接口。** 原话见 `requirements-analysis.md:174`；`traceability.md:101` / `:75` 也把「亚丝娜的观察」「首页 AI 总结」标为「⚠️ 依赖 `API-006`」。
2. **它是 `API-004` 与 `API-008` 的前置。** 首页 `ai_summary` 区块与简报四张卡都消费本接口（`tasks.md:154`、`tasks.md:181`）。

4. **它的风险点是「空数据」**：新用户 / 新设备必然无洞察；接口必须**返空列表**而非 500，否则首页与简报在冷启动即失败。

### 2.3 在 V5.0.0 中的位置

M2 后端第 3 个任务，是 `API-004`（首页聚合）与 `API-008`（简报预生成）的直接前置（`tasks.md:240`、`tasks.md:181`）。它是「卡片即结论」与「AI 叙事优先」两条设计原则的数据底座（`requirements-analysis.md:39-40`）。

## 3. Scope

### 3.1 In Scope

1. **端点**：`GET /api/v1/insights?domain=ledger|health|home&limit=N`（契约见 §4.1.1）。
2. **产品读面服务**：`app/services/insights/query.py::list_insights(user_id, domain, limit)`——**唯一读面合成点**：
   - 读 `insights`（`status="active"`）+ `evidence_links` → `memories`（复用 `reflection/attribution.py` 的证据链范式，`attribution.py:37-84`）；
   - 输出 `{id, domain, headline, narrative, evidence[], source_refs[], generated_at}`。
3. **`domain` 映射契约**（§4.1.2）——**读面派生维度，不是 DB 列**；映射规则冻结、可复算。
4. **无洞察返空列表**：`items: []`、HTTP **200**（不 500、不 404）。
5. **只做读面**：**不新增生成链路**；生成仍走既有 `services/reflection` / `services/development`（§4.2.1 D4）。
6. **身份**：`user_id` 从既有身份机制解析（API-001 落地后走 token）；请求中的 `user_id` **拒绝**。
7. **纯新增**：零新迁移、零 `*_enabled` 开关、零 `app/repositories` 反向依赖、零新事件类型。

## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 端点与响应

`GET /api/v1/insights`

| 方向 | 字段 | 类型 | 必填 | 语义 / 缺省 |
|---|---|---|---|---|
| 请求 | `domain` | `string` | 否 | `ledger` / `health` / `home`；缺省 `home`；非法值 → 422 |
| 请求 | `limit` | `int` | 否 | 默认 10，`1 ≤ limit ≤ 50`；超上限 → 422（不静默截断） |
| 响应 | `items` | `object[]` | — | 洞察列表；**无洞察时 `[]`**（HTTP 200） |
| 响应 | `domain` | `string` | — | 回显生效的 domain |
| 响应 | `generated_at` | `string` | — | ISO 8601（本地时区），本次查询时刻 |

`item` 字段

| 字段 | 类型 | 语义 | 来源 |
|---|---|---|---|
| `id` | `string` | 洞察 id | `insights.id`（`core/db.py:1023`） |
| `domain` | `string` | 所属域（读面派生） | §4.1.2 映射 |
| `headline` | `string` | 一句话结论（**短标题**） | `insights.statement` 的**确定性截断**（首句 / ≤ 40 字；可复算） |
| `narrative` | `string` | 叙事全文 | `insights.statement`（`core/db.py:1028`） |
| `evidence` | `object[]` | 证据链：`{memory_id, weight, content, memory_type, status}` | `evidence_links` → `memories`（范式见 `reflection/attribution.py:65-78`） |
| `source_refs` | `object[]` | 来源追溯：`{kind, ref, label}` | `memories.source` / `source_ref`（`core/db.py:101-...`）；`memory_candidates.source_table` / `source_id` |
| `generated_at` | `string` | 洞察生成时刻 | `insights.created_at`（`core/db.py:1036`） |
| `confidence` | `float` | 置信度（可选，供端上弱化展示） | `insights.confidence`（`core/db.py:1030`） |

**错误语义**：`422` 非法 `domain` / `limit`；`403` 越权（他人 `user_id`）；**不透传堆栈**；**无洞察 → 200 + `items: []`**（**不是 404、不是 500**）。

#### 4.1.2 `domain` 映射契约（**读面派生，不是 DB 列**）

> **依据**：`insights` 表**无 `domain` 列**（`core/db.py:1020-1042`），故 `domain` 必须由读面按**冻结规则**派生。规则只读、可复算、零 LLM。

| `domain` | 读面过滤规则（冻结） | 数据源状态 |
|---|---|---|
| `ledger` | `insights.status="active"` 且 `type="pattern"`，且证据链（`evidence_links` → `memories`）中存在 `memories.type="behavior_pattern"` 的证据（即账本 `ledger_insights` 桥入的模式记忆，`services/ledger/memory_bridge.py:17-18`） | ✅ 有写入方（账本模式桥） |
| `health` | 无匹配数据源（`services/health` 不存在，健康域 M4 门控未落地） | ⚠️ **恒返空列表**（不造数据，§3.2 第 5 条） |
| `home` | `insights.status="active"` 且 `scope="user"`，按 `confidence` 降序、`created_at` 降序取前 N（**跨域聚合读面**，供首页 AI 总结） | ✅ 有写入方（reflection / development） |

**排序（全域统一，冻结）**：`confidence` 降序 → `created_at` 降序 → `id` 升序（保证全序、结果稳定）。
**仅取 `status="active"`**：`superseded` / `invalidated` 不进列表（对齐 Insight 生命周期 `core/db.py:1045-1048`）。

#### 4.1.3 无洞察语义

| 场景 | 契约 |
|---|---|
| 用户从无洞察（新用户 / 新设备） | `items: []`、HTTP **200** |
| `domain=health`（无写入方） | `items: []`、HTTP **200** |
| 洞察全部为 `superseded` / `invalidated` | `items: []`、HTTP **200** |
| 证据链中的记忆已被物理删（`memory_purged`） | 该条 `evidence.status="memory_purged"`，**不整条丢弃**（沿用 `reflection/attribution.py:76`） |

> **纪律**：空结果是**合法结果**，不是错误。客户端据 `items: []` 走「还没有观察」空态（`APP-016` / `APP-014`）。
