## 2. Background

### 2.1 现状：后端是「单用户假设」，客户端传 `user_id` 直接 403

| 事实 | 证据 |
|---|---|
| `_current_user()` 的判定：传 `user_id` 且 ≠ `default_user` → **403「不得读写他人数据」**；传 `None` → 落到 `resolve_user(None)` = `default_user` | `apps/backend/app/api/v1/ledger.py:141-149` |
| `resolve_user(None)` 会 `ensure_default_user()`，即默认单用户 | `apps/backend/app/services/identity/user_service.py:31-42` |
| `user_id` 以**请求参数 / body 字段**形式进入各端点，而非凭据 | `apps/backend/app/api/v1/ledger.py:141`（`requested: str \| None`） |
| V4.0.0 裁决 7 明确「本版本不做注册 / 登录 / 鉴权」 | `docs/version/v5.0.0/requirements-analysis.md:139`（引 `docs/version/v4.0.0/tasks.md` §0.7） |
| `app/api/**` 已有 **26 处**反向依赖 `app/repositories`（V4.0.0 记为 **L3 债**） | `docs/version/v5.0.0/tasks.md:25`；`requirements-analysis.md:89` |
| 现有依赖注入点集中在 `app/api/v1/deps.py`（当前只有 `get_chat_llm`） | `apps/backend/app/api/v1/deps.py:1-17` |
| 路由在 `router.py` 静态聚合 13 个子路由 | `apps/backend/app/api/v1/router.py:19-31` |
| 运行时契约测试禁止 `contracts` 模块 import `app.repositories` 等 | `apps/backend/tests/v30/test_runtime_contracts.py:18-25` |

### 2.2 为什么必须做

1. **这是 App 化的硬前置，不是可选优化。** 桌面 / 局域网阶段无所谓；一旦装到真机、连公网，「传 `user_id=None` 即默认用户、传别人 `user_id` 即 403」的模型等于**把账本与记忆敞开**（`requirements-analysis.md:141`）。
2. **它阻塞整条 M1 对话闭环。** `API-002` 依赖本任务（`tasks.md:128`）；而 API-002 是 M1 收口点 C2 的关键路径（`tasks.md:236`、`tasks.md:246`）。鉴权不做，后续产品级端点都要重复「如何拿到可信 `user_id`」这个问题。
3. **它的风险点是「误伤既有域」，因此必须走纯新增路线。** 风险 R7：单用户鉴权改造影响既有域，概率低但影响高（`tasks.md:272`）。对策就是严格纯新增 + 基线对照法验证。
4. **它决定客户端凭据层的形态。** `APP-004` 的 `flutter_secure_storage` 存什么、`APP-003` 的 Dio 拦截器怎么带令牌，都取决于本任务冻结的令牌形态（`tasks.md:109`、`tasks.md:108`）。

### 2.3 在 V5.0.0 中的位置

M1 后端第 1 个任务，位于关键路径 `API-001 → API-002 → APP-013` 的起点（`tasks.md:246`）；可与客户端 M0 **并行开工**（`flutter-architecture.md:441`）。

## 3. Scope

### 3.1 In Scope

1. **配对端点**：首次扫码 / 配对，用配对凭据换取长期令牌（字段契约见 §4.1.1）。
2. **令牌形态**：长期令牌的载体、有效期、载荷、校验方式（§4.1.2）。
3. **鉴权依赖**：新增 `require_user`，注入点为 FastAPI `Depends`；`user_id` **由 token 解析**（§4.1.3）。
4. **401 / 403 语义区分**：无令牌 / 令牌无效 / 过期 → 401；令牌有效但越权 → 403（§4.1.4）。
5. **无令牌请求 401**：所有挂载了新依赖的端点，缺令牌即 401（不回落 `default_user`）。
6. **既有域零改动**：`ledger.py` / `chat.py` / `world.py` 等既有端点的 `user_id` 取值逻辑**一行不改**，继续走 `default_user`。
7. **纯新增**：零 `app/repositories` 依赖、零新迁移、零 `*_enabled` 开关。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | 注册 / 登录 / 密码 / 验证码 | 决策 D3 选的是**设备绑定 + 长期令牌**，不是账号体系（`requirements-analysis.md:373`）；账号体系会牵出找回、改密、注销等一整套 |
| 2 | OAuth / 第三方登录 / 短信验证 | 无需求来源；且引入外部依赖与合规面 |
| 3 | 多用户切换 UI / 多租户 | 单用户模型（`PLA-016.md:83`「不做多用户切换 UI」）；本任务只保证「令牌解出的 `user_id` 就是本人」 |
| 4 | 角色 / 权限分级（RBAC / scope） | 本版本只有「本人 / 非本人」二元语义；权限分级无需求来源 |
| 5 | 令牌轮换 / 刷新令牌 / 主动吊销列表 | 需持久化设备表 → 会引入新迁移，违反「本版本只加 1 个迁移」（`tasks.md:32-38`） |
| 6 | 设备管理页（查看 / 解绑设备） | 归后续版本；本任务只交付配对与鉴权能力 |
| 7 | **改造既有端点为强制鉴权** | 会改变既有域行为 → 触发 R7；V1 严格纯新增，既有端点保持 `default_user` 行为（验收 ③ 硬项） |
| 8 | 新增迁移 / 新建表 | 本版本只加 `0055_life_tasks.py`（`tasks.md:37`）；令牌须为**无状态签名令牌**，不自建表 |

| 10 | 修改 `app/repositories/**` 或让新 API 依赖它 | 铁律 1（`tasks/README.md:92`）；V4.0.0 已记 26 处 L3 债，不得扩大 |

## 4. Technical Design Requirements

### 4.1 接口契约

#### 4.1.1 配对端点

`POST /api/v1/auth/pair`

| 方向 | 字段 | 类型 | 必填 | 语义 / 缺省 |
|---|---|---|---|---|
| 请求 | `pairing_secret` | `string` | 是 | 部署侧提供的配对凭据；不符 → **401** |
| 请求 | `device_id` | `string` | 是 | 端侧生成的稳定设备标识（用于令牌绑定）；为空 → 422 |
| 请求 | `device_name` | `string \| null` | 否 | 人类可读设备名；缺省 `null` |
| 请求 | `platform` | `string` | 是 | `android` / `ios`（对齐决策 D7 的平台顺序，`requirements-analysis.md:377`） |
| 响应 | `token` | `string` | — | 长期令牌（形态见 §4.1.2） |
| 响应 | `token_type` | `string` | — | 固定 `"Bearer"` |
| 响应 | `user_id` | `string` | — | 令牌绑定的用户；V1 即 `default_user` |
| 响应 | `expires_at` | `string` | — | ISO 8601（UTC），令牌到期时刻 |
| 响应 | `device_id` | `string` | — | 回显绑定的设备标识 |

`GET /api/v1/auth/me`（自检端点，供客户端验证令牌仍有效）

| 方向 | 字段 | 类型 | 语义 |
|---|---|---|---|
| 请求头 | `Authorization: Bearer <token>` | `string` | 缺失 / 无效 → **401** |
| 响应 | `user_id` | `string` | 令牌解出的用户（**不由请求参数决定**） |
| 响应 | `device_id` | `string` | 令牌绑定的设备 |
| 响应 | `expires_at` | `string` | 到期时刻 |

#### 4.1.2 令牌形态契约

| 项 | 契约 |
|---|---|
| 类型 | **无状态签名令牌**（服务端不自建表、不存会话） |
| 载荷 | `user_id`、`device_id`、`iat`（签发时刻）、`exp`（到期时刻）、`jti`（唯一标识，供未来吊销预留） |
| 绑定语义 | 令牌同时绑定 `user_id` **与** `device_id`；换设备须重新配对 |
| 有效期 | 长期（默认以**模块内常量**冻结，不新增设置字段）；到期 → 401，需重新配对 |
| 传输 | `Authorization: Bearer <token>`（HTTP 头，不放 query / body） |
| 端侧存储 | `flutter_secure_storage`（Keychain / Keystore），**禁止**明文（`flutter-architecture.md:84`） |
| 不可自建表 | 不新增迁移、不新建表；吊销能力列后续版本（§3.2 第 5 条） |

#### 4.1.3 鉴权依赖的注入点契约

| 项 | 契约 |
|---|---|
| 依赖函数 | `require_user`（新增，落点 `app/api/v1/auth_deps.py`） |
| 注入方式 | FastAPI `Depends(require_user)`；**由端点显式挂载**，不做全局中间件 |
| 返回值 | `UserContext`（复用既有 `app/services/identity/user_service.py:8-13` 的类型，不新造用户模型） |
| `user_id` 来源 | **仅从 token 解析**；请求参数中的 `user_id` 若出现且与令牌不符 → 403（§4.1.4） |
| 依赖边界 | `auth_deps.py` **零** `app/repositories` 依赖；令牌校验为纯函数（签名校验 + 载荷解析） |
| 既有端点 | **不挂载**（V1 纯新增）；`ledger.py` 的 `_current_user()` 零改动 |

#### 4.1.4 401 / 403 语义区分

| 场景 | 状态码 | `detail` | 语义 |
|---|---|---|---|
| 缺失 `Authorization` 头 | **401** | 「未提供设备令牌」 | 未认证 |
| 头格式错（非 `Bearer`） | **401** | 「未提供设备令牌」 | 未认证 |
| 令牌签名校验失败 | **401** | 「设备令牌无效」 | 未认证 |
| 令牌已过期 | **401** | 「设备令牌已过期，建议重新配对」 | 未认证 |
| 令牌有效，但请求携带的 `user_id` ≠ 令牌解出的 `user_id` | **403** | 「不得读写他人数据」 | 已认证但越权（**沿用既有文案**，`ledger.py:145`） |
| 令牌有效，未携带 `user_id` | **200** | — | 用令牌解出的 `user_id` |

> **纪律**：401 = 「你是谁不知道」；403 = 「知道你是谁，但你不能碰这个」。二者不得混用。

### 4.3 数据流

```text
首次配对：
客户端（扫码 / 配对码）
   → POST /api/v1/auth/pair {pairing_secret, device_id, platform}
   → auth.py：校验 pairing_secret → 校验 device_id 非空
   → 签发无状态签名令牌（载荷 user_id + device_id + iat + exp + jti）
   → 响应 {token, token_type, user_id, expires_at, device_id}
   → 端侧写入 flutter_secure_storage（APP-004）

后续请求：
客户端（Dio 拦截器，APP-003）
   → Authorization: Bearer <token>
   → require_user（auth_deps.py，纯函数：验签 + 解析 + 过期判定）
        ├── 缺头 / 格式错 / 验签失败 / 过期 → 401
        ├── 令牌有效 + 请求 user_id 不符 → 403（「不得读写他人数据」）
        └── 令牌有效 → UserContext(user_id 来自 token)
   → 端点使用 UserContext.user_id（不再读请求参数）

既有端点（V1 不变）：
ledger.py::_current_user(requested)
```
