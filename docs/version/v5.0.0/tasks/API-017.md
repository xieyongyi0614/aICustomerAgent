## 2. Background

**分类是每用户 DB 行（非固定枚举），种子按 `parent_name` 建树。**

| 事实 | 证据 |
|---|---|
| 分类是 DB 行而非枚举 | `app/services/ledger/category.py:37`（`ledger_repository.list_categories(user_id, kind=kind)`）；兜底名来自设置 `app/core/settings/ledger.py:11`（`ledger_category_fallback = "其他"`） |
| 模型支持父子与别名 | `app/models/ledger.py:52-61`（`LedgerCategory`：`parent_id` / `name` / `kind` / `aliases` / `is_seed`） |
| 种子形态 = `{name, kind, parent_name, aliases}` 元组 | `app/character/asuna/ledger_categories.py:1-40` |
| 种子的落地入口 | `app/services/ledger/service.py:6`（import）与 `:137-139`（`ensure_seed_categories(user_id, seed_tree=SEED_CATEGORY_TREE, now=…)`） |
| 既有车辆相关节点 | `ledger_categories.py:9-13`：`交通`（父）/ `公交地铁` / `打车` / **`加油`（别名含「洗车」「充电桩」）** / **`停车`** |
| 「养车」当前不存在 | 全仓 `养车` 零命中（`reviews/v5.1-requirements-determination.md` §3 缺口 22） |

**为什么必须做**：`pages/35-car.html:155-161` 的「本月养车支出」按**子类目**分四条（洗车/小保养 ¥200、停车 ¥180、过路费 ¥130、充电费 ¥102）。若不建子类目，四条只能全部落在单节点上，页面无法呈现；若端上自行拆分，则跨域聚合逻辑泄漏到客户端，违反 `traceability.md:312` 的评审纪律。

**为什么一期就要做**：`API-019`（二期）的聚合依赖本任务的树形结构；`APP-031`（36 页）的六类型录入需要落点分类。同时它不改任何既有行为，属最安全的先行项。

## 3. Scope

### 3.1 In Scope

1. `SEED_CATEGORY_TREE` 新增 1 个父节点与 6 个子节点（见 §4.1），**全部 additive**。
2. 子节点别名覆盖口语（充电桩 / 快充 / 慢充 / 油费 / 高速费 / 停车费 / 洗车费 / 保养费 / 4S 店 / 年检 …）。
3. 「养车」父节点别名（养车 / 用车 / 车）。
4. 结论项：`app/services/tool/builtin.py:71` 的 `LEDGER_SOURCES`（`("conversation","action","manual","import")`）**是否需要为车辆来源扩展**——产出明确结论（扩展则同批登记相关用例；不扩展则说明现有值已足够）。
5. 核验 `ensure_seed_categories` 的重名口径（见 §4.2 裁决 1）。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | **改造「交通」既有子项**（`加油` / `停车`） | 它们已被既有用户数据与既有归类用例依赖；改名/迁移会波及回归面（`tasks.md` §0.4），且 `is_seed` 重播不改已存在的行 |
| 2 | **为既有用户做数据回填迁移** | 种子是 additive 补齐（`service.py:137-139` 返回 `categories_created` 计数），下次 bootstrap 自然补齐；**本任务零新迁移** |
| 3 | 车辆页的**聚合读面** | 归 `API-019`（二期）；本任务只提供分类树 |

## 4. Technical Design Requirements

### 4.1 种子契约（新增条目）

| name | kind | parent_name | aliases（示例，实现时收敛） |
|---|---|---|---|
| `养车` | expense | `None` | 养车 / 用车 / 车 |
| `充电` | expense | `养车` | 充电桩 / 快充 / 慢充 / 超充 / 换电 |
| `加油费` | expense | `养车` | 油费 / 汽油 / 加满 / 92 号 / 95 号 |
| `停车费` | expense | `养车` | 停车 / 月卡 / 地库 / 路侧停车 |
| `过路` | expense | `养车` | 过路费 / 高速费 / ETC / 通行费 |
| `保养` | expense | `养车` | 保养费 / 小保养 / 大保养 / 4S 店 / 机油 / 机滤 |
| `洗车` | expense | `养车` | 洗车费 / 打蜡 / 内饰清洗 |

> **命名纪律**：子项名**必须与既有节点不重名**（既有 `加油`、`停车` 在 `交通` 下，`ledger_categories.py:12-13`）。因此子项取 `加油费` / `停车费` 两个带「费」后缀的名字，而把口语「加油」「停车」放进 **aliases**（匹配走别名，展示走子项名）。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **实现前必须核验 `ensure_seed_categories` 的重名键口径** | 若按 `(user_id, name)` 全局唯一，则子项名重名会被跳过（静默失败）；若按 `(user_id, name, parent_id)` 则无碍。**这是本任务的第一个动作**，结论写入 §10 备注；若为全局唯一则 §4.1 的命名纪律是硬约束 |
| 2 | **additive，零迁移** | `service.py:137-139` 的 `ensure_seed_categories` 是补齐式；既有用户在下次 bootstrap 拿到新节点（`BootstrapReport.categories_created` 可验证） |
| 3 | **不动「交通/加油」「交通/停车」** | 迁移既有用户分类会破坏既有账目归属与回归面；**车辆页聚合口径**改由 `API-019` 用显式映射承接（养车子树 ∪ `交通/加油` ∪ `交通/停车`），映射写在 car 域，不改记账域语义 |
| 4 | **种子别名不得被 `API-016` 的 `GET /ledger/rules` 当作"学会的规则"** | `is_seed=True` 是排除依据（`API-016` §4.1.2）；本任务新增的别名同样带 `is_seed=True` |
| 5 | **`LEDGER_SOURCES` 倾向不扩展** | 车辆费用经 `record_entry` 落账时来源可取既有 `action`（工具链）或 `manual`（手动）；新增枚举值会波及工具参数校验（`builtin.py:516`）与被登记的契约用例，收益不足。**结论须在实现时以证据确认并写入 §10** |

### 4.3 数据流

```text
新用户首登 / 既有用户下次 bootstrap
  service.ensure_user_bootstrap(user_id)                 # service.py:130
    → ledger_repository.ensure_seed_categories(user_id, seed_tree=SEED_CATEGORY_TREE)  # service.py:137
      → 逐条按 parent_name 解析父节点 → 建行（parent_id 指向父）
      → 返回 categories_created（新增条数，含本次新增的 7 条）

消费方（二期）
  API-019 → 按「养车子树 ∪ 交通/加油 ∪ 交通/停车」聚合本月支出
  用户说「充电 42」 → category.normalize → 命中 养车/充电（走别名）
```
