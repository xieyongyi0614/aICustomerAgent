**结论**：本任务**不写客户端代码、不写页面**，只产出**可被下游直接消费的合规文案与结论**。它是「上架可行性」的唯一闭合点——4 项未闭合项若不给结论，`PLT-005` 的分发链路（Android 内测渠道 + TestFlight）与 `APP-025` 的健康同意流程都没有合规依据。

### 2.2 为什么必须做

1. **它是上架的硬前置，不是可选项。** 健康信息属 PIPL 敏感个人信息，**必须单独同意**（`requirements-analysis.md:187`）；「本地优先」若被理解为「数据不出设备」而实际上传服务端，属**误导性陈述**（`requirements-analysis.md:132`）。这是**审核被拒**的直接原因（风险 R6，`tasks.md:271`）。
2. **它决定 `APP-021` / `APP-025` 的文案能否定稿。** 两个客户端任务的文案**取自本任务定稿**（`APP-021.md:197`：「本任务与 `APP-025` 的文案均取自 `PLT-002` 定稿」）。本任务不出稿，两个 P0 合规任务无法开工/收口。
3. **它闭环调研报告遗留的 4 项未闭合项。** `REPORT.md:104` 与 `REPORT.md:207-209` 明确列出 4 项缺一手文本；`tasks.md:215` 把它们列为本任务的**验收口径**。不闭环，上架路径存在 4 个未知黑洞。
4. **它闭环字体授权（易被漏掉的合规项）。** `flutter-architecture.md:320-323` 明确「字体授权确认属 PLT-002 合规范围」——若用 `HarmonyOS Sans SC` / 思源黑体而未确认授权即打包，是**字体版权风险**（`flutter-architecture.md:416` 风险 4）。

### 2.3 在 V5.0.0 中的位置

PLT 第 2 个任务，依赖 `APP-021`（M3，`tasks.md:185`），因为需要后者提供**文案落点**与「健康同意独立成项」的**结构约束**（`APP-021.md:128-139`）。它是 `APP-025`（M4，合规 P0，`tasks.md:204`）与 `PLT-005`（发布流水线，`tasks.md:218`）的上游输入：前者消费法律文案，后者消费上架资质结论。与 `APP-021` 的绑定关系由风险 R6 明确（`tasks.md:271`）。

## 3. Scope

### 3.1 In Scope

1. **隐私政策文本**（§4.1.1）：覆盖数据范围 / 用途 / 存储 / 用户控制权（D2 口径）/ 第三方（LLM 服务）/ 删除与导出。
2. **单独同意文案（健康专项）**（§4.1.2）：独立于通用同意的健康数据同意文案 + rationale。
3. **中国 App 备案结论**（§4.1.3）：细则、适用主体、所需材料、结论。
4. **NMPA SaMD 分类结论**（§4.1.4）：健康类 / LLM 健康解读是否被认定为医疗器械，结论 + 依据。
5. **Google Play 健康政策结论**（§4.1.5）：政策要点 + 结论（是否阻塞）。
6. **国内安卓商店健康资质结论**（§4.1.6）：各商店资质要求 + 结论。
7. **字体授权结论**（§4.1.7）：`HarmonyOS Sans SC` / 思源黑体的授权与打包许可结论。
8. **文案口径与边界契约**（§4.1.8）：D2 口径、HealthKit 禁广告/出售、禁医疗级宣称、与 `APP-021` / `APP-025` 的职责切分。
9. **风险 R6 处置记录**（§4.2 D1）：文案与存储架构一致性核对。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |

## 4. Technical Design Requirements

### 4.1 交付契约

#### 4.1.1 隐私政策文本契约

| 段 | 必含内容 | 口径依据 |
|---|---|---|
| 1 数据范围 | 列出处理的个人信息类别：账号/设备标识、账目数据、记忆数据、任务数据、**健康数据（敏感 PI，单独成章）** | `requirements-analysis.md:222`；`REPORT.md:95` |
| 2 处理目的 | 逐类说明用途（对话 / 记账 / 记忆 / 任务 / 健康洞察） | 同上 |
| 3 存储与传输 | **服务端存储**（明示）；HTTPS；令牌存 `flutter_secure_storage`；**不得**出现「本地优先 / 数据不出设备」表述 | 决策 D2（`requirements-analysis.md:372`）；冲突 5（`:128-135`） |
| 4 **用户控制权**（核心口径） | 「可随时查看、导出、删除；未经你授权，健康数据不会上传」 | 决策 D2 原句（`requirements-analysis.md:372`） |
| 5 单独同意 | 健康数据独立同意段落（指向 §4.1.2） | PIPL 敏感 PI（`requirements-analysis.md:187`） |
| 6 第三方 | LLM 服务提供方、模型调用（不用于训练等需声明）；HealthKit/Health Connect 数据不出售、不用于广告 | `REPORT.md:100`（HealthKit 禁广告/出售） |
| 7 医疗免责 | 固定「**非医疗建议，请咨询医生**」；禁医疗级宣称 | `REPORT.md:99`；`SKILL.md:49`；`requirements-analysis.md:395` |
| 8 留存与撤回 | PIPIA ≥3 年（若适用）；同意可撤回 | `REPORT.md:95`（PIPIA ≥3 年） |
| 9 联系方式 / 生效日期 | 版本号 + 生效日期 + 更新机制 | — |

> **纪律**：隐私政策是**法律文本**，其**呈现**（在 `APP-021` 中的展示）不属本任务（§3.2 #1）。本任务只出**文本与结论**。
