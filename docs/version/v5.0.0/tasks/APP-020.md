### 2.2 为什么必须做

1. **它是「用户对 AI 的控制面」的唯一落点。** 设计稿把本页定义为「管理『我和 AI 的关系』与『AI 能碰什么数据』」（`traceability.md:131`）；`REQ-PROF-01~08` 全部落在这里，缺失则「主动但克制」无关闭入口、隐私治理无入口。
2. **它携带一处 P0 阻塞——关系等级无产品级接口。** `tasks.md:184` 把「关系等级数据来自产品级接口（非 debug）」写成**验收口径**，而现状只有 `GET /debug/relationship/state`（`debug.py:762`）；`traceability.md:57` / `:135` / `:229` 三处一致标注该缺口。本任务**不得**调 debug 接口、**不得**自行新增后端接口，须回改 `tasks.md` 补 `API-*`（见 §4.1.7 与 §7.3）。
3. **它携带一处合规风险——隐私设置行文案。** 原型写「本地优先」（`:660`），而数据实际在服务端 PG 存储；`requirements-analysis.md:132` 明确「**这是合规风险，不只是文案问题**」。决策 D2 已裁定改文案（`:372`），本任务必须落地并写成 AC。
4. **它是原则 4 的可判定载体。** 三开关「默认可见且可关；关闭后不再触发」（`principles.md:14`）由本任务提供 UI 与状态读写，`APP-019` 据此调度——边界不清会出现「关不掉」或「关了还响」。
5. **设备连接行是 D1 的门控展示面。** 无 `PLT-001` 结论时必须走**未连接 / 未授权**态，**不得显示假设备**（`tasks.md:214`、`:196`）。

### 2.3 在 V5.0.0 中的位置

M3 客户端第 4 个任务（`tasks.md:184`）。它消费 `APP-006`（`Orb md`）与 `API-001`（身份），是 `APP-019`（通知调度）的**开关与时刻来源**，并把「记忆管理」交给 `APP-017`、「数据授权 / 隐私设置」交给 `APP-021`；设备连接行随 `PLT-001` 结论切换形态。
