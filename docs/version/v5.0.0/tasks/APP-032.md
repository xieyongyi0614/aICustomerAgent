## 3. Scope

### 3.1 In Scope

1. `car_profile_page.dart`：照 B16 的 10 段（标题 → 身份卡 → AI 观察卡 → 四档案行 → 保养时间线 → 联动说明 → 记一次保养入口）。
2. 路由 `/car/profile`（`chromeImmersive`）。
3. **档案编辑**：身份卡字段与四档案行的可编辑子集（`PUT /car/profile`），含 422 校验反馈。
4. **D13 文案改口径**：副题改为「你的车辆档案只属于你，可随时查看、修改、删除」。
5. 时间线数据来自 `GET /car/profile` 的 `services`；**末行未发生态由数据契约保证**（`API-020` §4.1.2）。
6. 联动说明用服务端 `hint`；兜底文案含「不用重复记」。

### 3.2 Out of Scope

| # | 不做 | 理由 |
|---|---|---|
| 1 | 保养记录的新增表单 | 「记一次保养」跳 `APP-031`（`pages/39:193`）；本页不重复实现录入 |
| 2 | 保险 / 年检的**比价与续保**流程 | `pages/35:172` 只说「我会提前 60 天提醒你比价续保」；比价需外部数据（反范围） |
| 3 | 车辆档案的**本地存储 / 离线编辑** | 决策 D13 为服务端存储；本地会与"随时查看、修改、删除"的控制权口径矛盾 |
| 4 | 多车切换 | `API-018` §3.2 #3 |
| 5 | 档案变更历史 | `API-020` §3.2 #7 |
| 6 | 时间线分页 / 折叠 | 保养记录量级很小（设计稿 2 条），`GET /car/services` 的 `limit` 已足 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| 1 | **副题必须改口径（D13）**：「所有档案都在本机」不得落地 | 与服务端存储事实相反，属误导性陈述；与 V5.0.0 冲突 5（「本地优先」vs 服务端）同型，是合规风险而非纯文案问题 |
| 2 | **末行未发生态由调用方保证**，并对页面加用例断言 | `components.md:385` 是明文纪律；组件不做排序（`APP-042` §4.2 裁决 3），故契约在页面侧 |
| 3 | **车龄 / 剩余待还 / 已还比例一律用服务端派生值** | `API-020` §4.2 裁决 2；端上算会与 35 页分叉 |
| 4 | 联动说明文案用服务端 `hint` | `API-020` §4.2 裁决 4 |
| 5 | 档案编辑走**整块表单 + 422 反馈**，不做逐字段即时保存 | 不变量（`paid_periods <= total_periods` 等）需整体校验；逐字段保存会产生中间非法态 |
| 6 | 时间线的**免费项金额不显示为 `¥0`** | `pages/39:180` 显示「免费」；`amount_minor == null` 时右侧值为文本而非金额 |

### 4.3 数据流

```text
进入 /car/profile
  → repository.fetchProfile()            GET /car/profile
       → identity（派生 age_text）+ files + loan（派生 paid_ratio）+ services（末行未发生态）+ reminders
编辑保存
  → repository.updateProfile(...)        PUT /car/profile
       → 422 → 就地提示不变量错误，不 pop
       → 200 → 重新 fetchProfile()        # 提醒为派生值，改档案后立即变化
点「记一次保养」→ push /car/add（预选 service）
```
