### 2.2 为什么必须做

1. **无骨架则后续任务无落点**：`tasks.md` §1 中 M0~M4 共 25 个 `APP-*` 任务，全部以 `apps/mobile/lib/` 下的四层目录为交付位置（`flutter-architecture.md:160-189`）。
2. **三生成器冲突是已登记风险**：风险登记 R7「三生成器 `.g.dart` 互相覆盖」概率中、影响中，缓解措施明确指向 APP-001（`flutter-architecture.md:419`；`tasks.md:70`）。若不在此任务一次性解决，后续每次改模型都会出现「生成物被另一个生成器清空」的隐性故障。
3. **版本冻结时机必须是现在**：依赖清单只冻结**包清单与用途**，版本由本任务用 `flutter pub add` 一次性拉取并提交 `pubspec.lock`（`flutter-architecture.md:119-121`）。晚冻结 = 每个下游任务各自 `pub add`，最终 `pubspec.lock` 无法复现。
4. **分层纪律若无静态守卫必然腐化**：`features/*` 互相 import、`design_system/` 反向依赖 `core/` 都会破坏 golden 可测性（`README.md:98` 全局约束 7）。约定必须转成可执行断言，否则第一个赶工期的页面就会破例。

### 2.3 在 V5.0.0 中的位置

本任务是**关键路径（最长链）的起点**：`APP-001 → APP-002 → APP-007 → APP-013 → APP-014`（`tasks.md:246`）。同时它也是 M0 收口点 **C1**（设计系统冻结）的前置（`tasks.md:255`），以及 `PLT-003` / `PLT-004` / `PLT-005` 三个横切任务的依赖（`tasks.md:216-218`）。

## 3. Scope

### 3.1 In Scope

1. **工程创建**：在 `apps/mobile/` 建立 Flutter 工程（`lib/` / `test/` / `integration_test/`），工程名与 bundle id 按 flavor 区分。
2. **flavor**：`dev` / `prod` 两套（对应不同后端地址与 bundle id），配置经 `--dart-define` 注入。
3. **目录分层**：`lib/{app,core,design_system,features}` 四层，`features/` 下按业务域建 8 个空域目录（`home` / `chat` / `life` / `ledger` / `memory` / `health` / `briefing` / `profile`），每域三层（`data` / `domain` / `presentation`）。
4. **lint 基线**：`analysis_options.yaml`——以 `flutter_lints` 为基线，追加本项目纪律（禁 `print`、禁 `Color(0x` 与 `Colors.` 出现在 token 目录外、禁 `FontWeight.w550` 类不存在常量）。
5. **`build.yaml` 三生成器输出后缀隔离**：freezed / drift / riverpod_generator 的输出后缀与「一个文件只被一个生成器处理」约定。
6. **`build_runner watch` 约定**：日常开发的生成命令与「改模型必须重新生成」的纪律。
7. **生成物提交与 CI 校验**：生成物纳入版本控制，CI 以 `build_runner build` + `git diff --exit-code` 校验。
8. **依赖冻结**：`flutter_architecture.md` §1.7 的 **20 项依赖**用 `flutter pub add` 一次性拉取，提交 `pubspec.yaml` + `pubspec.lock`。**版本号不写进任何文档**。
9. **分层守卫静态断言**：把 L1 / L2 转成可执行测试。
10. **Flutter Hooks 边界落地**：把「只承载 widget 级临时资源」的三条边界写进 `analysis_options.yaml` 注释与代码评审清单（不引入额外 lint 包）。

## 4. Technical Design Requirements

### 4.1 工程契约（目录 / flavor / 依赖 / 生成物 / 分层守卫）

#### 4.1.1 目录分层契约

| 层 | 路径 | 职责 | 允许 import | 禁止 import |
|---|---|---|---|---|
| 装配 | `lib/app/` | 只做组装，不含业务 | 全部 | — |
| 装配-路由 | `lib/app/router/` | go_router 声明 + 深链映射 | `features/*`（仅页面入口）、`design_system/` | `core/` 内部实现 |
| 装配-主题 | `lib/app/theme/` | `ThemeData` 装配，消费 `design_system/tokens` | `design_system/` | `features/` |
| 基建 | `lib/core/` | 跨 feature 基建（无业务语义） | `design_system/`（仅类型） | `features/*` |
| 设计系统 | `lib/design_system/` | tokens / components / orb，与业务完全解耦 | Dart SDK 与第三方 | **`core/` 与 `features/`** |
| 业务域 | `lib/features/<domain>/` | 每域三层 `data` / `domain` / `presentation` | `core/`、`design_system/`、**本域内** | **其它 `features/*`** |
| 测试 | `test/` `integration_test/` | 单元 / golden / widget / 契约回放 | 全部 | — |

#### 4.1.4 三生成器输出隔离契约

| 生成器 | 处理对象 | 输出后缀 | 触发时机 |
|---|---|---|---|
| `freezed` + `json_serializable` | Freezed 模型文件（含 `ChatEvent` union） | `*.freezed.dart` + `*.g.dart` | 改模型 |
| `drift` | 表 / DAO 定义文件 | **`*.drift.dart`** | 改表结构 |
| `riverpod_generator` | provider 定义文件 | `*.g.dart` | 改 provider |

**两条硬约定（缺一即视为实现缺陷）**：

1. **后缀隔离**：drift 输出改为 `.drift.dart`，与 freezed / riverpod 的 `.g.dart` 在文件系统层面物理分离。
2. **一个文件只被一个生成器处理**：同一份源 `.dart` 文件中，**不得**同时出现 Freezed 模型、drift 表定义、Riverpod provider 中的任意两种。理由是 `.g.dart` 被两个生成器同时写入会互相清空（`flutter-architecture.md:111`）。

来源：`flutter-architecture.md:97-117`、`:419`（风险 7）；`tasks.md:70`。

#### 4.1.5 生成物提交与 CI 校验契约

| 项 | 约定 |
|---|---|
| 生成物是否提交 | **提交**（单人开发，省去每次 checkout 后的分钟级全量生成等待） |
| 代价 | diff 体积变大——已接受（`flutter-architecture.md:117`） |
| CI 校验命令 | `dart run build_runner build --delete-conflicting-outputs` 后 `git diff --exit-code` |
| 失败含义 | 有人改了模型 / 表 / provider 但**未提交生成物**，或生成物被互相覆盖 |
| 本地 watch | `dart run build_runner watch --delete-conflicting-outputs` 常驻；改模型后**必须**确认生成完成再提交 |

来源：`flutter-architecture.md:113-117`、`:439`（M0 一票否决自检 3）；`tasks.md:217`（PLT-004 的 codegen 产物校验）。

|---|---|---|---|---|---|
| `app/` | ✅ | ✅ | ✅ | ✅ | ✅ |
| `core/` | ❌ | ✅ | ✅ | ❌ | ❌ |
| `design_system/` | ❌ | **❌** | ✅ | **❌** | **❌** |
| `features/` 同域 | ❌ | ✅ | ✅ | ✅ | **❌** |
| `features/` 他域 | ❌ | ✅ | ✅ | — | ❌ |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **生成物提交进仓库** | 单人开发；省去每次 checkout 后的全量生成等待（分钟级）。代价是 diff 变大，已显式接受（`flutter-architecture.md:117`）。若改为不提交，则 CI 每次必须跑全量 `build_runner`，且新克隆仓库首次运行前必然编译不过 |
| D2 | **三生成器隔离 = 输出后缀隔离（drift 用 `.drift.dart`）+ 一文件一生成器** | 仅靠后缀隔离不够：freezed 与 riverpod_generator 仍共用 `.g.dart`。必须叠加「一个源文件只被一个生成器处理」的约定，才能从根上消除互相覆盖（`flutter-architecture.md:111`） |
| D3 | **依赖版本在本任务一次性冻结，文档不钉版本** | Flutter 生态迭代快，写死在文档里一个月就过期（`flutter-architecture.md:120`）。做法：`flutter pub add` 一次性拉取 → 提交 `pubspec.lock` → 下游任务**不得**各自再 `pub add` |
| D4 | **锁定 Freezed 3.x 并统一在本任务声明** | Freezed 3.x 语法已变为 `sealed class` + `abstract class X with _$X`，网上 2.x 示例编译不过（`flutter-architecture.md:44`）。`APP-003` 的 `ChatEvent` union 依赖此版本，故版本决策必须前置到本任务 |
| D5 | **配置经 `--dart-define` 注入，不写进仓库** | 后端地址等按 flavor 区分，密钥与 API Key 绝不进仓库（`flutter-architecture.md:401-402`） |
| D6 | **分层纪律用静态断言强制，不只靠约定** | 约定会被第一个赶工期的页面破例。L1 / L2 转成测试后，`flutter test` 即拦截（`README.md:98` 要求「破坏 golden 可测性」的后果可控） |
| D7 | **`design_system/` 保持零业务依赖（L2），Orb 的 controller 用 `useAnimationController`** | 设计系统必须能脱离网络与业务独立渲染，才能做 golden 测试（`flutter-mapping.md:101`）；hooks 的合规用法在 `APP-006` 落地，本任务在目录与 lint 注释里预留边界 |
| D8 | **不新增任何功能开关** | 全局约束 2（`README.md:92`）；本任务 `新增设置` = 无 |
| D9 | **`analysis_options.yaml` 中显式禁 `FontWeight.w550` 类不存在常量与散落色值** | 550 / 650 / 750 在 Flutter 无对应常量，会编译不过（`tokens.md:170-173`）；散落色值违反红线 2（`SKILL.md:43`） |
| D10 | **本任务不引入 `custom_lint` / `riverpod_lint` 等额外 lint 包** | 会突破 §4.1.3 的 20 项冻结清单。分层守卫改用纯 Dart 静态断言测试实现，零新增依赖 |

### 4.3 构建流（谁调谁）

```text
【日常开发】
  开发者改模型 / 表 / provider
    → dart run build_runner watch --delete-conflicting-outputs（常驻）
    → freezed  → *.freezed.dart / *.g.dart
      drift    → *.drift.dart
      riverpod → *.g.dart
    → 确认生成完成 → git add 生成物 + 源码 → 提交

【CI 校验】（PLT-005 落地，本任务只声明约定）
  flutter pub get
    → flutter analyze                       （期望 0 issue）
    → dart run build_runner build --delete-conflicting-outputs
    → git diff --exit-code                  （期望干净：生成物已提交且未互相覆盖）
    → flutter test                          （含分层守卫静态断言）

【配置注入】
  flutter run --flavor dev  --dart-define=API_BASE_URL=<dev>
  flutter run --flavor prod --dart-define=API_BASE_URL=<prod>
```

来源：`flutter-architecture.md:107-117`、`:396-405`、`:434-439`。
