## 2. Background

### 2.1 现状：四态在文档里被反复提及，但**没有任何契约**

| 事实 | 证据 |
|---|---|
| `apps/mobile/` 工程尚未创建（`apps/` 下只有 `backend` / `frontend`） | `ls apps/` → `backend frontend` |
| Riverpod 的 `AsyncValue` **天然三态**，文档明确要求「对齐设计系统的加载 / 空 / 错规范」 | `docs/version/v5.0.0/flutter-architecture.md:19` |
| 冷启动首页需「骨架 → 数据」过渡，且首页聚合要**只读缓存**支撑该过渡 | `flutter-architecture.md:374`；`flutter-architecture.md:371` |
| 记账页三态（空 / 加载骨架 / 错误含重试）已是既有交付惯例（V4.0.0 前端样板） | `docs/version/v4.0.0/tasks/PLA-016.md:69`、`PLA-016.md:102`（「三态必备…错误态必须有重试而非白屏」） |
| 非功能需求（性能 / 离线 / 安全 / 可观测 / 无障碍）在设计稿与原型中**完全未定义**，须在本版本补齐 | `requirements-analysis.md:213-226`（缺口 13） |
| 五条设计原则缺可判定验收口径，已并入 `PLT-004` 转成 golden / 走查规则 | `traceability.md:280`（G5） |
| 文案语气七条规则已冻结（用「建议 / 可以 / 别忘了」，不用「必须 / 请立即」） | `.agents/skills/zhaoxi-design-system/references/principles.md:67-75` |
| 动效纪律：除 Orb 与循环指示器外全部 ≤400ms | `tokens.md:235`；`SKILL.md:47` |

### 2.2 为什么必须做，且必须在 M0 做

1. **它是「不得白屏」这条质量线的唯一落点。** V4.0.0 的样板已把「错误态必须有重试而非白屏」列为硬验收（`PLA-016.md:102`）；客户端若不在组件层冻结，每个页面会各自写一个错误态，文案与交互必然漂移。
2. **错误文案是合规与信任问题，不只是文案问题。** 后端 `chat.py:85` 会把 LLM 失败细节以 `detail` / `error`（含 `status` / `code` / `message`）下发（`apps/backend/app/api/v1/chat.py:24-32`）；若端上直接透传，用户会看到英文状态码与异常信息——既违反「温暖而非企业」（`principles.md:15`），也暴露技术细节。
3. **骨架屏决定冷启动体验的成败。** 冷启动首屏 ≤ 2.5s 是基线（`requirements-analysis.md:219`）；骨架屏若与真实内容尺寸不同，数据到达时会**布局跳动**，用户感知为「闪一下」，比直接白屏更糟。
4. **它必须先于所有页面任务冻结。** `APP-009 ~ APP-022` 的每个页面都要消费四态；本任务晚一天，下游就多一天各自造轮子的风险。

### 2.3 在 V5.0.0 中的位置

M0 第 7 个任务（`tasks.md:113`），位于 `APP-007 → APP-008` 之后、所有页面任务之前。它是 C1 收口点「设计系统冻结」的一部分（`tasks.md:255`）。

## 3. Scope

### 3.1 In Scope

1. **四态组件**（与 Riverpod `AsyncValue` 三态对齐）：

   | 态 | 组件 | 契约要点 |
   |---|---|---|
   | 加载 | `LoadingState` | 轻量指示器（循环指示器，不受 ≤400ms 约束）；**不用 M3 `CircularProgressIndicator` 默认皮肤**（M3 禁令 3，`flutter-architecture.md:71`）；色 `aiPrimary` |
   | 空态 | `EmptyState` | 一句 AI 口吻的说明 + 可选下一步动作；**不得留白、不得用假数据**（`components.md:313`） |
   | 错误 | `ErrorState` | **必须含重试**；一句用户可读文案 + 一个下一步动作；**不得白屏**（`PLA-016.md:102`） |
   | 骨架屏 | `Skeleton` | 与真实内容**同尺寸同层级**；无布局跳动（`flutter-architecture.md:374`） |

2. **错误文案规范**：

   | 规则 | 契约 |
   |---|---|
   | 零技术细节 | **不得出现** HTTP status code、异常类名（`TimeoutException` / `DioException` 等）、英文堆栈、后端 `detail` / `error.message` 原文 |
   | 统一口吻 | 「亚丝娜」第一人称（`principles.md:69`） |
   | 必须给下一步动作 | 每条文案后必须跟一个可执行动作（重试 / 检查网络 / 稍后再试） |
   | 语气 | 对齐 `principles.md` §5.2 七条规则：用「建议 / 可以 / 别忘了」，**不用「必须 / 请立即」** |

3. **骨架屏尺寸契约**：与真实内容同尺寸同层级（见 §4.1.3）。
4. **冷启动首页骨架 → 数据的过渡契约**：缓存优先（`flutter-architecture.md:374`）。
5. **四态与 `AsyncValue` 的映射函数**：`loading` → 骨架/加载；`data` → 内容（空则空态）；`error` → 错误态。
6. **文案模板常量**：集中一处，供全站复用；不硬编码在页面里（为 V2 国际化留口，`requirements-analysis.md:226`）。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | 网络层错误映射实现（`DioException` → `AppError`） | 归 APP-003（网络层与 NDJSON 流式解析）；本任务只定义**组件与文案**，不碰 `core/network/` |
| 2 | 具体页面的数据装配与 provider | 归 APP-009 ~ APP-022；本任务只交付四态组件 |
| 3 | 崩溃上报 / 首屏耗时 / 漏斗埋点 | 归 PLT-003（可观测与埋点）；日志禁打账目金额与健康数值（`tasks.md:216`） |
| 4 | 离线写路径（写排队重试的 UI 明示） | 归 `core/network/retry_queue` + 各写操作页面（`flutter-architecture.md:375`）；V1 明确不做 Offline-first 写（`requirements-analysis.md:398`） |
| 5 | 全局 toast / snackbar 体系 | 本任务只做「页面级四态」；轻提示属交互反馈，不在四态语义内 |
| 6 | 多语言（i18n）实现 | V1 中文单语，但字符串不硬编码在组件里（`requirements-analysis.md:226`）；本任务只保证「不硬编码」，不引入 i18n 框架 |
| 7 | 骨架屏 shimmer 动效库 | 自绘即可；引入动效库违反依赖冻结（`flutter-architecture.md:146-154`） |
| 8 | 健康页 / 简报页等深色页面的专属四态皮肤 | 归 APP-018 / APP-024；本任务只做中性底色的通用四态，深色变体由调用方经 token 覆盖 |
| 9 | 新增依赖 / 功能开关 | 依赖冻结 + 裁决 9（禁止 `*_enabled`） |
| 10 | 硬编码色值 / 文案 | 红线 2 + 本任务核心纪律 |

## 4. Technical Design Requirements

### 4.1 组件契约

#### 4.1.1 四态组件字段表

| 组件 | 参数 | 类型 | 语义 | 必填 |
|---|---|---|---|---|
| `LoadingState` | `label` | `String?` | 可选的辅助文案（默认无，避免啰嗦） | 否 |
| `EmptyState` | `title` | `String` | 一句 AI 口吻说明 | 是 |
| `EmptyState` | `action` | `(String label, VoidCallback onTap)?` | 可选下一步动作（用 `A12 chip-btn`） | 否 |
| `EmptyState` | `illustration` | `Widget?` | 可选插图槽位（默认用 ✦ 四芒星占位，`orb.md:154`） | 否 |
| `ErrorState` | `message` | `String` | **用户可读**文案（已由调用方从 `AppError` 映射） | 是 |
| `ErrorState` | `retryLabel` | `String` | 重试按钮文案（默认「再试一次」） | 否 |
| `ErrorState` | `onRetry` | `VoidCallback` | **必填**；无此回调不得渲染 `ErrorState` | 是 |
| `ErrorState` | `secondaryAction` | `(String label, VoidCallback onTap)?` | 可选第二动作（如「检查网络」） | 否 |
| `Skeleton` | `child` | `Widget` | 骨架占位块（矩形 / 圆形 / 文本行） | 是 |
| `Skeleton` | `shape` | `enum { rect, circle, line }` | 占位形状 | 是 |
| `Skeleton` | `size` | `Size` | **必须与真实内容同尺寸** | 是 |

#### 4.1.2 错误文案规范表（**本任务的核心契约**）

| 场景（调用方映射后的语义） | 文案（亚丝娜口吻，对齐 `principles.md` §5.2） | 必须给的下一步动作 |
|---|---|---|
| 网络不可达 / 超时 | 「刚才没连上，可能是网络不太稳。可以检查一下网络，然后我们再试一次。」 | 「再试一次」+「检查网络」 |
| 服务端 5xx / 未知错误 | 「我这边出了点小状况，已经记下了。稍后再试一次，好吗？」 | 「再试一次」 |
| 请求被拒（401 / 403） | 「这次没能通过验证。建议重新配对一下设备，再来找我。」 | 「重新配对」 |
| 内容不存在（404） | 「这条内容好像不在了。可以返回上一页看看别的。」 | 「返回上一页」 |
| 流式中断（`done` 未到） | 「刚才的话没说完就断了。可以让我重说一次，或者直接再问一遍。」 | 「重新生成」 |
| 数据为空（非错误） | 「这里还是空的。等你记下第一笔，我就会整理给你看。」 | 「去记一笔」（视页面而定） |

**硬性禁止**（任一出现即判不合格）：

| # | 禁止内容 |
|---|---|
| 1 | HTTP status code（`500` / `403` / `422` …） |
| 2 | 异常类名（`DioException` / `TimeoutException` / `SocketException` …） |
| 3 | 英文堆栈或英文原文（如 `Internal Server Error`） |
| 4 | 后端 `detail` / `error.message` 的**原文透传**（`chat.py:24-32` 下发的字段不得直接展示） |
| 5 | 「系统检测到」「请立即」「操作失败」等无人称 / 命令式措辞（`principles.md:69`、`principles.md:71`） |

#### 4.1.3 骨架屏尺寸契约（同尺寸同层级）

| 页面区块（示例） | 真实内容尺寸 | 骨架尺寸 | 层级 |
|---|---|---|---|
| 首页 AI 总结卡（`A2`） | 圆角 24 · 内边距 18 · 高度由正文行数决定 | 同圆角 / 同内边距 / **同高度区间** | 与真实卡同层（`surface` 底 + 同投影） |
| 指标迷你卡（`A5`） | 圆角 18 · 内边距 `13/12` · 含 26px 图标方块 + sparkline 高 22 | 同尺寸占位块 | 同层 |
| 任务行（`A6`） | 内边距 `13/2` · 复选框 21px | 21px 圆占位 + 文本行占位 | 同层 |
| 账单行（`A20`） | 图标方块 36 圆角 12 | 36px 方块占位 | 同层 |
| 记忆卡（`A24`） | 圆角 18 · 内边距 `15/16` | 同尺寸占位 | 同层 |

**判定口径**：骨架渲染帧与「数据到达后的首帧」的**外框尺寸与层级必须一致**（用例 `test_skeleton_matches_real_content_size` 逐区块断言）。骨架的填充色用 `fillSubtle` / `fillMuted`（`tokens.md:33-34`），不用灰色系自造值。

#### 4.1.4 `AsyncValue` 映射契约

| `AsyncValue` 状态 | 渲染 | 备注 |
|---|---|---|
| `loading`（首次，无旧值） | `Skeleton`（若已知真实尺寸）或 `LoadingState` | 冷启动首页走 `Skeleton`（`flutter-architecture.md:374`） |
| `loading`（有旧值，刷新中） | 旧值内容 + 轻量刷新指示 | **不得**用骨架替换已有内容（避免闪烁） |
| `data`（有内容） | 真实内容 | — |
| `data`（空集合） | `EmptyState` | 空态是 `data` 的特例，**不是错误** |
| `error` | `ErrorState`（含重试） | 有旧值时：旧内容 + 错误提示条，不整屏替换 |
| `error`（无旧值） | `ErrorState` 整屏 | **不得白屏** |

> 映射函数落点 `design_system/components/states/async_state_view.dart`（纯函数 + 一个无状态 widget），**不依赖 Riverpod 类型之外的业务语义**。

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **错误态必须含重试，不得白屏** | V4.0.0 样板已把「错误态必须有重试而非白屏」列为硬验收（`PLA-016.md:102`）；这是用户面质量线 |
| D2 | **错误文案零技术细节**（禁 status code / 异常类名 / 英文堆栈 / 后端原文透传） | 技术细节既无助于用户决策，又违反「温暖而非企业」（`principles.md:15`）；后端 `chat.py:24-32` 的 `detail`/`error` 不得直出 |
| D3 | **错误文案必须给下一步动作** | 「不催促、给具体承诺」是人格设定（`principles.md:73`、`principles.md:75`）；只报错不给路，用户只能退出 |
| D4 | 文案语气对齐 `principles.md` §5.2 七条规则 | `tasks/README.md:67` 要求文案必须沿用 skill 范例，不得自创风格 |
| D5 | **骨架屏与真实内容同尺寸同层级** | 尺寸不一致会导致数据到达时布局跳动，感知比白屏更差（`flutter-architecture.md:374`） |
| D6 | 四态与 **`AsyncValue` 三态对齐**；空态是 `data` 的特例 | Riverpod `AsyncValue` 天然三态（`flutter-architecture.md:19`）；把空态当错误会导致「无数据」也弹重试 |
| D7 | 有旧值时**不用骨架 / 整屏错误替换已有内容** | 刷新闪烁会削弱「安静陪伴」的观感（`principles.md:21`） |
| D8 | 四态组件**无状态**、不 import `core/` / `features/` | 分层纪律 L2（`flutter-architecture.md:196`）；错误映射在 `core/network/`，组件只接收已映射文案 |
| D9 | 文案集中在**模板常量**，不硬编码在页面 | 为 V2 国际化留口（`requirements-analysis.md:226`）；也便于静态断言「零技术细节」 |
| D10 | 骨架屏**不引入 shimmer 动效库**；如需动效，自绘且 ≤400ms | 依赖冻结（`flutter-architecture.md:146-154`）+ 动效纪律（`tokens.md:235`） |
| D11 | 错误映射的唯一出口在 `core/network/`（APP-003），本任务**不实现映射** | 单一职责；也避免四态组件反向依赖网络层 |
| D12 | 加载指示器**不用 M3 默认皮肤** | M3 禁令 3（`flutter-architecture.md:71`）；自绘或经 token 覆盖 |

### 4.3 数据流

```text
Dio / NDJSON（core/network，APP-003）
   ↓ 异常归一 + 错误映射（唯一出口）
AppError { kind, userMessage, actions[] }        ← 技术细节在此被吸收，不外泄
   ↓ 经 Riverpod provider（AsyncValue）
AsyncStateView<T>(asyncValue, builder, skeletonBuilder, emptyBuilder, onRetry)
   ├── loading（无旧值）→ Skeleton / LoadingState
   ├── loading（有旧值）→ 旧内容 + 轻量刷新指示
   ├── data（非空）    → 真实内容
   ├── data（空）      → EmptyState（文案 + 可选动作）
   └── error          → ErrorState（userMessage + onRetry[必填] + 可选第二动作）
```

### 4.4 依赖与边界

| 类别 | 内容 |
|---|---|
| 允许依赖 | `flutter/material.dart`（基础绘制与手势）、`design_system/tokens/`（APP-002）、`design_system/components/`（APP-007 的 `Card` / `ChipButton` / ✦ 图标）、`riverpod`（仅 `AsyncValue` 类型，用于映射函数签名） |

| 反向约束 | 下游页面**只允许**用 `AsyncStateView` + 四态组件，不得自造错误态 / 骨架屏 |

## 8. Acceptance Criteria

| # | 判据 | 验证方式 |
|---|---|---|
| AC1 | 四态组件（加载 / 空 / 错误 / 骨架）全部交付且**无状态** | 7.3 + 代码检查 |
| AC2 | 四态与 Riverpod `AsyncValue` 三态对齐；空态是 `data` 的特例 | 7.1 六条映射用例 |
| AC3 | **错误态必须含重试，不得白屏**（`onRetry` 必填） | `test_error_retry_triggers_callback` + `test_error_state_requires_on_retry` |

| AC5 | 错误文案**必须给下一步动作**，且为「亚丝娜」口吻 | 7.2 后三条 |
| AC6 | 文案语气符合 `principles.md` §5.2（无「必须 / 请立即 / 系统检测到」） | `test_state_copy_has_no_command_tone` |
| AC7 | 骨架屏与真实内容**同尺寸同层级**，数据到达无布局跳动 | 7.3 两条尺寸用例 |
| AC8 | 冷启动首页「骨架 → 数据」过渡契约落地（缓存优先） | 7.1 loading 分支 + APP-014 联调用例 |
| AC9 | 有旧值时不用骨架 / 整屏错误替换已有内容 | 7.1 两条「有旧值」用例 |

| AC11 | 零硬编码色值；零 `core/` / `features/` import | 7.5 |
| AC12 | **零新增依赖、零新增功能开关** | `git diff --stat` |
