## 12. 使用方式

1. **开发前**：每个 Task Detail 生成时，先在本矩阵里找到它的来源条目，确认理解一致。
2. **评审时**：逐行核对 `⚠️` 项——它们全部指向具体阻塞项（`API-002` / `API-006` / `API-007` / D1），**阻塞项不解决，对应任务不得开工**。
3. **验收时**：§7.3「不要开发」6 项 + §7.2 后置项是**反范围清单**，出现即视为范围蔓延。
4. **变更时**：任何需求变更先改本矩阵，再改 `requirements-analysis.md`，最后改 `tasks.md`——**顺序不可颠倒**。
