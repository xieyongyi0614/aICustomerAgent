# MEM-010 Task Detail — 离线评估与回归清单

> 上游：[../tasks.md](../tasks.md) MEM-010 ｜ [../../architecture/evaluation.md](../../../architecture/evaluation.md) ｜ 依赖：MEM-006, MEM-008

## Task 目标

扩展 `offline_evaluator` 支撑 [evaluation.md](../evaluation.md) 的 E-MEM-01~06 场景集与门槛计算；建立本目录 regression-checklist 的可执行流程（Flag OFF golden 对比 + V4 checklist 重跑），形成 P1 验收闭环。

## 背景 / 为什么需要

项目已有离线评估底座：`app/services/offline_evaluator.py`（离线跑场景集出报告）与 V7.5 评估引擎（规则+Judge 双阶段、只读旁路）。但 memory 域指标（precision/recall/改述召回/冲突处理/遗忘）没有任何场景集与门槛，灰度推进（migration §6 验收门）无量化依据。

## 当前代码涉及位置

| 位置 | 现状 | 本 Task 动作 |
|---|---|---|
| `app/services/offline_evaluator.py` | 既有离线框架 | 注册 memory 场景集与指标计算器（不改框架） |
| `app/services/evaluation_engine.py` + `evaluation_rules/` | 规则注册表模式 | 新增 `evaluation_rules/memory.py`（纯函数规则），沿注册表惯例 |

| v1 regression checklist（v1.0.0/v4/ 等） | 人工清单 | 引用执行，不修改 v1 文档 |

## 设计方案

1. **场景集格式**：JSON 场景（`tests/eval/memory/*.json`，沿 v9 scenarios 惯例）：`{id, kind, seed_messages[], probe_query, expect{recall_ids|supersede|forget|reject}}`；首版 100 条（每类 ≥10）。
2. **指标计算器**（纯函数）：E-MEM-01~06 逐项实现（evaluation.md 门槛表），输出报告 JSON（含逐场景 pass/fail + 归因 trace 引用）。
3. **双态执行**：Flag OFF 跑 golden 对比（prompt_snapshots/响应逐字节）；Flag ON 影子环境跑全场景集。
4. **Judge 接入**：precision/relevance 用 Judge 抽样（复用 evaluation_judge_chain），失败记 skipped 重跑。
5. **报告归档**：`tests/eval/reports/mem-{date}.json`，作为灰度推进附件。

## 数据模型 / 接口变化

- 无业务表变化；新增测试资产（场景 JSON、指标计算器、报告目录）。

## 核心处理流程

```text
offline_evaluator --suite=memory
 → 逐场景: 注入 seed → 交互模拟(走真实 chat 链) → probe → 断言
 → 指标聚合(E-MEM-01~06) → 门槛判定 → 报告
双态: --flag=off(golden diff) / --flag=on(影子)
```

## 与现有模块的关系

- 只读旁路（沿 V7.5 铁律）；复用 offline_evaluator/evaluation_engine/judge；场景模拟走真实链路（依赖 MEM-002~008 全部就绪）。
- 不修改 v1.0.0 checklist 文档；不新建评估存储。

## 异常与边界情况

- Judge 失败/超时 → 场景 skipped 计数并在报告标注，重跑补齐。
- 场景断言需要确定性 → 模拟环境固定随机种子、冻结时钟（TimeProvider 注入）。
- 标注集规模不足 → 门槛按 evaluation.md 生效，报告标注覆盖率。

## 测试要求

- 指标计算器单测（构造已知输入验证数值）。
- 场景集冒烟（每类至少 1 条入 CI 快速档）。
- 双态执行脚本化（一条命令完成 OFF+ON 两轮）。

## 验收标准

- 给定 P1 全量场景集，当离线执行，那么 E-MEM-01~06 六项达到 evaluation.md 门槛并产出报告。
- 给定 Flag OFF 执行，那么 golden diff 为空。
- 给定报告，那么每个 fail 场景可通过 MEM-008 归因 API 定位环节。

## Implementation Constraints

- 只读；不产业务写入；不改 evaluation 框架本体（只注册）；不提前实现 P2+ 指标（reflection/development）。
