# MEM-005 Task Detail — 生命周期引擎（Lifecycle）

> 上游：[../tasks.md](../tasks.md) MEM-005 ｜ [../../design.md](../../design.md) §4/§7 ｜ 依赖：MEM-001, MEM-003

## Task 目标

实现 `memory2/lifecycle.py`：reinforce/merge/supersede/decay/forget 全状态机；指数衰减周期任务；新转正记忆的冲突检测（contradicts/merge 链）；显式 forget 全通道清除（软删+30 天物理删）。

## 背景 / 为什么需要

v1 的「生命周期」只有两段：`memory_service.reclaim_expired_memories`（L310，TTL 过期）+ `memory_repository` 的 `supersede_memory`/`invalidate_memory`/`forget_memory`/`delete_memory`（L141-181，**forget 是硬 DELETE**）。无强化、无合并、无衰减——长对话记性必然退化，误删不可恢复（version-boundary §2 明列 Replace 理由）。design.md §4 的六态状态机是 P1 完成标准「生命周期全链路有 trace」的承载。

## 设计方案

1. **状态机**（合法转换表落地为代码常量 + 转换守卫函数 `transition(memory, event)`，非法转换抛错）：
   `Active→Active(reinforce/update/merge)`、`Active→Superseded`、`Active→Invalidated`、`Active→Decayed`、`Decayed→Active(re-reinforce)`、`Decayed→Forgotten`、`Superseded/Invalidated→Forgotten`、`Forgotten→物理删(30 天后)`。
2. **衰减公式**：`salience_t = salience_0 · exp(-λ_type·Δdays)`，λ 按类型分档（preference/fact 低、experience 中、其余高，settings 配置）；周期任务按日桶幂等（记录 last_decayed_date，同日重跑跳过）。
3. **reinforce**：MEM-006 检索命中的 memory_id 聚合进内存缓冲 → 周期批量 flush（`last_reinforced_at`、`salience`↑）——**取代 v1 `touch_last_accessed` 的读路径直写**。
4. **merge/supersede**：新转正记忆与同主题既有行比对（`same_topic` + 向量邻域，MEM-004 后可用）：高相似修正 → supersede + `memory_links(relation=supersedes/merges)` + `merge_chain` 追加；矛盾（negate）→ **保守并存**：两行均 active，`memory_links(contradicts)` + pending 标记，交由用户澄清/P2 反思解决（修 v4 遗留的单跳互删）。
5. **forget**：状态置 forgotten + embedding 置 NULL + `forgotten_at`（同事务）→ 30 天保留期后物理删除（含向量/links）；期间任何检索通道过滤 status。
6. **trace**：`memory_lifecycle` 步骤（事件/迁移前后/公式参数/原因）。

## 数据模型 / 接口变化

- `memory_links`/`merge_chain`/`last_reinforced_at`/`salience` 使用（MEM-001 建）；新增 `forgotten_at`（并入 MEM-001 迁移范围，本 Detail 明确）。
- 新接口：`lifecycle.on_promoted(new_memory)`（MEM-003 调）、`flush_reinforce_buffer()`、`run_decay_cycle(now)`、`explicit_forget(memory_id|match)`（MEM-007 调）。

## 核心处理流程

```text
转正后: on_promoted → 冲突检测(same_topic+邻域) → [supersede+links | merge_chain | contradicts 保守并存 | 无冲突]
周期: flush_reinforce_buffer(批量) → run_decay_cycle(按日桶) → Decayed 超保留期 → Forgotten
显式 forget: 同事务置 forgotten + 清向量 → 保留期后物理删
```

## 与现有模块的关系

- 复用：`memory_conflict.same_topic`（纯函数）、repo 的 supersede/invalidate（扩展 links 写入）。
- 替代（Flag 内）：v1 硬删 forget、读路径 `touch_last_accessed` 直写。
- 不触碰：v8.5/State/Goal 任何表与数值。

## 异常与边界情况

- 非法状态转换（如 Forgotten→Active）→ 守卫拒绝 + trace。
- 衰减把 salience 压到 floor → 转 Decayed 而非删除（保底可被再强化复活）。
- 冲突检测误判 → 保守并存兜底（宁可并存不可误删，tasks.md Risk）。
- 周期任务中断 → 按日桶幂等，下一窗口续跑。
- forget 与检索竞争 → 状态先置 forgotten 同事务，检索过滤状态列，无窗口期（design.md §7）。

## 测试要求

- Unit：状态机全转换 + 非法转换拒绝；衰减公式数值（含同日幂等）。
- Integration：改口（supersede+链可溯）/部分修正（merge）/显式遗忘（三通道 0 命中）/Decayed 复活。
- Idempotency：同日重跑衰减、重复 forget。
- FailureInjection：flush 中途断连（缓冲不丢）。

## 验收标准

- 给定用户改口「其实我不吃辣」，当新候选转正，那么旧条目 superseded 且 `memory_links` 可溯。
- 给定显式 forget，那么向量/结构/Context 三通道检索均 0 命中。
- 给定 30 天无强化的低 salience 记忆，那么状态为 Decayed 而非被物理删除。
- 给定同日两次 decay 运行，那么 salience 只衰减一次。

## Implementation Constraints

- 冲突保守并存，禁止单跳双向丢弃；不硬删（v1 硬删代码保留待清理期）；不写其他域任何表；衰减/强化全部批量写，禁止读路径直写。
