# MEM-006 Task Detail — 混合检索与排序（Retriever）

> 上游：[../tasks.md](../tasks.md) MEM-006 ｜ [../../design.md](../../design.md) §6 ｜ 依赖：MEM-004, MEM-005

## Task 目标

实现 `memory2/retriever.py` 并接线 `context_builder`：语义（cosine）+ 结构化（recency/importance/salience/type_affinity）混合打分、top-5、检索类合并预算 800、分数解释 trace；embedding 缺席自动降级纯结构化；Flag OFF 输出与 v1 字节级一致。

## 背景 / 为什么需要

v1 检索链路：`context_builder.py` L38 `memory_service.retrieve(user_id, current_input)` → `_score_memory`（L242：`0.45·lexical + 0.25·importance + 0.20·recency + 0.10·type_affinity`，settings L173-176）→ `select_for_context`（L343）。词表打分导致同义改述必然召回失败（v1 审计问题 1）。v2 在同一接线点做 Flag 分支，不改变 context_builder 的装配结构（version-boundary：Extend）。

## 设计方案

1. **混合打分**：`score = w1·semantic(cosine) + w2·structured + w3·type_affinity − penalty`；
   - structured = recency + importance + salience（salience 来自 MEM-005 衰减体系）；
   - penalty = recently_rejected（被 MEM-003 拒后 24h 内）+ 被用户纠正未满 24h 的 contradicts 对侧；
   - 权重全部进 settings，离线校准。
2. **两路召回**：向量路（pgvector ANN top-20 候选）∪ 结构路（`list_active` 池内打分）→ 合并去重 → 统一打分排序 → top_k=5。
3. **降级**：query 或行 embedding 为 NULL → 该行/该路仅结构化；两路都不可用 → 返回结构化结果（不空转报错）。
4. **过滤**：status≠active、visibility=hypothetical、被纠正冷却期、superseded/invalidated 链目标不入结果。
5. **预算**：结果传入 MEM-011 的装配段执行 ≤800 合并预算截断（retriever 只负责排序，不截断字符）。
6. **trace**：每条结果/落选条目记录 semantic/structured/type 各分数与命中/未命中原因。

## 数据模型 / 接口变化

- 新接口：`memory2/retriever.retrieve(user_id, query, character_id, top_k) -> RankedMemories`（含 items + scores + trace 片段）。
- 新 repo 函数 `search_by_vector`；无新表。

## 核心处理流程

```text
query(用户消息+本轮意图) → embedding(有则) 
 → 向量路 ANN top-20 ∥ 结构路池内打分 → 合并去重
 → 混合打分 + penalty 过滤 → top-5 → RankedMemories(含分数解释)
 → context_builder 装配（MEM-011 预算裁定）→ trace
```

## 与现有模块的关系

- 接线点唯一：`context_builder.py` L38 分支；不改 `chat_pipeline`/prompts 结构。
- reinforce 信号投递 MEM-005（批量 flush）；排序依赖 MEM-004 向量与 MEM-005 salience。
- 被依赖：LIFE-005（P5 周期快查复用同接口，显著度参数不同）。

## 异常与边界情况

- 向量服务/索引异常 → 纯结构化降级（结果照常可用）。
- 结果为空 → Context 检索段为空，不报错。
- 改述查询但 embedding 全 NULL（迁移期）→ 结构化兜底，trace 标注 degraded。
- 同 query 同数据 → 结果确定（缓存窗口内），保证 golden 可比。

## 测试要求

- Unit：混合打分（权重边界）、penalty 冷却期、过滤规则。
- Integration：改述召回标注集（recall ≥0.8）；降级路径；消融对比（纯结构 vs 混合）。
- Performance：检索 P95 <200ms（ANN + 池打分）。
- Regression：Flag OFF 下 `context_builder` 输出与 v1 字节级一致（prompt_snapshots 对比）。

## 验收标准

- 给定同义改述查询，当检索，那么离线集 recall ≥0.8。
- 给定子闸 `v2_memory_vector_enabled` 关闭，那么输出与 v1 关键词路径语义等价（golden 字节级）。
- 给定任一被拒/被纠正记忆，当 24h 内检索，那么不出现在结果中且 trace 可见 penalty。

## Implementation Constraints

- 检索是唯一入口，禁止绕过 Context Architect 直改 prompt；不注入 hypothetical/forgotten；不改 12000 总预算与分段结构；不做任何写入（reinforce 走缓冲）。
