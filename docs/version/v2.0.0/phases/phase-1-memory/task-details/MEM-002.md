# MEM-002 Task Detail — 统一摄取通道（Ingest）

> 上游：[../tasks.md](../tasks.md) MEM-002 ｜ [../../architecture.md](../../architecture.md) §2 ｜ 依赖：MEM-001

## Task 目标

把 Conversation（turn_analysis 抽取产物）、ActionRecord、完结 WorldEvent、RelationshipEvent 四个来源统一接入 `memory2/ingest.py`，产出带 `source_ref` 与幂等键的 `memory_candidates` 行；Roleplay/瞬时请求在规则层拦截。

## 背景 / 为什么需要

v1 的经验沉淀只有一条通道：`app/application/post_process.py` L135 `run_memory_extract` → `memory_service.extract_and_save`（L46）→ extractor 链（`app/prompts/extractor.py` + `MemoryExtraction`/`MemoryCandidate` Pydantic 校验，`app/models/memory.py` L36-60）。ActionRecord/WorldEvent/RelationshipEvent 落库后就此终结——事件经历无法成为记忆，P2 Reflection 将无证据可用。v1 的 `MemoryCandidate`（L36）是 **LLM 抽取输出的值对象**，与本 v2 的「候选表实体」同名不同物——Detail 明确区分：Pydantic `MemoryCandidate` 保持不动，新表实体命名为 ORM `MemoryCandidateRow`（落 `memory_candidates` 表），避免命名冲突。

## 当前代码涉及位置

| 位置 | 现状 | 本 Task 动作 |
|---|---|---|
| `app/application/post_process.py` L135 `run_memory_extract`、L257 `STEP_HANDLERS` | 抽取步骤直调 extract_and_save | Flag 内改为调 `memory2/ingest.ingest_from_conversation(...)` |
| `app/services/memory_service.py` L46 `extract_and_save`、L128 `_execute_forget` | v1 抽取+落库+遗忘一体 | 保留不动（Flag OFF 路径）；ingest 复用其产物而非重抽 |

| `app/core/db.py` `WorldEvent`/`RelationshipEvent` ORM（L170 等）、`app/models/action.py` ActionRecord | 事件源 | 新增只读查询封装 `memory2/sources.py` |
| `app/core/settings.py` | — | 新增 `v2_memory_ingest_max_per_turn`、假设/瞬时词表配置项 |

## 设计方案

1. 新模块 `app/services/memory2/ingest.py` + `app/services/memory2/sources.py`（落位遵循 phase-1 architecture.md §1）。
2. 四个摄取入口，统一收敛到内部函数 `_create_candidate(source_table, source_id, content, proposed_type, source_kind, salience_init, visibility)`：
   - `ingest_from_conversation(turn_analysis_output, extraction_output)`：复用 v1 extractor 产物（`MemoryExtraction`），**不新增 LLM**；对每条候选执行词表预筛。
   - `ingest_from_action_record(record)`：仅取 v9 action_memory_policy 已允许沉淀的类型（settings `action_memory_policy_json` 中 deposit=true 项）；`source_table="action_records"`。
   - `ingest_from_world_event(event)`：仅完结（completed）事件；`source_table="world_events"`。
   - `ingest_from_relationship_event(event)`：`source_table="relationship_events"`（P4 REL-001 复用同一入口）。
3. **词表预筛（规则层拦截）**：假设/Roleplay 触发词（假装/如果/假如/要是/扮演…）→ `visibility="hypothetical"`（仍入库但永不进长期检索）；瞬时动作短语（拿/递/放下/开/关 + 物品…）→ 不产候选，trace 记拦截原因。
4. **幂等**：`source_table + source_id` 唯一约束兜底；insert 前先 SELECT，命中即返回既有候选（不更新）。
5. trace：复用 `trace_collector.py` 的 `TurnTraceSession.record`，新增步骤名 `memory_ingest`。

## 数据模型 / 接口变化

- 新 ORM：`MemoryCandidateRow`（mem002 建表于 MEM-001）；新服务模块 `memory2/ingest.py`、`memory2/sources.py`。
- `post_process.py` `STEP_HANDLERS` 元组内 `run_memory_extract` 内部分支（Flag 判断），元组结构与步骤顺序不变。

## 核心处理流程

```text
post_process（per-user 写锁内，沿 run_post_process L282 既有串行）
 → run_memory_extract: v2_memory_enabled?
   ├ OFF → v1 extract_and_save 原路径
   └ ON  → extractor 产物 → ingest_from_conversation
            + 该轮 ActionRecord/完结 WorldEvent/RelationshipEvent 各源 ingest
 → 词表预筛 → 幂等查重 → INSERT memory_candidates(status=pending) → trace
```

## 与现有模块的关系

- **只读**依赖 turn_analysis/extractor 输出、ActionRecord/WorldEvent/RelationshipEvent 表。
- **不读** `relationship_state` 数值（domain-boundaries §3 红线）；relationship 相关仅读事件表。
- ActionRecord 沉淀类型沿用 `action_memory_policy_json`（settings L140），不自创类型映射。

## 异常与边界情况

- DB 失败 → 事务回滚，该轮 post_process 记 failed，其余步骤照常（沿 `run_post_process` 单步异常不中断语义）。
- source 缺失/字段异常 → 丢弃候选 + trace（不抛出）。
- 同轮同内容多源重复 → 各源独立幂等键，允许并存（评估器 MEM-003 负责内容级去重）。
- 事件回放/补扫 → 幂等键拦截，天然安全。

## 测试要求

- Unit：词表预筛表驱动（假设/瞬时/正常各 ≥10 例）；`_create_candidate` 字段组装。
- Integration：四源各构造端到端用例（含 v9 reminder 完结 → important_event 候选）。
- Idempotency：同一 ActionRecord 重复摄取两次，`memory_candidates` 行数恒为 1。
- FailureInjection：ingest 中途 DB 断连，下一轮恢复不丢不重。

## 验收标准

- 给定「假装我是国王」，当摄取发生，那么候选 visibility=hypothetical。
- 给定「帮我拿块西瓜」，当摄取发生，那么不产生候选且 trace 记录拦截原因。
- 给定同一 ActionRecord 重复摄取，那么候选行数恒为 1。
- 给定 Flag OFF，那么 post_process 行为与 v1 逐字节一致。

## Implementation Constraints

- 不新增 LLM 调用（复用 extractor 产物）；不改 v1 `extract_and_save`/`memory_policy`/`memory_conflict` 本体；不消费 outbox（P5 LIFE-004 前 WorldEvent 直读表）；P2~P6 能力（评估转正语义、反思、里程碑）一律不做。
