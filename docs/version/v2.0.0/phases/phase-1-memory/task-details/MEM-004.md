# MEM-004 Task Detail — Embedding 批处理

> 上游：[../tasks.md](../tasks.md) MEM-004 ｜ [../../design.md](../../design.md) §1/§6 ｜ 依赖：MEM-001, MEM-003

## Task 目标

实现 `memory2/embeddings.py`：新转正记忆的 embedding 攒批（≥32 条或 60s 窗口）生成并同事务回填 `memories.embedding`；失败走 `background_jobs` 重试；embedding 服务不可用时保持 NULL、检索自动降级。

## 背景 / 为什么需要

项目当前**完全没有**任何 embedding/vector 设施（v1 审计：grep embedding/vector/pgvector 零命中）；v1 检索是 `memory_service._score_memory`（L242）的纯词表加权。MEM-006 的语义通道依赖向量列，但逐条同步生成会阻塞后台且造成写放大——必须批处理 + 异步补偿（data-flow.md §2.2/§5）。

## 设计方案

1. **攒批器**：内存队列 + 双条件 flush（条数 ≥`v2_embedding_batch_size` 或距首条 ≥`v2_embedding_batch_window_seconds`）。
2. **生成**：批量调 embedding 端点（batch ≤ 上限）；向量 768 维由配置声明，端点维度不符 → 该批失败入 job。
3. **回填**：每条 `UPDATE memories SET embedding=... WHERE id=... AND embedding IS NULL`（幂等条件更新），单批一个事务。
4. **失败路径**：网络/配额错误 → 指数退避重试 2 次 → 仍失败写 `background_jobs`（job_type=embedding_backfill，idempotency_key=`embedding:{memory_id}:{content_hash}`）。
5. **补扫**：批处理循环每窗口先扫 `embedding IS NULL AND status='active'` 的存量行（覆盖服务中断期间的积压）。
6. **内容变更**：记忆被 merge/supersede 后内容变化 → 旧行不再补向量；新行重新入队。

## 数据模型 / 接口变化

- 新接口：`memory2/embeddings.enqueue(memory_id, content)`（转正后由 MEM-003 调用）、`flush_if_due()`、`backfill_scan()`。
- 新 repo 函数 2 个；无新表（复用 background_jobs）。

## 核心处理流程

```text
MEM-003 转正 → enqueue(memory_id)
批处理循环（background_jobs 驱动）:
  存量 NULL 扫描 ∥ 内存攒批 → 凑批 → embedding 端点
  → 成功: 条件 UPDATE 回填（幂等）
  → 失败: 退避×2 → 仍败 → background_jobs 重试（指数退避, max5）
检索侧（MEM-006）: embedding IS NULL → 自动仅结构化打分
```

## 与现有模块的关系

- 依赖 MEM-003 的转正事件；被 MEM-006 消费。
- **不阻塞前台**：enqueue 为纯内存操作；批处理全后台。
- embedding 不作为 SoT：任何时刻可全量重建（rebuild = 清空 embedding 列 + backfill_scan），data-flow.md §2.2。

## 异常与边界情况

- 服务宕机/配额耗尽 → 全部退避+降级，无数据丢失（行仍在，检索走结构化）。
- 维度不匹配 → 该批失败入 job，trace 记录期望/实际维度。
- 进程重启 → 内存队列丢弃，靠 NULL 存量补扫恢复（不依赖内存态持久化）。
- 超长文本 → 按 token 上限截断后向量化（截断策略进 settings）。

## 测试要求

- Unit：攒批双条件触发；条件 UPDATE 幂等。
- Integration：批量注入 1000 条压测（吞吐与 P95）；服务中断→恢复→补扫闭环。
- FailureInjection：端点 500/超时/维度错误。
- Idempotency：重复 enqueue / 重启后不重复回填。

## 验收标准

- 给定转正记忆，当批处理周期完成，那么 ≤5 分钟向量可用。
- 给定 embedding 服务宕机 1 小时后恢复，那么存量 NULL 行在下一窗口全部补齐且期间检索正常。
- 给定重复 enqueue 同一记忆，那么仅生成一次向量。

## Implementation Constraints

- embedding 走批量异步、不阻塞前台；不改 `llm_factory._build_llm` 既有函数；不把 embedding 当 SoT；不引入独立向量库；不提前实现检索打分（MEM-006）。
