# REF-007 Task Detail — Insight→Context 注入段（Integration）

> 上游：[../tasks.md](../tasks.md) REF-007 ｜ [../../../architecture/context-architecture.md](../../../architecture/context-architecture.md) §1/§2 ｜ 依赖：REF-001, REF-005

## Task 目标

高置信 active Insight 以只读摘要进入 Context：Reflection 提供只读查询接口，编排层（context_builder + prompts/builder）新增 insight 段，并入检索类合并预算 800，Freshness 排序，invalidated 即时退出。不做行为调制（P3 DevPolicy 才是行为通道）、不做摘要压缩 LLM、禁止全量注入。

## 背景 / 为什么需要

domain-boundaries 裁决「Context（高置信 Insight 可入选）」，但 Phase 2 原始 Task 集无承接方——Design→Task 断层（TASKS-AUDIT §2）。不补则 P2 交付后 Insight 对角色行为零影响，认知闭环在最后一公里断裂：角色「形成了看法」却永远说不出口。本 Task 只做**只读注入**：改变的是角色每轮「知道什么」，不是「怎么做」（后者属 P3，防止 Insight 越过 DevPolicy 直改行为）。

## 设计方案

1. **只读查询接口（Reflection 侧）**：`list_active_insights` 已由 REF-001 交付；本 Task 补注入专用参数化：`status='active'` + `confidence >= v2_reflection_min_confidence`（默认 0.6）+ `scope IN v2_reflection_context_scopes`（默认 user/relationship——**scope 匹配的具体化裁决**：scope=world 的世界认知注入对话属 P6 Goal 调制范围，P2 不注入；此为对 tasks.md「scope 匹配」的落地解释，登记冲突记录第 9 条）+ 按 `confidence DESC, created_at DESC`（Freshness 排序）+ `LIMIT v2_reflection_context_max_items`。
2. **预算（检索类合并 800）**：MEM-011 已在 `context_builder.py` 实现双层装配与「检索类合并预算 800」贪心裁定（`context_assemble_v2` 预算占用 trace）；本 Task 将 insight 段接入该裁定——insight 段预算 = `max(0, v2_memory_retrieval_budget − 记忆检索段实际字符)`，按 `confidence DESC, created_at DESC` 逐条取用（statement 截断至 `v2_reflection_context_statement_chars=120`），超预算即停（后续条目 trace 记 `budget` 落选），预算占用计入 `context_assemble_v2` trace。不做独立预算通道、不改 MEM-011 既有裁定结构（冲突记录第 8 条）。
3. **渲染**：`builder.build` 在记忆段后追加：
   ```text
   【你确信的认知】
   - (belief) statement……
   （这是你基于相处形成的看法，仅在自然相关时体现，不要罗列或直接引用条目）
   ```
   段为空时不产生任何消息（Flag OFF 与无 Insight 场景 prompt 逐字节等于现状）。
4. **invalidated 即时退出**：查询在**每轮装配时执行**（无缓存跨轮复用），只取 active——invalidated/superseded 天然退出；结合 REF-005 时序口径（失效发生于 post_process），保证「处理澄清之后的任一轮 0 出现」。
5. **trace**：`context_insight` 步骤记录每条入选/落选原因（`in`/`below_confidence`/`scope_excluded`/`budget`/`over_limit`）与段字符数——回答「为什么这条认知在/不在 prompt 里」。
6. **Flag 门控**：`v2_reflection_enabled` OFF → 不查询、`state.insights` 保持默认空、无渲染段、无 trace 步骤——golden 字节级不变（tasks.md Regression 行）。

## 数据模型 / 接口变化

- 无新表、无迁移、无记忆写入。
- `ConversationState.insights: list[InsightSummary] = []`（新增可选字段，pydantic 默认值向后兼容）。
- 新接口：
  ```text
  reflection/lifecycle.py（注入视图）
    list_active_insights(user_id, character_id, min_confidence, scopes, limit) -> list[Insight]   # REF-001 交付，本 Task 消费
  context_builder.build 内部：_load_context_insights(user_id, trace) -> list[InsightSummary]
  ```
- settings 新增 3 个 `v2_reflection_*` 参数（见上表）。

## 核心处理流程

```text
装配期（每轮，Flag ON）：
  list_active_insights(active + 置信阈值 + scope + Freshness 排序 + max_items)
  → 记忆段字符实测 → insight 段预算 = 800 − 记忆段字符
  → 逐条取用（statement 截断）→ state.insights + trace(入选/落选)
渲染期：builder.build → 记忆段后追加【你确信的认知】（空则无段）
失效：REF-005 invalidated → 下一轮查询自然排除 → 0 出现
```

## 模块关系

- Reflection 只读接口 + 装配在编排层（context_builder/builder）——domain-boundaries：Reflection 被 Context 调用，装配权在编排层，Reflection 不直改 prompt。
- 与 MEM-006/MEM-011：复用 MEM-011 的分层装配与合并预算 800 贪心裁定，insight 段作为检索类第三成员参与裁定（冲突记录第 8 条）。
- 不接 Development（P3 DevPolicy 才是行为通道）；不写任何表。

## 异常与边界情况

- 查询失败/DB 异常 → 段为空、正常回答不报错（与记忆检索降级同款，tasks.md Error/Failure）。
- 无合格 Insight → 空段、无渲染消息（prompt 与 Flag OFF 逐字节一致）。
- 记忆段占满 800 → insight 段预算 0、全部落选（trace 记 budget）——记忆优先于认知（证据 > 结论）。
- Insight 被失效发生在「装配后、回答前」的窗口（单进程后台时序上 post_process 晚于装配，理论不出现；并发极端下）→ 本轮已注入不回撤，下一轮 0 出现（与 REF-005 时序口径一致）。
- statement 超长 → 截断 + 省略号（不做 LLM 压缩，tasks.md Non-Scope）。
- 注入质量风险（tasks.md Risk）→ 只取 top 置信（max_items=5 + 置信阈值双闸）；消融测试（有/无 insight 段的回答对比）进 E-CTX-01 验收。

## 测试要求

- Unit：过滤与排序（阈值/scope/max_items 表驱动）；预算裁定（记忆段占满/部分/为空三档）；statement 截断。
- Integration：端到端注入（高置信 active Insight 出现在最终 prompt 模板且预算内，tasks.md 验收）；invalidated 后下一轮装配 0 出现；prompt_snapshots 断言段位置与内容。
- Regression：Flag OFF 下 `builder.build` 输出与现状逐字节一致（prompt_snapshots 对比，V7.5 prompt 相关 checklist）。
- 消融：同场景有/无 insight 段的 golden 回答对比（人工评审口径，进 regression-checklist）。

## 验收标准

- 给定 confidence ≥ 阈值的 active Insight，当装配 Context，那么出现在 insight 段且预算内（tasks.md 原文）。
- 给定其被 invalidated，那么下一轮起 0 出现（tasks.md 原文口径 + REF-005 时序）。
- 给定记忆段已占满 800，那么 insight 段为空且 trace 可见 budget 落选。
- 给定 Flag OFF，那么 sections 与现状逐字节一致。

## Implementation Constraints

- 只读注入：不做行为调制（P3）、不做摘要压缩 LLM、禁止全量注入（阈值+scope+条数三重上限）；不写任何表。
- Flag OFF golden 字节级；装配权在编排层，Reflection 只提供只读查询。
- 不改 12000 总预算与 MEM-011 既有分段顺序（insight 段并入检索类裁定，其余段落不动）。
