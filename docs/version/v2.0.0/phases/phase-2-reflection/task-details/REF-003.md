# REF-003 Task Detail — 反思触发器（Core）

> 上游：[../tasks.md](../tasks.md) REF-003 ｜ [../architecture.md](../architecture.md) §2/§5 ｜ 依赖：REF-001, REF-002, P1 MEM-009

## Task 目标

实现 `reflection/triggers.py`：周期（每日低频）+ 事件（同主题 reinforce 计数达阈值）双触发，门槛前置（REF-002 `passes_gate` 在入队前判定），每用户每日 ≤1 次反思额度。证据不足直接跳过并记 `skipped`，0 LLM；合格才入队 `queued` 待 REF-004 执行。

## 背景 / 为什么需要

反思是「无 LLM 不做的事」，触发器必须保证绝大多数日子 0 调用，否则成本失控（risk.md R9 的前置防线）。三道闸门按序前置：**证据门槛（REF-002）→ 当日额度 → 入队**，任何一闸不过都不产生 LLM 调用。同时触发器是「为什么反思 / 为什么没反思」的唯一记录点（trace 口径），是 E-REF-03（无证据月反思 LLM 调用 = 0）的直接承载。

## 设计方案

1. **周期触发（每日低频）**：
   - 触发判定挂靠 MEM-009 job_worker 的周期 tick（`run_job_tick` 按 `v2_job_poll_interval` 轮询，容错模式对齐：异常记日志继续下一轮）；当本地时钟小时数 ≥ `v2_reflection_schedule_hour`（默认 4 点低峰）且「本用户在当前日桶尚未入队」时，对该用户执行一次触发判定。
   - 入队前门槛预检：调 REF-002 `aggregate_evidence_windows` + `passes_gate`；无合格窗口 → `reflection_runs` 写一行 `status=skipped`（trigger=scheduled，evidence_summary 记门槛失败原因），**0 LLM**（tasks.md：runs 记 skipped 的落点）。
   - 合格 → 额度检查（见设计 4）→ `enqueue_job("reflection_run", {user_id, character_id, trigger="scheduled"}, key)`；job payload 只存 id 与 trigger，**不存证据组**（REF-004 执行时重新聚合，同数据同分组幂等，且免大 payload 与证据过期问题）。
   - 每用户每日至多一条：`idempotency_key` 唯一约束天然拦截重复入队（`enqueue_job` 返回 False 即已入队/已执行）。
2. **事件触发（同主题 reinforce 计数达阈值）**：
   - 计数器：进程内 `{user_id: {topic_key: (count, last_event_at)}}`。topic_key 由 reinforce 的 memory_id 反查 content 后按 `same_topic` 归并到既有 topic 桶（新主题自立桶）。
   - 达 `v2_reflection_event_threshold`（默认 3 次同主题 reinforce）且距该主题上次事件触发 ≥ `v2_reflection_event_cooldown_hours`（默认 24h，tasks.md：计数器带冷却窗口）→ 走与周期相同的「门槛预检 → 额度 → 入队」路径，`trigger="event"`。
   - 计数器在事件触发成功或冷却判定后清零该主题桶（防重复累积）。
   - **重启语义**：计数器为进程内存态，重启即丢（架构明确允许 P1–P4 后台内存态；事件触发只是「提前于每日调度」的加速器，每日调度兜底，丢计数不丢能力）。
3. **reinforce 信号订阅方式（关键裁决，登记于 README 冲突记录第 2 条）**：
   - 现状：`record_reinforce` 只进内存缓冲；MEM-009 交付后 `run_job_tick` 每轮先 `flush_reinforce_buffer()`（job_worker 调用点不读返回值），原「检索路径 reinforce 永不落库」缺口已闭合。
   - 本 Task 的订阅点 = `post_process._run_memory_evaluate_v2` 尾部追加调用：`flushed = flush_reinforce_buffer(trace=ctx.trace)` 后 `triggers.observe_reinforce(ctx.user_id, flushed_ids, trace=ctx.trace)`。MEM-005 的函数本体、缓冲语义、状态机**零修改**（tasks.md Non-Scope），改动仅发生在编排层接线。
   - **双 flush 点张力**：job_worker 周期 tick 与 post_process 接线都会 flush（幂等，先到先清）。若某批 id 被 tick 抢先 flush，post_process 的 flush 返回空列表 → 该批不进事件计数 → 事件触发略欠灵敏，**由每日周期调度兜底**（事件触发只是加速器，见设计 2 重启语义）。可接受，不做跨模块回调改造。
   - flush 返回值当前为 int（updated 条数），不含 id 列表 → 本 Task 为 `flush_reinforce_buffer` 增加**返回值从 int 到 `list[str]`（本次落库的 memory_id）**的最小兼容扩展：`int` 是 `list` 长度，现有调用方（commands.py 与 job_worker 均不读返回值）与测试（`== 1` 断言改 `len(...) == 1`）同步调整。该改动属 P1 接口微调，登记于冲突记录第 2 条，不改 MEM-005 逻辑语义。
4. **额度控制**：每用户每日 LLM 反思 ≤1 次（architecture §5，事件与周期共用额度）。判定 = 查 `reflection_runs`：当日桶（created_at 落当日）已存在 `status ∈ {queued, running, done}` 的 run → 触发降级为 skip（trace 记 `quota_exhausted`，**不写新 run 行**——skipped 行只用于「门槛拦截」，额度拦截不产新行避免行膨胀）；`skipped/failed` 不占额度（failed 可由下一触发源重试）。
5. **runs 状态机（本 Task 负责的部分）**：`queued→running→done|failed` 由 REF-004 驱动；本 Task 写入 `queued`（入队成功）与 `skipped`（门槛拦截）两种。`queued` 行与 background_jobs 行通过 run.id（payload 内引用）关联。

## 数据模型 / 接口变化

- 无新表；写 `reflection_runs`（queued/skipped）与 `background_jobs`（job_type="reflection_run"）。
- `memory2/lifecycle.py` `flush_reinforce_buffer` 返回值 `int → list[str]`（唯一接口微调，见设计 3；冲突记录第 2 条）。
- 新接口：
  ```text
  reflection/triggers.py
    run_reflection_trigger_loop()                       # 周期触发入口：由 job_worker 周期 tick 挂靠（Flag OFF 空转）
    trigger_for_user(user_id, character_id, trigger, trace) -> str   # "queued"|"skipped"|"quota"|"off"
    observe_reinforce(user_id, memory_ids, trace) -> None            # 事件计数入口（post_process 喂入）
    reset_trigger_state()                               # 测试与运维复位
  ```
- settings 新增 3 个 `v2_reflection_*` 参数（见上表）。

## 核心处理流程

```text
周期路：job_worker 周期 tick → 到点未入队 → aggregate+passes_gate
        → [不足 → runs 记 skipped + trace，0 LLM | 合格 → 额度检查 → enqueue_job(queued)]
执行消费：job_worker 认领 reflection_run job → REF-004 execute_run
事件路：post_process evaluate 步骤尾部 → flush_reinforce_buffer → observe_reinforce
        → 同主题计数+冷却 → 达阈值 → 同上（门槛预检→额度→入队，trigger=event）
两路共用：门槛在入队前；当日 queued/running/done 存在 → 不入队不产行
```

## 模块关系

- Reflection 域内：写 `reflection_runs`、调 `background_job_repository`、调用 REF-002 门槛；被 REF-004 消费（queued run）。
- 跨域接线：`post_process.py` 追加 flush+observe 调用（编排层，方向为编排层调 Reflection，符合 domain-boundaries 单向约束）；执行消费经 `memory2/job_worker.py` `register_job_type` 注册（Reflection handler 注册进基础设施注册表，不反向依赖）。
- **不修改** MEM-005 的 reinforce 逻辑与状态机（tasks.md Non-Scope）；不修改 MEM-009 范围的 job 执行协议。

## 异常与边界情况

- 触发判定异常 → 捕获记日志，下一 tick 重试；某日整体漏跑（进程未活）→ 日桶 key 随次日推进自然恢复，无积压概念（每日一条是上限不是义务）。
- 事件风暴（单日大量 reinforce）→ 计数器带冷却窗口 + 当日额度兜底，最坏情况 = 当日 1 次 LLM 反思（tasks.md 验收）。
- `enqueue_job` DB 异常 → 触发降级记 trace，下轮重试（幂等键保证不重复）。
- 聚合异常（REF-002 抛出）→ 按「证据不足」处理记 skipped（原因=aggregate_error），0 LLM。
- Flag OFF → 循环不注册、`observe_reinforce` 直接返回（post_process 接线行以 Flag 守卫包裹，双保险）。
- 时钟：一律注入 `now`（测试可控制），循环内用本地时间对齐日桶。

## 测试要求

- Unit：额度判定表驱动（queued/running/done 占额，skipped/failed 不占）；事件计数与冷却窗口；日桶 key 生成。
- Integration：无证据日调度触发 → 0 LLM 且 runs 记 skipped（tasks.md 验收）；合格证据日 → 恰好 1 条 queued job 且重复触发不重复入队；事件路径端到端（3 次 reinforce → queued）。
- FailureInjection：事件风暴（同主题高频 reinforce → 仅首次入队）；`enqueue_job` 抛错 → 降级不崩溃。
- Regression：Flag OFF 时 `main.py` 不新增循环、post_process 接线行为为空、golden 字节级。

## 验收标准

- 给定无证据日，当调度触发，那么 0 LLM 调用且 `reflection_runs` 记 skipped（tasks.md 原文）。
- 给定证据爆发日 + 事件触发，那么当日 LLM 反思最多 1 次（周期/事件/重复事件叠加后仍 ≤1）。
- 给定同一日两次触发源都通过门槛，那么 `background_jobs` 中 `reflection_run` 对该用户日桶仅一行。
- 给定 Flag OFF，那么无循环、无入队、无 runs 行为。

## Implementation Constraints

- 不做反思执行（REF-004）；不修改 MEM-005 reinforce 逻辑（只订阅信号 + 编排层接线）；门槛检查必须在入队前（架构 §5）。
- 每用户每日 ≤1 次；事件与周期共用当日额度；禁止前台同步路径触发反思（仅后台循环与 post_process 尾部）。
- job payload 不携带证据内容（执行时重聚合）；不引外部队列；不修改 MEM-009 范围的执行协议（执行器落地前，queued job 的消费由 REF-004 的执行入口承担，见 REF-004 Detail）。
