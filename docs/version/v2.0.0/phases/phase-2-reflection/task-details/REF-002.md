# REF-002 Task Detail — Evidence Window 聚合（Core）

> 上游：[../tasks.md](../tasks.md) REF-002 ｜ [../architecture.md](../architecture.md) §2 ｜ 依赖：P1 MEM-006（检索/embedding 能力）、REF-001

## Task 目标

实现 `reflection/evidence.py`：从 memories（active、非 hypothetical）聚合出合格的证据组——按主题聚类分组、窗口过滤、组统计、门槛前置判定，输出 Evidence 候选组（组统计 + 成员引用）。纯规则 0 LLM；单条记忆不成组；不产出 Insight。

## 背景 / 为什么需要

反思质量的上限由证据质量决定。v1 无任何「经历→认知」通道；若 Reflection 直接把零星检索结果喂给 LLM，就是幻觉温床（README §9 之所以把 P2 排在 P1 之后：没有 P1 的语义召回与生命周期，反思只能拿关键词命中凑证据）。Evidence Window 把「用了哪些记忆、几条、跨度多久、是否互相印证」变成可计算的门槛判定，**在 LLM 调用之前**拦截不合格场景（E-REF-03：噪声场景 0 Insight 0 LLM）。

## 设计方案

1. **主入口**：`aggregate_evidence_windows(user_id, character_id, now, trace) -> list[EvidenceWindow]`（纯函数语义：同数据同分组，幂等）。
2. **流程四步**：
   1. **候选池**：`list_active` → 过滤 `visibility == hypothetical`、`content` 非空、`superseded_by IS NULL`（与 retriever `_candidate_pool` 同口径）；窗口过滤：`coalesce(last_reinforced_at, created_at) >= now - window_days`（近期被强化或新近创建的记忆才构成「当前认知的证据」）。
   2. **主题聚类（贪心单遍）**：按 `salience` 降序取种子；对每条记忆与既有簇判定归属——`cosine(embedding, 簇代表向量) >= cluster_cosine`（语义路）**或** `same_topic(content, 簇代表 content)`（关键词路，覆盖 embedding NULL 行）；归属则并入（簇代表向量取成员均值，代表 content 取最长成员），否则自立新簇。池规模 ≤ 数千条，O(n·k) 可控；单归属（先到先得），无跨簇成员。
   3. **组统计**：`member_count`、`span_hours`（组内最早/最晚 created_at 差）、`distinct_source_refs`（不同 `source_ref` 的 id 数——见口径裁决）、`source_type_mix`（`memories.source` 类型分布，仅统计不作门槛）、`coherence`（组内两两相似度均值：向量对用 cosine、缺向量对用 LCS 归一相似度，样本对抽样上限 20 对防 O(n²) 膨胀）、`member_weights`（每成员 weight = salience × recency 半衰归一，供 REF-004 confidence 折算）。
   4. **门槛前置判定**（与 REF-003 共用同一函数 `passes_gate(window, settings) -> tuple[bool, list[str]]`）：
      - 数量：`distinct_source_refs >= v2_reflection_min_evidence`（默认 3）；
      - 跨度：`span_hours >= v2_reflection_min_span_hours`（默认 24h——5 条挤在同一天的证据不构成「持续模式」）；
      - 印证度：`coherence >= v2_reflection_min_coherence`。
3. **「独立来源」口径裁决**（关键，登记于 README 冲突记录第 7 条）：README 防幻觉三闸「默认 ≥3 独立来源」落地为 **≥3 个不同 `source_ref`**（不同原始消息/事件），而非 3 个不同 `memories.source` 类型——核心验收场景「10 天内 5 次说累」的记忆全部经 turn_analysis 抽取（source 均为 user_stated），若按 source 类型判独立则该场景永远无法达标、与 E-REF-02 自相矛盾。`source_type_mix` 保留为统计信号与 REF-004 折算输入（全部 ai_inferred 的组降低 confidence 上限）。
4. **单条不成组**：`member_count < min_evidence` 的簇不产出窗口（成员不单独成组、也不并入其他簇），trace 记录落选原因。
5. **trace**：`reflection_evidence` 步骤记录：候选池大小、簇数、每簇统计摘要、门槛判定结果与失败原因列表（回答「用了哪些 Memory/几条/跨度多久/为什么没成组」）。

## 核心处理流程

```text
list_active 池 → hypothetical/空内容/窗口过滤 → 贪心聚类（语义邻域 ∪ same_topic）
 → 组统计（数量/跨度/独立来源/印证度/成员 weight） → passes_gate
 → [合格 → EvidenceWindow 列表 | 不合格 → 落选 + trace] → trace(池/簇/门槛明细)
```

## 模块关系

- **只读 memories，不写任何域**（domain-boundaries：Reflection 读 Memory；本 Task 连本域表也不写）。
- 被 REF-003（触发器门槛预检复用 `passes_gate` + `aggregate_evidence_windows`）与 REF-004（执行器取证据组）调用。
- 不 import `memory2` 私有函数（`_parse_vector`/`_row_facts` 为私有，本模块同构复刻，公共纯函数仅 `same_topic`）。
- 与 MEM-006 retriever 的关系：检索面向「本轮对话相关」，Evidence Window 面向「主题聚类聚合」，二者共用底层字段但场景不同，互不调用。

## 异常与边界情况

- 聚类异常（单条向量解析失败等）→ 跳过该行记 trace，不中断整批；整体异常 → 返回空列表 + trace error（tasks.md：聚类异常→返回空组+trace，调用方按「无证据」处理，0 LLM）。
- embedding 全 NULL（迁移期/子闸关闭）→ 纯关键词路聚类照常工作，trace 标注 `degraded=keyword_only`。
- 窗口边缘记忆（`last_reinforced_at` 刚被刷新的陈旧记忆）→ 按口径纳入（被近期强化即构成当前认知的一部分），trace 可见。
- 同一记忆高度泛化（与多个簇都 same_topic）→ 贪心单归属，归属相似度最高的簇；trace 不必逐条记录归属竞争。
- 空池 → 返回空列表（不报错），REF-003 据此记 skipped。

## 测试要求

- Unit：贪心聚类（语义邻域命中/关键词命中/混合/embedding NULL 降级）、组统计数值、`passes_gate` 三闸表驱动（数量/跨度/印证度各闸独立失败）。
- Integration：构造「10 天内 5 条同主题记忆（不同 source_ref）」→ 聚为一组且跨度/来源合规（对应 tasks.md 验收）；孤立单条记忆 → 不成组；hypothetical/窗口外记忆被排除。
- 幂等：同数据两次聚合结果逐字段相等。
- 阈值边界：coherence 恰在阈值上/下各一例。

## 验收标准

- 给定 10 天内 5 条同主题记忆，当聚合，那么聚为一组且跨度/来源合规（tasks.md 原文）。
- 给定孤立单条记忆，那么不成组、不产出 EvidenceWindow。
- 给定 5 条同主题但全部产生于同 1 小时内的记忆，那么因跨度门槛落选（gate_reasons 含 span）。
- 给定池内混入 hypothetical 记忆，那么该记忆不出现在任何组内。

## Implementation Constraints

- 纯规则 0 LLM；不产出 Insight（产出属 REF-004）；单条记忆不得成组（最少证据数是硬闸，README 明确禁止）。
- 只读 memories；不写本域或他域任何表；阈值全部进 settings 禁止硬编码。
- 不修改 `memory2/*` 任何文件；不提前设计 P3 的 Evidence 扩展（如 ActionRecord/WorldEvent 直接进入证据池——经 P1 ingest 沉淀为 memories 后自然进入，无需新通道）。
