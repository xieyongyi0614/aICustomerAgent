# DEV-002 Task Detail — DevPolicy 编译器

> 上游：[../tasks.md](../tasks.md) DEV-002 ｜ [../architecture.md](../architecture.md) §3 规则表 ｜ 依赖：DEV-001, P2 REF-004（启用）

## Task 目标

实现 Insight→行为参数调制的**确定性纯函数编译器**（0 LLM）：三类 Insight 按规则表折算为调制提案 → 强度封顶 → 同 key 仲裁 → 单事务写 `development_state` + `development_changes`（DEV-001 服务）。输出「叠加层」参数供 DEV-003 消费；全程 `development_compile` trace，让「行为为什么变了」可答。

## 背景 / 为什么需要

任务书 §十七：Development 必须与 Memory/Reflection 分层——用 LLM 做调制则不可重放、不可归因、角色漂移不可控。P2 交付的 Insight（`insights` 行，type/confidence 已由代码校准）目前只有 REF-007 的 Context 注入一个消费面；本 Task 把「怎么看」变成「因此变成什么样」的**确定性参数**，是 §十成长闭环（Insight→调制→行为）的中枢环节。

## 设计方案

1. **「新 active Insight 事件」的落地**（tasks.md Runtime Flow 首环）。P2 现状只有失效事件，无创建事件（README 核对记录 2）。最小扩展：`reflection/lifecycle.py` 镜像失效钩子新增创建钩子；`reflector._persist` commit 成功后以创建的 insight 摘要列表（insight_id/type/scope/confidence/statement）广播。P3 编排层（`main.py` lifespan，`v2_development_enabled` 门控）注册监听器 → 回调内 enqueue `development_compile` job（payload={insight_id}，幂等键 `dev_compile:{insight_id}`，天然重放/重启安全）。Reflection 不 import Development（依赖单向，经编排层注册，与 REF-005 事件钩子同一裁决）。
2. **纯函数编译**（`policy.py`）：`compile_insight(insight, settings) -> list[ModulationProposal]`。ModulationProposal={key, kind, value(dict), strength}。strength = insight.confidence 直接映射（**不设计叠加累积公式**——E-DEV-01「同主题 10 条强化仍封顶」由「幅度=strength×预设最大幅度」天然满足，且时间序重放确定性成立；README 核对记录 6）。规则表全部 settings JSON 驱动（离线校准面）：
   - preference → `response_style.length`（value={"max_tokens_delta": 负值, "length_hint"}；幅度=floor(strength×`v2_development_preference_max_token_delta`)）、`response_style.tone`（关键词规则表 `v2_development_preference_tone_rules_json` 命中→固定语气指令文本；未命中→无提案）。
   - belief → `behavior.care_topics`（关键词规则表命中→关心话题列表 + care 提示语）、`behavior.habit_candidates`（**只置候选**：settings 模板表产出 `HabitRule` 形状候选 id（`dev_habit_*` 前缀），不写 HABIT_LIST/HABIT_EXTRA_JSON——生效集资产零改动，候选合入属 DEV-003 读取侧）。
   - pattern → `goal.user_care.weight`（value={"tier_delta": ±有界值}）、`autonomy.time_preference`（value={"late_night_bias": ...}——**只编译落库，运行时接线属 P5 Life Loop**，架构 §2 数据流无 D→Autonomy 箭头，README 核对记录 3）。
   - 规则未命中 → 返回空提案列表 + trace `reason=no_rule`（不写 state，job 正常 done）。
3. **仲裁**：`apply_proposals(user_id, proposals, trace)` 逐提案调用 DEV-001 `upsert_modulation`——比较器 = strength 降序、同 strength 取 insight created_at 新者（architecture §3「confidence 高者生效；同 confidence 取新者」）；落败方由 upsert 写 superseded 留痕（败者=state 行语义，非 insight 行——Insight 层冲突由 REF-005 supersede 通道负责，两机制正交）。
4. **job handler**：`run_compile_job()`（handler 签名对齐 `_JOB_HANDLERS`：无参、内部扫描 payload）→ 取 insight 行（status 非 active → trace `skip_inactive` 并 done，终态不编译）→ compile → apply → trace。编译异常→该 job 走 MEM-009 退避重试，达上限死信 failed+last_error；**不阻塞其他 insight 的编译任务**（job 之间天然隔离）。
5. **幂等**：同 insight 重放 = 幂等键拦截 + upsert 仲裁对同输入输出恒定（已胜出→条件 UPDATE no-op，不产生新 changes 行）；同数据重放输出逐字节一致（E-DEV-01）。

## 数据模型 / 接口变化

- 无新表；写 `development_state/changes`（经 DEV-001 服务）。
- `app/models/development.py` 追加 `ModulationProposal` BaseModel。
- settings 新增：`v2_development_enabled`（DEV-001 已定义）、`v2_development_preference_max_token_delta: int`（如 200）、`v2_development_preference_tone_rules_json`、`v2_development_belief_topic_rules_json`、`v2_development_belief_habit_templates_json`、`v2_development_pattern_goal_tier_delta_max: float`（如 0.5，不突破 v6 tier 语义）、`v2_development_compile_llm_budget: 0`（声明性常量，编译路径禁止 LLM）。
- `reflection/lifecycle.py` 追加创建事件钩子三函数（对外新增 API，P2 既有语义零改动）。

## 核心处理流程

```text
REF-004 _persist commit → 创建事件钩子（编排层监听）
  → enqueue dev_compile:{insight_id}（MEM-009 协议）
  → job worker 认领 → 取 insight（非 active 跳过）
  → compile_insight（规则表匹配 → 强度折算 → 封顶）→ 空提案则 done
  → apply_proposals（同 key 仲裁 → upsert_modulation 单事务写 state+changes）
  → development_compile trace（规则命中/折算/仲裁结果）
```

## 模块关系

- Development → Reflection：只读 insights + 经编排层注册事件回调（不 import reflector；钩子 API 在 lifecycle）。
- Development → Memory：零接触（禁止直读 memories，必须经 Insight——domain-boundaries §3 单向约束 2）。
- Behavior/Goal/Autonomy：本 Task 零接触（调制参数只是 development_state 行，消费属 DEV-003 / P5）。

## 异常与边界情况

- 编译时 insight 已被失效/替代（事件与消费竞态）→ job 内复查 status，非 active 跳过（trace skip）。
- 规则表 JSON 解析失败 → 启动 fail-fast（settings 加载期抛错，模式同 `habit_extra_json` 解析）。
- 矛盾 Insight 并发编译（两个 job 同时仲裁同 key）→ per-user 写锁 + DEV-001 条件 UPDATE/部分唯一索引兜底，败者 superseded 留痕。
- LLM Usage: NONE——编译路径任何分支不调 LLM；`evaluation_judge` 采样属 DEV-005 离线面，与本 Task 无关。

## 测试要求

- Unit：规则表驱动（三类 Insight × 命中/未命中/部分命中）；封顶（strength=1.0 时幅度=预设最大幅度、10 条同主题编译幅度不超封顶）；仲裁（高胜低/破平取新/落败留痕 superseded）；空提案。
- Integration：REF-004 产 Insight（ScriptedLLM stub，模式同 tests/v2/test_ref006）→ 事件 → 入队 → 编译落库 → state/changes/trace 全链；幂等（同 insight 重放：行数、value、changes 计数不变）；时间序重放与在线结果一致。
- FailureInjection：DB 断连重试、JSON 规则表损坏 fail-fast、矛盾 Insight 并发。
- 回归：Flag OFF（`v2_development_enabled=false`）时事件不注册、job 不执行、`reflection` 既有测试全绿（创建事件钩子在 P2 语义下无注册方零行为）。

## 验收标准

- 给定同一 Insight 重复编译，那么 state/changes 输出逐字节一致（幂等）。
- 给定矛盾 Insight 对（同 key 不同结论），那么只有一个 active，败者 superseded 可溯（changes 留痕）。
- 给定同主题 10 条强化 Insight，那么调制幅度仍封顶（≤ strength×预设最大幅度）。
- 给定 Flag OFF，那么无任何 development 写入且 P1/P2 golden 不变。

## Implementation Constraints

- 纯函数 0 LLM；不改 BehaviorEngine/V8.5/V5/v6 goal 公式本体（version-boundary Preserve）；不新增 habit（只置候选）；不直读 memories；不接线任何行为消费方（DEV-003）；AutonomyPolicy 参数只编译落库不做运行时接线（P5）。
- 对 `reflector.py` 的改动限于 commit 后一行广播调用；不改 REF-004 事务、校准与三闸逻辑。
