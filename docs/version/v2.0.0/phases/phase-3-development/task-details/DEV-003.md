# DEV-003 Task Detail — 行为接线

> 上游：[../tasks.md](../tasks.md) DEV-003 ｜ [../architecture.md](../architecture.md) §2 数据流 ｜ 依赖：DEV-002

## Task 目标

让调制参数被运行时**真实消费**：行为域在读取时叠加 development 覆盖层（叠加层空 = v1 字节级一致），覆盖 BehaviorEngine / ResponseStyle 参数 / goal_service 权重三个消费面，变化全程 `development_apply` trace（before/after + 溯源 insight_id）。不接线则 Development 只是表数据——「角色因经历而改变」必须体现在行为参数上。

## 背景 / 为什么需要

DEV-002 产出后 `development_state` 仍是死数据。P3 完成标准 1 要求「Insight 入库后，对应行为参数变化在 trace 中可见」。接线原则：**只加读取层**——静态资产（`BEHAVIOR_POLICY` 等 character/asuna 文件）与 V6.5/V5/V8.5 公式本体零改动（version-boundary §1 Preserve / Extend 裁决），行为域只读消费、不回调 Development（domain-boundaries §1「被谁调用」列）。

## 设计方案

1. **叠加层读取**：`services/development/aggregate.py` 追加 `read_overlay(user_id) -> DevelopmentOverlay | None`（Flag OFF 或无 active 行 → None）。`DevelopmentOverlay`（`app/models/development.py`）聚合：`style: DevelopmentStyleParams | None`（length/tone，含每项 source_insight_id）、`care_hint: str | None`、`habit_candidates: list[HabitRule 形状候选]`、`goal_weights: dict[str, float]`、`modulation_summary: str`（≤100 字符摘要）。读取失败 → None + log（fail-safe 到 v1 行为，tasks.md Error/Failure 口径）。
2. **三个消费点**（均为「读取时叠加」，不改静态资产、不写行为域任何表）：
   - **BehaviorEngine**：`resolve(..., development_overlay=None)`——care_hint 挂到 directive；`match_habits(strategy, extra_candidates=overlay.habit_candidates)` 合入候选后仍走既有 domain 过滤 + `HABIT_MAX_COUNT=2` + 同向去重（**不新增 habit**：候选永不落 HABIT_LIST/HABIT_EXTRA_JSON，重启/回退即消失）。
   - **ResponseStyle**：代码现状无独立 ResponseStyleController（README 核对记录 1）——长度落地为按轮 `max_tokens = clamp(base+overlay.style.max_tokens_delta)`（answer_chain 读取处注入）；语气落地为 directive.style 提示行由 `prompts/behavior.py` 渲染（如「回复更简练」）。两处都是 Extend 点，不新增模块、不改 v1 公式。
   - **goal_service**：`_effective_tier` 命中 `goal.user_care.weight` 的目标加 tier_delta（有界），排序结果变化即「权重调制」；selection reason 附加「development 调制」标记，goal_selection trace 可见。
3. **Context 调制摘要段**：[architecture.md](../architecture.md) §2 数据流含 D→CTX 箭头，[context-architecture.md](../../../architecture/context-architecture.md) §1 将该段划给 DEV-003（P2 层 ≤100 字符）。落地：context_builder 在 Flag ON 且 overlay 非空时渲染 `【你因经历而改变】{modulation_summary}` 段（内容为调制结论摘要而非 Insight 原文——与 REF-007 insight 段内容正交不重复）；段缺席=字符串不出现（golden 零漂移）。
4. **trace**：每轮 overlay 非空时 `chat_pipeline` 在 behavior_engine 步骤后 `trace.record("development_apply", ..., key/before/after/source_insight_id)`（before=未叠加参数、after=叠加后参数，逐 key 记录）。
5. **Flag 门控**：唯一开关 `v2_development_enabled`；OFF → `read_overlay` 恒 None → 全链字节级 v1（含 max_tokens、prompt sections、goal 排序）。

## 数据模型 / 接口变化

- `app/models/development.py` 追加 `DevelopmentOverlay` / `DevelopmentStyleParams`。
- `behavior_engine.resolve` / `goal_service.select` / `match_habits` 追加**可选**尾参（全部默认 None/空 → 既有调用方零改动）。
- `BehaviorDirective` 追加可选字段；`prompts/behavior.py` 追加可选渲染分支。
- 无新表、无新 settings 之外的配置（`v2_development_answer_min_tokens` 一项新增）。

## 核心处理流程

```text
chat_pipeline 装配期：read_overlay（Flag 门控，读失败→None）
  → behavior_engine.resolve(overlay)：strategy/habits/care 合成（追加式）
  → goal_service.select(development_weights)：tier 有界调制
  → answer_chain：max_tokens 按 overlay 调整
  → prompt 渲染：development 风格行 / care 提示 / 调制摘要段（非空才出现）
  → trace：development_apply（key/before/after/insight_id）
```

## 模块关系

- Development 只提供只读参数（`read_overlay`）；行为域被调用、不回调 Development（domain-boundaries §3 单向约束）。
- 编排层（chat_pipeline）负责读取与透传——行为域函数保持可独立测试的纯函数性（与 `relationship_ctx` 同款注入风格）。
- Context 调制摘要段经 context_builder 装配（禁止绕过 Context Architect 直改 prompt）。

## 异常与边界情况

- overlay 读取失败/超时 → None → v1 行为（fail-safe），trace 记 error。
- habit 候选与既有 habit id 冲突 → 候选丢弃 + trace（不抛错）。
- tier_delta 使排序与 v6 修正规则冲突 → 仍按「叠加在 v6 结果之上」语义（development > 基线），delta 封顶防越级；v6 公式本体未动。
- max_tokens 调整后低于模型最小可用值 → clamp 下限保护。
- Flag OFF 且 DB 中已有 active 数据 → 一律不读不渲染（冻结，不是清空）。

## 测试要求

- Unit：叠加合并（style/habit 候选/goal 权重逐项）；overlay=None 逐字段等价（字节级）；候选去重与 domain 过滤；tier_delta 封顶。
- Integration：端到端——注入「用户偏好简短回复」Insight → 编译 → 回答轮 max_tokens 下降 + 风格行渲染 + `development_apply` trace 含 before/after/insight_id；「用户持续工作压力」→ care 提示 + 深夜关怀 habit 候选进入 match_habits 结果。
- Regression：**空数据 golden**（无 development 数据全量 pytest 输出与 v1 基线零差异）；V6.5 Behavior checklist + V6 Goal checklist（本目录 regression-checklist）。
- Performance：read_overlay 每轮一次、active 行索引命中（<5ms）；如需缓存可预留 `v2_development_overlay_cache_ttl`（默认 0=关），但**该设置尚未在代码中实现**，仅为文档留位，不提前实现。

## 验收标准

- 给定「用户偏好简短回复」Insight 生效，当回答生成，那么 ResponseStyle 长度参数下降且 trace 可见 before/after + insight_id。
- 给定 Flag OFF，那么行为与 v1 字节级一致（golden 断言）。
- 给定 development 读取失败，那么回退基线参数且无异常冒泡。

## Implementation Constraints

- 只加读取层；golden 行为在无 development 数据时不变；不写行为域任何表；不改 `character/asuna/*` 静态资产与任何数值公式本体；不做 AutonomyPolicy 接线（P5）；habit 只进候选不进生效集资产。
