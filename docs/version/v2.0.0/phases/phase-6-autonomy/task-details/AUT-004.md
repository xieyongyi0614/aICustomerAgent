# AUT-004 Task Detail — Goal 冲突与生命周期管理（Integration）

> 上游：[../tasks.md](../tasks.md) AUT-004 ｜ [../../../architecture/domain-boundaries.md](../../../architecture/domain-boundaries.md) §1 Goal 行 ｜ [../../../architecture/character-runtime.md](../../../architecture/character-runtime.md) §4 不变量 2 ｜ 依赖：AUT-001、P3 DEV-003

## Task 目标

把任务书 §二十三要求的**全部六语义**在 Goal 域落地为确定性裁决器——Priority / Conflict / Persistence / Failure / Completion / Abandonment：

```text
Priority     显式优先级 + Development/Relationship 调制（只读参数）
Conflict     同域冲突仲裁：高优先级 active，另一 suspended 留痕（不删除）
Persistence  long_term 跨会话存续：只有显式完成/放弃才终结
Failure      （AUT-003 已交付 failed 终态语义）本 Task 收口状态机全景
Completion   观察确认达成 → completed（语义在 AUT-003 判定，终态收口在此）
Abandonment  长期无进展 + 低相关 → abandoned（confidence 判定 + trace，不静默消失）
```

具体交付三件事：**仲裁器**（纯函数裁决 + 应用器落库）、**goal 状态机全景**（转换表守卫，非法转换拒绝）、**abandonment 检查**（规则置信计算，保守阈值）。0 LLM（tasks.md：abandonment 置信为规则计算）。

## 背景 / 为什么需要

- **缺冲突仲裁则多目标互相打架**：AUT-002 供给装配会随 Development/Pattern 演化持续创建层级 goal——同域两个 active goal（如 personal 域「成为更博学的人」与「养成规律作息」）同时驱动 Sub-Goal 执行时，周期预算与用户注意力被摊薄且无裁决依据；v1 的 tier 选择只覆盖轮内动机，层级 goal 的并存策略是空白；
- **缺 abandonment 则僵尸目标永久占预算**：长期无进展的 goal 若无退出机制，将永远出现在仲裁集合里（工作发现第四来源持续命中 → 永远不 Idle）——这是 §二十二成本铁律在 Goal 域的漏洞；
- **六语义不全则 Goal Consistency 不可测**：E-AUT-03 门槛「目标不无故消失/翻转」的前提是每种离开 active 的路径都有命名与留痕——suspended/abandoned/failed/completed 各自可溯，才谈得上「不无故」。

v2 裁决对齐：domain-boundaries §1 Goal 行「职责=目标层级、优先级、生命周期」——本 Task 就是生命周期语义的交付位；README §核心能力 2 的六语义表是本 Task 的验收契约原文。

## 设计方案

1. **仲裁触发与节流**：两类触发——「目标集合变更」（创建/suspended 复活/终态事件后，goal_advance 步骤内同步仲裁该用户）与「周期兜底」（`v2_autonomy_arbitration_interval_minutes` 节流的低频全量仲裁，捕获漂移）。同输入同输出（幂等，tasks.md 口径）：仲裁是纯函数，重复仲裁无新副作用时零写入。

2. **Priority 计算（显式优先级 + 调制，全只读）**：

   ```text
   score = priority(1-5)                          显式基准（创建时给定）
         + layer 调制（long_term +v2_autonomy_priority_layer_weight_long——长期追求让位原则的反向：
                      长期目标不被短期目标永久压制，同分时长期优先）
         + Development 调制（overlay.goal_weights.get(domain, 0) × 有界系数——复用 P3 已产出的
                      调制字典；P3 规则表无 domain 键时该项为 0，零 DEV 代码改动）
         + Relationship 调制（domain=relationship 时：tension 越限 → 修复类加分；
                      conflict_status 非 none → 全域 goal 降权——冲突期克制沿用 V8.5 R1 语义）
   ```

   score 是排序值不是状态：只用于冲突裁决与执行排序，不落库（trace 记录计算明细——优先级来源可答）。

3. **Conflict 裁决（同域互斥 + 级联）**：

   ```text
   冲突组定义：同 (layer, domain) 的顶层 active goal（parent NULL）≥ 2 个
     → 组内按 score 排序：第一名保持 active，其余 suspended（arbitration_state 留痕
       {conflict_with, score_basis, decided_at}，tasks.md「另一 suspended 留痕」）
   级联：父 goal suspended → 其子 short_term goal 级联 suspended（同理 active 复活）
   复活：组内第一名终态（completed/failed/abandoned）→ suspended 第二名自动复活 active
        （arbitration_state 留痕 revived_from_conflict）
   ```
   跨域不判冲突（无共同资源裁决依据，登记见冲突登记 GAP-AUT-05）；仲裁不删除行（tasks.md Non-Scope）。

4. **Abandonment（置信判定，保守阈值）**：

   ```text
   候选：layer=long_term 且 active 且（无进展天数 ≥ v2_autonomy_abandon_min_progress_days(14)）
     无进展 = goal_plans sub_goals 状态零变化 ∧ goal.updated_at 未动（窗口内）
   低相关信号（规则可计算，0 LLM）：
     a) goal 描述关键词在近 14 天 salient 记忆（list_top_salience）零命中
     b) 关联执行窗内零 action 记录（该 plan 的 capability 无任何尝试）
   confidence = f(无进展天数, 低相关信号数)   归一化到 [0,1]，纯规则
   裁决：confidence ≥ 0.6（两信号同时成立才可达）→ abandoned；单信号 → 保持 active + trace
   ```
   保守性设计：阈值 settings 化 + 双信号门槛 + 全程 trace（「为什么这个目标放弃」可答，tasks.md Observability）+ **用户对话中可自然可见**（验收口径：abandoned 后该 goal 的行动面消失、不再占工作发现——行为变化可感；状态在 trace/debug 面可溯；不做对话播报，见验收标准注）。

5. **状态机全景（转换表唯一权威）**：

   ```text
   GOAL_TRANSITIONS（v1 4 值 + AUT-003 failed + 本 Task suspended/abandoned）：
     active     → completed | failed | abandoned | suspended
     suspended  → active（复活）| abandoned
     active     → expired | cancelled        （v1 既有，仅 layer=NULL 行——层级行不开放，
                                               层级 goal 的退出只有显式完成/放弃/失败，
                                               tasks.md Persistence 语义）
     completed | failed | abandoned | expired | cancelled → （终态，禁止迁出）
   非法转换 → 拒绝（ValueError + trace）——「目标不无故翻转」的机制保障（E-AUT-03）
   ```
   `set_status` 是唯一状态变更入口（finish_goal/expire/cancel 内部收口到它），v1 调用点行为不变（转换表对 v1 路径的允许集与现状一致）。

6. **不变量 2 落地（Goal 变更有 decision_records）**：每次 suspended/abandoned/revived 转换写一条 `DecisionRecord(kind=GOAL_LIFECYCLE, decision=目标态, reason=裁决摘要, input_snapshot={goal_id, score 明细, 冲突对方})`——与 PROACTIVE_AUTONOMY 决策记录同表同协议（observability.on_decision）。「为什么这个目标暂停/放弃」双通道可答（trace + decision_records）。

7. **周期接线**：goal_advance 步骤内序扩展为「仲裁 → 封顶检查 → 观察 → 调整 → 执行」（AUT-003 流程前插仲裁段）；abandonment 检查按仲裁节流窗口执行（非每周期——纯 SQL 可判定的候选扫描 + 命中才做置信计算）。工作发现不受 suspended 影响（suspended goal 的 plan 不进 has_goal_work 判定——挂起即不追求，Idle 口径自然收敛）。

## 数据模型 / 状态变化

- `character_goals`（迁移 0032）：+`arbitration_state` JSON NULL（冲突留痕）；status 服务层扩 7 值（String 列无 CheckConstraint，无需 DDL 变更——迁移只加 JSON 列）。
- 状态流转写面：suspended/abandoned/active（复活）经 `set_status`；全程 decision_records（kind=goal_lifecycle）+ goal_arbitration trace。
- **仲裁不删除行、不改 layer/domain/priority 显式值**（显式优先级是创建时给定的事实，调制只在计算时叠加）。
- 新增 settings 4 项；零新表。

## 核心处理流程

```text
Flag OFF: goal_advance 内仲裁/abandonment 段不存在；转换表对 v1 路径允许集=现状；零差异

Flag ON（goal_advance 前段，0 LLM）:
  仲裁（目标集合变更触发 或 节流兜底）:
    ├─ 扫描同 (layer, domain) 顶层 active goal 分组（部分索引）
    ├─ 组内 score 排序 → [冲突→第一名 active 其余 suspended 留痕 | 无冲突→保持]
    ├─ 第一名终态 → suspended 第二名复活
    ├─ 级联父子状态；每转换 → set_status（转换表守卫）+ decision_records + trace
    └─ abandonment 检查（节流）: 候选扫描 → 置信计算 → [≥0.6 → abandoned | 不足 → trace]
  后续段（AUT-003）：封顶检查 → 观察 → 调整 → 执行
```

## 行为决策流程

```text
多目标裁决决策（全部确定性，输入快照留痕）:
  目标集合变更/周期兜底
    → 分组（layer, domain）→ 显式 priority + 层/Dev/Rel 调制 → score 排序
    → [同域互斥裁决 | 复活裁决 | 级联裁决] → set_status 守卫落库
  放弃决策:
    无进展天数（plan 进度 + updated_at）+ 双低相关信号 → confidence 规则计算
    → [≥0.6 abandoned | <0.6 保持 + trace 原因]
```

与 P6 闭环的关系：仲裁决定「追求谁」（goal_advance 执行段的输入集合），abandonment 决定「何时停止追求」——两者都是可解释、可追踪、可回溯的状态更新（trace + decision_records 双留痕），且直接影响未来周期（suspended 不进执行、abandoned 不进工作发现）。

## 与 Memory / Reflection / Development / Relationship / Life Loop 的关系

- **Memory**：abandonment 低相关信号读 `list_top_salience`（只读）；「Completion → experience 转写」在 AUT-003 经 Ingest 通道完成，本 Task 收口其终态语义，不触碰 Memory 写面；Memory 永不反向写 goal（矩阵铁律，评估断言面）。
- **Reflection**：无直接交互。
- **Development**：Priority 调制读 `read_overlay().goal_weights`（只读参数）；零 DEV 代码改动（domain 键缺失时调制为 0——P3 规则表的 settings JSON 可后续增配，不属于本 Task）。
- **Relationship**：Priority 调制读关系只读参数（tension/stage/conflict_status）；冲突期克制语义对齐 V8.5 R1（复用判定阈值常量，不改 V8.5 本体）；零关系数值写入。
- **Life Loop**：仲裁/abandonment 作为 goal_advance 前段被编排触发（Life Loop 不持有仲裁语义——编排域红线）；suspended goal 使工作发现与 Idle 判定自然收敛（僵尸目标不再阻止 Idle）。

## 异常与边界情况

- **仲裁异常**：维持当前态 + 告警（tasks.md Error/Failure 原文）——仲裁是幂等纯函数，下轮兜底重入；suspended 留痕期间 goal_advance 对该 goal 零执行动作（宁可不跑）。
- **score 并列**：同分裁决按（priority → created_at 早者优先 → goal_id 字典序）确定性破平——同输入同结果，无随机性。
- **父 goal abandoned 的子 goal**：级联 abandoned（留痕 abandoned_by_parent）——僵尸父不允许子继续占预算。
- **复活风暴防护**：suspended 复活仅由第一名终态触发（事件驱动），仲裁节流内不重复复活；复活后与原冲突方并存的可能性由下轮仲裁重新裁决（幂等收敛）。
- **v1 行误入仲裁扫描**：分组按 layer/domain 非空过滤，v1 行（NULL）天然不入组；转换表对 layer=NULL 行开放 v1 既有出口（expired/cancelled），对层级行关闭（Persistence）。
- **abandonment 误判**：阈值保守（14 天 + 双信号）+ 用户显式对话可干预（显式 remember/forget 类命令通道之外，goal 的显式取消走既有 API 面——登记：P6 不做用户侧 goal 管理界面，误判恢复靠复活语义或人工数据操作，评审材料）。
- **decision_records 写入失败**：状态转换已提交、留痕失败 → trace error + 告警（不回滚状态——状态正确性优先于审计完备性，审计缺口由 trace 兜底）。

## 测试要求

- Unit：状态机全路径（7 值 × 转换表逐格：合法落库、非法拒绝）；score 计算（显式/层调制/Dev 键缺省/Rel 调制逐项）；同域互斥与确定性破平；级联父子；复活语义；abandonment 置信（双信号边界、单信号保持）。
- Integration：①同域冲突两目标 → 仅一 active 另一 suspended 且 arbitration_state 可溯（E-AUT-03）；②第一名终态 → 复活留痕；③长期无进展低相关 goal → abandoned 且后续周期工作发现不再命中；④仲裁幂等（同输入重复仲裁零新写入）；⑤goal_lifecycle decision_records 落库。
- Regression：V6 goal checklist（v1 转换路径不收窄）+ Flag OFF golden + AUT-003 观察路径回归（仲裁前插不改变观察语义）。

## 验收标准

- 给定同域冲突两目标，当仲裁，那么仅一个 active 且另一 suspended 可溯（arbitration_state + trace + decision_records 三通道——E-AUT-03）。
- 给定长期无进展低相关 goal，那么按阈值 abandoned 且用户对话中可自然可见（行为面：该 goal 驱动的行动与工作发现消失；trace 面全程可答）。
- 给定任意状态转换尝试，非法转换被拒绝且无部分写入（转换表守卫）。
- 给定同输入重复仲裁，那么输出逐字节一致（幂等）。
- 给定 Flag OFF，那么行为与 v1 逐字节一致（含 v1 既有 expired/cancelled 路径）。
- 「目标不无故消失/翻转」成立：active 集合的每次变动均可归因到（仲裁/观察完成/失败/放弃/显式取消）之一且有留痕（E-AUT-03 全量口径，AUT-005 评估消费）。

- score 不落库（计算时值）；arbitration_state 只存裁决依据快照（对方 goal_id/score basis/时刻），不存全量快照。
- 不实现评估规则（AUT-005）；不改 AUT-003 的观察/执行语义（本 Task 只在其前段插入仲裁）。

## 冲突登记（评审决策材料）

### GAP-AUT-05：冲突判定的操作性口径

**问题**：tasks.md 定义「同域冲突取高优先级 active 另一 suspended 留痕」，但「冲突」本身无可判定口径；evaluation.md P6 场景写「personal 与 relationship 目标同域冲突」字面矛盾（personal 与 relationship 是不同 domain，如何「同域」）。
**裁决**：冲突域 = **(layer, domain) 分组内互斥**（同组 ≥2 个顶层 active 即冲突组）——最保守的确定性口径，无资源级检测的误判面。evaluation.md 场景解释为：冲突组内两目标（如 personal 与 relationship 两域各一）因调制后 score 竞争同一周期执行权，裁决路径与本 Detail 的同域互斥同构（跨域不 suspended，只按 score 排执行序）。若评审要求行动面资源冲突检测（同 capability+params 相交），登记为 3.0 演进项（当前 6 能力 × 单 goal 低频执行下收益低）。

### 裁决登记：suspended 期间工作发现的收敛口径
