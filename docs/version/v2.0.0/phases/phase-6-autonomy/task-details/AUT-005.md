# AUT-005 Task Detail — Goal 评估与回归（Observability / Evaluation）

> 上游：[../tasks.md](../tasks.md) AUT-005 ｜ [../../../architecture/evaluation.md](../../../architecture/evaluation.md) §1 Goal 行 ｜ [../evaluation.md](../evaluation.md) E-AUT-01~04 ｜ 依赖：AUT-003、AUT-004

## Task 目标

让「目标不无故消失/翻转」从设计承诺变成**可量化门槛**，并关闭 Phase 6 的验收回路：

1. **Evaluation 新增 goal 规则集**（纯函数规则，注册进既有 RULES 注册表）：Goal Consistency（不无故消失/翻转）、完成/失败/放弃语义正确性、冲突仲裁留痕完备性、abandonment 置信依据完备性、预算合规（规划 ≤3 次/goal、深度 ≤2、数量 ≤5）；
2. **规划质量 Judge**（采样 LLM）：对 goal_planning trace 抽样评审「拆解是否合理、判据是否贴切」（只读旁路）；
3. **跨会话剧情离线测试集**：长期目标跨 3+ 会话拆解执行并被观察调整的三分支剧情（完成/失败/放弃）+ 冲突剧情 + 预算剧情，确定性跑进 offline_evaluator；
4. **v2.0.0 autonomy regression-checklist 执行与结果记录**：目录内 [regression-checklist.md](../regression-checklist.md) 的执行步骤 1~5 落地，结果记附录。

只读旁路铁律继承（V7.5）：Evaluation 不写任何业务状态。

## 背景 / 为什么需要

AUT-001~004 交付了层级、规划、观察、仲裁的**机制**，但机制正确 ≠ 行为可信：

- **没有一致性指标，「追求」就不可信**：目标集合在供给创建、仲裁挂起、失败、放弃之间流转——任何一条流转路径的 bug（如 suspended 复活风暴、封顶误杀、判据异常计成失败）都表现为「目标无故消失/翻转」。规则集把 E-AUT-03 的验收口径变成每次离线评估的机械断言；
- **规划质量需要人评替代物**：校验闸保证「可执行」，不保证「合理」（如把三步能完成的事拆成五步）。LLM Judge 采样评审 goal_planning trace 是 V7.5 评估框架的既有扩展位（规则+Judge 双阶段），不引入新框架；
- **P6 是 v2.0.0 最后一个 Phase**：tasks.md M4「AUT-005 → Eval Gate + Regression Gate（含跨会话剧情）→ 申请开启 v2_autonomy_advanced_enabled → v2.0.0 全量」——本 Task 是全链 Flag 总闸的守门人。

## 设计方案

1. **GoalSlice 与采集口径**（对齐 LifeLoopSlice 先例）：

   ```text
   GoalSlice:
     goals:        character_goals 层级行（layer 非空，含终态）
     plans:        goal_plans 全版本（版本流转审计面）
     lifecycles:   decision_records(kind=goal_lifecycle) 行（状态变更溯源面）
     traces:       goal_planning / goal_observation / goal_arbitration trace 行
     stale 判定:    同 LIFE-006（2× job timeout 无更新即 stale）
   采集只读；一次采集多规则共享（同 ctx 求值，与 autonomy.py 5 规则模式一致）
   ```

2. **Goal 规则集（纯函数，逐条对齐 E-AUT 门槛）**：

   ```text
   GoalConsistencyRule        active 集合变动（周期对比）必须可归因到 lifecycle 记录；
                              终态行不得复活（GOAL_TRANSITIONS 守卫外的直写检出）
                              → 违例 IssueCode.GOAL_INCONSISTENT_STATE
   GoalSemanticRule           completed 必有 plan 全 done 前置；failed 必有 failure_reason；
                              abandoned 必有 confidence≥阈值依据
                              → 违例 GOAL_INVALID_TERMINATION
   GoalArbitrationRule        suspended 行必有 arbitration_state 留痕 + lifecycle 记录；
                              同域 active 顶层 goal 数 ≤1
                              → 违例 GOAL_ARBITRATION_MISSING
   GoalPlanningBudgetRule     每 goal goal_plans 行数 ≤3（attempt 口径）；入库 plan 100%
                              白名单判据 + capability 对齐（复用 AUT-002 校验函数只读复核）
                              → 违例 GOAL_PLANNING_BUDGET_EXCEEDED
   GoalExecutionCapRule       单 goal 执行周期 ≤ v2_autonomy_goal_max_active_hours；
                              Sub-Goal 连续失败 ≥ 阈值必已终态化
                              → 违例 GOAL_EXECUTION_CAP_EXCEEDED
   GoalSupplySanityRule       供给创建行 layer/domain 必非空、描述非生成式伪迹
                              （模板指纹核对——防 LLM 描述混入供给面）
                              → 违例 GOAL_SUPPLY_MALFORMED
   ```

   6 码入 GOAL 维度；ISSUE_CODE_COUNT 40→46 收口（数值以实现时实际码数为准，断言同步）。

3. **规划质量 Judge（采样）**：对象 = status=validated/active 的 goal_plans 行 + 其 goal_planning trace；Judge 输入 = goal 描述 + Sub-Goal 树 + 校验结果；评审三问（拆解是否贴目标 / 判据是否贴步骤 / 步骤序是否合理）→ 1~5 分；采样率 settings（`v2_autonomy_judge_sample_rate`，默认 1.0 对齐 reflection 先例）；失败 → skipped 可重跑（tasks.md Error/Failure）；结果进离线报告小节，不写业务状态。

4. **跨会话剧情集（E-AUT-04）**——`run_autonomy_storyline` runner（对齐 DEV-006 模式，确定性无真实 LLM）：

   ```text
   剧情一（三分支主线）：注入 Development 调制 → 供给创建 long_term goal → 规划 validated
     → 跨 3+ 会话模拟周期推进（每会话若干轮对话 + 周期 goal_advance）
     → 分支 A 判据逐步达成 → completed + experience 转写断言
     → 分支 B 注入连续失败 → 阈值 → failed + failure_reason 断言
     → 分支 C 注入长期无进展低相关 → abandoned + confidence 断言
   剧情二（冲突）：同域两 goal → 仲裁 suspended 留痕 → 第一名终态 → 复活断言
   剧情三（预算）：第 4 次规划请求拒绝断言；Sub-Goal 失败达阈值不再重试断言
   每剧情逐周期归因链审计（goal_planning/observation/arbitration trace 连续性）
   ```

5. **Eval Gate 门槛接线**（evaluation.md 四行全量落地）：E-AUT-01 = 校验通过率 100% + 封顶断言；E-AUT-02 = 推进/失败语义 100%；E-AUT-03 = 一致性规则零违例；E-AUT-04 = 剧情通过。Gate 未全过 → 不得申请开启 `v2_autonomy_advanced_enabled`（evaluation.md 头部铁律）。

6. **Regression Gate 执行**（regression-checklist.md 步骤 1~5）：①Flag OFF 旧 goal 行为快照对比（AUT-001 验收的执行落点）；②V6/V7 checklist 重跑；③跨会话剧情集 ON/OFF 双态（OFF 态 = 剧情跳过 P6 断言仅跑基线）；④全量验收报告；⑤结果记本目录 checklist 附录。P1~P5 Eval Gate 重跑作上游不回退证明。

## 核心处理流程

```text
在线（post_process 挂钩，采样）: 周期/轮次事件 → GoalSlice 增量 → 6 规则 → Issue 流入既有评估报告
离线（tests/eval/test_autonomy_eval_gate.py）:
  run_autonomy_storyline（三剧情确定性模拟）
    → 全程 GoalSlice/LifeLoopSlice 采集 → 规则断言 + Judge 采样（fake LLM 固定分）
    → E-AUT-01~04 门槛判定 → 报告归档 reports/
Regression Gate: checklist 步骤 1~5 → 附录记录 → v2 全量评审材料
```

## 行为决策流程

本 Task 无行为决策（只读旁路，0 业务写入）。唯一的「裁决」是 Gate 判定本身（确定性比较）：规则违例数=0 且剧情通过 → PASS；任何违例 → FAIL 并定位环节（供给/规划/观察/仲裁四段归因——报告按 IssueCode 维度分组，失败可定位到具体 Task）。

## 与 Memory / Reflection / Development / Relationship / Life Loop 的关系

- **Memory**：GoalSlice 不读 memories（一致性断言用 lifecycle/trace 面）；供给剧情经 P1 通道的转写断言（experience Candidate 落库）是测试侧断言非评估写入。
- **Reflection**：无直接交互（Judge 框架协议复用 V7.5 评估面，不碰反思域）。
- **Development**：剧情注入 Development 调制是测试输入（read_overlay 只读消费）；DEV-006 growth_loop 报告是上游不回退基线。
- **Relationship**：无直接交互（REL eval gate 报告是上游基线）。
- **Life Loop**：GoalSlice/LifeLoopSlice 同构同协议；剧情模拟消费 LIFE-002 周期管线与 LIFE-003 预算闸（Flag ON 态）；LIFE-006 的 5 规则与 4 码不回退是 Regression Gate 组成部分。

## 异常与边界情况

- **Judge 失败/超时** → 该样本 skipped 不阻塞 Gate（规划质量分缺失时 Gate 降级为「规则断言 + skipped 计数披露」，连续两次 skipped 告警——对齐 tasks.md Error/Failure）。
- **剧情模拟与真实 LLM 行为差异**：runner 用 fake LLM（结构化输出固定桩）——Gate 验证的是机制语义非模型质量；模型质量由真实回归（checklist 步骤 4）人工覆盖。登记为 Gate 覆盖边界。
- **stale 数据**：2× timeout 无更新 → 该样本规则 skipped + 报告披露（不误判为违例——对齐 LIFE-006 stale 口径）。
- **评估并行**：规则为纯函数 + Slice 一次采集快照——可重复执行（tasks.md Idempotency），xdist 下无共享写面。
- **Flag 双态一致性**：OFF 态 GoalSlice 为空集 → 6 规则零违例零断言（与「v1 字节级一致」验收互补：OFF 态评估面本身证明无观测点）。

## 验收标准

- 给定剧情集，当评估，那么目标不无故消失/翻转（GoalConsistencyRule 零违例）且冲突仲裁留痕、abandonment 有置信依据（E-AUT-03）。
- 给定规划产物全集，那么 100% 过可执行校验且 attempt 封顶无违例；Judge 采样分达标（E-AUT-01）。
- 给定观察/失败路径全集，那么推进/失败/封顶语义 100% 正确（E-AUT-02）。
- 给定三分支剧情，当跨 3+ 会话模拟，那么全部分支通过且归因链连续（E-AUT-04）。
- 给定 Flag OFF，那么与 v1 字节级一致（快照对比记录入 checklist 附录）。
- Eval Gate 全过 + Regression Gate 附录齐备 → 具备申请开启 `v2_autonomy_advanced_enabled` 的材料条件。

## Implementation Constraints

- **红线**：只读旁路——Evaluation 不写业务状态（沿 V7.5 铁律）；报告/Issue/trace 是唯一产出面。
- 规则集复用 AUT-002 校验函数做只读复核（同一份白名单常量），禁止重写第二份谓词逻辑。
- ISSUE_CODE_COUNT 收口与 dimension 别名按 LIFE-006 先例（tests/unit 计数断言同步，第五次收口）。
- 剧情模拟禁用真实 LLM（成本与确定性）；Judge 采样走既有评估 LLM 面。
- checklist 附录记录是交付物的一部分（无附录 = Task 未完成）。
- 不新增评估框架（规则+Judge 双阶段与 Slice 模式全复用）；不实现任何 P6 机制面修复（发现违例 → 归因到 AUT-001~004 的修复项，本 Task 只报告）。

## 冲突登记（评审决策材料）

### 裁决登记：Gate 覆盖边界与真实回归的关系

离线 Gate（fake LLM）验证机制语义，规划质量 Judge 采样验证结构合理性，但「规划是否真的聪明」「主动消息是否得体」属模型质量维度——由 regression-checklist 步骤 4（真实模型人工回归）覆盖。两层缺一不可：Gate 全过只解锁「申请开启 Flag」的材料条件，不是上线决定本身（evaluation.md 头部与 checklist 步骤 4~5 的既有分工，本 Detail 仅显式登记，不改变分工）。
