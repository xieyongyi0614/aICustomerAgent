## 1.1 Goal

消灭：

1. **trigger 行滞留**：每次维护 tick 对同一 `action_schedule:{id}` 重复 register，永不终态
2. **终态复活**：已 `done`/`cancelled` 的行被 register 回 `pending`
3. **双源漂移**：`action_schedules` 与 `trigger_registry` 无一致性收口

验收核心：连续两轮维护步后 `_due_trigger_present` 为 **False**（不再空转自治 tick / LLM 成本泄漏）。

## 1.2 问题回顾（audit D03）

| 基线 | 后果 |
|---|---|
| `step_action_schedule` 每 tick `register` 同键 | 状态永非终态 |
| `trigger_registry_repository.register` 终态 → `pending` | 复活 |
| 无 `done`/`cancelled` 收口 | `life_loop._due_trigger_present` 恒真 |
| schedule 与 trigger 双写无对账 | 表噪声、成本泄漏 |

## 1.3 与其他模块关系

| 方向 | 模块 | 关系 |
|---|---|---|

# 3. Scope

## 3.1 In Scope

- 一次性 `action_schedule` 的 register 策略：
  - 已终结（schedule `executed`/`cancelled`）不再 register
  - 已存在 pending/due 的行不无意义刷新（除非 due_at 需要更新且有明确语义）
- 防复活：对 `trigger_type=action_due` 且 payload `kind=action_schedule` 的终态行，register 不得拉回 pending（或 register 入口对终态直接返回/忽略）
- 执行完成后：`mark_schedule_executed` **同时** trigger → `done`
- 执行永久失败/取消：trigger → `cancelled`（或 `done`，二选一写进架构）
- 可选轻量对账：schedule `executed` 但 trigger 非终态 → 修复
- T4 测试段

## 3.2 Out of Scope

- 通用 followup/闹钟类 trigger 语义变更
- trigger 表历史清理策略（可记 P2，不在本卡强制）
- 多进程 CAS 全套（REF-004 认领；本卡终态）

# 4. 实现要点

## 4.1 生命周期（冻结）

```text
schedule() 
  → action_schedules.status=scheduled
  → trigger(action_due, key=action_schedule:{id}) pending

到期维护
  → 不重复 register 已有未终结行
  → 认领/执行（REF-004）

执行成功
  → schedule=executed
  → trigger=done

执行取消/永久放弃
  → schedule=cancelled
  → trigger=cancelled
```

## 4.2 防复活规则

在 `register` 或调用方：

- 若现有行 `status in (done, cancelled)` 且语义为一次性 action_schedule → **不**改回 pending
- 日志可记 skip，避免静默

实现位置二选一（推荐调用方 + 仓储双保险中最少一处权威）：

1. `step_action_schedule` 先查再写（不 register 已终态）
2. `trigger_registry_repository.register` 对终态+payload kind 拒绝复活

**禁止**只改文档不改代码。

## 4.3 与 `_due_trigger_present` 的关系

收口后：

- 无到期 schedule 且无 due trigger → False
- 连续两轮维护步后应为 False（执行成功场景）

# 5. Acceptance Criteria

- [ ] **T4**：到期 → 执行成功 → trigger `done`；再跑一轮维护步：不复活、`_due_trigger_present` False
- [ ] 对已 `executed` 的 schedule，维护步不再 `register` 其 trigger
- [ ] 对已 `done` 的 `action_schedule:*` 行，`register` 不会变回 `pending`
- [ ] schedule 与 trigger 终态一致（成功路径）
- [ ] Flag off：无行为变化
- [ ] 不影响非 `action_due` 的 trigger 用法（既有测试绿）

# 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 防复活逻辑误伤合法重开（用户重新设提醒） | 新提醒应 **新 Action id / 新 schedule**，不复用终态 trigger 键；文档写明 |
| 只在调用方过滤、其它路径仍可复活 | 仓储层对 kind=action_schedule 终态拒绝，或契约测试锁 register 行为 |

回滚：恢复每 tick register；接受成本泄漏（不可取，仅应急）。
