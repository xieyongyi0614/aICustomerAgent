## 1.1 Goal

Flag on 主路径产出的 `steps[].result` 与 `record.result` **同时包含**：

1. 新契约字段：`status` / `effects` / `error` / `failure_kind` / `output` / `metadata` / `observations` / `created_at` / `id` / `action_id`
2. 旧读键：`payload`（含 `deferred_world_op` 等 outbox 依赖）、`tool_id` / `duration_ms` / `observations` 等 extras

使 outbox 世界写、Reflection 工具证据窗、Replay/Debug 在 Flag on 下与 Flag off 数据质量等价或更好。

## 1.2 问题回顾（audit D01/D07）

| 现状（审计基线） | 后果 |
|---|---|
| `execute_internal` / `execute_tool` 有损归一，丢 `output` / `observations` / `effects` / `tool_id` / `duration_ms` | 世界事件引用丢失、证据窗空、调试失真 |

# 4. 实现要点

## 4.1 步骤结果形态契约（冻结）

```text
steps[i].result = {
  # 新契约（ActionResult）
  "id", "action_id", "status", "effects", "error", "failure_kind",
  "output", "metadata", "observations", "created_at",
  # 旧读键（兼容窗口）
  "payload": { ...output..., "failure_kind"? },
}
steps[i] extras:
  "tool_id", "permission", "validation", "duration_ms",
  "index", "capability", "action", "params", "status"
```

**约束**：该形态 **与 Flag 无关**——只要走 V2.6 主路径写 steps，就写全形态。Flag 只决定是否走 V2.6 执行链，不决定结果字段多少。

## 4.2 投影函数为唯一生产实现

- `execute_internal` → `result.from_capability_result`
- `execute_tool` → `result.from_tool_execution`
- 禁止再出现有损旁路 `_normalize_*`

## 4.3 旧读者对齐（验收时人工核对）

| 读者 | 期望键 |
|---|---|
| `services/tool/normalizer.py` outbox | `steps[].result.payload.*` |
| `services/reflection/evidence.py` | `steps[].tool_id`、`observations` |
| `executor_bridge._result_kind` | `result.status` / failure |
