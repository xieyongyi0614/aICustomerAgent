# 4. 实现要点

## 4.1 终态映射（冻结）

| ActionResult.status | ActionRecord.status | 说明 |
|---|---|---|
| succeeded | succeeded | 既有 |
| failed | failed | 既有；可重试则先 attempt/next_retry |
| partial | **failed** | 不滞留；`gate_reason` 带 partial 线索；不升新状态值 |
| （无）executing 超时 | **failed** + timeout | 孤儿恢复 |

## 4.2 恢复步伪代码

```text
def _recover_stale_executing():
  if not v26_action_execution_enabled:
    return
  cutoff = now - timedelta(minutes=settings.action_executing_timeout_minutes)
  for record in list_stale_executing(cutoff, limit=50):
    record.status = "failed"
    record.gate_reason = "timeout"
    # failure_kind 进 result 或既有字段，保持可读
    record.next_retry_at = now + backoff  # 仅当策略允许重试
    record.updated_at = now
    save_record(record)
```

**注意**：状态赋值尽量经 `transition_action("executing", ...)`；若六态表无该边，允许本卡在恢复路径使用文档化的权威迁移（并在 P1-5 一并收口），禁止多处裸赋值扩散。

## 4.3 与重试的关系

- 未超 `action_retry_max_attempts`：failed + `next_retry_at` → 既有 `list_retryable` / `_process_due_retries`
- 已达上限：终态 failed，不再重试

## 4.4 误杀防护

- 仅扫 `status=executing` 且 `updated_at <= cutoff`
- 执行路径应在开始/结束刷新 `updated_at`（确认现有 execute 是否刷新；若无则补写）

# 7. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 长工具执行被误判孤儿 | timeout 配置默认 30 分钟 ≫ execute 10s；必要时执行中刷新 updated_at |
| 恢复与在途 execute 竞态 | 维护步与对话链路同 user 锁 / 单进程假设写明；多进程属 P2 |
| partial 映射被下游当成 transient 可重试 | 文档写死；测试锁 status=failure_kind 语义 |

回滚：移除恢复步调用；保留仓储函数无害。
