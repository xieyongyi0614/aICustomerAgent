## 2. Background

### 2.1 现状：链接只能由「冲突消解」产生，且只有三义

| 事实 | 证据 |
|---|---|
| 链接的唯一写入路径在 `lifecycle.on_promoted` | `apps/backend/app/services/memory/lifecycle.py:267`（`on_promoted(memory_id, relation=None, trace=None)`）、`:296-297`（contradicts）、`:320-321`（merges / supersedes），底层 `:333`（`_link_exists`）/ `:346`（`_create_link`） |
| 触发时机是**转正时**，且 relation 由候选评估给出 | `apps/backend/app/services/memory/evaluator.py:227`（`_promote`）、`:268`（`_after_promotion`）→ `on_promoted`（`:273`） |
| 关系值域（`MEV-009` 后为 6 值） | `apps/backend/app/core/db/memory.py:119-122`（`ck_memory_links_relation`）；`MEV-009` §4.1.2（`MEMORY_LINK_RELATIONS` 常量） |
| 仓储层**无**链接函数；读面缺失 | `app/repositories/memory_repository.py` 无 `MemoryLinkRow` 引用（已核实）；`MEV-009` 将新增只读 `list_links` |
| 可复用的相似度与向量件 | `apps/backend/app/engines/memory_conflict.py:27`（`same_topic(left, right, threshold=None) -> bool`，LCS）；`app/services/memory/embeddings.py:199`（`embed_query(text) -> list[float] \| None`）；`app/repositories/memory_repository.py:329`（`search_by_vector(user_id, character_id, query_vector, limit=20)`，非 PG 返回 `[]`） |
| 后台 job 与幂等键基建 | `app/services/memory/job_worker.py:41`（`register_job_type`）、`:46`（`register_tick_hook`）、`:71`（`run_job_tick`）；`BackgroundJobRow`（`app/core/db/autonomy.py:138`）含 **`idempotency_key` unique**（`:141-151`） |
| lite LLM 与结构化输出范式 | `apps/backend/app/chains/structured.py:66-68`；lite 先例 `app/services/memory/evaluator.py:47` / `:79-81` |

### 2.2 为什么必须做

1. **`MEV-009` 的 1-hop 扩展需要链接数据才有价值**：值域与读面就绪后，若无人写新关系，扩展模块永远是空操作（`docs/agent-evolution-plan-2026-10.md` §2.3 M3.1 / M3.2 的分工）。
2. **因果与时序无法由规则稳定判定**：「买帐篷」→「去露营」是因果；「面试」与「入职」是时序——这类判断需要语义理解，是 LLM 的合理用武之地（而 `same_topic` 的 LCS 只能判「同主题」）。
3. **必须与既有冲突消解严格分工**：`supersedes` / `merges` / `contradicts` 已被 `lifecycle.on_promoted` 独占（它同时改 `status` / `superseded_by`）。若本任务也写这三值，会出现「链接状态与记忆状态不一致」的双写风险——故契约里**硬性忽略**这三值。

### 2.3 在本版本中的位置

M3 第 2 个任务；它把 `MEV-009` 的值域与读面变成「有数据可查」，为 `MEV-011`（搜索/筛选）与 `MEV-012`（主题聚类）提供关系维度。

6. 3 个新设置字段（§4.1.4）。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不写 `supersedes` / `merges` / `contradicts`** | 三值由 `lifecycle.on_promoted`（`:267`）独占并伴随 `status` / `superseded_by` 变更；双写会造成「链接与状态不一致」（D2） |
| 2 | **不做多跳关系推断**（A→B→C 的传递闭包） | 传递闭包会让链接规模平方级增长，且与 `MEV-009` 「只做 1-hop」的边界冲突 |
| 3 | **不正面对称化**（不写反向行） | 值域只有 6 值，反向关系（`causes` / `after`）会再扩值域；改为**检索侧双向匹配**（§4.1.3） |
| 4 | **不改 `lifecycle.on_promoted` 与冲突消解数学** | `same_topic`（`engines/memory_conflict.py:27`）与 `on_promoted` 属既有语义；本任务只**新增**一个公开写函数 |
| 5 | **不改检索打分与 1-hop 扩展逻辑** | 属 `MEV-001/002/008/009` |
| 6 | **不新增表 / 不加列 / 不加迁移** | 链接表已由 `MEV-009` 扩值域；本任务零迁移 |
| 7 | **不给每条记忆都抽关系**（只对「新转正 + 有候选」的记忆抽） | 全量抽取会产生大量无意义链接与 LLM 成本（R-M2） |
| 8 | **不新增 `*_enabled` 开关、不新增 Profile** | `tasks.md` §0.4 / 基线 ADR-7；用取值类 `memory_link_extract_mode` |

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 链契约（新增 `app/chains/memory_link_chain.py`）

| 符号 | 契约 |
|---|---|
| `MemoryLinkItem` | Pydantic：`related_memory_id: str`、`relation: str`、`confidence: float`（`ge=0, le=1`）、`reason: str = ""` |
| `MemoryLinkResult` | Pydantic：`links: list[MemoryLinkItem]`（可为空 = 判定「无关」） |
| 允许关系白名单（★ 冻结） | `LINK_EXTRACTABLE_RELATIONS = ("caused_by", "before", "related")` |
| **必须忽略** | 模型返回 `supersedes` / `merges` / `contradicts` → **丢弃该条**（不抛、不写）+ 计入忽略计数（trace） |
| `build_memory_link_chain(llm=None) -> Runnable` | 经 `build_structured_chain`（`:66-68`）；默认 `get_llm("lite")` |
| `async extract_links(anchor_content: str, candidates: list[tuple[str, str]], llm=None) -> list[MemoryLinkItem]` | `candidates` = `(memory_id, content)`；返回的 `related_memory_id` **必须**在候选集合内，否则丢弃（fail-closed，防幻觉 id） |
| 方向语义（★ 冻结） | `caused_by`：anchor **由** related 引起；`before`：anchor 在 related **之前**发生；`related`：相关但无明确方向。**写入单向**（anchor 为 `memory_id`） |
| prompt 纪律 | 只判定给定候选集合内的关系；无关系返回空列表；不得输出候选外 id；不得输出三既有值 |

#### 4.1.2 选材与候选契约

| 项 | 契约 |
|---|---|
| 触发 | 周期性 tick（`memory_link_extract_mode == "auto"`）+ 由 `ingest`/`evaluator` 转正后**入队**（job `idempotency_key = f"memory_link:{memory_id}"`，保证同一记忆只抽一次） |
| anchor 记忆 | 需满足：`status='active'`、`layer` 不限、`created_at` 在最近 `memory_link_window_hours`? — **不使用时间窗**，改为「**尚无任何 relation 链接**（既无出边也无入边）的 active 记忆」为待处理集合（幂等、可断点续跑） |
| 候选集合 | 优先取**向量近邻**（`embed_query` `:199` + `search_by_vector` `:329`，`k = memory_link_candidate_k`）；向量不可用（非 PG / 无 embedding）→ 回落 `same_topic`（`engines/memory_conflict.py:27`）+ 同类型近期记忆 |
| 候选上限 | `memory_link_candidate_k`（默认 5）；候选为空 → 跳过（不调 LLM） |
| 单次上限 | `memory_link_max_per_run`（默认 20）条 anchor |
| 排除 | anchor 自身、已 `forgotten` / `superseded` 的候选、已在链接中的候选（复用 `_link_exists` 语义） |

#### 4.1.3 写入契约

| 项 | 契约 |
|---|---|
| 写函数 | `lifecycle.create_relation_link(memory_id, related_memory_id, relation, trace=None) -> bool`（新增公开函数；内部 `_link_exists` 去重 → `_create_link`） |
| 白名单校验 | `relation` 不在 `LINK_EXTRACTABLE_RELATIONS` → 直接 `False` + warning（**不写**） |
| 幂等 | `_link_exists`（`:333`）保证同三元组不重复；job `idempotency_key`（`BackgroundJobRow` `:141-151`）保证同一 anchor 不重复排队 |
| 双向读取（★ 契约补充要求） | **本任务要求 `MEV-009` 的 `list_links` 必须双向匹配**（`memory_id IN ids OR related_memory_id IN ids`），否则单向写入会导致反向查询失效。若 `MEV-009` 已按单向实现，本任务须先补齐该匹配语义（属本任务交付的一部分） |
| 失败语义 | 单条 anchor 失败 → `logger.warning` + 跳过；整体不抛（除连接级错误交既有退避） |

#### 4.1.4 新设置字段（`app/core/settings/memory.py`）

| 字段 | 类型 | 默认 | 语义 | 校验 |
|---|---|---|---|---|
| `memory_link_extract_mode` | `str` | `"off"` | `off` / `auto` | 仅接受 `{"off","auto"}`；非法回落 `off` + warning |
| `memory_link_candidate_k` | `int` | `5` | 候选记忆条数上限 | `ge=1`、`le=20` |
| `memory_link_max_per_run` | `int` | `20` | 单次 job 处理的 anchor 数上限 | `ge=1`、`le=200` |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **只抽三义，硬忽略既有三义** | 既有三义由 `on_promoted` 独占并伴随状态变更（`superseded_by` / `status`）；双写会造成链接与状态不一致（§2.2 第 3 条） |
| D2 | **不写反向行，改双向匹配** | 写反向行会把值域从 6 值扩到 8+（`causes` / `after`）；双向匹配在同一次查询内解决且零 schema 变更 |
| D3 | **anchor 选取用「无任何链接」而非时间窗** | 幂等友好（处理过的 natural 退出集合）、可断点续跑、且天然避免重复抽取 |
| D4 | **候选外 id 一律丢弃（fail-closed）** | 与 `MEV-001` D3 / `MEV-007` D1 同源：不让模型发明引用 |
| D5 | **写函数落 `lifecycle.py` 公开面，而非仓储** | 既有链接写入全在 `lifecycle`（`:333` / `:346`），包含去重与 `MemoryLinkRow` 构造；把写面留在同处，仓储只承担只读（`MEV-009` 的 `list_links`） |
| D6 | **job 幂等键锚定 anchor id** | `BackgroundJobRow.idempotency_key` 唯一（`:141-151`）——同一记忆只抽一次，重试不会重复调用 LLM |
| D7 | **向量不可用时回落 `same_topic`** | 与记忆域既有降级精神一致（`retriever.py:344-346` / `:355-357`）；`search_by_vector` 非 PG 直接返回 `[]`（`:337`），必须有回落 |
| D8 | **不设时间窗** | 时间窗会让「上周已抽过的记忆」再次进入集合，与幂等目标冲突 |
| D9 | **默认 `off`** | 与 M1/M2/M3 其余能力一致：合入即零行为变化 |
| D10 | **本任务零迁移** | 值域与读面由 `MEV-009` 提供 |

### 4.3 数据流

```text
【入队】ingest / evaluator 转正后 → job_worker.enqueue(memory_link_extract, idempotency_key=f"memory_link:{memory_id}")
   或 周期 tick hook（mode=auto）→ 扫描「无任何链接的 active 记忆」（上限 max_per_run）

【抽取】relations.run_extract_tick() / run_extract(anchor_id)
   ① 候选：embed_query（:199）+ search_by_vector（:329，k=candidate_k）
        └─ 不可用 → 回落 same_topic（engines/memory_conflict.py:27）+ 同类型近期
   ② 候选空 → 跳过（零 LLM 调用）
   ③ chains/memory_link_chain.py::extract_links(anchor_content, candidates)
        ├─ 白名单外关系（supersedes/merges/contradicts）→ 忽略 + 计数
        ├─ 候选外 id → 丢弃
        └─ 空结果 → 判定「无关」，不写链接
   ④ lifecycle.create_relation_link(anchor, related, relation)
        ├─ relation 白名单校验失败 → False + warning
        ├─ _link_exists（:333）命中 → 幂等返回
        └─ 异常 → warning + 跳过该条（整体不抛）
   ⑤ trace 记录：anchor_id / candidates / kept / ignored_existing_relations / wrote

【读取（MEV-009）】list_links 双向匹配 → 1-hop 扩展召回

红线：不写既有三义；不写反向行；候选外 id 丢弃；零迁移；off 时零 LLM 调用
```
