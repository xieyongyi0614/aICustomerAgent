## 2. Background

### 2.1 现状：subAgent 域没有任何文档依据

| 事实 | 证据 |
|---|---|
| 基线的 Extension Points 无 subAgent 条目（裁决前） | `docs/current-system-architecture-baseline.md:438`（§8 标题；8.1~8.6 无该条目）；`SAG-000` 将新增 §8.x |
| 基线 §11.1 演进方向只提「扩展新 run_kind」 | `docs/current-system-architecture-baseline.md:569` |
| **没有任何一份文档是 subAgent / 多 Agent 协作 / 委派的设计文档** | `docs/agent-evolution-plan-2026-10.md` §4（审核结论：文档层仅 v3.0.0 Non-Goals 与 §10.4 预留点） |
| 域文档先例（体例可对齐） | `docs/version/v5.0.0/flutter-architecture.md`（客户端技术方案）、`docs/version/v5.0.0/update-system-architecture.md`（更新域唯一架构依据）、`docs/integrations/feishu/architecture.md`（通道域唯一架构依据） |
| 已有的契约落点（本文档的输入） | `SAG-001`（`app/application/agent_runtime/agents.py`）、`SAG-002`（迁移 `0012` + `execution_history` / `debug_view`）、`SAG-003`（`dispatch.py` + 收敛语义 + S-C 工具） |
| 基线纪律（域文档须被基线反向引用） | `docs/current-system-architecture-baseline.md` 开头「后续任何架构演进请先更新本基线，再进入开发」；域文档先例均在基线 §8 有条目 |

### 2.2 为什么必须做

1. **没有域文档，裁决会「随时间失效」**：`SAG-000` 的裁决记录是**决策记录**（当时为何这样决定），而实现者日常需要的是**现状 + 契约**（现在是什么样、边界在哪）。两者不可互相替代（`docs/agent-evolution-plan-2026-10.md` §4.5 第 1 条要求「基线登记」，本任务补齐域文档层）。
2. **它要固化「非目标」**：subAgent 最容易被范围蔓延的方向（多角色、并行、外部框架、多层委派、结果自动写域）必须写成明文 Non-Goals，否则每次评审都要重新争论（§4.1.3）。
3. **它是「是否升级 S-A」的决策依据载体**：`SAG-003` 的验证结论（S-C 四要素是否够用）必须落到一处可查的地方，作为升级决策的输入（D4）。

### 2.3 在本版本中的位置

S 线**收尾任务**（S 线终点）。S 线整体未排期，且全部阻塞于 `SAG-000`。

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 文档结构（`docs/version/v6.0.0/subagent-architecture.md`）

| 节 | 内容 | 必须引用 |

| §2 红线裁决结论 | RL-1~RL-5 的结论摘要（**指向** `SAG-000` 的裁决记录，不重述全文） | `docs/version/v6.0.0/reviews/subagent-redline-decision.md` |
| §3 身份契约 | `BaseAgent` 5 要素、注册方式、绑定解析、`tool_scope` 只收窄 | `SAG-001` §4.1；`app/application/agent_runtime/agents.py`（落成后） |
| §4 血缘与观测口径 | `parent_run_id` / `delegation_kind` 值域、参与树只读查询与节点上限、如何从既有 debug 面查看 | `SAG-002` §4.1；迁移 `0012`；`execution_history.py` / `debug_view.py` |
| §5 派发与收敛语义 | 派发契约、幂等、在飞上限、**五分支收敛语义**（成功 / 失败 / 超时 / 部分成功 / 未到达）、回投通道选择 | `SAG-003` §4.1；`app/application/agent_runtime/dispatch.py`（落成后）；`BackgroundJobRow` |
| §6 边界与非目标 | Non-Goals 明文清单 + 与既有 ADR 的关系 + 评测口径 + **未实现项**清单（含是否升级 S-A 的结论与依据） | 基线 ADR-7（`:545`）/ ADR-9（`:547`）/ ADR-10（`:548`）；`SAG-003` 的验证结论 |

#### 4.1.2 §6 必须包含的两张清单

| 清单 | 内容（冻结） |
|---|---|
| **Non-Goals（明文）** | ① 多角色 / 多租户并行（`character_id` 多实例属 S-B，需另裁）；② 并行调度 / DAG 执行；③ 外部 Agent 编排框架（RL-2）；④ 多层委派（深度 > 1）的调度策略；⑤ 子 Agent 结果自动写入业务域；⑥ 跨用户血缘 |
| **未实现项** | ① S-A（新 run_kind + 独立 Run）是否推进——**结论 + 依据（`SAG-003` 四要素验证结论）+ 未推进原因**；② 多角色；③ 并行；④ 评价口径的自动化（离线/在线）；⑤ 客户端展示参与树 |

#### 4.1.3 引用与标注纪律

| 项 | 契约 |
|---|---|
| 现状 vs 规划 | 每节内若含未实现内容，必须以「**未实现 / 规划中**」显式标注（对齐基线体例） |
| 引用形式 | 优先「`文件:行号`」；未落地（`SAG-001~003` 未开工）时引用「任务 ID + §节」并标注「**契约已冻结，代码未落地**」 |
| 术语一致 | `Run` / `Profile` / `run_kind` / `delegation_kind` / `parent_run_id` 等术语与基线一致，不得自造同义词 |
| 基线反向引用 | 在 `docs/current-system-architecture-baseline.md` 的 §8 subAgent 条目中补本文档路径（若 `SAG-000` 已建条目） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **不重新裁决，只转述** | 裁决归属单一（`SAG-000`）；域文档若也下结论会产生两个裁决源（`SAG-000` D7 的反面） |
| D2 | **域级视图，不复述 Task Detail** | 文档重复细节会与 Detail 漂移；用引用保证单一真相 |

| D6 | **不改历史文档，不调整 M / P 线文档** | 与仓库既有约定一致 |
| D7 | **零代码** | 文档任务与实现分离（与 `SAG-000` D5 同源） |
