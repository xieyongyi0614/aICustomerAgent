## 2. Background

### 2.1 现状：情景类记忆是碎片，没有「一段经历」的粒度

| 事实 | 证据 |
|---|---|
| 记忆写入只有「单条候选」一条路 | `apps/backend/app/services/memory/ingest.py:67-79`（`create_candidate`）、`:116`（`ingest_from_conversation`）、`:171`（`ingest_from_action_record`）、`:237` / `:272` / `:311` / `:346`（世界事件 / 关系事件 / 里程碑 / 目标完成）；四源封装 `app/services/memory/sources.py` |
| 提取粒度是「一条消息 → 若干条候选」 | `apps/backend/app/chains/extractor_chain.py:30`（`extract_candidates(user_input, ai_reply, recent_context, llm)`）、`:21`（`_cap_candidates`，受 `memory_ingest_max_per_turn` 约束，`core/settings/memory.py:64` 默认 10） |
| 只有「合并同主题」的冲突消解，没有「聚合多事件」 | `apps/backend/app/services/memory/lifecycle.py:267`（`on_promoted`）→ 同主题 supersede/merge（`:308-313`）、`merge_chain` 追加（`:317-319`）；`apps/backend/app/engines/memory_conflict.py:27`（`same_topic`，LCS 相似度） |
| 后台 job 基建齐备可复用 | `app/services/memory/job_worker.py:31-34`（`_JOB_HANDLERS`）、`:41`（`register_job_type`）、`:46`（`register_tick_hook`）、`:71`（`run_job_tick`，末尾 flush `:81` / `:82`）、`:100`（`_claim`，SKIP LOCKED `:111`）、`:163`（退避重试）、`:183`（僵尸回收） |
| 已有「非直接摄取」来源先例 | `ingest_from_goal_completion`（`:346`）、`revision_listener` 式的事件触发（`app/services/planning/revision_listener.py:132`） |
| 产品读面的来源枚举当前 11 值 | `apps/backend/app/services/memory/product_view.py`（来源 `source_kind` / `source_label` 映射；消费端 `apps/mobile/lib/features/memory/**`、`tests/v50/test_memory_product_view.py`） |
| `layer` 列与写入形参由 `MEV-005` 提供 | 本目录 `MEV-005.md` §4.1.3 / §4.1.4；`app/core/db/memory.py`（`layer` + `ck_memories_layer`） |

### 2.2 为什么必须做

1. **碎片化直接损害召回质量**：一次「周末去露营」会产生若干条 `experience`（买了装备 / 去了哪里 / 天气如何），检索时任何一条都只覆盖片段；聚合成一条后，`MEV-001`（重排）与 `MEV-008`（分层配额）才有稳定的「情景单元」可排序。
2. **它是「语义抽象」的前置材**：`MEV-007` 需要「若干同类情景」作为抽象输入；没有 `MEV-006`，`MEV-007` 只能对碎片做抽象，噪声会指数放大。
3. **必须走既有评估，不得开旁路**：聚合是**生成行为**，若绕过三段评估（`evaluator.evaluate_candidate` `:443` / `evaluate_pending` `:479`），等于在记忆域开了第二个写入口——违背域唯一写面纪律（`tasks.md` §0.1）。

### 2.3 在本版本中的位置

M2 第 2 个任务；产出 `layer='episodic'` 的上层条目，是 `MEV-007`（语义抽象）与 `MEV-008`（配额）的共同输入。

## 3. Scope

### 3.1 In Scope

1. 新增 `app/services/memory/episodic.py`：窗口选材、主题分组、聚合产出候选、成绩上报。
2. 主题键与聚合内容的**确定性契约**（§4.1.2）——零 LLM（本任务不调 LLM）。
3. 后台接线：新增 job 类型 `memory_episodic_aggregate`（经 `register_job_type`）+ 周期 tick hook（经 `register_tick_hook`）。
4. 4 个新设置字段（§4.1.4）。
5. `product_view.py` 的来源枚举**扩 1 项**（`memory_aggregate`），并同步受影响的既有断言。
6. 防递归护栏：聚合产物**不得**作为下一次聚合的输入（§4.1.3）。
7. 新增用例（§7.1 / §7.2）。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不调 LLM** | 聚合是**确定性归组 + 拼接**；用 LLM 会引入成本与不确定性，且与 `MEV-007`（LLM 抽象）职责重叠 |
| 2 | **不新增表 / 不加列 / 不加迁移** | 复用 `memory_candidates` 唯一约束做幂等（`app/core/db/memory.py:104`）；`layer` 由 `MEV-005` 提供 |
| 3 | **不直写 `memories`** | 一律经 `create_candidate`（`ingest.py:67`）+ 既有三段评估（`evaluator.py:443` / `:479`）转正 |
| 4 | **不修改 `lifecycle.py` 的冲突消解 / 衰减数学** | 聚合产物的同主题冲突交给既有 `on_promoted`（`:267`）；改它属 Preserve 面变更 |
| 5 | **不做「事件 → 情景」的跨源复杂推断**（不做因果链、不做地点图谱） | 因果/时序关系属 `MEV-009` / `MEV-010`（图谱）；本任务只做「同窗同主题归组」 |
| 6 | **不改 `sources.py` 的既有查询语义** | 只读复用；如需新查询，在新模块内实现（不扩既有函数签名） |
| 7 | **不改 `ingest.py` 的既有五路摄取** | 新增的是**第六种候选来源**（聚合），既有四条 `ingest_from_*` 与 `ingest_from_conversation` 零改动 |
| 8 | **不新增 `*_enabled` 开关、不新增 Profile** | `tasks.md` §0.4 / 基线 ADR-7；用取值类 `memory_episodic_mode` |

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 选材契约（只读）

| 项 | 契约 |
|---|---|
| 输入集合 | 同一 `user_id`（+ `character_id`）的 active 记忆：`status='active'`、`layer='episodic'`、`type='experience'`、`created_at` 落在**窗口**内 |
| 窗口定义 | `[now - memory_episodic_window_hours, now]`（默认 12 小时）；窗口按 tick 触发时刻滑动，**不做固定日历边界** |
| **防递归护栏（硬）** | `source_ref` 指向 `memory_aggregate` 的记忆**必须排除**（否则每次 tick 都会在产物之上再聚合，形成无限层级） |
| 候选上限 | 每组产出的候选数 = 1；单次 job 最多处理 `memory_episodic_max_per_run` 组（默认 20），超出部分下一 tick 继续 |
| 最少事件数 | 组内事件数 `< memory_episodic_min_events`（默认 3）→ **该组跳过**（不产出候选） |

#### 4.1.2 分组与内容契约（零 LLM，确定性）

| 项 | 契约 |
|---|---|
| 主题键 | `theme_key(memory) -> str` **纯函数**：由 `source_ref` 的 `table` + 归一化后的内容主题词（规则在实现期冻结，**必须确定性、零随机、零 LLM**）拼成；同一输入恒定输出 |
| 组键 | `(user_id, character_id, theme_key)`（**不含**窗口——窗口只用于选材，故跨 tick 的同主题片段会归入同组并复用同一 `source_id`） |
| 聚合内容 | 由组内事件内容按 `created_at` **升序**拼接（分隔符与单条截断长度在实现期冻结）；**不引入模型改写** |
| 聚合 Salience | 取组内 `salience` 的最大值（不放大、不累加），写入候选 `salience_init` |
| 聚合 `source_ref` | 至少含 `{"table": "memory_aggregate", "source_ids": [<组内记忆 id 升序>], "window_start": <ISO>, "theme": <theme_key>}`（**升序**，保证确定性） |

#### 4.1.3 产出契约（写入）

| 项 | 契约 |
|---|---|
| 写入入口 | `ingest.create_candidate(...)`（`:67-79`），`layer='episodic'`（显式传参，`MEV-005` §4.1.4） |
| `source_table` | `"memory_aggregate"`（**新值**；需同步 `product_view` 来源枚举，见 §4.1.5） |
| `proposed_type` | `"experience"` |
| `source_id`（★ 幂等键） | `f"episodic:{theme_key}:{comma_join(sorted(source_ids))}"` → 同一组重复执行得到**同一** `source_id`，命中 `uq_memory_candidates_source`（`app/core/db/memory.py:104`）即返回既有行（`ingest.py:86-95`），**不产生重复** |
| 转正 | 与本任务无关——由既有评估链路（`evaluator.evaluate_pending` `:479`）决定；本任务**不直接**置 `memories` |
| 失败语义 | 单组构造/写入异常 → `logger.warning` + 跳过该组（继续处理其余组）；**整体不抛**（除数据库连接级错误交由 job 退避 `:163`） |

#### 4.1.4 新设置字段（`app/core/settings/memory.py`）

| 字段 | 类型 | 默认 | 语义 | 校验 |
|---|---|---|---|---|
| `memory_episodic_mode` | `str` | `"off"` | `off`（不运行）/ `auto`（按 tick 自动聚合） | 仅接受 `{"off","auto"}`；非法值回落 `off` + 启动期 warning |
| `memory_episodic_window_hours` | `int` | `12` | 选材时间窗（小时） | `ge=1`、`le=168`（1 周上限，防「一次聚合全部历史」） |
| `memory_episodic_min_events` | `int` | `3` | 成组的最小事件数 | `ge=2`（1 条无法构成「一段经历」） |
| `memory_episodic_max_per_run` | `int` | `20` | 单次 job 处理组数上限 | `ge=1`、`le=200` |

#### 4.1.5 产品读面来源枚举扩展（`app/services/memory/product_view.py`）

| 项 | 契约 |
|---|---|
| 新增映射 | `source_kind = "memory_aggregate"` → `source_label`（中文短语，措辞需与移动端记忆页既有文案风格一致，实现期冻结） |
| 枚举规模 | 11 值 → **12 值**（`source_kind` 是产品响应字段，属**向后兼容扩展**：新值只可能出现在新数据上） |
| 受影响断言 | `apps/backend/tests/v50/test_memory_product_view.py` 中若有「枚举值集合/数量」断言，须按扩展同步并**显式标注为契约扩展**（不得静默改期望值） |
| 兜底纪律 | 未知 `source_kind` 的兜底分支**保持不变**（仍回落），新增值走**显式映射**而非兜底 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **聚合零 LLM，纯确定性归组 + 拼接** | 与 `MEV-007`（LLM 抽象）分工明确；确定性让幂等可验证（同一输入同一 `source_id`） |
| D2 | **`source_id` 由「主题键 + 组内 id 升序」构成**，而非时间戳 | 若含时间戳，同一组的每次 tick 都会生成新 `source_id` → 幂等失效、候选爆炸；去掉窗口后跨 tick 自然复用 |
| D3 | **组键不含窗口**（窗口只用于「选材」） | 同上；且「一段经历」的天然边界是主题而非时间 |
| D4 | **硬禁止聚合产物作为输入**（防递归） | 否则每 tick 都在产物上再聚合，层级无限增长、候选量指数爆炸（本任务最危险的设计陷阱） |
| D5 | **必须经 `create_candidate` + 既有评估** | 域唯一写面纪律；绕过评估等于开第二写入口 |
| D6 | **`memory_aggregate` 走显式枚举而非兜底** | 产品读面必须给出有意义的中文来源（兜底文案会让用户看到「未知来源」） |
| D7 | **产品读面枚举扩展须显式声明** | `source_kind` 是产品字段；静默改既有断言会让契约变更不可追溯（`tasks/README.md` §5 第 6 条） |
| D8 | **单组失败隔离，整体不抛** | 记忆域降级纪律（R-M4）；一组脏数据不得让整轮聚合停摆 |
| D9 | **salience 取最大值而非累加** | 累加会让聚合条目天然压过单条真实经历（salience 影响衰减与检索）；取 max 表示「这段经历的重要性不超过其中最重的一件事」 |
| D10 | **`le=168` 的窗口上限** | 防误配导致「一次聚合全部历史」把召回质量与评估门槛一起打乱 |

### 4.3 数据流

```text
application/life_loop / worker_loop（既有常驻）→ job_worker.run_job_tick（:71）
   └─ tick hook（★ 本任务注册）→ episodic.run_aggregate_tick()
        ├─ memory_episodic_mode != "auto" → 直接返回（零动作）
        └─ 选材（只读）：status='active' ∧ layer='episodic' ∧ type='experience'
                        ∧ created_at ∈ [now-window, now]
                        ∧ source_ref.table != 'memory_aggregate'      ← 防递归（D4）
             ▼
        分组：theme_key(memory) → 组键 (user_id, character_id, theme_key)
             ├─ 组内事件数 < min_events → 跳过
             └─ 取前 max_per_run 组
             ▼
        每组 → create_candidate(
                   source_table="memory_aggregate",
                   source_id=f"episodic:{theme_key}:{sorted_ids}",
                   proposed_type="experience",
                   layer="episodic",
                   salience_init=max(salience),
                   source_ref_extra={table, source_ids(升序), window_start, theme})
             ├─ 命中 uq_memory_candidates_source（core/db/memory.py:104）→ 返回既有行（幂等）
             └─ 异常 → warning + 跳过该组（D8）
             ▼
        既有评估链路（不属本任务）：evaluator.evaluate_pending（:479）→ _promote（:227）
             → lifecycle.on_promoted（:267，同主题 supersede/merge）
             ▼
        产品读面：source_kind="memory_aggregate" → 中文来源标签（§4.1.5）

降级红线：读侧异常 → 跳过；写侧单组异常 → 跳过；整体不抛（除连接级错误交既有退避 :163）
```
