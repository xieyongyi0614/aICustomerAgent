## 2. Background

### 2.1 现状：链接只有「取代/合并/矛盾」三义，且检索完全不用链接

| 事实 | 证据 |
|---|---|
| `MemoryLinkRow` 与 CHECK 表达式 | `apps/backend/app/core/db/memory.py:109`（类）、`:110`（表名）、`:112-116`（列 `id`/`memory_id`/`related_memory_id`/`relation`/`created_at`）、`:119-122`（`ck_memory_links_relation`，表达式 `relation IN ('supersedes','merges','contradicts')`）、`:123`（`idx_memory_links_memory`，仅按 `memory_id`） |
| 链接的读写**全在 `lifecycle.py`**（仓储层无任何链接函数） | `apps/backend/app/services/memory/lifecycle.py:267`（`on_promoted`）、`:296-297`（contradicts 分支写 link）、`:320-321`（merges/supersedes 分支写 link）、`:333`（`_link_exists`）、`:346`（`_create_link`）、`:253-258`（purge 时删 link）；`app/repositories/memory_repository.py` **无** `MemoryLinkRow` 引用（已核实） |

| 迁移链尾与钉值 | `migrations/versions/` 含 `0001`~`0009`（`MEV-005` 将新增 `0010`）；`tests/support/schema_pins.py:13-17`（`MIGRATION_HEAD` / `MIGRATION_HEAD_PARENT` / `SCHEMA_TABLE_COUNT` / `SCHEMA_COLUMNS_DIGEST`）；摘要算法 `:39`（`table_column_digest`，**只取列名/类型/可空/主键**） |

### 2.2 为什么必须做

1. **`memory_links` 目前是「冲突处理的副产品」**：只有取代/合并/矛盾三义，且仅供 `lifecycle.on_promoted` 与冷却过滤使用（`retriever.py:177` 的 `_filter_reasons`）。记忆之间**最有用**的关系——「这件事是那件事引起的」「这件事发生在那件事之前」「这两件事相关」——**无处表达**（`docs/agent-evolution-plan-2026-10.md` §2.2 G-M2）。
2. **1-hop 扩展是「想起」的最廉价实现**：用户提到「露营」时，「买帐篷」这条未必直接命中，但它与「露营」有因果链；有了 `caused_by` 与 1-hop 扩展，角色能顺着关系想起。相比「多跳遍历 + 图排序」，1-hop 的成本与风险都可控（`MEV-010` 负责把关系抽出来）。
3. **必须先有值域，才有抽取与扩展**：`MEV-010`（关系抽取）要写入新关系，本任务若不做迁移，`MEV-010` 的写入会被 CHECK 拒绝——故本任务是 M3 的迁移闸。

### 2.3 在本版本中的位置

M3 第 1 个任务；本版本**第二次也是最后一次迁移**（`0011`），之后 M3 其余任务（`MEV-010~014`）全部零迁移。

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 迁移契约（`migrations/versions/0011_memory_link_relations.py`）

| 项 | 契约 |
|---|---|
| `revision` / `down_revision` | `"0011"` / `"0010"` |
| 步骤 1 | `op.drop_constraint("ck_memory_links_relation", "memory_links", type_="check")` |
| 步骤 2 | `op.create_check_constraint("ck_memory_links_relation", "memory_links", "relation IN ('supersedes','merges','contradicts','caused_by','before','related')")` —— **必须传完整布尔式**（不得传值清单，仓库已知陷阱） |
| 表数 / 列 | **均不变**（`SCHEMA_TABLE_COUNT = 57`；`SCHEMA_COLUMNS_DIGEST` **不变**——摘要只覆盖列元信息，CHECK 不参与） |
| `downgrade` | 反向：先删新 CHECK，再建 3 值 CHECK（**注意**：降级前须确认无新值数据，否则降级失败——契约要求降级脚本先 `UPDATE` 把新值归并到 `related` 再重建约束，保证可逆） |
| 幂等 | 重复 `create/drop` 同名校验失败即报错（迁移只跑一次），但迁移内不得依赖「已存在」语义 |
| 生成方式 | 手写（autogenerate 不识别 CHECK 值域变更） |

#### 4.1.2 模型契约（`app/core/db/memory.py`）

| 项 | 契约 |
|---|---|
| CHECK | 表达式与迁移**逐字符一致**（6 值，顺序：既有 3 值在前、新增 3 值在后） |
| 常量 | 在 `app/services/memory/types.py` 新增 `MEMORY_LINK_RELATIONS`（6 元组，顺序冻结）与 `MEMORY_LINK_RELATIONS_LEGACY`（3 元组，既有值）；模型与迁移的 CHECK 由同一常量构造，避免两处漂移 |
| 既有列 / 索引 | `:112-116` 五列与 `:123` 索引**零改动** |

#### 4.1.3 1-hop 扩展契约（`retriever.py`）

| 项 | 契约 |
|---|---|
| 生效条件 | `memory_graph_expand_mode == "one_hop"`（默认 `off`）；否则**不进入扩展分支**（逐字节一致） |
| 生效位置 | **最终排序之后、分层配额（`MEV-008`）之前**：种子 = 当前结果集前 `memory_graph_expand_seeds` 条 |
| 邻居获取 | `memory_repository.list_links(seed_ids, relations=MEMORY_LINK_RELATIONS)`（本任务新增）；邻居须为**同 user + active + 未被 hypothetical/冷却过滤**（复用既有过滤判定） |
| 排除 | 已在结果集中的记忆**不重复加入**；已 `forgotten`/`superseded` 的邻居不加 |
| 降权 | 扩展候选分数 = 其自身 `score` × `memory_graph_expand_decay`（默认 0.7）；**不改其原始分量** |
| 排序 | 扩展候选**整体排在全部直连命中之后**，内部按降权后分数降序、同分按 `memory.id` 升序（确定性） |
| 标记 | 扩展候选 `reason` 追加 `hop:<关系>`；trace 记录 `expand_mode` / `expanded_count` |
| **不触发加固（硬）** | `record_reinforce`（`:322`）**只对直连命中**执行——扩展是「顺带想起」，不得间接强化记忆（否则关系越密的记忆越被反复加固，形成富者愈富） |
| 与其他增强的顺序 | ① `MEV-002` 多 query 归并 → ② 过滤/惩罚 → ③ `MEV-001` 重排 → ④ **本任务 1-hop 扩展** → ⑤ `MEV-008` 配额截取 → ⑥ 加固 + trace |
| 失败语义 | `list_links` 异常 → `logger.warning` + 跳过扩展（等价 `off`），**不抛** |

#### 4.1.4 新设置字段（`app/core/settings/memory.py`）

| 字段 | 类型 | 默认 | 语义 | 校验 |
|---|---|---|---|---|
| `memory_graph_expand_mode` | `str` | `"off"` | `off` / `one_hop` | 仅接受 `{"off","one_hop"}`；非法回落 `off` + warning |
| `memory_graph_expand_seeds` | `int` | `3` | 作为种子的结果条数 | `ge=1`、`le=10` |
| `memory_graph_expand_decay` | `float` | `0.7` | 扩展候选的降权系数 | `gt=0`、`le=1.0`（>1 会放大邻居，禁止） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **只扩 CHECK，不加列** | CHECK 变更不影响 `SCHEMA_COLUMNS_DIGEST`（摘要只取列元信息，`schema_pins.py:39`），故钉测影响面只剩 `MIGRATION_HEAD` / `MIGRATION_HEAD_PARENT` 两项——这是本任务选择「扩值域」而非「加权重列」的关键理由 |
| D2 | **扩展只降权、不重排直连命中** | 直连命中是用户语义的直接证据，邻居只是推断；任何「邻居超越命中」的设计都需要可信度模型（未来议题） |
| D3 | **扩展候选不触发 `record_reinforce`** | 防止关系密度决定加固频率（富者愈富）；加固必须只由**直接命中**驱动（与基线语义一致） |
| D4 | **种子取最终排序前 N 条** | 种子质量决定扩展质量；取尾部会引入噪声邻居 |
| D5 | **`list_links` 落仓储层（只读）** | 现有链接读写全在 `lifecycle.py` 内（`:333` / `:346`）；检索侧需要**只读**查询，落仓储符合「DB 访问唯一面」纪律；不改既有私有写函数 |
| D6 | **值域顺序：既有 3 值在前** | CHECK 表达式的可比对性；同时让「既有值不变」在 diff 中一目了然 |
| D7 | **降级脚本先把新值归并到 `related` 再重建约束** | PostgreSQL 的 CHECK 变更在存在违约行时会失败；显式归并保证迁移可逆（可回滚是本版本迁移纪律的一部分） |
| D8 | **默认 `off`** | 与 `MEV-001` / `MEV-002` / `MEV-008` 一致：新能力默认不影响基线，效果由配置开启 |

### 4.3 数据流

```text

   ① MEV-002 归并 → ② 过滤/惩罚 → ③ MEV-001 重排 → ④ ★ MEV-009 1-hop 扩展
        parse mode：off → 跳过（逐字节一致）
```
