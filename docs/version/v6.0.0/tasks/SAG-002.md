## 2. Background

### 2.1 现状：Run 台账是「唯一递归单位」，但没有亲子关系

| 事实 | 证据 |
|---|---|
| Run 唯一写面 = `loop_runs` | `apps/backend/app/application/agent_runtime/controller.py:3-5`（模块 docstring 声明）、`:57-66`（`loop_run_repository.create_run(...)`） |
| `open_run` 签名（血缘需在此注入） | `controller.py:38-46`（`open_run(user_id, run_kind, trigger_type, reason, now=None, *, session_id=None) -> RunContext`）；`close_run` `:137` |

| 缺口（规划稿已登记） | `docs/agent-evolution-plan-2026-10.md` §4.4 G-S3（无父子 / 嵌套 Run 概念，无委派链观测） |
| 密钥/成本可观测已具备 | `contracts.py:186`（`RunResult`）、`:194-200`（字段含 `budget_account`） |

### 2.2 为什么必须做

1. **没有血缘，委派就是「黑箱」**：子 Agent 的 Run 若无法关联到父 Run，排查「这个结论是谁得出的、花了多少预算、为什么失败」只能靠时间戳碰运气（`docs/agent-evolution-plan-2026-10.md` §4.4 G-S3）。
2. **它是 `SAG-003`（派发器）的必要配套**：派发必然产生新的 Run；若不先有血缘字段，派发器无法回投结果到正确的父上下文。
3. **必须复用既有观测面**：`execution_history` / `debug_view` / `debug/observability.py` 已构成完整只读栈（`:127` / `:151` / `:68` / `:32`）；新增独立观测体系会制造第二份真相。

### 2.3 在本版本中的位置

S 线第 2 个任务：**仅在 `SAG-000` 裁决放开且 `SAG-001` 提供身份后**开工。它是 S 线**唯一需要迁移**的任务（`0012`）。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不做并行调度 / DAG 执行** | `asyncio.gather` 全库仅 4 处且不可复用（§2.1）；并行属独立议题，且会与「单管线」纪律张力最大 |

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 迁移契约（`migrations/versions/0012_run_lineage.py`）

| 项 | 契约 |
|---|---|
| `revision` / `down_revision` | `"0011"` / `"0010"` |
| 步骤 1 | `op.add_column("loop_runs", sa.Column("parent_run_id", sa.String(length=32), nullable=True))` |
| 步骤 2 | `op.add_column("loop_runs", sa.Column("delegation_kind", sa.String(length=32), nullable=True))` |
| 步骤 3 | `op.create_check_constraint("ck_loop_runs_delegation_kind", "loop_runs", "<完整布尔式：delegation_kind IS NULL OR delegation_kind IN (...)>")` —— **必须完整布尔式**（含 `IS NULL`，否则既有行违约） |
| 步骤 4 | `op.create_index("idx_loop_runs_parent", "loop_runs", ["parent_run_id"])` |
| `delegation_kind` 值域（★ 冻结，候选取值，最终由 `SAG-000`/`SAG-003` 确认） | `task_delegate`（任务委派）/ `sub_query`（子查询）/ `agent_tool`（Agent-as-Tool） |
| 表数 | **不变**（零新表） |
| `downgrade` | 逆序删除（先索引 → CHECK → 两列） |
| 既有行 | `parent_run_id IS NULL` + `delegation_kind IS NULL` → **语义 = 无委派**（与基线等价，AC3） |

#### 4.1.2 模型与开 Run 契约

| 项 | 契约 |
|---|---|
| 模型同步 | `loop_runs` 模型新增两列 + CHECK + 索引，与迁移**逐项一致**（由 §7.1 的 schema 断言核验） |
| `open_run` 形参 | 追加 `parent_run_id: str \| None = None` 与 `delegation_kind: str \| None = None`（**带默认值** → 既有调用点零改动） |
| 校验 | 非空 `delegation_kind` 必须在值域内；`parent_run_id` 必须存在且属**同一 `user_id`**（否则 fail-closed：拒绝开 Run） |
| 写面 | 仍只经 `loop_run_repository.create_run`（`controller.py:57-66`）；不新增写函数（如需，须带默认值且不改既有签名） |
| 既有路径 | 未传血缘 → 两列为 NULL，行为与基线**逐字节一致**（D2） |

#### 4.1.3 参与树只读契约

| 项 | 契约 |
|---|---|
| 能力 | 由父 Run id 得「子 Run 列表」（一层）；递归可得深度 ≤ N 的树（N 由调用方限制，建议 ≤ 3） |
| 落点 | `app/application/agent_runtime/execution_history.py`（新增只读查询）与 `debug_view.py`（在既有 `debug_view` 结果中附「子树摘要」） |
| 读面 | 经既有 `/debug/turns/{turn_id}/trace`（`observability.py:32`）与既有 `debug_views_for_session`（`debug_view.py:73`）；**不新增端点**（D4） |
| 字段 | 每个节点：`run_id` / `run_kind` / `status` / `parent_run_id` / `delegation_kind` / `started_at` / `duration_ms`（**不暴露** payload / 用户输入全文） |
| 边界 | 单次查询节点数上限 `LINEAGE_NODE_LIMIT = 50`（模块常量，防大树） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **两列均可空 + CHECK 含 `IS NULL`** | 既有 Run 行必须无痛升级；CHECK 若不含 `IS NULL` 会让迁移在存量行上失败（仓库已知陷阱的同类风险） |
| D2 | **未传血缘 = 基线等价（逐字节）** | 既有前台/自治 Run 不能因新列而变化；这是本任务最硬的回归判据 |
| D3 | **`parent_run_id` 必须同用户** | 血缘跨用户会立即构成越权面（可推断他人计划/Run 存在性）→ fail-closed |
| D4 | **不新增端点，走既有 debug 读面** | 调试面治理成本高（ADR-17）；`debug_view` 已能承载子树摘要 |
| D5 | **`delegation_kind` 值域冻结为三类** | 三类覆盖了 `SAG-000` 可能选定的落点（S-A / S-C）；扩值域需新迁移（纪律：一次迁移只承载一个域面） |
| D6 | **不给 `loop_runs.steps` 加键** | 键集断言冻结 |
| D7 | **不做深度 > 1 的调度语义** | 本任务只记录；多层委派的调度策略属 `SAG-003`（且需裁决支持） |
| D8 | **节点数上限 50** | 防「一次查询整棵大树」；与 `MEV-005` / `PLN-005` 的批次上限同源的成本护栏 |
| D9 | **迁移号承接 `0010`** | `MEV-005` 与 `MEV-009` 合并入 `0010`（`docs/version/v6.0.0/tasks.md` §0.2）；串行入链，不得并行改链尾 |

### 4.3 数据流

```text
【迁移】alembic upgrade head（0010 → 0011）
   add_column parent_run_id（NULL 允许） + delegation_kind（NULL 允许）
   → create_check_constraint ck_loop_runs_delegation_kind（含 IS NULL 的完整布尔式）
   → create_index idx_loop_runs_parent
   → schema_pins：MIGRATION_HEAD="0011" / PARENT="0010" / TABLE_COUNT 不变 / COLUMNS_DIGEST 重算（新增两列）

【开 Run】controller.open_run（:38）
   既有调用（不传血缘）→ 两列 NULL → 行为逐字节等于基线（D2）
   委派调用（传血缘）→ 校验 delegation_kind 值域 + parent 同用户（fail-closed）
                       → loop_run_repository.create_run（:57）写入两列

【只读】execution_history（:40/:127/:151）+ debug_view（:68/:73）→ 参与树（节点上限 50）
   经既有 /debug/turns/{turn_id}/trace（observability.py:32）读取；不新增端点

红线：零新表；不给 loop_runs.steps 加键；既有路径零变化
```

| 类别 | 内容 |
|---|---|
