## 2. Background

### 2.1 现状：跨事件抽象只有「反思」与「成长」，且都不进记忆检索

| 事实 | 证据 |
|---|---|
| 记忆域有类型体系但**无抽象生成路径** | `apps/backend/app/services/memory/types.py:9-17`（7 规范类型含 `behavior_pattern` / `user_preference`）；写入口只有摄取五路 + 命令通道（`ingest.py:116` / `:171` / `:237` / `:272` / `:311` / `:346`；`commands.py`） |
| 既有跨事件加工在**别的域**，且不进记忆检索 | `apps/backend/app/services/reflection/`（Insight，三闸复检）；`apps/backend/app/services/development/`（belief / preference / pattern → 编译为人格轴调制）；基线 §3.6 将二者描述为「反思/成长上层」 |
| 冲突消解是「同主题取代/合并」，不是「跨事件抽象」 | `apps/backend/app/services/memory/lifecycle.py:267`（`on_promoted`）、`:308-313`（supersede/merge 判定）、`apps/backend/app/engines/memory_conflict.py:27`（`same_topic`） |
| lite LLM 与结构化输出范式齐备 | `apps/backend/app/chains/structured.py:66-68`（`build_structured_chain`）；`apps/backend/app/services/memory/evaluator.py:47` / `:79-81`（lite profile 先例） |
| 记忆域「明细永不进 Prompt」纪律 | 基线 §3.3 数据治理：财务数据 L1 受控保存，**明细永不进 Prompt**；`docs/version/v4.0.0/tasks.md` 裁决 2：记忆域只承接**抽象模式**，「金额明细永不进记忆」 |
| 后台 job 基建可复用 | `app/services/memory/job_worker.py:31-34`（`_JOB_HANDLERS`）、`:41`（`register_job_type`）、`:46`（`register_tick_hook`） |
| 三段评估是转正唯一通道 | `apps/backend/app/services/memory/evaluator.py:443`（`evaluate_candidate`）、`:479`（`evaluate_pending`）、`:227`（`_promote`） |

### 2.2 为什么必须做

1. **「情景」只解决粒度，「语义」才解决复用**：`MEV-006` 把碎片合成「一段经历」，但用户问「我平时喜欢什么」时，需要的是**跨经历的认识**（偏好 / 习惯），而非某一次经历。这正是 `docs/agent-evolution-plan-2026-10.md` §2.3 M2.3 的动机。
2. **它与 Reflection / Development 职责不重叠**：Reflection 产出 Insight（**证据链推理**，服务于反思与人格），Development 产出人格调制（**不参与记忆检索**）。本任务产出的是**记忆条目**——可被 `retriever` 检索、可被 `memory_refs` 引用、可被用户在产品页看见与遗忘。三者是不同真相面（R-M3）。
3. **必须有防幻觉与防明细的硬护栏**：抽象是「归纳」，最容易出现两类问题——类型跑偏（返回不存在的类型）与把金额明细带进记忆内容（违反治理纪律）。故判据把「类型 fail-closed」与「明细禁入」写成硬项。

### 2.3 在本版本中的位置

M2 第 3 个任务；与 `MEV-006` 共同构成「双通道」：episodic（时间线经历）+ semantic（跨事件认识）。它是 `MEV-008`（分层配额）的另一半输入。

| # | 禁止项 | 理由 |

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 链契约（新增 `app/chains/memory_semantic_abstract_chain.py`）

| 符号 | 契约 |
|---|---|
| `SemanticAbstractItem` | Pydantic：`content: str`（≤ `SEMANTIC_CONTENT_MAX_CHARS = 200`）、`proposed_type: str`、`reason: str = ""`（调试用，不入候选） |
| `SemanticAbstractResult` | Pydantic：`items: list[SemanticAbstractItem]`（**长度必须为 1**；非 1 视为失败） |
| `build_semantic_abstract_chain(llm=None) -> Runnable` | 经 `build_structured_chain`（`:66-68`）；`llm` 缺省 `get_llm("lite")`（`core/llm_factory.py:37`） |
| `async abstract_from_episodes(theme: str, episodes: list[tuple[str, str]], llm=None) -> SemanticAbstractItem \| None` | `episodes` = `(memory_id, content)` 按 `created_at` 升序；**类型不在白名单 → 抛 `ValueError`**（由调用方 catch 并记为 fail-closed 丢弃）；链内部**不做类型猜测** |
| 允许类型白名单（★ 冻结） | `SEMANTIC_TYPES = ("user_preference", "user_fact", "behavior_pattern", "relationship_fact", "commitment")`——**不得**包含 `experience` / `milestone_event`（情景类型不可作为语义抽象产物） |
| prompt 纪律 | system 段：① 只做归纳、不得虚构未出现的事实；② 类型只能取白名单值；③ **禁止**出现金额、账号、流水等账目明细；④ 输出长度上限 |

#### 4.1.2 选材与回路契约

| 项 | 契约 |
|---|---|
| 输入集合 | `status='active'`、`layer='episodic'`（**含** `MEV-006` 的聚合产物）、`created_at` 不限窗口（语义抽象是「累积归纳」，用组内条数而非时间窗触发） |
| **自反馈不可能（论证）** | 本模块只读 `layer='episodic'`；产物写 `layer='semantic'` → 产物永不在输入集合内。且 `MEV-006` 已排除 `source_ref.table='memory_aggregate'` 作为其输入 → 两个模块之间**无环** |
| 分组 | 复用 `episodic.theme_key`（`MEV-006` §4.1.2）作为组键的组成部分：`(user_id, character_id, theme_key)` |
| 触发条件 | 组内**未抽象过**的情景条数 ≥ `memory_semantic_min_sources`（默认 3） |
| 「未抽象过」判定 | 组内情景条目的 id 集合中，存在**未被任何既有 semantic 记忆的 `source_ref.source_ids` 覆盖**的条目（保证新情景追加后会再次触发，而已覆盖的不重复抽象） |
| 单次上限 | 最多 `memory_semantic_max_per_run` 组（默认 5） |

#### 4.1.3 产出契约（写入）

| 项 | 契约 |
|---|---|
| 写入入口 | `ingest.create_candidate(...)`（`ingest.py:67-79`），`layer="semantic"` 显式传参 |
| `source_table` / `proposed_type` | `"memory_aggregate"` / 由抽象结果给出（必须在白名单内） |
| `source_id`（★ 幂等键） | `f"semantic:{theme_key}:{comma_join(sorted(source_ids))}"` |
| `source_ref` | `{"table":"memory_aggregate","source_ids":[<升序>],"theme":<theme_key>,"abstract_kind":"semantic"}` |
| `salience_init` | 组内情景条目 `salience` 的**最大值**（不放大） |
| 明细护栏（硬） | 产出前对 `content` 做**确定性检查**：命中金额/账号类模式（正则集合在实现期冻结）→ **丢弃该候选** + warning（不脱敏后写入——避免留下「半个事实」） |
| 转正 | 由既有评估链路决定（`evaluator.evaluate_pending` `:479`）；本任务不直接写 `memories` |
| 失败语义 | 链异常 / 类型越界 / 长度越界 / 命中明细护栏 → `logger.warning` + 跳过该组；**整体不抛** |

#### 4.1.5 与 Reflection / Development 的边界（写入契约的一部分）

| 面 | 本任务产物 | 不产出的东西 |
|---|---|---|

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **类型白名单 fail-closed**（越界抛错 → 丢弃，不回落） | 回落猜测等于让模型输出决定记忆类型体系；`ck_memories_type`（`core/db/memory.py:61-66`）也不接受白名单外的语义类型组合（如 `experience` 出现在 semantic 层会造成语义混乱） |
| D2 | **只读 `episodic`，产物 `semantic`** → 天然无环 | 若允许读 `semantic`，抽象会自我强化（抽象 → 再抽象 → 内容漂移），且无法用配置阻止 |
| D3 | **用「未覆盖来源」而非时间窗触发** | 语义是累积性的；用时间窗会让「上周已抽象过的组」在本周被重复抽象，产生近似重复条目（虽幂等键可挡同一 id 集合，但新情景追加后会重新触发——这正是期望行为） |
| D4 | **命中账目明细模式直接丢弃，不脱敏** | 脱敏会留下残缺事实（「用户每月在 ████ 花费约 2000 元」），既违背「明细永不进记忆」，又制造不可解释的半真相 |
| D5 | **产物是记忆条目，不是 Insight / 人格调制** | 三者真相面不同（§4.1.5）；混淆会造成同一事实两份真相（R-M3） |
| D6 | **`salience` 取 max** | 与 `MEV-006` D9 同源：抽象条目不应压过其最重的原始经历 |
| D7 | **不做情感 / 关系阶段推断** | 跨域推断会造成与 `services/relationship/**` 的两套关系真相 |
| D8 | **不直接 supersede / invalidate** | 冲突消解是既有 `on_promoted`（`lifecycle.py:267`）的职责；跨任务改写状态机会破坏状态机不变量（`TRANSITIONS` `:48-62`） |
| D9 | **链内不做类型猜测，越界即抛** | 与 `MEV-001` D3 同源：宁可丢弃也不让模型「补齐」 |
| D10 | **本任务零迁移、零表** | 复用候选表（`uq_memory_candidates_source` `:104`）做幂等；`layer` 由 `MEV-005` 提供 |

### 4.3 数据流

```text
job_worker.run_job_tick（:71）→ tick hook（★ 本任务注册）→ semantic.run_abstract_tick()
   ├─ memory_semantic_mode != "auto" → 直接返回（零动作、零 LLM 调用）
   └─ 选材（只读）：status='active' ∧ layer='episodic'（含聚合产物）
         → 分组 theme_key（复用 MEV-006）→ 组键 (user_id, character_id, theme_key)
              ├─ 未抽象过的新情景条数 < min_sources → 跳过
              └─ 取前 max_per_run 组
         ▼
      每组 → chains/memory_semantic_abstract_chain.py::abstract_from_episodes(theme, episodes)
              ├─ 异常 / 类型越界 / 长度越界 → warning + 跳过该组（D1/D9）
              └─ 明细护栏命中 → warning + 丢弃该组（D4）
         ▼
      create_candidate(source_table="memory_aggregate",
                       source_id=f"semantic:{theme_key}:{sorted_ids}",
                       proposed_type=<白名单内>, layer="semantic",
                       salience_init=max(salience),
                       source_ref_extra={table, source_ids(升序), theme, abstract_kind:"semantic"})
         ├─ 命中 uq_memory_candidates_source → 返回既有行（幂等）
         └─ 异常 → warning + 跳过该组
         ▼
      既有评估链路（不属本任务）：evaluator.evaluate_pending（:479）→ _promote（:227）
         → lifecycle.on_promoted（:267，同主题 supersede/merge）
         ▼
      检索侧（M1 能力自动受益）：retriever 可召回 semantic 条目 → memory_refs 可引用

降级红线：链失败 → 跳过该组；护栏命中 → 丢弃该组；整体不抛
边界红线：不落 insights / evidence_links / development_state（§4.1.5）
```
