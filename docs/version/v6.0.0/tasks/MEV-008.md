## 2. Background

### 2.1 现状：检索无分通道配额，衰减速率只按类型

| 事实 | 证据 |
|---|---|
| 检索最终排序/截取在 `retrieve` 内，权重全自 settings 读 | `apps/backend/app/services/memory/retriever.py:265-271`（`retrieve(user_id, query, character_id="asuna", top_k=None, trace=None)`）；权重 `:247-249` / `:252` / `:309` / `:311` |
| 默认召回条数设置存在 | `apps/backend/app/core/settings/memory.py:12`（`memory_top_k: int = 5`） |
| 候选池上限与向量召回上限 | `core/settings/memory.py:25`（`memory_candidate_pool_limit=200`）、`:62`（`memory_vector_recall_k=20`） |
| 过滤与惩罚在排序前统一执行 | `retriever.py:280` / `:292`（hypothetical 剔除）、`:306`（冷却过滤应用）、`:309` / `:311`（penalty） |
| 加固与 trace 在结果确定后执行 | `:322`（`record_reinforce`）、`:323-330`（trace，步名 `:28`） |
| 衰减速率**只**按类型查表 | `apps/backend/app/services/memory/lifecycle.py:91`（`decay_lambda_for`）；配置 `core/settings/memory.py:39-44`（`memory_decay_lambda_json`，覆盖 7 规范类型） |
| 衰减公式与按日桶幂等 | `lifecycle.py:172`（`_decay_batch`，公式 `salience·exp(-λ·Δdays)` `:194`）、`:162`（`run_decay_cycle`） |
| `layer` 列由 `MEV-005` 提供 | `app/core/db/memory.py`（`layer` + `ck_memories_layer`）；本目录 `MEV-005.md` §4.1.3 |

### 2.2 为什么必须做

1. **没有配额，分层只是「标签」**：`MEV-006` / `MEV-007` 让 episodic 条目显著增多（聚合会产生比原始碎片更少的条目，但语义层会更慢积累），若同一 `top_k` 池内混排，某一层很容易把另一层挤出（`docs/agent-evolution-plan-2026-10.md` §2.3 M2.4 的动机）。
2. **没有衰减差异，情景会「赖着不走」**：情景条目的价值随时间快速衰减（「上周吃了日料」很快不重要），而语义认识（「用户不吃香菜」）应长期稳定。当前 `memory_decay_lambda_json` 按类型给了 `experience` 0.03，但**无法区分**「同样是 experience 类型的聚合情景」与「跨事件认识」——分层乘数正好补上这一维。
3. **必须能一键回到基线**：两项都是**纯参数**，空值即关闭；这是把「调优」与「行为变更」解耦的标准做法（`tasks.md` §0.4）。

### 2.3 在本版本中的位置

M2 收尾任务：M1 让排序更准、M2 前三个任务让条目更有结构；本任务让结构**在检索与生命周期两个出口上真正生效**。此后 M3（图谱与产品面）才在稳定的两层语义上叠加。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不改衰减公式**（`salience·exp(-λ·Δdays)` `:194`） | 公式是既有生命周期数学的核心（`docs/agent-evolution-plan-2026-10.md` §2.5 R-M3 关联的「分层不引入双重真相」）；本任务只调 λ |
| 2 | **不改 `TRANSITIONS` 状态机**（`:48-62`） | 状态转移是审计与重放的依据；调参数与改状态机是两类变更 |
| 3 | **不改检索打分数值**（`_recency` `:98` / `_structured_score` `:106` / `_affinity_score` `:113`） | 配额只做**截取**；改分会让 M1 的所有对照失效 |
| 4 | **不做「层内再配额」**（如 episodic 内部按类型再分配） | 会引入两级配额的组合爆炸与不可解释性；单层参数已足够 |

| 6 | **不改 `MEV-006` / `MEV-007` 的运行逻辑** | 两者只被读取（`layer` 分布）；改它们会把「调参」变成「改生成」 |
| 7 | **不新增表 / 不加列 / 不加迁移** | 两个参数都是运行期配置，无结构变更 |
| 8 | **不新增 `*_enabled` 开关、不新增 Profile** | `tasks.md` §0.4 / 基线 ADR-7；两个字段都是取值类 |

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 配额解析契约

| 项 | 契约 |
|---|---|
| 字段 | `memory_layer_quota: str`，格式 `"<episodic>:<semantic>"`，如 `"3:5"` |
| 禁用态 | **空串 `""`（默认）** → 不限额，`retrieve` 行为与基线**逐字节一致** |
| 解析 | `parse_layer_quota(raw: str) -> tuple[int, int] \| None`：合法 → `(episodic_weight, semantic_weight)`；非法（非 `a:b` 形态 / 非整数 / 任一 ≤ 0 / 任一 > 100）→ 返回 `None` + `logger.warning`（**回落禁用态**，不抛） |
| 确定性 | 纯函数；同一输入恒定输出 |

#### 4.1.2 配额截取契约（`app/services/memory/retriever.py`）

| 项 | 契约 |
|---|---|
| 生效位置 | **最终排序之后、截取之时**：即 `MEV-002` 归并 → 过滤/惩罚 → `MEV-001` 重排排序 **之后**，`record_reinforce`（`:322`）与 trace（`:323-330`）**之前** |
| 目标条数 | `N = top_k or settings.memory_top_k`（`:12`，默认 5） |
| 名额分配 | `episodic_quota = floor(N × a / (a + b))`、`semantic_quota = N - episodic_quota`（`a:b` 为 §4.1.1 解析值）；**确定性取整，无随机** |
| 选取方式 | 在**既有最终次序**上分别按层取前 N 名额；层内保持原次序（不再重排） |
| 补齐规则 | 若某层可选项少于其名额 → 该层全取，**剩余名额由另一层按既有次序补齐**，保证结果条数 == `min(N, 候选总数)` |
| 分数不变（硬） | 配额**只影响「取哪些」**，不修改任何 `score` / `rerank_score` / 分量；被截掉与未被截掉的条目分数不受影响 |
| `layer` 缺失容错 | `memory.layer` 为空/未知 → 归入 `DEFAULT_LAYER`（`MEV-005` §4.1.3）并记一次 warning 聚合（不逐条刷日志） |
| 加固与 trace | `record_reinforce` 与 trace 基于**截取后**的结果集（与基线同口径：基线也是基于最终结果集） |
| 关闭态 | 配额 `None`（禁用或非法）→ **不进入配额分支**，走既有截取代码（逐字节一致） |

#### 4.1.3 衰减调制契约（`app/services/memory/lifecycle.py`）

| 项 | 契约 |
|---|---|
| 函数签名 | `decay_lambda_for(memory_type: str, layer: str \| None = None) -> float`（`:91`；`layer` **带默认 `None`** → 既有调用点零改动） |
| 计算式 | `λ_effective = λ_type × multiplier(layer)`；`multiplier` 从 `memory_decay_layer_multiplier_json` 读取；表为空或缺 `layer` 或缺 `layer is None` → `multiplier = 1.0`（**逐字节不变**） |
| 配置形态 | `memory_decay_layer_multiplier_json: str = "{}"`，形如 `{"episodic": 1.5, "semantic": 0.6}` |
| 解析 | 非法 JSON / 非数值 / 负值 → 视为空表（`1.0`）+ `logger.warning`（**不抛**）；`multiplier` 允许 `(0, 10]` |
| 调用点 | `_decay_batch`（`:172`）内取记忆的 `layer` 传入；`run_decay_cycle`（`:162`）流程不变 |
| 幂等 | 按日桶幂等游标（`last_decayed_at`）语义不变；乘数只影响单次衰减幅度 |
| 保底 | 与既有 `memory_salience_floor`（`core/settings/memory.py:37`）的交互不变（压到 floor → `decayed`，`TRANSITIONS` `:54`） |
| 硬约束 | **公式与压底逻辑不改**；只改 λ 的取值来源 |

#### 4.1.4 新设置字段（`app/core/settings/memory.py`）

| 字段 | 类型 | 默认 | 语义 | 校验 |
|---|---|---|---|---|
| `memory_layer_quota` | `str` | `""` | `""` = 不限额；`"a:b"` = episodic : semantic 名额权重 | 由 §4.1.1 解析；非法回落禁用 |
| `memory_decay_layer_multiplier_json` | `str` | `"{}"` | 按层的 λ 乘数表 | 由 §4.1.3 解析；非法视为空表 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **空值即禁用**（配额与乘数都是） | 让「行为变更」与「参数调优」解耦：本任务合入时**行为逐字节不变**，效果由配置开启；这对既有回归基线最友好 |
| D2 | **配额只在截取阶段生效，不改分数** | 分数是 M1（重排/改写）与评估门槛的对照量；改分会让所有对照失效 |
| D3 | **名额用 floor 确定性分配 + 另一层补齐** | 必须保证「结果条数 == 期望条数」（用户可感知的稳定性），且分配可测；随机或按比例抽样会造成不可复现 |
| D4 | **层内不再重排** | 层内次序已是 M1 的最终排序结果；再排会让 M1 的重排名次失去意义 |
| D5 | **乘数调制而非新增 λ 表** | 新增整张 λ 表会让「类型级」与「层级」形成两套真相（改一处忘一处）；乘数保证类型级仍是唯一基准，层只是调制 |
| D6 | **乘数非法回落 1.0（而非 0 或跳过衰减）** | 0 会让 `exp(-0)` = 1、记忆永不衰减（静默失控）；1.0 等价「未配置」，是唯一安全的回落 |
| D7 | **`layer=None` 时行为与基线逐字节一致** | 既有调用点（可能未传 layer）必须零风险；这也让本任务可**分两步合入**（先改签名，再改调用点） |
| D8 | **`layer` 缺失/未知归入 `DEFAULT_LAYER`** | 与 `MEV-005` D5 的「未知类型 warning + 回落」同源；配额不得因脏数据抛错 |
| D9 | **warning 聚合而非逐条** | 检索是热路径；逐条 warning 会淹没日志（既有降级先例也是单条 warning：`retriever.py:344-346`） |
| D10 | **本任务零迁移** | 两个参数都是运行期配置 |

### 4.3 数据流

```text
【检索侧】retrieve（retriever.py:265）
   ① 召回：MEV-002 多 query 归并（或单路） ② 过滤：:280 / :292 / :306  ③ 惩罚：:309 / :311
   ④ MEV-001 重排排序（rerank_mode off/lite）
        ▼ ★ MEV-008 新增：配额截取
     parse_layer_quota(settings.memory_layer_quota)
        ├─ None（禁用/非法） → 既有截取路径（逐字节一致，D1）
        └─ (a,b) → N = top_k or memory_top_k

                    逐层按既有次序取前名额 → 层不足则由另一层按既有次序补齐
        ▼
   ⑤ record_reinforce（:322）+ trace（:323-330）基于截取后结果集

【生命周期侧】run_decay_cycle（lifecycle.py:162）→ _decay_batch（:172）
       λ = decay_lambda_for(memory.type, memory.layer)          ← ★ MEV-008 新增第二形参
            = λ_type（core/settings/memory.py:39-44）
              × multiplier(layer)（memory_decay_layer_multiplier_json；缺省 1.0）
       salience ← salience · exp(-λ · Δdays)                     ← 公式不变（:194）
       压到 memory_salience_floor（:37）→ decayed（TRANSITIONS :54）  ← 不变

红线：两者关闭态（"" / "{}"）时必须与基线逐字节一致；异常一律回落禁用态 + 单条 warning
```
