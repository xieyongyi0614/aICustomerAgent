### 2.2 为什么必须做

1. **`MEV-006` / `MEV-007` 的产物必须可区分**：情景条目（按时间线聚合）与语义条目（跨事件抽象）若同处扁平类型空间，`MEV-008` 的配额、衰减差异化与检索分通道**都无处落脚**（`docs/agent-evolution-plan-2026-10.md` §2.3 阶段 M2）。
2. **它是 M2 的迁移闸**：M2 的其余三个任务全部建立在 `layer` 列之上；先落迁移可让后续任务并行开发而不互相阻塞。
3. **必须一次做对写入侧**：若只加列不回填、不在写入路径赋值，`layer` 会长期为 NULL/错误值，让「通道」沦为装饰列——故本任务的判据把「写入路径一致性」也纳入（`layer ≡ layer_for_type(type)`）。

### 2.3 在本版本中的位置

M2 第 1 个任务；本版本**两次迁移中的第一次**（第二次为 `MEV-009` 的 `memory_links.relation` 扩展）。它不改任何检索行为，是纯结构 + 数据 + 写入对齐。

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 迁移契约（`migrations/versions/0010_memory_layer.py`）

| 项 | 契约 |
|---|---|
| `revision` / `down_revision` | `"0010"` / `"0009"` |
| 步骤 1 | `op.add_column("memories", sa.Column("layer", sa.String(length=16), nullable=False, server_default="semantic"))` —— 以 `server_default` 保证存量行**立即非空**，避免 NULL 窗口 |
| 步骤 2 | 幂等回填：`UPDATE memories SET layer='episodic' WHERE type IN ('experience','milestone_event','important_event') AND layer <> 'episodic'` |
| 步骤 3 | `op.alter_column("memories", "layer", server_default=None)` —— **撤掉默认值**，使未来「漏设 `layer` 的写入」**显式失败**（fail-closed），而不是静默落 `semantic` |
| 步骤 4 | `op.create_check_constraint("ck_memories_layer", "memories", "layer IN ('episodic','semantic')")` —— **必须传完整布尔式**（`f"layer IN {MEMORY_LAYER_VALUES}"` 形态），不得只传值清单（仓库已知陷阱） |
| 步骤 5 | `op.create_index("idx_memories_user_layer_status", "memories", ["user_id","layer","status"])` |
| 表数 | **不变**（`SCHEMA_TABLE_COUNT = 57`，零新表） |
| `downgrade` | 逆序：删索引 → 删 CHECK → 删列 |
| 幂等要求 | 重复执行迁移（或重复执行步骤 2 的等价 SQL）结果不变 |
| 生成方式 | 由 `Base.metadata` autogenerate 生成后**人工校正**（对齐 `0001` 的既有做法：CHECK 完整布尔式、`server_default` 显式化） |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **`layer` 落真实列，而非计算属性** | `MEV-008` 的配额与索引需要 SQL 层过滤/排序；计算属性无法建索引，且每次检索都要在 Python 侧重算 |
| D2 | **两值枚举 + CHECK**，不做多值/可空 | 「通道」本身只有两种；CHECK 让非法值在写入即失败（对齐 `ck_memories_type` 的既有做法） |
| D3 | **迁移期用 `server_default` 兜存量行，随后撤掉** | 既避免 NULL 窗口，又让「未来漏设」显式失败（fail-closed）；模型侧保留 Python 默认以免测试大规模崩 |
| D4 | **回填只把 `episodic` 类型改为 episodic，其余保持 `semantic`** | 用 `server_default="semantic"` 作基座后，只需一条定向 UPDATE；语句幂等（带 `layer <> 'episodic'` 守卫） |
| D5 | **`layer_for_type` 覆盖全部 9 值且未知值 warning 回落** | 与 `MEV-003` D4 同源：必须用枚举断言钉住覆盖完整性；未知值不抛（记忆域降级纪律） |
| D6 | **`ingest.create_candidate` 的 `layer` 形参带默认 `None`** | 既有调用点零改动；`MEV-006` / `MEV-007` 需要显式指定时才有实参 |
| D7 | **`layer` 不做权限 / 来源真相** | 来源真相永远是 `source_ref` + `memory_candidates`（R-M3）；`layer` 只作检索分通道与生命周期差异化的依据 |
| D8 | **不加启动回填** | 启动期数据改写会让「迁移已跑过」与「应用已启动」产生两套真相；`0001` 折叠后纪律是「结构变更只在迁移里」 |
| D9 | **CHECK 用完整布尔式** | 仓库已知陷阱：`create_check_constraint` 传值清单会在 PG 上 `DatatypeMismatch` |
| D10 | **本任务零设置** | 分层值域由类型映射决定，无灰度语义；设开关会制造「类型与层不一致」的合法态 |

### 4.3 数据流

```text
【迁移侧】alembic upgrade head（0009 → 0010）
   add_column(layer, NN, server_default='semantic')
   → UPDATE ... SET layer='episodic' WHERE type IN ('experience','milestone_event','important_event') AND layer <> 'episodic'
   → alter_column(server_default=None)
   → create_check_constraint ck_memories_layer（完整布尔式）
   → create_index idx_memories_user_layer_status
   → tests/support/schema_pins.py：MIGRATION_HEAD="0010" / PARENT="0009" / TABLE_COUNT=57 / COLUMNS_DIGEST=重算

【写入侧（三条路径，本任务对齐）】
  ① ingest.create_candidate（:67）  → layer = arg or layer_for_type(proposed_type)
  ② evaluator._promote（:227）      → 沿用候选 layer or layer_for_type(proposed_type)
  ③ repositories.create_memory      → layer_for_type(type)          （remember_fact 路径）
  不变量：layer ≡ layer_for_type(type)

【读侧】本任务零改动；MEV-008 才在检索中使用 layer
```
