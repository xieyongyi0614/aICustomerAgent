## 2. Background

### 2.1 现状：读面只有「四分组」，没有「按主题聚合」的视角

| 事实 | 证据 |
|---|---|
| 读面只有分组列表 | `apps/backend/app/services/memory/product_view.py:296`（`list_product_memories`）；分组映射 `:48-58`（`TYPE_TO_GROUP`，9 键）、`:39`（`GROUP_ORDER` 四组） |

| 无任何聚类/主题聚合能力 | `apps/backend/app/services/memory/` 下无聚类模块；`docs/agent-evolution-plan-2026-10.md` §2.2 G-M4 记为「未找到证据」的能力 |
| 客户端已有卡片组件可复用（后端只需给数据） | `apps/mobile/lib/design_system/components/cards.dart`（含 `MemoryCard`）；移动端记忆页 `apps/mobile/lib/features/memory/presentation/memory_page.dart:167`（`_card`） |
| 端点注册方式 | `apps/backend/app/api/v1/memory.py:25`（`memory_router = APIRouter(prefix="/memory", tags=["memory"])`）、`:51` / `:73` / `:93`（既有三端点）；`apps/backend/app/api/v1/router.py:34`（注册） |

### 2.2 为什么必须做

1. **分层结构的产物需要一个「人看得懂」的出口**：`MEV-006` 聚合出的情景条目与 `MEV-007` 抽出的语义条目，在四分组里会散落到「当下」「目标」等组；主题卡片是唯一能按「同一件事」组织它们的视角（`docs/agent-evolution-plan-2026-10.md` §2.3 M3.4）。
2. **成本极低且必须保持只读**：主题键已存在，归组是纯函数；一旦引入 LLM 聚类或缓存表，就同时引入成本、迁移与一致性问题（R-M1）。
3. **它是「记忆可见」原则的补全**：用户既能看到「我记住了哪些」，也能看到「关于 X 我记住了什么」。

### 2.3 在本版本中的位置

M3 第 4 个任务（M3 后端收尾），为 `MEV-013`（客户端入口）提供数据契约。M3 之后只剩客户端任务。

> **与注册表的显式偏差**：`docs/version/v6.0.0/tasks.md` §4 对 `MEV-012` 的交付面写了「后台 job 周期计算」。本 Detail 裁决为**读时派生（零 job、零表）**，理由与后果见 §4.2 D1 与 §4.4 待定项。

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 端点契约（新增 `GET /api/v1/memory/themes`）

| 项 | 契约 |
|---|---|
| 路径 / 鉴权 | `GET /memory/themes`，`user_id = Depends(require_user)`（`apps/backend/app/api/v1/auth.py:116`） |
| 参数 | `limit: int \| None = None`（组数上限，缺省 `memory_theme_max`，`ge=1`、`le=100`） |
| 响应 | `MemoryThemesOut`：顶层 `generated_at` / `total_themes` / `themes[]` / `degraded`；`themes[]` 为 `MemoryThemeOut` |
| 错误 | 401 无令牌（`require_user`）；422 参数越界；**无主题数据 → 200 + `themes: []`**（空态非错误） |
| 只读 | 不写任何表；不落检索 trace |

#### 4.1.2 归组契约（确定性、零 LLM）

| 项 | 契约 |
|---|---|
| 输入 | 该用户全部 `status='active'` 记忆（复用 `MEV-011` 的只读取数路径，`limit=memory_candidate_pool_limit`） |
| 主题键优先级 | ① `source_ref.theme`（`MEV-006` 写入，优先）；② `source_ref` 无 `theme` 且 `layer=='semantic'` → 用 `type`（`user_preference` / `behavior_pattern` / …）作为主题键；③ 其他（无 `source_ref` 的普通 `user_fact` / `experience` 等）→ **不归组**（避免「全部塞进一个杂项组」） |
| 分组键 | `(theme)`（单用户单角色，故不再带 `user_id` / `character_id`） |
| 卡片字段 | `theme`（键）/ `label`（中文派生）/ `count`（**全量条数**）/ `preview[]`（≤ `THEME_PREVIEW_ITEMS = 3` 条，模块常量）/ `last_updated`（组内最大 `updated_at`）/ `layers`（该组出现的 `layer` 集合，升序） |
| 标签派生 | 语义类主题（`type` 键）→ 用 `TYPE_LABELS`（`:60-68`）映射；`theme` 键 → 原样返回（`MEV-006` 的主题键是中文/短标识，读面不做二次翻译，与 `source_label` 的「未命中原样返回」纪律一致） |
| 过滤 | 组内条数 `< memory_theme_min_items`（默认 3）→ 不返回该组 |
| 排序 | 组间按 `count` 降序、同 `count` 按 `last_updated` desc、再同按 `theme` 升序（**全链确定性**）；组内 `preview` 按 `last_updated` desc、同值 `id` asc |
| 上限 | 返回组数 ≤ `limit or memory_theme_max` |
| 副作用 | **零**：不调 `retriever`、不 `record_reinforce`、不改 `last_accessed_at`、不落 trace |

#### 4.1.3 响应模型（`app/api/v1/schemas.py` 追加）

| 模型 | 字段 |
|---|---|
| `MemoryThemePreviewOut` | `id` / `type` / `type_label` / `content`(截断至 120 字) / `last_updated` |
| `MemoryThemeOut` | `theme` / `label` / `count` / `preview[]` / `last_updated` / `layers[]` |
| `MemoryThemesOut` | `generated_at` / `total_themes` / `themes[]` / `degraded` |

> **不暴露机制字段**：不得出现 `salience` / `confidence` / `status` / `importance` / `embedding`（对齐 `test_list_items_does_not_leak_mechanism_fields`，`tests/v50/test_memory_api.py:88`）。

#### 4.1.4 新设置字段（`app/core/settings/memory.py`）

| 字段 | 类型 | 默认 | 语义 | 校验 |
|---|---|---|---|---|
| `memory_theme_min_items` | `int` | `3` | 成组的最小条数 | `ge=2`（1 条不成「主题」） |
| `memory_theme_max` | `int` | `20` | 返回组数上限 | `ge=1`、`le=100` |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **读时派生，零 job、零表**（与注册表 §4 的「后台 job 周期计算」显式偏差） | 主题卡片是**纯函数的视图**：① 无表则 job 无落盘点；② 读时派生天然不会与记忆状态不一致；③ 成本极低（200 条内存归组）。若实测成本超预算，再引入缓存表（§4.4 待定项 ①） |
| D2 | **三级主题键优先级 + 「不归组」兜底** | 把无主题的普通记忆强行归组会产生一个巨大的「杂项」卡片，反而降低可用性；`MEV-011` 的筛选/搜索已覆盖「按类型找」的需求 |
| D3 | **`count` 是全量、`preview` 是截断** | 用户需要知道「关于这件事一共记住了几条」，而不是只看前 3 条 |
| D4 | **组间/组内排序全链确定性** | 卡片顺序若不稳定，客户端列表会「跳动」；同值必须有最终 tie-break |
| D5 | **主题键原样作为 label（语义类用 `TYPE_LABELS`）** | 与 `source_label`（`SOURCE_LABELS` 未命中原样返回，`:70-82` / `:201`）的既有纪律一致：读面不发明文案 |
| D6 | **新增独立端点而非并入 `/items`** | `/items` 的信封契约（四分组）是冻结的（`:86` 等用例）；主题是不同 shape 的视图，并入会迫使信封变形 |
| D7 | **不暴露 `layer` 之外的机制信息**：`layers[]` 只给集合 | `layer` 属结构可见项（M2 的产品价值），而 `salience` / `confidence` 属机制（D5 口径禁暴露） |
| D8 | **空数据返回 200 + 空列表** | 新用户的正常态，不该是错误（对齐 `:118` 的「空组保留」纪律精神） |

### 4.3 数据流

```text
客户端（MEV-013）
   ▼ Bearer token → require_user（auth.py:116）
api/v1/memory.py::list_themes（★ 新增端点）
   ▼
product_view.list_memory_themes(user_id, limit)
   ├─ 取数：既有只读路径（limit=memory_candidate_pool_limit）
   ├─ 主题键：source_ref.theme → layer=='semantic' 的 type → 不归组
   ├─ 过滤：count >= memory_theme_min_items
   ├─ 排序：count desc → last_updated desc → theme asc（组内：last_updated desc → id asc）
   ├─ 截断：limit or memory_theme_max
   └─ preview：每组前 THEME_PREVIEW_ITEMS 条
   ▼
MemoryThemesOut → JSON

零副作用红线：不调 retriever、不 record_reinforce、不改 last_accessed_at、不落 trace、不写任何表
```
