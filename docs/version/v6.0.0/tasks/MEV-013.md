### 2.2 为什么必须做

1. **「记忆可见」目前只在移动端成立**：Web 调试面板是开发者核验记忆行为的主要工作面，只读意味着每次要改一条记忆都得走 API 工具（`docs/agent-evolution-plan-2026-10.md` §2.2 G-M8）。
2. **它同时是 M2/M3 结构的验收面**：`layer`（`MEV-005`）、关系（`MEV-009/010`）、主题卡片（`MEV-012`）若在客户端无可视入口，就无法被人验收。
3. **必须显式做「契约切换」**：Web 面板当前消费 `/api/v1/memories`（旧调试端点，字段是 `memory` / `memoryType`），而产品读面是 `/memory/items`（字段是 `content` / `kind` / `type_label` / `usage_receipts`）。字段名与语义都不同——这不是「小改」，故本 Detail 把它列为**显式契约切换**并点名受影响的 8 条用例。

### 2.3 在本版本中的位置

M3 第 5 个任务（客户端面）；完成后 M3 收口，M4 之后进入 P（计划澄清）线。

## 3. Scope

### 3.1 In Scope

1. **前端数据层**：新增 `fetchMemoryItems(userId, params)`（→ `GET /memory/items`）、`editMemoryItem`（`PATCH`）、`forgetMemoryItem`（`POST .../forget`）、`fetchMemoryThemes`（→ `GET /memory/themes`）；新增对应 TS 类型（产品读面 DTO + 信封 + 主题）。
2. **前端 hooks**：新增 `useMemoryItems` / `useMemoryThemes`（沿用既有 TanStack Query 风格），并在编辑/遗忘成功后 `invalidateQueries`。
3. **前端面板**：`memory-panel.tsx` 切换数据源 + 新增搜索框（`q`，输入 debounce）+ 逐条编辑对话框 + 逐条遗忘（含二次确认）+ 主题卡片只读区块；保留既有 error/retry 与 skeleton 行为。
4. **移动端**：`memory_repository.listItems` 增可选 `q` / `type` / `layer` 参数（默认 `null` → 行为不变）；`memory_page.dart` 增搜索框（debounce、清空按钮）+ 空态（`EmptyState`）。
5. **测试**：更新受影响的 8 条前端用例并新增搜索/编辑/遗忘/主题用例；移动端增/改 widget 用例（`apps/mobile/test/features/memory_page_test.dart` 已有）。

## 4. Technical Design Requirements

### 4.1 前端契约（`apps/frontend/`）

| 符号 | 契约 |
|---|---|
| `fetchMemoryItems(userId: string, params?: {q?: string; type?: string; layer?: string; since?: string; until?: string; limit?: number})` | `GET /api/v1/memory/items`（透传 token 与参数）；返回信封：`generated_at` / `total` / `added_this_week` / `groups[]` / `degraded` / `filtered` / `matched_total` |
| `editMemoryItem(memoryId: string, body: {content: string; importance?: number \| null})` | `PATCH /api/v1/memory/items/{memoryId}`；成功返回更新后的 item |
| `forgetMemoryItem(memoryId: string)` | `POST /api/v1/memory/items/{memoryId}/forget`；返回 `{id, status, forgotten_at}` |
| `fetchMemoryThemes(userId: string, limit?: number)` | `GET /api/v1/memory/themes`；返回 `{generated_at, total_themes, themes[], degraded}` |
| 类型 | 新增 `MemoryProductItem`（`id` / `kind` / `type` / `type_label` / `content` / `source_kind` / `source_label` / `source_count` / `last_updated` / `usage_receipts[]`）、`MemoryGroup`、`MemoryItemsEnvelope`、`MemoryTheme`、`MemoryThemesEnvelope`；**保留**既有 `MemoryRecord` 类型（仍被其他调试面板使用，不删） |
| `useMemoryItems` / `useMemoryThemes` | TanStack Query；`queryKey` 含全部参数（保证缓存键正确）；编辑/遗忘成功后 `invalidateQueries` 两个 key（items + themes） |
| 搜索 debounce | 300ms；输入期间不触发请求；清空显示全量 |
| 错误态 | 沿用既有 error + 重试（`memory-panel.tsx:184-193` 的结构）；编辑/遗忘失败 → 行内提示 + 保持原值（不做乐观更新） |

### 4.2 移动端契约（`apps/mobile/`）

| 符号 | 契约 |
|---|---|
| `MemoryRepository.listItems({int? limit, String? q, String? type, String? layer})` | `GET /memory/items`；**仅在有值时**附加 query 参数（`q` / `type` / `layer`），保证无参调用与现状等价（`:108` 的默认 `limit=200` 保留） |
| 搜索框 | 置于既有 `data.total` / `addedThisWeek`（`:227`）之上；debounce 300ms；有内容时显示清空按钮；空结果用 `EmptyState`（`states/states.dart:38`） |
| 组件复用（硬） | 卡片用 `cards.dart` 的 `MemoryCard`（不新造卡片）；分组渲染沿用 `_body`（`:208`）的 `for (final group in data.groups)` 结构 |
| 分组与标签 | 仍**全部服务端下发**，端上零映射（既有纪律；`_tagColors`（`:145`）只做配色，不动） |

### 4.3 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **Web 面板数据源切换到产品读面**（`/memory/items`） | 旧 `/api/v1/memories`（`rest.ts:128`）无分组/来源/回执，且「不按 status 过滤」是 V5 已修正的历史缺陷；产品读面才是契约真源 |
| D2 | **保留既有 `MemoryRecord` 类型与旧 fetch 函数**（只新增，不删） | 其他调试面板仍可能依赖；删除会造成不可预期的破坏面（D3 与 AC6 的「后端零改动」精神一致） |
| D3 | **不做乐观更新** | 编辑/遗忘是用户可见的破坏性操作；失败必须显式暴露（回滚逻辑成本高且易错） |
| D4 | **测试用例显式改期望值，并列出清单** | 契约切换（字段名/端点/响应 shape 全变）必然让旧断言转红；静默改期望值会掩盖真实行为差异（`tasks/README.md` §5 第 6 条） |
| D5 | **移动端搜索按「有值才带参」实现** | 无参调用必须与现状逐字节等价（查询串相同 → 命中同缓存、同一行为） |
| D6 | **移动端不自造视觉** | 设计系统 Skill 是 UI 唯一真源，优先级高于设计稿；`MemoryCard` / `EmptyState` 已存在，重造会破坏 golden 与 token 一致性 |
| D7 | **不引入前端路由库** | 前端无 react-router（`App.tsx:16` 按 hash）；引入属架构变更 |
| D8 | **主题卡片先做前端只读区块** | `MEV-012` 契约已冻结，前端区块可独立推进且零风险；移动端入口延后 |

### 4.4 依赖与边界

| 类别 | 内容 |
|---|---|

## 7. Testing Requirements

### 7.1 Focused（前端 `vitest`）

| 用例名 | 断言 |
|---|---|
| `memory panel requests product items endpoint` | 渲染面板后 MSW 捕获的请求 URL 为 `/api/v1/memory/items`（**不再**是 `/api/v1/memories`） |
| `memory panel renders product item fields` | 展示 `content` / `type_label` / `source_label` / `source_count` / 回执文案；不渲染 `memoryType` / `confidence` 等旧字段 |
| `memory search debounces and requests with q` | 连续输入 5 次只产生 1 次请求且带 `q=<终值>`；清空后请求不带 `q` |
| `memory search shows empty state on no match` | 返回空分组 → 显示空态文案（不显示错误） |
| `memory edit dialog patches and invalidates` | 提交编辑 → `PATCH /memory/items/{id}` body 正确；成功后 items 与 themes 查询被 invalidate |
| `memory edit failure keeps original value and shows error` | `PATCH` 返回 403/404 → 显示错误、原值不变（D3 无乐观更新） |
| `memory forget asks confirmation then posts` | 点击遗忘 → 出现二次确认；确认后 `POST /memory/items/{id}/forget`；取消则不请求 |
| `memory theme cards render from themes endpoint` | 主题区块消费 `/memory/themes`，渲染 `label` / `count` / `preview` |
