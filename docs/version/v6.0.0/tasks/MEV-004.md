## 2. Background

### 2.1 现状：召回结果在 turn_meta 里只留「标签」，名次与分数全部丢弃

### 2.2 为什么必须做

1. **没有观测量，M1 的两项能力无法验收**：`MEV-001`（重排）与 `MEV-002`（改写）都是「可能变好也可能变差」的启发式；若不在 `memory_refs` 留下**名次与分数**，就无法回答「重排到底把哪条提到了前面」「这条是被改写召回的还是没有重排召回的」——`docs/agent-evolution-plan-2026-10.md` §2.3 M1.4 / M1.5 正是为此登记。
2. **离线门槛是本仓已有的成熟判据**：`offline_metrics` 的 `gate_passed` 是回归门（`:89`），扩展指标即把 M1 的能力纳入 CI 可判定范围，符合 `tasks.md` §0.7 的测试纪律。
3. **它是 M2/M3 的前置观测量**：`MEV-008`（分层配额）需要「episodic/semantic 各自被召回的名次」来调配额；`MEV-011`（记忆搜索）也需要同一套派生逻辑复用。

### 2.3 在本版本中的位置

M1 收尾任务：把 `MEV-001` / `MEV-002` 的产出物变成**可观测 + 可判定**的事实，并为 M2/M3 提供名次观测量。它本身不改变任何检索行为（纯派生 + 评估侧扩展）。

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 `memory_refs` 条目结构（`app/services/memory/refs.py`）

| 字段 | 类型 | 必填 | 派生规则 |
|---|---|---|---|
| `id` | `str` | 是 | `memory.id`（既有，不变） |
| `kind` | `str` | 是 | `memory.type`（既有，**不归一**，保留既有语义） |
| `label` | `str` | 是 | `memory_ref_label(content)`（既有，截 12 字 `:11`） |
| `score` | `float` | 否 | `ranked.items[i].score`，**四舍五入到 4 位小数**；`ranked is None` 时**不写入该键** |
| `rank` | `int` | 否 | 最终名次，**1-based**（= `ranked.items` 中的下标 + 1） |
| `rank_pre` | `int` | 否 | 重排前名次（§4.1.2）；`off` 时 == `rank` |
| `reranked` | `bool` | 否 | 该条是否实际获得 `rerank_score`（`rerank_score is not None`） |

**向后兼容纪律**：`ranked is None`（既有调用方形态）→ 输出**只含 `id` / `kind` / `label`**，与基线逐字节一致；为此新增参数**必须带默认值 `None`**。

#### 4.1.2 `rank_pre` 的确定性重算规则

| 项 | 契约 |
|---|---|
| 计算输入 | 仅 `ranked.items` 的 `score` 与 `memory.id`（**不依赖** `MEV-001` 是否暴露重排前快照） |
| 规则 | 按 `score` **降序**、同分按 `memory.id` **升序**重排后取 1-based 下标 |
| `rerank_mode == "off"` | `rank_pre == rank`（恒等，硬约束） |
| `rerank_mode == "lite"` | `rank_pre` 为重排前名次；`rank` 为最终名次；两者差异即「重排增益」的原始数据 |
| 稳定性 | 纯函数，同一输入重复执行结果一致 |

#### 4.1.3 离线门槛扩展（`app/services/memory/offline_metrics.py`）

| 项 | 契约 |
|---|---|
| `GATE_THRESHOLDS` 新增 | `E-MEM-07`（重排增益）、`E-MEM-08`（改写贡献）；**阈值默认值在实现期冻结**（须与既有 6 项同量纲，取值区间 `[0,1]`） |
| 指标定义（冻结） | `E-MEM-07` = 「重排后 top-1 与人工标注首选一致的场景占比」；`E-MEM-08` = 「仅凭改写 query（原 query 未命中）被召回且判定为相关的条目占比」 |
| `KIND_TO_METRIC` | 新增两个场景 kind → 新指标号的映射；**既有映射零改动** |
| `build_report` | `metrics` 中新增两项（键名与指标号一致）；`gate_passed` 判定**包含**新指标（全部指标均需达标） |
| `coverage` | 新场景 kind 计入 coverage（`:82`）；无新场景时 coverage 与基线一致 |
| 阈值不得放宽既有 6 项 | 既有阈值逐字节不变 |

#### 4.1.4 评估场景数据契约

| 项 | 契约 |
|---|---|
| 场景文件落点 | `apps/backend/tests/eval/memory_scenarios/`（沿用既有目录） |
| 场景 needed 字段 | 至少含：`query`、`memories[]`（含 `content` / `type` / `importance`）、`preferred_id`（人工首选，用于 `E-MEM-07`）、`unreachable_by_original_query: bool`（用于 `E-MEM-08`） |
| 场景数值 | 每个新指标 ≥ 1 个独立场景；场景**不得**引用真实用户数据 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | `build_memory_refs` 用**可选参数**而非改签名语义 | 既有调用方（turn_meta 装配）不改即得旧行为（逐字节兼容）；`MEV-001` / `MEV-002` 不必改调用点 |
| D2 | `rank_pre` **重算**而非让 `MEV-001` 暴露重排前快照 | 避免三任务间的字段耦合；`score` + id tie-break 已足以确定性复原重排前次序（`MEV-001` D1 已保证 `score` 不被改写） |
| D3 | `score` 四舍五入到 **4 位** | `turn_meta` 是逐轮落库的 JSON，浮点全精度会显著增体积且无信息价值；4 位足够区分名次 |
| D4 | 门槛阈值仍是**模块常量** | 与既有 6 项同源（`:12-19`）；运行期可调会让 `gate_passed` 失去稳定性（且违反 R-M1 不新增调参面） |
| D5 | 新指标**必须进入 `gate_passed`**（而非只输出不判定） | 「只报不判」等于没有门槛——`tasks.md` §0.7 要求 M1 的能力可被门槛判定 |
| D6 | 不新增调试端点 | 既有 `/debug/turns/{turn_id}/trace`（`observability.py:32`）已能读 extra；新增端点扩大调试面治理成本 |
| D7 | `memory_refs` 不放机制字段（`salience` / `confidence` / `status`） | D5 口径精神：机制不外露；名次与分数是**可解释的用途证据**，与机制字段性质不同 |
| D8 | `kind` 保留原始 `memory.type`（不归一） | 既有语义（`:35-38`）已被消费；归一属 `MEV-003` / 读面口径问题，混入本任务会造成两处口径 |
| D9 | 场景数据不含真实用户内容 | 评估集随仓库分发，必须避免个人数据（数据治理纪律） |

### 4.3 数据流

```text
retriever.retrieve（:265）→ RankedMemories(items, mode, rerank_mode)   ← MEV-001/002 产出
   ▼
turn_meta 装配（既有调用点）
   └─ refs.build_memory_refs(memories, ranked=ranked)                  ← ★ MEV-004 新增可选入参
        ├─ ranked is None → {id, kind, label}（与基线逐字节一致）
        └─ ranked 提供   → + score(4位) / rank(1-based) / rank_pre(§4.1.2) / reranked(bool)
             ▼
        turn_meta.memory_refs（落库 JSON）→ 既有 /debug/turns/{turn_id}/trace 只读可查

离线侧（离 CI 可判定，与运行期隔离）
   tests/eval/memory_scenarios/*  →  offline_metrics.build_report（:36）
        ├─ GATE_THRESHOLDS（:12-19）+ E-MEM-07 / E-MEM-08
        ├─ KIND_TO_METRIC（:21-33）新映射
        └─ metrics（:88）/ coverage（:82）/ gate_passed（:89）  ← 新指标参与判定
```
