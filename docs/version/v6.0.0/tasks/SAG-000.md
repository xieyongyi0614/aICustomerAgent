## 2. Background

### 2.1 现状：subAgent 属完全未决方向，且与 5 条现存红线直接冲突

| 事实 | 证据 |
|---|---|
| **RL-1**：多 Agent / 多角色并行属 **Non-Goal** | `docs/version/v3.0.0/architecture.md:53`（§0.3 Non-Goals），条目 `:55` |
| **RL-2**：禁止引入外部 Agent 编排框架（LangGraph / CrewAI 等） | `docs/version/v3.0.0/architecture.md:59` |
| **RL-3**：**不建第二套 Agent**（新能力走 Profile 阶段 / 段本体 / Update-handoff / 域唯一写面 / 既有 trigger 五种姿势） | `docs/version/v5.0.0/tasks.md:31`；`docs/version/v4.0.0/tasks.md:20` / `:35` |
| **RL-4**：**Agent Runtime 单管线**（三种 Run Profile 唯一声明，禁止另开阶段序列） | `docs/current-system-architecture-baseline.md:545`（ADR-7） |
| **RL-5**：基线 §8 Extension Points 与 §11 演进方向**均未登记** subAgent | `docs/current-system-architecture-baseline.md:438`（§8 标题，8.1~8.6 无该条目）、`:569`（§11.1 只提「扩展新 run_kind」） |
| 唯一预留点（「更远」非「规划中」） | `docs/version/v3.0.0/architecture.md:571-573`（§10.4：`character_id` / `session_id` 贯穿使运行时可**按角色实例化多份循环**；本版本不设计） |
| 可复用的原材料（现状） | `app/application/agent_runtime/profiles.py:17`（`ProfileSpec`，字段 `:25-30`：`run_kind` / `budget_tier` / `stages` / `llm_capable` / `critical` / `optional_stages`）；`contracts.py:233`（`AgentRuntime` Protocol，`run` `:236-238`）；`app/core/db/autonomy.py:138`（`BackgroundJobRow`，含 `idempotency_key` unique `:141-151`）；`app/application/worker_loop.py:21`（`run_worker_loop`） |
| 关键缺口（现状） | 无 `register_profile` 运行时注册（`profiles.py:80` / `:87` 仅两个读函数）；无「主体 → 独立 system prompt」绑定（`llm_gateway.acquire` `:89` 只裁决模型档位，`Grant` `:53-57` 仅 `granted` / `degraded` / `reason`）；`loop_runs` 无父子关联；`asyncio.gather` 全库仅 4 处且不可复用于步骤/Agent 级并发 |

### 2.2 为什么必须先做这一步

1. **裁决前任何 `SAG-*` 代码都判违规**：RL-3 / RL-4 是写进任务册与基线的**明示禁令**；在没有裁决与基线登记的情况下实现 subAgent，等于让后续所有评审都以「违反 ADR-7」结案（`docs/agent-evolution-plan-2026-10.md` §4.5 第 1 条）。
2. **红线不是「一句话禁令」，而是分层约束**：RL-1/RL-2 是方向禁令，RL-3/RL-4 是**实现姿势白名单**（S-A 可落在白名单内，S-D 直接违反 RL-2）。必须逐条裁决才能确定「哪种 subAgent 是合规的」（§4.3 的选项对比）。
3. **必须固化到基线而非停留在任务册**：基线纪律要求「任何架构演进须先更新该基线再进入开发」；只在任务册写一句「做 subAgent」不会改变评审依据。

### 2.3 在本版本中的位置

S 线**唯一前置**：`SAG-001~004` 全部阻塞于本任务（`tasks.md` §0.6 裁决 6）。

### 4.2 关键裁决（本任务自身的方法论约束）

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **裁决须由项目负责人确认才生效** | 红线是架构承诺，不能由实现者单方面解除（`docs/agent-evolution-plan-2026-10.md` §4.5 第 1 条）；§4.1.1 §6 的确认项是生效条件 |
| D2 | **逐条裁决，不允许「打包放开」** | RL-1/RL-2 是方向禁令、RL-3/RL-4 是姿势白名单、RL-5 是登记缺口——五条的性质不同，结论可以不同（例如放开 RL-3 但维持 RL-2） |
| D3 | **S-D（外部框架）预期维持禁止** | 引入 LangGraph / CrewAI 会同时违反 RL-2 并要求重写运行时（`docs/agent-evolution-plan-2026-10.md` §4.3 已判「明确不推荐」）；若无强理由不应放开 |
| D4 | **不重写历史版本文档** | 历史文档不改写是仓库约定；方向变更由**基线新条目**承接并显式声明与 v3.0.0 Non-Goal 的关系（§3.2 第 3 条） |
| D5 | **本任务零代码** | 裁决与实现分离；任何「顺手试一下」都会让「未经裁决的代码」进入仓库（§3.2 第 1 条） |
| D6 | **不预留迁移编号以外的基础设施** | 迁移取号在 `SAG-002` 落地时确定（承接 `0011`）；本任务只声明「可能需要迁移」 |
| D7 | **裁决记录成为域唯一依据** | 避免裁决散落在任务册与基线之间形成两个版本；文档路径进基线条目（§4.1.2 反向引用） |
