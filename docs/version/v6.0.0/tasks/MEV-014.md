## 2. Background

### 2.1 现状：遗忘只有「整条」一种粒度

| 事实 | 证据 |
|---|---|
| 整行遗忘的既有实现：置 `forgotten` + 清向量 + 落审计 trace | `apps/backend/app/services/memory/lifecycle.py:358`（`explicit_forget`）；trace 使用 `EVENT_FORGET`（同文件常量）；`product_view.forget_memory_for_user`（`product_view.py:353`）为产品写面（含归属守卫） |
| 保留期后物理删除 | `lifecycle.py:233`（`purge_expired_forgotten`，`memory_forget_retention_days` 默认 30） |

| 会被影响的既有断言 | `apps/backend/tests/v50/test_memory_api.py:133`（`test_forget_returns_audit_timestamp`）、`:141` / `:148`（403/404）；`apps/backend/tests/v50/test_memory_product_view.py:180` / `:187` / `:194`（来源派生） |

### 2.2 为什么必须做

1. **「整条删」与「不删」之间缺一档**：用户可能只想忘记「那笔 8000 元」的金额，但保留「买了台相机」这件事本身。当前唯一手段是整条遗忘，等于**连有用信息一起丢**（`docs/agent-evolution-plan-2026-10.md` §2.2 G-M5）。
2. **它是数据治理的细粒度兑现**：基线 §3.3 的治理纪律要求「用户可控、可导出删除」；部分遗忘把「可删除」从行级下沉到**片段级**，且留痕可审计。
3. **必须绕开 `merge_chain`**：这是本任务最关键的工程约束——`merge_chain` 被读面当作「被观察次数」（`:205`）。若把脱敏记录塞进去，用户会看到「5 次对话提及」这种虚假计数（D2）。故留痕改放 `source_ref`（JSON，零迁移）。

### 2.3 在本版本中的位置

M3 收尾任务（M3 第 6 个）。之后 M3 全部完成，进入 P（计划澄清）线。

## 3. Scope

### 3.1 In Scope

1. `lifecycle.py` 新增：`PARTIAL_FORGET_SCOPES` / `PARTIAL_FORGET_LABELS` / `PARTIAL_FORGET_PLACEHOLDER` / `PARTIAL_FORGET_EVENT` 常量与 `partial_forget(memory_id, scopes, *, trace=None) -> dict`（§4.1.1）。
2. 脱敏规则：按作用域的正则替换（确定性），命中数为 0 → **不写库**（幂等）。
3. 留痕：`source_ref["partial_forget_history"]` 追加记录（§4.1.2）。
4. 脱敏后清 `embedding`（交给既有 `embedding_backfill` 重建）。
5. `product_view.partial_forget_for_user(memory_id, user_id, scopes, trace=None)`（守卫 + 委托）。
6. 端点 `POST /memory/items/{memory_id}/partial-forget` + `MemoryPartialForgetOut`。
7. 新增用例（§7.1 / §7.2）。

### 3.2 Out of Scope（明确禁止扩张）

| # | 禁止项 | 理由 |
|---|---|---|
| 1 | **不改整行遗忘语义** | `explicit_forget`（`:358`）与 `forget_memory_for_user`（`:353`）已被 V5 验收并有审计断言（`test_memory_api.py:133`）；本任务只**新增**函数 |
| 2 | **不改 `merge_chain` 语义，也不写 `merge_chain`** | `merge_chain` 唯一语义 = 「同主题合并链」（`:317-319`），且被读面当作观察次数（`:205`）；写入会污染产品计数（D2） |
| 3 | **不新增列 / 不加表 / 不加迁移** | 留痕落在既有 JSON 列 `source_ref`（`:57`）；加列会改 `SCHEMA_COLUMNS_DIGEST` 并扩大迁移面 |
| 4 | **不做「字段级恢复 / 撤销部分遗忘」** | 撤销需要保存原文，等于把被遗忘的内容留在库里——与遗忘目的直接冲突（D4） |
| 5 | **不做批量部分遗忘** | 会引入「一批记忆的部分遗忘事务」语义；当前单条已足够（按条操作更可解释） |
| 6 | **不做客户端字段选择器 UI** | 客户端面归 `MEV-013` 之后的新任务；本任务只交付 API 与契约（见 §4.4 待定项 ③） |
| 7 | **不引入 NER 模型 / 外部脱敏服务** | 新增依赖 + 推理成本；本任务用**确定性正则**（作用域集合有限、可测、可解释） |
| 8 | **不改 `product_view` 既有读面函数与常量表** | `SOURCE_LABELS`（`:70-82`）/ `source_count_of`（`:205`）等被冻结用例钉住（`:180` / `:187` / `:194`） |

## 4. Technical Design Requirements

### 4.1 契约

#### 4.1.1 `lifecycle.partial_forget` 契约

| 项 | 契约 |
|---|---|
| 签名 | `partial_forget(memory_id: str, scopes: Sequence[str], *, trace=None) -> dict \| None`；`None` = 记忆不存在 |
| 返回 | `{"id": str, "changed": int, "scopes": list[str], "content": str}`；`changed` = 本轮替换命中处数 |
| 作用域白名单（★ 冻结） | `PARTIAL_FORGET_SCOPES = ("amount", "place", "person", "time", "contact")`；中文标签 `PARTIAL_FORGET_LABELS`（金额 / 地点 / 人物 / 时间 / 联系方式） |
| 脱敏规则 | 每个作用域对应一组**确定性正则**（模块常量，实现期冻结）；命中片段替换为 `PARTIAL_FORGET_PLACEHOLDER = "（已隐去）"`；**不做上下文改写、不调 LLM** |
| 幂等 | 第二轮执行时已无命中（占位符不含原模式）→ `changed == 0` → **不写库、不追加留痕**，但仍返回 `200` 语义 |
| 白名单校验 | `scopes` 含白名单外值 → **拒绝**（`ValueError` → 端点映射 422）；`scopes` 为空 → 拒绝（422） |
| 作用域归一 | 去重 + 按 `PARTIAL_FORGET_SCOPES` 顺序排序（保证留痕与响应确定） |
| 状态守卫 | 仅 `status == 'active'` 可部分遗忘；非 active → 返回 `None`（端点映射 404，对齐不可见条目语义） |
| 清向量 | 命中 > 0 时清空 `embedding`（避免与已脱敏内容不一致）；重建交既有 `embedding_backfill` |
| 失败语义 | 正则/写库异常 → 传播（这是用户主动的写操作，必须显式失败，不做静默降级——与检索链路的降级纪律区分开） |

#### 4.1.2 留痕契约（`source_ref`）

| 项 | 契约 |
|---|---|
| 位置 | `memories.source_ref["partial_forget_history"]`（JSON 数组；`source_ref` 为 NULL 时初始化为 `{}`） |
| 记录结构 | `{"at": <ISO8601>, "scopes": [<按白名单顺序>], "changed": <int>}` |
| **禁止** | 不得写入 `merge_chain`（`:56` 列，语义为「同主题合并链」，且被 `source_count_of`（`:205`）当作观察次数）；不得覆盖 `source_ref.table` / `source_ref.source_ids` / `source_ref.theme` 等既有键 |
| 保留 | 留痕随记忆生命周期（整行遗忘后随保留期清理）；**不单独删除** |
| 只读兼容 | `source_kind_of`（`:193`）仍优先读 `source_ref.table`；新增键不影响来源派生（由 §7.1 断言） |

#### 4.1.3 端点契约（新增 `POST /api/v1/memory/items/{memory_id}/partial-forget`）

| 项 | 契约 |
|---|---|
| 请求 | body：`MemoryPartialForgetIn`：`scopes: list[str]`（`min_length=1`）；未知作用域 → **422** |
| 响应 | `MemoryPartialForgetOut`：`id` / `status` / `changed` / `scopes` / `content`（脱敏后内容，供端上原地替换） |
| 状态码 | 200 成功（含 `changed == 0` 的幂等情形）；401 无令牌；**403** 越权（沿用 `_OWNERSHIP_DETAIL = "不得读写他人数据"`，`memory.py:27`）；**404** 不存在或非 active（**不区分**，沿用既有语义 `:102-103`）；**422** 作用域非法/为空 |
| 写面 | 端点只调 `product_view.partial_forget_for_user`（API 层零 `app.repositories` 依赖，对齐 `:23` 的既有 import 面） |
| 鉴权 | `user_id = Depends(require_user)`（`auth.py:116`） |

#### 4.1.4 与整行遗忘的关系（并列，不取代）

| 面 | 整行遗忘（既有） | 部分遗忘（本任务） |
|---|---|---|
| 结果 | `status='forgotten'`、清向量、退出列表 | `status='active'`、内容脱敏、**仍在列表** |
| 审计 | `forgotten_at` + `forget` trace | `source_ref.partial_forget_history` + `partial_forget` trace |
| 与 `merge_chain` | 不涉及 | **不涉及**（D2） |
| 保留期 | 30 天后物理删 | 不触发保留期 |

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **部分遗忘不是「软删除」，而是「内容脱敏」** | 记忆仍 `active`、仍可检索——语义是「忘记片段」而非「忘记这件事」；这样才不会与整行遗忘的状态机（`TRANSITIONS` `:48-62`）纠缠 |
| D2 | **留痕放 `source_ref`，绝不放 `merge_chain`** | `merge_chain` 被 `source_count_of`（`:205`）当作「被观察次数」渲染成「N 次对话提及」；写进去会直接虚增产品计数（本任务最关键的陷阱） |
| D3 | **命中为 0 时不写库** | 幂等且避免无意义的留痕膨胀；也避免「重复调用产生 N 条脱敏记录」 |
| D4 | **不支持撤销** | 撤销需要保存原文（或原文副本），与被遗忘的目的冲突；要恢复由用户重新告知（走正常摄取链路） |
| D5 | **确定性正则，不接 NER / LLM** | 作用域集合有限（5 类），正则可测、可解释、零成本；NER 会引入依赖与不可解释的误脱敏（R-M1/R-M2） |
| D6 | **清空向量** | 脱敏后内容与旧向量不再一致，留着会污染召回（脏向量比无向量更糟）；重建交既有补扫 |
| D7 | **写操作失败显式传播** | 与检索链路的「降级不阻断」不同：这是用户主动的写意图，静默失败等于欺骗用户 |
| D8 | **非 active 返回 404（与整行遗忘同语义）** | 与既有 `:102-103`（404 不区分「不存在」与「不可见」）一致，避免泄露 `forgotten` 条目的存在 |
| D9 | **本任务零迁移、零设置** | 留痕用既有 JSON 列；作用域集合是常量，无灰度语义 |
| D10 | **端点独立，不扩展既有 forget** | 两者请求体与响应语义不同（`scopes` vs 无 body；`content` vs `forgotten_at`）；合并会让既有契约变形（V5 冻结） |

### 4.3 数据流

```text
客户端（字段选择器，后续任务）
   ▼ Bearer token → require_user（auth.py:116）
api/v1/memory.py::partial_forget_item（★ 新增端点）
   ├─ scopes 校验（非空、∈ PARTIAL_FORGET_SCOPES；否则 422）
   ▼
product_view.partial_forget_for_user(memory_id, user_id, scopes, trace)   ← 写面 + 归属守卫（_guard :324）
   ▼
lifecycle.partial_forget(memory_id, scopes, trace)                       ← ★ 新增
   ① 取行（status=='active' 否则 → None → 404）
   ② 逐个作用域执行确定性正则替换 → 内容 + changed
   ③ changed == 0 → 早退（不写库、不留痕）→ 返回 {"changed": 0}
   ④ 写回 content（update_memory_content :187）
   ⑤ 清空 embedding（update_embedding :303）
   ⑥ 追加 source_ref.partial_forget_history（★ 不碰 merge_chain）
   ⑦ trace：PARTIAL_FORGET_EVENT（对齐 EVENT_FORGET 的既有做法）
   ▼
MemoryPartialForgetOut → 端上原地替换内容

红线：不改 status / 不写 merge_chain / 不新增列 / 幂等 / 失败显式传播
```
