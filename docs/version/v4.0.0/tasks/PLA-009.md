## 2. Background

### 2.1 为什么记账必须走治理链，不能直调写面

PLA-005 交付了写面，但**写面不等于可调用的行动**。若让抽取链直接调 `record_entry`：

| 缺失的治理 | 后果 |
|---|---|
| 权限段 | 无统一的能力准入检查 |
| 确认段 | 大额 / 模糊消费不会触发确认（PLA-010 的核心入口） |
| 校验段 | payload 合法性只在服务层，缺一层统一的 schema 校验 |
| 归一 / 健康度 | 无失败统计与熔断；外部依赖异常时会持续失败 |

项目既有的 `services/tool/executor.py` 已实现**权限 → 确认 → 校验 → 归一 → 健康度**五段短路，`ActionEngine` 已实现「create_record → evaluate_gates → assemble_plan → execute_plan → integrate_result」的完整闭环。**记账作为一次行动接入，等于免费获得这套治理。**

### 2.2 既有能力范本

`services/action/capabilities/` 已有六项内置能力：`reminder`（提醒）、`memory`（记忆）、`world_action`（世界动作）、`environment_query`（环境查询）、`search`（搜索）、`notification`（通知）；另有两项条件注册：`channel_feishu`、`external_api`。本任务是**新增第七项内置能力**，形态完全对齐既有实现。

### 2.3 在 V4.0 中的位置

- PLA-010（确认 / 订正 / 冲正）的直接前置——确认段正是本任务接入 Tool 五段才成为可能；
- PLA-011 / PLA-013 的间接前置（主动服务最终仍以行动形式投递）；
- 本任务是「记账」这条链路的**唯一入账入口**。

## 3. Scope

### 3.1 In Scope

1. **账本能力**（`services/action/capabilities/ledger.py`）：

   | 能力 ID | 语义 | 输入（结构化） | 输出 |
   |---|---|---|---|
   | `ledger.record` | 记一笔 | `amount_minor`(int, >0) / `currency` / `direction` / `category_id?` / `account_id?` / `occurred_at` / `merchant?` / `note?` / `source` / `source_ref` / `idempotency_key` | `CapabilityResult`（含 `entry_id`、`created`） |
   | `ledger.query` | 查账 | `period` / `group_by?` / `category_id?` / `account_id?` / `limit?` | `CapabilityResult`（`LedgerSummary` 摘要） |
   | `ledger.revise` | 订正 / 撤销 | `entry_id` / `reason` / `idempotency_key` | `CapabilityResult`（含冲正 `entry_id`） |

   - 三者均为**只做执行**：校验必填、调对应服务（PLA-005 / PLA-006）、返回结果；**不做任何决策**。
2. **工具注册**（`services/tool/builtin.py` 或 `services/tool/manifests/`）：
   - 注册 `builtin.ledger.record` / `builtin.ledger.query` / `builtin.ledger.revise`；
   - 每个工具的 `input_schema` 严格声明（金额为 **integer**、方向为枚举、时间 ISO 字符串）；
   - `permission` / `side_effects` 声明：`record` 与 `revise` 为**写副作用**，`query` 为只读；
   - 遵守 `ToolRegistry` 的**注册期七项校验**（id 格式 / 唯一 / 命名空间 / capability 可解析 / schema 自洽 / permission / 长度预算）。
3. **意图词表与动作映射**（**零 LLM，保持既有风格**）：
   - `services/action/detector.py` 增记账意图词表：动词（记 / 记账 / 花了 / 付了 / 收到 / 报销）+ 金额结构（数字 + 元/块/￥）+ 消费名词的**组合判定**，避免把「我记得你说过」误判为记账；
   - `character/asuna/action.py::ACTION_CAPABILITY_MAP` 增记账类动作 → `ledger.record` / `ledger.revise` / `ledger.query` 的映射；
   - `action_type` 枚举新增 `record_ledger_entry` / `revise_ledger_entry` / `query_ledger`（沿既有枚举风格）。
4. **入参结构化硬约束**：`ledger.record` **拒绝自由文本入参**——`message` / `text` / `raw` 之类字段不在 schema 内；金额必须是整数分；方向必须是枚举。**这是「能力不接受自然语言」的机械保证**。
5. **可审计**：每次能力执行经 `ActionEngine` 落 `action_records` 台账（状态机 `created→planned→executing→succeeded/failed/cancelled`），`steps[]` 增量落 `tool_id` / `permission` / `validation` / `duration_ms`。
6. **失败语义**：能力失败返回 `CapabilityResult(ok=False, ...)`，**不抛裸异常**；由 `CapabilityExecutor` 统一超时包裹与异常归一。

### 3.2 Out of Scope（明确禁止扩张）

- **不改 Tool 五段短路**（权限 / 确认 / 校验 / 归一 / 健康度）与 `ToolExecutor.run`。
- **不改 `ToolRegistry` 注册机制**（启动期代码注册，非热插拔）；**不做用户自定义记账工具**（受注册机制限制，架构 Backlog）。
- **不改 `ActionManager` / `ActionEngine` / Action 六态状态机 / `GateReason` / `FailureKind`**。
- **不绕过治理直调**：不得在业务层直接 `Capability.execute(...)`，必须经 `ActionEngine` / `ToolExecutor`。
- **不做外部账单源接入**（`external_api` 能力已存在，但账单源依赖未建的用户授权体系，架构 §11）。
- **不做重试 / 调度决策**（重试归 `action_schedules` + 既有维护循环）。
- **不做回复文案生成**（归 `chains/answer_chain` 与各域）。
- **不新增任何功能开关**（§0.9）。
- 不改账本表结构、写面、聚合语义（PLA-004 / 005 / 006 冻结）。

## 4. Technical Design Requirements

### 4.1 接口契约

```python
class LedgerRecordCapability:
    capability_id = "ledger.record"
    side_effects = "write"
    input_schema = {                     # 严格结构化，无自由文本字段
        "amount_minor": {"type": "integer", "minimum": 1},
        "currency": {"type": "string", "pattern": "^[A-Z]{3}$"},
        "direction": {"type": "string", "enum": ["expense", "income", "transfer"]},
        "category_id": {"type": "string", "nullable": True},
        "account_id": {"type": "string", "nullable": True},
        "occurred_at": {"type": "string", "format": "date-time"},
        "merchant": {"type": "string", "nullable": True},
        "note": {"type": "string", "nullable": True},
        "source": {"type": "string", "enum": ["conversation", "action", "manual", "import"]},
        "source_ref": {"type": "string", "nullable": True},
        "idempotency_key": {"type": "string", "minLength": 8},
    }
    required = ("amount_minor", "direction", "source", "idempotency_key")

    async def execute(self, payload: Mapping[str, Any], *, context: CapabilityContext) -> CapabilityResult: ...
```

```python
@dataclass(frozen=True, slots=True)
class CapabilityResult:
    ok: bool
    data: Mapping[str, Any]        # 如 {"entry_id": ..., "created": True}
    error: str | None              # 归一后的错误码，非堆栈
    duration_ms: float
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 记账走 Tool 五段 + ActionEngine **完整治理链**，不由抽取链直调写面 | 免费获得权限 / 确认 / 校验 / 归一 / 健康度五道治理；ADR-10 是项目铁律 |
| D2 | `ledger.record` 的 schema **不含任何自由文本字段** | 「记账必须是结构化事实」的第一道机械闸；也阻断「把自然语言塞进 note 再解析」的退化路径 |
| D3 | `amount_minor` 在 schema 层声明为 **integer 且 ≥1** | 精度纪律前移到治理层；非法值在 Tool 校验段就被拒，不进入服务层 |
| D4 | 能力**只执行不决策**：不判断该不该记、不选账户、不猜类目 | ADR-10；决策归 Reason / Decision Pipeline，类目归一归 PLA-008 |
| D5 | `idempotency_key` **必填**（schema required） | 把「无幂等键的写入」在接口层变成不可能，而非靠调用方自觉 |
| D6 | 记账意图检测**保持零 LLM 词表 + 正则** | 与既有 `detector.py` 风格一致；意图检测走 LLM 会引入延迟、成本与不确定性，且这一步只是「是否进入记账链路」的粗筛 |
| D7 | `action_type` 枚举新增而非复用既有类型 | 记账有独立语义与独立台账；复用 `use_object` 之类会造成语义混淆与统计困难 |
| D8 | 能力失败返回 `ok=False` 的 `CapabilityResult`，**不抛异常** | 对齐 `CapabilityExecutor` 的异常归一约定；裸异常会绕过健康度统计 |
| D9 | `ledger.query` 为**只读**副作用声明 | 让健康度与权限段能区分读写；避免查询被计入写配额 |
| D10 | 无开关（§0.9） | 入账入口是正确性地基，不应可关闭 |

### 4.3 数据流

```text
PLA-007 抽取候选（置信度达标 / 经 PLA-010 确认）
   ↓
ActionEngine.create_record(action_type="record_ledger_entry", ...)
   → evaluate_gates（权限 / 预算 / 一致性闸）
   → assemble_plan → 绑定 builtin.ledger.record
   → execute_plan
        ToolExecutor.run(builtin.ledger.record)
           ① 权限段  ② 确认段（大额 → 交 PLA-010 澄清）  ③ 校验段（schema / integer / 枚举）
           ④ 归一化  ⑤ 健康度（滑动窗 + 熔断）
        LedgerRecordCapability.execute(payload)
           → services/ledger/service.record_entry(draft, idempotency_key=...)
           → CapabilityResult(ok, data={"entry_id","created"})
   → integrate_result（写回 action_records 台账 / steps[]）

查询：PLA-015 API 或对话内查询 → ledger.query 能力 → services/ledger/query.summary
订正：PLA-010 订正指令 → ledger.revise 能力 → services/ledger/service.reverse_entry
```

## 5. Implementation Plan

1. **能力实现**：`services/action/capabilities/ledger.py`——三个 `Capability` 子类（或按既有能力实现形态），每个含 `capability_id` / `input_schema` / `side_effects` / `execute`。
2. **注册接线**：在 `services/tool/builtin.py`（或其 manifests 目录）注册 `builtin.ledger.*`；确认注册期七项校验通过。
3. **动作映射**：`character/asuna/action.py::ACTION_CAPABILITY_MAP` 增记账类动作映射；`action_type` 枚举扩展。
4. **意图词表**：`services/action/detector.py` 增记账意图的**组合判定**（动词 + 金额结构），并补**反例**（「我记得」「记账本就是」等不得命中）。
5. **服务层对接**：能力内部调用 PLA-005 `record_entry` / `reverse_entry` 与 PLA-006 `summary`；**不新写业务逻辑**。
6. **失败与健康度**：确保能力异常被 `CapabilityExecutor` 归一；打桩验证健康度熔断生效。
7. **测试**（§7），Focused → Module → Fast。
8. **台账抽样核对**：手工跑一次记账，检查 `action_records.status` 流转与 `steps[]` 内容完整。
