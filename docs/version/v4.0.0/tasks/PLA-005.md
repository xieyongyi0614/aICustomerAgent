## 2. Background

### 2.1 为什么写面必须唯一

项目既有铁律：**DB 唯一写面**（业务层禁止直接操作 ORM，一律经 `repositories/`）。账本域是最不能例外的领域：

| 若允许旁路写，会发生 | 后果 |
|---|---|
| 某处直接 `INSERT` 而不校验 `idempotency_key` | 同一笔消费被记两次，账目翻倍 |
| 某处直接 `UPDATE amount_minor` 纠错 | 破坏 append-only，历史不可对账 |
| 某处直接 `DELETE` 条目 | 账目凭空消失，审计链断裂 |
| 某处绕过 `user_id` 校验 | 越权写入他人账本 |

### 2.2 现状

账本域在 PLA-004 之前**完全不存在**；本任务是它的**第一次写入落地**，因此也是把「单一写面 + append-only + 冲正」这三条纪律**一次性固化**的最佳时机。

### 2.3 在 V4.0 中的位置

- PLA-006（聚合）与 PLA-007（抽取）的直接前置；
- **PLA-003 声明的「账本域注册」在本任务完成**（治理 handler 需要写面，故随仓储落地，避免循环依赖）；
- 是 `tasks.md` §2.3 风险点 4「PLA-005 必须先于 PLA-007 上线」的承担者——抽取先跑而无写面与幂等，会直接产出重复账目。

## 3. Scope

### 3.1 In Scope

1. **仓储**（`repositories/ledger_repository.py`，唯一写面）：

   ```python
   def create_account(user_id, name, type, *, currency=None, now=None) -> LedgerAccountRow: ...
   def get_account(account_id) -> LedgerAccountRow | None: ...
   def list_accounts(user_id, *, include_archived=False) -> list[LedgerAccountRow]: ...
   def ensure_default_account(user_id, *, now=None) -> LedgerAccountRow: ...

   def create_category(user_id, name, kind, *, parent_id=None, aliases=None, is_seed=False, now=None) -> LedgerCategoryRow: ...
   def get_category(category_id) -> LedgerCategoryRow | None: ...
   def list_categories(user_id, *, kind=None) -> list[LedgerCategoryRow]: ...
   def find_by_alias(user_id, text) -> LedgerCategoryRow | None: ...
   def ensure_seed_categories(user_id, *, now=None) -> int: ...

   def create_entry(entry: LedgerEntryDraft, *, idempotency_key: str, now=None) -> tuple[LedgerEntryRow, bool]: ...
       """返回 (行, created)；命中幂等键时返回既有行且 created=False，不报错、不重复写。"""

   def get_entry(entry_id) -> LedgerEntryRow | None: ...
   def list_entries(user_id, *, account_id=None, category_id=None, since=None, until=None,
                    direction=None, limit=None, offset=None, include_reversals=True) -> list[LedgerEntryRow]: ...
   def reversal_of(entry_id) -> LedgerEntryRow | None: ...
   ```

2. **业务服务**（`services/ledger/service.py`）：
   - `record_entry(draft, *, idempotency_key, now=None) -> RecordOutcome`：校验（方向 / 金额 / 账户存在 / 账户归属）→ 幂等 → 落账 → 溯源登记 → 返回 `RecordOutcome(entry, created, reason)`；
   - `reverse_entry(entry_id, *, reason, idempotency_key, now=None) -> RecordOutcome`：生成**反向条目**（`amount_minor` 同值、`direction` 取反）+ `reversal_of=原 id`；**原行不删不改**；已冲正过的条目再次冲正 → 幂等返回既有冲正行；
   - `ensure_user_bootstrap(user_id, *, now=None) -> BootstrapReport`：幂等建默认账户（「现金」）+ 种子类目树；
   - `RecordOutcome` / `BootstrapReport` 值对象（`frozen`）。
3. **种子类目树**（数据来源）：`character/<persona>/ledger_categories.py` 提供 `SEED_CATEGORY_TREE`（两级：餐饮 / 交通 / 购物 / 居住 / 医疗 / 娱乐 / 学习 / 人情 / 其他，含别名词表）。**本任务只消费该常量并播种**；归一算法归 PLA-008。
4. **治理域注册**（对齐 PLA-003 的注册点）：

   ```python
   register_domain(DomainHandlers(
       name="ledger",
       export=export_ledger_data,     # user_id -> {"accounts": [...], "categories": [...], "entries": [...]}
       delete=delete_ledger_data,     # user_id -> 删除行数（先 entries 后 categories/accounts）
       provenance=lambda domain, rid: resolve_ledger_provenance(rid),
   ))
   ```
   删除实现**必须经本任务交付的仓储面**（不得直接 SQL）。
5. **conftest 登记**：`ledger_repository` 登记进 `tests/conftest.py::_REPO_MODULES`；若 `services/ledger/service.py` 使用模块级 `SessionLocal`，登记进 `_SERVICE_DB_MODULES`。
6. **审计**：每次 `record_entry` / `reverse_entry` 落既有审计通道（复用 `services/observability` 或行动台账，按 Detail 冻结），保证可追溯。

### 3.2 Out of Scope（明确禁止扩张）

- **不做聚合查询**（PLA-006）；不做任何 `SUM` / 分组统计。
- **不做抽取**（PLA-007）；本任务的入口是**结构化 draft**，不接受自然语言。
- **不做确认交互**（PLA-010）；不做澄清回问、不做待确认登记。
- **不做定时 / 重试 / 调度**（不写 `next_retry_at` 类字段，不建调度记录）。
- **不做类目归一算法**（PLA-008）：`find_by_alias` 只做**精确别名命中**，不做规则 / 兜底 / LLM。
- **不做批量导入**（`source="import"` 枚举预留但无实现）。
- **不新增任何功能开关**（§0.9）；**不新增任何表**（零新表承诺）。
- 不改 `models/ledger.py` 的枚举域（PLA-004 冻结）。

## 4. Technical Design Requirements

### 4.1 接口契约

```python
@dataclass(frozen=True, slots=True)
class RecordOutcome:
    entry: LedgerEntryRow
    created: bool                 # False = 幂等命中，返回既有行
    reason: str                   # "created" | "idempotent_hit" | "reversed" | ...


@dataclass(frozen=True, slots=True)
class BootstrapReport:
    user_id: str
    account_created: bool
    categories_created: int
    created_at: datetime


def record_entry(draft: LedgerEntryDraft, *, idempotency_key: str,
                 now: datetime | None = None) -> RecordOutcome: ...

def reverse_entry(entry_id: str, *, reason: str, idempotency_key: str,
                  now: datetime | None = None) -> RecordOutcome: ...

def ensure_user_bootstrap(user_id: str, *, now: datetime | None = None) -> BootstrapReport: ...
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **幂等命中返回既有行而非抛错**（`created=False`） | 重复消息（飞书重投 / 用户连点）是常态；抛错会把「正常重放」变成故障。调用方按 `created` 决定是否播报 |
| D2 | 冲正**生成反向条目**（`amount_minor` 同值 + `direction` 取反），不写负金额 | 保持 INV-1（`amount_minor > 0`）在 DDL 层成立；净额由聚合双向计入（PLA-006） |
| D3 | 同一 `source_ref` **不重复沖正**：冲正也用 `idempotency_key` 守护 | 重复「撤销」指令不应产生两条冲正（否则净额变成负的原值） |
| D4 | 校验在**服务层**（账户存在 / 归属一致 / 方向与金额合法），仓储只做 CRUD | 与项目「仓储不做业务判断」纪律一致 |
| D5 | `ensure_*` 三件套**全部幂等**（对齐 `world_entities` 播种范式） | 播种在启动 / 首次访问都可能触发，必须可重复执行 |
| D6 | 种子类目**用 `is_seed=true` 标记**，不覆盖用户已改的类目 | 用户可能重命名 / 删除种子类目；播种不得「复活」或覆盖用户意图 |
| D7 | 治理删除**先 entries 后 categories / accounts** | 避免 FK 悬空；删除必须经本任务仓储面（PLA-003 裁决 D4） |
| D8 | `create_entry` 是**唯一**新增条目的入口；仓储层不暴露裸 `insert` | 单一写面纪律的可机械校验形态 |
| D9 | 无开关（§0.9） | 写面是正确性地基，不该可关闭 |

### 4.3 数据流

```text
记账：record_entry(draft, idempotency_key)
   → 服务层校验（金额 > 0 / 方向合法 / 账户存在且属本人 / 类目属本人）
   → ledger_repository.create_entry(...)
        命中 idempotency_key → (既有行, created=False)
        未命中             → (新行, created=True)
   → 溯源登记（source / source_ref 已在 draft 内）
   → 审计
   → RecordOutcome

纠错：reverse_entry(entry_id, reason, idempotency_key)
   → 取原行 → 生成反向行（direction 取反、reversal_of=原 id）
   → 原行【零改动】
   → RecordOutcome(created=True/False)

播种：ensure_user_bootstrap(user_id)
   → ensure_default_account("现金") → 幂等
   → ensure_seed_categories() → 只建缺失的 seed 项，不覆盖用户改动

治理：export_ledger_data / delete_ledger_data（经仓储面）
```
