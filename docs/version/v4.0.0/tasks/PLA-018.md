## 2. Background

### 2.1 审计发现的「测试态 ≠ 生产态」

`docs/version/v3.0.0/acceptance-report.md` 的边界不变量 8「前后台共用同一认知循环」判定为 **PASS**，但该 PASS 是在**开关开启的测试态**下成立的。默认生产配置的实际形态是：

| 路径 | 生产默认 | 证据 |
|---|---|---|
| 前台 | ✅ 已收编 `AgentLoop.run()` + `profiles.py` 9 段序列 | `core/settings/agent_runtime.py:41` `runtime_foreground_loop_enabled = True`；`chat_pipeline.py:401`、`:880-893` |
| 后台 | ❌ 仍走 legacy `_legacy_run_autonomous_cycle` | `core/settings/agent_runtime.py:40` `runtime_autonomous_cycle_enabled = False`；`controller.py:319-336`、`:255-316` |
| 六段 | 🔒 影子实现，未接入 | `settings/agent_runtime.py:42` `= False`；`stages/__init__.py:25 SHADOW_STAGE_IMPLEMENTATION = True` |

### 2.2 为什么必须现在处理

V4.0 的**节律投递（PLA-011）**与**超支预警（PLA-013）**要挂在维护步 / `trigger_registry` 上。若后台仍走 legacy，则：

1. 新能力会挂在 legacy 链上，形成「同一能力两条链路」；
2. 与架构不变量 1（Runtime 只调度）与不变量 12（零平行路径）冲突；
3. 排障时需要同时理解两套调度语义。

因此本任务列为 Phase 1 的**第 1 步交付**（`tasks.md` §4.2）：**先统一调度路径，再往上叠功能。**

### 2.3 在 V4.0 中的位置

PLA-011 / PLA-013 的**直接前置**（挂载面合法性）；PLA-017 的 G15（运行时单一路径）由本任务达成。

## 4. Technical Design Requirements

### 4.1 接口契约（签名不变，语义收敛）

```python
def run_autonomous_cycle(user_id: str, *, now: datetime | None = None) -> AutonomousCycleResult:
    """后台自治周期唯一入口。
    内部固定走 AgentLoop + profiles.get_profile(AUTONOMOUS_TICK).stages；
    不再按 runtime_autonomous_cycle_enabled 分支到 legacy。"""


def _run_autonomous_cycle_via_loop(user_id: str, *, now: datetime | None = None) -> AutonomousCycleResult:
    """实施体（原 :339 起）；成为 run_autonomous_cycle 的唯一实现路径。"""


def _legacy_run_autonomous_cycle(user_id: str, *, now: datetime | None = None) -> AutonomousCycleResult:
    """【回退位·代码级】不再被配置触达。保留至 flag-removal 批次删除。
    仅允许通过显式代码调用（回滚期）使用，文档登记其不可配置性。"""
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **统一，而非切换**：`runtime_autonomous_cycle_enabled` 不再作为分支条件 | 保留「切换」语义等于承认两条路径都合法；架构不变量 12（零平行路径）要求只有一条 |
| D2 | 保留字段本身、只置唯一有效值，**字段删除留给 flag-removal 批次** | 一次做一件事：本任务目标是「路径统一」，不是「配置清理」；混在一起会让回滚边界模糊 |
| D3 | legacy 分支保留为**代码级**回退位，**不可由配置触达** | 给紧急回滚留手工手段，同时不让它成为可配置的「第三条路径」 |
| D4 | 六段循环保持影子，**不随本任务激活** | 六段价值在循环形态，与「路径统一」是两个独立问题（裁决 R5） |
| D5 | 等价性必须**对照证明**，不接受「看起来一样」 | V3.0 的教训正是「开关开启的测试态」被当成了生产态；本任务用对照用例把等价性钉死 |
| D6 | 空转（无 due 工作）**0 LLM、0 Run** 语义不变 | 既有自治的核心成本纪律（`test_idle_short_circuit_zero_llm_zero_runs`），统一不得破坏 |
| D7 | 不新增开关（裁决 9） | 本任务恰是「消除开关」方向，加开关自相矛盾 |

### 4.3 数据流

```text
【统一前】
life_loop.run_life_loop_tick
   → agent_runtime.run_autonomous_cycle
        runtime_autonomous_cycle_enabled == False（默认）
             → _legacy_run_autonomous_cycle        ← 生产实际路径
        runtime_autonomous_cycle_enabled == True
             → _run_autonomous_cycle_via_loop(AgentLoop)

【统一后】
life_loop.run_life_loop_tick
   → agent_runtime.run_autonomous_cycle
        → _run_autonomous_cycle_via_loop            ← 唯一路径
             AgentLoop(spec=AUTONOMOUS_TICK, STAGE_RUNNERS)
                 budget_tier / llm_capable / critical 语义不变
                 三道预算闸 → llm_gateway.acquire → autonomy_engine.tick
        （_legacy_run_autonomous_cycle 仅可被代码显式调用）
```

- **禁止**依赖：任何具体渠道实现（`app.channels.feishu`）、`app.chains` 直调、`app.prompts`。

## 5. Implementation Plan

1. **对照测试先行**（推荐）：先写等价性对照用例（legacy vs AgentLoop 同 tick 输出对比），拿到「统一前」基线。

4. **legacy 降级标注**：`_legacy_run_autonomous_cycle` 的 docstring 登记「回退位·不可由配置触达·待 flag-removal 批次删除」（项目约定不写代码注释，故以 docstring + 文档登记承载）。

8. **基线回写**：`docs/current-system-architecture-baseline.md` §4.2 更新后台默认路径描述（由「legacy 默认」改为「统一经 Agent Runtime」）。
