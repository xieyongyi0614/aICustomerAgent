## 2. Background

### 2.1 为什么这一相是「边界验证」而不是「新能力」

项目已有的认知上层完全够用：

| 既有能力 | 位置 | 洞察场景的对应 |
|---|---|---|
| 证据窗聚合 | `services/reflection/evidence.py` | 把账目聚合特征作为证据输入 |
| 结构化推理 | `services/reflection/reflector.py` | 从证据推出「模式」叙述 |
| confidence 校准 + 三闸复检 | `services/reflection/`（V2.6.1 三闸） | 拒绝低置信模式 |
| Insight 生命周期 | `active → superseded / invalidated` | 模式演化 |
| 候选摄取（幂等） | `services/memory2/ingest.py`（`memory_candidates` 唯一约束） | 模式入记忆 |
| 类型封顶 7 类 | `services/memory2/types.py`（含 `behavior_pattern`） | 洞察的天然归属类型 |
| Development（belief / preference / pattern） | `services/development/` | 长期行为演化（由 Evolution 编译，本任务不碰） |

**因此本任务不新建认知能力**，只做两件事：① 把账本聚合特征**投影成证据**；② 严格约束**什么可以进记忆**。它的价值在于**把架构 §4.1 的裁决落成可机械校验的边界**。

### 2.2 边界的精确含义

| 允许进记忆 | 禁止进记忆 |
|---|---|
| 抽象模式（`behavior_pattern`，如「高频外卖」「夜间消费占比偏高」） | **任何金额明细**（`20 元`、`320.50`） |
| 经既有 Reflection 证据窗与三闸 | 绕过三闸直达 `memories` |
| 受既有 200 条 active 上限与 `salience` 衰减约束 | — |

> **注意**：洞察候选**受衰减与上限约束是正确的**，不是缺陷。记忆本该遗忘，账本才不该。这条区分正是本任务要固化的东西。

### 2.3 在 V4.0 中的位置

- 交付顺序第 7 步（P2，可延后至版本内末尾）；
- 为后续生活域（健康 / 待办）提供「领域 → 认知上层」的接入范例。

## 3. Scope

### 3.1 In Scope

1. **特征投影**（`services/ledger/insight.py::project_features`）：
   把 PLA-006 聚合结果投影为**不含金额的结构化特征**，作为 Reflection 的证据输入：

   ```python
   @dataclass(frozen=True, slots=True)
   class SpendingFeatures:
       period: Period
       top_category_share: Mapping[str, float]   # 类目名 -> 占比（非金额）
       late_night_ratio: float                   # 夜间（如 22:00 后）消费占比
       unclassified_ratio: float                 # 未归类占比
       frequency_by_category: Mapping[str, int]  # 类目名 -> 次数
       weekday_vs_weekend_ratio: float
       entry_count: int
       reversal_count: int
   ```

   - **关键约束**：`SpendingFeatures` **不含任何金额字段**（无 `amount` / `total` / `min` / `max`）。比率、次数、占比可以进；金额不行。这是把「零金额入记忆」做成**类型层保证**而非纪律口号。
2. **证据与洞察生成**（复用既有 Reflection）：
   - 把 `SpendingFeatures` 包装为既有证据窗的输入（沿 `services/reflection/evidence.py` 的既有证据结构，**不改其结构**）；
   - 触发方式：挂既有 `reflection_check` 路径（后台周期），或由既有触发条件驱动——**不新增常驻循环**；
   - 洞察文本由既有 `reflector` 生成（LLM 参与，但输入无金额，输出亦无金额）。
3. **候选摄取约束**（`services/ledger/memory_bridge.py`）：
   - 仅允许 `type == "behavior_pattern"` 的洞察进入 `memory2` 候选摄取；
   - 入候选前做**文本级金额断言**：复用 PLA-003 的 `prompt_guard.assert_no_financial_detail` 校验候选文本（**双保险**：类型层 + 文本层）；
   - 走既有 `services/memory2/ingest.py`（**唯一候选摄取入口**），不绕过 R1~R8。
4. **零金额硬保证**：
   - `SpendingFeatures` 无金额字段（类型断言）；
   - 候选文本过 `assert_no_financial_detail`（运行时断言 + 用例）；
   - 全仓静态扫描：`memories` / `memory_candidates` 相关写入路径不接收账本金额字段。

### 3.2 Out of Scope（明确禁止扩张）

- **不改 Reflection 三闸**（confidence 校准 / 复检）与 Insight 生命周期数学（Preserve）。
- **不改 Development 编译**（唯 Evolution；本任务不碰 `personality_state`）。
- **不改 `memory2` 的 7 类封顶、R1~R8、200 条上限、衰减公式**（Preserve）。
- **不做消费预测**（「下个月你会花多少」）——属预测，架构 §11 未排期。
- **不做财务建议**（「建议你少点外卖」）——避免越界为理财顾问（架构 §0.3 Non-Goal）。
- **不做对外分享 / 社交化对比**（与他人比较消费）。
- **不做洞察的可视化**（前端归 PLA-016，若需展示则另立）。
- **不新增记忆类型**、**不新增表**、**不新增功能开关**（§0.9 / §10.8）。
- 不改账本域既有模块（PLA-004~013 冻结）。

## 4. Technical Design Requirements

### 4.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | `SpendingFeatures` **不含任何金额字段** | 用类型层保证「零金额入记忆」，比纪律约束可靠；也避免下游误用金额 |
| D2 | 洞察**复用既有 Reflection 证据窗与三闸**，不新建认知链路 | Preserve 纪律；三闸是项目已验证的质量门 |
| D3 | 只有 `behavior_pattern` 类可入记忆；**由类型字段 + 文本断言双保险** | 单一防线容易在后续演进中被绕过；双层保证可机械校验 |
| D4 | 入候选走 **`memory2/ingest.py` 唯一入口**，遵守 R1~R8 | 绕过入口会破坏幂等（`memory_candidates` 唯一约束）与策略一致性 |
| D5 | 洞察候选**受既有衰减与上限约束**，不做豁免 | 记忆本该遗忘；账本才不该。这条区分是架构 §4.1 的落点 |
| D6 | 挂**既有 reflection 检查路径**，不新增常驻循环 | 架构 §2.3 第 4 条 |
| D7 | 洞察输出**不含金额数字**；若模型输出金额 → 丢弃并记审计 | 与 PLA-011 / 013 同一零幻觉原则；此处额外做文本断言 |
| D8 | 不做财务建议（只描述模式，不给行动建议） | 避免越界为投资 / 理财顾问（架构 §0.3） |
| D9 | 无开关（§0.9） | 洞察是 P2 能力，交付即生效；如效果不佳由后续决策调整，不靠开关 |

### 4.2 数据流

```text
后台周期（既有 reflection_check 路径）
   → project_features(user_id, period)
        PLA-006 summary（读金额用于**计算比率**）→ 立刻丢弃金额
        → SpendingFeatures（只含比率 / 占比 / 次数）
   → 包装为既有 Reflection 证据（不改证据结构）
   → 既有 reflector → Insight（含文本模式叙述，不含金额）
   → 三闸复检（既有）
   → memory_bridge.filter_and_ingest(insight)
        ① type 必须 == "behavior_pattern"
        ② assert_no_financial_detail(insight.text)  ← 文本层双保险
        ③ memory2/ingest.py 唯一入口 → memory_candidates（幂等）
   → Development（长期行为演化，由既有 Evolution 编译，本任务不触发）
```

### 4.3 依赖

- 允许依赖：`app.services.ledger.query`（只读聚合）、`app.services.reflection.*`（既有证据 / 反射 / 三闸）、`app.services.memory2.ingest`（唯一候选入口）、`app.services.governance.prompt_guard`（金额文本断言）。
- **禁止**依赖：账本写面（`ledger_repository` 写方法）、`app.api`、`app.channels.<impl>`、`personality_state` 直写。

## 5. Implementation Plan

1. **特征投影**：`services/ledger/insight.py::project_features` + `SpendingFeatures`（**无金额字段**）。
2. **证据适配**：把 `SpendingFeatures` 包装为既有 Reflection 证据结构（适配函数，不改上游结构）。
3. **桥接与过滤**：`services/ledger/memory_bridge.py`——类型过滤 + 文本金额断言 + 走 `memory2/ingest`。
4. **挂接**：在既有 Reflection 检查路径中接入账本证据源（**只追加证据来源，不改三闸**）。
5. **审计**：被过滤掉的洞察（含金额 / 非 `behavior_pattern` 类）记审计，不静默丢弃。
6. **测试**（§7），Focused → Module → Fast。
7. **边界核验**：静态 + 运行时双重断言「记忆里零金额」。
