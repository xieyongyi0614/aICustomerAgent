## 2. Background

### 2.1 为什么需要这个 Task

系统当前所有「生活」语义都挂在角色身上：

| 事实 | 证据 |
|---|---|
| 世界的定义是角色视角 | `character/asuna/world.py:12` `"description": "你和亚丝娜的家"` |
| 作息模板是角色的 | `character/asuna/routine.py:12` `ROUTINE_TEMPLATES`（做早餐 / 工作学习 / 下午茶） |
| 日计划由角色作息驱动 | `services/world/daily_plan.py:125` `build_daily_plan` |
| 用户处境只是「角色视角下的标签」 | `services/world/user_situation.py:3` 自述「处境是世界域事实（**角色视角下用户属于世界**）」；`:43-79` `SITUATION_PATTERNS` 仅 health / work / travel / emotional 5 维，**无消费维度** |

后果：个人生活 Agent 要承载的用户数据（账本、待办、健康、物品）**没有归属容器**。若直接复用角色世界，会出现「用户的账目挂在亚丝娜的家里」这类语义混乱。

### 2.2 当前架构问题

| # | 问题 | 影响 |
|---|---|---|
| O3 | 世界归属未定义（`worlds` 无 owner 概念） | 无法区分「角色的世界」与「用户的生活」 |
| O4 | 用户生活无容器 | 用户维度数据只能寄生于角色世界或散落各表 |
| — | 越权不可判 | 无法回答「这次读取是否越界」——PLA-015 的越权断言缺前置 |

### 2.3 在 V4.0 中的位置

PLA-002 与 PLA-003 / PLA-004 / PLA-018 并列为 B1 四并行面。它是 **PLA-015（查询 API 越权防护）的前置**：没有归属定义，「不得读写他人数据」这条红线无处落地。

> **与 V8 / V2.3 的边界**：V8（World State）与 V2.3（World Simulation）的**域模型与数学零改动**（Preserve）。本任务只**新增归属维度**并接入一个只读解析点。

## 3. Scope

### 3.1 In Scope

1. **归属列（迁移并入 `0053`，与 PLA-001 同批，一次迁移）**：
   - `worlds.owner_type`：`sa.String()`，`nullable=True`，**服务端默认 `"character"` 语义**（见裁决 D1）；
   - `worlds.owner_id`：`sa.String()`，`nullable=True`；
   - 索引：`ix_worlds_owner` on `(owner_type, owner_id)`（复合，支撑按归属过滤）。
2. **ORM 同步**：`core/db.py::WorldRow` 增两列（与既有列共表，不改其他列）。
3. **归属纯函数模块**：`services/life/ownership.py`：
   - `OWNER_CHARACTER = "character"` / `OWNER_USER = "user"` 常量；
   - `resolve_owner(row | mapping) -> OwnerRef`——归一归属（`owner_type` 为空 → 视为 `character`；`owner_id` 为空 → 取 `DEFAULT_CHARACTER_ID` 或 `default_user`，按 owner_type 分流）；
   - `assert_access(owner: OwnerRef, *, user_id: str, character_id: str, mode: Literal["read","write"]) -> AccessDecision`——纯判定，返回 `AccessDecision(allowed: bool, reason: str)`，**不抛异常**；
   - `scope_filter(owner_type, owner_id) -> dict`——生成查询过滤条件的纯值对象。
   - **纪律**：零 IO、零 LLM、零 random、零时钟依赖（`now` 若需要则由调用方传入），可直接单测。
4. **世界引擎接入点（只读）**：`application/world_engine.py` 在构建世界上下文处调用 `resolve_owner` / `assert_access`；越权时按**世界旁路纪律**处理——记录并降级为「空世界上下文」，**绝不阻断聊天与主动链路**。
5. **用户生活容器的最小可用形态**：允许以 `owner_type="user"` + `owner_id=<user_id>` 的 `worlds` 行承载用户生活容器；**本任务只提供建模能力与解析**，不建内容（内容随后续生活域逐域补充）。既有 `home` 世界保持 `owner_type="character"`。

### 3.2 Out of Scope（明确禁止扩张）

- **不做世界推演升级**（世界推演是 V2.3.0 领域能力，本版本只消费）。
- **不改 V8 / V2.3 的世界数学、状态机、OBJECT_STATE_MACHINES、时间系统、天气演化**（Preserve）。
- **不做数据迁移**：既有 `worlds` 行保持 `owner_type=NULL`，由 `resolve_owner` 归一为 `character`（避免 UPDATE 全表）。
- **不实现用户生活容器的内容建模**（账本归 PLA-004，待办 / 健康 / 物品为后续版本）。
- **不做多世界并行运营**（不建世界切换入口、不做世界列表 UI）。
- **不新增任何功能开关**（§0.9）：归属校验直接生效，无 `life_ownership_enforced` 之类字段。
- 不改 `services/world/*` 既有模块的对外签名（只在 `world_engine` 增解析调用）。

## 4. Technical Design Requirements

### 4.1 接口契约

```python
OWNER_CHARACTER: str = "character"
OWNER_USER: str = "user"


@dataclass(frozen=True, slots=True)
class OwnerRef:
    owner_type: str          # "character" | "user"
    owner_id: str
    is_legacy: bool          # True = 由 NULL 归一而来（用于审计与灰度观察）


@dataclass(frozen=True, slots=True)
class AccessDecision:
    allowed: bool
    reason: str              # "same_owner" | "character_world_readonly" | "cross_user_denied" | ...


def resolve_owner(
    row: Mapping[str, Any] | Any,
    *,
    character_id: str,
    user_id: str,
) -> OwnerRef:
    """把 worlds 行归一为归属引用；NULL 视为 character + character_id。"""


def assert_access(
    owner: OwnerRef,
    *,
    user_id: str,
    character_id: str,
    mode: Literal["read", "write"] = "read",
) -> AccessDecision:
    """纯判定，不抛异常、不写日志、不做 IO。"""


def scope_filter(owner: OwnerRef) -> dict[str, Any]:
    """生成仓储过滤条件（值对象，不执行查询）。"""
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | `owner_type` **列可空**，NULL 在 `resolve_owner` 中归一为 `"character"` | 不写默认值（DB 默认值需 UPDATE 既有行或依赖 dialect 行为）；**零数据迁移**即兼容，且 `is_legacy=True` 让「归一发生了几次」可审计 |
| D2 | **角色世界对用户「只读可见」**，用户容器对角色默认不可见 | 角色需要知道用户的生活（这是双人设定的一部分）；反向不需要。是否放开由后续域按需声明，**本任务冻结为「角色世界只读、用户容器定向可见」** |
| D3 | `assert_access` **返回判定而非抛异常** | 调用方按纪律降级（世界旁路：异常只 log 并给 None / 空段）；抛异常会把世界失败升级为链路失败 |
| D4 | 归属解析放在 `application/world_engine.py` 的**读取口**，不放进 `services/world/*` 各子模块 | 一个接入点好维护；散进子模块会污染 Preserve 面（V8 / V2.3 零改动） |
| D5 | 归属用**复合索引 `(owner_type, owner_id)`** 而非两列独立索引 | 查询形态恒为「同归属」双条件，复合索引才有选择性 |
| D6 | 允许 `owner_type="user"` 的 `worlds` 行存在，但**本任务不建内容** | 给后续生活域一个既定容器；不建内容避免越界到账本 / 待办的领域设计 |
| D7 | 无开关（裁决 9）：校验直接生效 | 归属校验是「正确性问题」而非「灰度功能」——不正确就不该上线 |

### 4.3 数据流

```text
请求 → application/world_engine.build_context(user_id, session_id)
   → world_repository 读 worlds 行
   → resolve_owner(row, character_id=..., user_id=...)
         owner_type NULL → OwnerRef("character", DEFAULT_CHARACTER_ID, is_legacy=True)
         owner_type "user" → OwnerRef("user", owner_id, is_legacy=False)
   → assert_access(owner, mode="read")
         allowed   → 继续构建世界切片（既有逻辑零改动）
         not allow → 记 reason → 返回「空世界上下文」→ 聊天链路照常继续（旁路纪律）
```

### 4.4 依赖

- 允许依赖：`core.db`、`core.settings`、`character/<persona>/` 常量（`DEFAULT_CHARACTER_ID`）。
- **禁止**依赖：`app.chains`、`app.prompts`、`app.repositories`（纯函数不碰 DB）、`app.channels.*`、任何 LLM 组件。
