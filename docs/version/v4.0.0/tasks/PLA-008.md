## 2. Background

### 2.1 为什么类目归一是一个真问题

架构评审已把「中文消费表述的类目归一」标为 Phase C 的**真实难点**（review §5）。原因：

- 中文消费表述是**开放集**：「快餐」「盖浇饭」「黄焖鸡」「美团外卖」「楼下那家面馆」都指向餐饮，但字面差异极大；
- 若交给 LLM 随手分类，会出现三类漂移：
  1. **同类不同标**：同一家店今天归「餐饮」明天归「外卖」→ 聚合分布失去意义；
  2. **随手新建**：模型自造「中式快餐」这类不在类目树里的类目 → 类目树膨胀；
  3. **不可复现**：同一输入两次分类结果不同 → 用户对不上账。

**因此归一必须「确定性优先」**：能靠词表 / 规则确定解决的，绝不交给模型。

### 2.2 现状

`ledger_categories` 表已在 PLA-004 建立（含 `aliases` JSON 列、`is_seed` 标记、`parent_id` 树结构）；PLA-005 已提供 `find_by_alias`（**只做精确别名命中**）与 `ensure_seed_categories`（幂等播种）以及 `SEED_CATEGORY_TREE` 的最小版本。本任务在两者之上补齐**归一算法、词表规模与度量**。

### 2.3 在 V4.0 中的位置

- 是 PLA-009（能力入账）前的**最后一道数据质量关**：归一不站稳，聚合（PLA-006）与洞察（PLA-014）都会失真；
- 其命中率指标是 PLA-017 验收的样本之一。

## 3. Scope

### 3.1 In Scope

1. **种子类目树与别名词表**（`character/asuna/ledger_categories.py`，按人设分子目录约定）：

   | 一级类目 | 二级示例 | 别名示例 |
   |---|---|---|
   | 餐饮 | 早餐 / 午餐 / 晚餐 / 外卖 / 零食 / 饮品 | 快餐、盖浇饭、黄焖鸡、外卖、食堂、夜宵、奶茶、咖啡、烧烤、火锅 |
   | 交通 | 公交地铁 / 打车 / 加油 / 停车 | 地铁、公交、滴滴、出租车、加油、停车费 |
   | 购物 | 日用 / 服饰 / 数码 | 日用品、洗发水、衣服、鞋子、数据线 |
   | 居住 | 房租房贷 / 水电燃气 / 物业 | 房租、房贷、水费、电费、燃气、物业费 |
   | 医疗 | 门诊 / 药品 / 体检 | 看病、挂号、买药、药费、体检 |
   | 娱乐 | 电影 / 游戏 / 聚会 | 电影票、游戏充值、KTV、聚会 |
   | 学习 | 书籍 / 课程 | 买书、教材、网课、课程 |
   | 人情 | 礼物 / 红包 | 送礼、红包、份子钱、随礼 |
   | 其他 | —（兜底，由 `ledger_category_fallback` 指定名称） | — |

   结构约定：**两级为主**（`parent_id` 支持更深，但种子只种两级，避免过度设计）。

2. **归一服务**（`services/ledger/category.py`）：

   ```python
   def normalize(user_id: str, hint: str | None, *, kind: str = "expense",
                 now: datetime | None = None) -> NormalizationResult: ...
   ```

   归一顺序（**命中即止，逐步降级**）：

   ```
   Step 1 空值处理      hint 为空 → 兜底类目（reason="empty_hint"）
   Step 2 精确名称匹配   用户类目名 == hint
   Step 3 别名精确匹配   用户类目 aliases 命中
   Step 4 规则匹配       规范化（去空格 / 全半角归一 / 去后缀「费」「钱」）后重试 Step 2/3
   Step 5 子串包含匹配   类目名或别名是 hint 的子串（长匹配优先）
   Step 6 兜底           ledger_category_fallback（reason="fallback"）
   ```

   ```python
   @dataclass(frozen=True, slots=True)
   class NormalizationResult:
       category_id: str | None
       category_name: str
       matched_step: int          # 1..6，用于度量与调试
       reason: str                # "exact" | "alias" | "rule" | "substring" | "fallback" | "empty_hint"
       confidence: float
   ```

3. **用户自定义通路**：
   - `add_category(user_id, name, kind, *, parent_id=None, aliases=None)`；
   - `add_alias(user_id, category_id, alias)`——用户把「楼下那家面馆」绑到餐饮；
   - 用户自定义**优先级高于种子**（Step 2/3 天然满足，因按用户维度查询全部类目）。
4. **命中率度量**（`services/ledger/category_metrics.py`）：
   - `evaluate(samples: Sequence[Sample]) -> CategoryMetricsReport`：命中率（Step 2~5 占比）、兜底率、耗散（同一 hint 多次归一是否一致）；
   - 样本集落 `tests/v40/fixtures/ledger_category_samples.py`（**≥120 条真实中文消费表述**，人工标注期望类目）；
   - 报告可离线运行，**不参与运行时链路**。
5. **零新建类目保证**：归一过程**只读**类目；任何路径都不得创建类目（新增类目只经 §3.1 第 3 项的用户显式通路与 `ensure_seed_categories`）。

### 3.2 Out of Scope（明确禁止扩张）

- **不做自动类目发现 / 聚类 / 重分类批处理**（架构 Backlog）。
- **不做多语言**（首版仅中文）。
- **不做类目预算**（预算走 Goal Stack，PLA-012）。

## 4. Technical Design Requirements

### 4.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **确定性优先**：Step 2~5 全部为确定性算法（字符串比较 / 规范化 / 子串），命中即止 | 可复现、可单测、零成本、零延迟。开放集问题不能靠更深的理解，而要靠可控的降级梯度 |
| D2 | **规则归一（Step 4）只做无损变换**：去首尾空格 / 全半角归一 / 去尾部「费」「钱」等虚词 | 有损变换（如截断 / 同义词替换）会引入不可解释的错配；宁可落到兜底 |
| D3 | **子串匹配长优先**（Step 5） | 「外卖」与「美团外卖」同时命中时，长者更具体；短者优先会把手写类目错配 |
| D4 | **不引入 LLM 兜底**（评审原考虑过 LLM 作最后兜底，本任务裁决为**不做**） | ① 兜底发生频率低（目标 < 15%）；② LLM 兜底必然引入不确定性与「随手新建」风险；③ 每多一次 LLM 调用就多一次幻觉面。**宁可显式兜底为「其他」并让用户补齐** |
| D5 | 归一结果**必须带 `matched_step` 与 `reason`** | 命中率度量与问题追查的基础；也是「兜底可统计」的实现方式 |
| D6 | 归一过程**绝对只读**，任何路径不得新建类目 | 防止「分类时顺手建类目」造成类目树膨胀；新建只经用户显式操作 |
| D7 | 用户自定义类目 / 别名**优先于种子**（同层级下用户项先匹配） | 用户的语义才是权威；种子只是默认值 |
| D8 | 样本集 **≥120 条**且人工标注 | 命中率是「可判定」指标，必须有固定样本与期望值；拍脑袋阈值不可验收 |
| D9 | 度量与报告**离线**，不进运行时链路 | 运行时只做归一，不做统计；避免热路径开销 |
| D10 | 无开关（§0.9）；`ledger_category_fallback` 是**取值参数**（兜底类目名） | 归一能力交付即生效；兜底名是配置项 |

### 4.2 归一算法（规范化细节）

```text
normalize_text(hint):
  1) strip + 去除首尾标点
  2) 全角 → 半角（数字 / 英文字母 / 括号）
  3) 去除内部空白
  4) 去除尾部虚词：["费", "钱", "钱儿", "的钱"]   # 仅尾部，不做全文替换

匹配：
  Step 2: categories(name == hint)                     → reason="exact"
  Step 3: categories(aliases ∋ hint)                    → reason="alias"
  Step 4: 对 normalize_text(hint) 重试 Step 2/3          → reason="rule"
  Step 5: max_len({name, *aliases} ⊂ hint)              → reason="substring"
  Step 6: fallback 类目（不存在则由调用方决定是否建）      → reason="fallback"
```

### 4.3 数据流

```text
PLA-007 产出 category_hint（原文，未归一）
   ↓
normalize(user_id, hint, kind)
   → Step 1~6（命中即止）
   → NormalizationResult(category_id, category_name, matched_step, reason, confidence)
   ↓
PLA-009 能力入账：把 category_id 写进 LedgerEntryDraft
   ↓（离线）
category_metrics.evaluate(samples) → 命中率 / 兜底率 / 一致性报告 → PLA-017 验收输入
```

- **禁止**依赖：任何 LLM 组件（`app.chains` / `llm_factory`）、`app.prompts`、`app.api`、`app.channels.*`。

## 5. Implementation Plan

1. **扩种子词表**：`character/asuna/ledger_categories.py::SEED_CATEGORY_TREE` 补全 §3.1 第 1 项的两级结构 + 别名（PLA-005 建立的骨架在此扩为完整版）。
2. **归一服务**：`services/ledger/category.py`——`normalize_text` / `normalize` / `NormalizationResult`；Step 1~6 逐级实现并单测。
3. **用户自定义通路**：`add_category` / `add_alias`（经仓储写面；校验名称非空、kind 合法、不越权）。
4. **样本集**：`tests/v40/fixtures/ledger_category_samples.py`（≥120 条，人工标注期望类目；覆盖 9 个一级类目与常见口语表述）。
5. **度量与报告**：`services/ledger/category_metrics.py` + `evaluate(...)`；产出命中率 / 兜底率 / 一致性三项指标。
6. **设置**：`core/settings/ledger.py` 增 `ledger_category_fallback: str = "其他"`；登记 `tests/v40/support.py`。
7. **阈值冻结**：跑样本集得到实测命中率，在 Detail 中冻结**验收阈值**（建议兜底率 ≤ 15%，一致性 100%）；阈值写进 PLA-017 的 Gate 证据。
8. **测试**（§7），Focused → Module → Fast。
