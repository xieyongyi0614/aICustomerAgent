## 2. Background

### 2.1 为什么账本必须是独立领域（不能塞进记忆）

| 账目要求 | 记忆的机制（证据） | 结论 |
|---|---|---|
| 精确、不可篡改 | LLM 抽取，`content` 为自然语言 | 冲突 |
| **不可遗忘** | `salience · exp(-λ·Δdays)` 衰减 + `decayed` / `forgotten` 生命周期 | **冲突（会忘掉花过的钱）** |
| 无限增长 | 单用户 active **软上限 200**，超出 `capacity_drop` 丢弃（`privacy-governance.md` §2） | 冲突 |
| 可累加可对账 | 无 amount / currency / category 字段，无法 SQL 聚合 | 冲突 |
| 必须保存金额 | 目标策略 L2（含财务）「不保存」→ 由 PLA-003 重裁 | 冲突（PLA-003 已处置） |
| 订正留痕 | 冲突消解走 `superseded`（取代），无冲正语义 | 冲突 |

**因此账本条目无衰减、无失效、无容量上限、无过期**——与记忆相反，**这是设计意图，不是遗漏**（架构 §4.1）。

### 2.2 现状：用户财务事实无处安放

- 全库 46 表（`SCHEMA_TABLE_COUNT`，PLA-001 后）无任何财务 / 交易 / 资产表；
- `services/domain_ledger.py` 是**多域审计账本**（只读投影，与金钱无关）；
- 用户信息只落 `memories` / `memory_candidates`，`content` 为 ≤50 字纯文本。

**后果**：用户说「中午吃了 20 块快餐」，走完全链路的产物是一条 content ≈「用户中午吃了快餐」的文本记忆候选——**数字 20 在整个系统里没有任何位置可以落**。

### 2.3 在 V4.0 中的位置

账本域内核的第一块：**建模与迁移**。PLA-005（写面）、PLA-006（聚合）、PLA-007（抽取）、PLA-009（能力）均以本任务为直接前置。

## 3. Scope

### 3.1 In Scope

1. **迁移 `0054_life_ledger_domain.py`**（`revision="0054"`, `down_revision="0053"`），建三表：

   **`ledger_accounts`**（账户）

   | 列 | 类型 | 约束 |
   |---|---|---|
   | `id` | String | PK |
   | `user_id` | String | NOT NULL，索引 |
   | `name` | String | NOT NULL |
   | `type` | String | NOT NULL，CHECK ∈ `cash` / `bank` / `ewallet` / `credit` / `other` |
   | `currency` | String(3) | NOT NULL，默认 `"CNY"` |
   | `status` | String | NOT NULL，默认 `"active"`，CHECK ∈ `active` / `archived` |
   | `created_at` / `updated_at` | DateTime | NOT NULL |

   唯一约束：`(user_id, name)`——同一用户下账户名唯一。
   索引：`ix_ledger_accounts_user` on `(user_id, status)`。

   **`ledger_categories`**（类目树）

   | 列 | 类型 | 约束 |
   |---|---|---|
   | `id` | String | PK |
   | `user_id` | String | NOT NULL，索引 |
   | `parent_id` | String | nullable（自引用，支持类目树） |
   | `name` | String | NOT NULL |
   | `kind` | String | NOT NULL，CHECK ∈ `expense` / `income` |
   | `aliases` | JSON | nullable（别名词表，如 `["快餐","外卖","盖浇饭"]`） |
   | `is_seed` | Boolean | NOT NULL，默认 `false`（种子类目标记） |
   | `created_at` / `updated_at` | DateTime | NOT NULL |

   唯一约束：`(user_id, parent_id, name)`；索引：`ix_ledger_categories_user` on `(user_id, kind)`。

   **`ledger_entries`**（账本条目，**append-only**）

   | 列 | 类型 | 约束 |
   |---|---|---|
   | `id` | String | PK |
   | `user_id` | String | NOT NULL，索引 |
   | `account_id` | String | NOT NULL，**FK → `ledger_accounts.id`** |
   | `category_id` | String | nullable，**FK → `ledger_categories.id`**（「未归类」为 NULL） |
   | `amount_minor` | **Integer** | NOT NULL，CHECK `> 0`（正数；方向由 `direction` 表达） |
   | `currency` | String(3) | NOT NULL，默认 `"CNY"` |
   | `direction` | String | NOT NULL，CHECK ∈ `expense` / `income` / `transfer` |
   | `occurred_at` | DateTime | NOT NULL（发生时间，非创建时间） |
   | `merchant` | String | nullable |
   | `note` | String | nullable |
   | `source` | String | NOT NULL，CHECK ∈ `conversation` / `action` / `manual` / `import` |
   | `source_ref` | String | nullable（原始消息 id / 行动 id） |
   | `idempotency_key` | String | **UNIQUE**（幂等） |
   | `reversal_of` | String | nullable，**FK → `ledger_entries.id`**（冲正指向） |
   | `created_at` | DateTime | NOT NULL |

   索引：`ix_ledger_entries_user_time` on `(user_id, occurred_at DESC)`；`ix_ledger_entries_user_cat` on `(user_id, category_id)`；`ix_ledger_entries_reversal` on `(reversal_of)`。

2. **ORM**：`core/db.py` 增 `LedgerAccountRow` / `LedgerCategoryRow` / `LedgerEntryRow`（集中定义，与既有 44 类同处）。
3. **领域模型**：`models/ledger.py`——Pydantic 值对象：`LedgerDirection`（Literal 枚举）/ `LedgerSource` / `LedgerAccountType` / `LedgerEntry` / `LedgerAccount` / `LedgerCategory` / `LedgerEntryDraft`（待落库形态）。
4. **设置模块**：`core/settings/ledger.py::LedgerSettings`，本任务只含 `ledger_default_currency: str = "CNY"`（**参数类**）；接入 `Settings` 继承链并登记 `tests/v40/support.py`。
5. **金额换算工具**：`models/ledger.py` 内提供 `to_minor(amount: Decimal | str) -> int` / `to_major(minor: int) -> Decimal`（**往返无损**），全仓账本路径统一经此换算。

## 4. Technical Design Requirements

### 4.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **金额以整数最小单位（分）存 `amount_minor`**，全仓账本路径**禁用 `float`** | 精度是账本的生命线；`0.1+0.2` 类错误会让账本失去可信度。货币出口用 `Decimal` / 格式化字符串 |
| D2 | `amount_minor` 恒为**正数**，方向由 `direction` 表达 | 避免「负金额 + 负方向」双重表达带来的聚合歧义 |
| D3 | **纠错用冲正**（`reversal_of` 指向被冲正条目），**append-only，永不 UPDATE 金额** | 账本是可对账的历史，不是可变状态；冲正保留「曾经记错」这一事实 |
| D4 | `idempotency_key` **唯一约束** | 同一句话不能被记两次（R2 风险的主要防线） |
| D5 | 账本表**无任何** TTL / `expires_at` / 衰减 / 状态软化列 | 不可遗忘（架构 §4.5）；与记忆相反是设计意图 |
| D6 | **账本内部关系加强制 FK**（entries → accounts / categories / entries），**`user_id` 不加 FK 到 `users`** | 域内 FK 保护引用完整性且无历史数据包袱；跨既有表的 `user_id` 加 FK 会撕裂历史数据（PLA-001 裁决 D1） |
| D7 | `direction` / `source` / `type` 用 **CHECK 约束**而非独立字典表 | 枚举值稳定且数量少；建字典表是过度设计，也违反零新表承诺 |
| D8 | `aliases` 用 **JSON** 列而非关联表 | 别名词表是「类目的附属属性」，不需要独立查询面；避免为它建第 4 张表 |
| D9 | `occurred_at` 与 `created_at` **分离** | 补记场景（今天补记昨天的账）二者不同；聚合必须按 `occurred_at` |
| D10 | 纳秒级时间统一用 UTC 存储、按本地时区聚合 | 与既有时间系统一致；跨月边界由 PLA-006 定义 |
| D11 | 不新增开关（§0.9）：`ledger_default_currency` 是**取值参数**，不是功能位 | 账本域随迁移直接可用 |

### 4.2 不变量（由 DB 层保证）

```text
INV-1  amount_minor > 0                       （CHECK）
INV-2  direction ∈ {expense, income, transfer}（CHECK）
INV-3  idempotency_key 全局唯一                （UNIQUE）
INV-4  每个 reversal_of 非空的行，其被指向行必须存在（FK）
INV-5  同一 user 下账户名唯一                  （UNIQUE）
INV-6  账本三表无过期/TTL 列                   （结构断言）
```

## 5. Implementation Plan

1. **领域模型先行**：写 `models/ledger.py`（枚举 + 值对象 + 金额换算），先跑纯函数单测（零 DB）。
2. **ORM**：`core/db.py` 增三个 Row 类；`__table_args__` 内声明唯一约束、CHECK、索引（与迁移逐字对齐）。
3. **迁移 `0054`**：`op.create_table` ×3 + 索引 + CHECK。
   ⚠️ **CHECK 写法**：`sa.CheckConstraint("direction IN ('expense','income','transfer')", name="ck_ledger_entries_direction")`——**必须是完整布尔表达式字符串，不是值清单**（`0045` 的教训：把值清单直接传给 `create_check_constraint` 会在 PG 上生成 `CHECK (('a','b'))` 而被判 record，导致迁移链断裂，见 `audits/...` §3.2 D-1）。
   ⚠️ SQLite 的 `batch_alter_table` 差异：本项目既有迁移用 `batch_alter_table` 处理 SQLite 约束，本迁移为**新建表**，直接用 `create_table` 内联约束即可；`downgrade` 逆序 drop（先 drop 有 FK 的 `ledger_entries`，再 `ledger_categories` / `ledger_accounts`）。
4. **FK 的 SQLite 兼容**：内存 SQLite 默认不启用 FK 强制；测试侧沿用既有 fixture 的 `PRAGMA foreign_keys` 处理方式（与 `tests/conftest.py` 一致），不在迁移里特殊处理。
5. **设置模块**：`core/settings/ledger.py` + 接入 `Settings` 继承链 + 登记 `tests/v40/support.py`。
6. **钉测更新**：`tests/support/schema_pins.py`（PLA-001 建立）更新 `MIGRATION_HEAD="0054"`、`SCHEMA_PREVIOUS_HEAD="0053"`、`SCHEMA_TABLE_COUNT=49`、`SCHEMA_COLUMNS_DIGEST` 重算——**只改这一个文件**（这正是 PLA-001 收敛的收益：改动文件 ≤ 3）。
7. **测试**（§7），Focused → Module → Fast。
8. **真实 PG 实测**：`alembic upgrade head` → 49 表 → `downgrade 0053` → 三表消失 → `upgrade head` → `downgrade base` → `upgrade head`；确认 PG 用例**非全 skip**（D-4 教训）。
