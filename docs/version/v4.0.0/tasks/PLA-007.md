## 2. Background

### 2.1 现状：摄取是「文本管道」而不是「事实管道」

| 事实 | 证据 |
|---|---|
| 行动意图检测是纯词表 + 正则、**零 LLM** | `services/action/detector.py`；调用点 `application/chat_pipeline.py:682` |
| `action_type` 枚举无记账类 | `character/asuna/action.py:22` |
| 记忆抽取输出为「文本 + 类型」 | `chains/extractor_chain.py:7` `build_extraction_chain`；`models/memory.py:69 MemoryExtraction`（仅 `content` 字符串 + `type`） |
| 唯一带结构化输出的是用户处境 | `services/world/user_situation.py:218 llm_assist_detect`（输出仍只是 dimension / summary / intensity） |

**实际后果**：用户说「中午吃了 20 块快餐」，系统里落下的是一条 `content ≈ "用户中午吃了快餐"` 的记忆候选——**没有金额字段、没有币种、没有类目、没有可聚合的数值**。这不是配置问题，是数据结构层面无处安放。

### 2.2 同构实现已在项目内

`services/world/interpreter.py` 做的是「用户消息 → 世界状态迁移解释」——与「用户消息 → 账目条目」是**同一件事**。本任务沿用该范式，但按「事实管道」要求补上缺的四样东西：

1. **Schema-first 的结构化抽取链**（走既有 `chains/structured.py`，禁止自由解析）；
2. **置信度 + 缺失字段标记**（低置信转澄清，不猜）；
3. **可回溯**（金额必须能对上原文片段）；
4. **幂等与去重键**（供 PLA-005 的 `idempotency_key` 使用）。

### 2.3 在 V4.0 中的位置

- 依赖 PLA-004（模型）、PLA-005（写面）；
- 是 PLA-008（类目归一）、PLA-009（能力）、PLA-010（确认）、PLA-014（洞察）的前置；
- **本任务是本版本最大不确定性来源**（`tasks.md` 风险 R1：抽取精度不足 → 账目错误 → 用户信任一次崩塌）。

## 3. Scope

### 3.1 In Scope

1. **抽取 schema**（`models/ledger.py::LedgerExtraction`，Pydantic）：

   | 字段 | 类型 | 语义 |
   |---|---|---|
   | `is_ledger_intent` | bool | 是否为记账意图（用于早退，避免非记账消息进后续环节） |
   | `amount_value` | `str \| None` | 金额原文（**字符串**，不用 float；解析归 `to_minor`） |
   | `currency_hint` | `str \| None` | 币种线索（「块」/「元」/「￥」） |
   | `direction` | `Literal["expense","income","transfer"] \| None` | 方向 |
   | `category_hint` | `str \| None` | 类目线索原文（如「快餐」）——**不做归一** |
   | `merchant_hint` | `str \| None` | 商户 / 场所线索 |
   | `occurred_at_hint` | `str \| None` | 时间线索原文（如「中午」「昨晚」） |
   | `occurred_at_resolved` | `datetime \| None` | 由 `occurred_at_hint` 解析出的绝对时间 |
   | `account_hint` | `str \| None` | 账户线索（如「微信」「现金」） |
   | `evidence_span` | `str \| None` | **金额在原文中的片段**（用于可回溯校验） |
   | `confidence` | float | 整体置信度 `[0,1]` |
   | `missing_fields` | `tuple[str, ...]` | 缺失的必要字段名（如 `("amount_value",)`） |

2. **抽取链**（`chains/ledger_extraction_chain.py`）：
   - **必须**经 `chains/structured.py::build_structured_chain`（主链 + 一层降级），禁止自由解析；
   - LLM 实例**必须**来自 `core/llm_factory.get_llm()`；
   - 提供 `extract_ledger(message: str, *, now, world_time, timezone) -> LedgerExtraction`；
3. **Prompt 模板**（`prompts/`）：新增账本抽取模板（经 PromptBuilder 组装，禁手工拼接）；模板内明确「金额必须原样摘出、不得换算、不得推断」。

4. **时间解析**（`services/ledger/timeparse.py`）：
   - 相对时间（「中午」「昨晚」「上周五」「今天早上」）→ 绝对时间；
   - 对齐**世界时间系统**（`services/world/time_provider.py`）与**本地时区**；
   - 无法解析 → `occurred_at_resolved = None` 并进入 `missing_fields`（**不猜**）。

5. **可回溯校验**（`services/ledger/evidence.py`）：`verify_amount_evidence(extraction, message) -> EvidenceCheck`——校验 `amount_value` 是否确实出现在原文 / `evidence_span` 是否与原文一致；不一致 → 降低置信度并标记（**这是零幻觉的第一道闸**）。

6. **分流与挂接**：
   - 置信度 ≥ `ledger_extraction_min_confidence` **且** `missing_fields` 为空 → 产出「可确认候选」，交 PLA-009 / PLA-010；
   - 否则 → 标记「待澄清」，交 PLA-010（**不直接入账**）；
   - 挂接为 `application/post_process` 的**新步骤**（既有步骤注册机制，独立容错）；
   - 遵守**读取进链、写入出链**：抽取发生在流式回答之后，失败不影响已产出的回答。

7. **去重键**：`services/ledger/dedupe.py::extraction_key(message_id, extraction) -> str`——供 PLA-005 的 `idempotency_key` 使用（同一条消息的同一抽取结果只入账一次）。

### 3.2 Out of Scope（明确禁止扩张）

- **不做类目归一算法**（PLA-008）：只输出 `category_hint` 原文。
- **不做入账写入**（PLA-009 / PLA-010）：抽取链**零 DB 写**。
- **不做确认 / 澄清交互**（PLA-010）：只标记「待澄清」，不做回问。
- **不接语音 / 票据 OCR / 图片**（架构 §0.3 Non-Goal）。
- **不改既有 `turn_analysis_chain` / `extractor_chain` / `action/detector.py`**（那些是记忆与行动意图的链路，与账本无关）。
- **不改 LLM Gateway 与预算机制**；不做跨消息的多笔合并抽取（首版一消息一笔）。
- **不新增任何功能开关**（§0.9）。
- 不做金额换算（「二十块」→20 的首版支持范围须在 Detail 冻结；不支持则进 `missing_fields`）。

## 4. Technical Design Requirements

### 4.1 接口契约

```python
def extract_ledger(
    message: str,
    *,
    message_id: str,
    now: datetime,
    world_time: datetime,
    timezone: str,
) -> LedgerExtraction: ...


@dataclass(frozen=True, slots=True)
class EvidenceCheck:
    amount_in_message: bool
    span_matches: bool
    confidence_penalty: float
    reason: str


def verify_amount_evidence(extraction: LedgerExtraction, message: str) -> EvidenceCheck: ...


@dataclass(frozen=True, slots=True)
class TimeResolveResult:
    resolved: datetime | None
    confidence: float
    reason: str


def resolve_occurred_at(hint: str | None, *, world_time: datetime, timezone: str) -> TimeResolveResult: ...


def extraction_key(message_id: str, extraction: LedgerExtraction) -> str:
    """稳定去重键（同消息同内容 → 同键；用于 idempotency_key）。"""
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | 金额在 schema 中是**字符串**（`amount_value`），不是 float | 精度纪律（PLA-004 D1）；且「二十块」这类中文数字需要单独解析策略，用字符串保留原文便于审计 |
| D2 | **必须走 `build_structured_chain`**，禁止自由解析 | 项目铁律（`AGENTS.md`：结构化输出统一走 `chains/structured.py`） |
| D3 | **可回溯校验是硬闸**：金额对不上原文 → 降置信度并标记 | 直接回应 `household-inventory-review.md` 证伪的失败模式；这是「系统侧强制」而非 prompt 祈祷 |
| D4 | 低置信 / 缺字段 → **转澄清，绝不猜** | 账目错误的代价远高于多问一句；猜测会毒化整个账本的可信度 |
| D5 | 时间解析失败**不阻断**，置 `None` 进 `missing_fields` | 发生时点可以从消息时间兜底（在 PLA-010 确认环节处理），不必阻塞抽取 |
| D6 | 抽取链**零 DB 写**，只产候选 | 读取进链、写入出链；也让抽取可被离线评估反复调用 |
| D7 | 挂接为 post_process **新增步骤**，独立容错 | 项目既有纪律：后处理失败不影响已产出回答（架构 §2.3 第 2 条） |
| D8 | 去重键由 `extraction_key` 统一生成，服务端不使用 LLM 生成 | 幂等键必须确定性可复算 |
| D9 | 一消息一笔（不做多笔合并） | 首版收敛复杂度；多笔（「早餐5块午餐20块」）列入后续 Backlog |
| D10 | 无开关（§0.9）；`ledger_extraction_min_confidence` 是**阈值**而非功能位 | 提取能力交付即生效；阈值是质量调节参数 |

### 4.3 数据流

```text
用户消息（流式回答已产出）
   ↓ post_process 新步骤（独立容错）
extract_ledger(message, now, world_time, timezone)
   → LLM（llm_factory + structured chain，主链 + 一层降级）
   → LedgerExtraction（含 category_hint 原文，未归一）
   ↓
verify_amount_evidence(extraction, message)      ← 零幻觉第一道闸
   → 不一致 → confidence -= penalty，标记
   ↓
resolve_occurred_at(occurred_at_hint, ...)       ← 相对时间转绝对时间
   ↓
分流：
   confidence ≥ 阈值 且 missing_fields 为空
        → 可确认候选 → （PLA-009 能力 / PLA-010 确认）
   否则
        → 待澄清标记 → PLA-010 澄清回问
   ↓
extraction_key(message_id, extraction) → 供 PLA-005 作 idempotency_key
```

### 4.4 依赖

- 允许依赖：`app.chains.structured`、`app.core.llm_factory`、`app.core.settings`、`app.prompts`、`app.models.ledger`、`app.services.world.time_provider`（只读世界时间）。
- **禁止**依赖：`app.repositories`（零写库）、`app.api`、`app.channels.*`、`app.application.*`（除 post_process 步骤注册点）。
