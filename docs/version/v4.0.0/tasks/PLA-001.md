## 2. Background

### 2.1 为什么需要这个 Task

个人生活 Agent 的第一性要求是「知道这是谁的生活」。现状是：

- `core/settings/pipeline.py:30` 硬编码 `default_user: str = "default-user"`；
- `user_id` 是贯穿 `conversations` / `memories` / `worlds` / `character_state` / `relationship_state` 等表的**裸字符串**（`core/db.py:35` `Conversation.user_id: Mapped[str]`），**无外键、无 users 表**；
- 4 处 API 以 `Query(default=get_settings().default_user)` 兜底（`api/v1/world.py:79`、`state.py:55`、`proactive.py:18`、`history.py:50`）；
- 唯一的多用户线索是 `core/db.py:1302` `channel_identities`（`channel` + `external_id` → `internal_user_id`，飞书身份映射）。

后果：账本、治理、查询等一切「属于用户」的数据**没有 owner 权威**，隔离无从谈起。

### 2.2 第二个问题：迁移链头钉测散落（必须先还的债）

| 事实 | 证据 |
|---|---|
| `MIGRATION_HEAD` 常量**重复定义在 ≥12 个测试文件** | `tests/v25/test_plan001_goal_contract.py:231`、`test_plan002_static_scan.py:74`、`test_plan003_mount.py:55`、`test_plan004_flags.py:28`、`test_plan005_static_scan.py:52`、`test_plan007_snapshots.py:199`、`test_plan008_static_scan.py:36`、`test_plan009_flags.py:25`、`test_plan010_static_scan.py:31`、`test_plan011_regression.py:70`、`tests/v24/tool012_support.py:74`（实测） |
| `SCHEMA_TABLE_COUNT` | `tests/v24/tool012_support.py:81` = `45` |
| 历史代价 | FEISHU-010 加迁移 `0050` 时实测 **22 个用例由绿转红**（baseline §9 P1 技术债） |

V4.0 要加 **2 个迁移 4 张表**（`0053` / `0054`），若不正本清源，每次加表都要机械升级十几处常量并把用例名 `test_migration_chain_head_is_still_00NN` 改成名不副实。**这是本版本唯一允许触碰既有测试文件的任务。**

### 2.3 在 V4.0 中的位置

PLA-001 是**版本门禁**：`user_id` 语义与迁移机制的底座。账本表一旦带着含糊的 owner 语义落地，后续 9 个任务全部承压。PLA-002（归属）、PLA-003（治理）、PLA-004（账本落表）均以本任务为直接前置。

## 3. Scope

### 3.1 In Scope

1. **`users` 表**（迁移 `0053_life_user_identity.py`，`revision="0053"`，`down_revision="0052"`）：
   `id`(PK, str) / `display_name`(str, nullable) / `status`(str, 默认 `"active"`) / `is_default`(bool, 默认 `false`) / `created_at` / `updated_at`。
   约束：`is_default` 上建**唯一部分索引**（保证「至多一个默认用户」）。
2. **ORM**：`core/db.py::UserRow`（与既有一致：集中定义于 `core/db.py`）。
3. **仓储**：`repositories/user_repository.py`——`get(user_id)` / `list_all()` / `upsert_default(user_id, now)` / `exists(user_id)`。**唯一 DB 访问面**。
4. **服务**：`services/identity/user_service.py`——`ensure_default_user()`（幂等播种）/ `resolve_user(user_id | None) -> UserContext`（缺失回落默认用户）/ `UserContext` 值对象（`frozen=True, slots=True`，零 IO 零 LLM）。
5. **钉测收敛（本任务的核心工程内容）**：
   - 新建 `tests/support/schema_pins.py`，作为**全仓唯一的链头钉测入口**，导出 `MIGRATION_HEAD`、`SCHEMA_PREVIOUS_HEAD`、`SCHEMA_TABLE_COUNT`、`SCHEMA_COLUMNS_DIGEST`、`schema_pin()` 辅助函数（一次给出全部口径）。
   - 把 ≥12 个既有文件中的**常量定义**改为 `from tests.support.schema_pins import MIGRATION_HEAD, SCHEMA_TABLE_COUNT`；用例名含旧版本号的（如 `test_migration_chain_head_is_still_0051`）改为口径无关的 `test_migration_chain_head_matches_pin`。
   - 交付**口径一致断言**：全仓 `MIGRATION_HEAD =` 字面量只出现在 `schema_pins.py` 一处。
6. **默认用户播种接线**：应用启动边界（`app/main.py` lifespan，与既有常驻 worker 启动并列）调用 `ensure_default_user()`；幂等，重复启动不重复建行。
7. **设置模块**：新建 `core/settings/life.py`（`LifeSettings`），本轮**不含任何字段**（除非实现期出现纯参数需求），并在 `core/settings/__init__.py` 的 `Settings` 多继承链中接入；登记进 `tests/v40/support.py`。

### 3.2 Out of Scope（明确禁止扩张）

- **不做注册 / 登录 / 鉴权**（裁决 0.7）：不建密码、token、session、OAuth 任何形态；`users` 表**不含凭据字段**。
- **不加强制外键**：既有各表的 `user_id` 列保持裸字符串，**零语义变更、零数据迁移**（加 FK 会撕裂历史数据）。
- **不做多租户运营能力**：无配额、无计费、无隔离运维视图。
- **不动 `channel_identities` 与 `channel_identity_service` 的身份派生结果**（`build_internal_user_id` 返回值不可变）。
- **不建 `sessions` 表**（V3.0 裁决 Q1 延续，会话仍为 `loop_runs.session_id` 挂接）。
- **不新增任何功能开关**（§0.9）：隔离能力在本任务只是**提供契约**，实际隔离生效于 PLA-002 / PLA-004 之后的领域面，不设 `*_enabled`。
- 不改 `api/v1/**` 的 4 处 `Query(default=...)` 兜底写法（行为等价，改动无收益）。

## 4. Technical Design Requirements

### 4.1 接口契约

```python
@dataclass(frozen=True, slots=True)
class UserContext:
    user_id: str
    display_name: str | None
    status: str
    is_default: bool


def ensure_default_user(*, now: datetime | None = None) -> UserContext:
    """幂等确保默认用户存在；已存在则原样返回，不覆盖 display_name / status。"""


def resolve_user(user_id: str | None, *, now: datetime | None = None) -> UserContext:
    """解析用户；user_id 为 None / 空串 → 回落 get_settings().default_user（与现状行为一致）。"""


def get_user(user_id: str) -> UserContext | None:
    """只读查询；不存在返回 None（不隐式建行）。"""
```

**仓储契约**（`user_repository.py`）：

```python
def get(user_id: str) -> UserRow | None: ...
def list_all(limit: int | None = None) -> list[UserRow]: ...
def upsert_default(user_id: str, *, display_name: str | None = None, now: datetime | None = None) -> UserRow: ...
def exists(user_id: str) -> bool: ...
```

### 4.2 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **不加强制外键**，`users` 只作所有权威，不做引用完整性强制 | 既有 `user_id` 值可能是 `default-user` 或通道派生的历史值；加强 FK 会造成历史数据撕裂与启动阻塞。与裁决 0.7 一致 |
| D2 | **回落而非报错**：`user_id` 缺失回落 `default_user` | 与现状 4 处 `Query(default=...)` 行为**逐字节一致**，保证零回归 |
| D3 | **默认用户用唯一部分索引**，而非「先查后插」的应用层互斥 | 并发启动（多 worker）下应用层判重会竞态；索引由 DB 保证「至多一个 default」 |
| D4 | 钉测收敛采用**单一常量模块 + 引用**，不引入 pytest 插件或动态扫描 | 项目既有约定为静态常量断言；插件会增加黑盒度。目标是「改一处」，不是「自动化」 |
| D5 | `ensure_default_user()` 挂**启动边界**而非首次请求 | 首次请求路径在热路径上，且 4 处 API 兜底已保证行为；启动播种让「用户表非空」成为可断言的不变量 |
| D6 | `UserContext` 为 `frozen` 值对象，零 IO 零 LLM | 与 V3.0 `contracts.py` 的值对象纪律一致 |
| D7 | 本任务**不引入任何设置开关**；`life.py` 可为空模块骨架 | 裁决 9（禁止新增功能开关）；空模块让 PLA-002 / PLA-003 有既定落点，避免后续新增第 24 个模块 |

### 4.3 数据流

```text
应用启动（app/main.py lifespan）
   → ensure_default_user()
        → user_repository.get(default_user)
             命中 → 返回既有行（不覆盖）
             未命中 → upsert_default() 建行（唯一部分索引兜底并发）
   ↓
请求路径（api / services）
   → resolve_user(user_id)
        user_id 有值 → get() → 命中返回 / 未命中返回「未落库」的 UserContext（宽松）
        user_id 为空 → 回落 default_user
   ↓
生活域（PLA-004 起的账本域）以 UserContext.user_id 作为分区键
```

### 4.4 依赖

- 允许依赖：`core.db`、`core.settings`、既有仓储范式。
- **禁止**依赖：`app.chains`、`app.prompts`、`app.api`、`app.channels.*`（含具体渠道实现）、任何 LLM 组件。
