## 2. Background

### 2.1 现状：前端是开发者调试台

| 事实 | 证据 |
|---|---|
| 主路由即工作台 | `apps/frontend/src/App.tsx:27` → `<Workbench/>` |
| 工作台挂调试面板 | `components/shell/workbench.tsx:5` → `DebugPane` |
| 组件全是 debug 面板 | `apps/frontend/src/components/debug/`（overview / state / memory / trace panel） |
| 有桌面端提示 | `workbench.tsx:49`「请使用桌面端获得完整调试体验」 |

**这是本项目的独特资产**——一个能实时观测 agent 状态 / 记忆 / 决策 / trace 的控制台，在同类项目中很少见。**新增用户视图绝不能以牺牲它为代价。**

### 2.2 为什么界面必须是双模而不是替换

| 模式 | 用户 | 价值 |
|---|---|---|
| Debug Console（保留） | 开发者 / 你自己 | 调 prompt、看决策、查 trace——**这是本项目的核心竞争力之一** |
| 账本视图（新增） | 最终用户 | 查账、订正、看分布——**这是产品化的第一步** |

两者的信息密度、交互范式完全不同，硬合并会同时伤害两边。

### 2.3 在 V4.0 中的位置

交付顺序第 7 步（P2，可延后）；依赖 PLA-015 的 API 面。

> **顺序纪律**：评审已明确「**不要先做 UI 再做数据**」——会得到漂亮的假数据界面。因此本任务排在 Phase 2~4 全部数据能力之后。

## 3. Scope

### 3.1 In Scope

1. **账本视图**（`apps/frontend/src/features/ledger/`）：

   | 视图 | 内容 |
   |---|---|
   | 月视图 | 本月合计（支出 / 收入 / 净额）、与上月对比、条目数；期间切换（月 / 周 / 自定义） |
   | 类目分布 | 类目占比列表（含「未归类」分桶）、`top-N` 类目、占比条 |
   | 条目列表 | 分页列表（时间 / 金额 / 类目 / 商户 / 来源标记）、按类目与方向过滤 |
   | 订正入口 | 单条「订正」与「撤销」操作；订正需填原因；结果反馈 |
   | 预算区 | 预算列表（额度 / 已消耗 / 剩余 / 进度）、设置或修改预算 |
   | 三态 | 空态（无数据 / 无账目）、加载态（骨架屏）、错误态（含重试） |

2. **双模入口**：在既有壳层新增模式切换（如顶栏 Tab 或路由分流），**Debug Console 原样可达**。
3. **数据获取**：全部经 **TanStack Query**（既有依赖）调用 PLA-015 的 API；无自写 fetch 层绕过 Query 缓存与失效策略。
4. **金额展示**：**直接使用 API 返回的 `*_text` 字段**，前端不做分的换算（避免各端格式化不一致）。
5. **样式**：沿用既有 Tailwind 4 设计令牌与主题体系；**不引入新图表库**（占比用 CSS 条形 / 进度条即可，避免新依赖）。

### 3.2 Out of Scope（明确禁止扩张）

- **不做移动端专门适配**（架构 Backlog；沿用既有响应式基础能力即可）。
- **不打改版 / 不换图表库 / 不重构既有设计令牌**。
- **不删除或改写 Debug 面板**（`components/debug/*`、`DebugPane`、`workbench.tsx` 的调试能力零改动）。
- **不做用户认证 / 登录页**（后端无鉴权体系，架构裁决 0.7）。
- **不做订阅 / 推送前端**（日结周报由后端投递到渠道，不在前端做站内信）。
- **不做多用户切换 UI**（单用户模型）。
- **不做导出按钮**（导出由 PLA-003 的 `/life/export` 提供，前端如需要只放链接，不在本任务实现下载交互）。
- **不新增任何功能开关 / 前端特性位**（§0.9）。
- 不改后端任何文件（本任务 pure frontend）。

## 4. Technical Design Requirements

### 4.1 关键裁决

| # | 裁决 | 理由 |
|---|---|---|
| D1 | **双模并存**，不替换 Debug Console | Debug Console 是本项目独特资产；用户视图不得以牺牲它为代价 |
| D2 | 前端**只经 API**，不 import 后端内部 / 不直连数据库 | 与后端分层纪律对应；也是「前端可独立部署」的前提 |
| D3 | 金额展示**只用 `*_text`**，前端零换算 | `format_minor` 是唯一格式化出口（PLA-006）；前端重复实现必然漂移 |
| D4 | 数据层统一走 **TanStack Query** | 既有依赖与既有约定；缓存 / 失效 / 重试策略统一 |
| D5 | **不引入新依赖**（图表库等） | 占比展示用 CSS 足够；新依赖带来体积与维护成本。如确实需要，属独立决策 |
| D6 | 订正操作**必须填原因**并做二次确认 | 订正是不可逆语义（生成冲正记录），需防误触 |
| D7 | 三态必备（空 / 加载 / 错误含重试） | 用户面的基本质量线；错误态必须有重试而非白屏 |
| D8 | 无开关（§0.9） | 页面交付即可访问 |
| D9 | 既有 Debug 能力**零回归**作为硬验收项 | 用既有前端测试 + 手工截图对比证明 |

### 4.2 数据流

```text
LedgerView（features/ledger）
   → TanStack Query hooks（useLedgerSummary / useLedgerEntries / useLedgerBudgets / useLedgerCategories）
   → PLA-015 API
         GET  /ledger/summary
         GET  /ledger/entries
         GET  /ledger/categories
         GET  /ledger/budgets
         POST /ledger/entries/{id}/reverse      ← 订正 / 撤销
         PUT  /ledger/budgets                   ← 预算设置
   → 渲染：金额直接用 *_text；占比用 CSS 条；列表分页

既有 Debug 分支（不变）：
   App.tsx → Workbench → DebugPane → components/debug/*
```

### 4.3 依赖

- 允许依赖：既有前端基建（TanStack Query / Zustand / Tailwind 4 / 既有组件与设计令牌）。
- **禁止**：直连后端内部结构、直接访问数据库、新增后端依赖、新增前端图表库。

## 5. Implementation Plan

1. **API 客户端层**：`features/ledger/api/`——封装 PLA-015 端点为 typed functions（类型定义与后端 schema 对齐）。
2. **Query hooks**：`features/ledger/hooks/`——`useLedgerSummary` / `useLedgerEntries` / `useLedgerBudgets` / `useLedgerCategories` + 订正 / 预算的 mutation hooks（含缓存失效）。
3. **视图组件**：月视图 / 类目分布 / 条目列表 / 预算区 / 三态组件。
4. **订正交互**：原因输入 + 二次确认 + 结果反馈。
5. **双模入口**：壳层模式切换（顶栏 Tab 或路由分流），确认 Debug 路径原样可达。
6. **测试**：组件测试（渲染 / 三态 / 交互）+ 手工验收清单（Debug 面板截图对比）。
7. **构建验证**：`npm run build` / 既有 lint 通过。
